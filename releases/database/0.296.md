# IcyDB 0.296

## [0.296.0] - 2026-11-03

### ⚠️ Breaking

- Adopt Platform Types 0.18 for public Principal/Account conversions and read
  authorization guards. Applications using those Rust types must update their
  direct Types dependency. Generated caller-byte boundaries remain unchanged
  ([#611](https://github.com/dragginzgame/icydb/issues/611)).
- Select IC Wire 0.16 for IcyDB's native interfaces and generated clients.
  Metrics report schemas are now owned by IcyDB; canonical Metrics still owns
  recording, arithmetic and decoded-state validation. Report bytes, public
  getter shapes and frontend identities remain unchanged
  ([#614](https://github.com/dragginzgame/icydb/issues/614)). Adopt Metrics 0.28
  with its supplier-owned Wire metadata removed; applications exchanging canonical
  Metrics Rust values must align their direct dependency. Storage 0.66 aligns public
  codec errors/configuration with Wire 0.16, removing the older Wire/Derive pair
  from the root graph. Stored bytes and same-contract reopening are unchanged.
- Keep IcyDB-owned Account/Subaccount native bytes, stored keys, schema metadata
  and None-versus-explicit-zero database identity unchanged. Platform Account's
  present subaccount now uses Serde bytes. This dependency update adds no
  persisted-data migration, reset or legacy decoder.
- Direct Platform Account payload users must qualify its new byte schema and
  budgets, retaining original bytes for exact retries or hashes. IcyDB endpoint
  contracts and browser schemas retain their existing identities.

### 🧹 Cleanup

- Share the admitted equality-prefix walk between access construction and
  diagnostic scoring, retaining its extent and typed stop cause. Physical
  planning can retain an earlier usable prefix where diagnostics report an
  incompatible later key. Ordered-range field/expression capability decisions
  also use one owner across extraction and diagnostic consumers. Existing
  literal lowering, ranking, range construction and budget charges remain
  authoritative ([#605](https://github.com/dragginzgame/icydb/issues/605)).
- Share scalar boolean truth tables, checked arithmetic and comparison dispatch
  across folding, function helpers and compiled execution. Callers retain their
  distinct numeric policies, NULL/error projection, traversal, lazy branches
  and accounting. Remove superseded operator wrappers and duplicate dispatch;
  no public API or persisted format changes
  ([#606](https://github.com/dragginzgame/icydb/issues/606)).
- Simplify nullable-unique schema fixtures by constructing snapshots once and
  reusing existing constraint-catalog setup. Keep malformed persisted images,
  predicate-depth cases and independent description assertions unchanged
  ([#609](https://github.com/dragginzgame/icydb/issues/609)).
- Reuse one field-lowering implementation for initial schema creation and
  physical migration planning. Preserve caller-owned identities, layout versions,
  defaults, write policies and historical-fill rules without changing schema
  publication or recovery ([#607](https://github.com/dragginzgame/icydb/issues/607)).
- Adopt published Platform 0.20.0 for the existing BLAKE3 capability; its Rust
  source matches 0.19.0. Keep direct Runtime use at 0.19.0 with Storage 0.66.0,
  retaining one raw-IC0 owner
  ([Storage #153](https://github.com/dragginzgame/ic-storage/issues/153)). Keep
  Host Text 0.74.1. Types adoption is described above; the independent Canic
  graph remains blocked by its existing executor
  ownership conflict ([#373](https://github.com/dragginzgame/icydb/issues/373)).
- Share checksum-trailer verification across five schema record decoders while
  preserving each format's size limits, validation order and typed failures.
  Encoders and persisted bytes are unchanged
  ([#607](https://github.com/dragginzgame/icydb/issues/607)).
- Share identical store-metadata accessors across diagnostic snapshot types,
  retaining their public methods, flat wire fields and role-specific metrics
  ([#612](https://github.com/dragginzgame/icydb/issues/612)).
- Adopt Shared Tooling 0.27.29's complete-inventory refusal for tool/cache
  maintenance and durable-checkout/delivery guidance. Existing release gates,
  tool selections and cache contents are unchanged
  ([#613](https://github.com/dragginzgame/icydb/issues/613)).
- Adopt Host Tools 0.79.0 for maintained artifact/interface helpers, aligning
  their optional Platform/Types identities with the current root graph.
  Host processing, text and artifact supplier versions are unchanged.
