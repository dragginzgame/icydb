# IcyDB database 0.306

## [0.306.0]

### ⚠️ Breaking

- Adopt Platform 0.28.0 through Testkit 0.96.0. Native testing uses canonical
  owned Principal identities and Platform-owned Candid codecs, errors and bounds;
  the root graph now shares one Types 0.19 provider. Canic remains deferred.

- Adopt Platform Types 0.19.0 for canonical Principal and Account identities.
  Remove the retired external-Principal conversion feature; transport callers
  continue through checked bytes with unchanged identity and wire semantics.

- Adopt published IC Storage 0.71.1 with bucket-backed allocation. Use fresh
  backing; reject incompatible whole-store images without automatic migration
  or reset. Existing 0.71 backing remains reopenable. The public Storage config
  loses its Wire limit and directory errors no longer include a Wire variant.
  Canic remains on its deferred independent stack.
- Storage now reserves fixed creation-time allocation/bucket tables. Defaults
  reserve 960 KiB of controls and permit 8 GiB of bucket data; physical limits
  include metadata and bucket slack. Reopening cannot increase image table
  capacities. IcyDB continues to consume Storage-owned admission and allocation.

### 🔧 Changed

- Adopt Storage's bounded directory reads and allocation lookup/verification
  improvements while retaining the 0.71 backing format and reopen contract.

- Align direct and Storage-owned raw IC0 dependencies on Platform Runtime 0.21.0,
  retaining one Runtime provider and rejecting duplicate executor ownership.

- Adopt published IC Entropy 0.1.0 for seeded expansion, preserving native entropy
  acquisition, legacy u128 ordering and monotonic ULIDs. Retain database boot-seed
  and cursor-key policy; remove the temporary sibling dependency.
  [#633 — published generator adoption](https://github.com/dragginzgame/icydb/issues/633).

- Update direct SHA-2 hashing to 0.11.1 with unused default features disabled.
  Preserve digest bytes and domain separation; retain older transitive versions
  where their owners still require them.

- Adopt the authenticated published Toko Tooling 0.37.5 snapshot and exact
  tooling selections in both maintained workspaces. Migrate the baseline to
  `TOKO-TOOLING.md`, the receipt to `.toko-tooling.snapshot`, commands/settings
  to `toko-tooling-*` / `TOKO_TOOLING_*`, and LOC metadata to its Toko namespace.
  Update actual Make, CI, deployment and documentation callers together; retire
  old entrypoints through the exporter without aliases or local payload edits.
- Adopt the standalone baseline export while retaining existing offline guides
  explicitly. Apply current direct-dependency selection guidance during authorized
  updates, preserving required shared contracts without unrelated upgrades.
- The earlier 0.37.2 selection preserves all 171 installed payloads byte-for-byte; its
  upstream dependency-report fixes are outside this consumer's selected roots.
- Reject obsolete LOC policy namespaces before counting source, preventing silent
  fixture reclassification; all IcyDB policies use the maintained namespace.
- Retain 0.36.1's test-only closure classification fix and the complete source
  inventory. Preserve unrelated locked records and all existing cleanup outcomes.
  Canic's deferred executor-links conflict still requires the previously approved
  tooling-only nested-lock repair; its runtime graph remains unchanged.
- Readmit mechanically renamed Make calls and the receipt input in the current
  validation mapping. Preserve every stage and historical native certificate;
  this adoption grants no new release-stage omission.

### 🧹 Cleanup

- Live-page collectors and scalar/order traversals use one bounded continuation
  drain. Each caller still constructs real request sessions, chooses public/trusted execution and
  checks its work counters. All datasets, expected results and resume suffixes
  remain; the common drain also rejects any repeated continuation token.
- Field-path and expression index views share accepted identity, uniqueness,
  predicate rendering/projection and catalog construction. Typed key vectors and
  pointer-based field ownership checks remain distinct, with exhaustive retained
  memory accounting for both instantiations.
- Row-local and unique validation share exclusive resume bounds and stored
  entity/key/row identity admission. Page ceilings, first-row byte exceptions,
  maintenance charging, finding precedence and unique staging remain local.
- Broad diagnostic variants declare their class, origin and compact code in one
  table. Detailed numeric registry ownership and compact Debug remain unchanged.
- List/Set derive metadata shares definition, schema kind and schema-part emission
  through a narrow helper. Map retains its key/value path; named public model
  types, generated Vec/BTreeSet types and immutable-key checks remain unchanged.
- Prefix diagnostic scoring borrows its existing index contract. Constant
  COALESCE folding borrows literal inputs and clones only the selected result
  through the existing shared evaluator; fold eligibility remains unchanged.

### 📊 Audit

- Post-adoption live-page consolidation removes another 39 test code lines and
  changes no non-test code. Catalogue ranges, public SQL, full-row reads, scoped
  ordering and secondary-order budgets reuse the existing helper. Preserve
  physical page ceilings, work/empty-page checks and error context. Exhaustive
  proof handoffs and staged diagnostic assertions retain their distinct flows.

- Planner and EXPLAIN already share equality-prefix traversal, range compare
  admission and key-item eligibility. Preserve different ranking, diagnostic
  rejection order and budget walks; no universal candidate evaluator is added.
- Compact/full schema descriptions already share accepted kind/payload rendering.
  Keep sorted compact columns distinct from persisted-order full descriptions,
  including their different bounds and historical metadata requirements.
- Initial/reconciled constraints already share expression and targeted-rule
  binders. Keep immediate initial activation distinct from retained-ID matching
  and journaled validation of added constraints.
- Literal and cached-template SELECTs already share preparation/lowering/binding
  primitives. Keep first-call parameter admission and value-independent cached
  bodies separate; no common orchestration mode is introduced.
- Runtime numeric evaluation and constant folding already share arithmetic
  kernels. Keep fallible runtime errors/budgets separate from conservative
  optional folds. No test scenario or supported feature is removed.
- The cleanup preceding Storage adoption measured 154 fewer non-test Rust code lines and
  131 fewer test code lines (285 total), excluding the incoming tooling update.
  All 2,169 Rust source files remain classified, with no unknown category.
  IC cycles/instructions and total/code-section Wasm changes are unmeasured.
