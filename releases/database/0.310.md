# IcyDB database 0.310

## [0.310.0]

### 🔧 Changed

- Prepare index bounds on the existing access-tree leaves. Borrowed executable
  projections carry those bindings directly; remove the traversal spec cursor,
  speculative cursor copies, prefix/range alignment protocol and grouped spec
  bundle. DISTINCT page suppression shares leaf bindings without re-encoding.
  Covering and metadata shortcuts borrow single-leaf bounds, and covering prefix
  expansion stays execution-local. Semantic equality and continuation inputs
  exclude physical residents. Unprepared index execution fails closed; primary
  access requires no binding allocation. Retained accounting includes the new
  owners and construction charges precede their publication. Composite plans
  now use per-index-leaf shared owners; no memory or Wasm reduction is claimed.
  Physical dispatch now accepts that bound leaf directly, deriving private scan
  inputs at its entrypoint. Remove the intermediate constraints/request wrappers,
  traversal forwarding method and redundant count arguments; validate prefix
  arity once before specialized scans. Prefix expansion, storage corruption
  checks, hard budgets and continuation policy retain their existing owners.

- Remove the complete unfiltered execution command formerly retained inside
  global-aggregate parameter templates. Keep aggregate strategies, projection,
  HAVING and base query shape; derive the structural query, extrema ordering and
  metadata eligibility only when constructing the actual invocation command.
  Ordinary and parameterized compilation share that construction owner. Extend
  cold/warm parameter parity to aggregate FILTER, HAVING and empty output windows,
  including failed binding and bounded cache retention.

- Bind WHERE parameters in the shared SQL expression lowerer for scalar,
  grouped and global-aggregate templates. Remove the invocation-local SQL copy,
  parameter/membership mutation and repeated operand-subtree lowering. Preserve
  pre-fold bound-operand admission, field arithmetic and numeric-scale literal
  rules, current-schema checks and first-call WHERE diagnostic precedence.
  SQL text retains literal-only numeric scales; programmatically authored WHERE
  scale slots retain their existing typed admission. Parameter payload copying
  is charged before allocation; templates retain no invocation-local values.

- Align the post-link source guard with infallible Build spec construction;
  retain negative coverage for planning error propagation and checked batch use.

- Adopt IC Build 0.83.0 in native qualification; Testkit 0.101.0 remains the
  latest published selection. Read progress heartbeat fields directly and
  resolve batch labels from their specification index. Maintain shared targets
  and prune exact/artifact caches explicitly before acquisition, once per
  selected batch target, preserving best-effort diagnostics and retention limits.
  This replaces interval-scheduled acquisition maintenance; retained records
  still protect live outputs. Remove the now-infallible specification error
  plumbing. Full workspace manifests and lockfiles now participate in Build's
  exact cache identity, so older cache entries are not automatically reused.

- Enable the shared `make deps-update` command for sequential root and native
  qualification Cargo updates, with optional package/version selectors and the
  existing repository Cargo directories. Record standing maintainer permission
  for dependency maintenance; Canic remains explicitly selected and deferred.
  The targeted tooling update changes only Toko Tooling; independent qualification
  dependency edits are preserved and need their own runtime validation.

- Adopt published Toko Tooling 0.39.15 in the root, native qualification and
  deferred Canic tooling selections. Refresh the authenticated 109-file snapshot;
  LOC labels are width-bounded with a `--wide` option, and supplier freshness
  reviews include explicit dispositions. Startup qualification now selects
  published Testkit 0.101.0. Canic retains Testkit
  0.75 under its executor-cohort compatibility hold
  ([#373](https://github.com/dragginzgame/icydb/issues/373)); revisit with that
  migration or the next applicable review. Its tooling-only lock repair changes
  no runtime selection. Product Testkit isolation and incoming Storage 0.73.3
  remain intact; no application or simulator code changes.

- Select published Host Tools 0.91.0 in both maintained workspace catalogs and
  locks. Native qualification retains its `ic-interface` selection for raw Wasm
  export facts. The changed optional Platform 0.31 codec and ledger identities
  are not consumed, so no unused Platform facade is added.
- Preserve the existing Host Foundation 0.76.4 selections, unrelated lock entries
  and the deferred Canic graph. Package versions are unchanged.
- Adopt Testkit 0.101.0 in native qualification and import its upstream client
  through `ic_testkit::pocket_ic`. Keep Testkit's server admission and lifecycle.
  The native graph now includes its required Platform management codec; the
  startup fixture does not consume the changed cached-snapshot preparation API.
  Product dependencies and the deferred Canic runtime graph remain unchanged.

### ⚠️ Breaking

- Replace `FilterValue` with the existing `InputValue` in filter literals and
  builders. Import it from `icydb::value` or the prelude; use its constructors
  instead of the retired enum variants. Typed values retain scalar identity,
  Unit remains separate from Null, and maps and enum payloads retain structure.
  Enum paths are checked against accepted schema authority. Explicit schema-aware
  text admission remains; SQL numeric token inference is unchanged.
- Serialized filters now use the PublicValue literal representation (including
  Text rather than String). Regenerate stored/transmitted filter requests with
  current clients; no compatibility decoder is retained. This changes filter
  request serialization, not persisted database row encoding.
- Bound map keys/values and enum payloads during request admission and rejection
  cleanup; charge recursive copies and map canonicalization before lowering.
  Query and schema-info qualification covers typed round trips, recursive limits,
  budget refusal and accepted enum identity. This first consolidation slice adds
  47 production and 82 test code lines while removing one public representation
  and its lossy conversion route; Wasm/IC impact is unmeasured.

- Remove Core's public `ExecutorErrorDetail` enum and `ErrorDetail::Executor`
  variant. Use the canonical diagnostic code/detail/facts projection; the
  retained constraint-program-corruption constructor preserves its corruption
  class, executor origin, boundary code and empty facts. No compatibility alias
  or replacement diagnostic registry is introduced.
- Replace the Testkit-bound `icydb::testing::drive_startup` wrapper and its
  Testkit type re-exports with the dependency-free `startup_poll` predicate.
  Compose it with Testkit's `pic::tick_until` to retain typed readiness/errors,
  one-second simulated rounds, zero/last-round boundaries and bounded exhaustion.
  No compatibility shim, IcyDB polling loop or shipped adapter package is added.

### 🧹 Cleanup

- Replace the unbound filter handoff with one accepted-schema admission owner.
  Query intent retains the complete expression, derived access restriction,
  coverage proof and input-resource summary; cache preparation borrows the
  admitted predicate instead of reconstructing it. Exact-count retains its
  lightweight route and checks the same schema authority.
- SQL supplies semantic expressions rather than independently asserted predicate
  mirrors. Required-predicate capability checks and early parameter validation
  remain frontend gates. UPDATE uses the predicate-capable semantic expression
  consistently for selection and diagnostics. Compiled SQL is rebuilt when a
  heap-root renewal changes store-local admission authority, even if durable
  schema identity is unchanged.

- Derive the actual schema-application publication head once and reuse it for
  ordinary receipts. Deferred activation retains a distinct future head, and
  no-op receipts retain the admitted target head.
- Borrow current/candidate schema bundles when assembling relation-domain
  preflight topology. Retain positional store alignment, missing/ambiguous
  target rejection and pre-publication emptiness checks without copying bundles.
- Continuation hashing consumes the planner's canonical predicate directly,
  removing its repeated copy and tree normalization. Membership/coercion byte
  canonicalization and fallible encoding admission remain at the shared encoder;
  continuation bytes, hash domains and algorithms remain unchanged.
- Executable access contracts borrow union/intersection children and project
  mechanical leaf payloads on demand instead of allocating another recursive
  tree. Preserve exact-intersection fallback, accepted-index union consistency,
  order and cursor behavior, and positional prefix/range binding validation.
  The spec cursor now retains only unconsumed slices, eliminating two offsets
  and their arithmetic; failed reads preserve the cursor and exhaustion checks
  still reject unused specifications.
- Replace three-state predicate coverage bookkeeping with one completeness
  flag. The optional subset already distinguishes absence from partial coverage;
  expression authority and conjunction coverage proofs remain intact.
- Remove the unused overlay-decision enum and both classifiers whose results
  recovery discarded. Actual exhaustive journal dispatch, store provenance and
  exact/superseded retirement continue to own recovery behavior.

- Migration fallback candidates consume completed working enum/composite
  catalogues, source bindings and entity snapshots. Rekeyed reconciliation still
  borrows its exact bundle; revision checks, precedence and errors are unchanged.
- Aggregate value ingestion now has one Cow-based semantic owner for NULL,
  numeric and extrema behavior. Borrowed calls delegate to it; owned callers
  move selected values without an extra adapter or clone.

- Grouped DISTINCT insertion no longer repeats the membership preflight already
  performed by borrowed admission. Final HashSet equality, fallible reservation,
  total/per-group budget ordering and unchanged-state refusal remain intact.

### 🧹 Query intent state reduction

- Every authored filter now carries its semantic expression. Remove the unused
  predicate-only intent variant, its constructor/append chain and the SQL wrapper
  states that could previously omit an expression. Retain SQL's prederived
  predicate where required, without adding a second derivation on those routes.
- Migrate historical fixtures to expression-backed filters and accepted-schema
  builders. Keep strict covering-contract fixtures at the existing paired
  expression/predicate handoff; frontend widening policy is a different concern.
  Retire two obsolete predicate-append-only tests while preserving failed
  admission, partial coverage, warmed cache identity, exact-count, mutation and
  residual execution coverage. Executable predicate-only filters remain valid.
- This removal reduces production Rust code by 79 lines and adds 37 test code
  lines (net reduction: 42), measured against the pre-removal working tree.
  It removes one intent mode, its multi-mode append dispatch and two impossible
  SQL states. SQL parameter writeback and wider bound-filter consolidation remain
  pending. Wasm module/code-section bytes and IC cycles/instructions are unmeasured.

### 🧹 SQL binding writeback removal

- Remove both canonical-literal writeback sites from SQL binding. Substitution
  still fills parameter slots, but admission no longer changes those values
  through a temporary predicate and back into parser syntax. Final schema-bound
  lowering retains responsibility for executable literal representation.
- Lower membership's shared target once for early admission and compare semantic
  operands directly. Remove the per-item temporary SQL equality tree and its
  repeated target lowering. Complex target comparisons retain typed inference;
  all items requiring admission are checked before dead branches can disappear.
- Add bound-target, complex-target and later-invalid-member regression cases.
  This change adds 22 production and 48 test code lines (net +70). It removes
  writeback and temporary SQL construction rather than claiming a LOC reduction.
  No new runtime representation or compatibility route is introduced. Wasm/IC
  effects remain unmeasured; ordinary whole-query lowering still remains for
  further shared-admission consolidation.

### 🧹 Admitted WHERE handoff

- Parameter admission now returns its already-lowered expression. Scalar,
  grouped and global-aggregate template binding consume that owned expression
  through the common SQL boolean normalization owner. The post-admission
  whole-WHERE lowering pass is removed; scalar CASE and grouped/global predicate
  admission policies remain distinct.
- Route uncached bound SELECT compilation through the existing checked-template
  compiler and remove the separate bound-statement preparation function. Cold
  and warm parameterized calls therefore share the same semantic handoff.
  Binding tests now inspect semantic output rather than rewritten parser syntax.
- Delta: +2 production / -23 test Rust code lines, net -21. No new expression
  representation or compatibility route is added. Parameter substitution still
  uses an execution-local SQL copy, and leaf admission still performs local
  lowering. Full direct binding and accepted-schema authority consolidation remain
  unfinished. The cold route now uses template construction too; no IC-cycle,
  instruction or Wasm-size saving is claimed without matched measurements.
