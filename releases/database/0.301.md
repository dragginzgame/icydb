# IcyDB 0.301

## [0.301.0]

### ⚠️ Breaking

- Adopt published Testkit 0.90.0 in the root graph. The facade's public native
  PocketIC and polling-error types acquire Testkit 0.90's crate identity;
  consumers combining these types with direct Testkit imports must use that
  line. Require a positive finite request duration at construction and preserve
  the prior five-minute request allowance in the maintained startup fixture.
  Its managed startup bound remains thirty seconds. Testkit owns budget
  admission, provisioning and explicit instance/server teardown. No stored
  database format or current-image recovery contract changes. The separately
  owned Canic integration stack remains unchanged
  ([#629 — Migrate root PocketIC request budgets](https://github.com/dragginzgame/icydb/issues/629)).

### 🐛 Fixed

- Supply host-only Wire metadata at the existing owners of `Id<E>`, `Unit`,
  `Blob` and all 31 transparent model base newtypes. IDs describe their key
  without requiring entity metadata; Blob remains bulk bytes with finite
  limits supplied by each concrete endpoint. Model metadata follows the
  generated inner serializer and does not add application validation or
  normalization. Forward the opt-in through the facade's `wire-schema` feature.
- Qualify an independent consumer DTO endpoint with exact native/TypeScript
  request and reply frames, numeric and Ulid IDs, Unicode geographic/web
  wrappers, byte/Decimal/integer families, truncation, malformed text,
  direction, trailing bytes and endpoint-budget refusals. Independently compare
  every supported base wrapper with its primitive Serde bytes. Preserve the
  existing twelve-endpoint registry, baseline, method IDs and admission limits;
  qualify the forwarded Wasm dependency boundary separately
  ([#628 — Complete consumer DTO metadata](https://github.com/dragginzgame/icydb/issues/628)).
- Remove field-kind tree cloning from CHECK operand validation and length-source
  resolution. Direct fields, literal kinds and catalog-resolved newtypes remain
  borrowed from their existing authority; length/cardinality results reuse the
  shared Nat64 kind. Preserve local snapshot deferral, exact catalog validation,
  comparison/length capabilities, canonical bytes and typed refusal behavior.
  This removes one validation allocation path; full construction and recovery
  accounting remains open
  ([#76 — Predicate construction accounting](https://github.com/dragginzgame/icydb/issues/76)).
- Reuse two local canonical-key buffers across CHECK Boolean comparisons and
  adjacent-child validation. The existing writer, compact sorter, strict byte
  order and duplicate elimination remain authoritative; malformed children
  still reach shape/bounds validation before key extraction. Qualify varying
  key sizes, Unicode, all comparison operators, duplicates, singleton collapse,
  same-family flattening, maximum width, nested opposite Boolean families and
  equal/reversed ordering refusals against fresh owned-key reference sorting.
  This removes repeated fresh key destinations; buffer growth, repeated encoding
  and complete recovery/construction accounting remain open
  ([#76 — Predicate construction accounting](https://github.com/dragginzgame/icydb/issues/76)).
- Admit targeted-rule ordering before whole-schema semantic compilation using
  the existing caller's construction budget. A full-source sort allowance
  bounds all root-group sorts; record-member sorts admit their ordinal vectors,
  comparison allowance and both index buffers. Admission and execution share
  one record roster and reserve both discovery walks, including filtered types.
  Preserve cumulative counters and typed resource/lane/limit/actual refusals;
  keep the existing single-activation semantic compiler without a fresh ceiling.
  Empty source sets retain their no-ordering path. Remaining program backing,
  literal-decoder backing and complete recovery accounting stay open
  ([#76 — Predicate construction accounting](https://github.com/dragginzgame/icydb/issues/76)).
- Admit CHECK and targeted-rule encoded literal inputs through the caller's
  existing `DecodedBytes` allowance before semantic decoding. Reuse the shared
  accepted-index literal boundary and targeted source vector without payload
  copies; admit each targeted operation dispatch and both numeric-range
  operands. Length-only rules and literal-free CHECKs need no decode bytes.
  Accepted and pending rules retain cumulative request/maintenance limits and
  typed exhaustion facts; pure retained projection and historical activation
  retain their existing authority. Qualify exact/short limits across four
  request lanes, Unicode/empty/maximum-size scalar inputs, Boolean children,
  each targeted operation, malformed payloads and sticky maintenance refusal.
  Decoder backing, recursive traversal and complete recovery accounting remain
  open ([#76 — Predicate construction accounting](https://github.com/dragginzgame/icydb/issues/76)).
- Remove the visited-set allocation from accepted newtype resolution. A
  single-successor chain can visit each catalog definition at most once before
  its terminal kind; the catalog extent plus one terminal visit bounds the
  existing borrowed resolver without a second graph or a new depth ceiling.
  Preserve direct kinds, scalar/collection terminals, missing/structural
  refusals and wrapper-only cycle rejection. Qualify every wrapper graph with
  up to four definitions plus full-catalog chain and late-cycle boundaries.
  General resolver visit admission and complete construction/recovery accounting
  remain open ([#76 — Predicate construction accounting](https://github.com/dragginzgame/icydb/issues/76)).
- Admit every whole-schema targeted rule's field-metadata lookup extent and
  bounded newtype-resolution visits through the caller's existing construction
  allowance. The resolver and admission share one catalog-owned bound; early
  field matches and short chains retain the full reservation. Reuse the
  resolved accepted field's physical slot, whose layout agreement is already
  checked at snapshot acceptance, without another layout scan. Preserve stable
  required slots, first-violation paths, accepted/pending rule authority and
  historical single-activation behavior. Qualify independent field/catalog
  growth, four request lanes, exact/short and cumulative request limits and
  sticky maintenance refusal. Decoder/program backing, other validation and
  resolver visits, traversal/stack and complete recovery accounting remain open
  ([#76 — Predicate construction accounting](https://github.com/dragginzgame/icydb/issues/76)).
- Remove the full root-key buffer previously built solely to validate CHECK
  encoded-byte limits. The existing canonical encoder writes either retained
  bytes or a saturating length-only output; there is no second format or sizing
  algorithm. Count fixed-width Boolean frames once and skip length backpatches
  in the counter. Preserve shape/depth/node/literal validation order, exact byte
  limits, canonical key bytes and Boolean ordering. Qualify all kind/codec and
  operand families, nested frames, and local/catalog validation at one below,
  exactly and one above the encoded-byte limit. This removes validation-only
  root backing; Boolean key buffers, encoder visits and complete construction/
  decoder/stack/recovery accounting remain open
  ([#76 — Predicate construction accounting](https://github.com/dragginzgame/icydb/issues/76)).

### 🔧 Changed

- Stop invoking Shared's generic tool-command fixture in the main and Canic
  adapter macOS matrices, removing four executions when both workflows trigger.
  Retain the existing product automation, workstation/setup, dependency/tool
  admission, shell lint, native builds and adapter/startup qualification.
- Adopt published Build 0.77.0. Consume the shared four-part batch entry and
  obtain the complete build error and failure details from its result; retain
  collect-all reporting, successful artifact records and post-link custody.
  Use the selected metadata editor through the existing Shared installer.
- Raise the root declared floors to the already selected Platform 0.23.6,
  Runtime 0.19.5 and Types 0.18.2. Preserve the other incoming dependency
  selections and the independent Canic manifest/lock. Qualify the consuming
  native and Wasm boundaries without inferring IcyDB cost changes from supplier
  instruction/size evidence.
- Review the published Platform 0.23.6 patch and its shared Candid type-child
  buffer. Preserve external bytes, traversal order, work quotas and the nesting
  limit; IcyDB adds no codec or runtime fallback. Verify the registry archive
  and supplier source while retaining Runtime/Types and other lock selections.
- Readmit the pending database-ledger path after its 0.301 move. The reviewed
  group declaration changes only that note path, with the complete stage roster
  and Make recipes unchanged. Existing native comparison records stay intact;
  this is not new release-omission qualification. Dependencies, workflow changes
  and unavailable exact mapping qualification still require the full gate.
- Adopt Shared Tooling 0.31.0 and its saved-context setup, status, recovery
  and guarded reconciliation commands. Use the renamed release-batch settings,
  automatic capture and schema-2 journals; retain older state with its original
  tooling. Recovery checks saved tools offline and preserves deferred edits.
- Reject malformed checksum output and incomplete snapshot annotations through
  the reviewed Shared integrity helpers.
