# IcyDB database 0.311

## [0.311.0]

### ⚠️ Breaking

- Public Wire re-exports now use IC Wire 0.22. Direct Wire consumers must align
  their Rust dependency versions; the adopted codec frame format is unchanged.

- Public error construction borrows `Diagnostic`; generated typed-output
  preparation borrows its column list. Callers pass references to these inputs.

- `ErrorTree::add` and `merge_for` accept `Into<String>`, moving owned messages
  and route keys without another allocation. Convert other displayable values
  explicitly before passing them.

- `EntityCatalogDescription::new` now borrows its count metadata; pass
  `&EntityCatalogCounts` when constructing catalog descriptions.

- Adopt Unicode 18 text transforms with Rust 1.100. Require fresh installations:
  reject all earlier database boot identities without modifying retained bytes,
  preventing old expression-index keys from being reused under changed case mappings.

- Physical migrations enter final validation directly after the last rewrite
  page. Remove the accounting-only public rebuild phase and atomically checkpoint
  completed-domain counts with row effects. Final proof and bounded abort remain.
- The migration-record envelope now uses a distinct discriminator. Reject old
  migration records intact, including terminal records; finish/recover with the
  original release and explicitly retire/reset those installations before adoption.
  No automatic conversion or data deletion is performed. Commit-marker byte
  fixtures now freeze this new migration envelope while preserving capacity,
  range, round-trip and corruption checks.

### 🧹 Cleanup

- Replace four restore-only guards with Rust 1.100 `DropGuard`, preserving scoped
  cleanup and adding nested/unwind request-scope coverage. Use `trim_prefix` for
  optional subaccount hex prefixes
  ([#638 — Rust 1.100 simplifications](https://github.com/dragginzgame/icydb/issues/638)).

- Borrow accepted index contracts, schema publication identities, mutation inputs
  and inspected SQL/error values instead of passing unused ownership. Planner
  assembly and validation scans also borrow metadata they do not retain. Remove
  redundant owned SQL/index-encoding forwarding helpers and move diagnostic
  fingerprints directly. Recovery/schema/projection test helpers avoid temporary
  byte/index copies and redundant expected-value conversions. Cardinality query
  fixtures borrow inspected filters, candidates and expected rows, removing
  temporary group-order vectors. Complete Core ownership-lint cleanup through
  its callers, retaining one-use commit publication with `apply(self)` and
  slice-based covering decoders, as part of
  [#637 — Rust 1.100 lint cleanup](https://github.com/dragginzgame/icydb/issues/637).

- Carry catalog-native DDL admission through publication instead of rediscovering
  the operation from before/after snapshots. Remove intermediate delta and
  transition-plan types; retain live authority, historical-fill and empty-entity
  checks.
- Bind each admitted derivation to its source schema version/fingerprint and
  reject mismatched handoffs before physical effects. Keep historical-fill and
  structural-change coverage at admission, and add source-binding/publication
  regressions. No persisted format or public API changes are introduced.
  Wasm total/code-section bytes and IC instructions/cycles remain unmeasured.

- Encode immutable schema candidates without repeating whole-bundle validation
  or decoding freshly encoded bundles and roots. Retain bounded recovery decoding,
  publication identity checks and canonical wire bytes.
  Constructor and persisted-decode rejection tests retain projection limits;
  candidate work accounting now charges only the retained byte-hashing pass.
  This slice removes 16 production code lines and adds 11 test code lines
  (net -5), with no new type, cache or persisted format. Component admission
  checks remain at bundle construction. Wasm/IC effects are unmeasured.

- Build schema migrations and ordinary reconciliation in one owned draft per
  store, then finalize once. Remove the duplicate snapshot/catalog construction
  path and fallback candidate selection while preserving identities, lineage,
  staged activations and typed failure classifications.

  Resolve source identities, relation targets and new-entity assignments before
  mutating any store. Migration transforms and ordinary additions/removals then
  update the same snapshots and source bindings. One finalizer creates the
  immutable accepted candidate; no legacy candidate or fallback path remains.
  Catalog validation/fingerprinting is shared with borrowed inputs, and exact
  named-type validation no longer constructs a second owned value catalog.
  Preserve rekeyed-catalog admission, canonical store order, namespace checks,
  physical migration validation and bounded persisted recovery decoding.
  The rewrite adds 107 production and 9 test code lines (net +116), while
  reducing mutable construction owners and finalizers from two to one. This is
  an ownership/construction simplification, not a net source deletion.
  Persisted/public contracts are unchanged. Wasm total/code-section bytes and
  IC instructions/cycles remain unmeasured.

- Reuse target snapshots through initial creation, reconciliation and migration,
  removing separate snapshot reconstruction paths. Share generated row-constraint
  construction and complete migration relations/constraints in one pass after
  forward-reference identities are established.
  Snapshot-owned structure edits preserve unrelated identities, SQL-owned objects,
  candidate indexes/relations and allocator state. Shared snapshots copy only
  retained components; uniquely owned drafts update in place. Initial creation
  completes its existing snapshot map instead of building a second map.
  Ordinary reconciliation retains exact comparison but skips replacement vectors
  and the second index projection when fields are unchanged. Migration keeps
  field/identity reservation ahead of cross-entity edge resolution and removes
  its separate final constraint traversal. The snapshot-shell helpers, temporary
  migration-field result and migration-only row-constraint compiler are deleted.
  Active generated row constraints share binding and catalog allocation;
  staged activation and migration transform policy remain separate. Retire the old
  active check/targeted-rule constructors and migrate their test callers.
  This replacement removes 83 production code lines and adds 180 test code lines
  (net +97), including caller propagation and cross-reference/state-preservation
  regressions. The focused affected-boundary selection passes 399 tests.
  Persisted formats, publication and recovery are unchanged. Wasm total/code-section
  bytes and IC instructions/cycles remain unmeasured.
