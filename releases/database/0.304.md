# IcyDB database 0.304

## [0.304.0]

### 🩹 Fixed

- For [#335 — guarded SQL read admission](https://github.com/dragginzgame/icydb/issues/335),
  add `execute_public_sql_query_page` and its parsed-dispatch counterpart. Move
  lowered SELECT intent into the existing public scalar pager, preserving SQL
  projections, display scales, total LIMIT, canonical work receipts and opaque
  authenticated continuation. Grouped SQL reuses public group/state caps and
  its grouped continuation; metadata remains observational and separately gated.
- A finite 105-key SQL `IN` query with total `LIMIT 103` returns 100 rows and
  then three after resumption. A primary-key range alone does not satisfy public
  indexed admission. Secondary-index predicates and ordering retain the same
  eligibility and finite execution/request budgets as dynamic public pages.

### ⚠️ Breaking

- The optional native testing surface now selects Testkit 0.94.0. Its install,
  snapshot and diagnostic helpers are inherent `PocketIc` methods; old extension
  traits/prelude are removed upstream. IcyDB's exposed client/error identities
  follow this generation. Startup polling retains typed terminal errors and
  finite progression; the caller and Testkit retain runtime/server ownership.
- Adopt published Storage 0.69.0. Map operations and canonical iterators now
  return direct values; data/index/schema/journal/progress stores and their
  callers consume that API without retired collection-error branches. Ordered
  overlay traversal still preserves live overrides, tombstones, direction and
  early stop; visitor failures, record decoding, schema admission and recovery
  invariants remain fallible. Storage owns engine/codec failure traps. Existing
  images remain readable under the same format; no deletion, reset or migration
  runs. Canic is explicitly excluded from this follow-up. No IcyDB package
  version or qualification record changes.
- Replace the ambiguous generated SQL read capability with
  `sql_query_public::<INTROSPECTION>(sql, continuation)` and
  `sql_query_trusted::<INTROSPECTION>(sql)`. Both retain complete reply admission.
  The host adapter owns caller authorization and must select the public function
  after guard approval on every initial/resumed call. Canic migration and installed
  authorization remain deferred under #373; this is a native contract cut.
- Top-level SELECT DISTINCT, nonzero scalar OFFSET, global aggregate reads and
  execution EXPLAIN currently lack a bounded public contract and reject before row execution. Full scans,
  unsafe sorts and mutations also reject. Explicitly trusted operator/in-process
  SQL and its existing result type remain available. Scalar public results use
  `SqlQueryPageResult::Scalar`; grouped and metadata output use its `Statement`
  variant, retaining grouped cursors where applicable.
- DISTINCT's existing cursor-mode executor suppresses scalar scan windows for
  complete materialization/replay. Public SQL rejects it before row reads, even
  for a finite key set; a key-count proof alone does not bound its byte work.
  Trusted SQL retains DISTINCT. Regression controls cover both direct and
  expression projections, finite key sets and zero row visits on refusal.
