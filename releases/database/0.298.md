# IcyDB 0.298

## [0.298.0]

### ⚠️ Breaking

- Automatic index names now use the shared schema naming owner: a readable,
  bounded label plus a domain-tagged SHA-256 128-bit suffix over exact framed
  entity/key terms, uniqueness and canonical parsed predicate bytes. Declaration
  order and cosmetic predicate spacing/case/parentheses do not affect names.
  Optional `name = "..."` overrides use existing schema-name admission; invalid
  or duplicate names produce source-level diagnostics with examples. Exact
  parsed duplicate definitions still reject even under different labels, and
  independent model/runtime intake checks remain. No digest is treated as proof
  of injectivity. Accepted catalog/IndexId remains runtime and physical authority.
  Update name-based callers or retain selected labels explicitly; no old-name
  fallback or alias map is added. The public IndexName helper uses the same
  automatic rule and shared name bound, including its fixed label envelope.
  ([#203 — Canonical index naming](https://github.com/dragginzgame/icydb/issues/203)).
- Native targets no longer select model collection, graph validation or actor
  source generation automatically. Enable `icydb/build` in build dependencies;
  schema-only build tools enable `icydb-model/build`. Shared schema libraries
  forward their own `build` feature through every reused declaration dependency,
  and consuming build dependencies select that feature explicitly.
- Model `build`, `node`, `fragment` and graph error APIs are host build APIs.
  Runtime declarations, typed adapter contracts, normalization and validation
  remain available without them. Dependency-owned expansion support selects
  registration without requiring similarly named features in caller packages.
- Enable `wire-schema` on the public facade, Core or Schema for native Wire
  metadata. This forwards to the canonical upstream TypeScript generator and is
  independent of actor generation. Runtime Serde codecs, bytes and accepted
  schema authority remain unchanged. No database installation reset is required
  by this source/build API change.

### 🧹 Cleanup

- Fill one exact-size CHECK/NOT NULL program destination after admitting its
  backing through the whole-schema caller's existing authority. Remove both
  intermediate compiled-family vectors and their merge construction. Preserve
  CHECK-before-NOT-NULL validation, stable constraint-ID sorting, accepted versus
  pending integrity scope, required slots and single-rule activation semantics.
  Even when borrowed-source capacity is reused, every additional compiled CHECK
  now requires its own backing allowance. Typed backing refusals propagate before
  filling this destination. Expression/targeted-program allocations, auxiliary
  containers and single-activation admission remain separate open obligations
  ([#76 — Constraint program backing](https://github.com/dragginzgame/icydb/issues/76)).
- Compile unique-index write dependencies without serializing a canonical
  predicate key that has no consumer. Accepted snapshot intake remains responsible
  for encoding and field validation. Projection, normalization, dependency visits
  and bitmap construction retain the caller's existing authority; dependency
  compilation no longer charges the discarded encoding's length. Exact,
  one-short and cumulative controls cover single-field, multiple-field and
  contradiction-normalized predicates, alongside existing malformed-field and
  normalized-write-barrier coverage. Stored bytes and dependency semantics are
  unchanged; complete construction accounting remains open
  ([#76 — Predicate construction accounting](https://github.com/dragginzgame/icydb/issues/76)).
- Project accepted scalar comparisons directly from their single literal,
  removing the temporary vector previously allocated and immediately discarded.
  AND/OR children and IN/NOT IN members allocate their known destination size
  once. Scalar operators reject zero or multiple persisted operands as typed
  corruption, while NULL, membership ordering and literal-decoding errors retain
  their existing behavior. All name-bound and row-contract projection consumers
  share this owner; accepted formats and valid predicate results are unchanged.
  Full projection admission remains open
  ([#76 — Predicate normalization allocation accounting](https://github.com/dragginzgame/icydb/issues/76)).
- Narrow the SQL DDL transition planner to field additions and field-path or
  expression-index additions. Remove generated reconciliation outcomes and
  first-difference diagnostics that its sole production caller discarded.
  Generated proposals and migrations retain their existing application owners.
- Return schema-version admission classifications directly instead of wrapping
  and immediately unwrapping a general transition rejection. Preserve the exact
  admission classifier, historical-fill decoding, empty-entity proof and physical
  index-work requirements. Keep historical-fill and mixed-change refusal tests;
  exercise version refusals through DDL derivation and generated targeted-rule
  behavior through its maintained application lowerer.
- Represent each admitted schema addition with one typed plan carrying its
  physical index target where required. Remove duplicate kind, mutation-plan
  and publication-preflight representations; publication still matches the
  independently admitted target and stages index work before publishing.
  Exercise field and index plans through accepted snapshot comparison.
- Remove unread MIN/MAX fast-path rejection reasons while retaining every
  eligibility guard and the booleans consumed by routing and EXPLAIN. Remove an
  unread empty-key-list shape flag; access validation remains unchanged.

### 🩹 Fixed

- Charge each accepted and pending constraint-source visit to the caller's
  existing construction authority. Admit CHECK, NOT NULL and targeted-rule
  source-vector growth before allocation, including retained-prefix copies;
  preserve accepted-before-pending order and borrowed rule payloads. Refusal
  returns the original resource/lane/limit diagnostic before family compilation,
  rather than reporting accepted-program corruption. Exact, one-short, exhausted
  and cumulative controls cover all four request lanes and shared maintenance
  capacity, including mixed families and vector growth. No new budget, persisted
  format or recovery ceiling is introduced. Decoder allocation, catalog
  validation and the remaining compiled-program construction stay open
  ([#76 — Constraint compilation accounting](https://github.com/dragginzgame/icydb/issues/76)).
- Admit accepted predicate literal payload bytes through the caller's decode
  budget before decoding, across metadata and row-contract projections; preserve
  retained recovery and typed corruption diagnostics
  ([#76 — Predicate normalization accounting](https://github.com/dragginzgame/icydb/issues/76)).
  Scalar and membership literals share cumulative `DecodedBytes` accounting;
  NULLs and empty memberships require no payload decoding. Refusal precedes
  decoder and name work. Decoder allocation, catalog validation and compiled
  program construction remain separate open obligations.
- Pass the existing construction authority through accepted-predicate projection
  and normalization together. Charge each dispatched node and inspected field-ID
  candidate, copied name visits/bytes, NOT boxes, junction children and membership
  backing before their construction. Field/expression metadata, ordinary commits,
  pending unique indexes, constraint dependency compilation, staging, migration
  and integrity use the same owner. Typed refusals retain their resource and lane;
  explicit canonical/replay/rebuild paths acquire no new request ceiling. Exact,
  one-short and cumulative controls cover all three projection sources and all
  four request lanes, with backing refusal stopping before child/name work.
  Literal decoding retains its existing bounded decoder; complete decoder,
  schema-validation and compiled-program allocation admission remains open
  ([#76 — Accepted predicate projection admission](https://github.com/dragginzgame/icydb/issues/76)).
- Charge every dispatched predicate-normalization node before its work through
  the caller's existing `PredicateExpressionSteps` allowance. Constants, leaves
  and NOT shells no longer bypass accounting when there are no pairs or sorts.
  Absorbing branches still skip later children, failures return no partial
  predicate, and already-admitted recovery retains explicit pure normalization.
  Exact/cumulative controls cover public, trusted, diagnostic and mutation lanes;
  pair-limit controls include node visits before reaching their intended refusal.
  Canonical membership construction now also admits sort entries and comparison
  work before ordering, including its canonical-input and deduplication scans.
  Accepted scalar/enum literals, OR collapse and compact/expanded expression
  lowering share the boundary. Accepted schema sets now use the same constructor,
  including sets nested inside lists/maps/sets and membership operands. Their
  charges accumulate before outer deduplication; ordinary lists retain authored
  order and duplicates. Empty/singleton lists need no ordering allowance;
  in-place sorting adds no auxiliary backing. Membership/set ordering also
  admits each operand's comparison extent once, then reserves the largest node
  and text/blob extents against the existing comparison allowance, including
  canonical-input and deduplication scans. Scalar, nested list/map/enum and
  recursive accepted-set consumers share that owner. Empty/singleton sets skip
  this work; already-ordered inputs receive the same conservative admission.
  No second comparator, payload copies or per-comparison scratch are added.
  Exact and cumulative controls retain typed refusals and canonical results.
  Canonical map encoding now charges ordering entries, its input-order scan and
  the shared comparison allowance, including key/value tie-break payloads. The
  same encoding owner serves predicate sort keys and value fingerprints; nested
  maps and repeated key encoding accumulate under the caller's authority before
  writing bytes. Refusal preserves existing hash streams and authored children.
  Canonical map order, duplicate-key tie-breaks and digest bytes remain unchanged.
  Raw IN/NOT IN key encoding now also admits its temporary-view ordering, source
  and view canonicality scans, and deduplication. Repeated comparisons share the
  payload extent owner; direct casefolded text uses the existing transform bound
  for its resulting byte extent without folding during admission. Nested values
  retain strict encoding. Normalized membership keys skip this extra ordering,
  and empty/singleton raw lists need no comparisons. Refusal preserves the hash
  stream, while successful structural bytes and canonical digests stay unchanged.
  OR-collapse eligibility now admits field-label comparisons and duplicate-only
  value equality through the existing payload-comparison owner, including enum
  payload trees. Refusal precedes operand consumption; the first unequal pair
  skips later comparisons. Pure retained normalization keeps its explicit
  no-ceiling authority. Conjunction simplification now charges field labels and
  structural operand extents before reducing comparison pairs. Case-insensitive
  pairs reserve both text transforms through the existing lowercase allowance
  and admit their folded comparison extent before allocation. Unsupported
  operators and unrelated domains skip payload work. Conjunction reductions
  also admit stable vector compaction: every predicate shell shifted after a
  removal consumes the caller's existing step allowance before removal or
  operator replacement. All four reduction branches share the removal owner;
  operand order and retained payload ownership stay unchanged. Tail removal
  needs no shift allowance. Skipped non-comparison predicates also consume one
  step per visit, including every prefix revisit after replacement; guard-only
  scans cannot bypass the caller's allowance. Exact/cumulative refusals preserve typed diagnostics
  and return no partial predicate. Enum-literal preflight now reserves possible
  collection ordering and adjacent uniqueness checks before catalog admission,
  using shared payload extents for list elements and map keys. This conservative
  reservation also covers canonical validation and nested enum payloads without
  interpreting schema contracts again. Empty/singleton containers need no
  ordering allowance. Catalog ordering, duplicate rejection and ordinary
  non-enum list behavior are unchanged. The enum preflight also admits text bytes
  before catalog length scans and record-label checks, including canonical enum
  payloads that previously reached validation before their copy was charged.
  Validation and copying consume separate byte allowances under the same request;
  UTF-8 character limits and successful values are unchanged. General
  encoding/sorting, numeric conversion, stack and complete recovery accounting
  remain separate
  ([#76 — Bound predicate normalization work](https://github.com/dragginzgame/icydb/issues/76)).
- Add `icydb::testing::drive_startup` under the native-only `testing` feature.
  Use Testkit 0.87's async-only client and lending async observation closure;
  callers own the async runtime and explicitly close their Testkit instance.
  Reuse Testkit's initial poll, bounded simulated-time rounds, final-round
  success and typed errors; IcyDB only maps its existing Ready/Recovering state.
  Applications retain their authorized observation transport and typed terminal
  startup failures. No business operation is retried and no IC endpoint or
  lifecycle owner is added. Default runtime and Wasm graphs exclude Testkit.
  Existing isolated Canic integration remains separately qualified
  ([#315 — Published typed startup driver](https://github.com/dragginzgame/icydb/issues/315)).
- Generate consuming entity-to-Insert/Patch/Replace conversions at the existing
  typed-adapter owner. Generated and managed fields remain unauthored; updates
  retain scalar or composite keys, while nullable absence authors NULL rather
  than omission. Relation values use the existing typed IDs. A key-only
  conversion supports deletion without encoding other row fields. Checked
  encoding, accepted-field renames and stale-binding refusal retain their
  existing owners; application normalization, validation and authorization
  remain explicit. Actual compiled adapters exercise assignment, update,
  replacement, deletion and schema-binding changes. Consumer adoption and
  matched Wasm/code-size qualification remain separate
  ([#322 — Canonical whole-row mutation adapters](https://github.com/dragginzgame/icydb/issues/322)).
- Typed and SQL EXPLAIN expose the default bounded-public-read policy decision
  for the displayed accepted plan, with the canonical first rejection code and
  label. Reuse the execution policy and frozen diagnostic facts; keep the
  diagnostic-only lane's refusal separate. Context-free and mutation plans
  carry no read verdict. Authorization, cursor validation, runtime budgets and
  caller-specific page-envelope changes remain execution responsibilities
  ([#275 — Explain public-read admission](https://github.com/dragginzgame/icydb/issues/275)).

### 🧪 Testing

- Exercise native replay and fold termination after successful semantic schema
  preflight. Subprocess controls apply and independently verify valid publications;
  fault cases then remove the prepared operation, truncate the handoff vector or
  dispatch through the wrong mode. Each contradiction must terminate with SIGABRT,
  so a returned error, test panic or missed test selection cannot qualify it.
  Reuse the existing journaled-schema fixture and the real shared apply paths;
  production source and fault-return hooks remain unchanged. This is native
  termination evidence, not installed IC trap, rollback, real-counter or maximum
  callback qualification; those obligations remain open
  ([#154 — Production failure-boundary qualification](https://github.com/dragginzgame/icydb/issues/154)).
- Preserve partial unique-index ownership across decode refusal and conflicting
  retries, including expression keys, legal transfers and journaled recovery
  ([#76 — Filtered uniqueness decode boundaries](https://github.com/dragginzgame/icydb/issues/76)).
  Field-path and LOWER expression fixtures retain raw row/index entries and
  commit control after denied activation and insertion. Fresh requests report
  typed uniqueness violations; subsequent transfer/recovery and insertion keep
  ownership and generated identity intact.
- Verify decode-budget refusal for populated mixed batches and successive writes
  under one request, preserving retained entry bytes, prior committed progress
  and identity-safe retry
  ([#76 — Populated mutation decode limits](https://github.com/dragginzgame/icydb/issues/76)).
  Cover zero and one-short limits plus exact complete-operation admission.
  Preserve commit control, absent markers and accepted schema identity on
  refusal; after retry, verify the surviving update, inserted identity and the
  next generated key using a fresh request.
  Sequential-operation controls share one cumulative request allowance: the
  first commit survives refusal of the second at exhausted and one-short
  limits. Exact combined admission succeeds; a fresh retry does not skip keys.
- Qualify decode-budget insert refusal before publication, exact-limit success
  and identity-safe retry; replay partial-index writes with decode capacity
  exhausted across publication interruptions
  ([#76 — Mutation and recovery decode limits](https://github.com/dragginzgame/icydb/issues/76)).
  Preserve commit control, absent markers, empty row/index entries, schema
  fingerprint and identity high-water on refusal. Extend the existing full-index
  byte comparison matrix with decode-byte exhaustion for all four interruption
  points, alongside its existing normalization resource controls.
- Cover decode-budget refusal at later membership and nested operands, before
  index scans, and across shared unique-index/migration projection allowances
  ([#76 — Predicate decoding budget coverage](https://github.com/dragginzgame/icydb/issues/76)).
  Include exact, one-short and cumulative boundaries for field/expression
  metadata; retain the first maintenance refusal and the independent corruption
  result when retained projection has no fresh request ceiling.
- Expand partial-index recovery qualification across six normalization resources
  and four interruption points: persisted marker, partial rows, complete rows
  and checkpoint publication. Seven predicate shapes cover deep/redundant AND,
  OR membership, mixed OR, NOT, contradictions, equal-bound replacement and
  non-comparison prefixes. Restarted recovery preserves all row values and
  complete index bytes against uninterrupted writes with each selected request
  allowance set to zero. Replay/rebuild preparation also preserves counters
  before and after ordinary admission fails; new writes still require capacity.
  These tests qualify request-authority separation, not complete allocation,
  stack or IC-instruction bounds
  ([#76 — Predicate normalization recovery accounting](https://github.com/dragginzgame/icydb/issues/76)).
- Parser predicate expectations construct SQL expressions directly instead of
  translating runtime predicates back into syntax. Retain all existing parser
  cases and full-statement comparisons, including coercion spelling, membership,
  qualified fields and boolean grouping. Complete SELECT expectations share
  explicit test-owned defaults; cases retain their distinct syntax and continue
  comparing every AST field without deriving defaults from the parser.
- ORDER BY expectations construct explicit field paths, nested functions,
  arithmetic, CASE and aggregate syntax trees. Expected terms no longer invoke
  the parser, so parsing errors cannot supply both sides of their assertions.
- Nullable-row and primary-key-range fixtures reuse the existing field/index
  initializer at the shared session-test owner. Keep their field identities,
  rows and assertions explicit.
- Five fresh heap initializers share store reset, recovery and initial accepted
  candidate publication through the existing request constructor. Five single-key
  fixtures share initial snapshot/layout construction while retaining explicit
  fields, indexes and enum/record catalogs. Keep sparse-index session identity,
  journaled recovery and historical transitions separate; preserve every test
  case and assertion.
- Model graph integration targets require `build`. Workspace lint retains
  runtime-only selection and separately lints the explicit model build; workspace
  tests select generation so graph targets remain covered.
  Workflow policy checks admit that exact feature selection, continue refusing
  filtered or incomplete providers, and verify compiler admission through the
  canonical stage roster.
- Documentation admission accepts the paired development-source examples for
  this pending cut, requiring generation only in the build dependency. Released
  examples still require matching supported tags; missing, mixed, extra and
  incompatible source selections refuse.
- Schema fixtures use qualified store paths instead of imports referenced only
  by generation. The paths resolve to the same canonical store identities and
  remain valid with generation disabled or enabled through another dependency.
- Qualify runtime-only, model-only, explicit generation and explicit metadata
  graphs independently; procedural macro execution remains distinct from
  generator dependencies in the runtime library graph. Preserve renamed model
  and runtime imports and build/runtime compilation of generated actor output.
- Native metadata fixtures explicitly enable their metadata providers. The
  requested complete Linux product gate and matched full/selected comparison
  pass; native macOS and installed-IC remain separately required. No Wasm size,
  cycle or instruction improvement is claimed.
