# IcyDB 0.299

## [0.299.0]

### ⚠️ Breaking

- Adopt Storage 0.68.0 collection engines and Testkit 0.88.0 public testing types.
  Require fresh installations; reject earlier database images before recovery
  without rewriting or deleting them. Preserve current-image recovery and
  application codecs; engine/codec failures now follow Storage’s trap contract.

### 🩹 Fixed

- Admit the whole-schema row program's integrity metadata destination through
  the same cumulative TemporaryBytes authority as its main constraint backing.
  Count accepted CHECK and targeted-rule entries during existing source
  classification, allocate once, then fill and sort the admitted destination.
  Pending write gates do not acquire integrity entries. Preserve stable
  constraint identity/order, evaluation and single-activation behavior. Refusal
  retains caller resource/lane/limit/actual facts rather than becoming program
  corruption. Literal-decoder/targeted-program allocation,
  single-activation admission and complete recovery/stack accounting remain open
  ([#76 — Constraint integrity backing](https://github.com/dragginzgame/icydb/issues/76)).
- Collect required slots directly from resolved CHECK/NOT NULL programs and
  targeted-rule roots, admitting each emitted slot and all destination growth
  through the existing caller authority. Remove per-expression dependency
  vectors and repeated field-ID-to-slot projection; sort and deduplicate the
  one destination in place. Preserve the same sorted unique slot set, pending
  rule scope and separate single-activation allocation contract. Exact and
  cumulative caller limits retain typed budget failures. Literal-decoder/targeted
  program allocation and complete traversal/stack/recovery accounting
  remain open
  ([#76 — Dependency-slot backing](https://github.com/dragginzgame/icydb/issues/76)).
- Admit whole-schema schedule, integrity-entry, required-slot and
  unique-write-barrier sorting through the existing construction authority.
  Reserve the existing entry/comparison allowance and the compact sorter's
  canonical two-index-buffer byte projection before sorting; scratch consumes
  both sort-temporary and cumulative construction bytes. Preserve the sorter,
  sorted identities/slots, blocker precedence and single-activation behavior.
  Empty/singleton slices require no sort allowance. Request and maintenance
  controls cover exact, short and cumulative limits; a two-barrier control
  isolates final-sort refusal and retained blocker semantics. Literal decoding,
  validation and targeted-program construction/internal ordering, full traversal/stack and
  recovery accounting remain open
  ([#76 — Row-program sort admission](https://github.com/dragginzgame/icydb/issues/76)).
- Admit fixed-size CHECK-tree backing and expression/value dispatch steps
  through the existing whole-schema construction authority before compilation.
  Validate shape/bounds before recursive admission; reserve NOT boxes and exact
  AND/OR child-vector backing without geometric collection growth. Shared tree
  compilation retains evaluation, constraint identity and the separate
  single-activation allocation contract. Accepted/pending nested-rule controls
  cover exact, short and cumulative request/maintenance limits with typed facts.
  Literal decoder backing and validation scratch,
  targeted-program construction and complete stack/recovery accounting remain
  open
  ([#76 — CHECK-tree construction](https://github.com/dragginzgame/icydb/issues/76)).
- Admit CHECK/NOT NULL metadata lookup bounds, integrity schedule/catalog visits,
  compiled dependency-tree dispatch and required-slot deduplication through the
  existing cumulative construction authority. Reserve full lookup extents even
  when a match can be found early, include filtered integrity entries, and admit
  deduplication comparisons/movement before sorting or mutation. Keep the same
  compiler, metadata authority, required-slot set, evaluation and separate
  single-activation contract. Request/maintenance controls retain typed
  exhaustion, exact allowances and cumulative refusal. Validation/canonical-key
  work, literal decoding, targeted-program construction and complete
  stack/recovery accounting remain open
  ([#76 — Row-program scan admission](https://github.com/dragginzgame/icydb/issues/76)).
- Validate each Boolean CHECK child before extracting its canonical ordering
  key. Recursive key construction previously preceded that child's validation;
  malformed unsorted children could reach key serialization before depth, node
  or literal bounds were checked. Both catalog-backed and local snapshot
  validation now preserve those refusals before ordering. Valid canonical keys,
  accepted depth limits and evaluation semantics remain unchanged. Complete
  validation/key allocation and stack-cost admission remain open
  ([#76 — Boolean validation bounds](https://github.com/dragginzgame/icydb/issues/76)).
- Write Boolean CHECK children directly into their parent's canonical-key
  buffer, filling the existing fixed-width child-length prefixes afterward.
  Remove intermediate per-child encoded vectors and copies without adding a
  sizing walk, alternate encoder or format change. Exact nested-byte fixtures
  and width/payload boundary controls preserve canonical keys, ordering and
  accepted validation. Root-key allocation/growth, full validation admission
  and the remaining decoder/targeted-program/stack/recovery work stay open
  ([#76 — CHECK-key buffer reuse](https://github.com/dragginzgame/icydb/issues/76)).

### 🔧 Changed

- Adopt published IC Build 0.75.0 for maintained builds and the release-metadata
  editor. Replace removed maintenance-configuration readers in the consumer
  test with the supported specification contract: single builds carry the
  selected maintenance policy, while batch entries leave maintenance with the
  batch owner. Preserve retention limits, best-effort behavior and source/cache
  identity checks. This changes no IcyDB runtime API or stored format.

### 🧪 Testing

- Qualify maximum journal fill/drain/refill reuse with Storage 0.68: retain
  exact backlog limits, empty tails after every drain and stable high-water
  capacity across repeated refills after the first warm refill.
- Consolidate repeated resource and cumulative-exhaustion fact assertions in
  existing test support. Keep request-lane loops, charge calculations, expected
  results and failure-order checks at their planner and normalization callers.
  All existing test cases remain; production code and diagnostic contracts are unchanged.
