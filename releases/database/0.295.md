# IcyDB 0.295

## [0.295.0] - 2026-11-02

### ⚠️ Breaking

- Adopt Storage 0.65.0 as the sole maintained runtime and collection owner,
  removing the direct Memory dependency. Host grants use `icydb_storage_grants`
  and `AllocationGrants`; generated owner labels are `icydb_<namespace>` while
  permanent keys retain `icydb.<namespace>.`. Maps, sets and schema-control
  regions use the new `ICMAP002` B-tree frame; prior map images reject without
  reinitialization or retained-byte mutation. The retired memory-profile and
  physical-slot configuration APIs are removed. Bound hosts retain their
  configuration and current admission authority.
- This adoption targets **fresh installations only**. Earlier Memory/Storage
  images reject without mutation. No compatibility decoder, conversion, reset,
  deletion or deployment is provided. Preserve earlier binaries and backups for
  required recovery/export. Same-contract restart and recovery remain supported.
- Allocation identities use the full opaque 64-bit Storage ID in current control
  records, startup receipts and identity hashes. Fallible collection reads,
  writes, iterators and codecs propagate failure instead of manufacturing empty
  results. The current internal representations replace their prior shapes.
- Allocation diagnostics and browser DTOs report named retained allocations,
  committed generation and logical extents; retired bucket/ledger/physical
  occupancy fields are removed. Physical usage and payload occupancy are not
  inferred from logical extents. Cycle/instruction and Wasm-size deltas are
  unmeasured.

### 🩹 Fixed

- Raw and retained scalar projections consisting entirely of sibling field
  paths select their leaves in one parent-map traversal. Raw bytes receive full
  canonical validation. Requested order, repeated leaves,
  first duplicate-key matches, missing/null values and complete suffix
  validation are preserved; scratch backing is admitted before allocation.
  Historical synthesized and retained roots share first-match selection without
  cloning the parent map. Missing-root and malformed-parent diagnostics match
  ordinary expression evaluation. Mixed
  expressions, grouped projections and projections using retained
  order values keep their existing path. This partially addresses
  [#400](https://github.com/dragginzgame/icydb/issues/400); stored bytes are
  unchanged and IC instruction/cycle and Wasm-size deltas are unmeasured.
- Async request boundaries return the existing `RequestExecutionRootMismatch`
  error before polling a child beneath a different active root, replacing the
  production assertion ([#161](https://github.com/dragginzgame/icydb/issues/161)).
  `with_request_execution_async` and async `#[icydb::request_execution]` functions
  now require `Result<T, E>` with `E: From<icydb::Error>`; existing successful and
  application-error results pass through unchanged. `RequestExecutionFuture`
  names the success type and optional error type. Update infallible async
  bodies to return `Ok` and handle the awaited result. Sync boundaries retain
  their return types. Async adapter fixtures are updated, including the scale
  fixture's `Result<u32, icydb::Error>` reply; stored data formats are unchanged.
- Heap Identity commits prepare one combined checkpoint image per affected
  store before marker publication, including every advancing owner. Apply
  transfers those bytes without decoding the accepted bundle again. The retained
  image is charged to the existing temporary-memory budget before allocation;
  exhaustion or stale owners refuse before publication. Stored formats and
  per-range marker recovery remain unchanged. This partially addresses
  [#102](https://github.com/dragginzgame/icydb/issues/102): preparation still
  decodes the accepted bundle and application still writes the full checkpoint;
  IC instruction/cycle and Wasm-size deltas are unmeasured.
- Typed and SQL logical EXPLAIN project the existing accepted-schema-bound
  executor decision for secondary-index ORDER BY pushdown. Eligible routes carry
  index/prefix details and rejected routes carry their existing typed reason.
  `ExplainOrderPushdown::NotApplicable` distinguishes primary-key-only, unordered
  and grouped routes from context-free logical projections, which still report
  `MissingModelContext`. Consumers with exhaustive matches must handle the new
  variant. This partially addresses [#275](https://github.com/dragginzgame/icydb/issues/275):
  it does not simulate PublicRead admission or change query execution policy.
- Keep Building cardinality generations current across ordinary journal folds
  ([#81](https://github.com/dragginzgame/icydb/issues/81)). Fold maintenance adjusts
  only the already-scanned row/index domain and advances the existing header and
  cursor watermark atomically. Changes ahead of the checkpoint are counted by
  the next scan; clearing retains its progress without treating old counts as
  current evidence. Schema/index-domain changes still restart, and malformed
  partial evidence remains unavailable. Existing count/control formats, page
  bounds, scheduling and planner fallback are unchanged.
- Online recovery preserves reverse entries belonging to surviving heap rows
  when resetting a journaled target's index overlay
  ([#170](https://github.com/dragginzgame/icydb/issues/170)). Target deletion
  remains restricted until those references are removed or moved. Accepted
  catalogs identify live source owners; durable-source entries still follow
  ordinary journal replay. No persisted format or heap durability guarantee
  changes.
- Ordered grouped continuation seeks beyond the last emitted group's complete
  index prefix in ascending and descending order. Later pages no longer exhaust
  their group-work limit by folding earlier pages again
  ([#50](https://github.com/dragginzgame/icydb/issues/50)). Accepted index encoding,
  equality prefixes, original range bounds and cumulative work limits remain
  authoritative. Hash grouping and the cursor format are unchanged; no retained
  data migration is required. IC instruction/cycle and Wasm-size deltas are
  unmeasured.

### ⚠️ Breaking

- Remove `acknowledged_finding_page` from `SchemaMigrationCommand::Advance`.
  It never resumed a rejected migration or exposed another finding page.
  Update Rust command construction and regenerate browser/native clients
  together with the canister; old encoded Advance requests are incompatible.
  A rejected plan retains its first bounded batch (at most 64 findings), and
  repeated advancement returns the same status. Persisted migration records,
  retained findings, accepted schemas and rows are unchanged. Additional
  finding pages and generated retries after data-only corrections remain open
  in [#96](https://github.com/dragginzgame/icydb/issues/96).
- Select entity adapters and record field references through `icydb::model`
  macro imports, removing dependency-presence detection
  ([#179](https://github.com/dragginzgame/icydb/issues/179)). Direct `icydb-model`
  declarations are always schema-only, including when `icydb` is a development,
  inactive-target, disabled optional or normal dependency. Runtime consumers
  must import entity/record macros from the facade, including its prelude.
  Renamed dependencies and explicit model-path overrides retain their meaning.
  Generated runtime adapters and schema proposals retain their existing shapes;
  accepted schemas, stored data and wire formats are unchanged. No migration,
  runtime option or compatibility fallback is introduced.
- Require Rust 1.99.1 for every owned package and pin that exact compiler for
  repository development, lint, CI and release qualification
  ([#600](https://github.com/dragginzgame/icydb/issues/600)). Members inherit
  their workspace floor; the independent Canic workspace follows the same
  compiler policy while retaining its own dependency selections and lockfile.
  Applications using an older compiler must update. Wire formats, retained data
  and runtime interfaces are unchanged by compiler policy.

### 🩹 Fixed

- Reject builds with standard-library Unicode data other than 17.0.0
  ([#111](https://github.com/dragginzgame/icydb/issues/111)), keeping persisted
  case/trim index keys and query bounds on one data contract. This applies to
  downstream builds as well as repository CI. Whole-scalar mapping/property
  goldens and contextual/index-expression vectors cover the current transforms.
  No dependency, copied table, runtime branch or persisted field is added.

  compatibility decision. The guard preserves current behavior but does not
  qualify indexes built with older/unknown Unicode data or repair keys that

  upgrading; this change performs no reindexing, data reset or codec migration.
- Finish pending generated CHECK/rule applications after unrelated schema
  publications ([#90](https://github.com/dragginzgame/icydb/issues/90), partial).
  Continuation proves promotion of the recorded activation and records the actual
  accepted database head. Pending candidate heads are predictions, rather than
  publication locks. Exact submission identity, terminal replay and bounded
  journal recovery remain intact; record layouts and checksums are unchanged.
  Jobs orphaned by store-topology identity changes still require a disposition.
- Charge each conjunction comparison while preparing accepted predicates for
  complete user-index staging, migration validation/rewrite and unique-index

  These callers borrow their existing construction authority. Unique validation
