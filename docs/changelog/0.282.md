# 0.282

## [0.282.0] - 2026-10-24

### ⚠️ Breaking

- Adopt published IC Wire/derive 0.7.2. Native payload, endpoint and lifecycle
  decoders require only `DeserializeOwned`, without reserializing the result.
  The publicly re-exported Wire error removes `Noncanonical`; nonminimal
  varints and invalid primitive representations return `Malformed`.
- Maps, sets and custom visitors may normalize received data or collapse
  duplicate entries. Successful decoding no longer proves canonical ordering,
  uniqueness or equality between original and re-encoded bytes. Retain original
  frames for exact retries, signatures and hashes; enforce application-level
  ordering and uniqueness at their semantic owner.

### 🧭 Migration Notes

- Update exhaustive Wire error matches and rebuild native consumers and generated
  clients together. Existing encoder bytes, envelope identities and configured
  limits are unchanged; encoding and decoding have independent resource costs.
  The database's explicit persisted codecs are unchanged; no storage reset is
  required by this adoption. New packed fields and schema advice remain opt-in.

  Correct the previous snapshot-version mismatch

  Distinguish busy Cargo-tool admission with status 75 and support explicit,

  ([Shared #306 — Distinguish busy tool admission](https://github.com/dragginzgame/shared-tooling/issues/306)).
- Retain the incoming IC Timers 0.30.12 selection, the latest published release.
  Its published library implementation is unchanged from 0.30.11; the upstream
  update concerns probe/development Tooling and Wire integration. Timer APIs,
  deployed dependencies and lifecycle semantics remain unchanged.
- Adopt published IC Tooling 0.68.0 for the five Host packages, Build and
  Testkit. Host/Build implementation sources are unchanged from 0.67.0;
  Testkit's changed optional Wire helpers are not enabled by IcyDB. Existing
  artifact, process, file, text and fixture-lifecycle interfaces remain intact.
- Update IC Memory/Storage from 0.50.15 to 0.50.16 in the lockfile, retaining
  their existing manifest ranges.
- Update the pinned SQL correctness oracle to rusqlite 0.41.0 and bundled
  SQLite 3.54.0. Refresh the exact engine version, source identity and compile
  options, retaining strict environment and connection-policy checks. Adapt
  column-name collection to the new iterator API.
- Remove nine exact-expression checks for merge/intersection assembly, active
  branch sizing and fast-path range-spec arity. Existing compiled tests own
  ordering, duplicate handling, bounded refills, budget failures and arity
  rejection. Retain the bans on executor-side semantic encoding and bypassing
  shared stream combinators, plus lowering checks whose behavioral replacement
  has not yet been established. No runtime, public API or stored-format change.
- Remove the shell scan duplicating Rust's exhaustive plan-rejection-to-public-code
  mapping and its synthetic fixture. Keep public diagnostic documentation coverage,
  including input-only rejections, and its fail-closed inventory check.
- Replace the accumulated Shared Tooling adoption history with current ownership,
  dependency-selection and host-qualification guidance. Link the preserved Git
  history and canonical issues for unresolved obligations; keep manifests,
  lockfile and snapshot receipt authoritative for selected versions.

### 🩹 Fixed

- Recheck only the changed comparison against previously settled operands
  after equal bounds collapse to equality. Preserve first-pair precedence,
  operand representations, coercion domains and contradiction handling across
  repeated replacements. Preparation-budget metering remains tracked by
  [#76 — Repeated AND-simplifier restarts](https://github.com/dragginzgame/icydb/issues/76).
- Keep SQL `REPLACE` input unchanged when the search string is empty, instead
  of inserting replacement text at each character boundary. Preserve NULL
  propagation and ordinary nonempty replacement in preview and execution,
  including cached SQL commands. Broader text-output resource accounting remains
  tracked by [#75 — Text function amplification](https://github.com/dragginzgame/icydb/issues/75).
- Admit index-component projection only when the accepted query kind matches
  the index-owned recovery codec. Pure and hybrid plans now decline unsupported
  components before scanning instead of discarding index work and scanning again.
  Keep primary-key projections and exact-prefix constants eligible; retain
  supported covering reads, typed corruption failures, result order, limits and
  continuation. Execution EXPLAIN now reflects the selected projection route.
  Capability and decode conformance, plus cold/warm projection behavior, are
  qualified across the maintained accepted-type matrix
  ([#80 — Unsupported covering components trigger a second scan](https://github.com/dragginzgame/icydb/issues/80)).
- Count the implicit null-guard AND and optional NOT when macros admit
  `IS [NOT] TRUE/FALSE` predicate depth. Reject overflowing Boolean-test
  predicates during authoring rather than allowing them to fail later at
  schema acceptance. Preserve the existing exact boundary for comparisons
  and NULL tests. Broader group/membership depth alignment remains tracked by
  [#198 — Generated predicate depth mismatch](https://github.com/dragginzgame/icydb/issues/198).
- Allow ordinary database errors to propagate with `?` into dynamic and typed
  exhaustive-read errors without losing codes, class, origin, numeric facts or
  query-field context. Update the public-handler guide to retain typed errors
  and require explicit application-owned Wire mapping instead of stringifying
  failures. Canonical adapter-error diagnostic conversion remains tracked by
  [#255 — Typed handler diagnostic preservation](https://github.com/dragginzgame/icydb/issues/255).
- Refresh compiled SQL command eviction order after current-schema admission
  on text, retained-dispatch and mutation cache hits. A repeated command now
  outlives an older unused command under entry or byte pressure. Reuse the
  existing bounded queue without replacing cached values or accounting handles;
  retained entry/byte ceilings and other cache consumers remain unchanged.
  Parameterized compilation reuse remains tracked separately within
  [#392 — Compiled SQL cache reuse](https://github.com/dragginzgame/icydb/issues/392).
- Escape SQL report metadata at the CLI output-line boundary using Host Text.
  Count headers, index listings, DDL status, constraint findings and other
  non-table lines now follow the same terminal-control policy as table cells.
  Preserve report-owned line breaks, printable Unicode, literal backslashes,
  normal report formatting and native DTOs. EXPLAIN remains a multiline report.
  Native macOS qualification and EXPLAIN's upstream text provenance remain
  separate from this local output-boundary correction
  ([#54 — SQL terminal output safety](https://github.com/dragginzgame/icydb/issues/54)).
- Populate scalar candidate resource reservations in one vector instead of
  repeatedly merging single-resource vectors. Preserve all reserved amounts,
  overflow rejection and page admission/receipt behavior without adding cached
  state. Broader per-row accounting remains tracked by
  [#293 — Repeated page accounting](https://github.com/dragginzgame/icydb/issues/293).
- Derive calendar parts directly from bounded epoch days in the schema Date
  owner, and reuse that calendar for timestamp validation. Keep `time` only as
  a test oracle covering every supported day, month/leap boundaries, offsets
  and fractional timestamps. Preserve date/timestamp parsing, expression results,
  Wire and persisted bytes, with no public API change. A matched SQL canister
  build reduces raw Wasm by 574 bytes and optimized Wasm by 753 bytes; cycles
  and instructions remain unmeasured
  ([#393 — Date parts use the `time` crate](https://github.com/dragginzgame/icydb/issues/393)).
- Validate identity ranges by entity in one journal-row traversal, decoding each
  row key once in that check. Preserve owner-specific allocation order, duplicate
  rejection and existing-row/delete handling. Decoding reuses constructor-validated
  records instead of validating each payload again during batch assembly; direct
  construction still checks supplied records, and both routes check batch-wide
  relationships. Schema validation and entity-tag inspection borrow journal
  buffers through the same bounded schema decoder used for reconstruction,
  avoiding full encoded-bundle/root copies. Reuse of decoded bundles across
  publication stages remains tracked by
  [#273 — Repeated journal validation work](https://github.com/dragginzgame/icydb/issues/273).
- Retain a single resume key when an index chunk stops at its visit/output limit,
  and mark natural range exhaustion without copying discarded keys. Direct
  primary-row visits retain compact identities and encode only the final
  resume boundary. Preserve filtering, limits, ordering and early-stop progress
  for scalar and composite primary keys; no public API or persisted format change
  ([#420 — Scan chunks copy discarded keys](https://github.com/dragginzgame/icydb/issues/420)).
- Read lifecycle-fixture stable-memory extent from canister status instead of
  downloading the entire image just to count its bytes. Retain upgrade/rollback
  extent checks, probe-row survival, lifecycle ordering and instruction ceilings
  ([#439 — Lifecycle extent checks download stable memory](https://github.com/dragginzgame/icydb/issues/439)).
- Resolve each path-group field once per row and share the borrowed values across
  hashing, collision comparison and new-group creation. Single-field probes stay
  allocation-free; wider probes retain a temporary vector of references
  ([#437 — Path groups resolve each field repeatedly](https://github.com/dragginzgame/icydb/issues/437)).
- Reuse prepared literal and `DEFAULT` intents in mixed SQL updates instead of
  converting them again for every row. Preserve assignment order for repeated
  fields and evaluate expressions against the original row
  ([#438 — Mixed updates rebuild literal assignments](https://github.com/dragginzgame/icydb/issues/438)).
- Resolve model/runtime dependency paths before generating framework references.
  Remove both broad token-rewriting passes and redundant node-generator wrappers.
  Preserve dependency aliases, the explicit model-path override, schema-only
  consumers, generated Serde paths and actor capabilities. User fields named
  `icydb` / `icydb_model` and paths through equally named modules remain intact
  ([#182 — Generated crate-path rewriting changes user-authored names](https://github.com/dragginzgame/icydb/issues/182)).
