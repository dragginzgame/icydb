# IcyDB 0.221 — Request-Bounded Query Reliability And Resumable Reads

## 0.221.2

### 📝 Summary

- Dynamic and SQL equality, ordered-range, and non-empty `IN` filters now
  share value-independent planning templates when their complete structural
  contracts match. Different literal values no longer force full schema and
  access planning for every execution.
- Accepted-schema filter handling now rehydrates `Blob`, `Date`, `Duration`,
  `Subaccount`, and `Timestamp` literals into their exact runtime types across
  comparisons, membership, collection containment, and relation keys.
- Host SQL integration tests use bounded restorable fixtures, reducing
  repeated PocketIC installation without changing canister behavior.

### 🔧 Changed

- A query plan is IcyDB's recipe for doing the work: which index to use, which
  filters to apply, what to sort, and which fields to return. Previously, the
  literal value was part of the plan-cache key. These simplified-ID examples
  therefore compiled as three unrelated plans even though they ask IcyDB to do
  the same kind of indexed lookup:

  ~~~sql
  SELECT id, stage FROM Token WHERE id = 'token-a';
  SELECT id, stage FROM Token WHERE id = 'token-b';
  SELECT id, stage FROM Token WHERE id IN ('token-a', 'token-b', 'token-c');
  ~~~

  IcyDB now compiles a reusable exact-set template and supplies the current IDs
  when each query runs. Fluent `DynamicQuery` filters lower to the same
  template, so SQL and Rust callers share this work.
- Range queries work the same way. For example, `score >= 10` and
  `score >= 50` share the `score >= ?` template, while `score < ?` remains a
  different template because it has different behavior.
- A template still records everything that can change how a query works: the
  field and value type, operators and boolean structure, selected columns,
  ordering, limit/window, accepted schema generation, store visibility, and
  chosen indexes. Only the current literal values are left out.
- On every execution, IcyDB validates the current values and creates fresh
  lookup keys or range bounds. It never reuses `token-a`'s stored bound while
  executing the `token-b` query. One replaceable same-value memo keeps the
  already-fast repeated-identical-query case cheap without storing one plan
  for every ID.
- Template admission is limited to 64 scalar/list slots, 1,024 items in one
  list parameter, and 256 KiB of estimated parameter payload. Unsupported or
  oversized shapes continue through the existing literal-specific planner.
- The unified shared plan/template cache uses deterministic FIFO eviction with
  a 1,024-entry ceiling and 4 MiB retained-template allowance. SQL attribution
  now exposes shared-plan insertions, evictions, and rejected oversize
  residents in addition to hits and misses.
- Cursor signatures continue to bind the current normalized predicate, so
  executions sharing a template cannot exchange continuations or retain the
  first execution's literal bounds.
- Blob filter text uses bounded hexadecimal decoding, durations use exact
  millisecond text, and malformed, wrong-width, or oversized string-backed
  atoms fail closed through accepted-schema authority.
- This reduces IcyDB's cost for any same-shaped calls that remain, but it does
  not turn an N+1 workload into a batch. Application code such as Toko should
  still load many known IDs with `get_many` and reuse preloaded provenance or
  snapshot data instead of issuing one database call per token.
- Public query result shapes, Candid, accepted schema, rows, indexes, journals,
  and cursor formats remain unchanged. No removed prepared-session API or
  compatibility route returns.

### 🧭 Migration Notes

- `SqlQueryCacheAttribution` adds counters for shared-plan insertions,
  evictions, and rejected oversize entries. Downstream exhaustive struct
  construction must initialize the new fields.

### 🧪 Testing

- Host integration moves to `ic-testkit` 0.3.4. SQL canister tests acquire
  bounded cached fixtures and restore each lease to its post-install baseline,
  keeping test isolation while reducing repeated setup.
- Focused coverage includes equality/range/list-template reuse, wrong-type and
  oversize fallback, dynamic/SQL convergence, stale-bound rejection,
  projection/order separation, cursor binding, deterministic cache eviction,
  weighted resident limits, and typed filter-atom rehydration.

### 📊 Audit

- Across 1,000 matched PocketIC 15 executions, distinct-literal point queries
  fall from 850,779,546 to 416,400,274 local instructions (`-51.0566%`). The
  repeated-identical point control grows by `+0.3851%`, and the ordered empty
  scan control grows by `+0.2958%`, both within the `+1%` gate.
- Put simply, the old distinct-value benchmark compiled nearly the same plan
  1,000 times. The new path compiles the reusable shape once and binds 1,000
  sets of values. The identical-query control was already cached before this
  patch, which is why it is used to prove that parameter binding did not make
  the existing fast case meaningfully slower.
- Final raw non-gzipped Wasm grows from 2,435,362 to 2,441,943 bytes
  (`+6,581`, `+0.2702%`), within the `+8,192`-byte gate. The 612-byte Candid
  contract remains byte-identical.
- Warning-denied all-feature core and audit-canister lint, no-default-feature
  core checking, focused unit tests, PocketIC measurement, formatting, and
  matched Wasm/Candid reporting pass. Repository-wide suites remain
  user-owned push validation.

## 0.221.1

### 📝 Summary

- Adds native typed `get` and `get_many` reads that go directly from an
  entity-bound `Id<E>` to bounded store lookups without constructing a dynamic
  query or compiling a general plan.
- Preserves one result position per requested identifier. Missing rows return
  `None`, while duplicate identifiers share one physical read and decode but
  remain duplicated in the logical result.

### ➕ Added

- `DbSession::get` reads one optional generated row by typed identifier.
  `DbSession::get_many` reads up to 1,024 identifiers in request order.
- Exact-key batches have explicit limits for input count, encoded key bytes,
  distinct stored-row bytes, and logical result bytes. Their public constants
  allow callers to size batches without copying internal values.
- Four numeric runtime-boundary diagnostics distinguish which exact-key limit
  was exceeded. CLI rendering preserves that distinction in human-readable
  errors.

### 🔧 Changed

- Generated scalar and composite entities implement the existing `EntityKey`
  contract, keeping primitive or tuple encoding at the storage boundary while
  the public API remains entity-type-safe through `Id<E>`.
- Typed binding validation borrows the accepted runtime root's compiled row
  contract. Exact reads do not populate the dynamic-query plan cache and
  validate persisted primary keys before projecting generated rows.
- No accepted-schema, row, index, journal, cursor, Candid, or other persisted
  format changed.

### 🧭 Migration Notes

- The read methods are additive, but the public `RuntimeBoundaryCode` enum now
  has four exact-key variants. Downstream exhaustive matches must add cases for
  item-count, input-byte, stored-byte, and result-byte exhaustion.

### 📊 Audit

- In one matched PocketIC 15 binary, 1,000 distinct missing-key reads fall from
  895,455,213 instructions in the per-key dynamic loop to 40,555,935 in one
  native batch (`-95.4709%`). Repeating one key 1,000 times falls from
  250,988,840 to 6,606,844 instructions (`-97.3677%`).
- The standard one-entity typed audit canister falls from 2,363,342 to
  1,785,015 raw non-gzipped Wasm bytes (`-578,327`, `-24.4707%`) because its
  point-read endpoint no longer retains the general dynamic planner. Its
  64-byte Candid contract remains byte-identical.
- Focused engine, facade, macro, diagnostic, CLI, heap/journal, generated
  canister, PocketIC, instruction, and Wasm/Candid validation passes.
  Repository-wide suites remain user-owned push validation.

## 0.221.0

### 📝 Summary

- Publishes one immutable accepted-schema runtime root for the complete
  database instead of rebuilding schema-derived query state for each call.
- Binds dynamic-query and SQL plan caches to the database incarnation and the
  complete accepted root, preventing reuse across mixed schema generations.
- Removes repeated accepted-schema serialization, hashing, schema metadata
  construction, and row-layout construction from the warm query path.

### 🔧 Changed

- Acceptance and recovery compile every participating entity runtime before
  atomically publishing the new root. Existing operations retain their exact
  captured generation; newly derived contexts observe the replacement root.
- The root identity includes the durable database incarnation and a canonical
  ordered record for every registered store, including stores without an
  accepted root. Reused entity versions or fingerprints therefore cannot
  cross a database replacement or an unrelated accepted-store change.
- Entity runtimes share immutable schema lookup tables, row-decode layouts,
  fingerprints, inspection plans, and executor authority. Query and SQL paths
  borrow those structures instead of deriving private copies.
- Warm root validation compares compact persisted root records before doing
  any cryptographic work. A changed root is compiled and revalidated before
  replacing the published handle.
- SQL DDL invalidates the complete runtime root rather than one entity-local
  cache entry. Accepted schema snapshots remain the only runtime authority;
  no generated-model fallback or compatibility path was added.
- Public APIs, Candid, successful query results, ordering, accepted schema and
  persisted formats remain unchanged.

### 📊 Audit

- A matched PocketIC 15 workload of 1,000 queries reduces exact point-query
  cost from 374,226,936 to 243,649,156 local instructions (`-34.8927%`) and
  ordered empty-scan cost from 348,175,956 to 216,398,832 (`-37.8479%`).
- The matched final raw non-gzipped Wasm grows from 2,432,420 to 2,434,132
  bytes (`+1,712`, `+0.0704%`). Candid remains byte-identical at 428 bytes.
- Counter-backed tests prove zero runtime-root identity hashes, accepted
  snapshot fingerprint builds, entity-runtime compilations, or root
  publications across 1,000 warm queries. Atomic replacement and mixed-root
  cache rejection are covered separately.
- Focused all-feature checks, warning-denied lint, runtime-root tests,
  query-canister regression, instruction measurement, and Wasm/Candid
  reporting pass. Repository-wide suites remain user-owned push validation.
