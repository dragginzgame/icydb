# IcyDB 0.242 Detailed Changelog

## 0.242.0

### 📝 Summary

- Row-equivalent global counts over one planner-selected, complete
  non-nullable `Int32` leading-index range can use synchronized exact
  multiplicity metadata instead of visiting every matching row and index entry.
- Equivalent range spellings converge on the same planner-owned target. All
  other shapes retain the existing prepared executor without runtime index
  reselection.

```sql
SELECT COUNT(*)
FROM PerfAuditUser
WHERE age >= 24 AND age < 40;
```

### 🔧 Changed

- The existing fingerprint-bound exact-or-prepared command slot gains one
  first-component range variant; no new cache, authority, persisted state,
  invalidation edge, execution mode or compatibility path is introduced.
- Canonical lowering remains the only bound encoder. Target construction reads
  the encoded component from the already-lowered raw bound, and execution sums
  generation-matched multiplicities through the index metadata owner.
- Exact indexed DISTINCT and ranged row counts now share the same bounded
  first-component metadata walk. Unavailable, incomplete or over-budget
  evidence enters the existing prepared fallback.
