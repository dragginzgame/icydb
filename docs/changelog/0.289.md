# IcyDB 0.289

## [0.289.0]

### ⚠️ Breaking

- Adopt published IC Metrics 0.17.0 and embed its validated `MeasurementAggregate`
  directly in lifecycle and entity instruction reports. Remove `InstructionMetrics`,
  duplicate entity numeric fields and the parallel lifecycle accumulator. Consumers
  now read entity observations through `instructions()` and use canonical aggregate
  accessors. Empty maxima remain absent and means derive from admitted state.
  Regenerate browser contracts; old report payloads have no decoding fallback.
- Shared `MeasurementWindow` owns reset sequencing. IcyDB retains timestamps,
  attribution, replicated admission and controller reset policy. Authoritative
  journal debt remains independent. Timers still selects Metrics 0.16 transitively;
  IcyDB's reports use 0.17. [IC Metrics #99](https://github.com/dragginzgame/ic-metrics/issues/99).
  Published Timers 0.32 adoption is blocked by the pinned Canic adapter's Timers
  0.31 requirement and exclusive global-timer linker identity;
  [Canic #709](https://github.com/dragginzgame/canic/issues/709) owns the prerequisite.
- The separate bounded-recording/endpoint integration remains staged pending a
  compatible Canic adapter; this report migration does not change storage owners.

### 📦 Dependencies

- Update the exact test-only rusqlite selection to published 0.41.1 and refresh
  its pinning exception. Preserve bundled SQLite 3.54.1, its source/compile-option
  contract and the existing enabled features. The update includes upstream FFI
  slice-safety fixes; SQLite remains outside deployed canister dependencies.
- Raise the Platform requirement to published 0.7.5, already selected in the
  lockfile, without enabling additional features. IcyDB library consumers can
  combine published Timers 0.32, Platform 0.7.5 and Metrics 0.17 without Canic;
  workspace fixture adoption still needs the compatible adapter dependency
  recorded in [Canic #709](https://github.com/dragginzgame/canic/issues/709).
- Adopt committed Shared Tooling 0.27.6 with unchanged consumer entrypoints and
  source-verified snapshot payloads; adopt published IC Build/Host/Testkit 0.69.10.
  Preserve local validation selection and release ownership.
- Adopt Memory/Storage 0.54.0 as one allocation/runtime identity. Their Rust
  sources match 0.53.1; persisted formats and custody are unchanged. Timers 0.32
  still requires a compatible committed Canic adapter under
  [Canic #709](https://github.com/dragginzgame/canic/issues/709).

### 🧹 Cleanup

- Compact canonical data-row and kernel-row pages through one in-place window
  owner. Preserve stable ordering, offset/limit saturation, zero-offset truncation
  without swaps, and propagation of data-row swap errors before truncation.
  Cursor filtering and covering-page drain semantics remain separate.
  [#586 — Page windows repeat the same compaction](https://github.com/dragginzgame/icydb/issues/586).
- Pair existing entity snapshots with candidate snapshots through one physical
  removal preflight traversal. Preserve store-authority and current-bundle
  invariants, candidate/entity order, new-entity skips and one-member removal
  guards. Index removal still proves both row and user-index emptiness; field
  removal checks row presence without opening the index domain. Row refusals
  retain precedence over stale-index corruption.
  [#529 — Physical removals repeat the same entity walk](https://github.com/dragginzgame/icydb/issues/529).
- Give unique-index activation/abort, check removal and pending not-null abort
  one SQL publication frame for next-version admission, accepted identity, error
  mapping, cache invalidation and report construction. Keep the schema operations
  and their statuses unchanged; rejected operations do not invalidate authority.
  [#513 — DDL results repeat the same publication](https://github.com/dragginzgame/icydb/issues/513).
- Derive data, index and catalog allocation metadata through one snapshot frame,
  retaining role domains, entity/version order, maximum version and entity count.
  Frozen pre-change fingerprints protect the existing method and payload bytes.
  [#581 — Schema allocation fingerprints repeat the same frame](https://github.com/dragginzgame/icydb/issues/581).
- Publish prepared convergence controls and initialized journal tails through
  one sequence. Fresh bootstrap still writes its boot record only after successful
  preparation; reconciliation retains registry/marker checks and preflights only
  newly added tails. Rejected preparation leaves fresh roots retryable.
  [#582 — Control replacements repeat the same publish](https://github.com/dragginzgame/icydb/issues/582).
- Project path shape facts and reduce composite children through shared owners
  for semantic and executable plans. Preserve the first available range detail,
  all-child reverse support and empty-composite behavior.
  [#570 — Access shape summaries repeat the same walk](https://github.com/dragginzgame/icydb/issues/570).
- Encode and decode migration-cursor presence, store identity and entity through
  one shared prefix. Row primary keys and index identity/key payloads retain
  their existing field order; exact-byte, truncation and unknown-tag tests protect
  the current persisted format.
  [#544 — Migration cursors repeat the same tag](https://github.com/dragginzgame/icydb/issues/544).
- Route infallible expression visits through the canonical fallible preorder
  walker. Preserve source child order, first-error/false stopping and the separate
  postorder comparison-index walk; remove the duplicated child traversal.
  [#585 — Expression walks repeat the same children](https://github.com/dragginzgame/icydb/issues/585).
- Read cardinality generation controls through one journaled range walk. Full
  reads decode the cursor; lifecycle reads observe presence without loading its
  payload. Preserve header decoding and typed backend/corruption refusals.
  [#587 — Cardinality controls repeat the same range](https://github.com/dragginzgame/icydb/issues/587).
- Construct source-lineage versions and proposal digests once for adoption,
  new entities and migration transitions, with one store/entity ordering rule.
  Preserve route-specific resolution, existing-source skips and typed rejections.
  [#589 — Source lineages repeat the same record](https://github.com/dragginzgame/icydb/issues/589).
- Give all relation shapes one target resolution and fragment finish. Preserve
  ordered target primary keys, restrict-on-delete policy, source shapes and
  target-reference error precedence.
  [#591 — Relation targets repeat the same primary key](https://github.com/dragginzgame/icydb/issues/591).
- Use one score-and-name decision across six index selection loops. Preserve
  each family's exact-match preference, eligibility checks and winning payload;
  names break ties only when complete scores are identical.
  [#584 — Index rankings repeat the same tie-break](https://github.com/dragginzgame/icydb/issues/584).
- Give prefix and range bounds one component validator for empty and oversized
  encoded segments. Preserve shape guards, prefix-before-bound error precedence,
  low/high sentinels and included/excluded range semantics.
  [#583 — Prefix bounds repeat the same component check](https://github.com/dragginzgame/icydb/issues/583).
- Route DELETE through the same count/RETURNING result formatter as INSERT and
  UPDATE. Reuse the column labels already prepared for pre-mutation response
  admission; preserve saturating counts, projection order and atomic rejection.
  [#590 — Delete results repeat the same projection](https://github.com/dragginzgame/icydb/issues/590).
