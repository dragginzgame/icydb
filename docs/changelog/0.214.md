# IcyDB 0.214 — Exact Unsigned Identity Generation

## 0.214.0

### 📝 Summary

- IcyDB can now own a sole unsigned primary key and allocate exact
  `Nat8`, `Nat16`, `Nat32`, `Nat64`, or `Nat128` values from one accepted
  `Identity::next` policy.
- Values start at one, advance by one, never cycle, and are never reused after
  commit. Rejected work consumes no value.

### ➕ Added

- Added one shared generation path for typed adapters, structural writes, SQL
  omission, SQL `DEFAULT`, and SQL `RETURNING`. Explicit insert authorship,
  update regeneration, and absent-row replacement remain rejected.
- Added bounded active and retired owner state, stale-safe marker-bound range
  commits, journal replay and fold, live-checkpoint recovery, and exact
  interruption handling without reallocating committed values.
- Added Quick control-state and Deep live-row integrity checks. Identity
  corruption is classified before a generic key conflict can hide it.
- Schema description now reports the accepted field and generator, exact
  unsigned kind and lifetime domain, committed high-water, remaining capacity,
  and exhaustion state.

### 🔧 Changed

- Generated typed insert inputs omit the database-owned field while decoded
  rows retain its exact unsigned Rust type. Ordinary Nat fields remain
  caller-authored.
- Accepted schema snapshots now preserve and fingerprint Identity as an
  exhaustive write policy. Adding, removing, or changing that policy requires
  an explicit schema migration.
- Durable ownership is bound to the accepted database incarnation, entity,
  field, and selected store rather than an authored source name.
- Commit and recovery distinguish the committed high-water in the authoritative
  marker from the materialized state projection. Replay is idempotent only for
  the exact marker, batch, sequence, and record ordinal.

### ⚠️ Breaking

- The accepted write-policy representation, Identity control state, journal
  records, and live schema checkpoint use only their current forms. This is a
  deliberate pre-1.0 persistence hard cut: recreate incompatible development
  stores rather than upgrading them in place.
- No experimental `Sequence` spelling, old decoder, alias, reconstruction
  fallback, reseed lane, or disabled compatibility surface is retained.

### 🧭 Migration Notes

- Declare the policy on the sole required scalar primary key:

  ```rust
  #[entity(
      store = "AppStore",
      version = 1,
      pk(field = "id"),
      fields(
          field(
              name = "id",
              value(item(prim = "Nat64")),
              generated(insert = "Identity::next")
          )
      )
  )]
  pub struct Project {}
  ```

- `Nat64` is the normal general-purpose choice. Narrower kinds reduce lifetime
  capacity without promising smaller physical keys; use ULID when allocation
  must be decentralized or cross-system.
- SQL DML consumes the accepted policy, but SQL DDL cannot create, alter,
  restart, or reseed it in this release. Custom starts, steps, cycling, and
  `BY DEFAULT` semantics are unsupported.

### 🧪 Testing

- All 124 active Identity-focused core tests pass; the ignored native timing
  probe also passes when selected.
- Focused coverage includes every admitted width, exact exhaustion, all
  maintained insert frontends, stale publication, journal replay and fold,
  four interruption boundaries, active/retired integrity, and schema
  description.
- Warnings-denied Clippy passes for affected packages and fixtures, core
  checking passes without default features, and maintained SQL and SQL-free
  Wasm builds pass. Full repository validation remains release-owner operated.

### 📊 Audit

- A generated Nat64 insert measures 20,447,441 instructions, 351,484
  (`1.749%`) above the caller-authored Nat64 control. Generated Nat128 is
  374,131 (`1.862%`) above that control.
- Active or retired owner state occupies 104 checksummed bytes. A successful
  owner range adds one 65-byte journal record regardless of row count.
- Raw non-gzipped `sql_perf` Wasm is 5,271,741 bytes, up 79,001 (`1.521%`)
  from 0.213.41. The representative SQL-free typed-query Wasm is 3,725,422
  bytes.
- No third-party dependency or Cargo package version changes are included.
