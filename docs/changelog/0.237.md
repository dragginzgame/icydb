# IcyDB 0.237 — SQL Query Performance Hotspot Rediscovery

## 0.237.0

### 🩹 Fixed

- Closed ICYDB-011 by making the release candidate's tested-tree gate reject
  non-ignored untracked paths. Validation can no longer pass using source or
  fixtures absent from the candidate commit and eventual release tag; ignored
  local build artifacts remain permitted.

### ⚡ Performance

- Route schema-proven row-equivalent global SQL counts through the existing
  accepted-authority exact entity-cardinality executor. At 2,048 rows,
  `COUNT(*)`, `COUNT(id)`, `COUNT(1)` and `COUNT(*) WHERE true` fall from
  96,891,236–126,777,804 instructions to 815,629–854,348 instructions, saving
  96,075,607–125,950,053 instructions with unchanged results and zero row or
  index traversal.
- Preserve buffered semantics for nullable-field counts, `DISTINCT`, aggregate
  `FILTER` and all other non-row-equivalent shapes. A true-warm exact count
  remains at 731,475 instructions through the existing fingerprint-bound
  compiled-command cache.
- Route one safe non-nullable direct-field scalar `MIN` or `MAX` through the
  existing aggregate route planner and bounded index edge. At 2,048 rows,
  `MIN(id)`, `MAX(id)`, `MIN(age)` and supported range `MIN(age)` fall from
  102,538,164–134,776,857 instructions to 899,317–1,727,704 instructions,
  saving 100,826,309–133,049,153 instructions with at most one row and one
  index-entry read.
- Preserve complete reduction for nullable targets, expressions, aggregate
  `FILTER`, multiple extrema, unindexed fields and non-tie-free secondary
  `MAX`. A true-warm primary `MIN` costs 579,445 instructions through the
  existing compiled-command cache.

### 📊 Audit

- Reassigned the unreleased 0.237 line to a separate SQL performance
  rediscovery audit while preserving the rejected accepted-schema candidate as
  historical no-build evidence.
- Hard-cut the comparable measurement identity to
  `icydb-sql-performance/0.237/v1`; earlier evidence remains historical and
  cannot be treated as a current baseline.
- Expanded the exact-cardinality scale profile first from 24 to 42 selected
  families and then, after broader hotspot localization, to 58 families and
  174 scenarios at 16, 256, and 2,048 rows. The added pairs
  isolate projection and payload width, token branch fanout, over-cap
  materialization, `OFFSET`, non-count and distinct/filter aggregates, computed
  projection, wide indexed reads, heap/journaled full-entity work, count
  equivalence, indexed extrema, secondary ordered endpoints, and the exact
  16/17 prefix-branch boundary.
- Removed the historical 15-case token-only forced hotspot shortlist. Complete
  P1 and scale rankings plus the existing regression and grouped contract
  sentinels now select confirmation work without that prior-investigation bias.
- Captured a complete local candidate cohort: all 1,787 P1 cases and all 126
  exact scale observations passed against one Wasm. The strongest 2,048-row
  costs are hash grouping at about 139.2M instructions, scalar aggregation at
  96.9M-109.3M, and heap/journaled full-entity materialization at about 82.5M.
- Established a strict three-run clean calibration at the committed candidate:
  every run passed 1,787 P1 scenarios, 126 scale observations and 502 repeated
  cold/warm P2 confirmations. All 72,600 reviewed P2 metric envelopes and all
  scale total, normalized and slope envelopes were identical across runs.
- Kept the earlier dirty candidate evidence out of strict P2 selection. The
  clean-source gate rejected it without being weakened; only the later clean
  committed subject contributes reviewed calibration evidence.
- Recorded 245 recurring ranked scenarios already covered by maintained
  sentinels and handed 125 additional recurring scenarios to the localization
  closeout for explicit promotion or rejection. No budget or sentinel is
  changed automatically from a ranking result.
- Closed the 125-case promotion review without adding permanent sentinels: 93
  small-fixture ranking members, 17 heap/journal mirrors and 15 token variants
  duplicate dynamic rankings or maintained scale/route controls.
- Declined to add 8,192-row canaries: three exact cardinalities already separate
  the steep families from fixed-window blob and admitted token paths, and a
  longer ladder would not yet identify a removable phase.
- Reopened the initial one-intake conclusion with 141 query/cardinality probes,
  each measured cold and warm. Four independent candidate owners remain:
  count-equivalent exact cardinality, indexed `MIN`/`MAX`, secondary ordered
  early-stop, and count-specific prefix-cardinality admission. Their measured
  2,048-row opportunities range from about 40.1M to 104.2M instructions. Patch
  4 implements only the exact entity-count intake; the other three remain
  separately planned.
- Rejected a blanket prefix-branch cap raise. The admitted 16-branch page is
  1.6M-2.1M instructions slower than the 17-branch fallback at the two smaller
  fixtures before becoming about 7.0M faster at 2,048 rows, so one static cap
  change is not justified.
- Rejected the apparent 119,265,228-instruction hash/ordered grouping gap as an
  optimization basis because the paired fixtures perform different physical
  work: 2,048 versus 358 row gets and 100 versus 17 observed groups.

### 🧪 Testing

- Pinned the final 58-family scale scenario-set hash and exact eight-shard
  membership while retaining the existing result, route, fixture,
  physical-work, phase, and artifact completeness checks. All eight candidate
  shards and their 174-observation merge pass.
- Confirmed identical instrumentation overhead of 48,155 instructions (366
  basis points) across the three clean runs and zero cross-run measurement,
  semantic or physical-work drift.
- Selected run one as the reviewed opening baseline and re-derived run two's
  independent raw receipts against it without repeating measurement. The
  ordinary comparison passes with all 74,925 P2 deltas, 126 scale totals, 504
  normalized costs and 84 slopes unchanged and no regressions.
- Repeated the final 58-family profile on the clean committed subject three
  times. Every run passed all 1,787 P1 cases, 174 scale observations and 502
  P2 confirmations; all 72,600 P2 envelopes plus 174 scale totals, 690
  normalized costs and 116 slopes had zero cross-run spread. The final
  ordinary comparison also passed with all 74,925 P2 deltas unchanged.
- Aligned the fixture-identity and synthetic merge, comparison and calibration
  goldens with the final profile's 174 observations and 116 slopes. The
  synthetic fixtures retain their own exact 345 normalized-cost rows; the live
  calibration's richer facts retain 690.
- Added focused release-receipt coverage for rejected untracked source and the
  permitted ignored-artifact control.
- Added focused exact-count proofs for empty, 16-, 256- and 2,048-row entities,
  true-warm compiled-cache reuse, accepted nullable-field fallback, distinct
  and filtered controls, nontrivial predicates, unavailable journaled metadata,
  fold maintenance and same-Wasm recovery.
- Added focused extrema proofs for empty, 16-, 256- and 2,048-row entities,
  primary and secondary bounded edges, supported predicates, true-warm cache
  reuse, conservative terminal shapes, unindexed fields, explicit order/limit
  semantics, nullable mixed/all-null fallback, atomic publication, signed
  ordering and same-Wasm recovery.
- SQLite remains a correctness reference for eligible reduced-SQL cases;
  PocketIC IcyDB instructions remain the performance unit. Native SQLite timing
  is not compared with IC Wasm instructions.
