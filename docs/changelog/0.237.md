# IcyDB 0.237 Detailed Changelog

## 0.237.0

### 🧹 Cleanup

- Accepted runtime-root construction now captures each store root once, admits
  each immutable accepted bundle once, and derives every entity selection from
  that same verified authority. The complete database-wide root still compiles
  every accepted entity and fails closed on unrelated corruption.
- Fully witnessed warm roots now use the existing `SchemaStore` bundle cache as
  their freshness proof and perform no stable root-slot read. A missing,
  mismatched, or absent-root witness falls back to the authoritative full root
  capture; borrow conflicts and corruption still fail closed.
- Accepted root-key mutation is the sole volatile invalidation owner. Seven
  SQL DDL call-site invalidations and the session invalidation entrypoint were
  removed without adding a callback, epoch, second cache, or compatibility
  path.

### 🧪 Testing

- Test-only phase counters prove that a one-store cold build moved from four
  root selections and two bundle/closure passes to two root selections and one
  bundle/closure pass. A two-entity store still uses one authority pass, and
  1,000 fully witnessed warm requests perform zero root selections, authority
  passes, closure validations, entity projections, or recompilations.
- Focused native coverage retains target and unrelated publication atomicity,
  old-context immutability, absent-root fallback, journal replay/fold/reset
  witness invalidation, and current-root DDL visibility. Production-shaped DDL
  publication continues to update describe, explain, and indexed reads in
  PocketIC.

### 📊 Audit

- The implementation adds no production module, public API, Candid/export,
  stable-memory, persisted-format, configuration, mode, or independent
  invalidation state. Maintained runtime code grows by approximately 170 net
  lines to make the captured-root proof explicit while deleting duplicate
  policy; test and counter evidence accounts for most remaining source growth.
- Against exact released `v0.236.1`, typed raw Wasm changes from 2,118,718 to
  2,116,875 bytes (-1,843), while SQL raw Wasm changes from 3,284,298 to
  3,286,589 bytes (+2,291, approximately 0.07%). Candid sizes and the six
  production exports are unchanged.
