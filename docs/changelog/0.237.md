# IcyDB 0.237 — SQL Query Performance Hotspot Rediscovery

## 0.237.0

### 🩹 Fixed

- Closed ICYDB-011 by making the release candidate's tested-tree gate reject
  non-ignored untracked paths. Validation can no longer pass using source or
  fixtures absent from the candidate commit and eventual release tag; ignored
  local build artifacts remain permitted.

### 📊 Audit

- Reassigned the unreleased 0.237 line to a separate SQL performance
  rediscovery audit while preserving the rejected accepted-schema candidate as
  historical no-build evidence.
- Hard-cut the comparable measurement identity to
  `icydb-sql-performance/0.237/v1`; earlier evidence remains historical and
  cannot be treated as a current baseline.
- Expanded the exact-cardinality scale profile from 24 to 42 selected families
  and from 72 to 126 scenarios at 16, 256, and 2,048 rows. The added pairs
  isolate projection and payload width, token branch fanout, over-cap
  materialization, `OFFSET`, non-count and distinct/filter aggregates, computed
  projection, wide indexed reads, and heap/journaled full-entity work.
- Removed the historical 15-case token-only forced hotspot shortlist. Complete
  P1 and scale rankings plus the existing regression and grouped contract
  sentinels now select confirmation work without that prior-investigation bias.
- Captured a complete local candidate cohort: all 1,787 P1 cases and all 126
  exact scale observations passed against one Wasm. The strongest 2,048-row
  costs are hash grouping at about 139.2M instructions, scalar aggregation at
  96.9M-109.3M, and heap/journaled full-entity materialization at about 82.5M.
- Kept dirty candidate evidence out of strict P2 selection and calibration.
  The existing clean-source gate rejected the uncommitted candidate, so these
  rankings remain localization input rather than a reviewed baseline.
- Declined to add 8,192-row canaries: three exact cardinalities already separate
  the steep families from fixed-window blob and admitted token paths, and a
  longer ladder would not yet identify a removable phase.

### 🧪 Testing

- Pinned the expanded scale scenario-set hash and exact eight-shard membership,
  while retaining the existing result, route, fixture, physical-work, phase,
  and artifact completeness checks.
- Added focused release-receipt coverage for rejected untracked source and the
  permitted ignored-artifact control.
- SQLite remains a correctness reference for eligible reduced-SQL cases;
  PocketIC IcyDB instructions remain the performance unit. Native SQLite timing
  is not compared with IC Wasm instructions.

### 📊 Audit Footprint

- Production runtime, schemas, generated code, public APIs, Candid, exports,
  stable formats, and package versions are unchanged.
- The SQL audit canister source is unchanged. The current shared build is
  4,576,629 raw bytes; no clean predecessor rebuild was taken in this patch, so
  no numerical Wasm delta is claimed. Maintained complexity growth is one
  release-gate helper and its focused fixture plus declarative host-side scale
  cases and documentation; no runtime state or behavior axis is added.
