# IcyDB 0.222 — Streaming Execution And Key-First Operators

## 0.222.2

This release makes grouped-query ownership complete and measurable. Ordered
grouping retains only its current closed-group candidate, hash grouping owns a
bounded complete build before output, and scalar aggregate `DISTINCT` no longer
rescans every previously retained value for each candidate. Query results,
cursor encoding, SQL grammar, and persisted data remain unchanged.

### 📝 Summary

- Ordered grouping owns one active canonical group and emits it only after a
  key transition or source exhaustion proves the group closed.
- Hash grouping completes its bounded canonical aggregate table before
  emitting any group, preserving correctness when equal keys occur far apart.
- Group keys, aggregate values, and grouped top-K ordering values now
  contribute their complete retained backing to execution accounting.
- Scalar aggregate `DISTINCT` uses stable hash buckets with exact collision
  equality instead of linearly scanning its complete retained set.

### 🔧 Changed - Grouped Ownership And Accounting

- Ordered and hash routes retain separate progress contracts. Ordered
  execution may stop after a bounded set of closed groups, while hash execution
  must consume its complete bounded input before page emission.
- Grouped accounting includes canonical group-key backing and separately owned
  top-K key, aggregate, and order values. A small visible value can therefore
  no longer hide a larger retained allocation from the budget evidence.
- Request diagnostics report `peak_estimated_state_bytes` alongside peak live
  groups, aggregate states, and grouped DISTINCT values.
- Aggregate DISTINCT membership derives one stable canonical hash per value.
  Hash collisions still compare the complete `Value`, so null, nested, map,
  and scalar equality semantics do not change.

### ⚠️ Breaking

- `GroupedExecutionAttribution` adds `peak_estimated_state_bytes`. Rust source
  constructing or exhaustively matching this record must add the field.
- The measured production canister Candid remains byte-identical at 4,670
  bytes, and no cursor, query result, schema, row, index, or journal migration
  is required.

### 🔍 Audit

- The fixed ordered fixture emits ten complete groups after scanning 1,329 of
  2,048 rows. It retains one peak live group and aggregate state, owns 496 peak
  estimated state bytes, and completes in 61,095,129 instructions.
- The fixed hash fixture scans all 2,048 rows and combines three noncontiguous
  groups before output. It retains three peak live groups and states, owns
  1,516 peak estimated state bytes, and completes in 69,496,220 instructions.
- The production dynamic-query canister is 2,532,107 raw final Wasm bytes,
  53 bytes smaller than `0.222.1`. Deterministic gzip shrinks by 2,666 bytes to
  994,567 bytes; Candid and all six exported method modes remain unchanged.
- All eight planned 0.222 implementation outcomes now have evidence. The
  frozen prefix-family, two-child intersection, top-N, and clean-tag DISTINCT
  instruction gates remain explicitly open rather than being weakened or
  replaced by the grouped fixtures.

### 🧪 Testing

- Focused coverage proves ordered group-key backing is charged and released,
  oversized retained keys fail with the typed memory limit, and grouped top-K
  counts independently owned ordering values.
- Real SQL/PocketIC coverage verifies complete ordered-group output, full hash
  construction for noncontiguous keys, route-specific live-state peaks, and
  progress beyond 10,000 physical units without false exhaustion.
- Warning-denied focused lint, materialization inventory checks, executor and
  repository invariants, formatting, diff hygiene, and canonical production
  Wasm reporting pass. Repository-wide suites remain push-owned.

### 📊 Complexity

The release changes approximately `+481/-57` lines across grouped accounting,
aggregate DISTINCT admission, diagnostics, tests, contracts, and design
evidence. Explicit retained-byte accounting adds moderate internal detail;
DISTINCT admission becomes algorithmically simpler by replacing repeated
full-set scans with expected constant-time bucket lookup.

## 0.222.1

This release removes avoidable row-payload ownership from scalar projection,
bounds top-N winners and projected `DISTINCT` state, and makes DISTINCT
pagination progress complete under both adjacent and global execution. Query
results, cursor encoding, and persisted data remain unchanged.

### 📝 Summary

- Cursor-emitting projections retain compact projected/order slots instead of
  keeping unrelated raw-row payloads alive until cursor assembly.
- Access-compatible scalar scans stop at the earliest legal matched window or
  cursor lookahead. Incompatible top-N ordering retains only its bounded
  winners and their complete backing bytes.
- Projected `DISTINCT` now uses closed adjacent groups only when the complete
  projected equality tuple leads the resolved order. Every other shape uses a
  complete bounded global build with deterministic replay.
- Bounded diagnostics report DISTINCT candidates, unique rows, selected
  strategy, bounded stops, and peak retained entries/backing bytes.

### 🔧 Changed - Projection And Ordering Ownership

- Slot-owned cursor projections decode and fetch each required payload at most
  once, then release it after extracting the projected and hidden ordering
  values. Model identity and nested field-path output continue to retain the
  full row only when their successful result requires it.
- Ordinary non-DISTINCT projection constructs the final owned row directly.
  Hybrid covering execution uses compact slot/value vectors and moves values
  at their final use rather than building per-row maps or cloning through an
  intermediate transport.
- Access-compatible scalar execution stops after `offset + limit` matched rows
  for one-shot reads and retains exactly one additional lookahead for cursor
  pages. Long nonmatching tails still run to proven exhaustion.
- Incompatible-order projection and full-entity top-N select bounded winners
  during the scan. Retained accounting includes the complete backing allocation
  instead of only the visible order-key slice.

### 🔧 Changed - Complete DISTINCT Progress

- Ordered-adjacent DISTINCT retains one canonical current-group key and emits
  its representative only after a different key or exhaustion proves that
  group closed. Its cursor boundary is the final duplicate in the closed group,
  so the next group cannot be skipped.
- Global DISTINCT scans to exhaustion before emitting a page, retains the
  complete bounded canonical key set, and owns projected rows only for the
  requested output window. Later pages deterministically replay and skip the
  authenticated number of completed output rows.
- Expression projections and direct projections with hidden ordering fields
  before the complete equality tuple fail closed to global execution. Null,
  nested, and map-valued keys retain canonical equality semantics.
- DISTINCT state charges entry count, nested traversal, and complete retained
  bytes. Exhaustion returns the existing typed execution-budget error rather
  than a partial page.

### ⚠️ Breaking

- `SqlQueryExecutionAttribution` adds the optional `distinct_projection` field.
  Candid record consumers that tolerate unknown optional fields remain
  compatible, but Rust source constructing or exhaustively matching this record
  must add the field. Regenerate bindings for canisters that expose SQL
  performance attribution directly.
- No cursor token, persisted schema/data, SQL grammar, or successful query
  result migration is required.

### 🔍 Audit

- The wide top-N fixture reduces retained candidates from eleven to ten and
  moves from 81,990,155 to 81,855,556 instructions (`-0.16%`). It satisfies the
  structural ownership goal but not the frozen 20% instruction target.
- Ordered-adjacent DISTINCT processes 2,048 candidates at 89,638,376
  instructions while retaining one canonical key and 196 complete key/output
  backing bytes. The conservative global control runs at 118,401,465
  instructions, discovers 19 unique tuples, and peaks at 2,704 bytes while
  retaining only ten output rows plus canonical keys.
- The clean-tag DISTINCT comparison could not execute because its PocketIC
  server failed to bind an ephemeral socket. The frozen DISTINCT instruction
  delta remains open rather than being replaced with an inferred result.
- The production dynamic-query canister is 2,532,160 raw final Wasm bytes:
  `+5,547` from the preceding landing patch but `-1,200` from published
  `0.222.0`. Deterministic gzip is 997,233 bytes; its 4,670-byte Candid and
  exported modes are unchanged.

### 🧪 Testing

- Focused unit coverage proves adjacent closed-group resumption, deterministic
  global replay across pages, hidden-order strategy rejection, canonical
  null/nested keys, and typed retained-state exhaustion.
- Real SQL/PocketIC coverage executes both DISTINCT strategies over the fixed
  2,048-row fixture and verifies candidate, unique-row, strategy, entry, and
  backing-byte attribution.
- Focused warning-denied lint with and without SQL diagnostics, materialization
  inventory checks, executor invariants, formatting, diff hygiene, and canonical
  Wasm reporting pass. Repository-wide suites remain push-owned.

### 📊 Complexity

Across the three landing patches, the implementation changes approximately
`+1,630/-780` lines across projection, ordering, diagnostics, tests, and
contracts. Explicit bounded winner and DISTINCT progress state add moderate
internal complexity, while borrowed row transports, per-row hybrid maps,
unbounded raw-row ordering collection, and ambiguous early global DISTINCT
completion are removed.

## 0.222.0

This release establishes the correctness authority for reducing executor
materialization, converts eligible index access to charged key-first
traversal, and enables bounded sparse exact-index intersection. It does not
change successful query results, cursors, Candid, or persisted data.

### 📝 Summary

- A deterministic 2,048-row audit fixture and machine-readable matrix freeze
  23 query identities, expected rows, structural counters, and performance
  gates across sparse, dense, ordered, distinct, grouped, and large-payload
  workloads.
- A held-head stream protocol separates positioning from consumption for
  ascending and descending traversal while retaining complete work
  accounting and typed stop/failure outcomes.
- Eligible primary and index leaves reposition by physical bounds. Prefix
  families merge through a bounded heap instead of retaining an eager
  candidate vector whose size followed the row count.
- The planner may combine two or three small exact index prefixes only after
  synchronized cardinality authority proves the whole operation fits its
  fixed work and key-byte envelope. Exact compound indexes remain preferred.

### 🔧 Changed - Bounded Key-First Execution

- Physical seeks preserve the first qualifying key as an unconsumed head and
  distinguish exhaustion, page stop, hard-budget failure, and accepted-index
  corruption.
- Prefix-family execution validates child count, descriptor bytes, bound
  bytes, and merge-heap ownership before allocation. The old eager candidate
  materialization path is removed.
- Exact intersection retains only capped overlapping primary keys. Vector
  slots and encoded key backing are charged, and no row, payload, or projected
  value crosses the probe boundary.
- Missing, stale, overflowing, or over-limit cardinality evidence falls back
  to the first planner-selected index with the complete residual predicate.
  Dense candidates therefore cannot opt themselves into expensive
  intersection execution.
- `EXPLAIN JSON` identifies admitted intersection with
  `planner_exact_index_intersection` and reports the residual predicate needed
  by the safe fallback route.

### 🔍 Audit

- Resumable intersection is admitted only inside a 256-entry atomic envelope.
  No successful page stop is published between child pulls, so divergent
  child heads never enter the scalar continuation and no cursor-format change
  is required.
- Late residual `LIMIT 1` and wide top-N still fetch all 2,048 fixture rows;
  retained-value ownership and early termination remain explicitly assigned
  to later 0.222 patches.
- The sparse two-index fixture reduces row fetches from 21 to 1 and moves from
  2,545,172 to 2,535,426 instructions (`-0.38%`). Its structural target is
  satisfied, while the line's 20% instruction target remains open.
- The sparse three-index descending fixture reduces row fetches from 120 to 1
  and moves from 7,970,504 to 5,394,711 instructions (`-32.32%`). Empty overlap
  performs no row fetch, while dense and compound controls retain their prior
  physical routes.
- The production dynamic-query canister grows from 2,479,797 to 2,533,360 raw
  final Wasm bytes (`+53,563`, `+2.16%`). Deterministic gzip is 993,818 bytes;
  the 4,670-byte Candid and exported method modes are unchanged.

### 🧪 Testing

- Focused contract tests prove inventory completeness, fixture determinism,
  bounded counters, and the formal held-head/intersection progress rules.
- Seek equivalence covers ascending and descending targets, duplicates,
  interruption, changed page envelopes, typed failures, overflow, and
  randomized suffix-oracle comparison.
- Heap/journal integration covers physical repositioning, finite windows,
  maximum prefix fan-out, malformed index entries, sparse intersection,
  conservative dense fallback, and compound-index preference.
- Focused schema/canister compilation, warning-denied lint, formatting, Wasm
  measurement, and diff hygiene cover this release candidate; repository-wide
  suites remain push-owned.

### 📊 Complexity

The release adds audit fixtures, a held-head stream protocol, two physical seek
state machines, one bounded prefix merge heap, and one bounded runtime-costed
intersection strategy. It removes the row-count-owned eager prefix candidate
path. Across four landing patches the line changes approximately
`+4,660/-190` lines; executor complexity grows moderately, with most added
surface devoted to explicit accounting, corruption handling, and focused
correctness evidence. Pre-existing approved 0.221 documentation is excluded.
