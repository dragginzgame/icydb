# IcyDB 0.248 — Native U256 Admission

## 0.248.0

### 🧪 Measurement

- Froze one version-1, 2,048-row Ethereum numeric workload with full-width
  token identifiers, a mixed balance distribution, allowances, total supply
  and eight exact query shapes. The complete `NatBig` control uses
  `max_bytes = 37`, the minimum unsigned-LEB128 bound for `U256::MAX`.
- Compared constrained `NatBig`, the same type with a fixed-byte Ethereum
  adapter, and an inline `ethnum::U256` candidate. The native kernels remove
  per-value heap allocation after ingress and reduce deterministic instruction
  counts by 6.7×–162× for division, hashing, fixed-byte conversion and index-key
  encoding; the full-width group-key and `DISTINCT` container control improves
  by 4.67×.
- Confirmed that an inline 32-byte candidate leaves every measured hot value
  enum at 64 bytes and the group and reducer owners at 80 bytes. The exact-size
  group-key mirror removes per-value big-integer payload allocations for both
  small and full-width keys without changing collection-slot size.
- Measured the checked-in workload's numeric row and index-component payloads.
  Fixed-width values use 26.8% fewer combined bytes for this full-width-heavy
  distribution, while zero and one use substantially more row and key bytes.
  The current stable B-tree remains capped at 11 entries per node, so native
  `U256` alone does not improve fan-out, height or pages touched.
- Compared Candid `nat`, exactly validated 32-byte `blob` and four-`nat64`
  carriers inside the full dynamic input-value shape. `nat` is retained as the
  recommendation: it is the smallest wire representation for the frozen
  distribution, has the natural generated JavaScript `bigint` shape, and adds
  only 1,083 final raw Wasm bytes in the disposable carrier mirror.
- A disposable mirror retaining carrier plus comparison, hashing, checked
  arithmetic and fixed-byte kernels adds 17,527 final raw Wasm bytes and
  16,395 final code bytes, below the representative-actor rejection gates.
  `ethnum 1.5.3` has no default dependency feature, is MIT OR Apache-2.0, and
  passes the workspace's Rust 1.88 Wasm check.

### 📌 Decision

- Built native unsigned `U256` through the existing schema, value,
  persistence, planner and index authorities after the candidate cleared its
  production retention gates.
- Keep `I256`, bitwise SQL operators, `AVG(U256)`, Ethereum SDK dependencies
  and compatibility layers outside the line.

### ➕ Native U256 Storage And Queries

- Added public `icydb::U256` as an inline, copyable 32-byte value. Candid uses
  `nat`, with values above `U256::MAX` rejected during bounded ingress.
- Added schema fields, generated adapters, typed writes, decimal SQL literals,
  fixed-width rows and primary keys, order-preserving index keys, group keys
  and cursor values through the existing scalar authorities.
- Added equality, ordering, indexed ranges, grouping, `DISTINCT`, `MIN`,
  `MAX`, pagination and relation-key eligibility. `U256` remains a distinct
  domain and does not implicitly widen into existing numeric types.
- Kept arithmetic and `SUM(U256)` out of this storage/query patch. They remain
  the separately reviewed Patch 3 outcome.

### 📊 Production Footprint

- The actor with no U256 schema grows by 4,181 final raw bytes and 4,017 final
  code bytes, within the 8 KiB and 4 KiB gates.
- The representative U256 storage/query schema grows by 4,182 final raw bytes
  and 3,635 final code bytes, well within the 96 KiB and 48 KiB gates.
- The existing value-bearing Candid actor gains exactly `U256 : nat` in
  `OutputValue`. No artificial audit endpoint is shipped.

### 🔧 Dependencies

- Updated `convert_case` from 0.11 to 0.12.0. The release keeps the existing
  API while optimizing ASCII checks, delimiter-only splitting and character-
  case classification in model validation and normalization.
