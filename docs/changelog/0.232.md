# 0.232 Typed Public SQL Diagnostics

## 0.232.0 - 2026-08-19

### 📝 Summary

- Rejected query field references may now carry one optional typed context
  containing the exact post-normalization resolver field and its semantic
  role. Existing E-codes and numeric facts remain authoritative.
- Context is limited to 256 UTF-8 bytes and is omitted, never truncated, when
  empty, oversized, unavailable, or produced by an invalid internal pairing.

### 🔧 Changed

- One planner-root carrier and one closed attachment adapter cover predicate,
  projection, grouping, HAVING, ordering, and aggregate-target failures across
  SQL and shared dynamic/fluent planning paths. SQL lowering feeds that owner
  instead of defining a frontend-specific public error route.
- The public error record gains optional `query_field` context with compact
  numeric role identity. Server-side invalid construction becomes the
  maintained invariant error; malformed decoded client context preserves the
  base error and fails typed context validation.
- Qualified, nested, and alias-derived references retain the existing
  normalization behavior before context is captured. Quoted-identifier parse
  failures and non-field errors remain outside this contract.
- Shared CLI output validates the public context and escapes controls,
  delimiters, quotes, and terminal sequences into one line. Malformed decoded
  context is withheld and reported without losing the numeric diagnostic.

### ⚠️ Breaking

- The shared Candid `Error` record now contains
  `query_field : opt QueryFieldDiagnostic`, where
  `QueryFieldDiagnostic` is `{ field : text; role : nat8 }`. This is the only
  public ABI change; endpoint names, modes, exports, authorization, and
  successful result types are unchanged.
- This is a pre-1.0 hard cut. No predecessor error shape, compatibility
  decoder, alias, or dual dispatch is retained.

### 🧪 Testing

- Focused coverage exhausts the internal producer/role matrix, exact UTF-8
  bounds, SQL and dynamic parity, qualifier/nested/alias normalization,
  server-versus-client trust behavior, facade Candid shape, and maintained
  generated ABI fixtures.
- A real generated canister reproduces the reference `ORDER BY hp, id` failure
  as E3 with `OrderBy`, `id`, and term index 1, while a corrected query proves
  the successful route and byte-identical stable memory.
- Warning-denied SQL, diagnostics, combined, no-default, and facade package
  lanes pass together with generated-endpoint, layer-authority,
  SQL-branch-ownership, and production no-panic invariants.

### 📊 Audit

- Against exact tag `v0.231.1`, final production `sql_perf` raw Wasm increases
  by 8,632 bytes to 4,383,255 bytes. Compiler-emitted Wasm is 5,018,485 bytes
  and deterministic gzip is 1,698,845 bytes.
- Candid increases by 184 bytes to 60,640 bytes with SHA-256
  `314f542d0c10fcce423ac6729f90d4a5aabec9baaabd12788247255aa0453707`.
  The artifact retains 70 exports with unchanged names and method modes.
- An isolated Candid-role variant costs 956 additional final raw Wasm bytes
  and 131 additional Candid bytes over the selected `nat8` representation.
  Numeric roles also preserve fail-soft decoding of unknown future values.
- No persisted format, stable allocation, scheduler, timer, public mode, or
  successful-query diagnostic allocation is introduced. The reference failure
  costs 8,519,031 instructions; the corrected query costs 8,455,854 and leaves
  511,770,624 stable bytes unchanged.
- The maintained optimized successful `sql_perf` query changes by only +2,157
  instructions (+0.115%) from the exact predecessor. The Patch 2 test probe is
  absent from production Candid and Wasm exports.
