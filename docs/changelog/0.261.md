# IcyDB 0.261

## 0.261.6 — Row and Prefix Ownership Cleanup

### 🧹 Cleanup

- Move consumed row buffers into journal publication and canonical folding,
  removing full-row copies through the existing ownership conversion.
- Sort and deduplicate borrowed parent prefixes during child enumeration,
  preserving deterministic results, generation checks and child limits.
- Keep the existing checked signed-cardinality arithmetic and zero removal.
  Remove the proposed map-entry rewrite after its measured cycle regression.

### 🧪 Testing

- Retain signed-count cancellation, zero-removal and both overflow-boundary
  tests. Exercise duplicate sparse parents at the exact child-result limit.
- All 20 focused arithmetic/index-store tests, strict core lint and relevant
  invariant checks pass after removing the rewrite; formatting passes.

### 📊 Audit

- Eight pending files, including measurement evidence, with six fewer production
  Rust lines and 21 net test lines. Moves and borrows simplify ownership;
  removing the occupied/vacant branches simplifies the signed-count helper.
  No new runtime state, API, format or dependency is introduced.
- Production sources match the previously measured C31+C32 combination.
  Against matched .5, four roles shrink in raw Wasm (Game Shard: 834 bytes)
  and Game Hub is unchanged. Recovery-worker instruction changes range from
  −0.053% to +0.106%, avoiding C33's consistent increase. Total cycle changes
  remain mixed: −0.119% to +0.241%, six improvements and two increases.
  These are ownership cleanups, not a uniform cycle optimization. All 48
  investigation cases passed; source equality permits reusing that evidence
  without another Toko run. Cargo versions are unchanged.
  See the [measurement report](../design/0.261-entity-rename/c31-c33-performance.md).
- Complete the requested split of the earlier .4-to-.5 walking-32 increase:
  command application contributes 12,490,095 additional instructions (71.6% of
  the diagnostic application increase); context contributes 4,954,925 (28.4%).
  Call counts match, stationary batches get slightly cheaper, and all 16
  diagnostic cases pass. This identifies application boundaries, not an
  exclusive IcyDB cause; the frozen Canic .35 measurements do not qualify .36.
  Runtime code and dependencies remain unchanged by the profiling follow-up.
- Complete the nested actor-state/locker probe: interaction dispatch accounts
  for 78.8% of its command-instruction increase, read validation/remainder for
  18.4%, and Candid codec work for 2.8%. All 16 additional diagnostic cases pass
  with identical codec call and byte counts. Repeated locker map projection
  is a concrete downstream candidate; its savings remain unmeasured. No
  runtime change or exclusive IcyDB defect follows from this attribution.

## 0.261.5 — Recovery Identity and Key Cleanup

### 🩹 Fixed

- Bind volatile recovery readiness to the actual thread-local registry storage,
  not the address of its handle. Separate startup and request handles to the
  same registry now share recovery progress, preventing false E259 rejection
  after successful recovery. Distinct registries and commit allocations remain
  isolated; pending commit markers still block ordinary work.

### 🧹 Cleanup

- Decode data-store primary keys directly from borrowed suffix bytes using the
  existing raw-key accessors and canonical codec. Remove the temporary owned
  primary key and repeated decode while preserving entity identity, raw-key
  retention and malformed-input classification.
- Remove the unreachable second-decode error variant and restrict owned decode
  conveniences to their remaining test consumers. No public API, persisted
  format, execution mode or dependency changes.
- Use standard comparisons for decoded index components and primary keys,
  removing two redundant helpers while retaining component-count-first ordering.
- Borrow index and primary-row scan bounds instead of cloning them before iterator
  creation, preserving stable iterators' owned bounds and structural admission.
  Remove an unused scan counter and its empty destructor.
- Frame borrowed row-key and sentinel segments through the same taxonomy encoder,
  removing temporary owned keys, primary-key decoding during encoding and a
  duplicate framing path. Preserve codec bounds and typed rejection; owned
  index-key conveniences are now limited to tests.
- Decode entry row identities through the existing borrowed key decoder and
  reuse decoded keys for cardinality witnesses. Avoid copying unused index
  components and reparsing keys while preserving full-frame and witness checks.
- Borrow the retained journal publication key for cardinality bookkeeping,
  removing a redundant copy for both row puts and deletes. Publication order
  and recovery behavior are unchanged.

### 🧪 Testing

- Cover scalar, composite and maximum-width keys, exact raw-byte retention,
  every truncation and trailing bytes, plus typed unknown-kind rejection.
- Exercise both populated rename interruption points with distinct driver and
  reader handles to the same registry. Verify shared startup readiness and
  isolation of unrelated registries and commit allocations.
- Cover merged range direction and early stop over heap, live and canonical
  stores with excluded and unbounded endpoints. Check encoding rejection at
  component/primary-key limits and maximum-size sentinel roundtrips.
- Check entry identity rejection for every truncation, trailing bytes and an
  invalid primary-key discriminator, including precedence over a bad witness.
- Cover primary-row and key-only ranges across heap, live and canonical stores,
  including reverse order and canonical checkpoints isolated from live overlays.
- Correct indexed-big-integer audit fixtures for binary magnitude encoding.
  Exercise the largest accepted all-nines decimal values and adjacent rejection
  cases, including an oversized final batch row; use the corrected accepted
  boundaries in the recovery matrix. Expand only the audit fixture's LEB128
  field limit so these probes reach index admission.

### 📊 Audit

- Recovery identity uses one existing helper for admission and startup witnesses.
  Key handling reuses existing owners with no new state or format; owned decode
  conveniences are limited to tests. Including measurement evidence, the patch
  touches twenty-five files, with 73 fewer core runtime lines,
  208 net test/audit-fixture lines and documentation. Implementation is simpler
  through shared framing, borrowed bounds and removal of unused bookkeeping.
  Cargo version numbers are unchanged.
- A matched `sql_perf` actor comparison isolates the latest scan/framing cleanup:
  872 fewer raw Wasm bytes (0.0195%), with 0.0069–0.3330% fewer cycles across
  twelve indexed-write cases. Range-read cycle changes are mixed, from −1.573%
  to +0.920%; this is not a blanket query-cost improvement. Both replays match
  exactly. Earlier cleanup, subsequent row-witness, primary-row-bound and
  publication-key changes, and downstream production deltas remain unmeasured.
  See [measurement scope and evidence](../design/0.261-entity-rename/c24-c26-performance.md).

## 0.261.4 — Index Codec Cleanup

  through the existing ownership conversion instead of copying their bytes.

## 0.261.3 — Schema Validation Reuse

### 🧹 Cleanup

- Share default and rename candidate derivation between catalogue admission and
  SQL publication validation. Remove the parallel field-comparison model and
  validate the complete after-image, including unrelated catalogue metadata.
  Declared-version admission and no-op dispatch retain their existing owners.
- Share finding-receipt acknowledgement and revision-triggered validation
  restart. Keep both revision checks around Verify pages, persist restarts
  before returning progress, and preserve kind-specific scans and publication.
- Classify schema-publication preflight results without collecting a temporary
  vector. Preserve sorted preflight order, typed error priority and rejection
  of partially current publication sets.
- Reuse the admitted nullability target when updating index metadata, removing
  a nested before/after field search. Unchanged requests retain exact index
  metadata; constraint and historical-fill handling are preserved.
- Read numeric journal revisions during validation checks, owning the store
  path only when capturing a persisted revision record. Both Verify checks
  and revision-triggered restart publication retain their existing ordering.
- Reuse unique-validation page keys for Forward publication, removing the
  second key vector and per-key byte clone. Verify still checks duplicates
  and staged-key presence without emitting writes; page bounds are unchanged.
- Borrow accepted fields while binding existing-field DDL and retain only the
  names and field IDs consumed by execution. Remove redundant snapshot clones
  while preserving generated-field checks, no-ops and pending activation aborts.
- Compare raw index keys using fixed storage for the existing maximum of four
  borrowed components. Remove temporary vectors and the duplicate comparison
  loop while preserving count-first ordering and complete malformed-frame checks.

### 🧪 Testing

- Cover complete default and indexed-rename candidates, declared schema
  versions, unrelated allocator drift and unchanged-operation rejection at
  the publication boundary.
- Cover both nullability directions for an indexed field and exact snapshot
  preservation for repeated requests.
- Cover same-page historical unique conflicts, retained finding receipts and
  aborting the conflicting activation through the SQL canister.
- Extend nullability coverage to abort a pending not-null activation using the
  bound field identity, preserving its default and subsequent no-op behavior.
- Compare raw and decoded ordering across every supported component count,
  key kinds and index IDs; cover truncated, trailing and excessive-count frames
  on both sides of a comparison.

### 📊 Audit

- Sixteen files change: 51 fewer production Rust lines and 293 added test lines,
  for 242 net added Rust lines plus documentation. Implementation has fewer
  independent validation bodies and no additional state, mode, format or
  public API. Raw-Wasm, IC-cycle and instruction deltas remain unmeasured;
  dependency and Cargo version numbers are unchanged.

## 0.261.0 — Entity Rename Qualification

### 📚 Documentation

- Establish the bounded [entity-rename qualification plan](../design/0.261-entity-rename/0.261-design.md)
  for a populated same-store rename preserving data and relationships. Current
  source-migration declarations already support `from_name`; this is not a new
  rename opcode or SQL command. Native publication/recovery and generated-actor
  qualification remain separate landing slices.
- Correct the lifecycle idea's capability assessment and retain entity
  creation/removal, relation DDL and store movement outside this line's scope.

### 📊 Audit

- Initial inspection identified existing rename support. The populated fixture
  exposed a missing declaration shape for inbound dependencies; correcting it
  reuses source digests, accepted lineage and the existing publication/recovery
  flow. No persisted format or lifecycle phase changes. Generated qualification
  records +31,553 raw successor actor bytes and IC lifecycle costs; these broad
  test actors do not establish production size or an optimization claim. See
  [E3 evidence](../design/0.261-entity-rename/e3-evidence.md). The subsequent
  [read investigation](../design/0.261-entity-rename/i1-read-investigation.md)
  explains recurring query-only preparation: about 34–35 million instructions
  before an ordinary update retains accepted runtime metadata, versus about
  2 million afterwards. Restart alone does not remove this cost. No production
  optimization is included; migration-body instructions and production release
  size remain unmeasured. [Closeout](../design/0.261-entity-rename/q1-closeout.md)
  reports ready within this agreed scope, with the query-only cost limitation
  retained and full-suite/release validation user-owned.

### 🔧 Changed

- Forward the existing entity-rename fixture features through the bounded SQL
  canister, which shares the SQL actor source. This fixes strict configuration
  checking for both source and successor builds.
- Update `ic-timers` from 0.7.1 to 0.8.0. Existing generated watchdog and
  application timer calls use the current API without source adaptation; the
  lockfile changes only this dependency's version and checksum. Startup recovery,
  lifecycle composition and migration regressions pass. Updated fixture costs
  are recorded in the [tracker](../design/0.261-entity-rename/0.261-status.md);
  earlier E3/I1 measurements retain their original 0.7.1 dependency scope.
- A dependent entity may declare an explicitly versioned transition without
  local operations when its complete source change is explained solely by
  relation-target entity renames in the same plan. Meaningless version bumps
  and unrelated changes still reject before publication.

### 🧭 Migration Notes

- For `Item` to `CatalogItem`, retain `from_name = "Item"` on the renamed
  entity. Each inbound owner such as `Holder` also advances its source version
  and declares `entity_migration(entity = "Holder", from = 1)`. No artificial
  row transform, old-name alias or implicit version advance is needed.

### 🧪 Testing

- Extend populated self/inbound rename coverage to accepted identities, exact
  row/index/reverse bytes, unchanged row-mutation revision, relation enforcement,
  stale bindings/cursors, exact retries and compound-marker interruption/recovery.
  Add current-format companion codec/grammar coverage and complete-meaning proof
  tests. Native qualification and both generated-canister upgrade/retry/restart
  scenarios pass using source/successor variants of the existing SQL fixture;
  its three physical cast regressions also pass. The actor checks include
  generated typed bindings, relation and uniqueness enforcement, and zero row
  rewrites/index rebuilds. Add the application recipe for explicit inbound-owner
  transitions and matched repeated-query/catalog controls around ordinary
  updates and restart. See the
  [tracker](../design/0.261-entity-rename/0.261-status.md) for measured qualification.
