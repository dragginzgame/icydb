# IcyDB 0.252 — Nested Storage Contract

## [0.252.11] - 2026-09-04

### 🧹 Cleanup

- Structural Binary now owns the canonical decimal tuple and signed/unsigned
  big-integer limb payloads shared by direct accepted-kind fields and the
  owner-local runtime-value envelope. Scalar validation, sign decoding, limb
  traversal, and fixed two-item splitting no longer have parallel owners.
- The value-storage primitive module and the direct leaf's heap-backed tuple
  splitter are deleted. The outer direct-field and value-storage envelopes,
  bounded field admission, error mapping, and version-1 bytes remain unchanged.
- C46 removes 145 net production lines across six Rust files. One value-storage
  regression covering decimal plus signed and unsigned big integers brings the
  complete seven-file code delta to 124 net lines removed, with one module and
  three optimized Wasm functions deleted.
- Exact global aggregation now carries one fallback state. Non-candidates,
  unavailable exact metadata, and exact attempts that cannot produce a row all
  converge before the prepared-plan owner resolves the accepted authority.
- The separate `Disabled` and authority-bearing fallback variants, optional
  fallback authority, and two one-use authority adapters are deleted. C47
  removes 46 net production lines across three Rust files without changing
  exact results, prepared execution, cache identity, diagnostics, or interfaces.
- Structural index range readers now receive only their resolved store, bounds,
  and limit. Store-path lookup remains in the commit-owned outer view, while
  entity identity and index metadata no longer cross reader implementations
  that never consumed them.
- Registry, canonical-commit, and preflight-overlay readers now share one
  key-owned row-identity decoder with the existing index-plan corruption
  mapping. The planner also drops the entity-path and uniqueness context that
  reached only ignored terminals. C48 removes 93 net production lines across
  nine Rust files without
  changing range order, limits, overlay precedence, stored bytes, or errors.
- Raw index keys now own retained bound-byte accounting used by merged scans,
  cardinality preparation, covering prefix merges, and physical prefix-family
  construction. Their four identical local helpers are deleted.
- The route-owned prefix expansion budget now validates the existing 128-child
  ceiling for both covering and physical consumers before charging or
  allocation. Two validators and their duplicate boundary tests converge on
  one owner and one maintained test. C49 removes 30 net lines across seven
  Rust files without changing limits, charge ordering, or query behavior.
- Scalar key-stream resolution now branches directly on the route's existing
  streaming contract, with canonical fallback resolution owned by the
  execution-attempt kernel. The one-use strategy enum and borrowed resolution
  context are deleted while verified-route dispatch and predicate-program
  lifetime ownership remain unchanged. C50 removes 78 net production lines
  across two Rust files.
- Unsafe multi-prefix execution now uses one unit fallback state. Covering
  execution still declines it and incompatible physical ordered paths still
  fail closed; the prefix vector discarded by every production consumer and
  observed only by its incidental unit test is removed. C51 also restores
  final-item placement for the connected route-contract test module.
- The diagnostic registry now contains only errors with a maintained production
  emitter. Grouped rows remain valid successful results through their dedicated
  typed and SQL result surfaces.
- The potentially breaking pre-1.0 hard cut removes 21 orphaned codes spanning
  retired response narrowing, access requirements, row projection, SQL
  ordering and write boundaries, and migration details. Their public detail
  variants, host-rendering branches, and diagnostic-only test are removed too.
- The remaining numeric registry is compacted from E1-E285 to E1-E264; no
  aliases, reservations, fallback decoding, or predecessor mappings remain.

### 🧭 Migration Notes

- Consumers that persist or match raw numeric error codes must refresh their
  mappings for the current E1-E264 registry.
- Existing diagnostic-bearing integrity jobs and startup/recovery receipts must
  be recreated by reinstalling or regenerating the current form. Predecessor
  numeric mappings are not decoded or translated.

## [0.252.8] - 2026-09-04

### ⚠️ Breaking Changes

- Removed the standalone hidden `sql_statement_entity_name` parser and changed
  hidden core public-update/delete admission plus generated facade update
  admission to consume the sealed parsed dispatch directly. There is no
  raw-SQL compatibility adapter beside the maintained generated ingress.
- Removed the unused public `ReadIntentKind`, `TraceReuseEvent`,
  `ExplainAggregateTerminalPlan`, and execution-descriptor type exports. Read
  intent had no live consumer, aggregate EXPLAIN always stored only
  `Unspecified`, and the descriptor vocabulary is an internal renderer detail.

### 🧹 Cleanup

- Mutation compilation, exact and bounded updates, public delete policy,
  resumable-update admission, DDL binding, and facade response projection now
  borrow one parsed statement and its entity identity from the ingress-owned
  `SqlStatementDispatch`. Generated query, update, and DDL routing use that
  same artifact instead of reparsing raw SQL at each layer.
- The change adds no feature, mode, persisted state, execution route, format,
  fallback, or compatibility path. Seventeen Rust source files add 89 net
  lines for explicit dispatch plumbing, while parser ownership and runtime
  flow are simpler.
- Ordinary dynamic, grouped, projection, aggregate, exact-aggregate, and SQL
  query execution now receives only its prepared plan from the shared cache.
  The hit/miss outcome is named and retained only by the cache and the verbose
  SQL `EXPLAIN` path that renders it.
- Removed the dead aggregate-EXPLAIN wrapper and query-plan clone, compact
  execution-tree and standalone node-JSON renderers, an impossible projection
  node variant, and stale attributed-terminal guidance. C30 spans 23 Rust
  files and removes 315 net lines; implementation shape is materially simpler.
- Nullable scalar-slot views now own their one conversion into runtime values.
  Lazy cache materialization, direct projection, and predicate comparison use
  that owner instead of repeating null/value matches.
- Dense and sparse direct row readers now delegate accepted-field decoding to
  the persisted-row contract owner instead of maintaining a second leaf-codec
  dispatch. C31 spans six Rust files and removes 13 net lines, including its
  owner-local regression test and module ownership headers.
- List, set, and map macro nodes now select their identical generated-trait
  baseline and implementation strategies through one collection policy in the
  existing node-trait owner. Concrete iterator, conversion, normalization,
  validation, and visitor implementations remain type-specific. C32 spans four
  Rust files and removes 59 net lines.
- Required `CREATE INDEX` and `ALTER TABLE` forms now share one accepted-entity
  binding policy instead of repeating missing-name and qualified-name mismatch
  handling in field, index, and constraint binders. Targetless `DROP INDEX`
  retains its distinct optional binding contract. C33 removes 47 net production
  lines; its owner-local contract test leaves the four-file slice 7 net lines
  smaller overall.

  on-canister entity-cost report remains the entity hotspot authority, Canic
  remains the endpoint-cost authority, and enforced execution budgets remain
  unchanged.

- Production and test source changes span 74 files and remove 1,884 net lines;
  implementation shape and state space are materially simpler.

  production actor, final raw Wasm falls from 1,906,076 to 1,905,935 bytes, a
  141-byte reduction. Gzip falls by 11 bytes, function count is unchanged, and
  Candid is byte-identical. This is principally a source-complexity cut rather
  than a Wasm optimization.
- Focused all-feature and no-default core/facade checks, public compile
  contracts, affected execution tests, CLI diagnostics, strict package lint,
  and the maintained Wasm build pass. The full repository/workspace suite
