# IcyDB 0.252 — Nested Storage Contract

## [0.252.6] - 2026-09-03

### ⚠️ Breaking Changes

- Removed the `diagnostics` and `request-diagnostics` feature axes, detailed
  SQL/request attribution DTOs, generated attribution endpoints, and duplicate
  total-only endpoint spellings without aliases or fallback paths.
- SQL parsing, compilation, cache lookup, execution, and result shaping now
  return their ordinary maintained contracts directly. The shared plan cache
  retains only the hit/miss fact rendered by verbose `EXPLAIN`.

### 🧹 Cleanup

- Deleted the off-canister SQL performance matrix, baselines, calibration and
  report formats, CI workflows, shard orchestration, and detailed attribution
  fixtures. The remaining focused audit canister records one complete local
  instruction delta and verifies result parity; it is not a metrics product.
- Kept the single optional `metrics` feature and heap-only entity hit/total/max
  report as the runtime authority, with endpoint attribution owned by Canic.
- Removed orphaned parser/compile phase timers, cache counter transport,
  projection/grouped observers, and cache outcome fields rather than keeping
  dormant instrumentation behind another mode.

### 📊 Audit

- Accepted-schema authority, execution budgets, storage reports, execution
  traces, and SQL `EXPLAIN` semantics remain unchanged. The full
  repository/workspace suite remains user-owned.
- The hard cut removes 42,992 net lines across 202 files, including 9,664 net
  runtime/actor lines. Against immutable `v0.252.5`, the maintained
  `sql_perf` production actor removes 120,774 raw Wasm bytes, 106,268 code
  bytes, 13,142 data bytes, 288 defined functions, seven indirect calls, 21
  exported methods, and 45,666 gzip bytes.

## [0.252.5] - 2026-09-03

### ⚠️ Breaking Changes

- Replaced the compact/extended retained-metrics graph with one optional
  `metrics` feature and one heap-only `MetricsReport`. `icydb_metrics()` now
  accepts no window argument and returns entity path, hits, total attributed
  instructions, and maximum attributed instructions; `icydb_metrics_reset()`
  resets that window. The extended endpoint, event report, sink override,
  window filter, and old counter DTOs are removed without aliases.
- Generated `icydb_query` endpoints now return `SqlQueryResult` directly.
  `SqlQueryPerfResult`, the unused facade SQL perf-attribution mirror DTOs, the
  ordinary dynamic/typed live-page attribution terminals, and their route/cache
  envelope types are removed. Downstream clients must regenerate Candid
  bindings and use Canic for endpoint-level instruction attribution.
- Hard-cut `TypedBindingError`, `TypedRowError`, `TypedWriteError`, and
  `TypedQueryError`. Typed binding, ordinary reads, row projection, and writes
  now return the single `TypedOperationError` adapter/database boundary.
- `TypedExhaustiveQueryError::Row` is replaced by
  `TypedExhaustiveQueryError::Operation(TypedOperationError)`. Generated
  `typed_binding` helpers and maintained downstream fixtures use the canonical
  error directly; no aliases or conversion shims remain.

### 🧹 Cleanup

- Entity-owned projection, aggregate, exact-key, and mutation work records
  directly into one on-canister accumulator. Replicated execution is detected
  at the span owner, so query calls do not perform heap writes that the IC would
  discard; Canic remains the endpoint authority. The SQL shell no longer
  decodes or renders a second performance envelope.
- Removed the extended-metrics audit actor, duplicate Wasm comparison subject,
  event/sink tree, route-capture execution branch, cache miss classifiers, and
  mutation index-delta annotations that existed only for the retired reports.
  Removed the frozen 0.217 endpoint-ABI renderer and fixture rather than
  carrying an obsolete pre-1.0 contract beside generated endpoint authority.
  The separate `diagnostics` feature remains available for explicit audit
  tooling and is not a metrics mode.
- Made `DeterministicSecondaryOrderContract` the single owner of whether a
  variable-prefix multi-lookup or branch-set access shape requires a full
  secondary-index order match.
- Planner access satisfaction and executor pushdown consume that decision from
  access-shape facts, while covering caches the same classifier result instead
  of locally mapping access variants to policy. Route selection, rejection
  details, and public interfaces remain unchanged.
- Converged SQL-DDL unique, check, and not-null constraint removal on one
  publisher that retires a validation job exactly for a validating activation.
- Made the supported single-trailing-wildcard `LIKE` prefix shape one predicate
  classifier shared by direct predicate parsing and SQL expression lowering.
- Made grouped finalization compile route-owned `HAVING` through one helper,
  replacing three identical compiler/error-conversion blocks.
- Made accepted field-path and expression index access and mutation share one
  predicate-owned persisted-SQL normalization boundary while preserving the
  separate strict corruption-reporting integrity boundary.
- Made `SELECT`, `UPDATE`, and `DELETE` share one ordered-window suffix parser;
  their statement-specific trailing-clause diagnostics remain unchanged.
- Restored required ownership and boundary headers across the affected core and
  integration modules, and attached the displaced secondary-order contract
  documentation to its type.
- Replaced predecessor-labeled unknown-field probes with neutral unexpected
  fields while retaining strict decoding coverage only for the current format.
- Structural and generated typed patches now share one accepted-field write
  cell lowerer for database-owned-field rejection, default semantics, nulls,
  and authored values. Dynamic save variants lower with their explicit
  canonical mode instead of rediscovering it from the request.
- `MutationMode` is the single save taxonomy consumed by accepted mutation
  diagnostics and constraint scheduling.
- Exact first-component range cardinality and numeric aggregation now share
  one generation-matched, range-bounded metadata fold. Their planner-selected
  terminals share one target, store, readiness, work-cap, charge, and
  completeness envelope while retaining their distinct result semantics.

### 🔧 Maintenance

- Updated the host-only integration harness from `ic-testkit 0.8.9` to `0.9.0`
  and its pinned PocketIC runtime from 15 to 16. The current SQL performance
  environment now requires `pocket-ic-server 16.0.0`; evidence captured with
  another server version remains historical and incomparable.
- Fixture Cargo execution and SQL performance evidence capture/validation now
  consume the same resolved build profile, SQL/Candid/path policy, and exact
  maintained feature set. A feature-policy change therefore changes the built
  subject and its recorded comparable identity together.
- Wasm build execution and report generation now receive one shared option
  vector and consume the same typed, sealed resolved configuration. Reports
  reject invalid profile/mode labels and Candid-artifact drift, derive exact
  features from maintained policy, and no longer claim path remapping for
  debug or ordinary release builds.
- The maintained actor policy table is now the only fixture name/package
  inventory. Per-actor build caches index that authority without repeating its
  twenty-one identities, and consumers can inspect but cannot construct an
  invalid resolved build configuration.
- Native upstream types now come from the complete `ic_testkit::pocket_ic`
  re-export introduced by 0.9. Fixtures, startup policy, snapshots, and
  extension traits remain under `ic_testkit::pic`; IcyDB does not add a direct
  PocketIC dependency or retain the narrower convenience re-exports as a
  competing import path.
- Hard-cut the current diagnostics-attribution identity and cache-mode policy
  to their only maintained version-1 encodings. Current evidence decodes only
  that form; older artifacts remain historical rather than gaining a legacy
  decoder or upgrade bridge.
- Kept the dedicated SQL performance actor metrics-free so it remains the
  neutral query-execution baseline. Its production surface exports no IcyDB
  endpoints, while local builds expose only fixture reset/load controls;
  endpoint compile fixtures conditionally declare metrics with the feature.
- Rebased instruction review ceilings on PocketIC 16 and removed comparisons
  against incomparable PocketIC 15 predecessor samples. Exact rows, cache
  outcomes, storage reads, index work, and bounded watchdog convergence remain
  the primary regression contracts; coalesced watchdog delivery may use any
  positive sample count within the existing maximum.

## [0.252.1] - 2026-09-01

### ➕ Added

- Added complete-hash grouping for accepted scalar paths through named records.
  SQL and structural queries now share one accepted-schema identity for nested
  keys, including missing/null collapse, mixed direct/path tuples, grouped
  expressions, raw-key `HAVING`, ordering, limits, and continuation cursors.

  ```sql
  SELECT profile.rank, COUNT(*)
  FROM Player
  GROUP BY profile.rank;
  ```

### 🔧 Changed

- Preserved the direct grouping representation and hot loops while selecting
  path-aware readers only for queries that contain a scalar path. Grouped cache
  identity now reuses the existing field-expression representation, and row
  decoding stores one mutually exclusive prepared decode choice.
- Complete accepted path indexes can now select the existing ordered grouping
  route. Omission-capable nullable indexes remain ineligible unless the query
  predicate proves that omitted rows cannot match; mixed direct/path keys must
  still match one ordered composite-index prefix.
- Runtime-enabled consumers can now author schemas through
  `icydb::model::prelude` with only the public `icydb` facade in their manifest.
  The independently published `icydb-model` package remains available for
  schema-only tooling.
- Every published intra-workspace dependency now uses the exact workspace
  version. Release versioning advances those pins with package versions so
  Cargo cannot combine contract-coupled IcyDB crates from different patch
  releases.

### 🩹 Fixed

- Treat a null intermediate record as an omitted path-index key during both
  index rebuild and ordinary index maintenance. It no longer surfaces as
  persisted-row corruption, and grouped planning rejects that incomplete
  stream unless the query excludes the omitted rows.
- Fixed [issue #12](https://github.com/dragginzgame/icydb/issues/12): model macro
  expansion now resolves through `icydb::model` when `icydb-model` is not a
  direct dependency, while exact internal pins turn version skew into a Cargo
  resolution failure instead of generated-code errors inside registry crates.

### 📊 Audit

## [0.252.0] - 2026-09-01

### ➕ Added

- Added `DbSession::bind_typed_input` so structural writes can consume an
  existing generated record, enum, or collection through one exact current
  accepted binding. The method reuses `TypedInputValue`, returns the ordinary
  `InputValue` root, and adds no bound-value wrapper, parallel encoder, or new
  mutation route.

### 🔧 Changed

- Removed automatic Cargo build-cache deletion from release cleanup and the
  aggregate validation/build target. Release, package, publish, deployment,
  and push workflows now preserve the validated cache; `make release-clean`
  removes only transient release state, while Cargo cleanup remains an explicit
  manual action.

### 📚 Documentation

- Published one normative nested-storage contract owned by accepted schema.
  Scalar member paths through required or optional named records retain their
  exact projection, filter, order, distinct, aggregate-expression, prepared,
  and eligible index cells; they do not become grouped keys or raw `HAVING`
  terms.
- Defined lists, sets, and maps as owner-local repeated aggregates. Existing
  root list/set predicates remain available, but repeated-member traversal,
  collection expansion, multikey indexes, nested relations or uniqueness, and
  subpath mutation are explicit pre-1.0 non-goals.
- Added a maintained named-list authoring example whose accepted
  `length_range_inclusive` rule owns the durable maximum. Anonymous
  `value(many, ...)` retains general physical limits without gaining a second
  inline capacity spelling.
- Reconciled foundations, query, SQL, write, schema-authoring, and diagnostic
  guidance around one canonical contract and whole-field mutation authority.

### 🩹 Fixed

- Hard-cut unknown structural root fields and dotted subpath targets from an
  executor invariant to the existing executor-origin runtime-unsupported
  boundary. The change removes unused error plumbing and adds no diagnostic
  variant, payload, mutation route, or compatibility path.

### 📊 Audit

- Verified that accepted nested-leaf metadata, query lowering, DDL binding, and
  generated references fail closed before repeated-path execution or catalog
  mutation and introduce no scan fallback.
