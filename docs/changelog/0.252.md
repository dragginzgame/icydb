# IcyDB 0.252 — Nested Storage Contract

## [0.252.5] - 2026-09-03

### 🧹 Cleanup

- Made `DeterministicSecondaryOrderContract` the single owner of whether a
  variable-prefix multi-lookup or branch-set access shape requires a full
  secondary-index order match.
- Executor pushdown now consumes that planner-owned fact instead of maintaining
  an identical policy helper. Route selection, rejection details, and public
  interfaces remain unchanged.
- Converged SQL-DDL unique, check, and not-null constraint removal on one
  publisher that retires a validation job exactly for a validating activation.
- Made the supported single-trailing-wildcard `LIKE` prefix shape one predicate
  classifier shared by direct predicate parsing and SQL expression lowering.
- Made grouped finalization compile route-owned `HAVING` through one helper,
  replacing three identical compiler/error-conversion blocks.
- Made accepted field-path and expression index mutation share one persisted
  predicate compiler while preserving the separate corruption-reporting
  integrity boundary.
- Made `SELECT`, `UPDATE`, and `DELETE` share one ordered-window suffix parser;
  their statement-specific trailing-clause diagnostics remain unchanged.

### 🔧 Maintenance

- Updated the host-only integration harness from `ic-testkit 0.8.9` to `0.9.0`
  and its pinned PocketIC runtime from 15 to 16. The current SQL performance
  environment now requires `pocket-ic-server 16.0.0`; evidence captured with
  another server version remains historical and incomparable.
- Native upstream types now come from the complete `ic_testkit::pocket_ic`
  re-export introduced by 0.9. Fixtures, startup policy, snapshots, and
  extension traits remain under `ic_testkit::pic`; IcyDB does not add a direct
  PocketIC dependency or retain the narrower convenience re-exports as a
  competing import path.

### 📊 Audit

- Sixteen production files remove 49 net lines. Six internal owners replace
  exact policy or mechanism copies without adding an allocation, public
  surface, execution route, persisted state, format, compatibility path, or
  behavior axis. Implementation shape is simpler.
- A clean same-tool comparison against immutable `v0.252.4` reduces the
  representative `group_path_sql_query` actor from 3,558,845 to 3,557,917 raw
  bytes and from 3,366,149 to 3,365,245 code bytes. Data falls by 36 bytes and
  defined functions by one; 793 indirect calls, nine exports, and the
  11,644-byte Candid interface remain exact. Gzip increases by 2,157 bytes as
  secondary context.
- Against the already-measured secondary-order-only candidate, the maintained
  membership controls move by only +456 instructions for `IN` and -212 for
  `NOT IN`, both below 0.03%.
- `ic-testkit` and PocketIC remain outside the representative canister's
  `wasm32-unknown-unknown` dependency graph, so the host-harness update has no
  raw Wasm or canister-runtime performance delta. It adds no IcyDB API,
  execution route, persisted state, format, compatibility path, or behavior
  axis; implementation shape remains neutral.
- Three host integration files change imports only. The dependency owner and
  runtime flow are unchanged, while upstream simulator types now have one
  explicit source boundary.

### 🧪 Testing

- Focused SQL parser, predicate parser/lowering, grouped `HAVING`, index-plan,
  DDL publication/removal, `LIKE`, secondary-order, and membership runtime
  coverage passes, as do strict all-target/all-feature core linting and the
  repository formatting, invariant, and whitespace gates. The updated
  integration package compiles across all test targets; focused cache,
  performance-environment, and PocketIC 16 canister-runtime coverage passes.
  The full repository suite remains user-owned.

## [0.252.4] - 2026-09-02

### 🧹 Cleanup

- Made the canonical `UnaryOp`, `BinaryOp`, `Function`, and `AggregateKind`
  enums the direct projection-diagnostic context. Four private numeric adapter
  mappings and their duplicated exhaustive matches are removed.
- Replaced the remaining numeric projection-access code with one explicit
  internal `ProjectionAccessKind` enum. The hard cut adds no conversion layer,
  allocation, generic owner, execution route, persisted state, cursor, format,
  compatibility path, or public API.
- Removed three planner error wrappers and their duplicate constant tables.
  Planner validation now converts canonical operators and functions once into
  the stable diagnostic-fact enums stored by its internal error boundary.
- Converged two identically implemented projection-to-executor error adapters
  on one internal terminal across scalar and grouped execution.
- Removed the duplicate `ExprPlanTypeClass`. Type inference now retains its
  canonical `ExprType` values until the planner error boundary converts them
  directly into stable diagnostic facts.
- Made `BinaryOp` the shared owner of general numeric-arithmetic lowering.
  Builder preview, aggregate input, compiled execution, and projection
  evaluation no longer maintain four parallel exhaustive mappings, and
  impossible non-arithmetic input now fails closed rather than defaulting to
  addition.
- Replaced the projection-function `QueryError` roundtrip with compact internal
  invalid-call, projection-reason, and numeric outcomes. Builder and executor
  callers now lower those facts exactly once at their respective boundaries.

### 📊 Audit

- Twenty-five production files remove 373 net lines. Most executor-file movement
  is the mechanical propagation of the single error terminal; focused test
  expectations move to maintained enums, with one semantic regression test for
  the executor-facing function-error boundary.
- Clean same-tool comparisons against immutable `v0.252.3` reduce
  `default_empty` by 4 raw/data bytes, `one_entity_typed_query` by 150 raw and
  145 code bytes with one fewer function, and `group_path_sql_query` by 2,579
  raw, 2,533 code, and 44 data bytes with two fewer functions. All three actors
  retain exact indirect-call and export counts and byte-identical Candid.
- Measured independently after the first 0.252.4 candidate, removing
  `ExprPlanTypeClass` saved 155 raw/code bytes in the SQL actor and 146 raw/145
  code bytes plus one function in the typed actor. Shared arithmetic lowering
  then saved another 1 raw and 15 code bytes in the SQL actor while adding 12
  data bytes and two defined functions; it was retained because raw/code do not
  grow and one fail-closed semantic owner replaces four mappings. The
  function-error hard cut then saved 2,345 raw and 2,338 code bytes plus three
  functions in the SQL actor; its only other actor effect was 4 fewer data
  bytes per control.
- Focused diagnostic, type-inference, compiled-expression, projection, and
  grouped-fold tests pass, as do the repository invariant gate and strict
  all-target/all-feature core linting. The full repository suite remains
  user-owned.

## [0.252.1] - 2026-09-01

### ➕ Added

- Added complete-hash grouping for accepted scalar paths through named records.
  SQL and structural queries now share one accepted-schema identity for nested
  keys, including missing/null collapse, mixed direct/path tuples, grouped
  expressions, raw-key `HAVING`, ordering, limits, and continuation cursors.

  ```sql
  SELECT profile.rank, COUNT(*)
  FROM Player
  GROUP BY profile.rank;
  ```

### 🔧 Changed

- Preserved the direct grouping representation and hot loops while selecting
  path-aware readers only for queries that contain a scalar path. Grouped cache
  identity now reuses the existing field-expression representation, and row
  decoding stores one mutually exclusive prepared decode choice.
- Complete accepted path indexes can now select the existing ordered grouping
  route. Omission-capable nullable indexes remain ineligible unless the query
  predicate proves that omitted rows cannot match; mixed direct/path keys must
  still match one ordered composite-index prefix.
- Runtime-enabled consumers can now author schemas through
  `icydb::model::prelude` with only the public `icydb` facade in their manifest.
  The independently published `icydb-model` package remains available for
  schema-only tooling.
- Every published intra-workspace dependency now uses the exact workspace
  version. Release versioning advances those pins with package versions so
  Cargo cannot combine contract-coupled IcyDB crates from different patch
  releases.

### 🩹 Fixed

- Treat a null intermediate record as an omitted path-index key during both
  index rebuild and ordinary index maintenance. It no longer surfaces as
  persisted-row corruption, and grouped planning rejects that incomplete
  stream unless the query excludes the omitted rows.
- Fixed [issue #12](https://github.com/dragginzgame/icydb/issues/12): model macro
  expansion now resolves through `icydb::model` when `icydb-model` is not a
  direct dependency, while exact internal pins turn version skew into a Cargo
  resolution failure instead of generated-code errors inside registry crates.

### 📊 Audit

- Froze one comparable scalar record-path grouping schema and actor with direct,
  required-record, optional-record, complete-index, omission-index, mixed-key,
  bounded-loader, SQL query, mutation, and DDL shapes. The actor adds no public
  performance instrumentation and is available as an explicit Wasm report
  subject without expanding the default actor set.
- Measured and removed three zero-benefit planner-owner candidates. The broad
  nominal form added about 3.8 KiB to unaffected SQL-off actors, a transparent
  newtype retained about 215 raw bytes, and an erased alias still added 27 raw
  and 37 code bytes to the exact downstream control.
- The comparable-actor slice changed no production source. The maintained SQL
  actor and downstream controls therefore retain their exact predecessor
  behavior and footprint; the comparable actor and exact predecessor overlay
  are byte-identical at 3,551,458 raw and 3,358,917 code bytes.
- The completed hash-grouping slice adds 9,417 raw and 9,200 code bytes to the
  comparable actor with 37 defined functions. The SQL-off entity controls add
  about 2.5 KiB fixed cost with effectively unchanged entity slope, while the
  path-normalized frozen Toko Miner control adds 2,922 raw and 2,870 code bytes.
  Exact Candid, exports, and indirect-call counts are retained.
- Ordered path-index admission adds 3,131 raw and 3,144 code bytes to the
  comparable actor over the hash-only slice, for cumulative growth of 12,548
  raw bytes, 12,344 code bytes, and 31 defined functions from `v0.252.0`. The
  SQL-off reachable controls remain below their 4 KiB fixed allowance with
  raw/code entity slopes 10 bytes below the predecessor and no function-slope
  growth. Consolidating path resolution makes the empty actor 646 raw and 625
  code bytes smaller without changing its Candid, exports, or indirect calls.
- The cumulative closeout removes duplicate plan/explain grouping fingerprint
  traversal and an allocated field projection. The final feature actor adds
  11,320 raw and 11,119 code bytes with 28 functions; the SQL-off one/ten
  controls add 2,386/2,373 raw bytes with -13-byte raw/code slope drift and no
  function-slope growth. A clean same-tool frozen Toko A/B adds 3,596 raw and
  3,540 code bytes with 19 functions, passing the fixed 4 KiB/24-function gate
  with exact Candid, exports, and indirect calls.

### 🧪 Testing

- Registered the retained schema/actor with fixture build policy and Wasm
  measurement contracts, including exact source hashes and the unchanged
  11,644-byte Candid boundary.
- Reproduced direct ordered and complete-hash grouping rows, resources, and
  route evidence below the frozen instruction ceilings. The group-key owner now
  lands with user-visible scalar-path hash grouping instead of as an
  independently taxed execution axis.
- Added a native 2,048-row direct-group correctness control and exact
  required/optional/mixed scalar-path rejection coverage. The retained nested
  index DDL workloads also exposed the predecessor's structural index-value
  serialization defect; it is recorded as an ordered-index precondition rather
  than frozen as expected behavior or folded into this planner slice.
- Added complete, omission-capable, predicate-excluding, and mixed-prefix path
  index coverage. The frozen ordered path workload is 14.82% above its mirrored
  direct control, below the 15% ceiling, while current direct ordered/hash
  routes remain within 1% of their frozen instruction baselines.
- Added a facade-only model consumer whose manifest names only `icydb`, plus
  invariants for the re-export, published dependency edges, exact workspace
  pins, and release-bump synchronization.
- Closed the final runtime matrix at 17.49% cold and 14.69% ordered path
  premiums. Three direct-control runs were exact; ordered and complete-hash
  instructions remain within 0.27% of `v0.252.0`. Focused contracts, strict
  package linting, repository invariants, and the maintained Wasm matrix pass;
  the full repository suite remains user-owned.
- Replaced the maintained-canister policy test's historical actor count with
  exact fixture/build-policy identity parity. New actors no longer require an
  unrelated magic-number update, while missing, duplicate, or mismatched
  canister/package registrations still fail closed.

## [0.252.0] - 2026-09-01

### ➕ Added

- Added `DbSession::bind_typed_input` so structural writes can consume an
  existing generated record, enum, or collection through one exact current
  accepted binding. The method reuses `TypedInputValue`, returns the ordinary
  `InputValue` root, and adds no bound-value wrapper, parallel encoder, or new
  mutation route.

### 🔧 Changed

- Removed automatic Cargo build-cache deletion from release cleanup and the
  aggregate validation/build target. Release, package, publish, deployment,
  and push workflows now preserve the validated cache; `make release-clean`
  removes only transient release state, while Cargo cleanup remains an explicit
  manual action.

### 📚 Documentation

- Published one normative nested-storage contract owned by accepted schema.
  Scalar member paths through required or optional named records retain their
  exact projection, filter, order, distinct, aggregate-expression, prepared,
  and eligible index cells; they do not become grouped keys or raw `HAVING`
  terms.
- Defined lists, sets, and maps as owner-local repeated aggregates. Existing
  root list/set predicates remain available, but repeated-member traversal,
  collection expansion, multikey indexes, nested relations or uniqueness, and
  subpath mutation are explicit pre-1.0 non-goals.
- Added a maintained named-list authoring example whose accepted
  `length_range_inclusive` rule owns the durable maximum. Anonymous
  `value(many, ...)` retains general physical limits without gaining a second
  inline capacity spelling.
- Reconciled foundations, query, SQL, write, schema-authoring, and diagnostic
  guidance around one canonical contract and whole-field mutation authority.

### 🩹 Fixed

- Hard-cut unknown structural root fields and dotted subpath targets from an
  executor invariant to the existing executor-origin runtime-unsupported
  boundary. The change removes unused error plumbing and adds no diagnostic
  variant, payload, mutation route, or compatibility path.

### 📊 Audit

- Verified that accepted nested-leaf metadata, query lowering, DDL binding, and
  generated references fail closed before repeated-path execution or catalog
  mutation and introduce no scan fallback.
- Corrected the diagnostic exception found by the entry audit. Unknown
  structural root fields and dotted subpath targets now return the existing
  executor-origin runtime-unsupported diagnostic before commit preparation;
  no new diagnostic variant, payload, mutation route, or fallback was added.
- Documentation changes add no Candid, public payload, accepted-schema,
  persisted-format, planner, cursor, mutation, recovery, or Wasm-reachable
  runtime state.
- Measured the maintained SQL-off reachable pair at 2,870,622 and 2,910,737
  final raw bytes, reductions of 568 and 506 bytes from `v0.251.0`. Code drops
  by 558 and 494 bytes, exact Candid and 717 indirect calls remain unchanged,
  and the 40,115-byte nine-entity raw delta continues to pass the 8 KiB gate.
- The method-isolation probe attributes about 61 raw bytes per added entity to
  the generated structural-input adapter itself. The final representative
  actors execute a generated list of records through single and atomic-batch
  writes and measure 2,910,803 and 2,952,157 raw bytes; the 41,354-byte delta is
  4,595 bytes/entity and passes the 8 KiB gate. Exact 190-byte Candid remains
  unchanged.

### 🧪 Testing

- Verified single and atomic-batch unknown-field rejection, including a late
  dotted target that leaves an earlier valid batch item uncommitted, while a
  complete root-field replacement continues to succeed.
- Added a no-SQL generated compile contract and focused nested-value regression
  covering scalar fields, unit and payload enums, null optionals, records, and
  lists through the one typed input encoder and the single/batch structural
  terminals.
- Added an executable PocketIC regression that binds the generated nested root,
  verifies affected-row and returned-row cardinality for one single write and
  one atomic two-row batch, and checks the exact unavailable-source adapter
  error for an unbound generated record.
- Extended release-cleanup invariants to reject direct or indirect Cargo
  cleanup from release, package, publish, push, and aggregate build workflows.
