# IcyDB 0.215 — SQL Structural Verification

## 0.215.5

### 📝 Summary

- Fixed atomic deletion of a relation source and its target in one mixed
  structural batch.
- Completed the accepted mixed-batch proof matrix for final-row relation and
  unique-index behavior, cross-entity admission, late failure neutrality,
  ordinary replacement, managed timestamps, durable constraints, and
  caller-key recovery.
- No public API, persisted format, response format, Cargo feature, dependency,
  or package version changed.

### 🩹 Fixed

- Delete-side relation validation now recognizes an explicit source deletion
  in the canonical final-row overlay. An absent committed source without that
  overlay proof remains corruption.
- Same-batch source updates that remove a reference and same-batch source
  deletions now release the target, while inserted or updated final sources
  that retain the reference still reject before publication.
- The ordinary caller-key mixed recovery fixture now crosses marker, journal,
  first-row, complete-row, and state-materialization interruption boundaries
  without allocating or changing Identity state.

### 🧪 Testing

- Focused accepted-catalog fixtures prove relation target visibility for
  inserted and updated sources, source/target deletion, retained-reference
  rejection, unique swaps and delete releases, cross-entity rejection, missing
  targets, insert collisions, and replacement semantics.
- The maintained targeted-rule fixture now proves one managed timestamp across
  a successful mixed batch and state neutrality when a later row violates a
  durable rule.
- Focused core tests, formatting, warnings-denied Clippy, no-default
  compilation, and diff hygiene pass. Full workspace and push-time validation
  remain user-owned.

### 📊 Audit

- The correction adds one production branch that consumes the existing final
  overlay override signal; the remaining delta is focused test and release
  evidence.
- Runtime performance and raw Wasm were not remeasured because the patch adds
  no storage operation or new runtime owner. No performance or size decision
  depends on this release.

## 0.215.2

### 📝 Summary

- Added one bounded public same-entity structural mutation batch that combines
  inserts, updates, replacements, and deletes under one accepted snapshot,
  operation timestamp, final-row overlay, marker, journal, and recovery
  outcome.
- Made the single structural mutation and insert-batch helpers delegate to the
  canonical mixed owner. No cross-entity transaction API, compatibility lane,
  or second commit protocol was added.

### ➕ Added

- Added `execute_trusted_structural_mutation_batch`, returning save
  after-images and delete before-images in deterministic input order.
- Added stable typed diagnostics for empty, over-count, over-byte,
  mixed-entity, and duplicate-target batches.
- Added exact 4,096-operation, 16 MiB staged structural-byte, and 1 MiB encoded
  public-result bounds, independent of the existing 4 MiB row and 16 MiB
  marker/journal limits.

### 🩹 Fixed

- Raised generated canisters to `ic-memory 0.12.3`, adding fallible
  foreign-memory preflight and bounded bootstrap policy identities while
  retaining the unified thread-local runtime and stable ledger format.
- Delete relation proof now reads the canonical batch-final overlay, allowing
  a source update/delete to release an old reference while still rejecting a
  final source that references a deleted target.
- Identity journal validation now distinguishes existing-key updates/deletes
  from interleaved generated inserts. Only the exact contiguous new range
  advances Identity state; rejection before marker publication consumes
  nothing.
- Public result conversion and exact Candid-size validation now complete before
  marker publication, so a committed batch cannot later report conversion
  failure.
- Scoped the new 1 MiB result limit to the mixed-batch entrypoint. Existing
  single-mutation and insert-only convenience calls retain their prior response
  behavior and skip the mixed-only Candid size serialization, while SQL
  `RETURNING` continues to enforce its independent query-owned response limit.
- The commit interruption harness now proves marker, journal, partial-row,
  complete-row, and state-materialization recovery for ordinary caller-key
  mixed batches as well as Identity writes.

### 🧪 Testing

- Added focused mixed update/insert/delete result-order, duplicate-target
  neutrality, exact bound, mixed Identity range, and journaled partial-row
  recovery tests.
- The two generated SQL oversized-`RETURNING` integration tests prove that a
  1.05 MiB seed still commits through the legacy single-mutation surface and
  the later SQL update rejects without mutation under its own diagnostic.
- The maintained heap/journaled write matrix remains within its frozen
  instruction ceilings after legacy single writes stop paying the mixed-only
  result-size serialization cost.
- Updated SQL-free and SQL-enabled public compile fixtures for the mixed
  facade. The marker and journal byte formats are unchanged.

## 0.215.0

  than treating repeated seeds, literals, or fixed family slots as broader
  coverage.
- SELECT and mutation evidence derives from one frozen catalog of supported
  interactions and retains exact structural receipts through generation,
  replay, reference comparison, and coverage reporting.

### ➕ Added

- Added a deterministic catalog covering all 106 current SQL contract
  features, 102 reachable providers, and 43 reviewed interaction obligations.
  Every required interaction closes to one exact provider and scheduled
  witness.
- Added two accepted SELECT profiles and catalog-bound typed witnesses for
  indexed ranges, nullable values, aggregation, ordering, scalar composition,
  bounded windows, and nine maintained rejection categories.
- Added an accepted-default mutation profile with independent state and index
  modeling. Authored, omitted, insert-`DEFAULT`, update-`DEFAULT`, and
  update-preserve intent remain distinct through SQL and typed ingress
  evidence.
- Added query-scoped diagnostics for compound-range extraction, residual
  predicate evaluation, membership normalization, prefix deduplication,
  exclusion pruning, and branch-cap decisions.

### 🔧 Changed

- Replaced the fixed SELECT family/slot schedule and four fixed mutation
  vectors with catalog-bound witness schedules and full structural
  signatures.
- Bundled SQLite comparison now validates complete SELECT and mutation
  schedules, including rows, `RETURNING`, affected counts, accepted defaults,
  post-state, and logical secondary-index state.
- Generator, replay, receipt, corpus, performance-profile, and diagnostics
  identities move directly to their current version-2 forms. These are
  test-evidence hard cuts; no old decoder, translation, or compatibility path
  remains.

### 🧪 Testing

  SQLite-reference tests, all 16 active SQL-correctness tests, and the complete
  256-case SELECT and 240-case mutation schedules.
- Focused live-canister checks prove one physical compound-range child with no
