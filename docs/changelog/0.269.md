# 0.269 — Bounded writes and SQL assignments

## [0.269.1]

### 🩹 Fixed

- Origin relabeling preserves the original error class when numeric facts do
  not fit the destination code. Retain valid facts and leaf identities using
  the canonical diagnostic schema; discard incompatible context without
  replacing corruption or unsupported errors with invariant violations.
  Reuse the existing fact payload, while fresh construction still rejects
  invalid fact schemas. Cover corruption, unsupported and invariant rejection
  cases, recovery fact families and every plain class/origin combination
  ([#288](https://github.com/dragginzgame/icydb/issues/288)).

### 🔧 Changed

- Adopt one Host 0.10.0 generation with Testkit 0.28.0. Artifact staging uses
  the consolidated streamed writer with explicit replacement and permission
  policy; write diagnostics retain publication phase, original cause and
  separate staging-cleanup errors. Preserve source permissions, existing
  outputs on producer failure, cache formats and the accepted server bundle.
  Prepare the newly selected Testkit CLI through explicit setup before offline
  validation; no retained-data reset or IcyDB public API change is required
  ([#307](https://github.com/dragginzgame/icydb/issues/307)).
- Update every CI and scheduled SQL workflow checkout to reviewed Checkout
  7.0.1 and the Rust toolchain Action to its reviewed checksum-retry revision.
  Prepare the Rust matrix's configured temporary directory before toolchain
  installation so the Action can create its install log. Keep the selected
  Rust versions and credential policy
  ([#10](https://github.com/dragginzgame/icydb/pull/10),
  [#297](https://github.com/dragginzgame/icydb/pull/297)).
- Static CI prepares the locked Testkit CLI for substitute-server fixtures,
  while only Tier B and native host qualification provision a real server.
  Native core, workspace and Tier A gates keep their existing tests and
  concurrency without a server prerequisite. Testkit retains setup, admission
  and lifecycle ownership ([#334](https://github.com/dragginzgame/icydb/issues/334)).
- Refresh the existing snapshot to committed Shared Tooling 0.2.6, extending
  its 83-file selection only with the shared release and formatting Make
  includes. Standard release routing, conflicting-goal checks, manifest sorting
  and rustfmt now use the common owners. Keep local release/receipt policy,
  Cargo directories and derive sorting; derive sorting runs after tool admission
  and before the shared format recipe, with rustfmt last. Preserve literal
  hook paths, reusable-fixture companion admission and Apple's Make tool lookup;
  setup and Testkit caller fixtures carry the selected Make includes
  ([#309](https://github.com/dragginzgame/icydb/issues/309),
  [Shared #91](https://github.com/dragginzgame/shared-tooling/issues/91),
  [Shared #92](https://github.com/dragginzgame/shared-tooling/issues/92),
  [Shared #89](https://github.com/dragginzgame/shared-tooling/issues/89),
  [Shared #73](https://github.com/dragginzgame/shared-tooling/issues/73),
  [Shared #85](https://github.com/dragginzgame/shared-tooling/issues/85)).
- Storage reports count entries and raw key/value bytes during their existing
  rollup traversal, including malformed entries in physical totals. Heap and
  journaled reports retain entity/alias rollups, index namespaces, allocation
  metadata and corruption counts without separate count/byte scans
  ([#263](https://github.com/dragginzgame/icydb/issues/263)).
- Structural mutation batches borrow the row contract already compiled in the
  captured accepted inspection plan. Insert, update, replacement, before-image
  normalization and row-local constraints share that authority; identity setup
  and returned-field projection are prepared once per participating entity.
  Remove the redundant owned-contract before-image wrapper. Root/store checks,
  historical fills, write policies, diagnostics and atomic commit remain at
  their existing boundaries; no cache or alternate write route is added
  ([#260](https://github.com/dragginzgame/icydb/issues/260)).

## [0.269.0] - 2026-10-09

### 🩹 Fixed

- Adopt canonical Shared Tooling 0.2.2. CI tool publication now atomically
  replaces the exact executable path, refusing a destination that became a
  directory during installation. The prior installer could instead overwrite
  a child beneath that directory. Preserve failed candidates and existing
  destinations; require the baseline Perl prerequisite before installation
  effects ([Shared #88](https://github.com/dragginzgame/shared-tooling/issues/88),
  [#309](https://github.com/dragginzgame/icydb/issues/309)).

### 🔧 Changed

- **Potentially breaking:** prefix UPDATE and public bounded DELETE now reuse
  exact UPDATE's 4,096-key scan ceiling, authoritative primary-key traversal
  and one-key overflow probe. Late or missing matches reject with E194 before
  any write instead of scanning an entire table. Exact UPDATE retains its
  separate affected-row assertion. E194's numeric identity and fact layout are
  unchanged; Rust consumers must use `WriteScanBudgetExceeded` and
  `SQL_WRITE_SCAN_BUDGET_EXCEEDED` for the renamed diagnostic
  ([#217](https://github.com/dragginzgame/icydb/issues/217)).
- Single-call UPDATE accepts field references and bounded scalar RHS expressions.
  Every assignment reads the original row; all computed results pass accepted
  field admission before one atomic commit. Literal, NULL and DEFAULT intent
  remain supported. Resumable jobs reject expressions before job creation with
  E282, preserving their fixed-patch recovery contract without a storage-format
  change ([#324](https://github.com/dragginzgame/icydb/issues/324)).

  ```sql
  UPDATE User SET royalty_bps = royalty_bps + 1 WHERE id = '<user id>'
  ```

- Qualify the selected Host 0.9.2, Testkit 0.27.0, Memory 0.33.0, Metrics 0.3.1
  and Timers 0.16.0 graph. Testkit shares the direct Host generation; its
  duplicate Host 0.8 dependencies are gone. Existing startup/error handling and
  artifact helpers use the current owner APIs without compatibility adapters
  ([#307](https://github.com/dragginzgame/icydb/issues/307),
  [Testkit #30](https://github.com/dragginzgame/ic-testkit/issues/30)).

### 🧪 Testing

- Extend the existing generated SELECT and bundled SQLite owners with required
  AVG DISTINCT global/grouped, computed, filtered, stored-NULL, all-NULL and
  empty-input witnesses, receipts and manifest obligations. Uneven duplicate
  counts distinguish AVG from AVG DISTINCT. SQLite REAL normalization admits
  only bounded exact integers, halves and quarters; other results fail closed,
  without tolerance or engine-derived expectations. Share numeric witness
  qualification with the maintained SUM DISTINCT control, including cold/warm
  execution ([#330](https://github.com/dragginzgame/icydb/issues/330)).
