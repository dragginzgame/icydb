# IcyDB 0.255

## 0.255.2 — Mutation Value Handoff

### 🔧 Changed

- Save and delete results move cached field values from their finished reader
  through one mutation-output handoff, avoiding duplicate heap payloads. Accepted
  field order, whole-row validation, Identity checks and precommit response-size
  limits are unchanged. No public API or storage format changes.
- Owned dynamic and typed batches move keys and authored values through their
  existing lowerers instead of cloning them. Accepted authority, binding checks,
  key-before-patch failures, defaults, Identity and atomic staging are unchanged.

### ⚠️ Breaking

- The hidden core `execute_trusted_typed_mutation` entry point now consumes its
  mutation request. Direct core callers pass the request by value; no reference
  compatibility shim is retained. Application-facing typed-write methods already
  own requests and keep their signatures. The borrowed dynamic single-write API
  retains its existing boundary copy.

### 🧪 Testing

- Added nested/text backing-ownership coverage, accepted output order differing
  from physical slot order, cold NULL/empty outputs and eager/lazy corruption
  rejection. Existing mutation, Identity and result-boundary checks protect the
  complete write path.
- Added owned nested-input backing checks for both lowerers, dynamic caller order
  and typed ordinal order, heap-bearing batch parity and late-failure atomicity,
  plus key-error precedence over stale typed patches.

### 📊 Audit

- The warmed 128-item nested output fixture drops from 387 allocation requests
  to one; warm and cold handoffs both save 156,293 requested bytes. Scalar output
  allocations are unchanged. These are handoff costs, not endpoint latency.
- Against published 0.255.1, matched insert/load cycles fall 0.55% at 64 rows
  and 0.71% at 256 rows. Most measured mutations are cheaper; UPDATE-all at 64
  rows rises 0.19%, within the 1% ceiling. The same mutation actor with an
  identical temporary UPDATE wrapper loses 299 final raw Wasm bytes and adds
  one defined function.
- Two Rust files add 205 net lines: 206 test lines, two wiring lines and three
  fewer runtime lines. Both output loops converge on one consuming helper.
  All 93 focused tests, 90 measured PocketIC calls/data checks, allocation gates,
  lint and SQL-disabled checking pass; one unrelated timing benchmark remains
  ignored. Full suites remain user-owned. See the
  [slice 13 receipt](../design/0.255-owned-value-handoff/0.255-slice-13-receipt.md).
- Against the complete unpushed slice 13, owned 128-blob insert lowering drops
  from 130 allocation requests to one in both frontends, saving 139,264 requested
  bytes; scalar controls are unchanged. Matched insert/load cycles fall 0.61%
  at 64 rows and 0.50% at 256 rows; all controls remain within the 1% ceiling.
  Final raw Wasm grows 595 bytes. Its six extra defined functions exceed the
  +4 review gate; symbol attribution identifies compiler-generated ownership
  cleanup, not another execution flow. The user accepted this slice-specific
  exception on 2026-09-07 based on the simpler ownership flow; future gates are
  unchanged.
- Slice 14 changes six Rust files by 306 net lines, including 286 new test lines,
  and keeps one lowering flow. Its 92 focused tests, lint, SQL-disabled checks,
  2,160 measured lowerings and 90 measured PocketIC calls pass. Full suites remain
  user-owned. See the
  [slice 14 receipt](../design/0.255-owned-value-handoff/0.255-slice-14-receipt.md).

## 0.255.1 — Response and Key Handoff

### 🔧 Changed

- Public response conversion consumes owned runtime values instead of cloning
  their text, blob and big-integer payloads. Dynamic, grouped, exact-key, SQL
  and mutation output keep one accepted-catalog converter. Enum label resolution,
  response shapes, ordering and result limits are unchanged.
- Schema payload descriptions consume their admitted values through the same
  converter. Recursive public containers and catalog-owned enum labels still
  require representation conversion; no public API or storage format changes.
- Mutation-key reconstruction reuses the validated after-image reader and borrows
  SQL UPDATE/DELETE projections directly through the existing key codec. Duplicate
  reader construction and validation, temporary SQL key vectors and session-owned
  key assembly are removed; accepted component order and encoded keys are unchanged.
  The shared reader retains cached key values for subsequent Identity checks.

### 🩹 Fixed

- Wasm audit capture tests use an executable Twiggy stub, so static CI checks
  run without a locally installed Twiggy. Failed capture checks print their
  captured output before temporary files are removed.

### 🧪 Testing

- Added recursive text/blob backing-ownership and public-value/Candid parity
  coverage, including enum payloads, catalog-label lifetime and typed failure
  traversal order. All 91 focused regressions pass on the serial run; the initial
  parallel run was interrupted by SIGKILL without an assertion failure.
- Added projected-key wire/error parity, accepted component-order and malformed
  non-key row coverage. The key-handoff selection passes 110 focused tests;
  one unrelated benchmark remains ignored.
- Key reconstruction also covers reuse of the reader's accepted contract and
  key/non-key values after reconstruction, including subsequent Identity reads.

### 📊 Audit

## 0.255.0 — Owned Value Handoff

### 🔧 Changed

- Accepted input normalization and canonical persisted-row decoding move their
  already-owned admitted values into the runtime instead of deep-copying them.
  Strict admission, accepted schema authority, resource budgets and typed errors
  are unchanged. No public API, storage format, cache or runtime mode is added.
- Schema payload rendering continues to borrow its admitted value. The consuming
  handoff returns plain data and does not retain reusable admission authority.
- Constraint evaluation borrows selected cached row values for write admission,
  activation and migration checks. Integrity's owned snapshots use the same
  evaluation input contract. Required slots still decode before evaluation;
  fingerprint checks, NULL/missing behavior, limits and violation ordering are
  unchanged. No new evaluator, cache or runtime mode is introduced.
- Full-row SQL projection consumes the persisted-row reader's cached values
  instead of cloning them into output and discarding the originals. Eager
  validation, primary-key checks and output-buffer reuse remain intact. Ordinary
  paged dynamic reads and direct projections are unchanged by this handoff.
- Direct raw-row projections now move the first owned value for each source
  field out of the reader cache. Paged dynamic reads and SQL share this handoff;
  repeated projected fields retain their necessary output copies. Scalar byte
  fast paths, selected-field validation and primary-key checks are unchanged.
- Deferred materialization delegates storage selection and payload validation
  to the existing row-contract decoder, without reader-side dispatch or
  prevalidation. Canonical and by-kind decoders retain their existing checks;
  eager whole-row validation stays separate. No cache state or decoder is added.
- Nested-relation target projection borrows its reader-owned decoded root
  instead of deep-copying it. The existing path interpreter still emits owned
  target keys and preserves validation, traversal/reference budgets and
  duplicate charging before deduplication. No new execution path is added.
- Filtered retained-row output consumes its opened reader and moves normal
  cached values into output. The cache-taking operation is shared with direct
  projection; each keeps its current admission path. Byte-length-only slots
  still borrow scalar bytes, and filter/key checks stay before output.

### 🧪 Testing

- Added nested list/map/text/blob ownership coverage, normalization and persisted
  round trips including empty and NULL values, and rejection coverage for invalid
  input, truncated payloads, wrong persisted kinds and scalar constraint failures.
- Added stored empty/populated text, list, set and map query coverage. Structural
  emptiness works for text/list/set and rejects maps; direct and parsed
  SQL accept text `LENGTH` and reject collection operands with matching diagnostics.
- Added borrowed-slot identity/lifetime coverage and owned/borrowed constraint
  parity, including integrity violation paths. Existing constraint tests now
  exercise borrowed operands while retaining their typed-error assertions.
- Added full-row nested/scalar heap-identity and output-capacity coverage, plus
  nested/empty/NULL/enum parity and rejection of malformed wire, wrong kinds,
  accepted scalar-bound violations and mismatched row keys before output.
- Added direct-projection heap-identity and reread coverage, repeated-output
  independence, scalar storage controls and selective corruption checks. Stored
  empty/populated nested projections agree across dynamic pages and SQL.
- Added canonical first-read/reread coverage for invalid tags, truncated and
  trailing wire, wrong root/nested kinds, NULL rejection and nested scalar
  bounds. Lazy unselected fields remain untouched; eager validation still
  rejects them with matching typed diagnostics. Successful NULL, empty and
  populated values remain valid after taking and refilling the cached value.
- Added by-kind decode/validation parity coverage for mutated and truncated
  wire, relation-null filtering followed by invalid elements, and eager/lazy
  projection parity including cached rereads and repeated output.
- Added nested-relation reader reuse, independent target-key output, NULL/empty
  roots and raw-reference budget coverage with duplicate targets.
- Added retained-output heap-identity, repeated-slot, NULL/empty, scalar
  byte-length and selective-corruption coverage. Stored nested projections now
  also exercise accepting/rejecting collection filters.

### 📚 Documentation

- Corrected the collection-emptiness preflight: maps already fail accepted field
  admission before operator checks, and SQL does not expose structural emptiness
  functions. Clarified current contracts without adding map querying or changing
  runtime behavior. See the [boundary receipt](../design/0.255-owned-value-handoff/0.255-slice-2-receipt.md).
