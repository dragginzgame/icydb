# 0.273 — Explicit component memory declarations

## [0.273.0]

### ⚠️ Breaking

- Adopt Memory 0.36 explicit requests. Generated applications expose a complete
  component request factory; composed hosts combine those requests before
  bootstrap. Standalone startup uses the same declarations, and warm adoption
  verifies existing allocations once. Remove global registration, update typed
  diagnostics and preserve stable keys, ledger bytes and recovery ordering
  ([#355](https://github.com/dragginzgame/icydb/issues/355)).

### 🔧 Changed

- Adopt Shared 0.9.13: retain tool-lock and Cargo-source failure statuses and
  refuse CI inspection when its implicit branch cannot be observed. Qualify Host
  0.16 with explicit native extraction features; CLI, artifact and report flows
  retain their existing shared owners
  ([#302](https://github.com/dragginzgame/icydb/issues/302),
  [#307](https://github.com/dragginzgame/icydb/issues/307)).

- Fix valid multiline Cargo recipe admission on Bash 3.2, restoring the workflow
  policy baseline used by both native macOS jobs.
- Attribute build progress and maintenance diagnostics to IC Build. Keep consumer
  artifact ownership coverage while removing duplicate producer pruning coverage
  ([#307](https://github.com/dragginzgame/icydb/issues/307)).
- Adopt Shared 0.9.10 reporting rules, retaining the 0.9.9 tooling changes below.

- Use Host's Wasm facts and IC method interpretation in the size report. Function
  and data-segment counts come from the binary; function exports retain exact
  names in deterministic order without tool-generated internal-name annotations.
  Post-link checks compare full exports, including query/update modes, lifecycle
  hooks and extraction helpers. Generated/custom endpoint lists include only IC
  service methods, supporting composite queries and complete whitespace/quoted
  names. Callback counts and data-payload bytes retain the selected `ic-wasm`
  metric; encoded data-section framing is not a substitute for payload bytes.
  Report keys, byte budgets, build profiles and explicit Candid-export selection
  remain unchanged. This is native report tooling and claims no deployed Wasm-size
  reduction ([#307](https://github.com/dragginzgame/icydb/issues/307)).

- Adopt committed Shared Tooling 0.9.9. Cargo tool setup and admission reject
  non-boolean TOML `net.offline` values before effects, preserving explicit
  environment precedence and prior installations. Explicit setup selects the
  changed policy identity. PR release admission compares complete repository,
  commit and number identities before shell extraction or recovery writes and
  retains each rejected observation. Rust-tool fixtures isolate the prepared
  compiler context and reuse existing Git history without creating commits;
  actual staged-hook, receipt and partial-staging checks remain covered
  ([#302](https://github.com/dragginzgame/icydb/issues/302),
  [Shared #140](https://github.com/dragginzgame/shared-tooling/issues/140),
  [Shared #139](https://github.com/dragginzgame/shared-tooling/issues/139),
  [Shared #143](https://github.com/dragginzgame/shared-tooling/issues/143),
  [Shared #144](https://github.com/dragginzgame/shared-tooling/issues/144)).
