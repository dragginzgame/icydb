## 0.258.0 — Logical Memory Identity

### ➕ Added

- Add `icydb::db::prepare_memory_bootstrap` and typed admission errors for composed
  hosts. Require complete current role groups and retained database namespaces;
  select only omitted journals for existing database safety checks. Standalone
  bootstrap uses the same function. It neither moves data nor decides retirement.

### 🔧 Changed

- Update `ic-memory` from 0.13.3 to 0.14.3 without unrelated dependency updates or
  IcyDB package-version changes. The dependency remains the sole allocator and
  persists key-to-ID assignments in its existing ledger.
- Adopt upstream request reuse, allocation-free request sorting and single
  resolved-snapshot construction for historical completion. No IcyDB API,
  durable-format or recovery-policy change accompanies the 0.14.2 update.
- Adopt bounded opaque-byte ledger encoding from 0.14.3, reducing repeated
  per-byte codec work while preserving recovery, capacity and commit checks.
- Update test/build dependency `ic-testkit` to 0.10.0. Single and batch builds
  retain exact compiler and post-link records through reading and staging;
  configured output paths remain publication destinations, not read authority.
- Generated stores and all three canister controls register logical requests.
  Recovery, startup receipts and integrity progress resolve committed identity;
  startup and integrity opens use keys directly. Memory profiles and existing
  database retirement checks are retained.
- Hosts grant pools explicitly with `ic_memory_range!(..., mode = Allowed)`.
  The upstream macro's default reserved range is not a logical placement grant.
  Schema declarations no longer own physical pools.
- Remove the duplicate commit-memory collision registry and its mutex. Keep
  current-database selection separate from the sole committed allocation
  authority; every production memory open still validates its key/ID pair.

### 🩹 Fixed

- Mark all four nested-relation audit actors' host ranges explicitly `Allowed`.
  The dependency's default reservation cannot place logical requests; this
  restores actor startup without changing runtime policy or relation budgets.
- Keep build-result ownership across Cargo-to-post-link and post-link-to-reader
  handoffs, preventing shared-output replacement or pruning from invalidating
  live consumers. Reuse upstream retention without another lock or retry flow.

### ⚠️ Breaking

- Replace numeric canister/store memory attributes with `memory_namespace` and
  `storage(journaled(key = "..."))`. Existing databases require recreation or
  reinstall; no fixed-ID fallback or migration bridge is retained.
- The 0.14.3 outer ledger encoding is also a hard cut: recreate stable data
  written by earlier dependency releases, including logical-memory candidates.
  No compatibility decoder is retained; the format version remains 1.
- Integration build helpers return `BuiltCanisterArtifacts` instead of bare
  paths. Keep the result alive and borrow its final path through `AsRef<Path>`;
  copying a path alone does not retain cache ownership. Canister APIs are unchanged.
- Rust renames and declaration order do not change keys. Changing a store key
  means removal/addition without transferring rows. Namespace removal rejects
  before allocation commitment. Store retirement still rejects journal debt and
  registry changes with pending commit markers; that later database rejection
  does not undo an allocation commit.
- `CanisterKind` resolves control IDs fallibly from keys; schema allocation
  descriptors no longer expose physical IDs. `DatabaseBootstrapError::cause`
  preserves `MemoryBootstrapAdmissionError` from logical admission.
- Dependency recovery rejects out-of-limit bytes, collections and nesting,
  including indefinite-length CBOR. Limits include 16 MiB logical payloads,
  32 MiB + 4 KiB outer cell values, depth 32, 255 allocation records and 65,536
  generation/schema-history entries. The maintained ledger format remains 1.

### 📚 Documentation

- Document permanent identities, explicit host grants, shared bootstrap admission
  and the reinstall boundary in schema-authoring and durability guidance.
- Keep the [logical-memory design and status](../design/0.258-logical-memory/0.258-design.md)
  explicit about executed generated upgrade coverage, matched costs and the
  qualification limits. Implementation is ready for the user-owned release gate.

### 🧪 Testing

- Cover duplicate/oversized keys, generated role wiring and retained memory
  profiles. Production-runtime admission tests cover stable placement, warm
  reuse, namespace replacement/retry, complete role sets, journal-only selection,
  retained debt bytes, revoked grants and foreign claims.
- Generated native startup/read/write coverage uses a host pool below ID 100;
  another generated actor advances convergence across 129 write messages.
  Existing convergence tests preserve retirement/reintroduction checks.
- Add one test-only actor with full/omitted-store builds and three executed
  PocketIC upgrade cases. Empty-journal removal retains surviving rows and IDs;
  retirement rejects reintroduction. Journal debt and valid pending markers
  reject removal without changing database control, then recover with the
  original actor. The marker comes from a normal commit and first passes a
  positive recovery control. No production fault-injection API is added.
- Cover exhausted-pool retry, immutable warm-host policy and persisted profile
  mismatch through production runtime admission. Check that Rust path renames
  retain all four allocation keys. Add a test-actor warm-open instruction probe
  and explicit install/upgrade cycle measurements.
- Cover repeated/switching commit-memory selection and committed-runtime
  rejection of mismatched or undeclared opens without changing authority.
- Remove duplicate assertions from the macro key-segment test and name it for
  the canonical-segment behavior it actually checks. Correct the upstream
  follow-up's stale qualification status; production behavior is unchanged.
- Add deterministic post-link retention coverage across warm reuse, concurrent
  output replacement/removal, pruning and final release. Batch partial-failure
  coverage verifies successful artifacts survive their mutable destinations.

### 📊 Audit

- Remove schema physical-ID fields, numeric validation and generated placement.
  Add one shared stateless admission function and committed-identity lookup;
  no new allocator, persisted state, recovery mode or reclamation flow.
- The earlier L3a handoff added about 650 lines across eight files, primarily
  admission tests. The generated hard cut is a net deletion across implementation,
  fixtures and documentation; current footprint is recorded in the status.
- Matched one-entity actor after cleanup and 0.14.2 adoption versus 0.257.22:
  raw Wasm +30,133 bytes (+1.174%), median warm-open instructions +1.168%,
  warm-open message cycles +0.117%, and typed-write cycles +0.527%; allocated
  stable bytes unchanged. The
  [qualification report](../reports/investigations/2026/09/17/logical-memory/02/report.md)
  separates lifecycle costs and coverage limits. This is a simpler allocation
  contract, not a performance improvement; full-suite validation remains user-owned.
- Removing the duplicate registry saves 1,044 raw Wasm bytes versus the earlier
  candidate. Warm-open instructions fall 0.145%; message cycles change +0.010%.
  The primary improvement is simpler ownership, not a meaningful speedup.
- Adopt the request-sorting and repeated-construction cleanup from
  [ic-memory #6](https://github.com/dragginzgame/ic-memory/issues/6) through the
  published dependency, without a local allocator workaround or weaker checks.
- The 0.14.2 update saves another 513 raw Wasm bytes on the matched actor;
  warm-open instructions/cycles and typed-write cycles remain exactly unchanged.
- Published 0.14.3 resolves the lifecycle cost failure: worst-phase instructions
  fall from 14,985,588 to 5,131,230 (65.759%) under the unchanged 12,750,000 ceiling.
  Stable extent remains unchanged; matched consumer Wasm/cycle deltas are
  unmeasured. Lifecycle behavior and native admission checks pass. The first
  combined lifecycle run hit a missing post-link input in its endpoint-surface
  test, which passed in isolation; subsequent retained-artifact adoption addresses
  that lifetime gap without claiming the precise original racing operation is known.
  All three lifecycle tests now pass together with concurrency enabled; instructions
  remain unchanged by the harness repair. Five focused cache tests and repository
  lint pass. Full release validation remains user-owned.
