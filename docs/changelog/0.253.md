# IcyDB 0.253 — Nested Relations

## [0.253.0] - 2026-09-04

### ➕ Added

- Four matched proving actors now isolate no-relation, direct-relation,
  single-valued composite, and repeated composite shapes behind one shared
  operation harness. Their fixed manifest covers optional and named wrappers,
  enum payloads, list items, set items, and map values without widening the
  production relation surface yet.
- The current-form fixture contract freezes fresh-catalog relation identities
  and exact path instructions for the upcoming hard-cut implementation.

### 🔧 Changed

- The 0.253 design now fixes per-image and per-batch traversal, raw-reference,
  target-lookup, and reverse-delta ceilings from real stable-tree instruction
  measurements. These are non-configurable contract limits, not actor modes.
- Accepted direct relations now persist an explicitly tagged `Direct` source
  locator and an entity-local, monotonic relation-ID high-water. Removing a
  relation cannot make its identity reusable.
- Reverse entries now use the exact accepted `RelationId` as their semantic
  domain. Physical generation remains a separate rebuild identity, and direct
  enforcement still follows the existing fast path.

### ⚠️ Breaking

- The database boot identity, accepted relation snapshot, and reverse-key
  representation replace their 0.252 predecessors in place. A 0.253 binary
  rejects 0.252 stable state instead of retaining a legacy decoder or upgrade
  bridge.

### 📊 Audit

- The immutable predecessor is published `v0.252.11` at revision
  `d497f60738a7e1e103298e9817185b9998be3bb1`, with exact clean-tree
  `default_empty` and `sql_perf` raw-Wasm baselines.
- The controlled actors retain identical code sections, function counts,
  indirect-call counts, exports, and Candid surfaces at the opening boundary.
  The direct annotation adds 103 raw bytes to the no-relation control; inactive
  shallow and repeated shapes add 216 and 248 raw bytes to the direct control.
- The hard-cut identity implementation adds 836 raw bytes, 825 code-section
  bytes, and 6 defined functions to both the no-relation and direct-relation
  controls. That stays within the isolated 2 KiB/2 KiB/8-function gate, and the
  two controls still have identical code, function, indirect-call, export, and
  Candid shapes. One reverse entry grows by 6 encoded bytes, or 6,000 bytes per
  1,000 edges before stable-tree overhead.
- The worst 2,730-row stable-tree replacement batch uses 4,928,211,587
  instructions. It leaves 35,071,788,413 instructions below the 40-billion IC
  update ceiling, comfortably preserving the required 25% reserve. The first
  row above both the one-delta and two-delta commit boundaries rejects through
  the existing typed limit.

### 🧭 Migration Notes

- Retained rows require export through the old binary, a fresh 0.253
  installation, and ordinary current-form import. There is no in-place
  upgrade, predecessor relation decoder, reverse-key fallback, or reverse-only
  regeneration path.
