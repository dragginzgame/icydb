# IcyDB 0.253 — Nested Relations

## [0.253.0] - 2026-09-04

### ➕ Added

- Four matched proving actors now isolate no-relation, direct-relation,
  single-valued composite, and repeated composite shapes behind one shared
  operation harness. Their fixed manifest covers optional and named wrappers,
  enum payloads, list items, set items, and map values without widening the
  production relation surface yet.
- The current-form fixture contract freezes fresh-catalog relation identities
  and exact path instructions for the upcoming hard-cut implementation.
- Single-valued relation sources may now follow accepted named records,
  explicit optional boundaries, and enum-variant payloads. Commit, reverse
  indexing, replacement, source deletion, target restriction, batch overlay,
  activation, migration, integrity, and recovery share the same accepted path.
  The path persists stable identities only; exact contracts are derived from
  the accepted catalogs instead of being duplicated in relation state.
- Repeated relation sources may now traverse accepted list items, set items,
  map values, and repeated combinations. Raw occurrences are charged before
  canonical deduplication through the same interpreter used by single-valued
  paths.

### 🔧 Changed

- Relation commits enforce the fixed per-image and shared per-batch traversal,
  raw-reference, unique-target-lookup, and reverse-delta ceilings derived from
  real stable-tree instruction measurements. These are non-configurable
  contract limits, not actor modes.
- Accepted direct relations now persist an explicitly tagged `Direct` source
  locator and an entity-local, monotonic relation-ID high-water. Removing a
  relation cannot make its identity reusable.
- Reverse entries now use the exact accepted `RelationId` as their semantic
  domain. Physical generation remains a separate rebuild identity, and direct
  enforcement still follows the existing fast path.
- Local validation now stops immediately on clippy failure and directs the
  repair loop through every maintained `cargo clippy` lane before feature and
  test failures are accumulated.

### ⚠️ Breaking

- The database boot identity, accepted relation snapshot, and reverse-key
  representation replace their 0.252 predecessors in place. A 0.253 binary
  rejects 0.252 stable state instead of retaining a legacy decoder or upgrade
  bridge.

### 📊 Audit

- The immutable predecessor is published `v0.252.11` at revision
  `d497f60738a7e1e103298e9817185b9998be3bb1`, with exact clean-tree
  `default_empty` and `sql_perf` raw-Wasm baselines.
- The controlled actors retain identical code sections, function counts,
  indirect-call counts, exports, and Candid surfaces at the opening boundary.
  The direct annotation adds 103 raw bytes to the no-relation control; inactive
  shallow and repeated shapes add 216 and 248 raw bytes to the direct control.
- The hard-cut identity implementation adds 352 raw bytes, 340 code-section
  bytes, and 7 defined functions to both the no-relation and direct-relation
  controls. That stays within the isolated 2 KiB/2 KiB/8-function gate, and the
  two controls still have identical code, function, indirect-call, export, and
  Candid shapes. One reverse entry grows by 6 encoded bytes, or 6,000 bytes per
  1,000 edges before stable-tree overhead.
- The shallow actor adds 4,103 raw bytes, 3,246 code-section bytes, and 9
  functions over its current direct control, passing the 32 KiB nested-actor
  raw/code gate. Removing duplicated persisted path contracts and binding
  flows recovers 8,750 raw bytes, 8,617 code bytes, and 8 functions from the
  first Slice 3 implementation. The remaining common machinery adds 8,986 raw
  bytes, 9,121 code bytes, and 15 functions to the no-relation control, passing
  the measured 12 KiB raw/code accepted-authority gate. The
  no-relation and direct controls retain identical code and function shapes.
- The worst 2,730-row stable-tree replacement batch uses 4,928,211,587
  instructions. It leaves 35,071,788,413 instructions below the 40-billion IC
  update ceiling, comfortably preserving the required 25% reserve. The first
  row above both the one-delta and two-delta commit boundaries rejects through
  the existing typed limit.
- The repeated candidate adds 7,182 raw bytes, 6,353 code-section bytes, and
  18 functions over the direct control, passing its 32 KiB raw/code gate.
  The cumulative no-relation control adds 11,441 raw bytes and 11,564 code
  bytes over Slice 2, passing both 12 KiB byte gates, and reports 46 additional
  functions. Function counts remain visible for future optimization but no
  longer act as an arbitrary pre-1.0 delivery blocker. Slice 4 completes the
  IcyDB behavior.
- Sorting the exact batch target cache removes repeated linear scans and cuts
  the final maximum 2,730-row replacement commit to 5,444,445,467
  instructions, 10.475% above the frozen baseline. The cache owns only proven
  targets and retains 24,555,554,533 instructions below the admitted
  30-billion mutation ceiling. All exact limits commit and their first
  over-limit units reject before mutation; the small target-restriction and
  same-batch deletion controls remain 1.266% and 1.098% above their 1%
  instruction target.
- The maintained referential-integrity, nested-storage, persistence-inventory,
  public-facade, and schema-authoring contracts now describe the accepted
  direct-or-nested source locator, supported rooted shapes, fixed work bounds,
  and unchanged no-query/no-partial-mutation boundary.
- Toko's available checkout proved stale and is not used as release evidence.
  Its classification, duplicate-validation cleanup, `project_instance` Wasm
  gate, and typical-call measurements remain explicitly unclaimed and are
  tracked in [toko#1703](https://github.com/dragginzgame/toko/issues/1703).

### 🧭 Migration Notes

- Retained rows require export through the old binary, a fresh 0.253
  installation, and ordinary current-form import. There is no in-place
  upgrade, predecessor relation decoder, reverse-key fallback, or reverse-only
  regeneration path.
