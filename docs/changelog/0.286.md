### 🧹 Cleanup

- Reuse primary-iterator payloads for full-row collections and cursor pages,
  including mixed journal overlays, while preserving limits and filtering
  ([#261 — Primary-range full-row scans repeat point lookups](https://github.com/dragginzgame/icydb/issues/261), partial).
  The existing borrowed visitor now honors the collection stop signal and
  matched-row offset. Journaled row preflight uses the existing ordered-overlay

  Heap and all journaled primary ranges avoid per-row point reads in both
  directions. The obsolete unsupported-backing result is removed from the store
  visitor. Retained-row cursor scans use the same traversal, slot decoder and
  filter owner, while the existing coordinator and physical-key observer retain
  page-stop and continuation authority. Materialized order windows still reject
  incomplete input. No token, storage or public API changes.
  Matched optimized SQL audit Wasm adds 2,040 raw bytes (0.049%). With 2,048
  journaled fixture rows, 100-row collection reads use 31.9–35.8% fewer measured
  instructions before upgrade and 51.3–54.5% fewer after same-artifact upgrade;
  update-call cycles fall 21.9–35.3%. Both directions and repeated calls preserve
  identical results. These are collection measurements for this actor, not
  fleet-wide size or cursor-page performance claims; cursor cost remains unmeasured.

- Reuse ordered budget-pair charging in index scans and aggregates, preserving resource order
  and partial accounting when a charge fails
  ([#293 — Per-row budget accounting repeats constant work](https://github.com/dragginzgame/icydb/issues/293), partial).
  Ordinary scan-key admission, exact-intersection overflow checks and merged
  range scans share the existing pair owner instead of consecutive active-budget
  lookups. Group creation and scalar/grouped DISTINCT admission also use the
  existing pair owner without changing their respective charge order or publishing
  aggregate state after a failed charge. No limits, cursor behavior, charge
  amounts or accounting state change.
  Remaining reservation and usage-snapshot work stays open; no measured IC cost
  or Wasm-size improvement is claimed.

- Consolidate grouped aggregate row reading, filtering and counting while retaining
  borrowed, owned and nested-path ingest behavior
  ([#477 — Grouped fold repeats the same row loop](https://github.com/dragginzgame/icydb/issues/477)).
  Ingest selection remains outside traversal; rejected rows do not construct
  group keys or consume group admission budgets. Read/filter/ingest error order
  and the separate ordered fold remain unchanged. No public or persisted
  contract changes.

- Consolidate CHECK and NOT NULL activation compilation while retaining exact
  constraint identities, isolated historical gates and typed rejection errors
  ([#479 — Constraint activation compiles repeat the same lookup](https://github.com/dragginzgame/icydb/issues/479)).
  The accepted constraint compiler owns one activation lookup and kind check;
  callers select its existing constraint kind. Targeted-rule compilation stays
  separate. Missing IDs still reject as unknown fields, kind mismatches retain
  their original error, and compiling one pending gate does not include other
  pending gates. No public API, activation lifecycle or persisted format changes.

- Share enum admission for ordinary and expression-index components while
  preserving scalar encoding and exact catalog authority
  ([#491 — Index component encodes repeat the same enum gate](https://github.com/dragginzgame/icydb/issues/491)).

  enum components. Missing authority still rejects before NULL omission; accepted
