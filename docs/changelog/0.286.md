# 0.286

## [0.286.1]

### 🔧 Changed

- Adopt IC Host/Build/Testkit 0.69.0, Platform 0.7.0, Memory/Storage 0.51.10
  and Shared Tooling 0.26.23. The compatible graph selects Timers 0.31.10;
  Wire remains at 0.7.18 and Metrics at 0.16.3.

  Tooling 0.69 aligns Host Tools and Testkit with Platform 0.7's Rust identities;
  its published Rust sources match 0.68.12. Platform 0.7 retires Candid compiler
  exports unused by IcyDB. The Canic adapter retains Platform 0.6.21; both
  versions share one executor identity. Core's selected Wasm normal/build graph
  remains Candid-free. No storage-format migration is required. Shared Tooling
  0.26.23 and Platform 0.7.0 are the latest verified releases for this adoption.
  Focused consumer tests, strict Clippy, Rust 1.91 Wasm compilation and dependency
  checks pass. The installed deterministic post-link/upgrade result belongs to the
  earlier Memory/Storage 0.51.9 and Timers 0.31.9 lock selection. Native macOS,
  browser and the full release gate have not been rerun for this graph.

- Delegate manifest, derive and Rust formatting to Shared Tooling's driver
  ([#473](https://github.com/dragginzgame/icydb/issues/473)).

  Adopt published revision `48ec9794892da6f8e2812653ec16c5e8ea23df47` through
  the canonical exporter, including the formatter's declared companion closure.
  Replace paired local shell commands with `FORMAT_RUST_ARGS := --sort-derives`.
  Grouped manifests now sort before derives and Rustfmt; the existing compiler,
  repo-local Cargo directories and offline prepared-tool admission are retained.
  The shared driver supplies per-pass output, failed logs and exact-input reuse;
  index-export hooks always execute all passes. A later write-pass failure keeps
  earlier successful writes in ordinary `make fmt`, while the hook discards
  failed exported writes without refreshing the selected index payload.
  Consumer fixtures cover the changed pass order and release dispatch rather
  than duplicating the shared driver's generic regression matrix. Focused Linux
  checks pass actual formatting/hook preservation, exact failure-log retention,
  unchanged-input reuse, source invalidation, forced runs, workstation dispatch,
  selected-source release metadata and snapshot integrity. Native macOS and broad
  release gates remain separate qualification obligations.

- Complete the matched cost qualification for the already-delivered secondary
  resume fix ([#25](https://github.com/dragginzgame/icydb/issues/25)).

  Two canonical `wasm-release` audit builds use released `0.286.0` source and
  its unchanged lockfile, plus identical test-only instrumentation. A temporary
  control disables secondary anchors and resumed ordered scan caps; it is not
  a retained runtime option. The fixed actor is 4,179,101 raw bytes versus
  4,175,093 for the control (+4,008 bytes, 0.096%). Across 2,048-row name-index
  traversals, total engine instructions fall 72.1–90.0% and update-envelope
  cycles fall 68.8–86.2%. These are workload-specific installed IC measurements,
  not query-mode cycle estimates or a comparison of the pending dependency graph.

  Both artifacts pass all 16 workloads: 256/2,048 rows, ASC/DESC, covering or
  row-backed projection, and residual-filter controls. Every page is replayed
  and checked against an independent name/identity ordering oracle. Small
  single-page controls have no resume saving; one cycle sample increases 0.10%.
  The maintained native range/IN and replayed-suffix regressions also pass.
  Testkit owns local PocketIC startup and shutdown. Production APIs, stored bytes,
  cursor formats and dependencies are unchanged by this qualification. Native
  macOS and broad release gates have not been rerun for the new audit probe.

### 🩹 Fixed

- Keep grouped `FIRST`/`LAST` identities stable across scan direction, index
  choice and continuation pages ([#52](https://github.com/dragginzgame/icydb/issues/52)).

  Grouped identity terminals reuse canonical primary-key minimum/maximum
  reduction and no longer select an identity from encounter order. Every
  admitted group key is inspected; existing group/result/request budgets still
  apply. Scalar terminal order, cursor format and stored bytes are unchanged.

- Admit text transforms before allocation during execution and literal folding,
  preserving typed budget facts through projections, filters and aggregate inputs
  ([#75](https://github.com/dragginzgame/icydb/issues/75)).

  Runtime replacement admits the sizing scan, exact requested backing and
  construction work before allocation, retaining cumulative charges and the
  existing typed resource/scope/lane facts on refusal. NULL arguments construct
  no output. Literal-only WHERE folding borrows the caller's preparation budget
  for visited values, argument containers and replacement output. Fallible child
  traversal propagates exhaustion without publishing partial expressions or
  visiting later children. LOWER/UPPER share the value owner's conservative
  requested-backing/growth allowance and retain Rust's canonical Unicode casing.
  TRIM/LTRIM/RTRIM, LEFT/RIGHT and SUBSTRING admit their input walk and exact
  selected UTF-8 copy before allocation. LENGTH also admits its input walk.
  Aggregate inputs and aggregate filters preserve typed exhaustion rather than
  changing it to an invalid-plan error. NULL and empty-range behavior is retained;
  no limit, public error variant, index-expression value or persisted format changes.

- Keep large admitted relation rows updatable by separating before/final-image
  allowances ([#61](https://github.com/dragginzgame/icydb/issues/61)).

  Each side shares its own batch allowance of 5,460 raw references and 349,440
  nested traversal steps across all rows and relations. Per-image admission,
  final-view target validation, unique-target lookup limits and the shared
  reverse-delta limit remain enforced. A large disjoint replacement can still
  require smaller edits; no unlimited transition is admitted. List/set/map
  regression coverage reproduces the former rejection with 3,201 references
  per image, then qualifies update, replacement, journal convergence and atomic
  missing-target refusal. No persisted or public error format changes.

- Expose wrapped causes from typed and exhaustive-read errors through Rust's
  `Error::source()` ([#255](https://github.com/dragginzgame/icydb/issues/255), partial).

  Typed operations, exhaustive reads and typed exhaustive reads retain their
  database, adapter and revision causes for downcasting. Display text, variants,
  Wire payloads and error classifications are unchanged. Canonical adapter-to-Wire
  mapping remains open: it requires new public diagnostic enum variants and an
  explicitly selected minor release boundary.

- Repair standalone facade install/upgrade qualification. The manual scenarios
  now consume the existing retained Wasm build/post-link owner directly and use
  Canic's native Wire init/post-upgrade encoders. The obsolete external-Wasm
  handoff and empty lifecycle argument bytes are removed. Manual qualification
  remains explicitly selected; ordinary CI does not gain an extra actor build.

### 🧹 Cleanup

- Reuse primary-iterator payloads for unbounded full-row loads on single-backing
  stores. Finite pages and mixed overlays retain their existing traversal;
  row admission and accounting stay shared
  ([#261](https://github.com/dragginzgame/icydb/issues/261), partial).
- Defer row-reader value-cache allocation until cached decoding is requested;
  encoded-byte reads and direct scalar projections avoid allocating cache cells,
  and invalid slots reject before cache allocation. Envelope validation stays eager ([#257](https://github.com/dragginzgame/icydb/issues/257), partial).
- Replace nine mechanical error implementations with existing error derives,
  preserving compact messages, typed diagnostics, conversions and source chains
  ([#470](https://github.com/dragginzgame/icydb/issues/470)).

## [0.286.0] - 2026-10-27

### ⚠️ Breaking

- Remove the always-unavailable `MemoryAllocation.payload_bytes` field and CLI
  column. Allocation diagnostics still report capacity, virtual extent and slack,
  not live payload occupancy. Regenerate clients for the changed snapshot contract
  ([#365](https://github.com/dragginzgame/icydb/issues/365)).
- Migration findings now expose optional accepted source/target field IDs and
  `SchemaMigrationTransformReason`; the CLI displays retained transform details.
  Regenerate clients for the changed migration-status contract. Persisted findings
  and migration execution are unchanged
  ([#206](https://github.com/dragginzgame/icydb/issues/206)).
- Remove the unwritten index `Missing` witness state and its scan/count/recovery
  branches. Written presence bytes remain `0`; other bytes fail as corruption.
  No rewrite is needed for entries produced by maintained writers
  ([#245](https://github.com/dragginzgame/icydb/issues/245)).

- Insert-only batch replies now share the 1 MiB batch result limit. Split larger
  imports into smaller batches; oversized replies reject before commit without
  consuming generated identities. Oversized-row and endpoint-response fixtures
  now seed within that limit before exercising their separate rejection boundaries
  ([#285 — Insert-only dynamic batches lack a result-size bound](https://github.com/dragginzgame/icydb/issues/285)).

- Remove the `TypedEntityAdapter::typed_binding` override hook; generic callers
  must use `session.bind_typed_entity(E::DESCRIPTOR)`. Generated entities retain
  their inherent `typed_binding` convenience method. Mixed typed batches share
  current accepted bindings per descriptor
  ([#164 — Typed mixed batch repeats binding issuance](https://github.com/dragginzgame/icydb/issues/164)).

### Changed

- Update the pinned Rust toolchain GitHub Action revision; the selected compiler
  versions remain unchanged ([#456](https://github.com/dragginzgame/icydb/pull/456)).
- Update the pinned Rust cache GitHub Action to 2.9.3 in CI and SQL qualification
  workflows ([#457](https://github.com/dragginzgame/icydb/pull/457)).

- Reuse checked SQL SELECT templates across parameter values within the existing
  cache limits. Each call still validates its inputs, current schema and
  value-sensitive query behavior
  ([#392 — Compiled SQL cache recompiles every bound call](https://github.com/dragginzgame/icydb/issues/392)).

### Testing

- Qualify pre-rewrite migration abort with more than one page of unrelated
  index entries, checking one-call completion and exact row preservation across
  upgrade. A migration-only test-admin seeder uses the trusted batch owner without
  widening public SQL admission ([#207](https://github.com/dragginzgame/icydb/issues/207)).
- Make the manual identity closeout probe explicitly use `wasm-release` and report
  raw Wasm bytes, artifact identity and whole-call cycles alongside its existing
  IC instruction samples ([#212](https://github.com/dragginzgame/icydb/issues/212)).

  Matched Linux/PocketIC qualification used published commit `6ee5540b3`, its
  locked graph, Rust 1.99.1 and the canonical `wasm-release` pipeline. Each
  counterfactual disabled only the relevant optimization, holding the fixture
  and other implementation choices fixed; these are not whole-release deltas.
  Abort with 1,024 added unrelated index entries fell from three calls and
  494,904,545 envelope cycles to one call and 158,736,437 cycles (-67.93%).
  Source/successor raw Wasm each grew 696 bytes. The identity workload fell from
  889,580,779 to 871,966,360 envelope cycles (-1.98%); its 64-entity context fell
  from 35,877,153 to 25,357,942 instructions (-29.32%). Its 4,095-row batch was
  nearly unchanged (787,162,419 to 787,144,052 instructions). Raw identity-probe
  Wasm grew from 4,145,871 to 4,145,879 bytes. Whole-call cycles include the
  envelope, not only the measured handler regions. These fixtures do not claim
  live-IC or native macOS qualification, or predict arbitrary retained-history
  workloads; the linked issues hold the full closeout evidence.

- Exercise a journaled exhaustive-read proof across two actual canister upgrades
  and verify that an ordinary later row update rejects the old proof as
  `StoreDataChanged`. The fixture query is test-admin-only and uses the existing
  exhaustive-read facade. This qualifies the recovery correction from 0.284.2;
  it does not change cursor-key rotation or promise that signed pagination
  tokens survive upgrades ([#66 — Journaled proofs fail across upgrades](https://github.com/dragginzgame/icydb/issues/66)).

- Add a populated-schema journal regression for caller-built and decoded
  batches. Both preserve the accepted entity inventory, advance only the written
  entity's revision and replay idempotently. This qualifies the validated-tag
  handoff delivered in 0.285.0 without removing independent raw-record or
  persisted-byte admission ([#273 — Batch validation repeats work](https://github.com/dragginzgame/icydb/issues/273)).
