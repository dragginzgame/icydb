# IcyDB 0.238 — Ordered Scalar DISTINCT Group Seek

## 0.238.0

### ⚡ Performance

- Route a cursorless `SELECT DISTINCT` projection through bounded accepted-index
  group seeks when the query has exactly one direct, non-nullable `Int32` or
  `Text` projection, exactly the same authored `ORDER BY` field and direction,
  one compatible range, no residual predicate, and `OFFSET + LIMIT <= 3`.
- At 2,048 rows, the four frozen direct-field queries now cost
  1,543,519–2,154,506 instructions instead of 90,861,504–93,144,415, saving
  88,856,029–91,062,151 instructions. Each query fetches no rows and visits no
  more than four physical index entries in no more than four range scans.
- Keep the existing complete route for absent or derived ordering, multiple
  projections or order terms, nullable fields, residual predicates, unsupported
  scalar kinds, runtime continuation controls, and windows above three.

```sql
SELECT DISTINCT age
FROM PerfAuditUser
ORDER BY age DESC
LIMIT 3;
```

### 📊 Audit

- Keep admission in one prepared covering-plan owner. Its private immutable
  contract owns the validated output window and derives the representative
  budget; execution cannot reconstruct eligibility or reread window values from
  the logical plan.
- Reuse the accepted index envelope, canonical component codec, covering
  presence proof, and existing adjacent DISTINCT finalizer. The implementation
  adds no cache, mutable owner, persisted state, invalidation edge, schema
  authority, public API, Candid method, export, or stable-format change.
- The production footprint is four existing files and 292 net lines. Final raw
  SQL audit Wasm grows by 6,370 bytes, from 4,450,140 to 4,456,510; deterministic
  gzip grows by 3,317 bytes. This is report-only complexity evidence under the
  accepted performance-first decision. Candid, exports, and the Wasm data
  section remain unchanged.
