# IcyDB 0.260

## 0.260.0 — Measured Runtime Footprint

### 📚 Documentation

- Establish the bounded [design and delivery plan](../design/0.260-runtime-footprint/0.260-design.md):
  ICYDB-033 composed Wasm attribution first, evidence-selected reduction only
  if justified, and collection materialization through existing owners. The
  user subsequently authorised the collection investigation while Canic work
  was pending.
- Reconcile the delivered Canic-owned six-subject entity/query/write comparison
  against the original handoff. W1's controlled attribution is complete; full
  application attribution and a demonstrated runtime reduction remain open.

### 🩹 Fixed

- Nullable by-kind fields now recognize only the exact null sentinel before
  invoking their accepted decoder or validator. The previous generic-wire
  precheck rejected valid Float32/Float64 lists and redundantly traversed
  non-null collections. Non-null bytes still receive complete accepted-kind
  validation; collection ownership and output reuse are unchanged.

### 📊 Audit

- Accept the [six-subject composed evidence](../design/0.260-runtime-footprint/w1-reconciliation.md)
  after independent artifact/source hash, Wasm section/function and delta checks.
  Adjacent raw increments are 1,417,213 bytes for the empty participant, 39,705
  for the first binding, 892,813 for the first typed page, 116,012 for insert
  after page and 8,202 for nine more matching entities. These measure published
  IcyDB 0.259.6 in controlled Canic subjects, not the dirty 0.260 candidate or
  Toko Miner. Named attribution identifies the projection/page owner for W2;
  it establishes no removable-byte estimate, runtime qualification or IC-cost
  improvement. W2's subsequent [source investigation](../design/0.260-runtime-footprint/w2-disposition.md)
  records no-build: no safe, simpler owner-local reduction was established.
  No further runtime change or measured footprint saving is claimed; final
  current-candidate qualification remains Q1's responsibility.
- The [matched collection comparison](../reports/investigations/2026/09/19/collection-materialization/02/report.md)
  reduces raw test-actor Wasm by 252 bytes, with unchanged defined functions
  and all 54 instruction/cycle observations identical. The named-list fixture
  uses a different existing decoder from the corrected by-kind boundary;
  this is not a measured query-speed or allocation win. Broader streaming is
  deferred rather than adding a second admission path. The correction changes
  two source files: about -10 production lines and +83 regression-test lines.
- The [matched typed-catalogue comparison](../reports/investigations/2026/09/19/typed-catalogue-reads/01/report.md)
  reduces ordinary 128-row query instructions by 16.1–16.3% and explicit-call
  cycles by 13.1%; raw actor Wasm falls by 744 bytes. This representative nested
  fixture is not a Toko Miner deployment measurement. The runtime change is
  one file, net +5 production lines and +7 unit-test lines; measurement support
  adds about 404 lines across five fixture files.
- A [same-output catalogue comparison](../reports/investigations/2026/09/19/selected-field-ergonomics/02/report.md)
  shows the existing selected-field API uses 38.8–39.3% fewer explicit-call
  cycles and 45.5–46.2% fewer instructions for 128 label rows than full typed
  reads followed by label extraction. This is a caller-side opportunity, not
  another runtime optimisation or a measured Toko Miner deployment gain.
  No public API or application changes. The added measurement endpoint costs
  8,236 raw test-actor Wasm bytes; both query alternatives run in that same
  actor, so this is fixture overhead, not their separate deployment-size delta.

### 🔧 Changed

- Exact counts now report `QUERY_EXACT_COUNT_METADATA_UNAVAILABLE` (E275) when
  an admitted metadata-only count cannot obtain exact cardinality. Unsupported
  count shapes retain `RUNTIME_UNSUPPORTED`; both fail closed without scanning.
  Typed/dynamic facade errors and CLI diagnostics preserve the distinction.
  Potentially breaking for callers matching the previous generic code: update
  matching to the new identity. No persisted-data or Candid-shape migration.
  ICYDB-004's application fallback removal still needs downstream qualification.
- Share immutable accepted typed bindings across output rows and generated
  adapters, avoiding repeated deep copies and field-by-field comparisons of
  identical mappings. Independently issued equivalent bindings retain content
  equality, current-authority checks remain mandatory, and native Send/Sync
  traits are preserved. No application changes, new cache or public API.

### 🧪 Testing

- Qualify unavailable entity/index-prefix metadata through dynamic and typed
  counts, unsupported count shapes, zero physical row/index reads, and the new
  diagnostic's public Candid round trip. Existing exact-count success coverage
  continues to prove row-free counts.
- Add collection-predicate qualification for early, late and absent matches,
  empty/nullable lists, and invalid tails after a matching first item. The
  current whole-value corruption checks remain mandatory. Add nullable by-kind
  float, malformed payload and maximum accepted nesting regressions at the
  field-contract owner.
- Establish a collection-query IC baseline through the existing SQL test actor:
  54 calls cover three list sizes, membership/emptiness, scalar controls and
  full-list output. Query instructions and full-message cycles are recorded
  separately for matched before/after comparison; no allocation-only attribution
  or universal query-cost claim follows from this fixture.
- Add full nested catalogue row qualification at 16 and 128 rows, including
  public-page continuation, independently checked field values, equivalent
  bindings and rejection before field consumption. Separate staged counters
  identify typed-adapter work without adding production instrumentation.
- Extend that retained catalogue fixture with exact label-output comparisons
  at both sizes. Full-row reads bracket selected-field calls on the same data;
  the existing bounded page owner and returned continuations remain in use.
