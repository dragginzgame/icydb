# IcyDB 0.217 — Explicit Canister Endpoint Exports

## 0.217.3

### 📝 Summary

- Completes the adversarial endpoint-export closeout after independently
  reconstructing all eight 0.217 patches from the 0.216.5 baseline.
- Preserves the deployed replica as the sole authority when an explicitly
  named endpoint is absent.
- Aligns shared IC runtime and test dependencies, and removes dormant
  EXPLAIN/SQL-diagnostic state from query-only builds.

### 🔧 Changed

- Updated `ic-cdk` to 0.20.2 and `ic-testkit` to 0.1.11, and moved to
  `time` 0.3.55 after removing the obsolete host-agent resolver guard. This
  keeps the workspace aligned with the maintained Canic, `ic-query`, and
  `ic-memory` dependency stack.
- EXPLAIN-only admission lanes and route facts now compile only with
  `sql-explain`. Ordinary public queries retain their existing mandatory
  limits, index requirement, full-scan rejection, and materialized-sort
  rejection.
- Projection, covering-read, data-store, and index-store instrumentation now
  compiles only for SQL diagnostics. Query-only and ordinary test builds no
  longer retain dormant callback or counter state.

### 🩹 Fixed

- Fixture loading now returns a missing deployed `icydb_fixtures_load` method
  as the replica failure instead of treating it as a successful local skip.
- The interactive SQL shell no longer labels an intentionally undeployed
  `icydb_query` method as stale Wasm based on local source assumptions.
- Nested canister builds use the lockfile consistently while retaining the
  exact frozen production and local/test Cargo feature profiles.

### 🗑️ Removed

- Removed the unreachable internal endpoint declaration parser and wrapper
  emitter left behind after `icydb::endpoints!` became the sole maintained
  public-wrapper authority. Private authorization-helper generation remains.
- Removed the unused prefix-cardinality lookup counter and related test-only
  diagnostic plumbing.

### 📊 Audit

- The complete 18-artifact production/local Candid-versus-raw-Wasm matrix
  matches the frozen migration policy with no undeclared IcyDB method.
- The endpoint closeout's exact tagged measurements keep production and
  local/test `sql_perf` below the 0.216.5 raw-Wasm baseline. Thirty-two warm
  SQL endpoint calls also use 20,320 fewer attributed instructions than the
  baseline cohort.
- The additional dependency and compile-ownership cleanup changes no accepted
  schema, endpoint or Candid response, successful query result, cursor, or
  persisted byte format.

### 🧪 Testing

- Expanded compile contracts cover duplicate blocks, handwritten same-name IC
  exports, invalid options and attributes, inactive declarations, and missing
  SQL, SQL-explain, extended-metrics, and fixture capabilities. SQL structural
  coverage now attributes both update policies to those public-macro tests
  instead of the removed internal emitter.
- Focused runtime checks prove controller authorization executes before SQL,
  fixture, schema, metrics, reset, and snapshot handlers.
- CLI, actor generation, grouped-query, package-shaped installation,
  warnings-denied Clippy, formatting, invariant, and diff-hygiene checks pass.
- Focused no-feature, query, diagnostics, SQL, and SQL-explain builds cover the
  tightened feature ownership. Full workspace and push-time suites remain
  release-owner validation.

## 0.217.2

### 📝 Summary

- Removes unreachable typed-query and grouped-response scaffolding while
  preserving query results, diagnostics, cursors, and persisted formats.
- Keeps `make test` and release validation exhaustive without making ordinary
  Cargo workspace tests recursively rebuild every maintained canister profile.

### 🔧 Changed

- Dynamic and SQL grouped execution now share one accepted-authority,
  execution-family, and cursor-preparation step.
- Grouped response finalization returns only the public rows and continuation
  cursor instead of carrying an unused execution trace through response
  shaping.
- The production/local 18-artifact Candid-versus-Wasm matrix is ignored by
  ordinary Cargo test discovery and runs deliberately through `make test`, the
  version-bump release gate, or `make test-canister-artifact-contract`.

### 🗑️ Removed

- Removed the never-produced `TypedQueryError::Binding` variant. Typed binding
  failures already enter the maintained database or row error paths.
- Removed unused executor-local row-flow counter scaffolding that had no
  production caller or effect on diagnostics.

### ⚠️ Breaking

- Rust callers with exhaustive matches over `TypedQueryError` must remove the
  `Binding` arm. No runtime error classification or serialized response shape
  changes.

### 🧪 Testing

- Fast policy completeness, ordering, ABI, Candid-parser, and Wasm-parser tests
  remain in ordinary Cargo runs; the exact built-artifact matrix remains part
  of the repository-owned full and release suites.

## 0.217.1

### 📝 Summary

- Adds bounded SQL-independent grouped dynamic and generated typed reads over
  the accepted-schema planner, cache, grouped executor, and public-value
  conversion already shared with SQL.
- Tightens feature ownership so query-only builds no longer compile helper
  surfaces used exclusively by SQL schema transitions, capability reporting,
  literal conversion, or result projection.
- Corrects malformed grouped facade requests to return query-intent or grouped
  read-admission diagnostics rather than planner-invariant errors.

### ➕ Added

- `DynamicQuery` and generated `Query<E>` can declare ordered group keys,
  aggregates, explicit group limits, page limits, and opaque continuation
  cursors, then execute through dynamic or typed grouped terminals without the
  SQL feature.
- `GroupedQueryOutput` is the engine-neutral grouped page for those new
  terminals. This is its initial public Candid shape; SQL keeps its existing
  response envelope and adapter.

### 🔧 Changed

- SQL-only schema mutation and transition helpers now follow the SQL feature
  boundary instead of remaining reachable in query-only builds.
- SQL capability, literal-conversion, and projection helpers are compiled only
  for the feature profiles that use them.

### 🐛 Fixed

- Scalar/grouped terminal mismatches and scalar selection on grouped output
  now use the typed query-intent diagnostic.
- Missing or zero grouped limits use the existing
  `GroupedQueryRequiresLimits` read-admission diagnostic. Public budget,
  full-scan, and invalid-cursor failures retain their established structured
  diagnostics.
- No accepted schema, persisted data, cursor, or existing successful SQL
  response format changes. Only malformed grouped-request error
  classification changes outwardly.

### 🧪 Testing

- Query-only, no-default, diagnostics, and SQL-enabled feature profiles retain
  their intended ownership boundaries.
- Focused runtime coverage proves exact intent, limits, budget, full-scan, and
  cursor diagnostics, accepted-binding staleness, trusted grouped paging, and
  the real generated `Query<E>::execute_grouped()` terminal in a canister that
  does not enable SQL.

## 0.217.0

### 📝 Summary

- Makes every maintained generated IcyDB endpoint an explicit declaration in
  the canister source, beside the lifecycle wiring it exposes.
- Separates compiled capability from public exposure: Cargo features determine
  what implementation can be built, while `icydb::endpoints!` determines the
  exact deployed Candid surface.
- Deletes the TOML endpoint configuration system and its CLI/build authority in
  a deliberate pre-1.0 hard cut.

### ➕ Added

- Added `icydb::endpoints!` with one fixed method per declaration, closed
  endpoint-specific options, compile-time capability checks, explicit
  authorization, and ordinary declaration-level `#[cfg]` support.
- Added one-argument `icydb::build::build_canister!(Canister)` generation for
  private runtime capabilities. `icydb::start!()` installs lifecycle and
  private wiring but never creates a public Candid method.
- Added exact canister-owned local/test and production feature profiles, with
  separate artifact directories and repository build entry points.
- Added the compilation-only `metrics-extended` capability and the public SQL
  performance response owner needed by fixed endpoint signatures.

### 🔧 Changed

- Fixture reset/load requires three independent locks: source declaration, the
  canister's `test-admin-api` feature, and controller authorization. Loading
  reuses the checked reset handler before invoking one fixed-signature hook.
- SQL query introspection requires `sql-explain`; SQL update declarations select
  exactly one of the primary-key-only or bounded-deterministic admissions.
- Metrics and schema authorization is explicit. Metrics reset and snapshot are
  controller-only, and undeclared methods are absent rather than disabled
  endpoints.
- Dependency-renamed canisters are supported consistently by both generated
  private actor code and public endpoint declarations.
- Internal text transforms, physical index-component materialization, grouped
  pagination windows, and redundant query/mutation carriers were consolidated
  without changing their maintained execution semantics.

### 🗑️ Removed

- Removed `icydb-config`, all seven maintained `icydb.toml` files, config
  discovery/resolution/reporting, endpoint build options, target-derived
  endpoint generation, and `ICYDB_CONFIG_PATH`/`ICYDB_BUILD_TARGET` policy.
- Removed the CLI `config` command, its complete module/test tree, TOML-derived
  preflight, endpoint-surface reporting, build-target inference, and config
  dependency.
- Removed `build_configured_canister!`, `BuildOptions`,
  `BuildSqlUpdatePolicy`, and `generate_with_options` without aliases or
  compatibility readers.

### ⚠️ Breaking

- Existing canisters must replace configured or implicit endpoints with one
  visible `icydb::endpoints!` block. Compiling a capability alone no longer
  exports its endpoints.
- Local-only endpoints must be controlled by explicit canister Cargo features
  that enable both the required IcyDB capability and their conditional source
  declarations. Production builds omit those features.
- Automation using `icydb config`, `icydb.toml`, or the removed build options
  must move to source declarations and ordinary Cargo feature profiles. No
  pre-1.0 compatibility layer remains.

### 🧭 Migration Notes

- Keep the generated actor build dependency and replace the build script call
  with `icydb::build::build_canister!(SchemaCanister)`.
- Keep `icydb::start!()` once at crate root, then declare only the IcyDB methods
  the canister intentionally exposes. Declaration order relative to `start!()`
  does not matter.
- Define local/test features in the canister's `Cargo.toml`, place matching
  `#[cfg(feature = "...")]` attributes on individual declarations, and build
  production with `--no-default-features` plus the frozen production feature
  set.
- Delete IcyDB TOML manifests and config-oriented CLI setup. The deployed
  replica/Candid surface is authoritative when a CLI call targets an absent
  method.

### 📊 Audit

- All nine maintained actors pass exact production and local/test Candid versus
  raw-Wasm export comparison. Production SQL, bounded SQL, and RPG actors omit
  their fixture and local-query methods; production RPG also omits extended
  metrics and its exclusive capability.
- The nine-actor production matrix falls from 32,264,810 to 30,108,745 raw
  non-gzipped bytes, a 2,156,065-byte (-6.6824%) reduction. The local/test
  matrix changes by only +4,518 bytes (+0.0140%).
- Production `sql_perf` is 5,316,766 raw bytes, 9,425 bytes (-0.1770%) below
  0.216.5. Thirty-two repeated real SQL endpoint calls average 707,717
  attributed instructions versus 708,368 at the release baseline (-0.0919%).
- A released-package-shaped canister with a renamed facade dependency builds
  natively and to Wasm without an IcyDB config file. The facade package listing
  and core archive preparation pass; facade archive preparation follows the
  normal same-version core-before-facade publication order.
- No accepted schema, row, key, index, relation, marker, journal, cursor,
  Identity, integrity response, endpoint argument/result type, or database
  persisted format changes in 0.217.0.

### 🧪 Testing

- Added deterministic Candid and raw-Wasm inspection, a frozen transitive ABI
  contract, exact nine-actor build policies, macro compile UI coverage, private
  handler/export guards, a package-shaped installation fixture, and the
  baseline/current endpoint-cost probe.
- Focused actor, facade, CLI, integration, package, canister, Clippy, invariant,
  formatting, dependency-feature, hard-cut search, raw-size, and endpoint-call
  validation passes. Full workspace and push-time suites remain release-owner
  checks.
