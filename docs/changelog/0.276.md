# 0.276 — Owned memory runtime

## [0.276.0] - 2026-10-16

- **Breaking: Memory 0.44.** Bind IcyDB to one bootstrapped `MemoryRuntime`
  retained by the application. Standalone generated startup constructs it;
  composed hosts call `bind_memory_runtime(Rc::clone(&runtime))` after bootstrap
  and before database startup. Storage opens, allocation diagnostics and
  integrity generation checks share that exact runtime. Rebinding the same
  instance is idempotent; replacing it or binding before bootstrap is rejected.
  Construction and binding errors retain typed causes in `DatabaseBootstrapError`.
  Policies now implement Memory's combined `RuntimeBootstrapPolicy` contract.
  Regenerate actor glue when updating consumers
  ([#365 — Memory allocation diagnostics adoption](https://github.com/dragginzgame/icydb/issues/365)).

- **Required retained-data action:** Memory 0.44 uses its current `ICMDIRCT`
  ledger snapshot and rejects earlier images. Retain the old binary and backups
  for required recovery/export, then explicitly retire or reset affected
  installations before adopting this image. No data reset is performed by this
  source change, and no older ledger reader is retained. IcyDB row, journal,
  checkpoint and cursor encodings are unchanged by this integration.

- Preserve IcyDB's allocation-report wire fields using Memory's canonical
  constants, measured bucket geometry and derived accounting methods. The
  reserved ledger slot is identified by upstream key/owner constants without
  claiming payload validation; live payload occupancy remains unavailable.
  Per-slot conversion now requires the containing report's bucket geometry;
  the context-free `From<ic_memory::MemoryAllocation>` conversion is removed.

- Correct checkpoint feature guards so the bounded writer is available without
  migration while the migration operation follows its feature-gated consumer.

- Repair the post-link invariant check to recognize Cargo requests derived from
  the maintained actor plan. Keep the checked batch-owner requirement intact.

- Use Host 0.22.1's explicit process failure-evidence renderer for optimizer,
  Candid and report tooling. Remove the optimizer-owned generic formatter and
  its duplicate test; preserve captured output and independent cleanup evidence.
  Adopt explicit replace/0666 options for staged Candid publication and retain
  owned CLI diagnostic strings at Host Text's borrowed-or-owned boundary
  ([#307 — Shared Host owners](https://github.com/dragginzgame/icydb/issues/307)).

- Keep wrapper-test control/server/command processes alive until explicit cleanup
  through private FIFO blockers. Preserve signal, exit-status, log-retention and
  unrelated-process survival assertions without expiring fixed-duration sleeps
  during portable CI qualification. Testkit retains all server supervision.

- Use Host's fork-safe executable-script writer in the Wasm-report fixture.
  Preserve tool admission, feature/metric parsing and drift rejection while
  preventing parallel launches from inheriting writable executable descriptors.

- Adopt IC Build 0.9's Cargo-derived profile directories and published inherited
  flag composer. Remove redundant profile plumbing and generic flag machinery;
  retain local remap policy, artifact/cache identities and collect-all builds.
  Adapt optimizer admission/publication to Host's explicit contracts and
  select Wasm interface inspection separately from Candid service inspection
  ([#307 — Shared build/Host owners](https://github.com/dragginzgame/icydb/issues/307)).

- Use one post-link cache transaction engine for single and batch actor builds.
  Preserve cache identity, reuse, optimizer policy and retained artifacts; keep
  producer failures primary and report independent abort cleanup failures.

- Share SELECT/mutation replay JSON and artifact-budget enforcement. Decode each
  replay through its own semantic admission once before comparing canonical
  bytes; retain current formats, typed failures and stale-record rejection.

- Share checked binary primitive writes across schema, cursor and journal
  codecs. Preserve byte order, format-owned ceilings, authentication/checksums
  and error classification; retain sticky overflow rejection for bounded schema
  envelopes.

- Keep each maintained actor's configuration and report context together in one
  build-plan entry. Derive ordered Cargo requests from those entries and consume
  the same plan during post-link preparation; retain profile/feature selection,
  collect-all failures and successful artifact ownership.

- Use the JSON dependency's nested object sorting for canonical test artifacts.
  Retain the existing byte format, scalar encoding and replay identities while
  removing the local recursive reconstruction of arrays and objects.

- Share deterministic first-match shrinking across SELECT and mutation cases.
  Preserve candidate order, exact signature matching, both budget ceilings and
  complete/incomplete replay accounting. Candidate generation and public reports
  remain owned by their respective lanes.

- Decode metrics, snapshot, schema and migration endpoint results through one
  typed CLI boundary. Keep malformed Candid failures distinct from decoded
  application errors, preserving target context, diagnostic facts, confirmation
  and query/update routing.

- Share SQL audit schema/startup wire records between the actor and integration
  harness. Keep independent Candid field/type expectations, including optional
  samples and wide instruction totals, so one shared declaration cannot hide
  an accidental wire-contract change.

- Convert runtime rows to public output values through one session-owned helper
  for structural projections, SQL, write RETURNING and grouped responses.
  Preserve accepted enum resolution, row order and typed failures while retaining
  row-at-a-time conversion.

- Reuse one lowercase hexadecimal encoder for database tokens, public blob text
  and CLI reports. Keep domain prefixes and bounded decoding with their existing
  owners; emitted text is unchanged.

- Share schema/snapshot report-section presentation while preserving titles,
  empty-state wording, indentation and table output. Keep terminal cell escaping
  and width handling in Host Text.

- Share fresh-thread isolation across native session fixtures. Keep each case's
  accepted schema and data setup local; return fixture results and forward the
  original child panic payload without replacing its diagnostic.

- Compile the shared structural panic scanner in a private source-check package,
  independently of database, build and simulator dependencies. Keep local root
  discovery and nonempty inventory checks; consume the shared semantic fixtures
  from an exact additive source snapshot
  ([Shared #225 — Rust panic scanner](https://github.com/dragginzgame/shared-tooling/issues/225)).

- Keep integration actor feature recipes beside their scenario owners. Build
  support retains one explicit variant-build operation and keeps retained
  artifact owners alive through each byte read. Actor roles, features, profiles
  and source/successor ordering are unchanged.

- Encode SQL and observability RPC arguments from their authoritative Candid
  types. Pass private binary argument files to ICP instead of maintaining SQL
  escaping and migration command text. Preserve integer widths, optional values,
  confirmations, endpoint routing and diagnostics; retire argument files after
  successful and failed child calls. Large SQL does not expand into process argv.

- Share journaled row/key traversal across visitor closures while preserving
  typed errors, bounds, early stop, live overrides and tombstones. Keep key-only
  reads and row preflight distinct. On the retained Memory 0.41 dependency graph,
  the matched SQL audit actor shrinks from 4,221,346 to 4,214,491 raw Wasm bytes.
  All 16 paired pre/post-reopen result digests match; instruction and cycle
  deltas range from −74 to +26 per sample. This does not qualify the incoming
  Memory 0.42 diagnostic hard cut
  ([#292 — Shared store traversal](https://github.com/dragginzgame/icydb/issues/292),
  [#365 — Memory adoption](https://github.com/dragginzgame/icydb/issues/365)).

- Align the query contract with the maintained accepted-index row-presence
  policy: an absent exact primary-key candidate may be ignored, while a missing
  row referenced by an accepted secondary index is typed store corruption.
  Qualify ordered DISTINCT group seek and retained-row execution in both
  directions against missing rows, invalid witnesses and malformed keys; cached
  plans retain that effective policy even for an Ignore intent. Runtime behavior
  and persisted formats are unchanged
  ([#149 — DISTINCT missing-row policy](https://github.com/dragginzgame/icydb/issues/149)).
