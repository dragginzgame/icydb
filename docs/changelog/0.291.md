# IcyDB 0.291

## [0.291.0]

### ⚠️ Breaking

- Encode schema fragments, proposals, migration plans and canonical source
  meanings through IC Wire under new `ICWF`/`ICWP`/`ICWM`/`ICWS` version-1
  identities. Change the migration-plan and source-meaning digest domains to
  `icydb.schema-migration-plan.wire.v1` and
  `icydb.entity-source-meaning.wire.v1`; proposal digests include the new framed
  bytes. Regenerate embedded and external artifacts together. Earlier source
  lineage, proposal/application receipts and pending migration identities cannot
  be reused or silently rebound to these digests. This joins the already selected
  fresh/reset-installation boundary for this release; any retained installation
  requires its own reviewed transition before installation. No compatibility
  reader, automatic conversion, lineage reconstruction or data reset is added.
  [#592](https://github.com/dragginzgame/icydb/issues/592).
- Encode durable Deep integrity-job payloads through bounded IC Wire under the
  checksummed `ICYIJWIR` version-1 record identity. Earlier Deep records must be
  explicitly retired before a qualified transition, or belong to a fresh/reset
  installation; never clear the shared progress tree independently. Physical
  keys, CRC framing, the progress allocation header, quotas and the separate
  resumable/mutation record families are unchanged. Same-contract reopening,
  interruption, terminal acknowledgement and exact receipt replay remain
  supported. This source change neither acknowledges jobs nor resets storage.
  [#594](https://github.com/dragginzgame/icydb/issues/594).
- Set the IC Platform minimum to published 0.8.3. Public read-authorization
  contexts and conversions between IcyDB's Principal atom and Platform's Principal now use
  Platform 0.8's owned identity. Consumers exchanging these Rust values must
  align their Platform dependency. Canonical Principal/Account bytes, text and
  native Wire encodings remain unchanged; no retained-data rewrite is required.
- Adopt published Memory/Storage 0.56.0 and align consumers exchanging IcyDB's
  exposed Memory types. Memory replaces its allocation ledger and enclosing Cell
  value with bounded IC Wire records (`ICML` / `ICMWIRE1`). Earlier CBOR bytes are
  unsupported: existing installations require fresh/reset memory or a separately
  reviewed transition before installation. No local compatibility decoder,
  converter or automatic reset is added. Never clear only the allocation ledger
  while retaining collection bytes. This source adoption does not reset or deploy
  data; retain earlier binaries and recovery evidence until each installation's
  disposition is qualified. See the supplier's
  [retained-installation contract](https://github.com/dragginzgame/ic-persistence/blob/956b2b92728f82f75dd51d4d10ed52f325529e91/docs/current-ledger.md#hard-cut-and-retained-installations).
- Replace the retired Memory bootstrap size-error fixtures with
  `StableCellLedgerEncode(ic_wire::Error)`, preserving typed causes and public
  internal-error classification. Memory owns allocation framing, decoding limits
  and recovery; IcyDB's row, index, schema and journal formats are unchanged.
  Existing numeric slots, checked custody and current-format reopening remain
  supported; the manager/Cell substrate layout is unchanged.

### 🩹 Fixed

- Explicitly enable Serde's `std` support in the model package, which uses
  `HashMap` in its diagnostic tree. Standalone Wasm builds no longer depend on
  another package supplying that feature; native behavior and serialized forms
  are unchanged.

- Execute declared list-item and map-value normalizers in declaration order,
  including scalar, optional and repeated map values. Preserve container-first
  normalization, child traversal, callback identities and entry-index issues.
  Reject direct set-item and map-key normalizers at macro parsing and model
  admission instead of silently ignoring them: normalize keys before insertion
  or rebuild through an explicit container normalizer. Key validators remain
  supported. This is a breaking correction to accepted declarations, without a
  compatibility path or persisted-format change. Application normalization stays
  explicit; database writes do not invoke these hooks. Record/entity field-item
  normalizers now follow scalar, optional and repeated cardinality, preserving
  field diagnostics and child traversal. Callbacks at an item position must
  implement `Normalizer<T>`; previously compiling whole-Option/Vec callbacks at
  that position must move their whole-container policy to a named collection or
  an explicit application operation. No legacy dispatch is retained. Other
  type-level and tuple/enum payload hook positions remain open in
  [#68](https://github.com/dragginzgame/icydb/issues/68).

- Protect the exact current generated schema-application receipt from terminal
  retention. The generated canister type resolves its submission and registry
  through the canonical application identity owner; the existing selected
  commit context carries that read-only resolver. Resolve only when capacity
  requires a victim, and keep physical lease identity independent of generated
  source. Pending receipts remain protected, other terminal records retain their
  stable-key retirement order, and a full store with no eligible victim returns
  the existing conflict before publication. Exact replay remains idempotent.
  No second readiness marker, retained-data format, cache, lifecycle route or
  dependency is added. Qualify capacity/refusal/reopening, context and lease
  isolation, and generated readiness through repeated control-only receipt
  turnover. [#34](https://github.com/dragginzgame/icydb/issues/34).

- Qualify the existing generated native database's thread isolation: independent
  workers using the same actor and primary key start empty, retain their own
  writes across startup/convergence driver calls and leave the caller's rows
  intact. Document fresh-thread fixtures rather than adding a global guard or
  destructively resetting a runtime with live exclusive handles. This rejects
  the proposed reset API in [#314](https://github.com/dragginzgame/icydb/issues/314);
  no production lifecycle or storage behavior changes, and application-specific
  fixture failures are not claimed resolved.

- Keep public schema-key Serde decoding on its established string hook for RPC
  reflection and reader-backed JSON. Apply tighter key/name/submission and
  direct-relation-list bounds at the authoring-artifact fields through IC Wire,
  preserving artifact bytes and digests. This repairs browser generation after
  [#592](https://github.com/dragginzgame/icydb/issues/592) without changing public
  endpoint metadata or introducing another codec.

- Accept bare positive SQL integers through `u128::MAX` using the existing
  `Nat128` atom when the value cannot fit Decimal's signed mantissa. Previously
  accepted literal types and canonical rendered spellings stay unchanged;
  fractional integer spellings, signed/unsigned field bounds and overflow
  refusals remain enforced. This admits, for example:
  ```sql
  SELECT balance FROM Ledger WHERE balance = 340282366920938463463374607431768211455;
  ```
  The shared SQL cursor serves standalone predicates, statements and CHECK
  rebinding. This addresses the unsigned literal range in
  [#232](https://github.com/dragginzgame/icydb/issues/232); floating-point
  render/parse identity remains open.
- Compare two `Nat128` values across their full unsigned range at the existing
  representation owner. Database comparison and compiled expression consumers
  delegate to that exact comparison instead of rejecting values above
  `i128::MAX`. Keep Decimal arithmetic and mixed-type coercion unchanged. Stored
  values, ordered keys, Wire forms and cursor/fingerprint bytes are unchanged;
  no new numeric mode or compatibility path is added. This addresses the
  same-type unsigned portion of
  [#110](https://github.com/dragginzgame/icydb/issues/110); floating-point and
  mixed-type comparison work remains open.
- Verify every touched index-store generation before opening a row commit
  window, instead of returning a stale-preflight error after its marker is
  already durable. The synchronous prepared window no longer carries those
  guards into Apply. Regression coverage changes either of two stores and
  checks typed refusal, unchanged database-control proof and absence of a
  recovery marker, then proves refreshed guards can publish and retire normally.
  This is the preflight portion of
  [#152](https://github.com/dragginzgame/icydb/issues/152); post-marker journal
  failure outcomes and their atomicity contract remain open there.

### 🧹 Cleanup

- Parse the browser Wire generator's optional output path with the existing Clap
  dependency. Preserve the default directory and native path bytes; help exits
  successfully and invalid/surplus arguments reject before schema generation or
  filesystem output. Generated contracts and vectors retain their existing
  serialization and budget owners.
  [#595](https://github.com/dragginzgame/icydb/issues/595).
- Remove the handwritten schema primitive codec and fragment/proposal/migration
  field walkers. Serde describes the domain shapes; IC Wire owns byte traversal
  and bounded fallible allocation. Keep schema collection/name/literal/depth
  limits, semantic validation and exact decode/re-encode canonical admission at
  IcyDB. Recompute derived migration digests rather than accepting supplied ones.
  Build-time generation and runtime application use the same public encoders
  and decoders; no generator-specific codec is retained.
- Remove the Deep-job primitive writer/reader and manual tag traversal. Private
  bounded Serde projections preserve field admission without changing public RPC
  DTOs. Keep job/proof/checkpoint/receipt validation and canonical payload refusal
  at the persistence boundary. Core now consumes IC Wire directly on deployed
  targets for this codec; its TypeScript feature remains host-only.
- Remove the workspace's direct `serde_cbor` declaration and Schema's test-only
  dependency. Replace CBOR fixtures and duplicate helpers with IC Wire coverage
  for scalar and batch shapes, exact widths, malformed inputs, truncation and
  domain refusals; retain JSON coverage for human-readable forms. This test
  dependency cleanup itself changes no production codec or stored format.
  Upstream PocketIC and IC transport
  dependencies still use CBOR, as does the browser agent's HTTP transport.
- Use `ic_wire::ByteBuf` for Schema Blob decoding and Wire sizing fixtures. This
  is Wire's re-export of the same Serde bulk-byte type, available at the existing
  minimum version; encodings, admission limits and error behavior are unchanged.
  Move Schema's remaining `serde_bytes::Bytes` fixture dependency to development
  dependencies. Core's separate target-specific dependency boundary is unchanged.
  [#593 — Reuse IC Wire's bulk-byte type](https://github.com/dragginzgame/icydb/issues/593).
- Share migration rewrite/final-validation program order, predecessor skipping,
  candidate preparation, current-entity cursor selection and latest accepted
  cursor retention. Reuse the existing phase page accumulators to carry capacity
  across entities. Capacity is checked before preparing the next candidate;
  rewrite keeps its row/row-byte/index-byte/effect/journal limits and journaled
  store requirement, while final validation keeps its row/byte limits. An
  unfinished entity ends the page. Index cleanup and row decoding remain at their
  existing owners. Boundary coverage exercises resumed row limits across entities,
  empty predecessor/final entities and restart, alongside existing byte limits
  and marker recovery. No public API, format, phase or limit changes.
  [#566 — Migration pages repeat the same program walk](https://github.com/dragginzgame/icydb/issues/566).
- Admit dynamic and typed mixed mutation batches through one captured accepted
  root, ordered admission loop and identity-insert count before the existing
  atomic executor. Request-specific entity lookup, binding checks and lowering
  remain statically dispatched. Preserve shape limits before lookup, stale
  binding refusal before store checks, store/entity limits before lowering,
  per-item result order and no publication on rejection. Owned and shared typed
  bindings use the same checks; the same-entity typed batch retains its simpler
  route without an entity-tag set. No public API, diagnostic, retained format,
  policy mode or dependency changes.
  [#565 — Mutation batches repeat the same admission](https://github.com/dragginzgame/icydb/issues/565).
- Generalize the existing ordered budget-pair charge to an ordered resource
  sequence and migrate its consumers directly. Page-output accounting borrows
  the active hard tracker once for the complete ordered charge sequence;
  existing two-resource consumers preserve their original amounts and order.
  Earlier and attempted charges survive refusal while later charges remain
  unapplied, and page receipts advance only after all charges succeed. Empty
  and zero-only work still avoids a borrow; inactive optional accounting remains
  a no-op. No atomic reservation bundle, extra counter, interval, policy or
  retained-state change is introduced. Differential coverage compares the
  single-resource owner across all resources, repeated charges, three read
  lanes, both limit scopes and refusal positions. Remaining route-reservation
  arithmetic, usage snapshots and performance qualification stay open under
  [#293](https://github.com/dragginzgame/icydb/issues/293).
- Give commit-marker control operations one field layout for allocation-free
  sizing and byte emission. A private typed output boundary keeps sizing
  infallible and saturating while emission retains existing checked u32 lengths
  and typed errors. Remove the separate per-operation size table and optional
  replacement-size calculation. Tags, field order, marker format, journal-batch
  ranges and the pre-publication size/writer drift guard remain unchanged.
  Frozen payload identities cover zero through four control operations,
  including maximum mutation-progress images, alongside appended-buffer offsets,
  exact journal envelopes and unknown-tag corruption refusal.
  [#588 — Commit markers repeat the same layout](https://github.com/dragginzgame/icydb/issues/588).
- Keep ordinary Principal consumers on Platform's minimal owned capability.
  Facade authorization tests explicitly select self-authentication and external
  conversions through a development dependency. The three authorization actors
  select self-authentication only where their fixtures need it. Schema's Principal
  regression retains IcyDB/Platform conversion and Wire-byte coverage; the
  supplier-only external conversion assertions belong to Platform's tests.
  No application protocol, decoder budget, guard, trap or lifecycle path changes.
- Route limited key/component scans and their bounded chunk variants through one
  resumed range visit with the existing charged key-advancement checks. Chunk
  scans share raw-entry counting and resume-anchor retention only at bounded
  stops; natural exhaustion still returns no anchor. Non-chunk scans retain
  their output limits without that counting or anchor ownership. Decoding,
  component selection, predicate-before-witness refusals and output allocation
  bounds remain with their existing owners. Zero entry/output limits still
  return before traversal, charging or decoding. No public API, cursor format,
  policy mode or dependency changes.
  [#553 — Index range scans repeat the same visit](https://github.com/dragginzgame/icydb/issues/553).
- Decode supported hybrid covering components and shape their row through the
  existing row projector. Keep the shared sparse-field reader and each page's
  missing-row/offset admission at their current owners: proven pages discard
  skipped pairs before row reads, while checked pages establish presence before
  counting an offset row. Both retain ordering and window application at their
  existing stages. Unsupported components still decline the entire optimization,
  malformed payloads preserve typed errors, and projection charging occurs only
  after successful component decoding. Repeated index/row columns retain their
  clone-until-last-use ownership. No policy callback, new mode or retained format
  is introduced.
  [#580 — Hybrid covering rows repeat the same projection](https://github.com/dragginzgame/icydb/issues/580).
- Partition accepted CHECK, NOT NULL and targeted-rule sources in one pass over
  each accepted/activation catalog. Borrow rule payloads and preserve accepted
  sources before pending sources within each family. Feed the existing compilers
  in their original order and retain the separate unique-write-barrier and
  single-activation admission paths. The extra targeted-source bucket is
  temporary and bounded by the existing catalog limits; row execution and
  retained programs are unchanged. Mixed-family coverage protects stable
  violation identity and excludes pending gates from integrity checks.
  [#563 — Constraint sources repeat the same catalog scan](https://github.com/dragginzgame/icydb/issues/563).
- Share one mixed-overlay visitor body within each Data, Index and Schema store.
  Forward and reverse iterator construction stay statically dispatched through
  the existing ordered-overlay merge. Each store retains its visitor/error type,
  early-stop policy and existing canonical-only/live-only fast paths. Data key
  scans still avoid row-value reads; Index visits retain their entry-read seam.
  Schema regression coverage exercises early stop, typed errors on live and
  canonical entries, and natural exhaustion in both directions with overrides
  and tombstones. No traversal framework, new mode, allocation or retained format
  is introduced.
  [#559 — Overlay directions repeat the same visit](https://github.com/dragginzgame/icydb/issues/559).
