# IcyDB 0.216 — Explicit Application Behavior And Durable Rules

## 0.216.3

### 📝 Summary

- Removed redundant commit-preparation and grouped-continuation intermediates
  so both paths construct their canonical runtime contracts directly.
- Unified dynamic, typed, and SQL projected rows on one engine-neutral
  `RowProjectionOutput` without changing query results or their Candid shape.
- Refreshed the final closeout record through the released 0.216.2 boundary,
  including its exact raw-Wasm, package, dependency, and format evidence.

### 🔧 Changed

- Index preparation now constructs `PreparedIndexMutation` directly; the
  duplicate non-persisted commit-index carrier and conversion are gone.
- Grouped continuation planning now constructs its outward window directly;
  the duplicate draft/finalization carrier is gone without changing cursor
  validation, resume arithmetic, or pagination handoff order.
- `RowProjectionOutput` is now owned by the engine-neutral core response layer
  and is the common result for dynamic reads, typed row decoding, SQL
  projections, rendering, and CLI output.

### ⚠️ Breaking

- Removed the duplicate public Rust `DynamicQueryResult`. Dynamic query APIs
  now return `icydb::db::RowProjectionOutput`.
- Hard-cut the nested `icydb::db::response::RowProjectionOutput` import path;
  SQL callers use the engine-neutral `icydb::db::RowProjectionOutput` path.
  No alias or compatibility wrapper remains.

### 📊 Audit

- The shared projected-row type is byte-equivalent to the frozen Candid record
  containing `entity`, `columns`, `rows`, and `row_count`.
- No row, key, accepted-schema, marker, journal, cursor, Identity, integrity,
  database-error, or Candid wire layout changes in 0.216.3.
- The final 0.216.2 closeout remains ready with one explicit non-blocking
  follow-up: attribution of the roughly 12–13% cross-line no-rule
  mutation/guard instruction increase.

## 0.216.2

### 📝 Summary

- Corrected timestamp and duration edge semantics, separated engine-neutral
  Blob values from proposal-literal admission, and removed obsolete scalar
  conversions in a deliberate pre-1.0 Rust API hard cut.
- Simplified collection membership evaluation and kept minimal-feature SQL
  fixture canisters warning-free without changing query results or endpoint
  availability.
- Preserved Unicode `UPPER(...)` semantics in full boolean expressions while
  preventing text-casefold predicates from selecting incompatible `UPPER`
  expression-index keys.
- Added the final 0.216 closeout audit and corrected the frozen release scope,
  raw-Wasm, package-size, Date-domain, and persisted-format evidence.

### 🩹 Fixed

- Timestamp addition and subtraction now perform the complete operation in a
  wide signed domain before saturating, so the full unsigned Duration range is
  handled correctly at both timestamp boundaries.
- Microsecond, nanosecond, RFC3339-fractional, and whole-second conversion now
  floor consistently before the Unix epoch instead of truncating toward zero.
- Duration text whose unit multiplication exceeds `u64` now returns
  `InvalidDuration` rather than silently saturating.
- SQL fixture-loading, oversized-response, and SQL-only query helpers now
  compile only with the SQL feature that owns their endpoints and imports.
- Boolean-expression canonicalization no longer rewrites `UPPER(field)` to
  `LOWER(field)`. Full SQL execution retains the authored transform, while the
  reduced predicate-only contract rejects unsupported `UPPER` wrappers.
- Casefold lookup planning now admits only semantically matching `LOWER`
  expression indexes and cannot answer Unicode lowercase predicates from an
  uppercase key domain.

### 🔧 Changed

- `Blob` is now an engine-neutral byte atom with infallible `From<Vec<u8>>`,
  `From<&[u8]>`, and related conversions. The 64 KiB limit remains at the
  `ScalarLiteral::Blob` proposal boundary instead of constraining all runtime
  and Candid Blob values.
- Scalar/list `contains_any`, `contains_all`, and case-insensitive variants no
  longer allocate a temporary vector or carry impossible internal optionality;
  their existing public `Option<bool>` surface and results are unchanged.
- Time-atom and Blob contract tests now live beside the schema types that own
  those semantics; redundant facade tests were removed.

### ⚠️ Breaking

- Replaced the always-successful `Duration::try_from_u64` with
  `Duration::from_millis`.
- Removed saturating `From<u64> for Timestamp`; callers requiring fallibility
  use `Timestamp::try_from_u64`.
- Removed unit-error `TryFrom<f32>` and `TryFrom<f64>` implementations for
  finite floats; callers use `Float32::try_new` and `Float64::try_new`.
- Removed `Blob::try_new`; Blob construction is infallible and proposal
  literal validation owns the bounded failure.
- Removed the unused `InvalidFloat` and `InvalidUlid` parse-error variants.
  No deprecated aliases or compatibility wrappers remain.
- Reduced predicate-only `UPPER(field) LIKE 'prefix%'` and
  `STARTS_WITH(UPPER(field), 'prefix')` now reject with the maintained typed
  unsupported-feature diagnostic. Use `LOWER` for that casefold contract;
  `UPPER` remains supported as an ordinary full SQL scalar expression.

### 📊 Audit

- The final closeout reconstructs all eight planned 0.216 patches and finds no
  correctness, authority, recovery, compatibility, or format blocker.
- The released 0.216.2 SQL performance Wasm is 5,327,610 raw bytes with
  SHA-256
  `e8cbe879d0a642f9824dc555ee4ddc3fea4edd514d2f30ff99200c5b73b3ac78`.
  It is 462 bytes (0.009%) below the released 0.216.1 artifact. The packaged
  `icydb-model` crate is 101,684 compressed bytes across 109 files with
  SHA-256
  `e6eb8730e52d3aba843740f5b294f1e978ccf5adbd8f2c95aa010033a20f8562`.
- Release tooling resolves `clap` and `clap_builder` uniformly to 4.6.5; the
  final CLI dependency graph contains no duplicate version.
- The roughly 12–13% cross-line no-rule mutation/guard cost increase remains
  an explicit performance follow-up. A measured empty-rule shortcut did not
  improve it and was not retained.

### 📊 Audit — Persisted And Public Formats

- 0.216.2 changes no persisted row, key, schema, marker, journal, cursor,
  Identity, integrity, database-error, or Candid wire layout.
- Blob Candid values may now exceed the proposal-literal limit, duration text
  overflow rejects, pre-epoch timestamp conversion floors consistently, and
  `UPPER` predicates preserve their authored Unicode transform. The removed
  Rust constructors, conversions, and reduced-predicate forms are intentional
  behavioral and API hard cuts.

## 0.216.1

### 📝 Summary

- Completed the 0.216 closeout with final generated-helper reachability,
  correctness, instruction-cost, raw-Wasm, package-size, format, and
  complexity evidence.
- Removed unconsumed low-level Rust conveniences, marker traits, and hidden
  generated-code aliases.
- Bounded `Date` to the proleptic Gregorian `0000-01-01` through `9999-12-31`
  calendar and made raw-day construction, persisted decoding, cursor decoding,
  timestamp-to-date projection, and day arithmetic fail explicitly outside
  that domain.

### 🔧 Changed

- Replaced infallible `Date::from_days_since_epoch` with
  `Date::try_from_days_since_epoch` and added `checked_add_days`,
  `checked_sub_days`, and `days_since`.
- `Date::MIN` and `Date::MAX` now describe the supported calendar boundary
  rather than the complete `i32` epoch-day domain.
- Date decoding now rejects out-of-range Candid values, persisted row slots,
  cursor values, numeric values, and schema defaults instead of constructing
  an unrenderable value. Date projections from out-of-range timestamps reject
  instead of saturating to an unrelated boundary date.
- `TypeParseError` display text now identifies the rejected scalar category
  rather than returning one generic parse message.

### 🗑️ Removed

- Removed the unused `Kind` and `StoreKind` marker traits. `CanisterKind` now
  states its actual `Path + 'static` requirements directly.
- Removed the unused `ScalarRelationTargetKeyMatchesDeclaredPrimitive` marker;
  the canonical scalar-key codec remains the key-shape authority.
- Removed unconsumed `Predicate` and `CompareFieldsPredicate` convenience
  constructors for field-to-field comparisons. Maintained parser lowering
  constructs the existing explicit comparison form directly.
- Removed the unused `DbSession::select_one`, `DbSession::prepare_sql_ddl`,
  `Value::is_unit`, and macro-internal `NodeGen` conveniences.
- Removed `Date` implementations of `Add`, `AddAssign`, `Sub`, and `SubAssign`;
  callers now use the explicit checked day operations.
- Narrowed `icydb::__macro` to the 35 helpers emitted by maintained generated
  code and `icydb::__reexports` to the two dependencies used by actor glue.
  The facade also drops its unused direct `ctor`, `derive_more`, and `remain`
  dependencies.

### ⚠️ Breaking

- The removed Rust APIs have no aliases, deprecated wrappers, or forwarding
  traits. This is the intended pre-1.0 hard cut.
- Existing development data containing a `Date` outside
  `0000-01-01..=9999-12-31` no longer decodes and must be recreated. There is
  no legacy fallback or saturating conversion.
- Field-to-field application code should use `FilterExpr::eq_field` and its
  related typed forms, or construct `CompareFieldsPredicate::with_coercion`
  explicitly at the lower-level boundary.
- Replace `select_one()` with the intended literal value and `is_unit()` with
  direct `Value::Unit` matching. There is no replacement public prepare-only
  SQL DDL surface; maintained administration executes through the accepted
  schema-mutation boundary.

### 📊 Audit

- Every remaining hidden facade helper has a maintained generated
  construction site. The typed-adapter fixture now proves named-value traits
  through their owning model crate rather than a duplicate runtime-facade
  route.
- Focused scans found all 15 maintained durable rules on the typed grammar,
  no old string/positional rule authoring, no application callback in database
  execution, no generated-model runtime fallback, and no old-profile decoder.
- The final released SQL performance Wasm is 5,328,072 raw bytes, 0.477% above
  the frozen early-0.216 baseline. Its SHA-256 is
  `16b4e4527e5380157f474ecd9a58dfa3c76b4b3720efb143fa2cf8f952d15587`.
- A matched accepted rule adds roughly 0.8–1.4% to steady journaled writes.
  The wider 0.215.7-to-0.216 no-rule mutation/guard path remains roughly
  12–13% higher and is retained as an explicit performance follow-up rather
  than hidden by another budget increase.

### 🧪 Testing

- Focused facade, model, macro, schema, targeted-rule, predicate/parser,
  generated-canister, adapter, Date boundary/codec/projection, performance,
  compile-contract, architecture, formatting, and warnings-denied Clippy
  validation passes.
- The full workspace and push-time suites remain release-owner validation.

### 📊 Audit — Persisted And Public Formats

- 0.216.1 changes no proposal, accepted-schema, row, key, index, relation,
  marker, journal, cursor, integrity, database-error, or Candid response wire
  layout. `Date` remains an `i32` epoch-day value in persisted rows, cursor
  tokens, and Candid, but decoding now rejects values outside the maintained
  calendar domain. The Rust API removals and narrower accepted `Date` domain
  are deliberate pre-1.0 hard cuts.

## 0.216.0

### 📝 Summary

- Replaced string-selected durable-rule operations and positional operands
  with one closed typed grammar whose operands are named and checked by the
  model compiler.
- Kept durable enforcement under accepted-schema authority while making Rust
  normalizers and validators explicit application operations.
- Made the required trait contract of every generated application value type
  unconditional and compiler-owned.
- Completed maintained consumer conversion and removed obsolete pre-hard-cut
  helpers, diagnostics capture paths, runtime-value bridges, and duplicate
  tests that no longer had a live caller.

### ➕ Added

- Added exact `numeric_maximum_inclusive` and integer/fixed-scale-decimal
  `multiple_of` durable operations alongside the existing length, minimum,
  and numeric-range operations.
- Added the consuming `NormalizeAndValidate::normalize_and_validate()`
  application convenience. It normalizes first, validates second, returns the
  normalized value only on success, and never participates in database
  admission or recovery.
- Added typed application-operation, callback-kind, callback-path, and bounded
  value-path diagnostics for explicit normalization and validation failures.
- Added catalog-native same-identity durable-rule evolution. An operation or
  operand edit retains its accepted constraint ID, keeps the old operation
  authoritative while the candidate gates new writes, and uses the existing
  bounded validation, publication, abort, and recovery machinery.

### 🔧 Changed

- Durable rules now require exactly one operation with named operands:

  ```text
  rule(name = "length", length_range_inclusive(min = 1, max = 40))
  rule(name = "minimum", numeric_minimum_inclusive(value = 0))
  rule(name = "maximum", numeric_maximum_inclusive(value = 100))
  rule(name = "range", numeric_range_inclusive(min = 0, max = 100))
  rule(name = "step", multiple_of(divisor = 5))
  ```

- `Clone`, `Debug`, `Path`, `CandidType`, `Deserialize`, `Eq`, `PartialEq`,
  `NormalizeAuto`, `ValidateAuto`, and `Visitable` are emitted for every
  generated application value type. Authors cannot add or remove required
  traits; ergonomic, override, and shape-derived traits remain independently
  configurable.
- Direct validation now checks the supplied value without silently normalizing
  a copy. Generated typed adapters and every database write ingress remain
  callback-free.
- The 15 maintained built-in durable-rule declarations use the typed grammar.
  Schema-only and renamed-dependency downstream fixtures exercise the complete
  operation vocabulary and explicit application behavior.
- A stable local durable-rule name remains source identity. Changing an
  operation or operand uses catalog-native evolution; changing the local name
  remains an explicit removal plus fresh addition.
- Scalar key eligibility and encoding now converge directly on the canonical
  key codec rather than an obsolete generic runtime-value abstraction.

### ⚠️ Breaking

- Removed the old durable-rule `kind = "..."` and positional rule
  `args(...)` grammar. No deprecated spelling, alias, dual expansion, or
  compatibility parser remains. Application normalizer and validator
  constructor arguments are unaffected.
- Hard-cut the sole version-1 proposal operation shape and changed the current
  accepted snapshot profile from `ICYT` to `ICYU`. The semantic fingerprint
  remains in its current domain and consumes the new canonical bytes.
- Required generated traits can no longer be explicitly added or removed.
- Explicit normalization and validation return the typed visitor-error
  boundary rather than an untyped or serializable application-error surface.
- Removed the unused `icydb_model::build_with_options!` build-script macro;
  maintained canister builds use the configured build facade.
- Removed unused public/internal helper surfaces rather than carrying pre-1.0
  compatibility for APIs with no maintained consumer.

### 🗑️ Removed

- Removed unconsumed hidden structural-read, row-check, scalar-lane, and SQL
  projection diagnostics capture APIs and their dormant recorder plumbing.
- Removed the unused public explain-plan continuation-signature helper; cursor
  signature derivation remains runtime-internal.
- Removed the obsolete core generic runtime-value conversion and collection
  traits. Public wrapper and collection traits resolve to their model owner.
- Removed unused low-level internal-error helpers, stranded pre-hard-cut test
  sources, uncompiled duplicate tests, and unused helper/dependency edges.
- Removed generated-authority schema-mutation cases while reconnecting current
  catalog-native planning coverage to the active test suite.

### 📊 Audit — Authority Boundaries

- A durable rule is compiler-authored proposal metadata that lowers to one
  accepted targeted constraint per reachable persisted root. Accepted schema
  is the only runtime authority for typed, structural, SQL, and batch writes,
  integrity, activation, replay, and recovery.
- A validator is explicitly invoked Rust application behavior. It checks the
  value supplied by the caller and cannot substitute for an accepted database
  constraint.
- A normalizer is explicitly invoked Rust application behavior that may change
  the caller-owned value. It is never persisted as a callback, trigger,
  rewrite language, or recovery policy.
- Generated models remain proposal and application conveniences. Runtime code
  does not reconstruct accepted authority from them.

### 📊 Audit — Persisted And Public Formats

- The schema proposal remains contract version 1, but its nested durable-rule
  operation enum is the new current form.
- The accepted schema remains version 1 with current profile `ICYU`.
  Fingerprint tags retain length range `1`, numeric minimum `2`, and numeric
  range `3`, then append numeric maximum `4` and multiple-of `5`.
- Rows, primary and secondary keys, layouts, relations, commit markers,
  journals, cursors, constraint-validation jobs, integrity progress, and
  public database Candid response shapes are unchanged by the durable-rule
  cut.
- Pending same-identity semantic edits may project the validated operation and
  candidate activation as adjacent lifecycle entries with the same stable ID;
  the response type itself is unchanged.

### 🧭 Migration Notes

- Rewrite every old declaration directly:

  ```text
  rule(name = "range", kind = "numeric_range_inclusive", args(0, 100))
  ```

  becomes:

  ```text
  rule(name = "range", numeric_range_inclusive(min = 0, max = 100))
  ```

- Recreate development and test stores whose accepted snapshot uses `ICYT`.
  There is no old-profile decoder, translation path, dual read, or dual write.
- Remove explicit `traits(add(...))` or `traits(remove(...))` requests for
  required generated traits. Keep only supported ergonomic or override trait
  configuration.
- Replace `icydb_model::build_with_options!` with the maintained configured
  canister build facade.
- Call `normalize`, `validate`, or `normalize_and_validate` explicitly where
  application behavior is desired. Do not expect typed, structural, or SQL
  writes to invoke application callbacks.

### 🧪 Testing

- Model and macro suites cover the complete typed grammar, invalid operands,
  required-trait diagnostics, all maintained built-in declarations,
  deterministic application traversal, and typed callback diagnostics.
- Core coverage proves exact lowering and fingerprints, direct and nested
  admission across typed/structural/SQL writes, stable-ID rule evolution,
  direct promotion, durable activation, abort, guarded recovery, and
  application-only validator/normalizer edits.
- Schema-only and typed-adapter downstream packages compile through renamed
  dependencies and prove that generated actor wiring contains no application
  callback route.
- Both SQL test-canister variants compile the shared application-behavior
  probe through explicit direct model dependencies; the bounded variant no
  longer relies on the primary canister manifest to supply an unavailable
  crate.
- Focused warnings-denied Clippy, no-default-feature compilation, formatting,
  diff hygiene, authority guards, and retired-grammar searches pass. Full
  workspace and push-time validation remain release-owner checks.

### 📊 Audit — Complexity

- The implementation reuses the accepted constraint catalog, evaluator,
  activation jobs, markers, publication, integrity, and recovery owners. It
  adds no callback registry, dynamic dispatch, source-model runtime fallback,
  or second durable-rule evaluator.
- The no-rule write path performs no per-row source-rule work. Explicit
  application behavior incurs cost only when application code calls it.
- Raw non-gzipped Wasm remains the authoritative size measure; detailed
  implementation snapshots and complexity deltas are recorded in the 0.216
  status tracker.
