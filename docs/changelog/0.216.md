# IcyDB 0.216 — Explicit Application Behavior And Durable Rules

## 0.216.0

### 📝 Summary

- Replaced string-selected durable-rule operations and positional operands
  with one closed typed grammar whose operands are named and checked by the
  model compiler.
- Kept durable enforcement under accepted-schema authority while making Rust
  normalizers and validators explicit application operations.
- Made the required trait contract of every generated application value type
  unconditional and compiler-owned.
- Completed maintained consumer conversion and removed obsolete pre-hard-cut
  helpers, diagnostics capture paths, runtime-value bridges, and duplicate
  tests that no longer had a live caller.

### ➕ Added

- Added exact `numeric_maximum_inclusive` and integer/fixed-scale-decimal
  `multiple_of` durable operations alongside the existing length, minimum,
  and numeric-range operations.
- Added the consuming `NormalizeAndValidate::normalize_and_validate()`
  application convenience. It normalizes first, validates second, returns the
  normalized value only on success, and never participates in database
  admission or recovery.
- Added typed application-operation, callback-kind, callback-path, and bounded
  value-path diagnostics for explicit normalization and validation failures.
- Added catalog-native same-identity durable-rule evolution. An operation or
  operand edit retains its accepted constraint ID, keeps the old operation
  authoritative while the candidate gates new writes, and uses the existing
  bounded validation, publication, abort, and recovery machinery.

### 🔧 Changed

- Durable rules now require exactly one operation with named operands:

  ```text
  rule(name = "length", length_range_inclusive(min = 1, max = 40))
  rule(name = "minimum", numeric_minimum_inclusive(value = 0))
  rule(name = "maximum", numeric_maximum_inclusive(value = 100))
  rule(name = "range", numeric_range_inclusive(min = 0, max = 100))
  rule(name = "step", multiple_of(divisor = 5))
  ```

- `Clone`, `Debug`, `Path`, `CandidType`, `Deserialize`, `Eq`, `PartialEq`,
  `NormalizeAuto`, `ValidateAuto`, and `Visitable` are emitted for every
  generated application value type. Authors cannot add or remove required
  traits; ergonomic, override, and shape-derived traits remain independently
  configurable.
- Direct validation now checks the supplied value without silently normalizing
  a copy. Generated typed adapters and every database write ingress remain
  callback-free.
- The 15 maintained built-in durable-rule declarations use the typed grammar.
  Schema-only and renamed-dependency downstream fixtures exercise the complete
  operation vocabulary and explicit application behavior.
- A stable local durable-rule name remains source identity. Changing an
  operation or operand uses catalog-native evolution; changing the local name
  remains an explicit removal plus fresh addition.
- Scalar key eligibility and encoding now converge directly on the canonical
  key codec rather than an obsolete generic runtime-value abstraction.

### ⚠️ Breaking

- Removed the old durable-rule `kind = "..."` and positional rule
  `args(...)` grammar. No deprecated spelling, alias, dual expansion, or
  compatibility parser remains. Application normalizer and validator
  constructor arguments are unaffected.
- Hard-cut the sole version-1 proposal operation shape and changed the current
  accepted snapshot profile from `ICYT` to `ICYU`. The semantic fingerprint
  remains in its current domain and consumes the new canonical bytes.
- Required generated traits can no longer be explicitly added or removed.
- Explicit normalization and validation return the typed visitor-error
  boundary rather than an untyped or serializable application-error surface.
- Removed the unused `icydb_model::build_with_options!` build-script macro;
  maintained canister builds use the configured build facade.
- Removed unused public/internal helper surfaces rather than carrying pre-1.0
  compatibility for APIs with no maintained consumer.

### 🗑️ Removed

- Removed unconsumed hidden structural-read, row-check, scalar-lane, and SQL
  projection diagnostics capture APIs and their dormant recorder plumbing.
- Removed the unused public explain-plan continuation-signature helper; cursor
  signature derivation remains runtime-internal.
- Removed the obsolete core generic runtime-value conversion and collection
  traits. Public wrapper and collection traits resolve to their model owner.
- Removed unused low-level internal-error helpers, stranded pre-hard-cut test
  sources, uncompiled duplicate tests, and unused helper/dependency edges.
- Removed generated-authority schema-mutation cases while reconnecting current
  catalog-native planning coverage to the active test suite.

### 📊 Audit — Authority Boundaries

- A durable rule is compiler-authored proposal metadata that lowers to one
  accepted targeted constraint per reachable persisted root. Accepted schema
  is the only runtime authority for typed, structural, SQL, and batch writes,
  integrity, activation, replay, and recovery.
- A validator is explicitly invoked Rust application behavior. It checks the
  value supplied by the caller and cannot substitute for an accepted database
  constraint.
- A normalizer is explicitly invoked Rust application behavior that may change
  the caller-owned value. It is never persisted as a callback, trigger,
  rewrite language, or recovery policy.
- Generated models remain proposal and application conveniences. Runtime code
  does not reconstruct accepted authority from them.

### 📊 Audit — Persisted And Public Formats

- The schema proposal remains contract version 1, but its nested durable-rule
  operation enum is the new current form.
- The accepted schema remains version 1 with current profile `ICYU`.
  Fingerprint tags retain length range `1`, numeric minimum `2`, and numeric
  range `3`, then append numeric maximum `4` and multiple-of `5`.
- Rows, primary and secondary keys, layouts, relations, commit markers,
  journals, cursors, constraint-validation jobs, integrity progress, and
  public database Candid response shapes are unchanged by the durable-rule
  cut.
- Pending same-identity semantic edits may project the validated operation and
  candidate activation as adjacent lifecycle entries with the same stable ID;
  the response type itself is unchanged.

### 🧭 Migration Notes

- Rewrite every old declaration directly:

  ```text
  rule(name = "range", kind = "numeric_range_inclusive", args(0, 100))
  ```

  becomes:

  ```text
  rule(name = "range", numeric_range_inclusive(min = 0, max = 100))
  ```

- Recreate development and test stores whose accepted snapshot uses `ICYT`.
  There is no old-profile decoder, translation path, dual read, or dual write.
- Remove explicit `traits(add(...))` or `traits(remove(...))` requests for
  required generated traits. Keep only supported ergonomic or override trait
  configuration.
- Replace `icydb_model::build_with_options!` with the maintained configured
  canister build facade.
- Call `normalize`, `validate`, or `normalize_and_validate` explicitly where
  application behavior is desired. Do not expect typed, structural, or SQL
  writes to invoke application callbacks.

### 🧪 Testing

- Model and macro suites cover the complete typed grammar, invalid operands,
  required-trait diagnostics, all maintained built-in declarations,
  deterministic application traversal, and typed callback diagnostics.
- Core coverage proves exact lowering and fingerprints, direct and nested
  admission across typed/structural/SQL writes, stable-ID rule evolution,
  direct promotion, durable activation, abort, guarded recovery, and
  application-only validator/normalizer edits.
- Schema-only and typed-adapter downstream packages compile through renamed
  dependencies and prove that generated actor wiring contains no application
  callback route.
- Focused warnings-denied Clippy, no-default-feature compilation, formatting,
  diff hygiene, authority guards, and retired-grammar searches pass. Full
  workspace and push-time validation remain release-owner checks.

### 📊 Audit — Complexity

- The implementation reuses the accepted constraint catalog, evaluator,
  activation jobs, markers, publication, integrity, and recovery owners. It
  adds no callback registry, dynamic dispatch, source-model runtime fallback,
  or second durable-rule evaluator.
- The no-rule write path performs no per-row source-rule work. Explicit
  application behavior incurs cost only when application code calls it.
- Raw non-gzipped Wasm remains the authoritative size measure; detailed
  implementation snapshots and complexity deltas are recorded in the 0.216
  status tracker.
