# 0.285

## [0.285.0] - 2026-10-26

### ⚠️ Breaking

- SQL CHECK/index creation, generated CHECK validation and schema-proposal
  CHECK/index admission reject the exact case-sensitive `__icydb_` prefix.
  The schema naming owner supplies one prefix policy. Accepted catalog decoding
  and engine construction still permit primary-key, NOT NULL and targeted-rule
  names. Rejected authoring cannot occupy the name needed by a later NOT NULL
  column addition or advance the accepted schema head. Existing retained
  catalogs are not rewritten; new user-authored names must use another prefix
  ([#209](https://github.com/dragginzgame/icydb/issues/209)).
- Column-less INSERT VALUES and INSERT SELECT now use accepted field order,
  excluding managed fields. Nullable/defaulted fields retain their positions;
  changing omission policy cannot silently redirect supplied values. Removed
  the required-field-count heuristic and source-width inference. Callers using
  shortened positional tuples must name their target columns, or supply every
  position (including DEFAULT where appropriate). DEFAULT VALUES is unchanged.
  Coverage checks both input routes, exact field placement, explicit omission,
  typed width rejection and atomic rejection of a mixed-width VALUES batch
  ([#223](https://github.com/dragginzgame/icydb/issues/223)).

### 🩹 Fixed

- Refresh malformed lifecycle-participant and SQL guard compile-fail diagnostics
  for the selected Canic adapter revision; preserve the expected macro rejections.
- Query preparation and expression lowering now charge each visited conjunction
  comparison pair against the caller's existing construction budget. Signature
  hashing and index/check compilation reuse this admission where construction
  authority already exists. One fallible normalization traversal preserves
  canonical output, pair precedence and absorbing-branch behavior; exhaustion
  propagates without returning a partial predicate or resetting request counters.
  Catalog binding without construction authority retains the pure entrypoint;
  its budget propagation and other normalization allocation/sort costs remain
  outside this correction
  ([#76](https://github.com/dragginzgame/icydb/issues/76), partial).
- Relation transitions skip the old projection and reverse-entry merge when
  every direct source component, or the complete nested source root, has
  identical physical bytes. The final image still undergoes normal projection,
  budget admission and target-existence validation against the batch's final
  view. Unrelated updates therefore no longer double-charge unchanged high-fanout
  relations. Changed fields and absent historical slots retain ordinary
  two-image admission; batch limits, retained formats and recovery modes are
  unchanged. No measured instruction/cycle or raw Wasm improvement is claimed
  ([#61](https://github.com/dragginzgame/icydb/issues/61), partial).
- Fresh convergence checks physical root extents without initializing lazy
  journal stores. Control encoding and capacity preparation complete before
  journal initialization and publication; returned preparation failures no
  longer leave a journal header that prevents fresh admission on retry.
  Existing non-virgin roots still reject, and retained-database reconciliation
  keeps its tail validation. Regression coverage checks repeated read-only
  admission, rejection of an existing header, and successful initialization
  after rejected control preparation
  ([#146](https://github.com/dragginzgame/icydb/issues/146)).
- Optional in-memory prefix cardinality retains at most 4,096 distinct entries
  across its leading-component and longer-prefix maps per index store. Crossing
  that cap clears both maps and uses the existing unavailable-evidence behavior;
  later writes and synchronization cannot publish partial counts. Multiplicity
  changes at the cap remain exact. Authoritative index rows and the separate
  journal-overlay delta are unchanged; no persisted format or configuration is
  added. Instruction, cycle and raw Wasm-size effects are unmeasured
  ([#58 — Unbounded prefix metadata](https://github.com/dragginzgame/icydb/issues/58)).
- SQL, bounded-SQL and SQL-perf production actors no longer export fixture
  seeding, trusted-query or measurement helpers. Those helpers consistently
  require the existing test-admin feature. A focused artifact check compares
  their complete production application exports with the maintained generated
  endpoint policy and verifies local helper retention. Across all maintained
  actors, the existing profile contract also rejects production update exports
  outside generated endpoints and explicit actor-owned probe allowlists.
  Intentional reachability, relation, grouping and authorization-control probes remain
  admitted; timer exports retain their independent admission. Local profiles
  retain their fixture surfaces
  ([#120 — Fixture endpoints escaping production policy](https://github.com/dragginzgame/icydb/issues/120)).

### 🔧 Changed

- Align the root dependency minimums with the already-selected published graph:
  Build/Host/Testkit 0.68.8, Platform 0.6.19, Wire 0.7.17, Memory/Storage 0.51.4,
  Metrics 0.16.3 and Timers 0.31.5. Preserve feature flags, dependency roles,
  workspace release versions and the immutable Canic adapter selection. The
  independent browser Platform selection remains current at 0.1.0.
- Refresh Shared Tooling canonically to published commit `a7f85d4` (0.26.20),
  excluding uncommitted producer edits. Adopt compact task-specific guidance
  and opt-in detailed reporting. Replace the browser harness's local SDK scanner
  with Shared's declaration/import checker for authored and generated sources;
  Existing IC tool pins remain unchanged. No storage migration or application
  wire-format change is required by these selections. Historical runtime qualification remains
  labelled separately from current consumer checks.

- Same-type `Nat128` ordering and equality use checked integer inputs instead
  of constructing two Decimals. Both inputs still must fit the signed Decimal
  mantissa; values at or above `2^127` remain outside numeric-widen admission.
  Differential coverage includes zero, the `u64` boundary, adjacent values at
  the signed-mantissa boundary and `u128::MAX`, in both operand orders and
  mixed numeric/non-numeric pairs. Float coercion and performance qualification
  remain open; no instruction, cycle or raw Wasm-size improvement is claimed
  ([#112](https://github.com/dragginzgame/icydb/issues/112), partial).
- Materialized-row, result and discarded-output accounting reuse the existing
  paired-charge owner instead of separately borrowing the active budget for
  each resource. Scalar and grouped row readers call one ordinary function
  instead of expanding a charging macro. Exact limits, charge order, partial
  failure accounting and inactive behavior remain unchanged. Route reservation
  and usage-snapshot work remain open; no instruction, cycle or raw Wasm-size
  improvement is claimed
  ([#293 — Repeated per-row budget accounting](https://github.com/dragginzgame/icydb/issues/293), partial).

### 📚 Documentation

- The request-execution attribute and public future now document first-poll
  root ownership and the panic when a pending future moves beneath another
  request root. Applications should share completed data rather than pending
  request futures. The actual attribute is covered by the cross-root rejection
  and native scope-restoration regression. Runtime behavior is unchanged;
  a fallible public integration contract remains unresolved
  ([#161 — Cross-root async polling](https://github.com/dragginzgame/icydb/issues/161), partial).
- Resumable application progress atomically replaces only its own record.
  Callback writes survive ordinary errors and post-page invalidation; successful
  invalidation receipts also need handling. API and durability guidance explain
  read-only/idempotent work, exact-replay limits and the separate IC message
  rollback boundary without promising native or earlier-message rollback
  ([#272 — Application side effects and progress atomicity](https://github.com/dragginzgame/icydb/issues/272)).
- Ordinary structural, typed and SQL write batches retain per-call mutation
  bounds but do not automatically install aggregate mutation instruction
  accounting. Resource and facade guidance distinguish these writes from
  explicitly budgeted mutation-job advances and warn against treating request
  headroom as write admission
  ([#284 — Ordinary structural-write budget limits](https://github.com/dragginzgame/icydb/issues/284)).

### ⚠️ Breaking

- Endpoint names, IDs and bidirectional lookup now come from one roster in the
  Canic adapter. Endpoint and lifecycle envelopes move to `canic_icydb::wire`;
  callers supply `icydb::wire::limits` using the existing request/reply ceilings.
  Native payload encoding and precommit complete-response sizing stay in IcyDB.
  The consumer selects immutable Canic contribution `45db926a326712f402fa639e0ca2888031988973`
  ([Canic #652](https://github.com/dragginzgame/canic/pull/652)); there is no alias,
  alternate endpoint roster or new lifecycle/memory owner. Managed composition
  remains tracked by [#373](https://github.com/dragginzgame/icydb/issues/373).
- Remove unused model exports `MAX_ENTITY_NAME_LEN`, `MAX_FIELD_NAME_LEN` and
  `MAX_INDEX_NAME_LEN`. Maintained sibling/source searches find no consumer;
  schema name admission and differently scoped persisted identity limits are
  unchanged ([#469](https://github.com/dragginzgame/icydb/issues/469)).

### 🧹 Cleanup

- Planning and diagnostic scoring share equality-operand admission, borrowed
  per-slot equality resolution, lookup-coercion eligibility and complete range
  family admission. Concrete key ownership, bound materialization and diagnostic
  reasons retain their distinct projections and existing budget order.
- Journal admission carries the accepted entity-tag projection into its immutable
  batch. Tail revision updates no longer reopen the schema bytes. Raw variants
  and decoded recovery records still pass the same payload and batch-shape
  admission; retained journal bytes are unchanged. Constructor/batch admission
  remains independently protective ([#273](https://github.com/dragginzgame/icydb/issues/273)).
- Fixed read, mutation and aggregate request profiles derive from one common
  resource array, retaining all ceilings, failure reserves and policy identity.
- Enum/composite reference checks share bounded container recursion while
  retaining separate catalog leaf checks. Migration validation, rewrite and
  final validation share exact entity/checkpoint bounds while keeping their
  phase-specific resource and recovery behavior.
- Schema reports and DESCRIBE share the same fifteen accepted field cells,
  preserving headers and layouts. Normalizer callbacks share invocation and
  issue emission across scoped/unscoped contexts. Entity, Record and Enum share
  custom trait dispatch without changing their individual baselines.

Raw Wasm-size, cycle and instruction changes are unmeasured; source convergence
is not a measured performance claim. No package version bump or release action
is part of this batch.

### 📊 Audit

The ten-outcome complexity batch spans 70 IcyDB files and eleven Canic contribution
files, excluding unrelated incoming edits. Physical Rust churn is +791/-896
(net -105) in IcyDB and +297/-45 (net +252) in Canic, or +1,088/-941 (net +147)
combined. These are authored source/test lines, not semantic deletion or measured
Wasm savings. One endpoint roster replaces repeated projections; the source
increase includes independent producer tests and explicit native-policy plumbing.

Focused native, lint, generated-consumer and three installed endpoint/lifecycle
checks pass. Broader gates, native macOS, fresh public MSRV and matched permitted
cost deltas remain unqualified or unmeasured. Canic-managed runtime composition
retains its separate owner and acceptance.
