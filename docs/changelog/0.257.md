# IcyDB 0.257

## 0.257.0 — Bounded Query Preparation

### 🔧 Changed

- Accepted-value normalization and canonical validation also reuse exact
  big-integer lengths, removing four size-only encodings. Field-limit errors,
  encoded-byte budget charges and persisted payloads are unchanged. Matched
  structural writes reduce warm instructions 0.39–3.07% and whole-update cycles
  0.16–1.47%; matched raw Wasm shrinks 141 bytes with unchanged function count.
  The test-admin measurement endpoint adds a separate 2,705 raw bytes and five
  functions. See the [catalog-admission receipt](../design/0.257-typed-query-explain/0.257-catalog-admission-perf.md).
- Big-integer literal size checks no longer allocate an encoding, and filter
  conversion no longer clones a freshly parsed integer for validation. Exact
  typed big integers reuse their storage; necessary container copies charge
  the current request before cloning. Signed/unsigned encoded byte limits,
  accepted input families and persisted encodings are unchanged. Decimal parser
  internals and unrelated catalog copies remain separate accounting work.
  Dedicated warm instruction medians improve, while cycle changes range from
  −0.873% to +0.605%; this is not a blanket cycle speedup. Matched raw Wasm adds
  375 bytes and loses one function, excluding the separately measured audit
  fixture/probe cost. See the [big-integer receipt](../design/0.257-typed-query-explain/0.257-big-integer-perf.md).
- Accepted-schema filter conversion reuses unchanged text/blob values and
  collections containing only unchanged values. Conversions construct a separate
  result only when needed, preserving the original literal if an element fails.
  Introduced list storage, copied elements, hex decode buffers and enum-label
  copies now charge the current request before allocation; scalar parsing charges
  an input-byte work allowance. SQL grouped-HAVING callers propagate exhaustion
  from the same conversion owner. Parser internals and deeper catalog admission
  are not yet fully covered by these preparation charges.
  Matched numeric controls add at most 0.543% whole-update cycles and 1.172%
  instructions; raw Wasm grows 3,433 bytes and three functions. Unchanged-storage
  reuse is tested separately, not presented as a measured text-query speedup.
  See the [conversion receipt](../design/0.257-typed-query-explain/0.257-value-conversion-perf.md).
- Typed/structural `AND` and `OR` use a balanced initial-expression builder.
  Flat input width adds logarithmic junction depth
  without changing operand order, schema-directed conversion, empty-list
  identities, duplicates or NULL operands. No new intermediate collection is
  introduced by the builder.
- Typed nonempty `IN`/`NOT IN` moves its admitted value vector into the existing
  compact membership operation, sharing construction with SQL. It no longer
  builds and subsequently collapses a comparison tree or clones every value
  during lowering. Empty typed lists retain their constant results. The shared
  compiler uses its existing per-value comparison path for collection operands
  and mixed coercions instead of treating those operands as scalar IN values.
- Shared boolean normalization collects each same-operator input group before
  normalizing its terms, then sorts, deduplicates and rebuilds once. It no longer
  repeats those steps for every nested binary subtree. Groups exposed by term
  normalization are flattened without normalizing their contents again.
- Canonical boolean sorting renders already-normalized operands directly,
  removing recursive normalization and expression cloning from comparisons.
  Canonical ordering, identity and CASE expansion policy are unchanged by this
  repair; it introduces no additional pagination migration.
- Request-metered canonical sorting now renders each operand label once and
  retains a typed Debug key only when labels tie. The temporary table and output
  buffers are charged and discarded at the sort boundary; comparisons still consume the
  current request, and failure leaves operands unmoved. This reduces redundant
  construction without adding another cache or normalization route.
- Boolean CASE expansion now has a fixed, content-based rewrite budget that
  accounts for both condition copies, introduced nodes and variable payload
  before copying. Larger expressions keep the existing compact CASE form and
  compiler/evaluator. This limits optimization growth without introducing a
  query-rejection policy; access-path opportunities can change for affected
  queries. Allocation capacity and request state cannot change the decision.
  The duplicate CASE expansion in predicate compilation is removed, so it
  cannot undo the canonicalizer's decision. Predicate projection remains
  whole-expression based: retaining CASE can also prevent an adjacent indexable
  conjunct from supplying a predicate access path. Existing scan-admission
  rules still apply; no partial-extraction planner is added.
- Typed/dynamic requests now share fixed pre-lowering admission: at most 128
  authored expression/value levels, 4,096 input nodes and 2 MiB of variable
  payload across the request. Checks include filters, membership values,
  ordering, aggregates, selected/group fields and cursor text before cloning or
  simplification. Ordinary public and trusted reads use the same policy.
  Structural filter lowering now borrows the admitted input instead of cloning
  its complete frontend tree. Owned dynamic requests detach recursive children
  during cleanup, including errors from consuming typed terminals.
- SQL preparation now uses the same shared input budget, replacing its separate
  depth-only walk. Parsed query/write statements, introspection and CHECK
  expression syntax are checked before preparation; warm query and mutation
  compilation cannot bypass admission. Bound SQL retains its existing scalar
  slot/vector limits and additionally accounts for every effective operand copy
  before substitution. Accepted-schema normalization and cache policy are unchanged.
- SQL expression cleanup is iterative at the syntax owner, including parser
  errors and retained dispatch destruction. Runtime-value disposal is shared
  with typed requests. Postfix parsing transfers its accumulated operand instead
  of cloning it; BETWEEN checks both copies before its required duplication.
  Alias rewriting now shares one scalar-child traversal and keeps existing
  boxes/vectors while transferring owned children.
- Planner expression cleanup now also belongs to the expression owner, covering
  intermediate trees and ordinary destruction rather than only consuming dynamic
  requests. Boolean/CASE, aggregate-input, affine and SQL literal rewrites transfer
  owned children in place, preserving boxes/vectors and eliminating redundant
  CASE-child clones. The dynamic-request-specific planner-expression destructor
  and its unused extraction accessors are removed. This is ownership work toward
  fallible preparation, not completed request-work charging.
- Typed filter lowering now propagates request-budget failures through the
  existing structural preparation path. It charges frontend expression visits,
  nested literal visits, raw literal text/vectors, copied field names and
  introduced expression backing storage before that work. Text and collection
  operators share one construction flow; empty membership produces allocation-free
  planner constants.
  A short-lived context borrows the session's existing request counters;
  retries and derived sessions do not reset them. Public/trusted and exact-count
  preparation retain their current routes and accepted-schema conversion.
- Planner labels now stream through one shared writer instead of building
  subexpression strings and joining them. The writer stops on sink failure and
  preserves escaping, precedence and aggregate identity. Existing String
  consumers remain infallible; canonical sorting uses a request-limited sink.
  This is not the pending public explain-renderer hard cut.
- Canonical normalization now propagates typed request exhaustion through typed
  intent and SQL preparation. Abortable ordering charges key construction and
  comparisons without substituting partial keys or changing successful order.
  SQL command-cache hits still skip compilation; bound invocations prepare their
  current values, and aggregate classification cannot disguise exhaustion as a
  different query shape.
- Filter labels reuse canonical planner trees without cloning/re-normalizing.
  Comparison operands and function arguments retain their allocations, while
  HAVING append drops an unused policy switch and predicate-only filters avoid
  unnecessary expression preparation.
- Canonical normalization still owns sorting, simplification and deterministic
  left-associated boolean-junction identity. These are preparation improvements, not
  an end-to-end stack-safety guarantee. SQL grammar, cursor formats and storage
  remain unchanged. Complete construction/copy and traversal accounting, typed
  `.explain()` and bounded diagnostics remain pending.

### ⚠️ Breaking

- Typed lowering and shared canonical preparation now consume existing request budgets even without
  an active row executor. Exhaustion returns typed request-resource facts;
  cached plans and a trusted route do not exempt lowering work actually performed.
- Oversized typed/dynamic input now fails with a typed depth, node or payload
  diagnostic, including trusted reads. Simplify nesting or split large inputs;
  a trusted route is not an exemption. Caller construction, standalone DTO
  Clone/Debug/drop and decoding are not newly bounded by execution admission.
- SQL inputs and effective binding copies exceeding the shared limits also
  reject, without a trusted-route exemption. Existing parser lexical limits
  remain in force. No predecessor admission mode or concrete bound-command cache
  is retained; DDL semantic authority stays catalog-owned.
- Nonempty typed membership changes the expression shape used by affected query
  fingerprints and continuation signatures. Restart affected pagination after
  upgrading. The current version-1 cursor format and typed signature-mismatch
  rejection remain in place; there is no predecessor hash, decoder or fallback.
  Public arguments and stored rows do not change.
- CASE expressions retained in compact form also change affected fingerprints
  and continuation signatures. Restart their pagination after upgrading.
  No old canonicalizer, predecessor fingerprint or compatibility cursor path
  is retained; the cursor format stays version 1.

### 🧪 Testing

- Focused coverage exercises accepted-schema conversion, empty and singleton
  filters, uneven widths, source order and balanced depth through 4,096 operands;
  canonical-association parity includes NULLs and duplicates.
- Added canonical-output, deduplication, association, idempotence, comparison
  direction and double-NOT/opposite-operator boundary checks. An ignored manual
  native timing test isolates normalization from input-tree construction and
  row execution; it is not a timing assertion in the correctness suite.
- Compact membership coverage checks owned-list handoff, constant expression
  depth, results and predicate evaluation against explicit comparisons, NULLs,
  duplicates, negation, empty lists, collection operands, accepted scalar
  families, wrong-type rejection and current-value cache rebinding.
- Added normalized-label/order parity, mixed-operator and nested-CASE checks,
  plus a manual native preparation probe. Matched baseline/candidate canonical
  models and label bytes produce the same receipt digest.
- CASE budget coverage includes exact copied-payload boundaries, capacity-
  independent identity, large/container/big-integer operands, repeated
  canonicalization, first-match/NULL results through the compiled evaluator,
  predicate-projection limitations and stored-row A/B/A binding execution.
- Input admission coverage adds exact and cumulative depth/node/payload limits,
  discarded branches, order/aggregate operands, warm reads after rejection and
  deep owned-request cleanup on a small native stack. This is not a Wasm stack
  measurement or a proof of planner-produced construction bounds.
- SQL input coverage includes query/write and CHECK syntax, effective binding
  copies, pre-copy BETWEEN rejection, partial parser-error cleanup and retained
  A/B/A statement execution after rejection without reparsing. Existing SQL,
  fingerprint, cursor and SQL-free typed-input controls continue to pass.
- Planner-owned cleanup has a small-native-stack probe for 20,000-level unary,
  binary, CASE, function and aggregate trees, plus nested literal values. It does
  not establish a Wasm stack bound or bound recursive cloning/formatting.
- Typed lowering adds nested-value and cold/warm request-exhaustion coverage,
  including shared-root retries, lane attribution and no row execution before
  rejection. Constructor coverage tests exact storage allowances and one-byte-short
  rejection across all introduced shapes, plus empty no-allocation cases.
  Streaming labels add exact-text and every-output-boundary failure
  tests. The existing canonical-model/label receipt, fingerprint and cursor
  controls remain unchanged.
- Canonical preparation adds abortable-sort/tie-break tests, small-stack cleanup
  after exhaustion, and session coverage for typed cold/warm calls, SQL command
  hits and bound A/B/A rejection. Aggregate classification preserves resource
  errors, and failed commands are not cached. The frozen canonical receipt is
  now asserted directly.

### 📊 Audit

- Typed filter construction adds 37 production and 185 test/propagation lines
  across seven files including five docs, consolidating repeated operand-building
  branches while enforcing existing request limits. Matched whole-update cycle
  increases stay below 1%; raw audit Wasm grows 696 bytes and four functions.
  A 16-term AND instruction median rises 4.655% (+275,370), crossing the existing
  review threshold despite a 0.240% cycle increase. That cost-review flag remains
  open; see the [construction receipt](../design/0.257-typed-query-explain/0.257-filter-construction-perf.md).
- Fallible canonical preparation touches 46 files including propagation, tests
  and four docs. Its ordering owner adds 149 production and 140 test lines;
  the affected paths have about +2,000 pending Rust lines versus 0.256.1,
  including preceding 0.257 work. Explicit accounting adds code without a new
  semantic route. Native 128-term normalization increases from 30–32 to 54–57
  microseconds; compact 128-value IN stays near 13 microseconds. This is a
  measured safety cost, not an IC/Wasm or full-query result. Complete allocation
  and traversal qualification remains open in the
  [current status](../design/0.257-typed-query-explain/0.257-status.md).
- Typed lowering and streaming-label work touches 16 files including four docs,
  adding approximately 170 production and 300 test/wiring lines. Accounting adds
  explicit fallibility; streaming removes repeated strings without adding a
  second conversion route or label grammar. Repeated native 128-value membership
  preparation rises from 8.1 to 14.4 microseconds (77.6%): this is a measured
  accounting cost, not a speedup or full-query/IC-cycle result. See the
  [current qualification](../design/0.257-typed-query-explain/0.257-status.md).
- Planner-expression ownership work changes 19 files including tests and docs,
  removing approximately 200 net production Rust lines and adding a focused
  52-line cleanup test. One expression-owned destructor replaces request-specific
  cleanup, and in-place child traversal replaces repeated rebuilding. Work
  charging and its cost qualification remain unfinished; no runtime-speed or
  Wasm-size improvement is claimed from source reduction alone.
- SQL integration spans 27 files, adding approximately 25 net production Rust
  lines and 225 test lines plus docs. It replaces the depth-only walker, shares
  runtime-value cleanup and merges scalar alias traversals while adding input
  checks and iterative syntax destruction. One admission authority and one
  preparation flow remain; no performance or Wasm-size delta was measured.
- Typed input admission spans 24 files including diagnostics, tests and docs,
  adding approximately 470 net production Rust lines and 280 test/wiring lines.
  Explicit accounting and iterative cleanup add code but no alternate execution
  route or normalization authority; one whole-filter clone is removed. No native
  speed, IC-cycle or Wasm-size improvement is claimed for this safety slice.
- Initial lowering converges two fold implementations on one helper, removing
  15 net production lines and adding 191 net test lines. Shared normalization
  adds 18 net production lines plus 149 test/timing/wiring lines while eliminating
  repeated subtree work. Compact membership removes another seven net production
  lines across five owners and adds 277 test/timing/wiring lines; its 13-file
  slice converges typed/SQL construction on one representation. The combined
  pending handoff through compact membership spans 17 files, with no new mode,
  public API or runtime authority. The subsequent ordering repair spans eight
  files: executable production line count stays unchanged, two intent-comment
  lines and 126 test/timing lines are added, and the production flow is simpler.
- Repeated native microbenchmarks show about 83% less normalization time for
  balanced 64/128-term synthetic input (about 5.9x throughput for this pass).
  This excludes initial tree construction and all row execution; it is not
  an IC-cycle or full-query latency claim. See the
  [measurement receipt](../design/0.257-typed-query-explain/0.257-normalization-perf.md).
- Compact membership reduces native preparation of a 128-value typed `IN` from
  about 528 microseconds to 6.8 microseconds in repeated matched probes. This
  includes lowering, normalization and predicate derivation, but no row execution.
  Its baseline already includes the preceding normalization improvement; the
  percentages must not be combined. See the separate
  [membership receipt](../design/0.257-typed-query-explain/0.257-membership-perf.md).
- Removing comparator re-entry reduces six-level nested-CASE native preparation
  from about 270 ms to 1.2 ms (99.6% less time) in repeated matched probes with
  debug assertions disabled. This is not full-query latency or IC-cycle evidence;
  see the [ordering receipt](../design/0.257-typed-query-explain/0.257-ordering-perf.md).
- Bounded CASE rewriting reduces that same six-level native preparation from
  about 1.23 ms to 0.10 ms (91.8% less time) against the completed comparator
  repair; smaller measured cases remain near their prior timings. This is not
  an end-to-end or IC-cycle result. The twelve-file slice adds approximately
  122 production and 227 test/wiring lines while replacing two CASE expansion
  owners with one bounded owner. See the
  [CASE budget receipt](../design/0.257-typed-query-explain/0.257-case-budget.md).
- An extra SQL-only test-target lint attempt exposed 64 unused migration-helper
  errors outside this edit. The repository's prescribed lint gate is the release
  control; SQL/migration tests use the combined feature configuration.
- Matched Wasm instruction/cycle evidence for metered sort-key reuse is recorded
  in the [canonical ordering receipt](../design/0.257-typed-query-explain/0.257-canonical-wasm-perf.md).
  With isolated 128-term application-built AND/OR queries, engine instructions
  fall 25.24%/21.06% and whole-update cycles fall 17.79%/14.67%; compact IN
  controls match exactly and warm SQL retains its compilation savings.
  The maintained reachable-entity audit actor grows by 198 raw Wasm bytes and
  two defined functions. This is not the full-line footprint or the pending
  SQL-free explain substitution gate. Full-suite validation remains user-owned;
  applications and Cargo versions are unchanged.
