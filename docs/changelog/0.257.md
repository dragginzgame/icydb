# IcyDB 0.257

## 0.257.5 — Preparation and Diagnostics

### ➕ Added

- Generated application values support `traits(add(Serialize))` for application
  blob codecs without handwritten field serializers. Deserialization remains
  automatic; serialization remains opt-in through the existing trait owner.
- Single-package canisters can share ordinary `src/design` modules between
  `src/build.rs` and the runtime. `build_canister!` resolves the type's canonical
  model path, not call-site spelling, and tracks the invoking source file.
  Separate model libraries remain supported; no path aliases are required.

- Typed `Query::explain()` returns the existing detached logical plan without
  SQL, row execution or generated row decoding. Current accepted binding and
  index lifecycle checks run through ordinary planner/cache authority. Logical
  scans/sorts may be inspected even when public execution would reject them.
  Grouped queries require explicit positive limits; all supplied cursors reject
  with `ExplainDoesNotAcceptCursor`. Dynamic grouped shape validation is shared
  with execution. Canonical reports retain their fallible 1-MiB output contract.

### 🔧 Changed

- **Internal pre-1.0 hard cut: recreate databases.** Application receipts and
  checkpoint/lineage/migration records now share one variable-page control tree,
  removing the fixed 256-MiB checkpoint partition and duplicate physical headers.
  Current boot identity is `ICYDBCTL`, still format version 1; no compatibility
  decoder, in-place conversion or automatic reclamation is provided. Record
  codecs, admission/retention limits and marker-owned publication remain intact.
  Absent metadata inspection does not allocate storage. Fresh journaled fixture
  backing drops from the original 488 MiB to 64 MiB (86.9% less); the explicitly
  migration-enabled native fixture also falls from the intermediate 304 MiB to
  64 MiB. Production bucket policy is unchanged. Matched costs and lifecycle
  evidence are recorded in the downstream qualification receipt.
  The maintained shared-source fixture covers serialization, native access and
  PocketIC install/write/read/upgrade, with an opt-in native attribution probe.

- Control-record inspection borrows allocation names from its validated payload
  instead of constructing owned strings that identity, key and header readers
  discard. Only callers retaining the allocation registry materialize ownership.
  Fixed four-role arrays replace temporary role/order vectors. Encoding and
  decoding share the same registry checks; persisted bytes, corruption rejection
  and bounded-header semantics are unchanged. No cache or new format is added.

- Typed binding validation selects the session's commit domain before reading
  its incarnation and reuses that checked value within the synchronous match.
  This removes a repeated durable-control read and prevents an unrelated
  previously selected allocation from rejecting a valid retained session.
  Startup, stale/foreign binding, accepted-schema and mixed-batch checks remain
  enforced; no identity is cached across requests or a query builder's lifetime.

- Typed binding issuance borrows the verified accepted schema bundle instead
  of cloning every entity's schema. The returned binding remains owned; current
  authority, descriptor compatibility and live constraint-job checks are unchanged.
  The schema borrow ends before execution or publication. No new binding cache,
  lazy authority or explain-specific path is introduced.

- Removed `ExplainPlan::fingerprint()` and its diagnostic hash construction.
  Use structured plan fields or canonical text/JSON for diagnostic comparisons.
  Cache, accepted-schema and cursor identities are unchanged. The diagnostic
  profile/source adapters, retained digest and fallible HAVING hash-label plumbing
  are deleted; continuation hashing consumes planner semantics directly. There
  is no replacement hash, compatibility method or optional hashing mode.

- Access fingerprints borrow already-lowered keys for single-key, multi-key and
  key-range paths. The private visitor no longer carries an unused generic key
  conversion that cloned every payload; key lists reuse the existing value-list
  hash loop. Ordinary continuation identity retains its bytes and traversal order. No request counter, public API or key-admission policy changes; nested
  value hashing and unordered-map scratch remain separate qualification work.
- Predicate encoding borrows unchanged scalar and membership literals instead
  of deep-copying them for coercion. Only numeric/text conversions own replacements;
  raw IN/NOT IN lists sort borrowed-or-converted views using the same value-set
  ordering/dedup owner as owned values. Already-normalized lists retain their
  no-sort path. Predicate bytes, fingerprints and admission policy are unchanged.
  Normalization copies, encoded-key buffers and map-sort scratch remain separate
  qualification work; this is not a complete hash-construction bound.

- Hashing and predicate encoding borrow already-canonical map entries directly,
  removing their reference-vector allocation and redundant sort. Both consumers
  share the existing key-then-value comparator; unordered maps retain its sort
  after an order check. Duplicate entries, source values and encoded identity
  are unchanged. No canonical flag, request setting or accounting is added;
  scratch/work admission for unordered maps remains separate.
- Bigint hashes stream canonical LEB128 bytes using fixed 64-byte scratch;
  predicate keys write directly into their final buffer. Signed and unsigned
  atoms share one borrowed-limb encoder, and the owned-byte convenience collects
  that same iterator. This removes temporary encoded vectors without additional
  accounting, format changes or fingerprint changes. Other hash construction
  scratch remains under qualification.
- Diagnostic access projection enforces a fixed 128-level root-to-leaf limit
  before allocating or visiting children beyond it. A deeper derived plan returns
  `QueryExplainDepthExceeded` with numeric limit/actual facts, not a truncated DTO.
  The existing visitor owns the check; no extra walk, setting or budget counter is
  added. Ordinary planning and query/cursor identity do not use this diagnostic
  policy. Detached canonical access rendering inherits the admitted tree bound.
- Canonical logical text/JSON hard-cut to plan summaries. Access reports retain
  path structure, operand counts, bound fields and inclusivity, not operand dumps;
  predicate and HAVING trees become presence flags. Grouping keeps strategy,
  fields, aggregate labels and limits. Text now includes the same structured
  access decisions, candidates and alternatives as JSON. Existing clause labels
  may contain literals: these reports are not a redaction boundary.
  One access writer replaces the compact/detailed split, including access objects
  in execution JSON. Other execution-descriptor output is unchanged. Consumers
  parsing canonical reports must adopt the current summary fields; no old-output
  mode remains. Plan metadata and query/cursor identity stay unchanged. Detached output no longer formats arbitrary Value or Expr trees;
  ordinary hash accounting remains preparation work; diagnostic access depth is bounded above.
- Bigint size checks and resource summaries use the existing exact LEB128 length
  calculation instead of serializing values into discarded buffers. This covers
  key-input summaries, runtime value accounting, structural leaf limits and schema
  literal admission. Limits, charge totals, rejection decisions and encoded bytes
  are unchanged; hashing and other consumers needing actual bytes retain encoding.
- Scalar labels route bigint values nested in lists, maps and enum payloads
  through the same upfront-admitted decimal converter as direct literals.
  Compact labels remain byte-identical to Value Debug, including ungrouped nested
  decimal digits; no container copies or intermediate decimal Strings are built.
  Exhaustion stops rendering and returns no partial label. This closes the nested
  literal bypass, not detached rendering or fingerprint scratch qualification.

- Grouped aggregate comparison and HAVING lookup borrow input/filter expressions
  instead of constructing disposable owned semantic keys. Retained SQL keys use
  the same comparison view, preserving their representation and cache identity.
  COUNT literal/null, observable DISTINCT and filter semantics are unchanged.
  Remaining ordinary expression-comparison work belongs to preparation.
  No request limits, cache modes or persisted state are added.
- Continuation order and aggregate hashing borrow source lists and render labels
  only for the current term/aggregate. Hash bytes and resource limits are unchanged.

- Direct bigint scalar labels and index keys share one decimal-chunk conversion.
  Request-backed label writers admit both scratch buffers and a conservative work
  allowance once before reading limbs; arithmetic has no per-step callbacks.
  They stream Candid-style grouped digits without temporary decimal Strings.
  Repeated calls share the request budget. Conservative admission may reject work
  whose actual conversion cost would fit; successful text and key bytes are unchanged.
  Instructions are checked before admitted conversion and on preparation-scope
  exit, not inside arithmetic. No IC instruction/headroom bound is claimed from
  semantic work units alone.
  Nested scalar labels use the admitted compact formatter described above;
  detached canonical summaries do not invoke Value Debug.
- Low-level Rust API hard cut: `IntBig::sign_and_u32_digits` and
  `NatBig::u32_digits` return borrowed exact-size iterators instead of Vecs.
  Callers needing owned limbs must explicitly collect them; admitted callers
  reserve first. Structural Binary streams those iterators without temporary limb
  vectors. Numeric values, persisted bytes and encoder admission policy are unchanged.
- Decimal chunk backing uses a proven radix-expansion bound, replacing the
  insufficient `limbs + 1` estimate for large magnitudes. Label conversion now
  shares the key encoder's repeated-division algorithm; the dependency used a
  divide-and-conquer path for large labels, so convergence is not a speedup claim.
- Session-facing logical explain requires a finalized shared prepared plan;
  SQL logical explain uses that entry and raw model projection is query-local.
  This preserves frozen residual facts without a second planner or extra DTO
  copy. Formatter scratch admission and the public typed terminal remain open.
- SQL-free unit builds can access the predicate diagnostic DTO used by existing
  residual-accounting tests; production feature visibility is unchanged.
- Residual pruning consumes owned predicates and reuses their AND backing and
  operands. Finalization charges its preparation and residual predicate copies
  before construction; pre-finalization guard-to-bound handoff avoids a second
  copy. Newly counted work can reject exhausted requests (potentially breaking).
  Successful predicate semantics and identity are unchanged; proof traversal,
  expression-derived residual work and predicate compilation remain separate.
- Index implication checks traverse borrowed clauses instead of collecting
  temporary vectors or copying single-clause predicate shells. Filtered-guard
  pruning and sparse-index completeness share the same proof rules; unsupported
  shapes and contradictory-query handling retain their conservative policy.
  Remaining traversal/comparison and residual-output accounting stays open.
- Residual access proofs borrow index fields and operands instead of building
  temporary owned comparison vectors. Prefix, range and branch membership
  proofs retain the existing comparison/coercion rules and pruning policy.
  This removes discarded construction, not remaining traversal or residual
  output work; typed `.explain()` remains pending.
- Prepared-plan residual inspection now borrows the frozen predicate instead
  of cloning it. Presence checks, residual ranking and execution explain consume
  the same view; diagnostic DTO copies still use the current request budget.
  Unfinished plans retain their existing residual derivation semantics. This
  removes the finalized inspection copy, not pre-finalization construction work.
- Grouped logical explain now charges strategy-local aggregate inspections,
  ORDER BY and HAVING visits, and group/index-key comparisons to the current
  request. Repeated calls share the allowance; exhaustion stops before later
  work and returns no fallback strategy or partial DTO. Ordinary planning and
  fingerprinting use the same borrowed evaluator without diagnostic limits.
  No retained strategy cache or new budget profile is added. Residual-predicate
  construction remains a separate gap; this is not full diagnostic boundedness.
- Grouped canonical-order proof checks only the field/constant-offset shape it
  admits, without recursively computing discarded expression summaries. Heap
  detection and Top-K field/wrapper admission use the shared short-circuit
  expression visitor, deleting their custom recursive summary. Canonical prefix
  checks omit trailing terms, and grouped cursor validation renders labels only
  when returning the corresponding error. Decisions and diagnostics are unchanged;
  typed `.explain()` remains pending.
- Grouped aggregate-family and streaming checks inspect borrowed identity facts
  instead of copying entire input expressions to construct disposable identities.
  Row-count classification shares its rule with owned identity normalization;
  DISTINCT inspection reuses the existing kind-specific rule. COUNT literal/null
  behavior, MIN/MAX DISTINCT semantics, strategy choices and fingerprints are
  unchanged. This removes construction work, not all grouped-strategy traversal
  or diagnostic accounting gaps; no cached artifact or new request mode is added.
- Logical explain construction now consumes the current request budget for
  filter labels/HAVING model copies, group-key/path storage, aggregate metadata and
  labels, and ordering labels. Repeated SQL logical explains share that request
  allowance; failures return no partial DTO. Complete diagnostic construction
  and recursive formatter qualification remain open.
- Predicate projection charges the retained diagnostic DTO, including nested
  values and coercion parameters. Logical explain and execution descriptors share
  the same fallible DTO projector and current request authority, without an
  identity-only copy. Canonical
  syntax and successful output are unchanged; upstream effective-residual
  construction and complete diagnostic bounds remain separate work.
- Access projection now charges nodes, index-field/operand copies and final
  composite backing before construction across logical, load and aggregate
  explain. The shared visitor borrows field names and projects children on
  demand, removing temporary field lists and discarded child outputs. Labels,
  root scoring and admission summaries omit unneeded descendants; hashing
  retains its canonical child-before-parent byte order. Failed projection
  returns no partial DTO and does not continue through later siblings.
- Logical decision projection now charges candidate, alternative and rejection
  lists before copying their payloads, plus names, label writes, selected-identity
  comparisons and composite constraint counts. The candidate copy pass also finds
  the first selected identity. Shared label formatters write into the destination
  without temporary Strings; successful labels and planner evidence are unchanged.
  Planner candidate enumeration and remaining execution-descriptor construction
  are separate work. No new budget configuration or query route is introduced.
- Verbose execution diagnostics borrow their scalar facts directly, avoiding a
  complete logical explain DTO whose owned operands were immediately discarded.
  Maintained diagnostic labels, ordinary identity and canonical models are unchanged.
- Logical explain's canonical text/JSON renderers now return
  `Result<String, QueryError>` and reject output above 1 MiB before growing the
  destination. Callers must handle errors, normally with `?`. Rejections expose
  a typed output-limit diagnostic with numeric facts and no report contents;
  partial output never escapes. Rendering remains detached from sessions.
- Shared JSON emission propagates formatter errors and writes nested access
  objects directly into one output, removing child-string retention/copying.
  Text access summaries also stream. Execution JSON uses the same emission
  owner without a new output limit; SQL propagates rendering failures.

### 🩹 Fixed

- JSON string emission now escapes all U+0000–U+001F control characters instead
  of emitting invalid JSON for controls lacking a short escape. Existing valid
  output field order and escaping are preserved.

### 🔧 Changed — Preparation

- Grouped aggregate attachment preparation consumes its existing list instead
  of copying aggregate identities, input/filter syntax and list backing. It
  charges each attachment visit to the existing request budget, including
  aggregates without input expressions. Scalar compilation keeps its existing
  payload accounting. Each spec installs its compiled attachments only after
  every operation succeeds; failures return no partially prepared list.
- Newly counted visits can reject an exhausted request (potentially breaking).
  Successful query results, accepted-schema authority and identity are unchanged;
  no public API, numerical ceiling or storage format changes. This closes one
  grouped preparation boundary, not typed `.explain()` or all planner accounting.
- Byte-identical commit before/after images share one raw-row copy and one
  validated reader, borrowing the accepted row contract. Both semantic sides
  remain present to index/relation planning and finalization. The existing row
  size cap is checked before comparison or copying; no admission limit or
  recovery stage changes. Earlier recovery image acquisition remains separate.
- Recovery's final-row lookup borrows keys and row images from its existing
  operation list instead of retaining another owned snapshot. Canonical
  before-row acquisition transfers its buffer into the operation. Witness
  reads remain owned, deletion overrides hide canonical rows, and existing
  size validation and duplicate-key rejection remain in force.
- Commit preparation consumes an explicitly selected accepted catalog, deriving
  entity and store identity from it. The runtime caller retains the existing
  live/canonical selection rules; replay semantics no longer implicitly replace
  the supplied schema inside construction. Recorded operation fingerprints and
  operation-local context lifetimes remain unchanged. No recovery budget is enabled.
