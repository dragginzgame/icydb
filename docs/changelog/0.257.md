# IcyDB 0.257

## 0.257.1 — Query Preparation

### 🩹 Fixed

- The dynamic-query audit canister's generated Candid now includes its grouped
  measurement endpoint, matching the Wasm exports in both build profiles.
- Index-backed reads and exact counts now require proof that every matching row
  is represented in the selected index. This fixes issue #14: nullable trailing
  fields could omit rows while cardinality-based selection preferred the empty
  index. Ordinary planning, candidate diagnostics and metadata counts reuse the
  accepted-schema completeness check already used by grouped/ordered reads.
  EXPLAIN reports `index_membership_unproven` for incomplete candidates.
- Queries that prove non-null membership through equality, ranges, `IN`,
  text-prefix predicates or explicit guards retain index access. When no complete
  access path exists, public reads and exact counts reject instead of returning
  incomplete results (potentially breaking); trusted scans retain their existing
  admission policy. Restart pagination that selected an affected index. Stored
  rows, index encodings and schema formats are unchanged.

### 🔧 Changed

- Grouped validation checks current accepted key identity without constructing
  and discarding replacement keys. Direct type-metadata and path-string copies
  disappear from that check; insertion and validation share borrowed identity
  comparison. Planner rebinding and diagnostic rejection roles are
  unchanged. Retained-key accounting remains open; matched cost measurement is
  deferred while independent planner work is concurrent. See the
  [qualification note](../design/0.257-typed-query-explain/0.257-group-validation.md).
- Grouped key and aggregate clauses now reserve destination backing once and
  move completed vectors into shared intent. Typed/dynamic and SQL preparation
  retain one key resolver and duplicate-key policy; empty scalar grouping skips
  the grouped handoff. Raw Wasm adds 524 bytes; grouped empty-query instructions
  rise 0.206%, while scalar controls decrease 0.008–0.018%. Key-payload copying,
  duplicate-comparison work and planner bounds remain open. See the
  [receipt](../design/0.257-typed-query-explain/0.257-group-clause-perf.md).
- Scalar ORDER BY and selected-field construction now reserve and charge their
  known-length vectors once, including implicit accepted-primary-key ordering.
  Names use the shared copier; completed clauses move into intent, replacing
  the incremental ordering helper flow. Cold/warm and public/trusted rejection
  precedes row execution and preserves the reusable request. Raw Wasm decreases
  213 bytes; ordered empty scans add 0.0070% local instructions. See the
  [receipt](../design/0.257-typed-query-explain/0.257-scalar-clause-perf.md).
- Typed/dynamic ORDER BY and aggregate operand copies now charge traversal and
  allocated backing to the current request before copying. Cold and warm calls
  reject exhaustion before execution, including trusted reads; retries cannot
  reset charges. Copies preserve raw expression shape, DISTINCT and typed values.
  Group-key payloads, duplicate comparisons and planner work remain
  open preparation checks; typed `.explain()` is not yet exposed.
  Matched ordered empty scans add 0.2062% local instructions; raw Wasm adds
  3,818 bytes with three fewer defined functions. Whole-message cycles are
  unmeasured; see the [receipt](../design/0.257-typed-query-explain/0.257-typed-copy-perf.md).
- Shared intent conversion consumes ORDER BY and aggregate wrappers instead of
  cloning their owned expression trees again. Raw aggregate flags, filter/input
  syntax, ordering direction and cache/fingerprint semantics are preserved.
  Borrowed-request copies and planner construction still require accounting;
  this does not yet expose typed `.explain()`.
- Maintainer and CI toolchains now use Rust 1.98.1, including Rustfmt, Clippy
  and local Wasm builds. New compiler lint findings are addressed with
  const-capable helpers, fixed-size byte iteration and direct Result checks;
  no runtime mode or format changes. Public MSRV requirements are unchanged. Existing
  performance receipts retain their original compiler identity; further
  preparation measurements require a matched Rust 1.98.1 baseline.
- Identifier rewriting now charges traversal, matching work and introduced
  field-path backing against the current request budget. Nested paths match
  without temporary qualifier strings or a second segment vector; clause
  vectors and plain field strings retain ownership. The NULL-test preparation
  step reuses its field and box. Alias copying and normalization share dotted
  field construction. Matching semantics are unchanged; initial statement
  cloning and local-canonical classification accounting remain open.
  Measured qualified/alias compilation cycle medians rise 0.016–0.051%; literal
  controls are unchanged. Raw Wasm adds 5,238 bytes and two defined functions.
  See the [receipt](../design/0.257-typed-query-explain/0.257-identifier-budget-perf.md).
- Alias substitution charges scalar visits, projection lookup and copied SQL
  operands against the current request budget. Copies preserve typed values and
  syntax, using the shared value copier; exhaustion stops before later siblings
  and failed preparation is not cached. ORDER BY/HAVING retain their clause
  vectors, and warm commands skip this work. Other normalization traversals and
  statement copies still need accounting.
  Literal-only cost controls are unchanged; alias cycle medians vary by less
  than 0.023%. Raw Wasm adds 6,724 bytes with unchanged function count. See the
  [measurement receipt](../design/0.257-typed-query-explain/0.257-alias-budget-perf.md).
- ORDER BY and HAVING use one projection-alias resolver. HAVING normalizes and
  resolves each clause in one pass, without an intermediate collect. Alias
  matching, non-recursive replacement and aggregate-scope behavior are unchanged;
  alias traversal and copied-subtree accounting remain unfinished.
  Matched alias-query compilation saves 186–532 cycles, hits are unchanged,
  and raw Wasm shrinks 303 bytes with unchanged function count. See the
  [receipt](../design/0.257-typed-query-explain/0.257-alias-owner-perf.md).
- SQL normalization now receives the current request budget through ordinary,
  bound and nested preparation, including exact/prefix and resumable UPDATE
  policy admission. Scope-candidate backing and text copies are charged before
  allocation and the candidate vector reserves once. Warm compiled commands
  still skip normalization. This is the shared accounting boundary and first
  allocation, not complete traversal, alias or syntax-copy accounting.
  Aliased compile cycle medians rise 0.022%; literal-only hits are unchanged.
  Raw Wasm adds 1,462 bytes and two defined functions. See the
  [measurement receipt](../design/0.257-typed-query-explain/0.257-normalization-scope-perf.md).
- Shared SQL qualifier reduction removes a matched prefix in place rather than
  copying the retained suffix. Direct candidate-order matching, qualified-tail
  matching and Unicode boundary handling are unchanged. The owned allocation
  is reused and can retain spare capacity; no additional normalization route
  or compatibility behavior is introduced.
  Matched alias-query cycle medians improve about 0.020% on compilation and
  0.008% on hits; raw Wasm adds 190 bytes with unchanged function count.
  The [receipt](../design/0.257-typed-query-explain/0.257-qualifier-move-perf.md)
  retains the local-counter flag and its measured phase offset.
- SQL field/path normalization moves retained identifier strings instead of
  cloning them into its result. Plain field leaves keep their original string;
  scoped nested paths reuse owned segment backing. Longest-prefix and
  case-insensitive scope matching remain unchanged. Qualifier joining and other
  normalization work still need preparation accounting.
  Focused ownership/parity tests and a matched alias-query probe accompany the
  change: cycles remain effectively flat, raw Wasm adds 202 bytes and function
  count is unchanged. See the [receipt](../design/0.257-typed-query-explain/0.257-identifier-move-perf.md).
- SQL aggregate lowering borrows input and FILTER syntax instead of cloning a
  complete aggregate subtree. Shared lowering charges retained field-name copies
  and input/filter boxes before allocation. Grouped direct-field inputs now
  copy their retained name instead of moving it from the consumed syntax; no
  second owned/borrowed lowering route is introduced.
  Exact-limit and syntax-preservation tests accompany the change. Matched
  aggregate probes add 100 raw Wasm bytes and no functions; cycle medians remain
  close to flat, but two reproducible hit instruction regressions remain under
  review. See the [measurement receipt](../design/0.257-typed-query-explain/0.257-aggregate-copy-perf.md).
- SQL literal/membership copies and normalized-filter materialization share one
  request-metered value copier. It charges nested visits, byte-copy work and
  payload/container backing before allocation without a separate sizing walk.
  Lists, maps and enum payloads preserve their values and identities; owned
  filter results still move without copying. Other normalization and
  expression-copy sites remain separate preparation work.
- SQL expression lowering charges current request work for expression visits,
  field/path and LIKE text copying, and introduced vector/box backing before
  allocation. Known-length argument, membership and CASE vectors reserve once.
  Exhaustion rejects without returning partial trees or caching failed commands;
  warm concrete commands still skip lowering. Nested literal payload copies use
  the shared copier; aggregates borrow syntax and charge retained operand backing.
- SQL field/literal arithmetic lowers through the ordinary binary-expression
  path after the same numeric-family check. It no longer constructs a fluent
  projection wrapper or clones that wrapper's expression. Numeric-scale checks
  borrow their literal, including rejected containers. Successful planner trees,
  numeric families and public fluent APIs are unchanged.
- CASE expansion moves ELSE/results and one condition occurrence instead of
  cloning them. Compact CASE keeps its original arms and ELSE box. The existing
  admission walk supplies a conservative allowance for the remaining condition
  copy; copying and new CASE/truth-wrapper backing are charged before allocation.
  No second recursive estimator or compatibility path is added, and successful
  canonical form is unchanged.
- CASE rewrite admission now charges the existing request's expression-work and
  nested-value counters, including declined expansion and retries. Exhaustion
  returns a typed error instead of selecting a different canonical form
  (potentially breaking for exhausted requests). Fixed rewrite thresholds,
  successful query semantics and warm concrete-command cache savings are
  unchanged. Admission and construction consume the same current request.
- Grouped `HAVING` field resolution borrows current accepted authority without
  constructing a temporary execution key or copying its type. Nested paths no
  longer render and reparse a dotted label; retained grouping keys and HAVING
  share nested eligibility checks. Direct-field admission, dotted spelling and
  later role-specific rejection remain unchanged.
- Grouped-key `HAVING` conversion updates the owned lowering intermediate in
  place. Unchanged values and unconverted list children retain their existing
  storage; no replacement list or fallback copy is constructed. The ordinary
  scalar converter remains the conversion authority, including charges for
  necessary decoded storage. Accepted families, partial list conversion and
  successful results remain unchanged.
- Grouped conversion traversal charges the existing request's nested-value
  work budget, including failed attempts. Exhaustion propagates as an error and
  the private lowering intermediate is discarded; retained SQL syntax and prior
  bindings are not mutated. This does not complete all preparation accounting
  or introduce typed explain.

## 0.257.0 — Bounded Query Preparation

### 🔧 Changed

- Accepted-value normalization and canonical validation also reuse exact
  big-integer lengths, removing four size-only encodings. Field-limit errors,
  encoded-byte budget charges and persisted payloads are unchanged. Matched
  structural writes reduce warm instructions 0.39–3.07% and whole-update cycles
  0.16–1.47%; matched raw Wasm shrinks 141 bytes with unchanged function count.
  The test-admin measurement endpoint adds a separate 2,705 raw bytes and five
  functions. See the [catalog-admission receipt](../design/0.257-typed-query-explain/0.257-catalog-admission-perf.md).
- Big-integer literal size checks no longer allocate an encoding, and filter
  conversion no longer clones a freshly parsed integer for validation. Exact
  typed big integers reuse their storage; necessary container copies charge
  the current request before cloning. Signed/unsigned encoded byte limits,
  accepted input families and persisted encodings are unchanged. Decimal parser
  internals and unrelated catalog copies remain separate accounting work.
  Dedicated warm instruction medians improve, while cycle changes range from
  −0.873% to +0.605%; this is not a blanket cycle speedup. Matched raw Wasm adds
  375 bytes and loses one function, excluding the separately measured audit
  fixture/probe cost. See the [big-integer receipt](../design/0.257-typed-query-explain/0.257-big-integer-perf.md).
- Accepted-schema filter conversion reuses unchanged text/blob values and
  collections containing only unchanged values. Conversions construct a separate
  result only when needed, preserving the original literal if an element fails.
  Introduced list storage, copied elements, hex decode buffers and enum-label
  copies now charge the current request before allocation; scalar parsing charges
  an input-byte work allowance. SQL grouped-HAVING callers propagate exhaustion
  from the same conversion owner. Parser internals and deeper catalog admission
  are not yet fully covered by these preparation charges.
  Matched numeric controls add at most 0.543% whole-update cycles and 1.172%
  instructions; raw Wasm grows 3,433 bytes and three functions. Unchanged-storage
  reuse is tested separately, not presented as a measured text-query speedup.
  See the [conversion receipt](../design/0.257-typed-query-explain/0.257-value-conversion-perf.md).
- Typed/structural `AND` and `OR` use a balanced initial-expression builder.
  Flat input width adds logarithmic junction depth
  without changing operand order, schema-directed conversion, empty-list
  identities, duplicates or NULL operands. No new intermediate collection is
  introduced by the builder.
- Typed nonempty `IN`/`NOT IN` moves its admitted value vector into the existing
  compact membership operation, sharing construction with SQL. It no longer
  builds and subsequently collapses a comparison tree or clones every value
  during lowering. Empty typed lists retain their constant results. The shared
  compiler uses its existing per-value comparison path for collection operands
  and mixed coercions instead of treating those operands as scalar IN values.
- Shared boolean normalization collects each same-operator input group before
  normalizing its terms, then sorts, deduplicates and rebuilds once. It no longer
  repeats those steps for every nested binary subtree. Groups exposed by term
  normalization are flattened without normalizing their contents again.
- Canonical boolean sorting renders already-normalized operands directly,
  removing recursive normalization and expression cloning from comparisons.
  Canonical ordering, identity and CASE expansion policy are unchanged by this
  repair; it introduces no additional pagination migration.
- Request-metered canonical sorting now renders each operand label once and
  retains a typed Debug key only when labels tie. The temporary table and output
  buffers are charged and discarded at the sort boundary; comparisons still consume the
  current request, and failure leaves operands unmoved. This reduces redundant
  construction without adding another cache or normalization route.
- Boolean CASE expansion now has a fixed, content-based rewrite budget that
  accounts for both condition copies, introduced nodes and variable payload
  before copying. Larger expressions keep the existing compact CASE form and
  compiler/evaluator. This limits optimization growth without introducing a
  query-rejection policy; access-path opportunities can change for affected
  queries. Allocation capacity and request state cannot change the decision.
  The duplicate CASE expansion in predicate compilation is removed, so it
  cannot undo the canonicalizer's decision. Predicate projection remains
  whole-expression based: retaining CASE can also prevent an adjacent indexable
  conjunct from supplying a predicate access path. Existing scan-admission
  rules still apply; no partial-extraction planner is added.
- Typed/dynamic requests now share fixed pre-lowering admission: at most 128
  authored expression/value levels, 4,096 input nodes and 2 MiB of variable
  payload across the request. Checks include filters, membership values,
  ordering, aggregates, selected/group fields and cursor text before cloning or
  simplification. Ordinary public and trusted reads use the same policy.
  Structural filter lowering now borrows the admitted input instead of cloning
  its complete frontend tree. Owned dynamic requests detach recursive children
  during cleanup, including errors from consuming typed terminals.
- SQL preparation now uses the same shared input budget, replacing its separate
  depth-only walk. Parsed query/write statements, introspection and CHECK
  expression syntax are checked before preparation; warm query and mutation
  compilation cannot bypass admission. Bound SQL retains its existing scalar
  slot/vector limits and additionally accounts for every effective operand copy
  before substitution. Accepted-schema normalization and cache policy are unchanged.
- SQL expression cleanup is iterative at the syntax owner, including parser
  errors and retained dispatch destruction. Runtime-value disposal is shared
  with typed requests. Postfix parsing transfers its accumulated operand instead
  of cloning it; BETWEEN checks both copies before its required duplication.
  Alias rewriting now shares one scalar-child traversal and keeps existing
  boxes/vectors while transferring owned children.
- Planner expression cleanup now also belongs to the expression owner, covering
  intermediate trees and ordinary destruction rather than only consuming dynamic
  requests. Boolean/CASE, aggregate-input, affine and SQL literal rewrites transfer
  owned children in place, preserving boxes/vectors and eliminating redundant
  CASE-child clones. The dynamic-request-specific planner-expression destructor
  and its unused extraction accessors are removed. This is ownership work toward
  fallible preparation, not completed request-work charging.
- Typed filter lowering now propagates request-budget failures through the
  existing structural preparation path. It charges frontend expression visits,
  nested literal visits, raw literal text/vectors, copied field names and
  introduced expression backing storage before that work. Text and collection
  operators share one construction flow; empty membership produces allocation-free
  planner constants.
  A short-lived context borrows the session's existing request counters;
  retries and derived sessions do not reset them. Public/trusted and exact-count
  preparation retain their current routes and accepted-schema conversion.
- Planner labels now stream through one shared writer instead of building
  subexpression strings and joining them. The writer stops on sink failure and
  preserves escaping, precedence and aggregate identity. Existing String
  consumers remain infallible; canonical sorting uses a request-limited sink.
  This is not the pending public explain-renderer hard cut.
- Canonical normalization now propagates typed request exhaustion through typed
  intent and SQL preparation. Abortable ordering charges key construction and
  comparisons without substituting partial keys or changing successful order.
  SQL command-cache hits still skip compilation; bound invocations prepare their
  current values, and aggregate classification cannot disguise exhaustion as a
  different query shape.
- Filter labels reuse canonical planner trees without cloning/re-normalizing.
  Comparison operands and function arguments retain their allocations, while
  HAVING append drops an unused policy switch and predicate-only filters avoid
  unnecessary expression preparation.
- Canonical normalization still owns sorting, simplification and deterministic
  left-associated boolean-junction identity. These are preparation improvements, not
  an end-to-end stack-safety guarantee. SQL grammar, cursor formats and storage
  remain unchanged. Complete construction/copy and traversal accounting, typed
  `.explain()` and bounded diagnostics remain pending.

### ⚠️ Breaking

- Typed lowering and shared canonical preparation now consume existing request budgets even without
  an active row executor. Exhaustion returns typed request-resource facts;
  cached plans and a trusted route do not exempt lowering work actually performed.
- Oversized typed/dynamic input now fails with a typed depth, node or payload
  diagnostic, including trusted reads. The [read-admission contract](../contracts/READ_ADMISSION.md)
  documents all three diagnostics, their limits and remedies. Its CI guard
  requires public counterparts for plan rejections without requiring earlier
  input failures to appear in the plan-only enum. Simplify nesting or split large inputs;
  a trusted route is not an exemption. Caller construction, standalone DTO
  Clone/Debug/drop and decoding are not newly bounded by execution admission.
- SQL inputs and effective binding copies exceeding the shared limits also
  reject, without a trusted-route exemption. Existing parser lexical limits
  remain in force. No predecessor admission mode or concrete bound-command cache
  is retained; DDL semantic authority stays catalog-owned.
- Nonempty typed membership changes the expression shape used by affected query
  fingerprints and continuation signatures. Restart affected pagination after
  upgrading. The current version-1 cursor format and typed signature-mismatch
  rejection remain in place; there is no predecessor hash, decoder or fallback.
  Public arguments and stored rows do not change.
- CASE expressions retained in compact form also change affected fingerprints
  and continuation signatures. Restart their pagination after upgrading.
  No old canonicalizer, predecessor fingerprint or compatibility cursor path
  is retained; the cursor format stays version 1.
