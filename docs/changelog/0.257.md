# IcyDB 0.257

## 0.257.4 — Planner Construction

### 🩹 Fixed

- CLI allocation-summary formatting writes directly into the output buffer,
  fixing strict lint validation without changing rendered text.
- Deep integrity inspection reports typed budget exhaustion as `ResourceLimited`
  instead of an authority failure (`Uninspectable`). Genuine authority errors
  retain their classification. Failed candidate work does not advance the
  checkpoint, and terminal receipts retain their existing replay/acknowledgement
  behavior. No new limits, public variants or storage formats are introduced;
  callers should handle the existing resource-limited outcome. Shared scalar
  encoder accounting and integrity page construction ownership remain open.
- Interrupted identity commits on heap-backed stores now recover marker-owned
  rows and indexes through the existing prepared commit applier. Direct replay
  retains complete-batch preparation instead of discarding it and calling a
  journal-only row writer. Mixed insert/update/delete markers keep batch-level uniqueness,
  already-applied deletes are idempotent, and identity allocation resumes after
  the committed range. Marker verification remains unchanged; no new storage
  format, recovery phase or construction budget is introduced.

### 🔧 Changed

- Execution preparation reuses a completed "no safe index prefilter" result
  instead of compiling it again during execution. Supported programs remain
  borrowed; a different, unprepared policy uses the same compiler owner on
  demand. Strict covering/aggregate eligibility and row filtering are unchanged.
  One policy/result record replaces two program slots and the duplicate runtime
  dispatch. No public API, encoder limit or storage format changes.
- The existing controller-only `icydb_snapshot` response and CLI now include
  canister-wide physical allocation accounting: all 255 slots, current/ledger/
  unknown bindings, actual bucket sizing, virtual extents, slack and separate
  unknown-binding/unmanaged residuals. Payload occupancy remains unavailable.
  The allocation collector reads bounded manager metadata without creating a
  runtime or reading ledger history. No runtime yields an absent allocation
  report; other collection failures reject through the existing store-error
  boundary. The existing per-store scan is unchanged. Regenerate snapshot
  consumers for the current Candid shape. Production bucket sizing stays at
  128 pages; the fresh 16-page trial and limits are documented in the
  [allocation report qualification](../design/0.257-typed-query-explain/0.257-memory-allocation-report.md).
- Updated `ic-memory` from `0.12.3` to `0.13.2`. The final dependency restores
  upstream optimized reads and removes its redundant private backing adapter;
  IcyDB adds no unsafe forwarding or local dependency override. Stable stores and database
  control regions now consume `ic_memory::RuntimeMemory<DefaultMemoryImpl>`;
  handwritten callers of low-level store constructors must use runtime-opened
  handles. Generated memory macros already return that type. Isolated core
  fixtures now bootstrap explicit runtimes before opening their test slots.
  The allocation-ledger and IcyDB storage formats remain unchanged, as does the
  default 128-page bucket size; this update itself requires no recreation.
  The dependency pins its manager-layout adapter to `ic-stable-structures 0.7.2`,
  already the workspace's resolved version. All collection, backing-memory and
  trait imports now use `ic_memory::ic_stable_structures`; the workspace and
  core package no longer declare a direct substrate dependency. This keeps
  their type identity tied to the memory runtime's exact dependency.
- Recovery verification reuses accepted-schema setup across rows of the same
  entity and schema, through the same operation-local helper used by writes and
  replay. Every row and index effect is still checked. Setup is discarded after
  each verification call, including failure; no public API, storage format or
  recovery-budget limit changes. Verification retains those contexts until the
  call ends, so fewer constructions do not by themselves prove lower peak memory.
- Writes derive after-image index keys even when the indexed fields are
  unchanged, so that validation cannot be skipped for keys recovery must later
  reconstruct. The existing no-index-read/no-delta shortcut remains, and changed
  inputs reuse the admitted key. This adds after-image derivation work to
  unrelated-field updates and can reject invalid unchanged keys earlier. No new
  resource limits or formats are introduced; complete replay-budget admission
  remains unfinished.
- Nonempty startup now separates marker replay, each complete journal fold and
  final verification across driver calls. A volatile marker-bound continuation
  advances only after success; losing it restarts idempotent replay and retains
  durable fold progress. Reads and writes stay gated until verification finishes.
  Debt-free startup and ordinary online convergence keep their existing paths.
  Test drivers must continue until completion. No persisted format or budget limit
  changes; shared encoder accounting and replay admission remain unfinished.
- Journal folding and online retirement now consume the same prepared row
  transitions, removing unused reconstruction paths and an extra retirement-time
  row decode. Existing journal admission already keeps schema publication
  separate from ordinary row mutations; the unused candidate-row resolver is
  removed. Complete row preparation remains before canonical publication, and
  final recovery verification is unchanged. No write/replay budget or format
  change is included; shared scalar encoder accounting remains open.
- Unique-index validation and migration validation/rewrite pages now own an
  explicit construction budget; complete schema-index staging retains one across
  all observed rows and finalization. These reuse the existing mutation limits,
  without requiring an active query or changing soft page-yield limits. Hard
  exhaustion is sticky and rejects before output/progress handoff, including when
  an inner caller discards the original failure. No persisted status or public
  configuration changes. This establishes maintenance authority and charges row/
  key visits and instruction watermarks; scalar codec allocation/work accounting
  and predicate error propagation are the next landing, not completed here.
- Query planning builds its projection once under the existing request budget,
  validates it, and moves it into the final execution contract. Prepared scalar
  and SQL readers borrow that retained projection instead of cloning it or
  reconstructing an unprepared plan. Projection order, aliases, grouped paths,
  aggregate DISTINCT semantics and successful fingerprints are unchanged.
  Schema-wide projection reserves conservative scratch/sort work before the
  existing canonical slot sorter; expression and payload copies use their
  existing budgeted owners. Newly counted work can reject exhausted requests.
  This closes projection construction, not all validation or typed explain.
- Logical-plan handoff borrows query clauses for shape checks and charges retained
  FILTER, ORDER BY, GROUP BY, aggregate, HAVING and projection copies against the
  existing request before allocating. Exact-key plans skip copying discarded
  filters; reranking moves the existing logical/projection inputs. Current budget
  exhaustion rejects before cache publication, while warm hits skip these copies.
  Clause order, aliases, grouping authority and successful identities are unchanged.
  This closes clause-copy accounting, not predicate normalization,
  the full planner budget or the typed explain terminal.
- ORDER BY canonicalization charges primary-key visits, exact-name comparisons,
  destination growth and appended names before work. Initial access selection
  also budgets its temporary order copy; logical assembly and template rebinding
  use the same canonicalization owner. Missing/grouped order early exits, scalar
  tie-break direction and successful query identity are unchanged. Warm bound
  memo hits skip this construction. Newly counted work can exhaust existing
  budgets; no new limit or query policy is introduced.
- ORDER BY duplicate and primary-key consistency checks charge visits,
  comparisons, scratch backing and computed-label writes against the same
  request. Direct labels are borrowed and primary-key-only orders allocate no
  duplicate-check scratch. Computed labels reuse the existing abortable text
  sink used by boolean normalization; errors never become partial strings or
  fallback comparison results. Duplicate positions, label equality and missing
  composite-key diagnostics are unchanged. Full semantic/type-checking and
  diagnostic rendering bounds remain separate unfinished work.
- Scalar expression compilation charges visits, accepted-name lookups/copies,
  literal payloads, path encoding and final container backing before construction.
  Projection, residual expressions, ORDER BY and aggregate inputs/FILTERs use
  the caller's existing budget. Newly counted work can exhaust current limits
  (potentially breaking); successful program semantics are unchanged.
- One required internal construction interface connects request preparation and
  active execution to the same compiler and value-copy owner. It creates no
  request root, instruction interval, counter or public option. Execution-time
  compilation fails if its active budget is missing; standalone builder previews
  retain a private unmetered adapter because they have no database request.
- Unsupported scalar syntax remains distinct from typed budget exhaustion.
  Resumable mutation scope compilation uses the existing execution-budget restart
  reason on exhaustion, not an ineligible-intent result. No persisted format or
  policy discriminator changes.
- Candidate ranking, exact-cardinality tie enumeration and explain metadata borrow
  scalar semantics and candidate access instead of cloning whole logical queries
  and projections. Shared residual derivation computes the candidate remainder
  once; finalized chosen plans still use their frozen contract. Selection policy,
  current-authority checks and cache identity are unchanged.
- Exact-cardinality selection builds evidence and chooses the first minimum in
  one pass, removing the intermediate ranked-candidate vector. Candidate visits,
  prefix-count addition, comparisons, evidence backing and copied names charge
  the existing request budget before work. Exhaustion rejects rather than becoming
  an optional-policy fallback; successful evidence order and cursor pins are unchanged.
- This accounts scalar-program construction, not all preparation. Other on-path
  planner/schema work and bounded diagnostics remain open before typed `.explain()`.
  Grouped-result execution compilation is outside this landing, not an automatic
  explain prerequisite. No additional cleanup is included.
- Cardinality probe-count policy now runs before access lowering and output-buffer
  allocation. Oversized optional tie-breaks keep their policy fallback without
  encoding their prefixes. Prepared/key buffers reserve once under the request
  budget; byte-size observations and duplicate comparisons are also charged.
  Encoded-byte limits remain post-encoding checks, not an encoder allocation bound.
- Access lowering builds only the index specs its consumers retain, deleting the
  temporary executable tree and its composite-child buffers. The remaining
  depth-first walk charges one expression step per access node before descent
  or leaf encoding. Cold planning, template rebinding and pinned continuations
  pass their existing request budget; warm hits still skip lowering. Exhaustion
  rejects, while prefix/range encoding failures keep their existing classification.
  Scalar encoding and raw-bound construction accounting remain open.
- Index-spec output backing is reserved against the existing request budget before
  leaf encoding. Prefixes, multi-lookups, branch sets and ranges share their current
  shape-count authority; composite growth charges the replacement allocation,
  including retained entries. Preparation and lowering share one reservation owner.
  Exact-prefix specs and count keys now retain encoder-owned component buffers
  instead of copying them. Cache accounting includes their actual spare capacity;
  avoiding a tight copy can therefore increase retained weight without adding a
  second payload buffer. Canonical bytes, deferred-bound policy and identity stay unchanged.
- Access lowering requires accepted schema information throughout its private
  helpers. An unreachable schema-free range/prefix route and its unused request
  representation are removed. Maintained range lowering consumes the already
  encoded accepted prefix directly; planner text-prefix construction remains
  unchanged. This deletion adds no limit, request charge or public API change.
- Encoded prefix lists reserve their backing and charge each component visit
  before encoding. Prefix, range, branch, multi-lookup and exact-count keys share
  that owner; branch scans borrow their operands instead of cloning a temporary
  value list. Multi-lookups share the prefix-spec assembly owner while retaining
  their existing deferred-bound threshold. Metadata-only count construction
  borrows the current public/trusted/diagnostic request budget and preserves
  typed exhaustion. This does not yet meter scalar-codec bytes or raw bounds.
- Big-integer index encoding emits decimal chunks directly into the final key,
  removing the intermediate ASCII digit buffer and its copy. Signed/unsigned
  encoding share chunk conversion and emission; the existing digit-length limit
  is checked before reserving the final payload. Canonical bytes, zero/sign
  handling and accepted query types are unchanged. This adds no request charge
  and is not scalar-encoder boundedness qualification.

## 0.257.3 — Planner Construction Accounting

### 🔧 Changed

- Structural scalar aggregate input/FILTER preparation uses the shared scalar
  compiler for field admission, removing a duplicate tree scan and discarded
  unknown-field label. Successful programs and payload-free rejection stay unchanged.
- Planner candidate scoring, order-only index selection and boolean route-order
  checks compare accepted key items without rendering temporary index-label lists.
  Scalar matching checks the primary-key tail once; grouped trailing-key rules
  and owned diagnostic labels retain their existing semantics.
- Secondary-order contracts share accepted primary-key names during candidate
  scoring, finalization and plan cloning instead of copying the key vector and
  labels. Retained-cache accounting includes the shared header, backing and string
  capacity per resident; ordering and current-authority selection are unchanged.
- Covering reads, ordered DISTINCT seeking and execution-explain ordering reuse
  the finalized secondary-order contract. They no longer rebuild its labels and
  primary-key names; route eligibility and accepted-schema authority are unchanged.
- Primary-key ordering, covering-read and cursor checks borrow the accepted
  name slice directly instead of building temporary reference vectors. Planner
  selection and tie-break insertion/validation use the same representation; tuple order,
  route eligibility and current-authority behavior are unchanged.
- SQL aggregate-input and FILTER validation reuse the existing expression
  analysis instead of compiling and discarding a scalar program. This removes
  temporary trees and literal/name copies while preserving current-schema field
  checks, unsupported-expression errors and unknown-field precedence.
- Accepted schemas and finalized plans share immutable primary-key names instead
  of copying their list and labels during finalization or cloning. The owning
  schema/plan handles use `Rc` throughout the thread-local session/executor
  handoff, including grouped execution. Key order and current-authority rebinding
  are unchanged; cache accounting includes shared headers and string capacity.
- ORDER BY referenced-slot construction now charges expression visits, duplicate
  comparisons and backing growth before publishing planner metadata. One shared
  compiled-expression traversal serves fallible preparation and runtime slot
  marking; first-reference order and duplicate elimination stay unchanged.
  Newly counted work can exhaust existing request limits.
- Projection identity checks compare accepted slots without collecting or sorting
  schema field names. Field shape, label visits and slot comparisons charge the
  existing request budget; exhaustion remains a typed error, not a non-identity
  result. Physical order, including sparse slots, and successful plans stay unchanged.
- Direct projection layouts share one budgeted field-resolution pass over the
  already-lowered projection. This removes repeated schema ordering and temporary
  field-name lists while preserving unique consuming-reader slots and repeated
  raw-row slots. Newly counted construction can reject before cache publication;
  grouped/computed layout availability and successful output remain unchanged.
- Projection referenced-slot construction now charges expression visits, sorted
  insertion comparisons/shifts and vector growth to the existing request budget.
  Direct fields and path roots share one resolver; sorted unique output is
  preserved without a separate final sort. Newly counted work can reject before
  static-contract/cache publication; schema lookup internals remain unmetered.
- Scalar expressions compile directly into the final program, removing the
  temporary scalar tree and its second traversal. Projection, ordering,
  aggregates, previews and resumable SQL updates share the recursive compiler;
  accepted-schema and preview leaf policies retain their existing errors.
  Every CASE child is admitted before branch specialization. Final programs and
  evaluation semantics are unchanged; construction accounting remains open.
- Compiled binary-expression specialization moves already-owned field labels
  and literal values into the final program instead of cloning and discarding
  them. Existing arithmetic/comparison forms, operand order and evaluation
  semantics are unchanged; no new accounting resource or execution route.
- ORDER BY preparation no longer renders discarded diagnostic labels or resolves
  expression fields twice. Its order-term backing and scalar-seam traversal now
  charge the existing request budget before work; newly counted work can reject.
  Successful order programs and typed invalid-order errors are unchanged.
  Expression compilation remains a separate accounting gap, not covered by
  order traversal and referenced-slot admission.
- Static index execution slots and predicate compile targets share one accepted
  key traversal instead of resolving the same fields twice. Both output vectors
  reserve exact key arity under the existing request budget; newly counted
  construction can reject before static-contract/cache publication. Output
  layouts and expression-index semantics are unchanged.
- Retained grouping-key preparation now charges path copies, key-container
  backing and duplicate comparisons to the existing request budget. Frontend
  construction and planner rebinding share the same owner; cold, rebound and
  cardinality-reselected plans preserve typed exhaustion before cache publication.
  Existing ceilings are unchanged, but newly counted work can reject (potentially
  breaking). This does not yet bound all planner or schema-lookup work.
- Prepared execution consumes already-finalized planner metadata. The executor
  no longer recomputes route profiles or constructs missing static contracts;

  compact membership operation, sharing construction with SQL. It no longer
  builds and subsequently collapses a comparison tree or clones every value
  during lowering. Empty typed lists retain their constant results. The shared
  compiler uses its existing per-value comparison path for collection operands
  and mixed coercions instead of treating those operands as scalar IN values.
- Shared boolean normalization collects each same-operator input group before
  normalizing its terms, then sorts, deduplicates and rebuilds once. It no longer
  repeats those steps for every nested binary subtree. Groups exposed by term
  normalization are flattened without normalizing their contents again.
- Canonical boolean sorting renders already-normalized operands directly,
  removing recursive normalization and expression cloning from comparisons.
  Canonical ordering, identity and CASE expansion policy are unchanged by this
  repair; it introduces no additional pagination migration.
- Request-metered canonical sorting now renders each operand label once and
  retains a typed Debug key only when labels tie. The temporary table and output
  buffers are charged and discarded at the sort boundary; comparisons still consume the
  current request, and failure leaves operands unmoved. This reduces redundant
  construction without adding another cache or normalization route.
- Boolean CASE expansion now has a fixed, content-based rewrite budget that
  accounts for both condition copies, introduced nodes and variable payload
  before copying. Larger expressions keep the existing compact CASE form and
  compiler/evaluator. This limits optimization growth without introducing a
  query-rejection policy; access-path opportunities can change for affected
  queries. Allocation capacity and request state cannot change the decision.
  The duplicate CASE expansion in predicate compilation is removed, so it
  cannot undo the canonicalizer's decision. Predicate projection remains
  whole-expression based: retaining CASE can also prevent an adjacent indexable
  conjunct from supplying a predicate access path. Existing scan-admission
  rules still apply; no partial-extraction planner is added.
- Typed/dynamic requests now share fixed pre-lowering admission: at most 128
  authored expression/value levels, 4,096 input nodes and 2 MiB of variable
  payload across the request. Checks include filters, membership values,
  ordering, aggregates, selected/group fields and cursor text before cloning or
  simplification. Ordinary public and trusted reads use the same policy.
  Structural filter lowering now borrows the admitted input instead of cloning
  its complete frontend tree. Owned dynamic requests detach recursive children
  during cleanup, including errors from consuming typed terminals.
- SQL preparation now uses the same shared input budget, replacing its separate
  depth-only walk. Parsed query/write statements, introspection and CHECK
  expression syntax are checked before preparation; warm query and mutation
  compilation cannot bypass admission. Bound SQL retains its existing scalar
  slot/vector limits and additionally accounts for every effective operand copy
  before substitution. Accepted-schema normalization and cache policy are unchanged.
- SQL expression cleanup is iterative at the syntax owner, including parser
  errors and retained dispatch destruction. Runtime-value disposal is shared
  with typed requests. Postfix parsing transfers its accumulated operand instead
  of cloning it; BETWEEN checks both copies before its required duplication.
  Alias rewriting now shares one scalar-child traversal and keeps existing
  boxes/vectors while transferring owned children.
- Planner expression cleanup now also belongs to the expression owner, covering
  intermediate trees and ordinary destruction rather than only consuming dynamic
  requests. Boolean/CASE, aggregate-input, affine and SQL literal rewrites transfer
  owned children in place, preserving boxes/vectors and eliminating redundant
  CASE-child clones. The dynamic-request-specific planner-expression destructor
  and its unused extraction accessors are removed. This is ownership work toward
  fallible preparation, not completed request-work charging.
- Typed filter lowering now propagates request-budget failures through the
  existing structural preparation path. It charges frontend expression visits,
  nested literal visits, raw literal text/vectors, copied field names and
  introduced expression backing storage before that work. Text and collection
  operators share one construction flow; empty membership produces allocation-free
  planner constants.
  A short-lived context borrows the session's existing request counters;
  retries and derived sessions do not reset them. Public/trusted and exact-count
  preparation retain their current routes and accepted-schema conversion.
- Planner labels now stream through one shared writer instead of building
  subexpression strings and joining them. The writer stops on sink failure and
  preserves escaping, precedence and aggregate identity. Existing String
  consumers remain infallible; canonical sorting uses a request-limited sink.
  This is not the pending public explain-renderer hard cut.
- Canonical normalization now propagates typed request exhaustion through typed
  intent and SQL preparation. Abortable ordering charges key construction and
  comparisons without substituting partial keys or changing successful order.
  SQL command-cache hits still skip compilation; bound invocations prepare their
  current values, and aggregate classification cannot disguise exhaustion as a
  different query shape.
- Filter labels reuse canonical planner trees without cloning/re-normalizing.
  Comparison operands and function arguments retain their allocations, while
  HAVING append drops an unused policy switch and predicate-only filters avoid
  unnecessary expression preparation.
- Canonical normalization still owns sorting, simplification and deterministic
  left-associated boolean-junction identity. These are preparation improvements, not
  an end-to-end stack-safety guarantee. SQL grammar, cursor formats and storage
  remain unchanged. Complete construction/copy and traversal accounting, typed
  `.explain()` and bounded diagnostics remain pending.

### ⚠️ Breaking

- Typed lowering and shared canonical preparation now consume existing request budgets even without
  an active row executor. Exhaustion returns typed request-resource facts;
  cached plans and a trusted route do not exempt lowering work actually performed.
- Oversized typed/dynamic input now fails with a typed depth, node or payload
  diagnostic, including trusted reads. The [read-admission contract](../contracts/READ_ADMISSION.md)
  documents all three diagnostics, their limits and remedies. Its CI guard
  requires public counterparts for plan rejections without requiring earlier
  input failures to appear in the plan-only enum. Simplify nesting or split large inputs;
  a trusted route is not an exemption. Caller construction, standalone DTO
  Clone/Debug/drop and decoding are not newly bounded by execution admission.
- SQL inputs and effective binding copies exceeding the shared limits also
  reject, without a trusted-route exemption. Existing parser lexical limits
  remain in force. No predecessor admission mode or concrete bound-command cache
  is retained; DDL semantic authority stays catalog-owned.
- Nonempty typed membership changes the expression shape used by affected query
  fingerprints and continuation signatures. Restart affected pagination after
  upgrading. The current version-1 cursor format and typed signature-mismatch
  rejection remain in place; there is no predecessor hash, decoder or fallback.
  Public arguments and stored rows do not change.
- CASE expressions retained in compact form also change affected fingerprints
  and continuation signatures. Restart their pagination after upgrading.
  No old canonicalizer, predecessor fingerprint or compatibility cursor path
  is retained; the cursor format stays version 1.
