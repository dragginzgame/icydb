# IcyDB 0.290

## [0.290.0]

### ⚠️ Breaking

- Adopt published IC Memory/Storage 0.55.1 together. IcyDB publicly exposes
  Memory allocation, declaration and authority types, so consumers exchanging
  those types must select the same dependency identity. Memory and Storage library sources
  match 0.55.0 and 0.54.1; allocation custody, ledger and B-tree formats are
  unchanged. IcyDB does not select Metrics Stable or Logging Stable, so their
  checkpoint format retirement does not apply and no memory reset is required.

### 📦 Dependencies

- Raise the Metrics minimum to published 0.17.2, already selected in the lockfile.
  It retains 0.17.0 measurement, transport and recording contracts; Logging is a
  separate package and is not added to IcyDB. Preserve optional metrics and the
  existing report/reset semantics.
- Adopt published IC Build/Host/Testkit 0.69.14, keeping the selected feature
  boundaries and unrelated dependency selections. The release preserves public
  APIs, cache/report formats and lifecycle responsibilities.
- Raise the Platform requirement to published 0.7.6, already locked and qualified
  through the current facade. Wire 0.7.21 and Metrics 0.17.2 are already current;
  preserve their feature selections. Timers 0.32 remains incompatible with the
  retained Canic revision's 0.31 requirement and single-owner links contract.
  [Canic #590](https://github.com/dragginzgame/canic/issues/590) now owns that
  prerequisite; #709 was consolidated there, not completed. No supplier override
  or extra timer runtime is introduced.
- Refresh Shared Tooling to committed 0.27.7 (`11d519c604b1727a2bf6272557a97e770a63b29f`)
  through its canonical exporter, preserving the 130 selected payloads. Adopt the
  clarified IC Observability ownership rules without enabling scheduled work.

### 🩹 Fixed

- A definite accepted-constraint refusal during a durable mutation job now
  persists `RestartRequired(TargetRowRejected)` instead of leaving the same
  failing checkpoint active indefinitely. The failed page commits no row
  changes; earlier pages and their totals remain applied. Exact request replay
  returns the retained terminal receipt, which can be acknowledged to free the
  job slot. Correct the row or intent before starting a new job identity.
  The mutation-job executor owns this transition; query-side, corruption and
  other target failures retain their existing behavior. This adds one public
  restart reason, with progress-codec tag 8, while preserving tags 0–7 and the
  existing lifecycle. Consumers exhaustively matching restart reasons must add
  the new case. No abandon API, phase or compatibility reader is added.
  [#104 — Constraint rejection pins an active mutation job](https://github.com/dragginzgame/icydb/issues/104).

### 🧹 Cleanup

- Publish direct and replayed accepted schema candidates through one effective
  identity transition, bundle persistence/verification and inactive-root-slot
  sequence. Reuse the existing write target for payload and identity effects;
  durable and materialized retention remain distinct. Preserve both root-slot
  preparations and replay's final bundle revalidation. Journal replay still
  rejects heap backends before identity preparation, and a current root cannot
  silently recreate missing identity state. Canonical fold keeps its prepared
  publication path and unchanged write semantics. Add refusal regressions beside
  existing idempotence, cold-reopen, replay/fold and identity tests.
  [#554 — Schema publications repeat the same root write](https://github.com/dragginzgame/icydb/issues/554).
- Traverse forward-index and reverse-relation integrity pages through one
  checkpoint admission and bounded-entry walk. Keep accepted domain/store
  resolution and entry-specific witness checks at their existing owners. Limit
  admission order, within-key corruption checks, stop-before-consumption and
  exhausted-page results remain unchanged. Add regressions for missing within-key
  checkpoints with a successor and at the end of both domains; exclusive After
  checkpoints still resume past a removed key.
  [#552 — Integrity pages repeat the same visit](https://github.com/dragginzgame/icydb/issues/552).
- Finish accepted updates and replacements through one last-write-wins intent
  collection, slot admission, logical comparison, managed-timestamp check and
  canonical row emission. Keep authored/canonical/default update handling and
  replacement insertion-policy handling distinct. Sparse updates still exclude
  preserved values and historical fills from comparison; replacement compares
  every non-UpdatedAt slot. No-op writes preserve managed time and still reject
  inverted stored timestamps. Insert handling is unchanged. Extend mutation
  coverage to exercise both operations against unchanged, changed and regressing
  clocks, overwritten assignments and invalid stored timestamp order.
  [#579 — Existing row patches repeat the same finish](https://github.com/dragginzgame/icydb/issues/579).
- Assemble merged and branch-ordered index-prefix streams through one active
  prefix admission and child construction flow. Preserve construction charging
  before sorting or leaf reads, branch-count-based refill budgets, and the single
  active-prefix path. Branch-ordered streams still sort by raw lower key, reverse
  for descending scans and concatenate; merged streams retain primary-key order
  and duplicate suppression. Resume policy remains with each route.
  [#571 — Index prefix streams repeat the same assembly](https://github.com/dragginzgame/icydb/issues/571).
- Project borrowed, owned and single-component covering rows through one field
  walk. Preserve projection-step charging before shape/source admission, typed
  refusals, primary-key and constant output, and independent duplicate columns.
  Borrowed components clone per output; owned components clone until their final
  use moves the value. The single-component path shares that last-use move with
  stack-only bookkeeping.
  [#569 — Covering rows repeat the same field walk](https://github.com/dragginzgame/icydb/issues/569).
- Route dedicated grouped COUNT row-view ingests through the shared filtered
  source reader, including ordered early stopping. Keep one narrow single-field
  scan for both ordered and unordered COUNT. Missing/filter-rejected rows and
  an unconsumed stopping boundary do not count; completed-row accounting follows
  successful ingest on every path. Borrowed, owned and path-aware key ingestion
  retain their existing owners, and the general ordered grouped fold is unchanged.
  Extend refill/continuation coverage to compare dedicated COUNT with the general
  grouped bundle against the same expected pages.
  [#560 — Grouped count scans repeat the same key walk](https://github.com/dragginzgame/icydb/issues/560).
- Reuse one grouped-runtime source reader for global DISTINCT field aggregates
  and generic grouped bundles. Missing rows and rejected filters are handled
  before terminal ingestion; NULL/duplicate skipping, distinct-value limits and
  reducer updates stay with DISTINCT execution. Pass the existing grouped stream
  directly instead of unpacking and threading its read/filter inputs separately.
  Preserve generic filtered-row counts and leave ordered grouped execution intact.
  [#561 — Distinct field aggregates repeat the same filtered read](https://github.com/dragginzgame/icydb/issues/561).
- Resolve generated field, index, relation and constraint removals through one
  entity/source-binding/member admission sequence. Preserve unsupported missing
  bindings and ownership refusals, invariant failures for missing bound members,
  and pending-publication guards. Fields and indexes still require generated
  ownership; constraints still require a generated check or targeted rule;
  relations retain their identity-only membership check. Later per-entity removal
  grouping remains independent.
  [#578 — Generated removals repeat the same identity](https://github.com/dragginzgame/icydb/issues/578).

### 🧪 Testing

- Protect typed diagnostic priority across entity member lists: duplicate keys
  are rejected across all lists before individual field-policy validation. Keep
  the existing shared sorting and uniqueness helpers and explicit admission
  phases; a per-list sort/check/validate pipeline would change this ordering or
  require additional phase machinery. Retire that extraction proposal rather
  than add another validation framework.
  [#564 — Fragment members repeat the same canonicalization](https://github.com/dragginzgame/icydb/issues/564).
