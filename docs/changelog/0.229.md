# 0.229 Continuous Journal Convergence And Bounded Backlog Admission

## 0.229.1 - 2026-08-17

### 📝 Summary

- Bounded continuous convergence is now active: retained complete journal
  batches fold through the existing startup watchdog while the database is
  `Ready`, and exact cumulative pressure rejects new debt with retryable E284
  until enough work drains.
- The current pre-1.0 persisted and cursor representations now use only version
  1. Predecessor forms are unsupported and require reinstall or recreation.

### 🔧 Changed

- The canonical commit owner enforces cumulative admission after individual
  batch admission and before marker, journal, or target publication. Checked
  arithmetic binds the exact retained and proposed envelopes to at most 38
  batches, 16,384 records, and 16,777,216 encoded bytes.
- A rejected commit preserves its sequence, marker, journal, and target state,
  reports exact E284 pressure facts, and wakes the existing watchdog so the
  caller can retry after sufficient drain.
- Host CLI diagnostics render E284's backlog resource, current contribution,
  proposed contribution, and limit explicitly, including human-readable batch,
  record, and encoded-byte resource labels.
- Every debt-retaining commit publishes exact positions for row, derived-index,
  schema, validation-job, identity, and migration effects. Reads continue to
  observe the newest live value while older batches reconstruct from canonical
  predecessor state.
- Each non-quiescent watchdog callback selects exactly one globally oldest
  complete batch, then synchronously validates, preflights, applies, retires
  its exact live positions, and advances its journal tail. Impossible
  post-preflight contradictions trap so IC whole-message rollback remains
  authoritative.
- Startup empty-tail closure now validates the current exact tail control for
  every registered journal owner before reporting recovery complete. Missing,
  malformed, or physically contradictory control authority fails typed under
  that journal owner instead of becoming a delayed callback failure.
- Complete-batch recovery now shares one batch-resolved canonical context and
  one prepared row transition across validation, retirement, and apply. This
  removes repeated catalog and row preparation from the critical message
  without raising its instruction ceiling.
- Quick integrity and SQL compilation avoid duplicate current-control,
  accepted-catalog, and startup-readiness work while retaining the same
  control and failure-receipt validation boundaries.
- Complete accepted-index staging reuses identical before/after row-decode
  authority and its proven current-domain inventory. Mechanical publication no
  longer repeats stable point reads for keys already proved absent.
- Mechanical live publication now consumes the exact positioned and
  mutation-progress preflight evidence without repeating stable lookups.
  Production Apply no longer builds best-effort rollback snapshots after the
  complete preflight boundary; any impossible contradiction traps so IC
  whole-message rollback remains the sole atomicity authority.
- Durable mutation Verify pages now examine at most 208 authoritative keys
  while retaining the 56-row staging limit. The sole current version-1 batch
  policy identity binds the narrower limit in place.
- The current journal, database-control, cursor, integrity-progress, migration,
  schema-proposal, and SQL-generator discriminators were replaced in place by
  their sole current version-1 forms. Predecessor constants, decoders,
  activation paths, and old-form fixtures were removed rather than retained as
  compatibility machinery.
- Maintainer setup and CI jobs that validate workflows or inspect performance
  authority now install and verify the GitHub CLI through one shared helper.

### 🧪 Testing

- Cumulative-pressure coverage proves exact E284 facts at the 38-batch limit,
  unchanged publication state on rejection, successful drain and retry, and
  exact final rows, indexes, and identity high water.
- Current-state coverage exercises same-key predecessor folding, every
  maintained record family, late corruption before mutation, positioned
  supersession and retirement, upgrade recovery, and clean recreation.
- Journaled unique-index coverage folds same-batch swaps and delete/reuse
  transitions against exact batch-final row evidence.
- CLI coverage exhaustively renders the E284 boundary and its complete typed
  pressure-fact tuple.
- Startup fixtures reopen the same stable allocations, submit collection-sized
  setup as Gate-2-valid batches, and expect the online watchdog wake-up owned
  by every successful debt-retaining commit.
- Generated native libtests use a host-safe recovery wake-up while production
  and Wasm builds retain the replicated startup watchdog, so journaled write
  fixtures do not invoke IC timer syscalls outside a canister.
- Real-canister coverage proves stable-memory length and digest rollback after
  a deliberate convergence trap, followed by one clean watchdog retry with
  exact final rows and indexes.
- The collection-scale fixture delivers the existing watchdog between setup
  commits and job calls, so continuous convergence drains retained setup debt
  without depending on a later user mutation while upgrade recovery still
  begins with deliberately retained current debt.
- SQL performance fixture resets now drive the existing watchdog to observed
  quiescence before sampling, and multi-ingress write measurements deliver it
  between independent calls. Startup delivery covers the frozen
  `B_0 + C_driver = 38 + 4` residual bound instead of the stale 32-message
  assumption.

### 📊 Audit

- A 2,048-row commit with three derived indexes converges in one callback at
  2,615,527,509 instructions and 5,439,488 observed Wasm-memory bytes. This is
  more than 27 billion instructions below the frozen 30-billion callback
  ceiling and remains below the IC's 40-billion message limit.
- The 65,536-key accepted-index fixture publishes in 29,946,837,958
  instructions. Its accepted-index fold peaks at 21,011,006,924 instructions;
  four retained setup batches plus that batch converge in five exact
  one-batch callbacks totaling 31,113,972,716 instructions.
- Cold and populated 38-batch histories each converge in exactly 38 callbacks,
  totaling 1,114,818,866 and 1,127,326,339 instructions. Post-upgrade recovery
  drains the same debt in 1,923,573,708 instructions and returns startup to
  `Ready` with ordinary queries gated until completion.
- The maintained 10,001-row collection-scale fixture completes in 179 Forward
  and 49 Verify calls. Its maximum tier steps are 27,862,838 Forward and
  7,597,129 Verify instructions against the unchanged 31,000,000 and 8,000,000
  ceilings; mid-debt upgrade recovery preserves all rows and stable-memory
  length exactly.
- The production SQL audit artifact is 4,888,976 compiler-emitted Wasm bytes,
  4,269,683 final deployable raw Wasm bytes, and 1,647,662 deterministic-gzip
  bytes. Relative to tagged 0.229.0, these are increases of 71,852, 63,859,
  and 23,505 bytes respectively. Its Candid declaration remains exactly 60,428
  bytes with SHA-256
  `5bc8b2c65e8e57ec1bee7db4677d7fff3bcab686159128fc2604fe40c00882d1`,
  and the final artifact retains 70 exports.
- No public method, stable-memory identifier, cursor, compatibility decoder,
  runtime mode, timer, scheduler, or caller configuration was added. The
  release activates one admission authority and one convergence route.

### ⚠️ Breaking

- The persisted version-1 shapes replace predecessor forms in place. This
  includes the version-3 journal envelope shipped by 0.229.0; noncurrent bytes
  fail typed and closed with no decoder, upgrader, repair shim, or fallback.
- Writes may now return retryable E284 while cumulative retained debt is at its
  bounded limit. Exhaustive consumers of the public error taxonomy must handle
  that variant.

### 🧭 Migration Notes

- Reinstall or recreate any canister carrying state from 0.229.0 or an earlier
  release before using 0.229.1. There is intentionally no in-place pre-1.0
  compatibility bridge.
- Fresh 0.229.1 databases need no new timer, configuration, or operating mode;
  the generated startup watchdog drives convergence automatically.

## 0.229.0 - 2026-08-16

### 📝 Summary

- Journal and database controls now carry exact database-wide ordering and
  retained-work facts needed for bounded cross-store convergence.
- Dormant position-aware overlays and a test-only cumulative admission
  evaluator establish the later online-convergence shape without changing the
  current production commit, recovery, scheduler, or timer routes.
- This release does not activate cumulative Gate 2 admission or Ready-state
  online folding. The maintained 0.229 design still requires the integrated
  evidence freeze and atomic production activation before those behaviors can
  ship.

### 🔧 Changed

- The sole current journal envelope is version 3 with a codec-derived 93-byte
  fixed header. Its domain-separated SHA-256 fingerprint binds a nonzero
  database commit sequence in addition to the existing marker, owner-local
  sequence, count, length, and record bytes.
- Each current journal tail persists exact batch count, record count, encoded
  envelope bytes, and optional oldest database sequence. Append, identical
  replay, inspection, retirement, reopen, overflow, underflow, and head-order
  checks share that owner-local control authority.
- The existing commit-control allocation now owns one nonzero database
  incarnation, a checked database-sequence high-water mark, and a canonical
  active-plus-retired journal-store registry. The registry admits at most 38
  four-allocation stores and never reuses retired identifiers within an
  incarnation.
- Fresh initialization and eligible 0.228 activation preflight every declared
  allocation and encoded control before publishing the complete version-3
  authority. Current reconciliation initializes only fresh additions and
  retires only stores whose exact tails are empty.
- Data, index, and schema owners contain dormant volatile position maps over
  their existing live values and tombstones. Every maintained journal and
  derived-index effect has an explicit classification, and exact-position
  retirement preserves a newer same-key effect.
- A test-only Gate 2 evaluator sums exact current tail controls with immutable
  prepared-envelope contributions using checked batch, record, and encoded-byte
  arithmetic. Existing individual admission remains authoritative and retains
  diagnostic priority.
- Durable mutation pages now examine at most 224 authoritative keys and stage
  at most 56 row updates, and the current batch-policy identity binds those
  limits directly. Commit-control preview/publication, exact live marker
  retirement, and mutation-progress replacement avoid repeated validation
  work while preserving the complete checksummed authority at publication and
  recovery boundaries.

### 🧪 Testing

- Current-format tests cover fresh and eligible-empty initialization, racing
  predecessor writes, exact sequence publication, registry add/retire/no-reuse,
  maximum registry occupancy, tail aggregate maintenance, reopen, corruption,
  arithmetic failure, and interrupted publication.
- Position-aware owner tests cover all maintained record families, later-batch
  supersession, delete/reinsert, same-batch derived-index coalescing, and exact
  retirement without adding a production call edge.
- Dormant admission tests cover each pressure dimension, Gate 1 diagnostic
  priority, exact prepared-byte fidelity, checked overflow, all 38 store
  allocations, and the 4,096-row zero-index maximum shape. Maintained Gate 1
  coverage continues to pin the maximum-fanout and identity boundaries.
- The lifecycle rollback fixture retries only the typed transient install-code
  throttle with bounded simulated cooldowns, while still requiring the
  deliberate post-upgrade failure to report the exact canister-trap code.

### 📊 Audit

- The production SQL audit artifact is 4,817,124 compiler-emitted Wasm bytes,
  4,205,824 final deployable raw Wasm bytes, and 1,624,157 deterministic-gzip
  bytes.
- Its Candid declaration remains exactly 60,428 bytes with SHA-256
  `5bc8b2c65e8e57ec1bee7db4677d7fff3bcab686159128fc2604fe40c00882d1`,
  and the final artifact retains 70 exports.
- The current format adds one database sequence, one bounded no-reuse registry,
  and one exact tail control per journal allocation. Dormant overlays add one
  volatile position map to each existing owner; Gate 2 instrumentation is
  compiled only for tests.
- The maintained 10,001-row real-canister fixture converges in 179 Forward and
  45 Verify calls. Its maximum tier Forward step is 28,375,024 instructions
  against the unchanged 31,000,000 ceiling, and its maximum tier Verify step is
  7,183,800 against the unchanged 8,000,000 ceiling. Successful upgrade may
  synchronously fold retained work and grow stable memory; exact final rows,
  indexes, receipts, and recovery closure remain asserted, while the dedicated
  trap test owns byte-for-byte rollback proof.
- No public Rust or Candid method, exported method mode, stable-memory
  identifier, timer, scheduler, runtime mode, caller configuration, cursor,
  compatibility decoder, or alternate recovery route is added.

### ⚠️ Breaking

- Journal envelopes and database controls use version 3. Versions 1 and 2 are
  not accepted as current-format authority, and nonempty predecessor tails have
  no decoder, upgrader, repair shim, or dual-format execution interval.
- Only a fresh database or the exact eligible 0.228 state with all journal tails
  empty can initialize version 3. Missing, partial, mismatched, reused, or
  nonempty predecessor authority fails typed and closed.

### 🧭 Migration Notes

- Before upgrading an existing canister, quiesce writes, run exact 0.228.3 until
  startup reports `Ready` with every journal tail empty, keep writes stopped,
  and then install 0.229.0. A racing predecessor write invalidates activation.
- Canisters that cannot establish the exact empty-tail predecessor state must
  be reinstalled or recreated. There is intentionally no pre-1.0 compatibility
  bridge for retained predecessor journal work.
- Production cumulative pressure admission, cross-store online selection,
  positioned publication/retirement, and driver self-chaining remain disabled
  in 0.229.0; their later activation must land atomically after the frozen
  evidence gate.
