# 0.229 Continuous Journal Convergence And Bounded Backlog Admission

## 0.229.0 - 2026-08-16

### 📝 Summary

- Journal and database controls now carry exact database-wide ordering and
  retained-work facts needed for bounded cross-store convergence.
- Dormant position-aware overlays and a test-only cumulative admission
  evaluator establish the later online-convergence shape without changing the
  current production commit, recovery, scheduler, or timer routes.
- This release does not activate cumulative Gate 2 admission or Ready-state
  online folding. The maintained 0.229 design still requires the integrated
  evidence freeze and atomic production activation before those behaviors can
  ship.

### 🔧 Changed

- The sole current journal envelope is version 3 with a codec-derived 93-byte
  fixed header. Its domain-separated SHA-256 fingerprint binds a nonzero
  database commit sequence in addition to the existing marker, owner-local
  sequence, count, length, and record bytes.
- Each current journal tail persists exact batch count, record count, encoded
  envelope bytes, and optional oldest database sequence. Append, identical
  replay, inspection, retirement, reopen, overflow, underflow, and head-order
  checks share that owner-local control authority.
- The existing commit-control allocation now owns one nonzero database
  incarnation, a checked database-sequence high-water mark, and a canonical
  active-plus-retired journal-store registry. The registry admits at most 38
  four-allocation stores and never reuses retired identifiers within an
  incarnation.
- Fresh initialization and eligible 0.228 activation preflight every declared
  allocation and encoded control before publishing the complete version-3
  authority. Current reconciliation initializes only fresh additions and
  retires only stores whose exact tails are empty.
- Data, index, and schema owners contain dormant volatile position maps over
  their existing live values and tombstones. Every maintained journal and
  derived-index effect has an explicit classification, and exact-position
  retirement preserves a newer same-key effect.
- A test-only Gate 2 evaluator sums exact current tail controls with immutable
  prepared-envelope contributions using checked batch, record, and encoded-byte
  arithmetic. Existing individual admission remains authoritative and retains
  diagnostic priority.
- Durable mutation pages now examine at most 224 authoritative keys and stage
  at most 56 row updates, and the current batch-policy identity binds those
  limits directly. Commit-control preview/publication, exact live marker
  retirement, and mutation-progress replacement avoid repeated validation
  work while preserving the complete checksummed authority at publication and
  recovery boundaries.

### 🧪 Testing

- Current-format tests cover fresh and eligible-empty initialization, racing
  predecessor writes, exact sequence publication, registry add/retire/no-reuse,
  maximum registry occupancy, tail aggregate maintenance, reopen, corruption,
  arithmetic failure, and interrupted publication.
- Position-aware owner tests cover all maintained record families, later-batch
  supersession, delete/reinsert, same-batch derived-index coalescing, and exact
  retirement without adding a production call edge.
- Dormant admission tests cover each pressure dimension, Gate 1 diagnostic
  priority, exact prepared-byte fidelity, checked overflow, all 38 store
  allocations, and the 4,096-row zero-index maximum shape. Maintained Gate 1
  coverage continues to pin the maximum-fanout and identity boundaries.

### 📊 Audit

- The production SQL audit artifact is 4,817,124 compiler-emitted Wasm bytes,
  4,205,824 final deployable raw Wasm bytes, and 1,624,157 deterministic-gzip
  bytes.
- Its Candid declaration remains exactly 60,428 bytes with SHA-256
  `5bc8b2c65e8e57ec1bee7db4677d7fff3bcab686159128fc2604fe40c00882d1`,
  and the final artifact retains 70 exports.
- The current format adds one database sequence, one bounded no-reuse registry,
  and one exact tail control per journal allocation. Dormant overlays add one
  volatile position map to each existing owner; Gate 2 instrumentation is
  compiled only for tests.
- The maintained 10,001-row real-canister fixture converges in 179 Forward and
  45 Verify calls. Its maximum tier Forward step is 28,375,024 instructions
  against the unchanged 31,000,000 ceiling, and its maximum tier Verify step is
  7,183,800 against the unchanged 8,000,000 ceiling. Successful upgrade may
  synchronously fold retained work and grow stable memory; exact final rows,
  indexes, receipts, and recovery closure remain asserted, while the dedicated
  trap test owns byte-for-byte rollback proof.
- No public Rust or Candid method, exported method mode, stable-memory
  identifier, timer, scheduler, runtime mode, caller configuration, cursor,
  compatibility decoder, or alternate recovery route is added.

### ⚠️ Breaking

- Journal envelopes and database controls use version 3. Versions 1 and 2 are
  not accepted as current-format authority, and nonempty predecessor tails have
  no decoder, upgrader, repair shim, or dual-format execution interval.
- Only a fresh database or the exact eligible 0.228 state with all journal tails
  empty can initialize version 3. Missing, partial, mismatched, reused, or
  nonempty predecessor authority fails typed and closed.

### 🧭 Migration Notes

- Before upgrading an existing canister, quiesce writes, run exact 0.228.3 until
  startup reports `Ready` with every journal tail empty, keep writes stopped,
  and then install 0.229.0. A racing predecessor write invalidates activation.
- Canisters that cannot establish the exact empty-tail predecessor state must
  be reinstalled or recreated. There is intentionally no pre-1.0 compatibility
  bridge for retained predecessor journal work.
- Production cumulative pressure admission, cross-store online selection,
  positioned publication/retirement, and driver self-chaining remain disabled
  in 0.229.0; their later activation must land atomically after the frozen
  evidence gate.
