# 0.266 — Shared Tooling and Correctness

## [0.266.0] - 2026-10-06

### 🩹 Fixed

- Sum repeated resources before preflighting a budget bundle or estimating
  remaining complete units. Request and execution budgets share checked totals;
  overflowing costs and bundles exceeding either limit are refused without
  committing semantic charges. Preserve exact-limit admission, zero-cost and
  empty bundles, retained prior work and typed instruction-exhaustion failures.
  Regressions cover every request resource, both limiting scopes, mixed/reordered
  charges, retries and the active execution helper
  ([#286](https://github.com/dragginzgame/icydb/issues/286)).
- Reject unknown SQL UPDATE assignments and INSERT columns with the existing
  typed `ValidateError::UnknownField` from the accepted descriptor instead of
  reporting engine corruption. Check the full INSERT column list before
  required-field policy or source execution, including empty SELECT sources.
  Literal, NULL and DEFAULT writes share the rejection; resumable starts return
  `IneligibleIntent` without persisting a job. Focused regressions cover exact
  and prefix updates, public primary-key/bounded plans, missing/matching selectors,
  repeated unknown columns, multi-row admitted INSERT controls and preserved
  rows/jobs
  ([#221](https://github.com/dragginzgame/icydb/issues/221)).
- Fail invariant searches on ripgrep errors while retaining the no-match
  success case. SQL, layer, index and mutation scans share that exit contract;
  missing SQL roots and failed/empty executor inventories no longer pass.
  Detect assertion variants, unreachable/todo/unimplemented macros and macro
  delimiter variants. Restrict test exclusions to attributes requiring test,
  and scan ignored production files. Offline fixtures qualify search errors,
  grouped pipelines, root discovery, comments, production/test cfg boundaries
  and panic patterns; native macOS qualification remains CI-owned
  ([#266](https://github.com/dragginzgame/icydb/issues/266)).
- Preserve full PocketIC server stdout/stderr on startup failure, child failure
  and interruption, and print their retained directory. Stop and reap only the
  owned server while preserving the failure exit status; successful scratch
  cleanup remains unchanged. Tier B CI uploads retained logs, with substitute
  fixtures covering startup, child failure, SIGINT, SIGTERM and success
  ([#303](https://github.com/dragginzgame/icydb/issues/303)).
- Parse workflow YAML with the selected yq/jq tools. Check permissions, each
  runner's timeout, each checkout's credential setting and job dependency sets
  by their parsed owner instead of counting lines or requiring one list order.
  Reuse shared action pinning rules; retain IcyDB's lane and recipe policies.
  Fixtures cover comments, quoted/folded YAML, block/reordered dependency lists,
  misplaced settings, failed discovery and malformed input
  ([#304](https://github.com/dragginzgame/icydb/issues/304)).

### Breaking

- Replace the local tag-maintenance shell command with the shared Perl command:
  `perl scripts/dev/delete-github-tags-up-to.pl --cutoff 0.210` previews every
  stable tag through that minor line. Update invocations to the `.pl` command and
  provide an explicit full minor or patch cutoff; no default cutoff, single-number
  shorthand or implicit remote remains. Deletion still requires explicit scopes
  and confirmation. The shared owner checks exact object identities, performs
  atomic remote batches before local removal and retains selection/attempt
  evidence for interrupted operations. Release and publication never invoke it;
  this tooling change requires no database regeneration or reset
  ([#305](https://github.com/dragginzgame/icydb/issues/305)).

### 🔧 Changed

- Adopt shared structural Cargo inheritance checks in the existing CI/release
  gates. Accept ordinary and inline TOML tables and root-owned aliases; reject
  member versions, dependency source overrides and missing catalog entries.
  Remove the incomplete local text scan and Bash-4-only inventory while retaining
  coupled package pins, dependency bans, duplicate-sensitive versions and the
  resolved time constraint. Consolidate version reads through the shared offline
  Cargo/yq/jq reader, including valid quotes/comments and malformed or failed
  observations. Receipts still select an exact committed source tree with its
  package targets, retaining failed exports before admitting a new receipt.
  Remove the unused cargo-get setup selection. Refresh the shared actionlint
  installer together with its implementation; preserve consumer pins and the
  selected executable on checksum/version rejection, retaining failed candidates
  ([#306](https://github.com/dragginzgame/icydb/issues/306),
  [Shared Tooling #18](https://github.com/dragginzgame/shared-tooling/issues/18)).

- Refresh the committed shared snapshot to `d957d1f` (0.1.8), adopting explicit portable
  installer/snapshot refusals and applying the same rejection contract to local
  version reads and candidate checks
  ([Shared Tooling #14](https://github.com/dragginzgame/shared-tooling/issues/14)).
- Delegate exact local lockfile rewriting to the shared owner. Derive the roster
  from locked workspace metadata, preserve source-qualified external entries and
  refuse missing, duplicate or inconsistent local identities before replacement.
  Retain failed inputs/candidates; existing locked offline validation and release
  rollback keep their ownership
  ([Shared Tooling #15](https://github.com/dragginzgame/shared-tooling/issues/15)).
- Qualify the real formatting targets and isolated staged hook with the shared
  checker, retaining consumer derive sorting and unusual-path coverage. Enable
  the qualified repository hook independently of the formatting checks. Give
  the disposable formatter package an explicit workspace boundary so release
  scratch directories inside IcyDB cannot make Cargo adopt its parent workspace
  ([Shared Tooling #16](https://github.com/dragginzgame/shared-tooling/issues/16)).
- Provision checksum-pinned PCRE2-enabled ripgrep through the shared host installer
  for local setup and CI, replacing a second system-package selection. Offline
  tool checks verify the selected artifact and PCRE2 capability before use
  ([Shared Tooling #17](https://github.com/dragginzgame/shared-tooling/issues/17)).
- Adopt the reviewed Shared Tooling 0.1.8 snapshot. `make install-tools`
  explicitly provisions pinned jq/yq and the six common IC executables in
  `.tools`; `make tools-check` verifies them offline. Workstation and CI setup
  use the same owners. IcyDB retains the Binaryen 132 pipeline, raw optimizer
  admission and locked PocketIC client/server alignment; test processes do not
  download missing servers
  ([#302](https://github.com/dragginzgame/icydb/issues/302)).
- Use shared audit methods through thin IcyDB overlays, retaining catalog,
  publication/recovery, facade, report and focused-test obligations. Preserve
  original methods and historical reports without rescoring them
  ([#301](https://github.com/dragginzgame/icydb/issues/301)).
- Delegate documentation navigation, standard release-command fixtures,
  crates.io version observation and portable report digests to shared helpers.
  Keep product inventory/version checks, release receipts and cache preparation,
  publication ordering/waits, and report schema/subject identities local.
  Adapter fixture archives also use the shared digest owner instead of selecting
  checksum backends separately.
- Reuse `ic-host-tools` hex decoding and executable resolution in the CLI and
  optimizer, with streaming optimizer hashing. Preserve CLI labels, whitespace
  normalization and rejection semantics, and verify the admitted optimizer
  before executing it. The dependency remains confined to host consumers.
- Core and all direct audit/test-canister readers use
  `ic_cdk::api::call_context_instruction_counter()`. Remove the `ic` feature
  selection and reader-only metrics dependencies from fixtures; adopt published
  registry ic-metrics 0.2.0 for dependency-free arithmetic. Inclusive overlapping
  spans, native zero, measured zero/saturation, maxima, report shapes and reset
  identity are unchanged ([ic-metrics #10](https://github.com/dragginzgame/ic-metrics/issues/10)).
  Counter-0 reads retain their distinct scope; native canister CDK calls remain
  unsupported measurement paths. Adopt published IC Timers 0.14.0 so the whole
  graph uses one ic-metrics 0.2 identity; timers read through their existing
  `ic0::performance_counter(1)` adapter. Generated actor glue and direct timer
  callers share that dependency. Supported IcyDB APIs, Candid/storage contracts,
  scheduling and attribution are unchanged.
