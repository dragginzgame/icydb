# IcyDB 0.256

## 0.256.1 — Downstream SQL Handler Linting

### 🩹 Fixed

- Generated SQL query, DDL, primary-key update, bounded update and integrity
  handlers now locally allow their intentional owned-input pattern. This fixes
  Toko Miner's ICYDB-022 without application-wide suppression. Public endpoint
  arguments, authorization, dispatch and runtime behavior are unchanged.

### 🧪 Testing

- Existing SQL-consuming audit and authorization canisters deny
  `needless_pass_by_value`, overriding the workspace allowance. The SQL-enabled
  consuming-crate checks run in the existing local and CI lint gates, covering
  both an application with no SQL exports and a generated guarded SQL endpoint.

### 📊 Audit

- SQL-enabled and disabled strict consuming-crate checks and five existing
  facade compile-contract tests pass. Changes span eight files; the three Rust
  files add only lint attributes/comments (+24/−1 lines), with no new runtime
  flow. Cycle/Wasm measurements and full/downstream suites were not run;
  no measured performance change is claimed. Applications and Cargo versions
  remain untouched.

## 0.256.0 — Application API Friction

### 🔧 Changed

- Generated row decoding moves text, blob and big-integer values into Rust rows,
  including values nested inside collections, records, tuples and enum payloads.
  The existing decoder is changed in place; ordinary generated query and write
  calls, accepted-schema checks and post-publication decoding semantics remain
  unchanged. Neither downstream application was edited.
- Typed blob inputs transfer their existing byte buffer into the public value,
  including blobs nested in optional collections. The scalar adapter uses the
  atom's existing consuming accessor; no API or admission behavior changes.

### ⚠️ Breaking

- Handwritten `TypedOutputValue` and `TypedAdapterContext` output implementations
  now consume public values; `TypedEnumSelection` owns its payload. Custom row
  adapters use `take_row_value` with a mutable scratch row and consume the output
  wrapper. `record_output_values` likewise consumes its record. Generated
  implementations are updated together; no borrowed compatibility path remains.

### 🧪 Testing

- Added generated-row text/blob buffer-ownership checks, nested enum/tuple
  decoding, record permutation/NULL checks and malformed-field/collection
  regressions. The final focused run passes 33 tests; lint and SQL-enabled
  facade checking also pass. Full suites remain user-owned.
- Added scalar/nested blob-input buffer-ownership and accepted-field rejection
  parity checks. The input slice's final 20 focused tests, lint and SQL-enabled
  facade checking pass; full suites remain user-owned.

### 📚 Documentation

- The enrollment guide and SQL-disabled compile fixture return the preallocated
  user ID without retaining unused handles or decoding discarded saved rows.
  Dedicated runtime coverage still exercises handles and one-time row decoding.
- Clarified that result decoding is optional application work after publication:
  a later decoding error does not roll back the batch. The existing executor,
  database validation, result preparation and public APIs are unchanged.

### 📊 Audit

- Traced lookup, paginated projection and read/validate/write flows in Toko Miner
  and Toko, separating existing application adapters and older dependency pins
  from current library capabilities. Existing exact-key and batch terminals
  cover the concrete simplification opportunities; no new write API is added.
- Recorded application-owned post-publication failure boundaries and focused
  qualification requirements. This was source inspection only, not downstream
  compilation, failure injection or an adoption verdict. See the
  [application audit](../design/0.256-application-api-friction/0.256-application-audit.md).
- The slice 1 example correction removes three net Rust lines with no production Rust
  change. Its SQL-disabled compile test, existing runtime batch-row test and
  focused lint pass. Formatting, local documentation links and guide/fixture
  parity checks also pass; no performance or Wasm-size change is claimed.
  Full suites remain user-owned.
- The owned-decoding slice changes seven Rust files (about −2 production and
  +261 test lines) with one converged decoder. It removes intermediate record
  buffers rather than adding a new execution path. The matched instrumented
  typed actor is 4,698 final raw Wasm bytes smaller, with 16 fewer functions.
  At 256 rows, decoder allocation requests fall from 257 to 1 for text-only
  rows and 6,657 to 1,281 for nested rows. End-to-end cycle deltas are mixed:
  −0.4944% to +0.8614%, within the predeclared +1% ceiling; large nested reads
  are slightly more expensive. See the [measurement receipt](../design/0.256-application-api-friction/0.256-owned-decoding-receipt.md).
- The blob-input slice replaces one production line and adds 94 test lines in
  two Rust files, without another execution path. It removes one allocation and
  one payload-sized copy per nonempty blob. Its separate instrumented actor adds
  62 final raw Wasm bytes and no functions; measured request cycles range from
  −0.8225% to +0.0000355%, within the unchanged gates. These byte deltas cannot be
  combined with the different slice 3 actor. See the [blob-input receipt](../design/0.256-application-api-friction/0.256-blob-input-receipt.md).
