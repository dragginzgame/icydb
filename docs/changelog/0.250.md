# IcyDB 0.250 — Reachable Generated Entity Specialization

## [0.250.1] - 2026-08-31

### ⚠️ Breaking

- Hard-cut `InputValue::list` to accept `Vec<InputValue>` and
  `InputValue::map` to accept `Vec<(InputValue, InputValue)>`. Recursive lists,
  maps and enum payloads now compose entirely through the input root; callers
  should remove nested `InputValue::into_public()` conversions. The safe owned
  conversion also makes the two constructors non-`const`.

### 🔧 Changed

- Kept conversion in one concrete core-owned implementation rather than a
  generic iterator convenience layer, avoiding downstream specialization over
  iterator and closure shapes. The constructors move nested values without
  cloning and retain the existing single `PublicValue` recursive kernel.
- Preserved distinct input/output roots, accepted-schema enum admission and all
  Candid, Serde, schema, persistence, cursor and runtime value contracts. The
  focused demo Candid is byte-identical; final raw/code Wasm grows by only
  151/150 bytes with flat indirect calls.

## [0.250.0] - 2026-08-31

### 📊 Audit

- Added a maintained one-to-ten-entity comparison that makes bounded page,
  exact-key, single-write, same-entity batch and delete adapters reachable for
  every measured entity. Nine added entities increase final raw Wasm by 83,540
  bytes, or 9,283 bytes per entity, and increase the final code section by
  82,173 bytes.
- Final defined functions increase by 110 while `call_indirect` remains flat.
  Named monomorphization evidence attributes 76,647 duplicate bytes to the
  selected shared terminal, page and write families, qualifying the concrete
  prepared-page owner planned for the next landing slice.
- Frozen downstream source, toolchain and retained artifact identities are
  recorded separately from the maintained comparison. The removed
  proof-of-concept source remains intake evidence and is not represented as a
  reproducible accepted A/B.
- Retained a simplified concrete prepared-page cursor after an exact final Toko
  A/B reduced code by 30,969 bytes, raw Wasm by 35,345 bytes and defined
  functions by 12 with flat `call_indirect`. This is an explicit
  candidate-specific exception 1,799 code bytes short of the original 32 KiB
  target; the target itself was not lowered.
- Replaced generated binding request construction with static entity
  descriptors. The sequential Toko A/B removes another 20,089 raw bytes,
  31,462 code bytes and 19 defined functions with flat `call_indirect`; the
  cumulative reduction from `v0.249.6` is 55,434 raw and 62,431 code bytes.
- Converged exact-key lookup and row preparation behind a concrete terminal.
  The sequential Toko A/B removes another 12,319 raw bytes, 12,306 code bytes
  and five defined functions with flat `call_indirect`; the cumulative
  reduction from `v0.249.6` is 67,753 raw and 74,737 code bytes.
- Converged source-bound same-entity insert, update, replace and delete batches
  behind one prepared-row terminal. The sequential Toko A/B removes another
  14,123 raw and 13,711 code bytes with flat `call_indirect`; the cumulative
  reduction from `v0.249.6` is 81,876 raw and 88,448 code bytes.
- Closed the cumulative audit with 32 fewer functions, flat indirect calls and
  unchanged public artifacts in the exact downstream actor. The retained
  reachable-entity slope improves from 9,283 to 4,466 raw bytes per entity but
  remains distinct from dead-strippable schema growth; it passes the explicitly
  authorized 8 KiB reachable-adapter ceiling while the schema-only comparison
  keeps its 2 KiB gate.

### 🔧 Changed

- Hard-cut the Wasm measurement identity to
  `icydb-wasm-footprint/0.250/v1`, retained representation version `1`, and
  named the original unused-entity comparison `schema_entity_scale` so it
  cannot be confused with reachable adapter cost.
- Extended machine reports with final code-section bytes, defined-function
  count and `call_indirect` count. Separate fail-closed schema and reachable
  validators now enforce 2 KiB and 8 KiB ceilings respectively, replacing the
  reachable comparison's temporary report-only path without adding runtime
  configuration.
- Centralized public/trusted typed page execution, continuation validation and
  accepted-row preparation in one concrete cursor. Final generated row decode
  remains typed, while the existing typed query builder remains the sole
  request-construction owner.
- Hard-cut the allocation-backed generated binding request DTOs and conversion
  layers to one core-owned static source contract. Accepted snapshots remain
  runtime authority and validate ordered primary keys, field shapes and
  nullability before issuing the existing opaque binding.
- Hard-cut entity-generic exact-key execution to concrete
  `PrimaryKeyValue` inputs and prepared distinct rows with bounded position
  metadata. Only final typed identifier encoding, row decoding and duplicate
  reconstruction remain generic; `get` remains a convenience over `get_many`.
- Added delete to the source-bound typed mutation contract and one same-entity
  admission that validates the accepted binding/catalog once before reusing
  the canonical atomic executor. The proving consumer removes its parallel
  generated structural insert/update/delete encoder family.
- Split release validation into a cheap fail-fast preflight and an accumulating
  long phase. Failed long targets are retained together in one text log, and
  the read-admission invariant now guards the concrete prepared-cursor handoff.

### 🧪 Testing

- Added focused PocketIC controls that execute every selected operation on the
  one-entity and ten-entity actors and record request-local instruction
  sentinels. Generated API, Candid behavior, persistence and cursor formats are
  unchanged.
- Verified that the retained Toko candidate preserves all 274 export names and
  byte-identical embedded Candid. Focused page controls changed by fewer than
  800 instructions, and the other selected read/write controls were unchanged
  or slightly lower.
- Added focused generated-descriptor coverage for scalar, list, named,
  nullable and composite-key shapes plus accepted rename, name-reuse and stale
  binding behavior. The descriptor candidate preserves exports and Candid, and
  every selected operation-cost sentinel improved slightly.
- Added focused exact-key coverage for missing rows, duplicates, input order,
  one/many parity, composite keys, stale bindings, hard budgets and prepared
  output rows. The maintained nine-entity raw slope falls from 83,938 to
  43,177 bytes with flat indirect calls and stable operation costs.
- Added focused typed-batch coverage for mixed operation order, bounds,
  stale/foreign bindings, atomic rejection, interrupted recovery,
  single/batch parity and delete before-images. A provisional mixed-admission
  shape was rejected after a material delete-cost regression; the retained
  shape improves both batch and delete controls and lowers the maintained raw
  slope to 40,188 bytes across nine entities.
- Rebuilt final symbol-bearing attribution and reran the focused reachable
  operation mix. The remaining named duplicate bloat is concentrated in
  generated conversion/write leaves rather than common page, exact-key or
  atomic execution, and the cursor round-trip plus preserved Candid hashes
  confirm that closeout changes no format or public behavior.
- Added exact-limit, one-byte-over-limit and rounding controls for both entity
  budgets. The real schema pair passes at 1,038 bytes per entity and the real
  reachable pair passes at 4,466, with 1,010 and 3,726 bytes of headroom.
- Added focused validation-runner probes for first-error stopping and combined
  multi-target failure retention; the corrected repository invariant gate
  passes without rerunning already-completed long tests.
