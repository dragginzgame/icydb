# 0.279

## [0.279.0]

### ⚠️ Breaking

- Public schema Principal conversions and read-authorization contexts use the
  IC Platform 0.5.0 type identity. Update caller dependencies to the same release
  and retain explicit conversions for external Agent/PocketIC identities. Wire,
  binary Serde, stored bytes and authorization decisions are unchanged. The
  whole pending batch therefore selects 0.279.0; package version changes remain
  with the release workflow.

### 🔧 Changed

- Adopt committed Shared Tooling 0.25.8 through the canonical snapshot exporter,
  preserving the selected roots and grouped formatting. Metadata checks retain
  failed Cargo observations and source inputs; release preparation accepts both
  supported numbered pending-heading forms.
- Select published Platform 0.5.0's runtime-only feature for four system-helper
  fixtures, removing the unused Platform entrypoint generator from the lockfile.
  Canic retains endpoint/lifecycle ownership and IC Wire retains application
  codecs. Transitive Canic Candid/CDK dependencies remain; declaration/graph
  checks do not establish final-artifact exclusion enforcement.
- Run the existing complete Clippy gate before expensive release validation and
  repository ICP builds. Parallel-Make regression fixtures reject lint failure
  before builders, tests or Wasm staging, preserving existing artifacts.

- Adopt verified upload-artifact 7.0.2, download-artifact 8.0.2, setup-node
  7.1.0 and the Rust toolchain action's safer input handling. Keep the selected
  Node/npm/Rust versions, artifact names and paths, Wire-only release staging,
  permissions and evidence retention. The shared failure-evidence action already
  uses the same upload pin ([#351](https://github.com/dragginzgame/icydb/pull/351),
  [#352](https://github.com/dragginzgame/icydb/pull/352),
  [#353](https://github.com/dragginzgame/icydb/pull/353),
  [#385](https://github.com/dragginzgame/icydb/pull/385)).

- Use the same pure Cargo candidate projection during version preparation and
  receipt admission, backed by the published IC Build metadata editor. Retain
  Make-owned editor admission, the eight MiB per-document allowance, exact
  internal pins, external dependency selections, checked producer failures and
  the existing rollback owner. README examples are ordinary source; remove their
  automatic rewrite and cargo-edit from workstation setup. Refuse failed version
  discovery even after it emits a complete version, preserving the admission
  boundary on system Bash
  ([#377](https://github.com/dragginzgame/icydb/pull/377)).

- Delegate native TypeScript type rendering, reference validation and method
  objects to published IC Wire 0.5. IcyDB retains concrete Serde reflection,
  endpoint identities, admission allowances and scalar validation. Remove the
  local recursive renderer. Contracts, runtime files and exact native vectors
  remain byte-identical; TypeScript declarations use the shared emitter's
  header, import quoting and JSON-parsed metadata ([#383](https://github.com/dragginzgame/icydb/pull/383)).

- Use published Testkit's `advance_and_tick` for startup fixture delivery,
  preserving each time advance and tick count, including zero-time completion
  after instruction exhaustion. Testkit retains PocketIC lifecycle ownership;
  IcyDB retains bounded watchdog readiness policy
  ([#381](https://github.com/dragginzgame/icydb/pull/381)).

- Extend regression coverage for repeated oversized indexed SQL literals and
  matching warm bootstrap after historical journal admission. Refusals preserve
  rows; warm adoption preserves the generation, admission call count and every
  backing-memory byte ([#387](https://github.com/dragginzgame/icydb/pull/387),
  [#366](https://github.com/dragginzgame/icydb/pull/366)).

### 🩹 Fixed

- Select fixture-owned Cargo cache and target paths for both Make dispatch and
  standalone deployment build hooks. Release validation's inherited paths can
  no longer fail the substitute Cargo assertions before builder dispatch.
  Retain the complete lint gate, live jobserver checks, failure admission and
  unchanged staged-artifact assertions; production cache handling is unchanged.
- Reject an incomplete existing journal batch as store corruption before
  publishing controls or bytes. Remove the prefix-repair route and its alternate
  sequence/commit-order admission; keep complete identical replay idempotent.
  Valid retained journal frames and format identities are unchanged. Regression
  coverage exercises truncation at a chunk boundary and within the final chunk,
  repeated refusal and unchanged backing bytes
  ([#174 — Remove journal prefix repair](https://github.com/dragginzgame/icydb/issues/174)).

- Admit the complete release-file inventory before capturing originals or
  attempting metadata edits. A failed Git inventory cannot be hidden by process
  substitution after valid paths have been emitted; retain its output for
  diagnosis. Incomplete preparation also refuses a zero exit status while
  restoring its existing rollback set
  ([#377](https://github.com/dragginzgame/icydb/pull/377)).

- Admit the locked, prepared IC Build editor and its eight MiB input allowance
  before standalone receipt validation. Static CI no longer depends on editor
  variables inherited from release verification. The adapter regression clears
  those variables and checks actual Make dispatch, Cargo cache/jobserver
  forwarding and editor selection. Receipt projection, failure admission and
  release effects retain their existing owners
  ([#361 — Build and Wasm reporting qualification](https://github.com/dragginzgame/icydb/issues/361)).
