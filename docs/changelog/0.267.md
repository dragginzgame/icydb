# 0.267 — Diagnostic accuracy and tooling

## [0.267.2]

### 🔧 Changed

- Delegate PocketIC batch supervision to the published Testkit runner, selected
  from the workspace lock during explicit setup. IcyDB keeps complete failure
  output paths, console presentation, signal forwarding and successful scratch
  cleanup; Testkit owns startup, readiness and process-group cleanup. Native CI
  prepares the runner before validation, which never installs it implicitly
  ([#307](https://github.com/dragginzgame/icydb/issues/307),
  [Testkit #29](https://github.com/dragginzgame/ic-testkit/issues/29)).
- Narrow shared-tooling adapter tests to IcyDB's repository/evidence selection,
  argument/status forwarding, nested jobserver context and actionlint pins/assets.
  Shared runner and installer failure permutations remain protected by tests at
  the reviewed upstream snapshot revision
  ([#318](https://github.com/dragginzgame/icydb/issues/318)).
- Adopt reviewed Shared Tooling 0.1.20. Its runner retains raw failed-target
  logs in dispatch order and publishes `latest-combined.log`; `latest.log`
  remains the last failed target. Remove IcyDB's separate per-run directory,
  globbing, framing, concatenation and latest-log copy machinery. The consumer
  selects only repository/log roots and target arguments
  ([#318](https://github.com/dragginzgame/icydb/issues/318)).
- Use the shared PocketIC checker with the actual root manifest, canonical pin
  matrix and prepared repository Cargo cache. Cargo owns locked offline graph
  selection; the shared pin validator owns the three-host matrix. Retire local
  lockfile/TSV parsing and its workstation fixtures; qualify the shared checker
  alongside the maintained Make dispatch
  ([#302](https://github.com/dragginzgame/icydb/issues/302)).
- Admit the report's explicitly selected optimizer through the same version and
  digest authority as deployable builds. Project its observed identity into the
  existing report format and retain the admitted handle for feature and metrics
  queries, rejecting executable drift before execution. Preserve optimizer
  flags, inherited environment, capture limits and whole-stream artifact hashing
  ([#307](https://github.com/dragginzgame/icydb/issues/307)).
- Qualify the selected Host 0.5.0 libraries and converge transform, feature and
  metrics execution on the optimizer owner's existing inherited environment,
  capture limits and failure projection. Preserve report format and command
  flags. Testkit 0.21.3 still requires Host 0.4; its approved next minor owns
  dependency convergence and shared child-group adoption
  ([#307](https://github.com/dragginzgame/icydb/issues/307),
  [Testkit #25](https://github.com/dragginzgame/ic-testkit/issues/25)).
- Use an explicit temporary-directory template for release lockfile snapshots,
  preserving caller-selected failure evidence on Darwin as well as Linux.
  Qualify retained original/candidate bytes with a native-temp selection
  substitute, without running release effects or changing the repository's
  versions or selected lock
  ([#309](https://github.com/dragginzgame/icydb/issues/309)).
- Run core commit/recovery tests through the production marker-presence hint.
  Remove the test-only always-present and no-op bookkeeping implementations;
  retain one thread-local, allocation-scoped hint owner. Qualify publication,
  verified clear, failed clear, allocation switching and thread isolation.
  Production persistence/recovery contracts remain unchanged; the separate
  test backlog allocator is still an independent qualification boundary
  ([#267](https://github.com/dragginzgame/icydb/issues/267)).
- Remove the panic assertion from ordinary String planner-label rendering.
  Reuse the same streaming grammar and infallible String sink; charged and
  bounded sinks still return their first formatting failure. Labels, cursor
  ordering identity and projection output remain unchanged
  ([#276](https://github.com/dragginzgame/icydb/issues/276)).
- Bind SQL CHECK literals against the accepted catalog's resolved newtype kind,
  matching generated checks without another type resolver. Canonical numeric,
  decimal and quoted text checks round-trip through ALTER TABLE
  parsing, including nested wrappers, all comparison operators and either literal
  position. Retain
  strict literal bounds, type/length rejection and rejection of missing catalog
  authority. Persisted expressions and runtime evaluation are unchanged
  ([#282](https://github.com/dragginzgame/icydb/issues/282),
  [#232](https://github.com/dragginzgame/icydb/issues/232)).
- Admit CARDINALITY in SQL CHECK expressions using the existing accepted
  list/set/map cardinality node and evaluator, including nominal wrappers.
  Qualify empty, single-item, over-limit and NULL collections, malformed calls,
  wrong kinds and current query-surface rejection. Preserve query function
  admission, existing grouped identity tags and persisted CHECK representation
  ([#282](https://github.com/dragginzgame/icydb/issues/282)).
- Resolve integral SQL literals exactly against accepted Decimal field scale,
  sharing the numeric conversion and strict literal-admission owners across
  CHECK, read predicates and writes. Canonical zero and integral Decimal checks
  bind without changing rendered spellings or general number parsing. Preserve
  existing Decimal literals and reject scale overflow or unrelated literal
  domains. Broader wide-integer and float spelling cases remain separate
  ([#232](https://github.com/dragginzgame/icydb/issues/232)).
- Bind bare wide integers represented by scale-zero Decimal atoms exactly to
  accepted Int128, Nat128, IntBig and NatBig fields. Reuse the strict field
  admission owner and checked Decimal integer conversion across SQL writes,
  comparisons, membership and CHECK binding, including nominal wrappers.
  Preserve negative/byte-bound rejection and reject Decimal-point spellings;
  document quoted integer spelling beyond the parser's signed 128-bit range.
  General numeric typing and rendering are unchanged, so arbitrary wide and
  float render/parse cases, including Candid's grouped big-integer display,
  remain open
  ([#232](https://github.com/dragginzgame/icydb/issues/232)).
- Project execution EXPLAIN's logical order-pushdown diagnostic from the same
  frozen route fact and canonical label owner as its route diagnostic. Eligible,
  rejected and non-applicable routes no longer report missing model context.
  Remove the duplicate formatter; query planning, execution and report shapes
  retain their existing owners. The broader typed logical-EXPLAIN and admission
  questions remain separate
  ([#270](https://github.com/dragginzgame/icydb/issues/270),
  [#275](https://github.com/dragginzgame/icydb/issues/275)).

- Charge dedicated grouped COUNT window sorting against the existing execution
  sort budgets. Share the generic grouped heap-candidate accounting owner,
  including owned key bytes, and reject exhaustion before allocation or heap
  work. Preserve HAVING, offset, canonical direction and continuation behavior;
  tests now exercise the production selector instead of a separate heap loop
  ([#269](https://github.com/dragginzgame/icydb/issues/269)).

  table must accept that marker for empty, inconsistent or saturated inputs;
  valid numeric averages retain integer-floor rounding. This requires the next
  minor changelog from finalized 0.266.0, carrying the complete pending batch.
  Cargo versions are unchanged; no Candid, persisted data or endpoint changes
  and no reinstall/reset are required
  ([#313](https://github.com/dragginzgame/icydb/issues/313)).

### 🩹 Fixed
