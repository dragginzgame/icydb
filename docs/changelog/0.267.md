# 0.267 — Diagnostic accuracy and tooling

## [0.267.0]

### Breaking

- CLI average cells can contain `unavailable`. Scripts parsing this diagnostic
  table must accept that marker for empty, inconsistent or saturated inputs;
  valid numeric averages retain integer-floor rounding. This requires the next
  minor changelog from finalized 0.266.0, carrying the complete pending batch.
  Cargo versions are unchanged; no Candid, persisted data or endpoint changes
  and no reinstall/reset are required
  ([#313](https://github.com/dragginzgame/icydb/issues/313)).

### 🩹 Fixed

- Render entity averages through ic-metrics 0.2.6 `checked_mean`. Empty,
  inconsistent and independently saturated count/total pairs display
  `unavailable`, rather than a misleading numeric average; observed zero stays
  `0` and valid nonempty means still round down. The CLI declares the shared
  dependency through the root catalog. Report fields, Candid, attribution and
  stored data are unchanged ([#313](https://github.com/dragginzgame/icydb/issues/313)).

- Converge journal, commit marker/control, identity-state, startup-receipt and
  mutation-intent byte extraction on the checked reader. Preserve each format's
  endianness, bounds, trailing-byte checks and typed error classification. Remove
  inactive-slot placeholders and branches from dense accepted row contracts;
  retain historical layout admission and accepted missing-field fills
  ([#290](https://github.com/dragginzgame/icydb/issues/290),
  [#268](https://github.com/dragginzgame/icydb/issues/268)).
- Check the exact generated index name against the schema's 128-byte limit and
  share the key-term bound across authoring and runtime. SQL literal/identifier
  helpers borrow mismatch evidence instead of cloning consumed payloads. Journal
  publication uses row presence for cardinality instead of fetching a discarded
  previous row; value-returning mutations retain their existing contract
  ([#241](https://github.com/dragginzgame/icydb/issues/241),
  [#228](https://github.com/dragginzgame/icydb/issues/228),
  [#262](https://github.com/dragginzgame/icydb/issues/262)).

- Select published host 0.4.0. The CLI uses response decoding without the
  extraction/process dependency; integration explicitly retains Candid
  extraction. Error rendering borrows original captured output and cleanup
  failures through the process owner instead of matching its error variants.
  Preserve response grammar, admission limits, diagnostics and runtime contracts
  ([#307](https://github.com/dragginzgame/icydb/issues/307),
  [Host #3](https://github.com/dragginzgame/ic-host-tooling/issues/3),
  [Host #9](https://github.com/dragginzgame/ic-host-tooling/issues/9)).

- Read complete Wasm artifacts through their opened descriptors using shared
  regular-file admission and fallible bounded allocation. The observed file
  length bounds each read; linked build outputs remain supported and no fixed
  compiler/report artifact-size cap is introduced. Report provenance, versions,
  feature inspection and structural metrics use shared capture with 1 MiB per
  stream and a 600-second operational deadline, retaining argument/environment
  selection, parsing and bounded failure/cleanup diagnostics
  ([#307](https://github.com/dragginzgame/icydb/issues/307)).

- Use the committed Shared Tooling 0.1.15 Make include for pinned setup, offline
  checks and LOC reports. Host setup installs jq, yq, ripgrep and cloc together;
  workstation setup no longer selects a second system cloc. Preserve PocketIC
  client/server alignment and raw optimizer admission as IcyDB-owned checks.
  Make and CI use the same reviewed commands; isolated formatting and release
  fixtures include their dependencies. Keep the explicitly approved existing
  package layout, with no package relocation or dependency/version change
  ([#302](https://github.com/dragginzgame/icydb/issues/302),
  [#310](https://github.com/dragginzgame/icydb/issues/310),
  [Shared Tooling #34](https://github.com/dragginzgame/shared-tooling/issues/34)).

- Use published host 0.3.1 Candid extraction and streamed filesystem publication
  for ICP artifacts. Keep raw Candid text, Wasm permissions, existing paths and
  per-file ordering. Refuse tool/source identity drift, bound each captured
  stream to 1 MiB and child execution to a 600-second operational deadline.
  Failed producers preserve existing destinations; build feature selection owns
  intentional Candid omission and removes stale sidecars. Guard tests reuse the
  complete already-inspected Candid instead of invoking the extractor twice.
  Report byte counts and hashes identify the same file stream
  ([#307](https://github.com/dragginzgame/icydb/issues/307)).
- Correct the durability upgrade and deployment checklists: preserve the memory
  namespace, journaled store keys, accepted store paths and committed allocation
  mapping instead of manually assigning physical IDs. Retired identities cannot
  be reused; key preservation does not permit renaming populated store types
  ([#248](https://github.com/dragginzgame/icydb/issues/248)).
- Adopt committed Shared Tooling 0.1.14. Release, validation and staged formatting
  refuse Make ignore-errors, dry-run, query, touch and version-only modes before
  effects or successful evidence. IcyDB's outer Make command also rejects unsafe
  execution modes during parsing; normal recursive selections and parallel Make
  retain their jobserver. Formatting refusal preserves selected files and index,
  and validation refusal preserves previous complete logs
  ([#311](https://github.com/dragginzgame/icydb/issues/311),
  [Shared Tooling #30](https://github.com/dragginzgame/shared-tooling/issues/30)).
  Source counts exclude Cargo's selected output directory even inside a member
  or under a custom path ([Shared Tooling #31](https://github.com/dragginzgame/shared-tooling/issues/31)).
  Host guidance names the four current package owners
  ([Shared Tooling #35](https://github.com/dragginzgame/shared-tooling/issues/35)).
  Retain the maintainer-restored canister, schema and testing package locations.
- Scope CI's sccache wrapper to the jobs that provision it, so static formatter
  installation can execute Cargo. Align the CI MSRV lane with the manifest's
  existing declaration and qualify the workstation fixture with nested Bash 3.2
  ([#309](https://github.com/dragginzgame/icydb/issues/309)).
- Capture the first accepted primary-key slot at the fallible row-layout
  construction boundary. Empty keys return a typed store invariant before a
  decode contract can be handed off; single and reordered composite keys retain
  their physical slot order. No persisted layout or public API changes
  ([#283](https://github.com/dragginzgame/icydb/issues/283)).
- Qualify public/controller metrics queries and metrics reset declarations
  without the metrics feature through the maintained compile-fail contract
  ([#271](https://github.com/dragginzgame/icydb/issues/271)).
- Retain the Shared Tooling 0.1.11 formatter corrections. Both formatting targets
  check the reviewed cargo-sort version and prepared rustfmt offline, including
  isolated staged-hook fixtures
  ([Shared Tooling #19](https://github.com/dragginzgame/shared-tooling/issues/19)).
  Tag-maintenance retries admit their own retained attempt directories containing
  underscores ([Shared Tooling #11](https://github.com/dragginzgame/shared-tooling/issues/11)).
- Keep passing and ignored Rust `error::` test names out of error highlights,
  including nested validation. Actual diagnostics and failed tests remain
  highlighted; surrounding failure context uses neutral labels and complete raw
  failure logs remain retained
  ([Shared Tooling #22](https://github.com/dragginzgame/shared-tooling/issues/22)).
- Compare changelog version components textually, preserving exact pending-note
  ownership beyond floating-point precision and across component lengths
  ([Shared Tooling #23](https://github.com/dragginzgame/shared-tooling/issues/23)).
- Use the four published host packages at 0.4: artifact digests, Wasm report and
  method inspection use `ic-host-artifacts` with its Wasm feature; diagnostic
  artifact reads use `ic-host-fs`; executable resolution, pinned admission and
  execution use `ic-host-process`; CLI response decoding remains in
  `ic-host-tools`. Convert integration workload digest imports to the artifact
  owner. Remove the handwritten Wasm framing parser; retain IcyDB's method modes,
  CDK exclusions, Candid agreement and report format
  ([#307](https://github.com/dragginzgame/icydb/issues/307)).
- Delegate diagnostic error JSON streams to the shared bounded reader and schema
  artifacts to shared opened-file admission. Preserve the 64 KiB/2 MiB limits,
  exact-limit acceptance, selected-file symlink behavior and existing JSON and
  provenance checks; schema artifacts require regular files. Qualify malformed,
  missing, oversized and special-file inputs, interrupted reads and I/O failures
  ([#307](https://github.com/dragginzgame/icydb/issues/307)).
- Carry one admitted Binaryen handle through each optimizer batch. Shared
  execution rechecks the pinned executable identity before each transform,
  captures at most 1 MiB per stream and kills/reaps its child after a 600-second
  operational deadline. Preserve explicit inherited environment, exact optimizer
  arguments, bounded failure/cleanup evidence, existing output on failure and
  publication/cache policy. These ceilings are resource limits, not performance
  measurements; native CI exercises spaced paths, failure preservation and
  continued batch processing
  ([#307](https://github.com/dragginzgame/icydb/issues/307)).

- Adopt the committed Shared Tooling 0.1.12 snapshot, retaining unrelated working
  changes. Release validation and push dispatch check the saved destination, and

- Require passing executed tests in native CI's existing focused selections,
  using the shared runner. A stale filter selecting zero tests fails, Cargo and
  logging failures preserve their exits and evidence, and the original package,
  feature and filter arguments remain unchanged. This adds no test lane and
  does not substitute upstream CI for native IcyDB qualification
  ([#309](https://github.com/dragginzgame/icydb/issues/309)).
