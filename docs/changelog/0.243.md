# IcyDB 0.243 Detailed Changelog

## 0.243.0

### 📝 Summary

- SQL index DDL now carries its one staged entity-owned index-domain
  replacement directly through accepted-schema publication. The unused plural
  contract and its collection/sorting machinery are removed without changing
  accepted schema, physical index contents, recovery or SQL behavior.
- Accepted snapshots now own canonical relation-ID order, allowing relation
  metadata to iterate the accepted slice directly instead of allocating and
  sorting a second vector on every description.

### 🧹 Cleanup

- Validation consumes the single accepted-before/accepted-after authority
  binding directly instead of maintaining a duplicate-entity set.
- Journal preparation writes the same bounded deletion chunks followed by the
  same bounded insertion chunks without allocating and sorting a second
  replacement collection.
- Physical publication applies the one replacement through the existing index
  readiness and exact-cardinality generation boundary; no cache, state,
  invalidation edge, public surface or persisted representation is added.
- Codec ingress, cloning, mutation rebuilds, migration replacement and
  activation converge on snapshot-owned relation order. The migration-local
  value sort and metadata-local reference sort are removed while duplicate
  relation corruption remains fail-closed.

- Patch 2 independently removes 6,230 final raw Wasm bytes and one net

  byte-identical with six exports. Focused core publication, relation ordering
  and integrity, codec, describe, migration, SQL index create/drop, same-Wasm
  recovery, no-default compilation and warning-denied all-feature checks pass.
- The closing numeric-aggregate audit measured indexed 2,048-row `SUM` at
  98,081,958 instructions cold / 97,717,969 true warm and `AVG` at 98,067,171 /
  97,703,437. Both still load all 2,048 rows, while the existing five-entry
  exact metadata reference takes 591,864 / 369,948 with zero row or physical
  index-entry reads.
- More than 97.1M instructions are directly attributed to removable row and
  reducer work in each cold query. The evidence justifies a separate bounded
  exact `(count, sum)` design, but 0.243 adds no aggregate runtime, cache,
  persisted state, execution route or Wasm bytes for that finding.
