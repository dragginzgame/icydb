# IcyDB 0.254

## 0.254.0 — Reusable Typed SQL And Shared Query Retention

### ➕ Added

- Application code can retain `SqlStatementDispatch` and execute it with typed
  `InputValue` WHERE operands through the existing trusted Rust session API.
  Syntax is parsed once; each invocation resolves current accepted authority.
  SQL remains optional ecosystem support; structural Rust queries stay the
  production default, with no new production SQL endpoint.
- Scalar bindings are admitted before predicate folding, including every IN
  element and operands in unreachable branches. Admission limits are 64 values
  and 64 KiB of logical scalar payload; containers, enum inputs and bound HAVING
  are excluded. Query comparison rules apply, not stored-field write limits.
- A representative new invocation is fixed SQL
  `SELECT id FROM Transfers WHERE account = ? AND amount >= ?`, with account
  and amount supplied as typed values rather than rendered SQL text.

### ⚠️ Breaking

- `execute_trusted_sql_query_dispatch` now requires a bindings slice. Pass `&[]`
  for literal-only SQL. The old Rust arity is removed without a compatibility
  wrapper. Existing endpoint arguments and result types stay unchanged.

### 🩹 Fixed

- Shared expression typing distinguishes known NULL from unresolved types in
  production and tests alike, keeping bound scalar-function arguments consistent
  with literal SQL. CASE unification preserves accumulated branch types even
  with an implicit NULL ELSE; invalid operands and mixed branches still reject
  before folding.
- NULL arithmetic now matches literal SQL for admitted numeric operands, including
  `WHERE (? + 1) IS NULL`. Both operand subtrees and families are validated before
  NULL propagates; incompatible siblings and mixed non-NULL widths still reject.
- Shared query-cache admission now charges concrete plans, structural key copies,
  template metadata, bound operands and accepted-schema references. Replacing a
  template's recent binding reweights the complete entry.
- Lazy preparation products reserve retained capacity before attachment;
  eviction and replacement release their charges. Deferred index bounds reserve
  their encoder-calculated capacity in advance without changing their borrowed
  execution API.
- Cache ineligibility and exhausted retention budgets do not reject valid
  queries. The existing strong plan and recent-binding reuse policy remains.

### 🔧 Changed

- The per-registry 4-MiB shared-plan budget measures owned payload capacity,
  conservatively charging shared graphs. It is not a whole-process heap limit;
  bounded container bookkeeping, allocator overhead, execution temporaries and
  the separate SQL compiled-command cache are outside that claim.
- Arbitrary-precision values with opaque limb capacity are currently ineligible
  for this shared cache. Query execution remains supported. Excessively deep
  accounting traversals also decline caching rather than rejecting execution.
- Bound SQL invocations skip concrete-command cache lookup and insertion.
  Existing shared-plan reuse remains eligible under the retention budget;
  literal-only SQL retains its concrete cache. There is no binding digest,
  statement registry, production endpoint, runtime mode or persisted format change.
- Bound calls perform input preflight once at query ingress. Enclosing typed
  expressions validate nested wrappers/arithmetic together, retaining nested
  comparison normalization and every IN-element check before folding.

### 🧪 Testing

- Adds capacity, overflow, lazy reservation, deferred-bound capacity,
  replacement/eviction and current-binding retention coverage.
- Adds typed scalar handoff, bounded admission, pre-fold rejection, A/B/A
  execution, accepted-field rename and aggregate-WHERE coverage, plus stored-value
  parity against structural reads across 20 scalar families.
- Adds non-test Wasm NULL-function parity and pre-fold rejection coverage through
  a fixed no-argument test-admin probe, with no production or generated endpoint
  change. The regression failed before the shared typing correction and passed
  afterward; native tests separately protect CASE accumulation and unresolved
  argument rejection.
  Coverage now includes all four NULL arithmetic operators and nested-expression
  rejection without weakening query-specific operand normalization.
- Extends the public compile example with reusable syntax and typed domain
  arguments. The maintained fixed-query audit handler initializes syntax at init
  and post-upgrade without adding an export; its Candid annotates empty init arguments.

### 📊 Audit

- Frontend controls separate parsing, copying, admission, execution and allocation
  costs. Changing bound reads use 4.73% fewer instructions than rendered SQL but
  10.29% more than structural queries; identical bindings use 46.89% more than warm
  literal SQL. These are pre-closeout measurements, not a general speedup claim.
- Before the NULL correction, SQL-disabled empty/ten-entity controls grew 38 and
  29,395 raw Wasm bytes (1.003% for ten entities) versus 0.253.3, with unchanged
  Candid. These include shared accounting, not just bindings. The subsequent
  NULL correction adds 184 raw bytes to each matched dynamic/SQL actor, with no
  additional defined functions or Candid change; these are separate comparisons.
- The NULL correction touches nine Rust files: +95 net lines, including 47 fewer
  runtime lines. Shared typing is simpler; regression coverage accounts for the
  growth. Its 74 focused native tests, non-test Wasm regression, lint and feature
  checks passed. Instruction/allocation benchmarks were not rerun for that fix;
  full-suite/release validation and final read-only closeout remain outstanding.
- Subsequent admission cleanup reduces a 32-wrapper host probe from 630 to 70
  lowering visits. Its matched dynamic/SQL actors grow 180/153 raw Wasm bytes,
  with unchanged Candid; six Rust files add 138 net lines, mostly regression
  coverage. This is an admission-work improvement, not an end-to-end speedup claim.
