# IcyDB 0.294

## [0.294.0]

### ⚠️ Breaking

- Adopt registry IC Platform 0.17.0, canonical Types 0.16.0 and the independently
  owned Runtime 0.17.1 IC0 surface. Public Principal/Account conversions now
  require matching Types identities; consumers must align dependencies and
  rebuild. Principal/Account representation, text, Serde and retained database
  bytes are unchanged. Application protocols remain on IC Wire.
- Replace Schema's Platform facade dependency with Types directly. The facade
  uses Types and Runtime; Core selects Runtime for IC0 and keeps Platform only
  for BLAKE3. The IC0-only actor depends directly on Runtime. Core identity tests
  select Types as a development dependency. These are the same published Rust
  identities the facade previously re-exported, with unchanged public conversion
  impls and IC0 bodies. No wrapper or compatibility re-export is added.
- Select only `ic0` on Runtime. No executor, CDK, Candid, parser or native client
  is added. External Principal conversions remain explicit facade test features
  because self-authentication no longer enables them implicitly.
- Adopt published Memory/Storage 0.62.0, aligning public Memory and codec-error
  identities with Wire 0.14. Retained ledger, checkpoint and collection bytes,
  bounds, admission and recovery are unchanged; no reset is required. Consumers
  passing public Memory values or inspecting codec sources must align and
  rebuild. Both published implementation directories match 0.61.1 exactly.
  Platform 0.17 remains their stable-structures owner; no second runtime or
  canonical Types identity is introduced. Canic keeps its separate qualified
  stack; no storage migration or supplier override is introduced.
- Adopt registry Wire/Derive 0.14.0 with Metrics 0.25.0, aligning native report
  schema traits after the supplier fixes
  [Observability #120](https://github.com/dragginzgame/ic-observability/issues/120).
  Schema consumers require the matching Wire 0.14 identity. Arithmetic, numeric
  representations, encoded bytes, decoder limits and browser shapes are
  unchanged. The subsequent Memory/Storage adoption removes Wire/Derive 0.13.5
  entirely from the root lock, preserving the incoming Wire/Derive 0.14.1 patch
  selection. No consumer bridge or copied measurement type is added. Canic
  qualification keeps its independent stack.

### 🛠 Tooling

- Adopt registry `ic-host-tools` 0.77.0 for CLI response decoding and native
  canister-interface inspection. Its selected source modules are unchanged
  from 0.76.2; Platform-backed Agent/certificate/ledger features stay unselected.
  Foundation, Testkit, product and Canic selections remain unchanged by this
  host-only adoption; Wire/Metrics alignment is recorded separately above.
  No consumer adapter, runtime behavior or deployed canister dependency is added.
- Protect direct Types, Runtime and crypto-facade ownership with package
  allowlists across dependency aliases and normal/build/dev/target declarations.
  Extend the existing metadata fixture to cover those owners and all dependency
  roles. The resolved graph also refuses multiple Types or Runtime versions.
  Shared snapshot payloads and Canic's independent policy/lock remain unchanged.

### 🩹 Fixed

- Rotate the existing single optional cardinality page across journaled stores
  ([#81 — Cardinality rebuild starvation](https://github.com/dragginzgame/icydb/issues/81), partial).
  A busy first store can no longer monopolize every callback. The driver keeps
  one disposable last-served path per active registry, shared by aliases of the
  same TLS registry and isolated from other registries. Quiescence removes it.
  Every source proof, page limit and per-store restart rule remains unchanged.
  No durable field, public option, timer policy or alternate build route is added.
- This repairs cross-store starvation, not fold-driven restart liveness within
  one busy store. Whole-database optional construction can still remain active
  under sustained writes; that part of #81 remains open.

### 📚 Documentation

- Document the public composite-key and typed-write names emitted beside each
  entity and their ordinary Rust type namespace
  ([#180 — Generated name collisions](https://github.com/dragginzgame/icydb/issues/180)).
  Standard type/trait/macro shadowing repairs are already delivered in 0.292.1.
  Retire the remaining helper-relocation/customization proposal: preserving the
  public names and separating conflicting application DTOs avoids an API cut,
  renaming configuration or another generation route. Rust remains the duplicate
  item authority; no generator or runtime behavior changes.
- Correct Account schema guidance to select IC Wire's compatible `platform-types`
  integration rather than the removed Platform `wire-schema` feature. Producers
  must align canonical Types identities; database Account bytes stay unchanged.
