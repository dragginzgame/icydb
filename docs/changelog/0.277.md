# 0.277

## [0.277.1]

Use published Testkit 0.53's `advance_and_tick` for the shared fixture startup
driver, zero-time watchdog completion, and the schema/startup timer tests.
The existing two-, four- and twenty-four-tick batches, eight-round setup bound,
readiness predicates and cadence-backed retry policy remain IcyDB-owned.
Zero-duration completion sends ticks without a time operation. No dependency,
server selection, canister format or public runtime behavior changes.
This is consumer adoption for [Testkit #98](https://github.com/dragginzgame/ic-testkit/issues/98).

The Wasm-size job explicitly runs `install-ic-tools`/`ic-tools-check` beside its
common setup/check aggregates. The live Tier B lane also prepares and verifies
the declared IC bundle before preparing Testkit and running canister builds.
The former empty local-target overrides skipped `ic-wasm`, `icp` and `wasm-opt`
even though their directories were added to PATH. This repairs prerequisites
without changing pins, downloading during checks, provisioning an unnecessary
simulator in the reporting job or weakening tool admission.
Workflow policy refuses missing, misrouted, ignored or late IC preparation, and
its regression harness prints the actual policy refusal when a case mismatches.

### ⚠️ Breaking

- Cap each complete encoded secondary-index key at 512 bytes, including index
  identity, component framing and the primary-key suffix. The taxonomy owner
  supplies one budget to write/rebuild admission, raw framing, persisted decoding
  and query-bound construction. Oversized keys reject with typed diagnostics
  before mutation; values are neither truncated nor replaced by hashes.
  Keep four index fields and the 254-byte composite primary-key ceiling, subject
  to the complete-key budget. Query sentinels consume only remaining key space.
  Nullable components still omit their index entry without imposing this key
  budget on ordinary row text. Adjust oversized indexed values or index
  definitions before reimporting or rebuilding retained data.
  Retain backups and recovery/export access using the previous binary, then
  explicitly recreate index stores and regenerate outstanding continuations.
  Oversized persisted key frames fail closed; recreation remains explicit.
- Adopt the Toko Studios Source Available License — Verifiable ICP Burn 1.1
  from the [canonical Shared Tooling master](https://github.com/dragginzgame/shared-tooling/blob/4b0615c43eac50bcc32c089cd06d1e62092771e3/licenses/Dragginz-ICP-Burn-1.1.txt).
  Preserve IcyDB's original copyright notices and prior Apache-2.0/MIT grants;
  append the exact prior-material MIT notice and remove standalone Apache license
  files from the repository and publishable crates. Workspace members inherit
  the license file, including unpublished fixtures. Contributions require express
  rights-holder acceptance; existing grants and third-party terms are unaffected.
- Remove `IntBig` and `NatBig` from schema authoring, public inputs/outputs,
  runtime values, SQL binding, arithmetic, indexes, cursors, storage and catalogs.
  Use fixed-width signed integers through `Int128`, unsigned integers through
  `Nat128`, or `U256` as appropriate. The integer-only `max_bytes` authoring and
  SQL type modifier are removed.
- Compact the current scalar/value tag sequences. Schema proposals, accepted
  catalogs and snapshots, recursive value storage, index keys, value hashes,
  cursor payloads and durable mutation intents now use the new assignments.
  Preserve the previous binary and backups for required recovery/export, then
  explicitly retire or recreate affected databases before adopting this build.
  Discard outstanding cursors and regenerate serialized artifacts. No old-image
  reader or compatibility path remains, and no installation is reset by this change.

### 📊 Audit

Matched production `wasm-release` builds on Linux with Rust 1.99.0, SQL and
Candid exports enabled, and the pinned Binaryen 133 pipeline reduce raw final
deployable Wasm as follows:

| Maintained subject | Before bytes | After bytes | Saved bytes | Reduction |
| --- | ---: | ---: | ---: | ---: |
| Empty | 2,000,573 | 1,969,841 | 30,732 | 1.54% |
| One entity, typed query | 1,989,233 | 1,958,301 | 30,932 | 1.55% |
| One entity, SQL query | 3,375,281 | 3,323,756 | 51,525 | 1.53% |

The baseline uses release source `996498ad4` with the same dependency versions
as the changed tree; the only lockfile difference is core's removed dependency
edge. These subjects retain the same production actor and fixture source and
exported method names. This historical measurement covers the integer hard cut, including tag
compaction, before the subsequent library and generated-endpoint Candid removal.
All six artifacts pass the maintained artifact contract. Local artifacts,
digests, source evidence and comparison data are retained under
`target/wasm-bigint-comparison/`. IC cycles and instructions remain unmeasured;
these Linux builds do not qualify macOS.

The separate IC Wire trial compares the same dynamic-query actor before and
after replacing just its row-count endpoint transport. Raw deployable Wasm grows
from 2,898,575 to 2,900,105 bytes: **+1,530 bytes (+0.053%)**. Compiler-emitted
Wasm grows by 1,901 bytes. Both use matching production `wasm-release` settings,
Rust 1.99.0, existing dependency versions and the pinned Binaryen 133 pipeline.
Candid remains linked for the other endpoints, so this is a mixed-codec trial,
not a measurement of complete Candid removal.

Fourteen focused tests pass, including exact vectors, admission before query
execution, artifact declarations and installed request/reply plus same-contract
upgrade behavior. The installed trial rejects 15 invalid requests. Native and
Wasm lint and dependency pin/inheritance checks pass. Testkit owns the temporary
PocketIC server lifecycle. Local evidence is under `target/ic-wire-trial/`;
IC cycle/instruction changes, full workspace/release gates and macOS remain
unqualified.

The codec-only follow-up removes Candid completely from the Wire actor's Wasm
dependency graph. Two evidence actors share the same finite key/count handler
and raw IC adapter, with neither actor depending on CDK or IcyDB. Canonical
`wasm-release` and Binaryen 133 builds produce **240,951 raw bytes for Candid**
and **19,857 for Wire**, saving **221,094 bytes (91.76%)**. This isolates codec
footprint and does not establish a whole-database saving.

Two native codec tests and one installed comparison pass. Four key/count cases
agree, including duplicates, a missing key and the maximum `u64`; 33 malformed or
wrong-codec requests reject, and both actors still answer correctly afterward.
Native/Wasm lint and dependency checks pass. Artifacts, exact vectors, dependency
graphs and provenance are retained under `target/codec-only-comparison/`.
Cycle/instruction deltas and macOS qualification remain unmeasured.

The subsequent removal of IcyDB-owned Candid contracts has no matched before/after
Wasm measurement yet. The earlier endpoint trial and codec-only percentages do
not quantify this complete database change. IC cycles and instructions for the
complete change remain unmeasured.

### Host integration prerequisites

Rust contracts use registry IC Wire 0.3. The browser generator alone selects the
immutable shared runtime contribution from [Wire #1](https://github.com/dragginzgame/ic-wire/pull/1)
until that native metadata support is published. It does not add another codec
or change the library/canister Wire dependency.

Adopt registry Host 0.25.1, including the compatible error dependency floor
contributed in [Host #177](https://github.com/dragginzgame/ic-host-tooling/pull/177).
The build harness passes expected tool versions separately and consumes Build
0.13's structured batch entry results, retaining partial failure details.
Memory 0.47 bindings and committed generation are borrowed from the runtime;
IcyDB projects allocation labels and pool eligibility from that same host context.
Numeric reports no longer support context-free conversion into labeled reports.
Stored bytes and the IcyDB diagnostic response shape are unchanged.
Use Testkit 0.51's explicit install and retry inputs in integration fixtures;
native lifecycle calls carry empty application bytes.
Read-only startup observation restores journal handle bindings after upgrade,
preserving exact metrics before a recovery page without acquiring another lease.
