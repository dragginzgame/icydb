# IcyDB 0.247 — Measured Wasm Footprint Reduction

## 0.247.1

### 🩹 Fixed

- Removed the accidental `canic-cli` dependency from IcyDB's optimizer
  bootstrap. Local setup and CI now download the official Binaryen 132 Linux
  archive directly, verify both the archive and executable checksums, and
  invoke `wasm-opt` without a framework or IC toolchain dependency.
- Tightened post-link invariants so the canonical installer remains shared by
  workstation, CI and SQL-performance setup while the installer and verifier
  reject any Canic bootstrap dependency.
- `make update-dev` now replaces any non-matching local optimizer with the
  repository pin and checks GitHub's latest official Binaryen release. It
  reports whether the pin is current and warns without blocking the rest of
  the workstation update when the latest-release lookup is unavailable.

### 🔧 Changed

- Hard-cut the maintained post-link contract from Binaryen 108 to 132 while
  retaining the existing `-Oz`, IC feature and bounded one-caller-inlining
  flags. The current pipeline identity is version 1; no predecessor optimizer
  or dual dispatch remains.

| Canister | Binaryen 108 raw | Binaryen 132 raw | Raw delta | Gzip delta |
| --- | ---: | ---: | ---: | ---: |
| `default_empty` | 1,742,169 | 1,736,836 | -5,333 | +530 |
| `one_entity_typed_query` | 1,904,445 | 1,897,977 | -6,468 | +433 |
| `sql_perf` | 1,933,548 | 1,927,541 | -6,007 | +559 |

The paired outputs use identical compiler-emitted inputs and preserve exact
Candid. Raw non-gzipped Wasm remains authoritative; the small deterministic
gzip increases are secondary context.

## 0.247.0

### 🔧 Changed

- Replaced compact sort's per-type heap traversal with one safe internal
  position-sort kernel. In an exact `v0.246.1` Toko Miner A/B, release code fell
  by 10,128 bytes before Binaryen and 8,908 bytes afterward; raw bytes fell by
  10,360 and 9,142. Public Candid stayed byte-identical.
- The frozen `sift_down` family moved from 43 instances and 11,705 approximate
  bloat bytes to one 275-byte concrete body with no monomorphisation bloat.
  Exact query controls improved by 0.09–0.31%; startup was effectively flat;
  recovery samples stayed between a 0.28% improvement and a 0.26% increase.
- Moved all six structural row-read strategies behind one private concrete scan
  driver selected through stack-borrowed callbacks. The old retained driver,
  row-read and borrowed-primary generic families move from `4/6/3` instances to
  one non-generic source body each, while the primary-map visitor continues to
  borrow row storage directly.
- Against the accepted compact-sort candidate, the retained-scan convergence
  removes another 16,944 release code bytes before Binaryen and 16,251 after
  it; raw bytes fall by 16,786 and 16,101. The three 2,048-row query controls
  add only 0.10–0.13%, startup stays effectively flat, and the two 64-batch
  recovery controls add about 0.057% while retaining exact results, physical
  work, 64 callbacks and 145 ns of simulated time.
- Ordered-map construction now inserts directly into its canonical `BTreeMap`
  owner for accepted record traversal, mutation-preflight index overlays and
  migration-abort store identities. The first two hard cuts remove 19 frozen
  stable-sort members totalling 8,930 shallow bytes; the third is Wasm-neutral
  and removes two source lines.
- Against the accepted retained-scan candidate, canonical map construction
  removes another 9,002 release code bytes before optimization and 8,935 after
  the checksum-pinned official Binaryen 108 pass. Raw bytes fall by 9,021 and
  8,953, 19 compiler functions and 18 final functions disappear, all 35 exports
  remain, and public Candid stays byte-identical.
- The three exact query controls add 0.18–0.26%, startup observation is flat to
  30 instructions lower, and populated-history plus 64-batch recovery add
  0.0015–0.0305%. Results, physical visits, stable-memory assertions, callback
  counts and simulated convergence time remain unchanged.
- Hard-cut the distro-specific Binaryen installation and admission path. Local
  setup, CI and fixture-canister validation now share Canic's checksum-pinned
  official Binaryen 108 executable; the optimizer flags and post-link pipeline
  identity are unchanged.

### 📊 Audit

- Froze Toko Miner's IcyDB `0.246.0` release App as the read-only downstream
  baseline: 6,157,093 raw bytes, a 5,619,140-byte code section and 12,240
  functions before final optimisation. The equivalent Binaryen 108 `-Oz`
  result is 5,823,004 raw bytes with a 5,290,184-byte code section and 10,887
  functions, preserving all 34 exports and exact public Candid metadata.
- Reproduced the requested compact-sort, retained-scan and query-fingerprint
  monomorphisation counts. IcyDB-named Rust sort members occupy 101,064 shallow
  bytes, while 726 IcyDB-related drop-glue instances occupy 46,824 bytes.
- Established seven bounded landing patches and paired source-size decisions
  with query, startup/recovery, Candid, schema, ordering and persistence gates.
  Toko Miner remains read-only, Canic remains final-artifact authority, and the
  baseline patch changes no runtime code or public surface.
- Replayed the exact `v0.246.1` predecessor and current candidate through the
  same official Binaryen 108 command. Across the first four patches, release
  input moves from 6,205,962 raw and 5,663,195 code bytes to 6,169,795 raw and
  5,627,121 code bytes; final output moves from 5,848,828 raw and 5,310,238 code
  bytes to 5,814,644 raw and 5,276,166 code bytes.
- Audited all five named cold-outlining roots and retained no new helper. One
  startup candidate was byte-identical, a second added 12 compiler code bytes,
  and a third hit a Rust 1.97.1 LTO missing-rlib failure and was removed without
  affecting production. The large roots remain canonical shared owners of hot
  work, so cumulative 0.247 Wasm savings are unchanged.
- Built and removed a canonical pre-lowered initial-schema candidate. It cut
  22,338 compiler and 16,718 final code bytes, but embedded accepted bundles
  added about 33 KiB of data, growing compiler raw Wasm by 10,969 bytes and the
  final deployable artifact by 16,334 bytes. Exact Candid and all 35 exports
  stayed unchanged; the failed raw-size gate leaves no production or format
  change.
- Closed the line with a same-source Canic 0.109.19 qualification against exact
  `v0.246.1`: the retained candidate removes 33,213 compiler raw bytes and
  32,349 final raw bytes, while code falls by 34,925 and 34,023 bytes. All 35
  exports and the 66,136-byte public Candid interface remain exact.
- Requalified the previously failing maintained-canister artifact contract:
  all 32 local/production compiler artifacts and both 16-entry post-link
  batches pass their frozen endpoint policies. The focused Toko Miner App suite
  also passes 21 tests; repository-wide IcyDB and Toko Miner CI remain
  user-owned release validation.
