# 0.231 Explicit Nullable Unique-Index Contracts

## 0.231.1 - 2026-08-19

### 🔧 Changed

- Whole-fleet canister validation moves to `ic-testkit 0.8.9` and prepares all
  LocalTest and Production build inputs once under an explicit caller-held
  source write-exclusion guard. Both concurrent readers consume that fixed
  declaration set; undeclared specifications and detected mutation fail
  instead of falling back to independent resolution.
- Ordinary single-canister, single-profile, and local deployment builds retain
  their independently validated paths. No production crate, deployed Wasm,
  Candid surface, persisted format, or runtime behavior changes.

### 🧪 Testing

- The maintained two-profile artifact contract now exercises the guarded
  prepared-reader flow over all 32 exact canister specifications, while the
  repository invariant keeps snapshot preparation and consumption wired to
  the canonical collect-all pipeline.
- Independent closeout coverage now exercises maximum-size repeated and mixed
  nullable sources, active and candidate SQL classifications, promotion
  revalidation with unchanged residue, physical omission/key equivalence,
  exact filtered and unfiltered constraint projection, and equality/range
  indexed-versus-forced-scan result parity.
- Diagnostics-only real-canister probes now pair SQL DDL admission, accepted
  schema reopen at 1, 8, and 64 indexes, exact stable-byte identity, and an
  unchanged accepted unique write against the exact 0.230.3 predecessor. They
  are absent from production Candid and exports.

### 📊 Audit

- Against the immediately preceding warm `ic-testkit 0.8.8` run, the guarded
  `0.8.9` flow reduces cumulative input resolution from 5.81 seconds to 3.96
  seconds and total contract time from 11.18 seconds to 10.73 seconds. All 32
  Cargo and 32 post-link acquisitions reuse their warm artifacts, with 13
  prepared resolution runs, 19 preparation reuses, and 32 reader reuses.
- The first prepared-flow pass populated new exact Cargo entries for 30 of 32
  specifications while reusing every post-link result. Final Wasm bytes remain
  unchanged; the local `default_empty` artifact stays 3,633,101 raw bytes.
- Reopen reads increase by only 0.04%, 0.07%, and 0.16% at 1, 8, and 64
  indexes. Changed DDL admission adds 0.60% to 2.34%, while the unchanged
  accepted unique write falls from 3,821,324 to 3,743,162 instructions. An
  identical accepted schema and physical index domain retain the exact same
  511,770,624 stable bytes and fingerprint.
- The exact released `sql_perf` artifact is 5,008,089 compiler-emitted and
  4,374,594 final raw Wasm bytes, correcting the earlier dirty pre-release
  candidate table. It is 9,736 raw bytes above v0.230.3; Candid remains 60,456
  bytes and the production surface remains 70 exports.

## 0.231.0 - 2026-08-18

### 📝 Summary

- Accepted schema no longer permits a unique index to omit nullable key values
  without explicitly declaring that partial membership through matching
  `IS NOT NULL` guards.
- Generated proposals, SQL DDL, candidates, promotion, nullability changes,
  rename, reconciliation, codec ingress, and reopen now consume one canonical
  accepted-schema decision rather than maintaining frontend-specific rules.
- Queries can use a compliant filtered unique index when the complete query
  proves its guards; unavailable or unsupported proof retains the conservative
  route.

### 🔧 Changed

- One bounded schema-level omission derivation classifies direct, nested, and
  expression key sources without inspecting rows. Exact top-level non-null
  guards are required for every omit-capable unique-key source; duplicate
  guards canonicalize and incomplete, malformed, or unsupported shapes reject.
- Accepted unique constraints now identify their backing index and expose its
  exact optional predicate. Unfiltered constraints report `unique_index_v1`;
  filtered constraints report `partial_unique_index_v1`, so partial uniqueness
  is not presented as an unconditional table constraint.
- Candidate creation and promotion revalidate the complete final accepted
  revision. Root-field rename rewrites and rebinds predicate identity, while
  nested-member rename rebuilds key-source identity against the final schema;
  failed rewrite or stale references reject instead of retaining predecessor
  text.
- Field nullability changes update active and candidate index-source metadata
  before final validation, preventing stale source facts from bypassing or
  pre-empting the nullable-unique decision.
- The existing filtered-index implication owner now proves exact matching
  `IS NOT NULL` clauses and supported equality or ordered comparisons against
  concrete non-null values. Every composite guard and additional filter
  conjunct remains required; `OR`, `NOT`, null or unknown values, cross-field
  comparisons, and expression-to-source inference stay conservative.
- Physical null omission, uniqueness probes, index encoding, version-1 schema
  representation, cardinality semantics, stable-memory allocations, and
  scheduling remain unchanged. No uniqueness mode, persisted proof, repair
  path, compatibility decoder, or second planner route was added.
- Local deployment environments build only maintained audit and demo canisters;
  static inventory validation rejects stale targets before deployment.
- Canister validation reports independent Cargo and post-link failures together
  with stable labels, partial phase timings, and aggregate cache metrics. Local
  ICP builds trace cache reuse and avoid host-only workspace invalidation under
  ic-testkit 0.8.8. Its source-immutability session constructor now names the
  caller's proof obligation explicitly; IcyDB does not opt into that session
  without a genuine source write-exclusion guard.

### 🥾 Governance

- Changelog authoring no longer stages work under `Unreleased`. Each slice
  updates the latest active version and its shared minor-line notes directly.
  After that version gains its release tag or is reported published, agents
  open the next patch in the explicitly authorized minor line instead of
  rewriting published history or asking for a routine patch number.

### 🧪 Testing

- Ninety-three focused tests cover accepted and candidate integrity, generated
  and SQL admission, nullability, rename and final-revision binding, constraint
  projection, codec reopen, conservative planner cases, residual stripping,
  and production-shaped real-canister routing.
- The real-canister route probe validates a guarded nullable unique index,
  confirms its proven `IndexPrefix` route matches pre-index and equivalent
  full-scan output, and confirms `IS NULL` and unsupported `OR` proofs cannot
  select that filtered index.
- Exact Candid-size and public ABI goldens include the accepted constraint
  predicate, while candidate logical-fill collision coverage now enters
  staging through a valid explicitly guarded nullable unique index.
- Warning-denied Clippy, formatting, diff hygiene, and the repository invariant
  scripts pass. Full repository/workspace suites remain user-owned validation.

### 📊 Audit

- Against an equal-result conservative full scan on the same accepted schema,
  the proven index route uses one data get instead of three and completes in
  8,271,327 instructions versus 8,486,517, a 2.54% reduction. Accepted filtered
  predicate compilation dominates both totals; the maximum remains far below
  the maintained 40-billion-message ceiling.
- The final production `sql_perf` artifact is 5,007,617 compiler-emitted Wasm
  bytes and 4,373,952 final raw Wasm bytes, increases of 10,514 and 9,117 bytes
  from 0.230.3. Deterministic gzip is 1,695,921 bytes; raw Wasm remains the
  authoritative measure.
- Candid is 60,456 bytes with SHA-256
  `6caca71287d87c900ff750e6a2f5aa3ec40e0e88f6c575c935706dd02df6208c`.
  The intentional 28-byte change exposes the optional accepted constraint
  predicate. The artifact retains 70 exports: 27 query, 39 update, and the
  unchanged four lifecycle/support exports.
- No persisted field, stable-memory allocation, or steady-state stable byte was
  added.

### 🧭 Migration Notes

- This is a pre-1.0 hard cut. A current version-1 accepted or candidate snapshot
  containing a nullable unique key without every required explicit non-null
  guard is now incompatible and must be reinstalled or recreated.
- Structural corruption and predicate parse/bind corruption retain their
  existing classifications. No predecessor decoder, translation, migration,
  repair endpoint, or fallback path is provided.
