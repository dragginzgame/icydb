# 0.228 Fingerprint-Bound Journal Validation And Convergence Bounds

## 0.228.3 - 2026-08-16

### 📝 Summary

- The final code-first closeout confirms that fingerprint-bound complete-batch
  recovery is synchronous, cursor-free, bounded, and rollback-safe on the IC.
- Real-canister evidence proves that a trap after complete recovery rolls the
  replicated message back and that the canonical watchdog retries the same
  current-format batch to exact rows and indexes.
- Retained predecessor journal envelopes fail closed with the documented typed
  format error, while explicit reinstall recreates an empty current-format
  database.

### 🧪 Testing

- A generated helper available only with `test-admin-api` lets the local audit
  canister invoke the canonical startup driver inside an ordinary request
  boundary. The helper and its trap probe are absent from production builds.
- A maintained 2,048-row fixture with three derived indexes traps only after
  complete recovery, preserves the pre-message stable-memory length and digest,
  remains typed pending, and then completes through one canonical watchdog work
  sample. Final queries prove 2,048 rows, 512 range matches, 21 exact-name
  matches, and one primary plus three derived indexes.
- A current canister carrying predecessor-version journal envelopes returns
  `RUNTIME_INCOMPATIBLE_PERSISTED_FORMAT`; explicit reinstall then reaches
  `Ready` with an empty journaled store.
- Core regressions freeze the exact fingerprint preimage, 16-MiB envelope
  boundary, marker-owned header identity, 16,384-unit identity boundary, and
  stale startup-receipt behavior when journal authority changes.
- Production/local artifact checks prove that the local-only audit methods are
  declared consistently and remain excluded from production.

### 📊 Audit

- The maximum accepted-index fixture recovers in one 21,021,486,862-instruction
  message, leaving 18,978,513,138 instructions of headroom. The maintained
  2,048-row/three-index fixture also completes in one 22,052,962,438-instruction
  message, leaving 17,947,037,562 instructions of headroom.
- The maintained 4,096-row zero-index and 240-row maximum-fanout fixtures
  recover in 16,262,805,149 and 15,544,885,836 instructions. The 241-row shape
  remains rejected before target or marker publication at 16,388 work units.
- The production SQL audit artifact is 4,174,858 raw Wasm bytes and 1,607,768
  deterministic-gzip bytes. It retains the 60,428-byte Candid declaration and
  70 exports; against the 0.228.2 measurement this is +163 raw bytes, -3,933
  gzip bytes, and no Candid or export-count change.
- The closeout found no runtime correctness defect. It adds no production
  endpoint, timer, scheduler, stable-memory ID, mode, configuration option,
  compatibility path, or persisted state axis.

### 🧭 Migration Notes

- Moving from 0.228.2 to 0.228.3 requires no new persistence migration. The
  predecessor journal format remains unsupported; canisters retaining it must
  still be reinstalled or recreated rather than upgraded in place.
- Public IcyDB Candid methods, result shapes, method modes, and generated
  production exports are unchanged.

## 0.228.2 - 2026-08-16

### 📝 Summary

- Journal recovery now authenticates each complete immutable batch before
  applying it, preventing late corruption from following earlier canonical
  writes.
- A complete validated batch is applied, watermarked, and retired in one
  replicated message, leaving only before-message and after-success durable
  states.
- The fold cursor and its startup-receipt binding are removed without adding a
  replacement progress state, scheduler, or execution route.

### 🔧 Changed

- Journal batches use a version-2 envelope with an 85-byte fixed header and a
  domain-separated SHA-256 fingerprint over the canonical envelope outside the
  fingerprint slot. Stable-tail inspection still bounds allocation from the
  header before assembling the remaining physical chunks.
- Complete read-only validation now proves row, index, schema, identity,
  validation-job, migration, backend, encoding, and terminal-watermark work
  before the first canonical mutation. A contradiction during the later
  mechanical apply traps so whole-message rollback preserves the prior state.
- Recovery pages stop only between complete batches. Startup failure receipts
  use version 2 and bind the exact journal proof without record-level cursor
  state.
- Sequence-zero journal controls accept only the current watermark, data
  revision, and access revision records. Removed or unknown control shapes fail
  closed.
- Normal live apply reuses the exact fingerprinted journal envelope already
  encoded and persisted in the commit marker, avoiding a second SHA-256 pass
  while recovery continues to verify bytes loaded from stable memory.
- The reviewed 64-update Forward ceiling is 31 million instructions for the
  version-2 fingerprinted envelope. The complete collection-scale fixture
  peaks at 30,422,168 instructions for tier updates and 28,820,367 for scoring
  updates.

### 🗑️ Removed

- `FoldRecordCursor`, its stable control record, record-level recovery branch,
  startup observation, and optional receipt field are deleted completely.

### 🧹 Cleanup

- Historical-tag cleanup treats a minor cutoff as the complete minor line and
  verifies remote deletion before removing the corresponding local tags.
- Repository fixtures, diagnostics, and documentation now use framework-neutral
  collection/reference-workload language rather than a downstream product name.

### 📊 Audit

- Focused journal, startup, paging, late-corruption, schema, and identity
  validation passes, together with warning-denied core and integration lint.
- The maximum accepted-index fixture publishes and recovers 65,536 records in
  exactly one 21,021,486,537-instruction recovery callback, leaving
  18,978,513,463 instructions of headroom below the IC's 40-billion message
  limit.
- The production SQL audit artifact is 4,174,695 raw Wasm bytes, a 4,291-byte
  increase over the immediate promotion-evidence baseline. It retains 70
  exports. Renaming only its private audit endpoints moves the fixture Candid
  from 60,348 to 60,428 bytes; the generated IcyDB surface is unchanged.
- The implementation changes about 490 inserted and 450 removed Rust lines.
  It removes one persisted state axis and adds no mode, memory ID, endpoint,
  timer, configuration option, or duplicate recovery flow.
- The post-candidate live-append and terminology correction changes about 243
  inserted and 69 removed Rust lines across 17 source/test files. Exact marker
  byte-range plumbing is modestly more code, but it removes a duplicate encode
  and fingerprint pass without adding durable state.

### ⚠️ Breaking

- Journal batches and startup failure receipts written by the predecessor
  format are not decoded. This is an intentional pre-1.0 hard cut with no
  compatibility decoder, upgrader, repair bridge, or dual-format interval.

### 🧭 Migration Notes

- Reinstall or recreate every existing 0.228.1 canister database when moving
  to 0.228.2. In-place upgrade from predecessor persisted state is unsupported.
- Public IcyDB Candid methods, result shapes, method modes, generated exports,
  and stable-memory allocation IDs are unchanged. Repository-private audit
  endpoint names are framework-neutral in this release.

## 0.228.1 - 2026-08-15

### 📝 Summary

- Current-form journal reads now fail closed earlier on malformed batch
  envelopes and impossible record-family shapes.
- This patch keeps the existing journal format, fold cursor, stable-memory
  layout, public Candid surface, generated exports, timers, and recovery
  execution routes unchanged.
- Fingerprint-bearing envelopes, cursor replacement, and convergence changes
  remain blocked on the 0.228 promotion evidence recorded in the status doc.

### 🔧 Changed

- Journal batch decoding now inspects the current fixed header through batch
  ID, marker ID, sequence, and record count before decoding records. The
  stable-tail read path uses the same current-envelope facts to reserve only
  the exact declared length and reject impossible lengths, count drift,
  sequence drift, missing tail bytes, or trailing persisted chunks.
- Append repair keeps a separate prefix-tolerant comparison path, so an
  interrupted multi-chunk append can still complete by republishing the same
  full batch.
- Batch-shape validation rejects same-batch duplicate ordinary row targets,
  duplicate migration row/index targets, mixed migration plan digests,
  multiple constraint-validation job transitions, and accepted-schema index
  chunks whose store path differs from the leading accepted-schema
  publication.
- Accepted-schema publication batches now fail closed unless the publication
  is ordinal zero, unique, and followed only by the schema-owned suffix records
  maintained producers can emit.
- Workspace dependencies now accept `ic-timers 0.6.1` and compatible 0.6.x
  releases, keeping generated recovery and application timers on the current
  shared timer facade without adding compatibility fallback paths.

### 📊 Audit

- Focused journal validation covers the new fixed-header inspection,
  stable-tail malformed-read rejection, duplicate-target rejection,
  validation-job singleton rejection, accepted-schema publication-family
  rejection, and accepted-index store-path binding.
- The maintained core journal module passes with 57 tests, and
  `cargo check -p icydb-core` passes.
- The dirty-tree footprint for the prepared slice is about 806 insertions and
  40 deletions across journal codec/store/tests, release notes, status notes,
  and the timer dependency update.
- No production Wasm or performance measurement was rerun for this patch; the
  release carries no new raw Wasm attribution beyond the existing 0.228
  evidence.

### 🧭 Migration Notes

- No public Candid method, result shape, exported method mode, database
  persisted format, stable-memory allocation, journal format version, cursor
  encoding, or recovery route changes in 0.228.1.
- Downstream lockfiles may resolve `ic-timers` 0.6.x. Before 1.0, no
  compatibility facade for retired timer APIs is retained.

## 0.228.0 - 2026-08-15

### 📝 Summary

- Structural mutation admission now reflects the work the IC must actually
  perform, rather than treating row count and encoded bytes as sufficient
  proxies for derived index and recovery cost.
- Recovery wake-up ownership is captured before durable marker publication, so
  missing generated lifecycle wiring fails closed instead of creating recovery
  work that no timer can advance.
- This first 0.228 release does not change the journal envelope, fold cursor,
  persisted format, or convergence state machine. Fingerprint-bound validation
  remains later work in the 0.228 design line.

### 🔧 Changed

- Canonical structural preparation incrementally enforces one fixed work
  equation over exact prepared effects:

```text
4 × rows + index mutations + 4 × identity ranges + 4 × progress successor
    <= 16,384
```

- The bound counts actual prepared index-store mutations, including
  counter-neutral candidate-index and reverse-index work. It rejects as soon
  as the first prepared row crosses the limit, before commit payload, marker,
  journal, target-row, identity, or progress publication.
- Cheap zero-index batches retain the existing 4,096-row maximum. A batch that
  inserts into all 64 supported secondary indexes admits at most 240 rows; a
  replacement that removes and inserts all 64 keys admits at most 124 rows.
  Generated-identity batches admit 4,095 rows plus their one range advance.
- IcyDB hard-cuts from exact `ic-timers 0.3.8` to exact `0.5.0` and uses its
  policy-specific watchdog callback context. The generated startup watchdog
  remains the only recovery timer and execution owner.
- Commit windows capture the generated recovery wake-up before publishing
  durable marker authority. Every normally returned post-marker failure uses
  that captured function to retain future progress; traps still rely on IC
  whole-message rollback.

### ➕ Added

- E283,
  `RUNTIME_BOUNDARY_MUTATION_BATCH_COMMIT_WORK_EXCEEDED`, reports the exact
  attempted work-unit count and fixed limit. Checked-arithmetic overflow uses
  the same typed boundary with the limit fact and no fabricated count.
- Closed audit fixtures now exercise the last admitted and first rejected
  maximum-fanout shapes through maintained structural admission and the real
  generated startup watchdog.

### 🧹 Cleanup

- Obsolete startup-watchdog audit endpoints and generated scheduling-
  observation scaffolding are removed. Maintained evidence reads canonical
  `ic-timers` scheduler/work observations without adding a private recovery
  driver or second execution path.
- The 10,001-row streaming setup is repartitioned into admitted internal
  batches without changing its final rows or traversal contract.

### 📊 Audit

- The first rejected maximum-fanout shape is 241 rows with 64 secondary-index
  mutations per row: it reaches 16,388 units, returns E283 against the 16,384-
  unit limit, leaves zero target rows, and leaves startup `Ready`.
- The 240-row maximum-fanout boundary produces in 4,365,734,067 instructions
  and recovers in one 12,898,311,935-instruction watchdog work message.
- The preserved 4,096-row zero-index boundary recovers in 16,447,781,109
  instructions. Under complete-batch recovery, the preserved 2,048-row three-
  index shape now finishes in one 22,052,962,063-instruction work message,
  below the IC's 40-billion replicated-message limit.
- The current production SQL audit artifact is 4,166,588 raw Wasm bytes and
  1,607,086 deterministic gzip bytes. Its 60,348-byte Candid is byte-identical
  to the prior artifact and retains 70 exports. The small total Wasm delta also
  includes the timer, schema, and preceding investigation changes in the dirty
  candidate, so it is not attributed solely to the admission gate.
- The implementation adds one checked scalar accumulator and no persisted
  bytes, stable-memory ID, mode, caller setting, cursor, scheduler, timer,
  executor, or alternate commit route.
- The shared SQL audit canister's widened accepted schema raises the complete
  warmed `LIMIT 1` endpoint envelope to at most 1,100,000 instructions. The
  query-owned attributed ceiling remains 1,000,000, and accepted-schema
  observation remains an explicit future optimization rather than 0.228
  integrity scope.
- The same audit-only schema growth recalibrates the complete two-child sparse-
  intersection attribution ceiling to 2,100,000 instructions while preserving
  its exact 41-index-entry, one-row-fetch structural gate and every other
  streaming-operator ceiling.

### ⚠️ Breaking

- Downstream exhaustive matches over public diagnostic codes must handle E283.
- A formerly accepted high-fanout structural batch may now return E283 even
  when it remains below the independent 4,096-operation and 16-MiB staged-byte
  limits. Applications should submit smaller fixed batches; the limit is not
  caller-configurable.
- Downstream lockfiles must resolve exact `ic-timers 0.5.0`. No compatibility
  facade for the retired timer API is retained before 1.0.

### 🧭 Migration Notes

- No public Candid method, result shape, exported method mode, database
  persisted format, or stable-memory allocation changes in 0.228.0.
- Applications already using bounded batches need no code change. Clients that
  construct large indexed batches should treat E283 as a deterministic request
  partitioning boundary and retry using smaller application-owned batches.
