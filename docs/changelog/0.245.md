# IcyDB 0.245 Detailed Changelog

## 0.245.1

### 📝 Summary

- Trusted compiled SQL now creates one canonical AST per ingress attempt. The
  same statement supplies its entity-routing fact and cache-miss semantic
  compilation instead of parsing the text twice.
- Accepted-catalogue selection, fingerprint-bound compiled-command caching and
  immutable execution contexts remain the only authority chain. Cache hits
  still parse once before catalogue selection; there is no AST cache, new
  execution route or runtime mode.
- Generated query endpoints now pass that same opaque parsed dispatch through
  their existing introspection gate into compiled-query ingress. Authorization,
  malformed SQL and forbidden introspection still resolve before database
  acquisition.
- The dispatch now borrows the exact SQL text that produced its AST. Generated
  and facade execution seams accept only that sealed artifact, so one query's
  parsed syntax cannot be cached under another query's text.

### 🔧 Structure

- The existing compiled query and mutation cache shell receives an already
  parsed statement. Entity routing borrows from that statement before the
  pinned session selects accepted catalogue authority.
- The attributed query facade now receives response entity identity from the
  same core compile result, removing its former extra full parse.
- Compile-phase attribution includes the sole routing parse from its
  parser-owned phase measurements. Warm cache hits therefore report their real
  parser cost instead of showing a zero parse bucket while doing unreported
  work.
- Parser-owned subphases now supply their exhaustive parse total directly, and
  the parsed statement is borrowed through the generated facade rather than
  copied or parsed again.
- The generated boundary no longer exposes an unused entity observer or a
  full-AST debug formatter.

## 0.245.0

### 📝 Summary

- Generated schema installation, exact replay and same-Wasm recovery now carry
  their existing no-removal guarantee into core lowering. Minimum generated
  actors no longer retain explicit-removal resolution and mutation code that
  generated proposals cannot request.
- Fragment decoding, canonical proposal composition, accepted-head proof,
  capacity checks, receipts and atomic publication remain one shared authority.
  Explicit public proposals retain the complete removal path.

### 🔧 Structure

- One compile-time generated application contract selects a no-removal
  existing-head lowerer. It is not a runtime mode and adds no cache, persisted
  state, mutable owner, invalidation edge or schema authority.
- Existing-store candidate completion is shared after optional removal
  preparation, so generated and general proposals still use the same entity,
  type, index, relation and constraint lowering and the same publication flow.
- Generated ingress fails closed if a non-empty removal set reaches the core
  boundary. The general proposal entry remains the sole owner of explicit
  removal behavior.
