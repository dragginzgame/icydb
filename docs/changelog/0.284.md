# 0.284

## [0.284.0]

### Breaking

- Interpret Blob defaults as bounded hex, consistently with migration fills.
  Hex-encode older raw-text defaults to preserve their intended bytes; existing
  rows and runtime Blob encodings are unchanged
  ([#186 — Align Blob default and migration literals](https://github.com/dragginzgame/icydb/issues/186)).
  Reuse the scalar Subaccount parser for migration fills while retaining their
  exact unprefixed width; reject signed hex pairs in the scalar parser too.

- Keep quoted macro defaults and arguments literal, including `"::1"`. Replace
  quoted function/constant arguments with bare Rust paths such as `String::new`;
  dedicated `path` and `generated` fields are unchanged
  ([#184 — Keep quoted arguments literal](https://github.com/dragginzgame/icydb/issues/184)).

- `ConstraintValidationFindingOutput.primary_key`, `IntegrityFinding.physical_key`
  and optional `primary_key`, `SchemaMigrationFinding.primary_key`, optional
  `SchemaMigrationStatusPage.next_cursor` and `SchemaMigrationStatusRequest.cursor`
  use `serde_bytes`. Rust field/accessor types and serialized payload bytes stay
  unchanged. Regenerate browser clients and supply `Uint8Array` values, including
  inside optional values; old numeric-array inputs are no longer supported.
- Byte fields count as buffers rather than per-byte sequence traversal. Existing
  byte, allocation and application length limits remain in force. No persisted
  database format migration is required; diagnostic field IDs remain varints.
- Browser map entries now use two-element tuples matching native Rust pairs,
  replacing reflection's homogeneous fixed-array description. Valid frame bytes
  and traversal charges stay unchanged. TypeScript enforces the pair length;
  invalid-length entries produce `WireError('value')` instead of `limit`.

### 🔧 Changed

- Distinguish grouped query limits from hard execution-budget exhaustion with
  a typed `grouped_limit` diagnostic fact; preserve E252 and execution context
  ([#148 — Distinguish grouped limit failures](https://github.com/dragginzgame/icydb/issues/148)).

- [#447 — Remove duplicate commit-key decoding](https://github.com/dragginzgame/icydb/issues/447):
  canonical preparation checks the raw entity prefix and retains its single decoded
  key for row/index planning. Remove the scheduler's discarded decode and copy.
  Malformed keys and wrong entity tags retain executor-invariant diagnostics and
  precedence over envelope admission. Persisted replay keeps its corruption
  classification; row bytes, commit semantics and public contracts are unchanged.

- Adopt the coordinated published dependency graph: Host/Build/Testkit 0.68.2,
  Memory/Storage 0.51.1, Metrics 0.16.2, Platform 0.6.16 and Timers 0.31.1,
  alongside Wire/derive 0.7.9. Keep the existing feature selections and Canic pin.
  These dependency updates require no IcyDB API adaptation or persisted-format
  migration; retain endpoint codecs, scalar validation and lifecycle ownership.

- [#446](https://github.com/dragginzgame/icydb/issues/446): previous-row-returning
  store operations move live predecessor payloads out of their map entries.
  Stable predecessors are read only when visible and not overridden; tombstones,
  heap behavior and cardinality remain unchanged. Raw corruption fixtures reuse
  the same insertion owner. Normal journaled commits already use presence-only
  positioned publication and do not request predecessor payloads.
  Recovered journal puts now return success only and use presence for cardinality;
  migration/replay callers no longer materialize a predecessor only to discard it.

- Adopt published IC Wire 0.7.9 and its matching derive: generated browsers use
  incremental output buffers, and endpoint budgets use Wire's validated typed
  projection. Preserve current contract layouts, byte ceilings and admission policy.
  Optional-byte and symmetric Serde-rename metadata fixes remove the reproduced
  derive blockers. DTOs now derive native-only Wire metadata; handwritten scalar
  serializers provide explicit metadata at their owner. The generator retains
  public browser names and delegates recursive layout collection to Wire, deleting
  its general reflection-to-metadata translator and central scalar patching.
  Serde reflection remains only for independent sample/vector generation.
  Remove the discarded nested-enum tracing and reflection-registry completeness
  check; Wire now owns metadata completeness, with the native vector corpus intact.

- Gate browser contracts against a reviewed endpoint-layout baseline and extend
  installed checks to byte-buffer cursor refusal and retained constraint-finding
  keys ([#194](https://github.com/dragginzgame/icydb/issues/194), partial).

- Browser node/depth budgets now come from the schema wire policy alongside
  native limits. Preserve the intentional 32,768-node/32-level browser contract
  and separate request/reply bytes. The normal browser check compares every
  generated method with the owner projection and rejects changed settings;
  native allocation allowances remain independent. Full cross-runtime boundary
  qualification remains tracked in [Wire #21](https://github.com/dragginzgame/ic-wire/issues/21).

- Browser contract generation runs IC Wire's bulk-field lint over named types
  and inline request/reply roots. Unreviewed primitive-list candidates and stale
  acknowledgements fail generation. Diagnostic field IDs retain compact varints;
  the six key/cursor fields now use byte-oriented serialization.
  Regression coverage proves that the field-ID acknowledgement cannot exempt
  another identical list, and becomes stale after field removal or a change to
  byte representation. Wire 0.7.9's explicit-root lint resolves shared registry
  containers while preserving field-scoped review ([Wire #25](https://github.com/dragginzgame/ic-wire/issues/25));
  a consumer regression checks that another field remains visible and unrelated
  registration order does not change diagnostic identity. Generation now reviews
  every endpoint request/reply root and its reachable types. The field-ID decision
  is scoped to its three SQL response paths, not the shared container definition.

- [#164](https://github.com/dragginzgame/icydb/issues/164), partial: mixed typed
  batches pass their existing shared bindings into Core without deep clones.
  Owned and shared inputs use one validation and execution implementation,
  preserving current-root checks, atomicity, bounds and result order. Repeated
  binding issuance during builder insertion remains separate outstanding work.

- [#444](https://github.com/dragginzgame/icydb/issues/444): covering-prefix scans
  consume buffered component rows through an owning iterator. This removes the
  per-row key copy and separate buffer-position state. Chunk progression,
  filtering, limits, ordering and the keys retained for monotonicity and duplicate
  suppression keep their existing contracts.
- [#442](https://github.com/dragginzgame/icydb/issues/442): expression ordering
  reads borrowed cached slots through the shared borrowed/owned expression
  adapter. Synthesized slot values remain supported; sort caches and cursor
  boundaries still own their results. Remove the redundant owned-only adapter
  and ordering accessor while preserving missing-path and NULL semantics.
- [#445](https://github.com/dragginzgame/icydb/issues/445): grouped single-slot,
  nested-path and retained-slot reads decode within the store's borrowed read.
  Heap/live payloads no longer need a temporary whole-row copy; canonical stable
  reads retain their necessary owned payload for decoding. Missing-row policy,
  read/decode charges and owned grouped values are unchanged.
- [#443](https://github.com/dragginzgame/icydb/issues/443): scalar function calls
  retain borrowed or computed argument values through the shared evaluator,
  removing temporary payload copies from projection, filters and grouped HAVING.
  Function results, eager argument order, errors and COALESCE short-circuit
  selection retain their existing contracts.
- [#167](https://github.com/dragginzgame/icydb/issues/167): child-prefix expansion
  seeks each distinct parent instead of walking unrelated index metadata.
  Examined entries consume the existing key/index visit budget, with exhaustion
  propagated through the store and executor. Sorted unique output, child caps,
  generation checks and journal completeness proofs retain their contracts.

### 🐛 Fixed

- [#183](https://github.com/dragginzgame/icydb/issues/183), partial: model macros
  preserve authored doc comments and explicit `doc` attributes on the main
  generated type, including expression-valued documentation. Entity helpers
  retain their own documentation rather than inheriting the entity description.
  Authored `allow`, `warn`, `deny`, `forbid` and `expect` attributes retain their
  main-type scope and arguments without leaking onto helpers. Other attribute
  and declaration-shape handling remains open.

- [#180](https://github.com/dragginzgame/icydb/issues/180), partial: generated
  named-value and runtime entity adapters use the fully qualified standard
  `Result` type. Consumer-local aliases such as `std::io::Result` no longer
  change generated trait signatures. Generated primitive/newtype comparisons
  likewise use qualified comparison traits and calls, preserving both operand
  directions when consumers shadow `PartialEq` or `PartialOrd`. Schema-only and
  runtime-enabled fixtures retain these aliases in scope. Generated optional,
  collection and indirect fields, collection conversions/defaults, relation-write
  inputs and numeric conversion signatures also qualify `Option`, `Vec` and `Box`,
  with distinct consumer aliases retained in both fixtures. Generated schema metadata,
  adapters, defaults, validation and visitor calls also qualify `Some`, `None`,
  `Ok` and `Err`, so consumer variant imports cannot change their meaning. Both
  fixtures retain conflicting variant imports. Generated enum/tuple default bounds
  and constructors, plus managed/identity field placeholders, explicitly use the
  standard `Default` trait. A consumer alias no longer redirects those defaults;
  the enum/tuple regression checks their unchanged zero and empty-string values.
  Generated newtype/list/set/map conversions also qualify `Into` bounds and calls,
  preserving list order, set deduplication and map replacement when consumers
  shadow that trait name. Other prelude and helper-name collisions remain open.

- [#95](https://github.com/dragginzgame/icydb/issues/95): migration completion
  checks each proposed entity against its current accepted identity, declared
  version and source digest instead of comparing proposal size with retained
  historical lineage. Removed entities no longer make completed renames report
  Idle or force successor reconciliation to re-plan an applied migration.
  Historical entries and persisted formats remain unchanged.

- [#156](https://github.com/dragginzgame/icydb/issues/156): retain scalar lookahead
  through ordering and pagination until projection decides continuation. An
  exactly full exhausted page no longer requires an empty follow-up request.
  Withheld matches remain beyond the emitted boundary; work-envelope stops still
  preserve continuation. Lookahead is discarded before outward projection, and
  ordinary LIMIT/OFFSET and DISTINCT window ownership remain unchanged.

- [#93](https://github.com/dragginzgame/icydb/issues/93): accepted field-kind
  summaries enforce the shared recursive-depth limit and a 512 KiB output cap
  across sibling expansions. Recursive and excessively reused named types return
  Unsupported without a partial summary. Bounded summaries keep their exact text.
- [#92](https://github.com/dragginzgame/icydb/issues/92): nested-leaf lowering
  applies the persisted codec's existing 256-leaf-per-field cap before cloning
  another path or kind. Shared record DAGs fail with Unsupported before expanding
  millions of leaves. Exact-limit schemas and recursive back-edge handling retain
  their existing behavior; no new schema limit or persisted format is introduced.
- [#210](https://github.com/dragginzgame/icydb/issues/210): direct CHECK proof
  rejections preserve the actual 256-row or 4 MiB page limit and the attempted
  count or byte size in diagnostic facts. Failed proofs publish no schema or
  validation job. Document both thresholds, the first-row exception and the lack
  of heap validation continuation; persisted jobs and paging remain unchanged.
