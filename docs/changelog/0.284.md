# 0.284

## [0.284.3] - 2026-10-26

### 🩹 Fixed

- Descending primary scans can use the existing direct borrowed-row traversal
  for heap, live-only journal and canonical-only journal stores. The same range
  iterator admits each key before materializing its payload; early stops retain
  an exclusive upper resume boundary. Scalar/composite keys, limits, both stop
  points and resumption are covered in both directions. Mixed overlays and
  full-row strategy expansion remain separate work; no measured instruction,
  cycle or raw Wasm-size reduction is claimed
  ([#261](https://github.com/dragginzgame/icydb/issues/261), partial).

- Ordered raw-row pages retain their admitted tuples through projection and
  cursor construction. Direct sources move into result columns; repeated columns
  retain independent ownership. Plain pages keep compact raw-row storage, while
  cursor pages forward retained order fields before dropping kernel rows.
  Frozen order contracts share their immutable inputs. Extra retained tuple
  storage is budgeted before allocation, and layout proofs exclude omitted fields
  and byte-length substitutes. Missing expression results retain projection's
  own error behavior ([#408](https://github.com/dragginzgame/icydb/issues/408)).

- Journal folding no longer requires a valid optional cardinality-delta watermark.
  Matching evidence advances; stale or unavailable evidence stays unavailable,
  while authoritative row/index validation remains mandatory. Regression coverage
  drains a populated journal with an invalidated delta and verifies indexed query
  results. Malformed or mismatched durable count records and count arithmetic
  overflow/underflow likewise skip maintenance without partial writes, retaining
  the old header and records for diagnosis. The advanced canonical source makes
  those counts unavailable; rebuilding restores accurate counts. Invalid caller
  requests and storage-backend failures still reject. A delete-fold regression
  exercises inconsistent counts through convergence, query and rebuild.
  ([#79](https://github.com/dragginzgame/icydb/issues/79)).

- Materialized raw-row ordering extracts sort values before releasing the
  residual-filter reader. Rejected rows do not touch order-only slots or pay
  sort charges; accepted direct-field orders retain primary-key validation.
  Unfiltered ordering retains its sparse decoder, and expression ordering keeps
  its established missing-value behavior. Nulls, ties, bounded winners, rejected
  corrupt slots/keys and decode-budget limits have focused coverage
  ([#410](https://github.com/dragginzgame/icydb/issues/410), filter-to-sort handoff).

- Row readers retain a borrowed view of the immutable physical offset table,
  removing the per-reader field-span vector. Full table validation still rejects
  malformed unselected spans before field access; historical missing fields and
  lazy value decoding remain unchanged. Slot-value cache allocation remains
  separate work ([#257](https://github.com/dragginzgame/icydb/issues/257), partial).

- Cardinality row scans retain the preceding iterator entry until the next row
  is admitted. They copy a resume key only when stopping before an unconsumed
  row; exhausted pages retain none. The canonical visitor owns this lifetime
  for both heap and journaled storage, preserving page boundaries and excluding
  live overlays. Index pages retain the key already decoded for prefix counts
  and encode only their final checkpoint, preserving its exact bytes through the
  strict index codec. Completed index pages retain their existing final anchor.
  Constraint-validation pages likewise retain decoded primary identity and encode
  only the final checkpoint; findings still own their reported row keys. Empty
  resumed pages retain their incoming anchor, including Account subaccount and
  composite-key byte identities
  ([#459](https://github.com/dragginzgame/icydb/issues/459)).

- Delete scheduling no longer decodes and clones a raw key that it immediately
  discards. Commit preparation remains the strict key-admission owner and retains
  its decoded key before marker publication. Transition checks, duplicate-target
  scheduling and relation protection remain in place
  ([#462](https://github.com/dragginzgame/icydb/issues/462)).

- Scalar field-pair predicates borrow text/blob payloads instead of constructing
  discarded owned values. Case-insensitive text still folds both row values;
  blob ordering, mixed-type comparisons and invalid coercions remain rejected.
  A parity matrix checks all operators and coercions against general comparison
  semantics, alongside existing reader-level casefold tests
  ([#465](https://github.com/dragginzgame/icydb/issues/465)).

- Migration validation, rewrite and final-check pages pass decoded primary-key
  values directly through candidate evaluation and projection. They no longer
  retain a discarded raw-key copy. Strict key decoding, primary-key agreement,
  findings, journal records and retained cursors are unchanged
  ([#463](https://github.com/dragginzgame/icydb/issues/463)).

- Migration journal validation checks borrowed row size without constructing and
  dropping an owned row; application still owns the row it stores
  ([#466](https://github.com/dragginzgame/icydb/issues/466)).
- Cardinality row pages and their resume checkpoints use the existing non-copying
  key decoder. Entity admission, count digests and page boundaries are unchanged
  ([#460](https://github.com/dragginzgame/icydb/issues/460)).
- Unique-index projection compares borrowed components from retained raw keys.
  Duplicate raw keys, accepted unique conflicts, candidate conflicts and malformed
  frames retain their distinct errors
  ([#464](https://github.com/dragginzgame/icydb/issues/464)).
- Storage diagnostics, user-index domain checks, migration staging cleanup and
  journal index validation use strict borrowed frames rather than allocating
  discarded components and primary-key suffixes. Retained raw keys remain owned;
  the redundant owned-key namespace helper is removed
  ([#461](https://github.com/dragginzgame/icydb/issues/461)).

### 🧹 Cleanup

- Borrowed-row traversal charges rows visited and stored bytes through one
  active-budget lookup. The existing paired-charge owner preserves charge order,
  partial accounting on failure and request-root totals. No limit, reservation,
  execution route or state changes; broader page accounting remains separate
  ([#293](https://github.com/dragginzgame/icydb/issues/293), partial).

- The browser qualification harness selects published Platform npm 0.1.0 and
  consumes its Agent/identity exports. SDK Core remains 6.1.1 transitively;
  Wire codecs, exact retry frames and explicit disposable-fixture root-key
  fetching are preserved. Browser checks reject first-party direct SDK
  dependencies, npm aliases and literal module references
  ([#468](https://github.com/dragginzgame/icydb/issues/468)).


- Index commit preparation directly constructs at most two ordered presence
  changes. It no longer carries discarded row identities or a fixed constructor
  callback; index deltas retain their key-owned identity without a second
  primary-key payload. Same-key no-ops and removal/insertion ordering remain.
- Field-path and expression-index mutations share transition orchestration
  through the existing two-family key authority. Specialized key construction,
  after-image admission, filtered membership, uniqueness and error origins remain.
- Access-plan constructors own structural flattening, empty-set identities and
  arity collapse. Value normalization adds canonical ordering and deduplication
  over that structure, preserving continuation and fingerprint semantics.
- Scalar and grouped results share the existing resource owner's ordered result
  charges. Exact-limit admission and retained counters after failure remain.
- Fixture staging, entity-scale checks and Wasm reports use Clap for arguments
  and help. Existing typed build labels, aliases and fixture defaults remain;
  help returns success before any artifact acquisition or staging.
- Generated SELECT and mutation witness schedules share canonical ordering and
  identity validation while retaining their distinct recipes and fixed schedule
  identity. The model index-field bound re-exports the Schema-owned constant.
- Index preparation carries the existing decoded primary key directly instead
  of wrapping it in a second identity type. Stored entry witnesses still validate
  before use; reverse-index reads continue to validate untrusted raw index keys.
- BLAKE3 users consume published IC Platform 0.6.18's optional feature. The
  selected BLAKE3 version and hashing recipes remain unchanged; dependency
  admission rejects direct aliases, optional and inactive-target bypasses
  ([#467](https://github.com/dragginzgame/icydb/issues/467)).
- Public input and output scalar constructors share one private implementation.
  Their root types, const constructors, documentation and must-use attributes
  remain; recursive collection construction and enum admission remain distinct.

### 🧪 Testing

- Native tests can scope a synthetic instruction counter per thread and restore
  its previous value after nested scopes or unwinding. Tests drive the actual
  runtime sampling seam to cover baseline exclusion, repeated samples, exact
  instruction limits, finish-time exhaustion and nested read/request accounting.
  Production native and Wasm counters are unchanged. Real IC counter/reserve and
  commit-contradiction qualification remain outstanding
  ([#154](https://github.com/dragginzgame/icydb/issues/154), partial).

### 📚 Documentation

- Document durable mutation-job liveness under concurrent writes: verification
  needs one unchanged target-entity revision across its whole sweep, drift
  restarts Forward without undoing committed pages, and repeated drift has no
  retry ceiling. The API and operator guide identify `verify_restarts_total`,
  maintenance-window coordination and the distinction between bounded advances
  and eventual completion ([#222](https://github.com/dragginzgame/icydb/issues/222)).

### 📊 Audit

- The order-value handoff adds 649 and removes 71 Rust physical lines across
  19 files (net +578). Internal ownership is more explicit; the implementation
  carries cached and uncached batches without adding a public execution mode.
  Raw Wasm, cycle and instruction deltas remain unmeasured.
- Follow-up cleanup spans 38 files relative to its incoming working tree: Rust
  physical lines +88/-290 (net -202). The implementation is simpler, with no new
  execution modes or retained state. Raw Wasm, cycle and instruction deltas are
  unmeasured; Linux compilation does not qualify macOS.
- The subsequent filter-to-sort handoff spans seven files: Rust physical lines
  +358/-22 (net +336), mostly focused tests. It reuses the existing raw-row window
  and adds no execution modes or retained state. Cost deltas remain unmeasured.

## [0.284.2] - 2026-10-26

### 🔧 Changed

- Refresh the canonical Shared Tooling snapshot to 0.26.19 (126 payloads).
  Normal release commands start fresh; explicit `release-resume` owns saved-plan
  recovery. Adopt the cross-runtime RPC-budget rule without treating configuration
  equality as proof of equivalent runtime admission.
- Raise the IC Tooling manifest minimums to 0.68.6 and Wire to 0.7.15, matching
  the already-selected lockfile. Published Tooling requires a successful Cargo
  build-finished event for native executables; Wire rejects duplicate numeric
  method identities. Existing consumer interfaces, frame bytes and product limits
  remain unchanged. No unpublished sibling implementation is required.
  Bulk-review test endpoints now receive distinct numeric IDs so schema admission
  reaches field-scoped diagnostics; duplicate-name rejection remains covered
  independently of numeric identity collisions.

### 🩹 Fixed

- Durable job advancement now uses the same journaled-source proof verifier as
  creation on both sides of application work. A retained record whose current
  source is heap-backed rejects with `DurableStoreRequired` before invoking the
  callback, preserving its progress on repeated attempts. Existing exact receipt
  replay and source-change invalidation remain unchanged. Exhaustive reads also
  require durable sources when a caller supplies a proof or the bounded result
  needs continuation. Fresh, complete one-call heap reads remain supported;
  incomplete heap reads return `DurableStoreRequired` rather than an unsafe
  cursor. Live pagination remains unchanged
  ([#67](https://github.com/dragginzgame/icydb/issues/67)).

- Startup recovery restores journaled index readiness using its existing durable
  access revision, rather than advancing that revision for disposable
  Building/Ready transitions. Real access-state changes still advance the revision
  and invalidate old proofs. Native regressions cover retained and empty journal
  tails, exhaustive cursor resumption and durable job advancement; installed
  canister upgrade qualification remains outstanding
  ([#66](https://github.com/dragginzgame/icydb/issues/66)).

- Migration abort seeks each candidate physical index domain in raw-key order
  instead of scanning every entry in its stores. The existing cursor, 512-entry
  page ceiling and byte ceiling remain unchanged. User/system namespaces,
  generation boundaries and malformed candidate suffixes retain strict handling.
  Regression coverage proves unrelated entries no longer consume cleanup pages,
  and multi-page cleanup preserves predecessor rows and retained writes. Raw
  Wasm size, IC cycles and instruction deltas remain unmeasured
  ([#207](https://github.com/dragginzgame/icydb/issues/207)).

- Add installed-canister coverage for heap ADD COLUMN, CREATE INDEX and DROP
  INDEX in the mixed-store SQL audit actor. After each publication, only queries
  and timer delivery are permitted: watchdog work completes without failure,
  returns to idle, retains Ready and preserves query results. The local fixture
  exposes DDL through the Canic adapter under `test-admin-api`; its frozen local
  endpoint policy is updated and the production policy stays unchanged. This
  qualifies actual timer delivery for the existing heap-publication fix; it does
  not qualify heap migration or claim a measured cache-cost improvement
  ([#196](https://github.com/dragginzgame/icydb/issues/196)).

- Cache successful identity-inventory closure validation in the existing
  accepted-bundle cache. Identity writes, removals and exact overlay retirement
  revoke the proof; root replacement and projection reset discard the cache.
  Failed validation is never cached as success, and integrity inventory scans
  remain explicit. A single non-persisted validity bit avoids repeated scans
  without rebuilding accepted value/index metadata on each identity write.
  Heap, live/canonical, repair and retirement controls retain typed corruption
  refusal. IC instruction/cycle and raw Wasm deltas remain unmeasured
  ([#212](https://github.com/dragginzgame/icydb/issues/212)).

- Exact-key batches project each distinct row while its store borrow is active,
  removing the temporary owned raw-row vector and heap/live row copies. Stable
  reads retain their required single owned row. Original positions, duplicate
  read sharing, missing rows and stored/decoded/materialized/result admission
  remain; per-row projection now follows that row's read admission. Regression
  coverage includes heap, journal live and folded canonical storage, plus exact
  and insufficient row budgets
  ([#455](https://github.com/dragginzgame/icydb/issues/455)).

- Initial generated indexes, existing-index reconciliation and new migration
  indexes use one key/predicate binding and snapshot-construction path. Callers
  retain source-binding registration, logical identity allocation and physical
  generation selection. Public APIs, accepted schema bytes and migration/recovery
  contracts are unchanged
  ([#458](https://github.com/dragginzgame/icydb/pull/458)).

- Use BLAKE3 only for normalized predicate fingerprints in the session plan cache
  and recent bound-plan memo. Canonical bytes and construction admission stay
  unchanged; general value and continuation fingerprints retain SHA-256. BLAKE3
  is now classified as a production dependency; no persisted or public format
  changes. Matched local Testkit IC measurements using the existing preparation
  matrix (AND/OR/IN, 4/16/64/128 terms, three warm/typed repetitions) reduced
  cold SQL instructions by 7,716–146,394, warm SQL by 7,259–146,394 and typed
  instructions by 7,514–136,274 per call. Charged update cycles decreased in all
  samples. The raw wasm-release SQL audit actor grew from 4,146,207 to 4,159,421
  bytes (+13,214; 0.32%). These are whole-call measurements on the same locked
  graph with BLAKE3 1.8.7, not isolated hash throughput or native timing claims.

- Extend the persisted-format policy scan to revision, epoch and generation
  suffixes. Existing semantic job-policy counters keep their retained identity;
  exact owner/name/type/value exceptions distinguish them from version-1 wire
  discriminators. Fixtures reject unclassified counters, changed exception
  values, copied declarations under another owner and missing scan inputs.
  The contract documents this classification and the static scan's limits
  ([#119 — Persisted-policy scan misses revision counters](https://github.com/dragginzgame/icydb/issues/119)).

- Normal-write preparation checks the supplied schema fingerprint against the
  independently selected accepted catalog before preparing constraints. A mismatch
  returns the existing unsupported-store error; a later valid preparation still
  succeeds. Recovery replay and derived rebuild retain their historical identity
  handling, and the operation/context consistency check remains. The durability
  and write-admission contracts distinguish this consistency check from actual
  accepted-catalog/layout compatibility and from publication-candidate fingerprint
  checks. A folded-schema regression preserves historical row identity under
  both replay and rebuild without requiring equality to the later fingerprint
  ([#141 — Independent commit fingerprint validation](https://github.com/dragginzgame/icydb/issues/141)).

- Reuse the maintained checked-cast migration source/successor fixture for a
  second installed Chromium subject. It verifies a real rejected finding's
  nonempty byte-buffer key and exact status retries; native Rust re-decodes the
  actual requests/replies and compares the complete retained status. The existing
  browser test target includes this subject. Populated physical-integrity
  findings still need their separate disposable corruption fixture
  ([#448 — Populated browser finding coverage](https://github.com/dragginzgame/icydb/issues/448), partial).

- Full and sparse row readers require slot payloads to cover the data section
  contiguously in directory order, matching the canonical writer. Overlapping,
  reordered and gapped spans or unused trailing bytes now fail as persisted-row
  corruption, including malformed unselected slots. Valid row encodings and
  historical layout/fill handling are unchanged. Relation-key decoding also
  applies the ordinary scalar decoder's declared integer-width checks to
  singular, list and set targets; valid extrema and omitted null targets are
  preserved. By-kind Decimal decoding enforces the exact accepted scale,
  including nested list/map values and lazy/eager row reads; numerically equal
  values with another stored scale reject instead of being normalized on read.
  Borrowed and owned scalar-slot reads enforce accepted nullability and Text/Blob
  limits before caching or materialization; Text counts Unicode characters and
  Blob counts bytes. Sparse reads and direct primary-key validation share that
  same accepted-field admission. Valid nullable and empty values are preserved.
  By-kind Text/Blob leaves also enforce those lengths before allocating their
  owned value, covering nested list items and map keys/values in both decode
  and validation paths. Oversized unselected items reject during eager reads.
  By-kind sets and map keys must also be strictly ordered under the accepted
  value comparator; duplicate or reversed entries reject without sorting or
  repairing stored bytes. Nested collections share the check, while ordinary
  lists retain their order and duplicates. Validation retains only the preceding
  element/key needed for comparison rather than materializing the whole container.
  Non-nullable by-kind structural slots now reject the structural-null sentinel
  before leaf decoding; nullable fields retain their existing null representation.
  Ordinary list/set elements and map keys/values reject null, including nested
  containers; the maintained relation-collection null-omission behavior remains.
  Delivery and final issue acceptance remain outstanding
  ([#144 — Noncanonical persisted row admission](https://github.com/dragginzgame/icydb/issues/144), partial).

- Scalar output rows run page admission once before ordered hard-budget charges;
  the redundant second admission loop is removed. Candidate start and finish
  each borrow the page tracker once. Inactive scans, nested-unit rejection,
  envelope stops and hard failures retain their accounting and receipt behavior.
  Route-dependent reservation arithmetic and broader per-row charges remain
  ([#293 — Repeated page accounting work](https://github.com/dragginzgame/icydb/issues/293), partial).

- Journal batch validation computes an accepted entity fingerprint once for
  the batch's immutable candidate, then checks each index chunk against it.
  Store/mode admission and per-key index membership checks remain in place;
  a later mismatched fingerprint still rejects. The temporary map is discarded
  after each batch. The isolated positioned-effect qualification now covers
  131,072 effects, matching the accepted before/after projection ceiling rather
  than the former one-sided 65,536-key shape. It retains the existing instruction
  and memory ceilings. Full production replacement-fold qualification remains
  outstanding; isolated bookkeeping does not prove complete callback fit
  ([#86 — Index-replacement recovery repeats fingerprints](https://github.com/dragginzgame/icydb/issues/86), partial).

- Qualify standard derives and the `From` trait in generated declarations and
  composite-key conversions. Consumer fixtures shadow `Clone` with another derive
  and `From` with an unrelated type; conversion retains component order and integer
  widths. Scope private schema constants and host registration inside anonymous
  constants, keeping generated bookkeeping names out of the application module.
  Schema expressions remain const-checked on native and Wasm targets. Authored
  derives are unchanged; public entity key/patch helper-name collisions remain
  separate unfinished work
  ([#180 — Generated names collide with application aliases](https://github.com/dragginzgame/icydb/issues/180), partial).

- Structural writes admit borrowed before/after images through the existing
  constraint scheduler, finish extracting output values, then transfer the same
  key and images into staging. Duplicate-target, row-local constraint, key,
  schema and after-image checks retain their order. Unchanged rows still produce
  no physical commit operation; neither row decoding nor output extraction is
  repeated
  ([#425 — Structural writes copy keys and after-images](https://github.com/dragginzgame/icydb/issues/425)).

- Integrity field-value checks borrow the existing decoded slot cache instead of
  cloning a value used only to establish successful decoding. Invalid-field
  findings and constraint evaluation's retained owned values are unchanged
  ([#453 — Integrity field checks copy discarded values](https://github.com/dragginzgame/icydb/issues/453)).

- Covering-index scans evaluate predicates against borrowed key components and
  copy requested output bytes only after accepting the entry and its row witness.
  Invalid component selections still fail before predicate evaluation; decoded-byte
  and predicate budgets, component order, duplicate selections and scan continuation
  are unchanged
  ([#454 — Index predicates copy rejected components](https://github.com/dragginzgame/icydb/issues/454)).
