# IcyDB 0.240 Detailed Changelog

## 0.240.1

### 📝 Summary

`0.240.1` admits one evidence-bounded SQL global aggregate:

```sql
SELECT COUNT(DISTINCT age) FROM Entity
```

When the direct non-nullable `Int32` field is the leading component of a
complete accepted user index, IcyDB counts exact synchronized
first-component metadata. Incompatible shapes and unavailable evidence enter
the existing prepared executor before it performs store work.

### 🔧 Changed

- SQL lowering owns one immutable exact-distinct eligibility fact, including
  the rejection of authored ordering and predicates.
- The accepted query planner selects one complete compatible index by shortest
  arity and stable name. Execution cannot reselect an index.
- The singular fingerprint-bound exact-or-prepared command slot gains one
  accepted `IndexId` target; no neighboring or nested cache was added.
- The former direct-count session owner is hard-cut to the broader
  `exact_count` owner without aliases or forwarding modules.
- Synchronized first-component metadata is exact result authority only while
  its decode state and data generation match the pinned store.

### 🩹 Fixed

- Impossible zero multiplicity and checked metadata-count or budget-layout
  overflow return typed invariant failures instead of looking like optional
  metadata unavailability and entering prepared fallback.
- Exact-success retained-state charges come from the canonical scalar-DISTINCT
  reducer layout, including hash-entry and collision-promotion costs.
- Request and execution budget publication uses one checked atomic commit;
  rejected bundles leave both authorities unchanged.
- SQL lowering carries the admitted target slot as its immutable fact, so the
  session does not re-derive the field from aggregate strategy shape.

### 📊 Audit

| Shape | `v0.240.0` predecessor/control | `v0.240.1` | Saving |
| --- | ---: | ---: | ---: |
| 2,048 rows / five values, cold | 120,671,186 | 467,343 | 120,203,843 |
| 2,048 rows / five values, true warm | 120,426,858 | 299,976 | 120,126,882 |
| 2,048 all-unique values | 136,644,062 | 940,455 | 135,703,607 |

The exact route fetches zero rows and reads zero physical index entries. A
request with nearly exhausted DISTINCT capacity takes the bounded metadata
probe and preserves the prepared executor's typed budget diagnostic facts.

Final production raw Wasm grows from 3,293,820 to 3,299,581 bytes (+5,761),
inside the frozen 8 KiB gate; deterministic gzip grows by 2,250 bytes. Candid,
final exports, stable state, generated API and public SQL syntax are unchanged.

The maintained runtime delta is approximately +510 net lines across 13
substantive production Rust files plus narrow module wiring. It adds zero
production types, cache slots, mutable owners, persisted states or invalidation
edges.

### 🧪 Testing

Focused evidence covers empty, duplicate-heavy and all-unique distributions;
alias preservation; true-warm reuse; incompatible prepared fallbacks;
generation mismatch; journaled metadata unavailability; bounded stop-after;
typed corruption/overflow outcomes; atomic budget rejection/commit;
deterministic planner selection; same-Wasm recovery; warning-denied feature
configurations; authority invariants; and production Wasm/Candid comparison.

## 0.240.0

### 🧹 Cleanup

- Compiled SQL global aggregates now retain one immutable, fingerprint-bound
  preparation: either an exact entity/index-prefix cardinality target or the
  existing shared prepared plan.
- The separate exact-count cache slot, cache-entry wrapper, measured-only
  outcome type and prepared-plan resolution wrapper were removed. Prepared
  fallback remains owned by the existing registry-scoped shared query-plan
  cache.
- Publication continues to create a new compiled command through the existing
  outer cache key. A retained command rejects a mismatched fingerprint and its
  populated slot is never replaced.

### 📊 Audit

- The final SQL audit Wasm falls from 8,204,964 to 8,196,454 raw bytes
  (`-8,510`); deterministic gzip falls from 2,632,767 to 2,630,288 bytes
  (`-2,479`).
- At 2,048 rows, `COUNT(*)`, `COUNT(id)`, `COUNT(1)` and `COUNT(*) WHERE true`
  improve by 192–203 instructions. True-warm `COUNT(*)` improves by 6
  instructions, and every exact case continues to fetch zero rows and visit
  zero index entries.
- Cold/warm `COUNT(DISTINCT age)` and aggregate `FILTER` controls remain within
  -33,411 to +29,995 instructions of the predecessor; the largest regression
  is 0.026% against the frozen 2% gate.
- An unavailable exact target now proves persistent fallback through one
  shared-plan miss followed by one shared-plan hit, with identical 512-entry
  physical work and cold/warm regressions of only 0.058%/0.251% against the
  frozen 5% gate.
- Production cache slots decrease from two to one and production types decrease
  by three. The production SQL runtime is 22 lines smaller. No execution route,
  invalidation edge, persisted state, public API,
  Candid method or compatibility path was added.

### 🧪 Testing

- Added owner-level coverage for exact and prepared cache installation,
  fingerprint rejection and attempted replacement of an occupied entry.
- Extended the production-shaped recovery proof to lock shared fallback cache
  ownership and warm reuse while optional cardinality metadata is unavailable.
- Existing exact-count, ordinary aggregate, lifecycle and recovery proofs
  remain the behavioral authority.
