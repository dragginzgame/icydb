# IcyDB 0.244 Detailed Changelog

## 0.244.0

### 📝 Summary

- Strictly admitted unfiltered global `SUM` and `AVG` projections over one
  direct, non-nullable indexed `Int32` field can use the index store's existing
  synchronized leading-component multiplicities instead of loading and
  reducing every row.
- The exact path derives one shared `(count, sum)` fact for either aggregate or
  both together. Missing or stale optional metadata, incompatible query shapes
  and unavailable selected indexes retain the existing prepared aggregate
  executor.

```sql
SELECT SUM(age), AVG(age) FROM users;
```

### 🔧 Structure

- The existing fingerprint-bound exact-or-prepared compiled-command slot gains
  one planner-selected numeric target. It remains the only command-local plan
  owner and never caches a data result.
- The accepted planner selects one complete leading-field index. Execution
  cannot reselect another index, reclassify SQL eligibility or establish schema
  freshness.
- `IndexStore` remains the synchronized metadata owner and exposes only one
  bounded checked fold. No aggregate cache, persisted sum, materialized view,
  mutable owner, invalidation edge or format change is introduced.
- Canonical signed-integer component decoding is shared from the index-key
  owner rather than duplicated by metadata and covering execution.

### 📊 Audit

- The exact released `v0.243.1` predecessor measures 2,048-row indexed
  `SUM(age)` at 98,081,958 instructions cold / 97,717,969 true warm and
  `AVG(age)` at 98,067,171 / 97,703,437.
- Candidate `SUM(age)` measures 471,713 instructions cold and 301,275 true
  warm, saving 97,610,245 cold instructions. Candidate `AVG(age)` measures
  471,502 cold and 300,025 true warm, saving 97,595,669 cold instructions.
  Both exact paths fetch zero rows and visit zero physical index entries.
- With 2,048 distinct values, exact `SUM` measures 1,357,758 instructions
  against 122,854,457 for prepared execution, a 121,496,699-instruction
  saving. Bounded over-budget probing preserves the predecessor typed failure
  and remains below its prepared control.
- Final production SQL Wasm is 3,287,174 raw bytes and 1,305,929 gzip bytes,
  respectively +5,740 and +2,155 bytes from the identical `v0.243.1` build.
  Production Rust grows by 241 net lines and focused test/audit evidence by 290
  net lines. Candid, six exports, stable formats, generated surfaces, package
  versions and `Cargo.lock` remain unchanged.
