# IcyDB 0.293

## [0.293.0] - 2026-11-01

### ⚠️ Breaking

- Adopt registry `ic-memory` and `ic-storage` 0.61.0. Hosts composing IcyDB's
  public Memory runtime must use the matching 0.61 identity. Canic qualification
  retains its separate supplier selections and was not run against this cut.
  Generated bootstrap uses `NonZeroU16` bucket sizes and canonical checked keys at runtime calls.
- Fresh zero-page stores call `create`; retained stores call `load`. No reset,
  compatibility reader or local replacement storage implementation is added.
  Valid retained collection, allocation-ledger and checkpoint bytes remain
  supported. Corrupt retained headers still refuse without writes or growth.
  The generated hidden bootstrap helper now accepts a nonzero bucket size.

### 📚 Documentation

- Clarify that query-created cache entries can serve later preparations within
  the same call, while query completion discards their non-replicated heap
  changes. Registry scope, bounded retention and current-authority validation
  remain unchanged. Retire the blanket non-replicated-insertion bypass proposal
  ([#280 — Query cache insertion](https://github.com/dragginzgame/icydb/issues/280), not planned):
  it would remove supported reuse and introduce another cache policy without
  matched cold/warm IC cost evidence. No performance improvement is claimed.
- Reconcile scalar-page accounting with the maintained refill contract
  ([#293 — Scalar-page accounting](https://github.com/dragginzgame/icydb/issues/293)).
  Earlier releases already replaced repeated resource-vector construction and
  separate budget lookups with direct resource population, a constant output
  reservation and the ordered charging owner. Access reservations are not
  stream-wide constants: buffered primary/index leaves report zero until another
  bounded refill is needed. Retain per-pull admission and exact before/after
  usage snapshots; retire the remaining stream-wide reservation-cache proposal.
  This adds no cache, state, policy, format or claimed performance saving.
- Close the remaining unchanged-index shortcut proposal
  ([#344 — Unchanged-index update work](https://github.com/dragginzgame/icydb/issues/344), not planned).
  Its fixed accepted metadata is already shared by the commit context. Remaining
  component encoding proves membership, component/primary-key validity and the
  complete key length. Constructing the admitted `IndexKey` only moves those
  buffers; it does not serialize another raw key. Preserve typed after-image
  refusal without introducing a second proof cache. No cost saving is claimed.

### 🩹 Fixed

- Admit generated accepted-schema reports using the same exact IC Wire success
  envelope and message-context caps as SQL replies
  ([#78 — Unbounded schema replies](https://github.com/dragginzgame/icydb/issues/78)).
  The existing 3 MiB query and 2 MiB replicated caps now protect both handlers.
  Known byte overflow returns `RUNTIME_BOUNDARY_SCHEMA_REPLY_BYTES_EXCEEDED`
  with response origin; Wire sizing/traversal refusals retain the existing typed
  internal-response behavior. Errors fit the smaller reply cap. Success payloads,
  method identities and authorization are unchanged; Canic retains IC exports.
  This admits delivery after full report construction; it adds no pagination,
  truncation, report-construction budget or alternate codec.

- Refresh existing adopted source digests with completed ordinary schema
  publication and its receipt
  ([#94 — Ordinary source-lineage drift](https://github.com/dragginzgame/icydb/issues/94), partial).
  Completed defaults and immediately validated checks keep their admitted source
  version. Version admission also runs before deferred validation publishes,
  including changes to another entity in the same proposal. An unplanned version
  change returns typed `MissingMigration` without publishing an activation,
  receipt, head, row or lineage change; corrected same-version proposals remain
  admissible. A fresh, fully admitted no-op application can repair an already stale digest without
  changing rows or the accepted head. Existing unadopted records remain
  unadopted. Retained lineage read/write and marker recovery use the same current
  codec even when migration authoring is disabled; fresh feature-disabled
  creation still does not implicitly initialise lineage.
  Deferred generated activations keep their prior digest because they can still
  abort. Their completion/abort lineage propagation remains open in this issue.
  No persisted field, record version, adoption mode or recovery route is added.
- Pass operation budgets through accepted field-path/expression index predicate
  projection, semantic access contracts and visible-index preparation
  ([#76 — Predicate normalization budgets](https://github.com/dragginzgame/icydb/issues/76), partial).
  Ordinary query preparation, exact-count/aggregate metadata selection and
  diagnostic EXPLAIN retain their existing request and lane. Schema metadata
  projects the accepted tree; each consumer owns its normalization authority.
  Reuse the existing fallible normalizer and typed budget errors without a new
  profile, state, codec or fallback. Commit metadata keeps its existing pure
  normalization because the same constructor also serves journal replay.
  Commit/recovery, shared user-index-domain and migration/activation preparation
  still require separate authority propagation. Whole-pipeline allocation/sort
  accounting and cost qualification are not claimed.
- Stage exact physical-generation deletions before a SQL unique-index abort
  publishes, then remove those keys, the activation and its validation job under
  the same schema commit marker
  ([#38 — Aborted unique generations poison later DDL](https://github.com/dragginzgame/icydb/issues/38)).
  Reuse the accepted candidate owner, existing raw index bounds, staged-effect
  carrier and journal deletion records. No persisted state, cleanup job, codec
  profile or alternate recovery route is introduced. Other index generations,
  entities and system keys remain outside the removal range.

### 🧭 Migration Notes

- Exhaustive `RuntimeBoundaryCode` consumers must handle
  `SchemaReplyBytesExceeded`. Its public error code appends 293; existing numeric
  codes and encoded success/error representations are unchanged.

- Candidate cleanup is bounded by existing construction, index-deletion and
  journal limits. A prepublication refusal retains the activation, job and all
  keys instead of reporting a successful abort that leaves an orphan. Keys
  orphaned by already completed aborts on older releases are not silently
  removed; existing complete-domain corruption checks still reject them. This
  repair does not supply an operator repair/reset workflow for those installations.

  max and max-plus-one, decoded deliverable errors and empty/small successes.
  Retain SQL reply/codec controls and actual generated-caller compilation.
  Four distinct accepted schema snapshots sharing one value catalog demonstrate
  that a valid report can exceed reply admission.

- Cover default/digest drift, a later unrelated physical migration, admitted
  no-op repair, version refusal, unadopted isolation and interrupted compound
  publication with repeated recovery. Check immediate empty/populated constraint
  proof and retained-digest isolation through deferred constraint abort.
  Reproduce deferred version bypass for both the validated entity and another
  assigned entity; verify repeated typed refusal with unchanged retained state,
  followed by successful corrected admission and abort in both feature setups.
- Qualify primary and secondary-index refill transitions in both directions:
  one four-entry refill leaves its buffered keys admissible, then the next refill
  stops before storage traversal. The page receipt retains exactly four physical
  entries. This checks current admission behavior, not instruction/cycle cost.
- Add exact and cumulative accepted-predicate projection controls for both index
  families and all three read lanes, with typed resource/limit/actual facts,
  zero row/index visits and repeated preparation against the same request.
  Existing planner fixtures now supply finite construction authority explicitly.
- Cover aborts before validation and after staging or conflict findings,
  generation isolation, zero-write construction refusal, malformed generation
  entries, journal batch shape and interrupted replay/fold followed by index
  DDL. Verify that empty generated entity removal also succeeds after an abort.
