# IcyDB 0.239 — Generated Schema References

## 0.239.1

### 🔧 Changed

- The internal held-head key-stream protocol now exposes only monotonic seek
  and held-occurrence consumption, the two capabilities used by production
  execution.
- Zero-target head loading remains available on the repeated-pull reference
  oracle and physical-stream unit fixtures without imposing an unused method
  on every production adapter.
- Migration guidance now shows both supported ways to bring `EntitySource`
  into each module that uses `Entity::ENTITY` shorthand.
- Startup failure classification and receipt publication no longer carry
  staging-era production dead-code suppressions: the live startup driver owns
  both paths and warning-denied builds now enforce that wiring directly.
- Explicit entity-source adoption planning now compiles only when the
  `migration` feature needs it or when its no-feature test oracle is active,
  instead of remaining dead-code-suppressed in base production builds.

### 📊 Audit

- Query planning, physical seeking, work accounting, corruption handling,
  accepted-schema authority, persisted formats, Candid and exports are
  unchanged. No execution route, mutable owner, cache or behavior axis was
  added.
- The focused code change touches three files with 28 inserted and 42 deleted
  lines. It removes one production trait requirement and two forwarding adapter
  methods; the implementation shape is simpler. Including release notes and
  status evidence, the complete patch touches ten files with 175 inserted and
  65 deleted lines.
- Against the recorded `0.239.0` SQL audit canister, compiler-emitted Wasm
  remains 5,098,544 raw bytes. The final deployable artifact is 4,459,669 raw
  bytes (-11); deterministic gzip is 1,731,681 bytes (+362). Candid SHA-256
  remains `2df06ec3697e3392c16d80d0b2578c40005e489a3fb36cc75c7a17bd626c8ee5`
  and the final export count remains 70.
- The startup cleanup deletes 15 stale attribute/comment lines across two
  production files. It changes no runtime statement, allocation, branch or
  code-generation attribute, so the preceding Wasm measurement remains the
  applicable footprint evidence.
- Migration-planner narrowing changes one production file by one insertion and
  two deletions. Compiler-emitted and final raw Wasm remain 5,098,544 and
  4,459,669 bytes respectively; gzip is 1,731,679 bytes (-2). Candid SHA-256
  and the 70-export surface remain unchanged.

## 0.239.0

### ➕ Added

- Runtime-enabled `#[entity]` declarations generate one public upper-snake
  `FieldRef` associated constant for every authored and managed field.
- Runtime-enabled `#[record]` declarations generate the same references for
  every authored member.
- Generated entities implement the public model-owned `EntitySource` contract,
  making the exact authored source available without reserving a field name.

```rust
let page = db!()?
    .query::<User>()?
    .filter(User::ACTIVE.eq(true))
    .order_by(asc(User::ID))
    .limit(25)
    .execute_live_page(None)?;

let patch = StructuralPatch::new().field(
    User::DISPLAY_NAME.as_str(),
    WriteCell::Value(InputValue::Text("Ada".to_string())),
);
db!()?.execute_trusted_structural_insert_batch(
    <User as icydb::traits::EntitySource>::ENTITY,
    vec![patch],
)?;
```

### 🔧 Changed

- Maintained typed-query and structural-write examples now use generated
  schema references instead of repeating entity and field strings.
- Schema-only `icydb-model` consumers remain runtime-independent and do not
  receive `FieldRef` constants. Renamed direct runtime dependencies continue
  to resolve through the existing macro path-rewriting boundary.

### 🧭 Migration Notes

- Applications with hand-written `Entity::FIELD` or `Entity::ENTITY` bridges
  should delete those implementations when adopting 0.239. The generated
  surface replaces them directly; no alias or compatibility layer is retained.
- Use `<Entity as icydb::traits::EntitySource>::ENTITY` whenever an entity
  source string is required. `Entity::ENTITY` remains convenient shorthand
  when `EntitySource` is in scope and no authored field is named `entity`.
  A field named `entity` is valid and generates the inherent `ENTITY`
  `FieldRef`; the fully qualified trait constant remains the unambiguous source.
- `Entity::ENTITY` requires `EntitySource` in every module that uses the
  shorthand. An anonymous import in a parent module does not cover a nested
  module, including a nested test module. Use either common form locally:

  ```rust
  use icydb::prelude::*;
  // or, with narrow imports:
  use icydb::traits::EntitySource as _;
  ```

- Generated constants contain source spelling only. Queries and writes still
  bind against the request's accepted schema snapshot and fail closed when a
  source is absent or stale.

### 📊 Audit

- Runtime behavior axes, accepted-schema authorities, mutable owners, caches,
  invalidation edges, persisted formats, Candid, and exports are unchanged.
- The implementation extends the existing entity/record macro emission path;
  it does not add a second query or structural-write route.
- Against exact `v0.238.0`, the SQL audit canister changes from 4,456,432 to
  4,459,680 final raw Wasm bytes (+3,248). Compiler-emitted Wasm changes from
  5,100,161 to 5,098,544 (-1,617), while deterministic gzip changes from
  1,731,736 to 1,731,319 (-417). Candid SHA-256 and the 70-export surface are
  unchanged.
- The complete slice touches 22 files with 552 inserted and 26 deleted lines,
  including its bounded design, tracker, release notes, maintained examples
  and focused proofs. Production generation/facade code adds approximately 80
  net lines with no runtime state or execution-path increase.
