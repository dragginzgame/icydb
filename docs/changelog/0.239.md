# IcyDB 0.239 — Generated Schema References

## 0.239.0

### ➕ Added

- Runtime-enabled `#[entity]` declarations generate one public upper-snake
  `FieldRef` associated constant for every authored and managed field.
- Runtime-enabled `#[record]` declarations generate the same references for
  every authored member.
- Generated entities implement the public model-owned `EntitySource` contract,
  making the exact authored source available without reserving a field name.

```rust
let page = db!()?
    .query::<User>()?
    .filter(User::ACTIVE.eq(true))
    .order_by(asc(User::ID))
    .limit(25)
    .execute_live_page(None)?;

let patch = StructuralPatch::new().field(
    User::DISPLAY_NAME.as_str(),
    WriteCell::Value(InputValue::Text("Ada".to_string())),
);
db!()?.execute_trusted_structural_insert_batch(
    <User as icydb::traits::EntitySource>::ENTITY,
    vec![patch],
)?;
```

### 🔧 Changed

- Maintained typed-query and structural-write examples now use generated
  schema references instead of repeating entity and field strings.
- Schema-only `icydb-model` consumers remain runtime-independent and do not
  receive `FieldRef` constants. Renamed direct runtime dependencies continue
  to resolve through the existing macro path-rewriting boundary.

### 🧭 Migration Notes

- Applications with hand-written `Entity::FIELD` or `Entity::ENTITY` bridges
  should delete those implementations when adopting 0.239. The generated
  surface replaces them directly; no alias or compatibility layer is retained.
- Use `<Entity as icydb::traits::EntitySource>::ENTITY` whenever an entity
  source string is required. `Entity::ENTITY` remains convenient shorthand
  when `EntitySource` is in scope and no authored field is named `entity`.
  A field named `entity` is valid and generates the inherent `ENTITY`
  `FieldRef`; the fully qualified trait constant remains the unambiguous source.
- Generated constants contain source spelling only. Queries and writes still
  bind against the request's accepted schema snapshot and fail closed when a
  source is absent or stale.

### 📊 Audit

- Runtime behavior axes, accepted-schema authorities, mutable owners, caches,
  invalidation edges, persisted formats, Candid, and exports are unchanged.
- The implementation extends the existing entity/record macro emission path;
  it does not add a second query or structural-write route.
- Against exact `v0.238.0`, the SQL audit canister changes from 4,456,432 to
  4,459,680 final raw Wasm bytes (+3,248). Compiler-emitted Wasm changes from
  5,100,161 to 5,098,544 (-1,617), while deterministic gzip changes from
  1,731,736 to 1,731,319 (-417). Candid SHA-256 and the 70-export surface are
  unchanged.
- The complete slice touches 22 files with 552 inserted and 26 deleted lines,
  including its bounded design, tracker, release notes, maintained examples
  and focused proofs. Production generation/facade code adds approximately 80
  net lines with no runtime state or execution-path increase.
