# IcyDB 0.288

## [0.288.0] - 2026-10-28

### ⚠️ Breaking

- Split standalone memory construction from verification of a bound host runtime.
  Ordinary database access cannot create another allocator when host binding is
  missing. A standalone bootstrap refuses an existing binding before invoking
  its pool provider; composed verification preserves host allocations and policy.
  [#373 — Move generated canister endpoints into the Canic IcyDB adapter](https://github.com/dragginzgame/icydb/issues/373).
- Regenerate actors and select the matching `canic-icydb` adapter. Standalone
  lifecycle roots call generated `bootstrap_standalone_memory(icydb_memory_pool)`
  on init and post-upgrade. Manual native consumers must call it before database
  access; composed hosts bind the committed runtime instead. Endpoint mounting
  is now `canic_icydb::mount!`; partial participant declarations are rejected.

### 🧹 Cleanup

- Share activation lookup, candidate admission, enforcing/validating catalog
  transition and version assignment between unique-index and relation promotion.
  Each caller retains its typed candidate move, deterministic ordering and final
  snapshot validation. Not-null field/history rewriting remains separate. Cover
  both states and structural owner types, missing activations/candidates, wrong
  owners and preservation of the original snapshot on failed/successful promotion.
  [#546 — Activation promotions repeat the same state](https://github.com/dragginzgame/icydb/issues/546).
- Use one contiguous journal chunk traversal for complete batches and prefixes.
  Missing chunk zero, interior gaps and chunk-index overflow retain typed store
  corruption; reader errors still stop before advancing the chunk ordinal. Full
  reads retain fixed-header identity and exact-length validation, while prefix
  reads retain their maximum-byte bound without requiring a complete batch.
  Regression coverage checks empty and complete sequences, missing first/interior
  chunks, and the intentional difference for a valid truncated prefix.
  [#541 — Journal batch reads repeat the same chunks](https://github.com/dragginzgame/icydb/issues/541).
- Construct existing and generated schema-proposal store candidates through one

  named-type rejection and final namespace admission now have one owner. Existing
  ingress still applies and validates even empty removal batches and carries the
  resulting version advances; generated ingress rejects removals before traversal
  and finishes without removal advances. Preserve mixed entity-removal rejection.
  [#573 — Proposal stores repeat the same candidate](https://github.com/dragginzgame/icydb/issues/573).
- Delegate appended/retired journal batch, record and byte accumulation to
  IC Metrics `MeasurementCounter`. IcyDB retains only projection to the existing
  `u64` Wire report: an exact maximum remains valid, excess clips and reports

  Metrics remains optional behind the existing `metrics` feature. Cover every
