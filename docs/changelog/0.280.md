# 0.280

## [0.280.2]

### 🩹 Fixed

- Accept prefix-related unique indexes and filtered indexes in either declaration
  order. Prefix terms alone do not establish equivalent uniqueness constraints
  or filtered membership. Preserve each index in the generated proposal and
  keep ordinary unfiltered, non-unique prefix rejection unchanged. Existing
  valid schemas, runtime index enforcement and stored formats are unchanged
  ([#178 — Incorrect redundant-prefix index rejection](https://github.com/dragginzgame/icydb/issues/178)).
- Preserve accepted/candidate membership in the shared targeted-rule program.
  Integrity inspection evaluates the accepted operation even when its pending
  replacement has the same constraint ID. New writes still enforce both rules;
  historical activation validation still evaluates the candidate. After
  promotion or abort, integrity follows the resulting accepted catalog,
  including after schema reload. Public and stored formats remain unchanged
  ([#98 — Pending rule replacement falsely reports corruption](https://github.com/dragginzgame/icydb/issues/98)).
- Retain failed numeric configuration conversions as errors in application
  hooks. Comparisons, ranges, divisors and decimal-place validators report a
  visitor issue; clamp and decimal rounding return an error before changing
  the input. Valid settings, zero-based defaults and constructor signatures
  remain unchanged. These hooks remain separate from accepted database
  admission and persisted formats
  ([#73 — Unrepresentable validator and normalizer settings](https://github.com/dragginzgame/icydb/issues/73)).
- Materialize general intersections under the existing key-entry and temporary
  memory budgets before primary-key-ordered live pages consume their results.
  AND-of-OR predicates now return pages instead of an internal invariant error.
  Preserve ascending and descending order, authored limits and every continuation
  suffix. Cursorless reads retain their lazy intersection; public APIs, cursor
  bytes and stored formats are unchanged. This fallback may exhaust the request
  budget before returning a page when the intersection is large
  ([#53 — General intersections lack a live-page access bound](https://github.com/dragginzgame/icydb/issues/53)).

  ```sql
  SELECT id FROM PlannerRow
  WHERE (lane_a = 0 OR lane_b = 0) AND (lane_a = 1 OR lane_b = 0)
  ORDER BY id ASC;
  ```

- Retain the last emitted canonical group key before projection in both general
  and ordered grouped pagination. Limited queries such as
  `SELECT SUM(id) FROM PlannerRow GROUP BY rare LIMIT 1` no longer fail because
  their displayed columns omit grouping keys. Computed and reordered projections
  retain the same canonical continuation boundary. Preserve lookahead, HAVING,
  offsets, count specialization, cursor encoding and projected values; no stored
  format or public API changes. Correct the SQL subset guidance to match the
  existing admitted projection forms
  ([#49 — Grouped cursor uses projected keys](https://github.com/dragginzgame/icydb/issues/49)).

- Keep searched `CASE` expressions lazy when their conditions or results contain
  checked arithmetic or functions outside the existing boolean/unary-text
  families. Scalar filters, DELETE and HAVING reuse the existing
  conditional evaluator, so guards such as `CASE WHEN qty = 0 THEN FALSE ELSE
  6 / qty > 2 END` do not divide on the zero row. Selected numeric errors remain
  typed failures. Preserve bounded pure boolean expansion, three-valued results
  and request-budget error propagation. Omitted-ELSE HAVING checks its existing
  content bound independently of eager safety; no evaluator, cursor or stored format
  is added
  ([#74 — CASE rewrite evaluates unselected branches](https://github.com/dragginzgame/icydb/issues/74)).

### 📚 Documentation

- Correct browser-generation guidance to follow the workspace-selected registry
  IC Wire package, preserving IcyDB's concrete metadata and finite limits. Link
  the maintained browser qualification to its owning adoption outcome
  ([#372 — Qualify native Wire browser codecs](https://github.com/dragginzgame/icydb/issues/372)).
- Explain Canic's serving boundary: pre-handler request admission rejects,
  synchronous reply-encoding failure traps and rolls back the current message,
  and typed application errors remain encoded replies. Earlier messages and
  external effects across awaits retain their own recovery obligations
  ([#371 — Roll back mutations after reply-encoding failure](https://github.com/dragginzgame/icydb/issues/371)).

### 🧪 Testing

- Select the existing CLI observability report and endpoint-decoder suite in
  both native macOS jobs with the nonempty-test runner. Cover ASCII reports,
  wide/combining Unicode and control-bearing schema cells at IcyDB's actual
  report paths, complementing the existing diagnostic escaping controls. Host
  Text remains the table/terminal mechanics owner; no runtime or dependency
  change is introduced. Native qualification requires the delivered jobs to pass
  ([#362 — Qualify the CLI Host Text integration](https://github.com/dragginzgame/icydb/issues/362)).
- Cover maximum-u32 SQL limits and offsets through the installed Wire endpoint,
  comparing bounded controls across identity, primary-key, scalar and multi-field
  projections, both order directions, empty/populated selections and repeated
  calls. This qualifies the existing allocation clamp on wasm32 without changing
  query semantics or execution budgets
  ([#116 — Excessive scalar-page preallocation](https://github.com/dragginzgame/icydb/issues/116)).
- Extend the existing SQL instruction probe with identical cold and resident
  query calls around an update that persists the command cache. Record the
  canonical raw fixture Wasm bytes and its selected profile alongside the
  existing loop mean. These are session/SQL measurements on the same artifact;
  they exclude Wire serving, do not isolate parser cost or claim a release-size reduction
  ([#346 — Avoid reparsing resident SQL commands](https://github.com/dragginzgame/icydb/issues/346)).
- Check actual watchdog work after trapped recovery against the existing
  30-billion instruction ceiling, reporting the observed maximum on failure.
  Remove redundant IC-limit assertions from SQL and schema probes while keeping
  their typed results, counter checks and retained-state proofs. Label the dormant
  convergence probe's frozen reference and historical fit estimate separately
  from measured overhead; preserve its existing reserved-headroom bound. Current
  production fit comes from live callback samples. Runtime budgets and callback
  scheduling are unchanged
  ([#44 — Ineffective instruction-budget assertions](https://github.com/dragginzgame/icydb/issues/44)).

### 🥾 Governance

- Retire the partial-index SQL-depth report: accepted predicates already persist
  as bound trees, so generated declarations no longer render and reparse SQL
  during acceptance. The SQL frontend retains its own syntax bounds
  ([#199 — Rendered partial-index predicates exceed parser depth](https://github.com/dragginzgame/icydb/issues/199)).
- Consolidate remaining composed-memory acceptance from the delivered explicit
  request-factory adoption into the Canic adapter tracker. Preserve installed
  lifecycle, retained-data, application-Wasm and supported-host requirements;
  this tracking change does not claim composition is complete
  ([#355 — Explicit component memory requests](https://github.com/dragginzgame/icydb/issues/355),
  [#373 — Move generated endpoints into the Canic adapter](https://github.com/dragginzgame/icydb/issues/373)).

## [0.280.1] - 2026-10-21

### 🔧 Changed

- Refresh the canonical Shared Tooling snapshot to 0.26.2 and qualify the already
  selected published IC Tooling 0.63.2 Host, Build and Testkit packages. Keep
  library features narrow and prepare the existing binaries with explicit `cli`.
  Select ICP CLI, ic-wasm and wasm-opt for workstations, only wasm-opt for
  canister-build/browser CI, and ic-wasm plus wasm-opt for size reporting.
  Offline admission and compact failure retention use the same selections;
  tool pins, Wire protocols and Testkit server ownership remain unchanged.

### 📚 Documentation

- Explain that IC-generated ULIDs use predictable timestamp/sequence values,
  even after startup entropy is supplied. Public generation APIs and schema
  guidance require authorization independently of row IDs; private bearer
  tokens remain application-owned. Key generation and stored bytes are unchanged
  ([#265 — Predictable generated ULID keys](https://github.com/dragginzgame/icydb/issues/265)).

### 🩹 Fixed

- Reuse the bounded next-header lookup when retiring a complete journal batch,
  avoiding a copy of the next payload. Reject missing, malformed and miskeyed
  headers before publication. Keep complete validation of the retiring batch
  and of future payloads before consumption, including after reopening. Explicit
  integrity inspection still validates prior batches before trusting their IDs
  ([#175 — Retirement copies the next batch for its header](https://github.com/dragginzgame/icydb/issues/175)).
- Report rows above the existing 4 MiB encoded-row limit as unsupported input
  instead of an internal serialization failure. Preserve actual/maximum byte
  facts through public diagnostics and reject before any batch effects. Exact
  boundary rows remain valid; encoder inconsistencies remain internal failures
  ([#143 — Oversized rows reported as internal errors](https://github.com/dragginzgame/icydb/issues/143)).
- Start read instruction accounting at execution entry, so the first sample
  includes earlier executor work and short reads are charged at completion.
  Preserve the existing instruction ceilings, typed exhaustion facts and shared
  request counters; no endpoint or stored format changes
  ([#151 — Read instruction accounting starts too late](https://github.com/dragginzgame/icydb/issues/151)).
- Allow README runtime/build examples to retain the same deliberately selected
  supported release when workspace metadata advances. Both canonical release
  tags remain required, must match and cannot be newer than the workspace.
  Missing, malformed and conflicting selections still fail admission. Release
  preparation continues to preserve ordinary README source
  ([#361 — Build and Wasm tooling qualification](https://github.com/dragginzgame/icydb/issues/361)).

### 🧪 Testing

- Exercise both maintained startup counter projections at zero, one, the u64
  maximum, values above u64 and exact/overflowed u128 caps. Keep the audit trap
  and typed entity-fixture error policies; round-trip all six audit count fields
  at both wire boundaries and exercise entity snapshots across a same-Wasm upgrade
  ([#386 — Tracked startup fixture counters](https://github.com/dragginzgame/icydb/issues/386)).
- Run feature-enabled counter unit tests through the existing native-canister
  leaf in both local validation and the CI workspace lane. Keep their pure
  native execution independent of PocketIC server admission; actual installed
  subjects continue using Testkit.

### 🗑️ Removed

- Retire the standalone timer-primitive actor, its three integration subjects,
  duplicate snapshot records, five fixture methods and artifact policy. Published
  Timers 0.30.1 owns the corresponding exhaustion, trap/upgrade and overdue
  coalescing proofs. Database startup, schema/recovery and lifecycle-participant
  scenarios remain IcyDB-owned
  ([#379 — Retire duplicate timer-primitive probe](https://github.com/dragginzgame/icydb/issues/379)).

## [0.280.0] - 2026-10-21

### ⚠️ Breaking

- Public schema Principal conversions and read-authorization contexts now use
  the IC Platform 0.6.0 type identity. Consumers passing Platform values must
  adopt the same minor line. External Agent/PocketIC identities still convert
  explicitly. Principal text, Wire frames, binary Serde and stored formats are
  unchanged; no retained-data rewrite is required.

### 🔧 Changed

- Align the seven consumed Host, Build and Testkit packages on published IC
  Tooling 0.63.0. Their library profiles keep empty defaults; Build and Testkit
  no longer select Clap unless the separate CLI feature is requested. Existing
  filesystem custody, process admission, artifact budgets and Wire contracts
  retain their owners and behavior.
- Prepare and check the release editor and Testkit server CLI with `cli` through
  the existing installer. Saved release recovery derives the feature selection
  from its exact archived Build version: pre-0.63 editors retain their original
  recipe. Source and admission failures still stop before release callbacks;
  regressions cover both binary contracts and conflicting working selections.
- Testkit's removed Candid helpers and benchmark error type have no workspace
  callers. Native application calls continue using IcyDB's concrete IC Wire
  contracts over raw PocketIC transport. No Candid compatibility layer, benchmark
  conversion or new simulator lifecycle owner is introduced. Native PocketIC
  still selects Candid internally.
- Enable `principal` explicitly in the schema and public facade packages.
  Platform 0.6 no longer provides those types in an empty feature selection.
  Core and system-only fixtures retain `ic0`; runtime/client packages retain
  their existing profiles, which imply Principal when needed. No Candid,
  parser, entrypoint generator, codec or runtime fallback is added locally.
- Select the incoming Canic adapter revision `9505996`, which aligns its
  Timers requirement with registry 0.30.0 and the workspace's Metrics 0.15
  identities. The adapter still owns exports, entropy and lifecycle; its SDK
  migration remains separate. This selection is an immutable Git dependency,
  rather than a claim that the adapter exists in the local Canic main checkout.
  Refresh the two compile-fail diagnostic origins to that selected revision;
  malformed lifecycle declarations and guard calls retain their rejection checks.

### 🩹 Fixed

- Read startup watchdog counters through Timers' exact measurement totals and
  checked `u64` conversion. Overflow or values outside the existing audit reply
  range trap instead of supplying inexact evidence. The entity lifecycle fixture
  likewise retains its count fields and returns its existing invariant error
  when exact conversion fails. Reply schemas and Wire bytes retain their
  contracts; both fixture consumers build with Timers 0.30.1.
