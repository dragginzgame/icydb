## [0.280.4]

### 🩹 Fixed

- Validate proposed entity names against the runtime's existing 64-byte identity
  bound and ASCII case-insensitive uniqueness rule before publication. Check
  candidate bundles together with unchanged stores for initial, explicit and
  generated application, including migration rename reconciliation. Invalid
  proposals leave the accepted head, receipts, rows and indexes unchanged;
  64-byte names and unambiguous case-only renames remain supported. No public
  API, stored-format or recovery-policy change is needed
  ([#91 — Schema admission misses runtime entity-name rules](https://github.com/dragginzgame/icydb/issues/91)).
- Read the actual execution mode through IC Platform when admitting complete
  SQL Wire replies. Replicated queries use the IC's 2 MiB ceiling; ordinary
  queries retain the existing 3 MiB RPC allowance. Oversized successes return
  the existing typed response error before transport reply, preserving Wire
  framing, codec-resource refusals and the shared generated handler contract.
  Exact byte-boundary tests and an installed ordinary/replicated query pair
  cover both limits without adding endpoints, configuration or stored state
  ([#162 — SQL reply guard ignores replicated execution](https://github.com/dragginzgame/icydb/issues/162)).
- Require each registered store's row, index, schema and journal handles to be
  exclusive to its path. Reject partial sharing and journal reuse before adding
  the registration, preserving the original store and permitting a corrected
  retry with independent handles. Keep the existing store-invariant diagnostic;
  stable-memory ID/key collision checks remain with database-format convergence.
  Heap and journaled registration coverage includes every sharing combination;
  no public API, stored-format or memory-ownership migration is needed
  ([#202 — Store registrations accept partially shared storage](https://github.com/dragginzgame/icydb/issues/202)).
- Apply the existing scalar key capabilities when constructing or decoding
  entity fragments. Primary-key fields must be non-null exact scalar keys;
  collection, named and non-keyable scalar fields are refused, and Unit remains
  valid only as a sole-field key. Preserve supported scalar widths, compound
  key order, ordinary-field policies and valid canonical transport bytes.
  Invalid declarations return the existing typed field-policy error before
  proposal composition; accepted row formats and recovery behavior are unchanged
  ([#189 — Schema fragments accept invalid primary-key shapes](https://github.com/dragginzgame/icydb/issues/189)).
- Preserve store-wide index readiness during ordinary and atomic-progress row
  commits. Remove the per-write registry scan and Ready promotion; recovery and
  complete index-domain replacement retain readiness ownership. Commit closure
  now ends the row write without a later fallible access-state publication.
  Heap/journaled coverage includes insert, update, replacement, delete, typed
  batches, interrupted writes and recovery, with stable readiness revisions
  until the lifecycle owner completes. Public APIs and stored formats are
  unchanged; IC cycle/instruction and Wasm-size deltas remain unmeasured
  ([#153 — Row commits promote an entire index to Ready](https://github.com/dragginzgame/icydb/issues/153)).
- Make the published commit guard own its captured recovery wake-up through
  normal early exits, apply errors and marker-clear failures. Successful marker
  retirement disarms the callback only when no journal debt remains; retained
  journal work still requests convergence. Consolidate the existing error-path
  scheduling without changing typed errors, marker bytes, replay authority or
  IC trap rollback. No public API or stored-format change is needed
  ([#140 — Commit guard early exits can miss recovery wake-ups](https://github.com/dragginzgame/icydb/issues/140)).

  ([#100 — Wide check findings exceed the receipt field limit](https://github.com/dragginzgame/icydb/issues/100)).
