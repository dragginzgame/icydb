# 0.271 — Accepted schema storage

## [0.271.0]

### 💥 Breaking

- Adopt selected Metrics 0.7: accumulated entity, schema-owner and journal-fold
  totals are Rust `u128` and Candid `nat`; individual observations, counts and
  maxima remain `u64`/`nat64`. The CLI decodes and renders wide totals and means
  without narrowing. Regenerate current metrics bindings and use the matching
  CLI. Heap-only metrics still clear on reset/upgrade; no stable format or
  compatibility decoder is introduced
  ([#350](https://github.com/dragginzgame/icydb/issues/350)).
- Store accepted entity schemas once, inside the bundle selected by the accepted
  root. Remove namespace-0 entity/version copies, their `ICYDBCAT` frame, and
  standalone journal discriminator 3 (`SchemaPut`), including replay, fold,
  overlay and effect-verification consumers. The retired identities are not
  reused. Existing accepted bundle/root, row, index, Identity, activation and
  progress formats retain their current encodings and recovery
  ([#214](https://github.com/dragginzgame/icydb/issues/214)).
- The maintainer confirmed database deletion/recreation for this pre-1.0 cut.
  Recreate all affected databases before running 0.271; superseded database
  images, pending recovery records and backups are not upgrade inputs. No
  compatibility reader, translator or deployment reset is included.

### 🗃️ Storage

- Derive data, index and schema allocation metadata from the selected accepted
  bundle, preserving existing role domains, version selection and fingerprint
  encoding. Storage reports no longer scan a separate catalog copy. Publication
  and prepared folds retain only the accepted bundle/root and operational
  controls; stale candidates cannot publish a partial bundle or Identity effect
  ([#214](https://github.com/dragginzgame/icydb/issues/214)).

### 🩹 Fixed

- Stop refresh before deployment when its installation probe reports an error.
  Preserve the existing installed/uninstalled mode selection and stop fixture
  loading after a failed deployment; a failed probe no longer falls through to
  ordinary deployment
  ([#127](https://github.com/dragginzgame/icydb/issues/127)).
- Ctrl-D or EOF exits the SQL shell and discards unfinished input instead of
  submitting it to a canister or history. Completed semicolon-terminated
  statements still run, including before an unfinished pasted suffix. Piped
  shell input uses the same completion rule; one-shot SQL remains independent
  ([#47](https://github.com/dragginzgame/icydb/issues/47)).
- Complete the public read inventory with metadata-only exact counts and
  bounded typed exact-key batches. Document their separate admission proofs,
  request charging and endpoint response responsibility; extend the existing
  read-admission guard through their public facade handoffs
  ([#193](https://github.com/dragginzgame/icydb/issues/193)).
- Correct refresh guidance: the CLI deploys or reinstalls before calling
  `icydb_fixtures_load`. A missing endpoint or failed fixture call returns an
  error after that step; reinstall has already cleared stable memory. The
  default ICP environment remains `local` unless `ICP_ENVIRONMENT` is set.
  Runtime behavior is unchanged
  ([#130](https://github.com/dragginzgame/icydb/issues/130)).
- Adopt reviewed Shared Tooling 0.8.1 with explicit snapshot entrypoints and
  transitive companion selection. Keep directly used helpers, CI actions and
  maintained governance documents selected; unchanged obsolete payloads can
  retire through the canonical exporter. Select and explicitly prepare
  `cargo-sort-derives` 0.14.1, preserving literal `$crate` paths during direct
  and conditional derive sorting. Contributor setup changes do not change
  library APIs, storage formats or consumer MSRV
  ([#302](https://github.com/dragginzgame/icydb/issues/302),
  [Shared #131](https://github.com/dragginzgame/shared-tooling/issues/131),
  [Shared #113](https://github.com/dragginzgame/shared-tooling/issues/113)).
- Reject malformed snapshot fields consistently while retaining valid filenames
  with spaces. Failed Cargo-tool activation retains both build-identity
  observations, names changed fields and preserves the previous selection;
  no automatic rebuild or second installer is added
  ([#302](https://github.com/dragginzgame/icydb/issues/302),
  [Shared #133](https://github.com/dragginzgame/shared-tooling/issues/133),
  [Shared #134](https://github.com/dragginzgame/shared-tooling/issues/134)).
- Preserve Timers 0.19's wide accumulated work and scheduler instruction totals
  in the populated migration and SQL audit startup snapshots, matching decoders
  and recovery observations. Counts and per-callback maxima remain
  `u64`/`nat64`; totals use `u128`/Candid `nat`, allowing audit, recovery,
  rename and entity-creation actors to build with the selected timer dependency
  ([#350](https://github.com/dragginzgame/icydb/issues/350)).
- Resolve SQL coverage evidence from the moved mutation test's current module
  and refresh the canonical Tier C manifest digest. Provider identities,
  evidence requirements and SQL semantics are unchanged. Regenerate Tier C
  receipts for the current manifest before merging evidence
  ([#236](https://github.com/dragginzgame/icydb/issues/236)).
- Propagate Timers 0.18's explicit initial schedule through all four direct
  registration calls in the startup probe, lifecycle participant and SQL audit
  canister. Registration arms the first deadline atomically; remove immediate
  separate arming while preserving the SQL audit's later retained rearming.
  Cadences, identities, callbacks and endpoint schemas remain unchanged.
- Check mutation-job policy bounds during compilation rather than in a callable
  constant function. Preserve current scan limits and checkpoint policy identity
  while satisfying the production-panic guard without weakening its checks
  ([#348](https://github.com/dragginzgame/icydb/issues/348)).
- Adopt reviewed Shared Tooling 0.6.5 and its common Make entrypoint. Preserve
  IcyDB's full derive-sort/manifest-sort/rustfmt policy through paired command
  inputs, removing duplicate formatting and hook recipes. Shared snapshot
  admission is a portable-gate prerequisite. Validation checkpoints the selected
  manifest, lockfile and compiler inputs and stops later stages if they drift;
  staged formatting uses prepared receipts against the exported inputs
  ([#302](https://github.com/dragginzgame/icydb/issues/302),
  [Shared #130](https://github.com/dragginzgame/shared-tooling/issues/130),
  [Shared #129](https://github.com/dragginzgame/shared-tooling/issues/129)).
- Explicit Cargo-tool setup stops on lock,
  verification or activation failure and preserves its original exit status and
  retained attempt. Padded native build counts are accepted. Existing common
  and selected Testkit setup commands retain their single shared owner
  ([#302](https://github.com/dragginzgame/icydb/issues/302),
  [Shared #120](https://github.com/dragginzgame/shared-tooling/issues/120),
  [Shared #124](https://github.com/dragginzgame/shared-tooling/issues/124)).
- Interrupted direct release preparation can restart from a clean descendant
  containing its metadata disposition, retaining the earlier plan and requiring
  fresh validation. Source conflicts identify the saved and current revisions;
  exact staged or delivered releases retain their existing reconciliation rules
  ([#299](https://github.com/dragginzgame/icydb/issues/299),
  [Shared #126](https://github.com/dragginzgame/shared-tooling/issues/126)).
- Adapt native optimizer and report capture to Host 0.14's required completion
  status. Require a successful exit before parsing command output or publishing
  Wasm, including a producer that emits a valid header and then fails. Preserve
  captured failure and cleanup evidence through Host's existing success policy
  ([#307](https://github.com/dragginzgame/icydb/issues/307),
  [Host #66](https://github.com/dragginzgame/ic-host-tooling/issues/66)).

Contributor tooling changes leave published library APIs, consumer MSRV,
stored formats, optimizer selection and Testkit's sole PocketIC ownership
unchanged. Rerun explicit common/selected setup and offline admission after
the prior Shared 0.6.0 setup refusal; no legacy installation fallback is added.

### 🔧 Changed

- Keep SQL CHECK syntax lowering in the SQL frontend and reuse the existing
  schema-owned input, field-ID binder, literal admission and canonical check
  semantics for generated declarations. Catalog publication consumes accepted
  checks, index snapshots and constraint identities, with frontend-neutral
  private requests and entrypoints. Current SQL constraint provenance and
  activation/recovery behavior remain intact
  ([#238](https://github.com/dragginzgame/icydb/issues/238)).
- Move finite execution/request accounting, primitive construction and retained
  cache weight into one neutral internal resource owner. Lower layers borrow
  that owner directly; query expression adapters and executor plan/row
  attribution retain their existing semantic owners. Preserve fixed profiles,
  policy identity, precharges, failure reserves, rejected-work accounting,
  instruction checkpoints and weak cache-weight lifetime; no new policy or
  accounting trait is introduced
  ([#237](https://github.com/dragginzgame/icydb/issues/237)).
- Keep one executor-owned structural mutation coordinator and compiled accepted
  catalog authority. Session APIs lower intents and prepare results or durable
  progress, preserving identity allocation, replacement/existence rules,
  constraints, exact staging bounds, atomicity and interruption recovery. Move
  four inline test modules into ordinary files under the existing test tree;
  retain the single workspace, packages, public APIs and stored formats
  ([#236](https://github.com/dragginzgame/icydb/issues/236)).

- Keep durable mutation-job checkpoint encoding, authority-bound advances and
  Forward/Verify scans with the executor mutation owner. SQL retains accepted
  scope/fixed-patch preparation; session retains job admission, exact replay and
  authority/cache lookup. The engine calls the existing structural coordinator
  directly, preserving policy identities, timestamps, current checkpoint bytes,
  packing and atomic progress/recovery
  ([#348](https://github.com/dragginzgame/icydb/issues/348)).
- Keep SQL parser/lowering/DDL diagnostic conversion with the frontend and the
  prepared-plan EXPLAIN adapter with its executor-owned type. Query keeps its
  error taxonomy and logical projection. Numeric codes, facts, field context,
  renderings and public APIs are unchanged
  ([#349](https://github.com/dragginzgame/icydb/issues/349)).

### 📊 Audit

- The schema-storage cut affects 13 Rust source files with -1,202 net lines,
  including removed duplicate-copy fixtures. One selected accepted bundle
  replaces the second persisted schema owner and standalone journal recovery
  path. No new state, mode or package is introduced; matched raw Wasm,
  instruction and cycle deltas are unmeasured
  ([#214](https://github.com/dragginzgame/icydb/issues/214)).
- The ownership cleanup affects approximately 240 core source paths, mainly
  mechanical imports and moves, with a net increase of 86 Rust lines.
  The session write frontend shrinks from 9,513 to about 1,130 lines; moved
  tests are retained, not counted as deleted machinery. No independent mode,
  persisted state, execution route or public symbol is added. Matched raw Wasm,
  IC instruction and cycle deltas are unmeasured. Broad workspace/release gates
  and native macOS execution remain user-owned qualification.

- The follow-up engine/adapter move affects 13 Rust source paths with +32 net
  lines. SQL mutation-job preparation shrinks from 2,016 to 131 lines as the
  maintained engine and tests move to their owner. The temporary
  `PreparedResumableUpdateStart` carrier is removed; its facts already reside in
  accepted catalog authority, the fixed patch and current intent/checkpoint.
  The broader prior footprint above describes its separately recorded batch.
