# IcyDB 0.224 — Coherent SQL Introspection Surfaces

## 0.224.1

This patch prevents a reachable accepted schema from producing an
undeliverable generated SQL query success. It preserves every schema and
projection maximum and returns a typed response error instead of truncating,
paging, or trapping at the IC reply boundary. It also corrects the evidence
used to close the 0.224 line.

### 🩹 Fixed

- Generated `icydb_query` handlers now measure the exact complete successful
  Candid envelope against the 3-MiB public query-reply limit. Oversized
  successes return
  `RUNTIME_BOUNDARY_SQL_QUERY_REPLY_BYTES_EXCEEDED` with response origin while
  leaving stored rows unchanged.
- The compact-column bound is documented as the 65,792-row algebraic
  allocation ceiling rather than an asserted reachable accepted maximum. A
  real 310,861-byte persisted schema now proves a reachable 24,416-row,
  3,693,110-byte compact result.
- Accepted-default coverage now publishes a real long default and verifies its
  bounded byte-count/hash fallback through both compact commands.
- The frozen `SHOW RELATIONS` comparison now encodes exactly three direct
  maintained relation DTOs. The corrected contract is 456 Candid bytes and
  remains below its unchanged 512-byte ceiling.

### ⚠️ Breaking

- The public diagnostic registry adds raw code 279 and the corresponding
  `RuntimeBoundaryCode` variant. Rust consumers with exhaustive diagnostic
  matches must handle it. Public SQL result shapes, Candid labels, persisted
  formats, exported methods, and method modes are unchanged.

### 🧪 Testing

- Focused native and PocketIC regressions prove exact complete-envelope
  measurement, typed oversized-reply recovery, accepted-schema reachability,
  accepted-default authority, and successful queries after rejection.
- The corrected seven-case introspection matrix remains within every frozen
  instruction and response-size ceiling, including the like-for-like direct
  relation gate.

### 📊 Audit

- Focused measurements put one-entity SQL at 2,936,482 raw Wasm bytes (+70)
  and SQL performance at 4,069,134 bytes (-712). Deterministic gzip remains
  secondary context.
- The correction adds no persisted state, result variant, endpoint, executor,
  paging mode, or caller-tunable policy. It adds one typed fail-closed boundary
  outcome and one generated-handler preflight.

## 0.224.0

This release makes routine SQL schema inspection compact and predictable while
preserving the complete operational dossier behind explicit `VERBOSE` syntax.
All results come from the accepted schema snapshot, with deterministic ordering
and bounded typed responses.

### ➕ Added

- `DESCRIBE entity` and `SHOW COLUMNS entity` return the same conventional
  six-column summary: name, type, nullability, index hint, accepted insert
  default, and closed extra flags.
- `SHOW RELATIONS FROM entity` and its `IN` spelling return accepted relation
  rows in stable relation order, including qualified target paths and the
  existing closed `Single`, `List`, or `Set` cardinality.

```sql
SHOW RELATIONS FROM Card;
```

- Public SQL results now expose explicit compact/verbose envelopes and closed
  typed values for index hints, defaults, and extra facts.

### 🔧 Changed

- `DESCRIBE entity` is now compact by default. `DESCRIBE entity VERBOSE`
  preserves the complete pre-0.224 dossier, including identity, row layouts,
  fields, indexes, relations, constraints, and validation progress.
- `SHOW COLUMNS entity` is compact by default. `SHOW COLUMNS entity VERBOSE`
  preserves the detailed field/layout table without becoming an alias for the
  complete dossier.
- Compact columns share one accepted-schema projector. Top-level fields follow
  stable field-ID order, nested paths follow canonical dotted-path order, and
  compound unique-index members render `MUL` rather than implying independent
  uniqueness.
- Nested nullability includes nullable ancestors. Default values come only
  from accepted insert behavior, and extra flags use the fixed `Identity`,
  `Generated`, then `Relation` order.
- Compact `DESCRIBE` uses 347,976 instructions on the frozen representative
  fixture, 57,904 fewer than the former full-dossier default. Every frozen
  instruction and response-size ceiling passes.

### ⚠️ Breaking

- `SqlQueryResult::Describe` now contains `SqlDescribeOutput`, and
  `SqlQueryResult::ShowColumns` now contains `SqlShowColumnsOutput`. Rust and
  Candid consumers must match the explicit `Compact` and `Verbose` variants.
- Shell scripts that relied on the former multi-section `DESCRIBE` output must
  add `VERBOSE`. Consumers that expected detailed `SHOW COLUMNS` rows must do
  the same.
- This is a pre-1.0 hard cut: there is no alias, compatibility decoder, or
  fallback for the retired result shapes. No persisted schema, row, index,
  journal, or cursor migration is required, and no exported method or method
  mode changes.

### 🧪 Testing

- A named golden freezes the complete pre-0.224 verbose typed result, canonical
  Candid, relation projection, and shell rendering.
- Focused coverage proves compact/verbose parsing and execution, positional
  equality between compact commands, accepted identity/default/index facts,
  relation syntax, typed missing-entity behavior, maximum and max-plus-one
  bounds, exact public Candid envelopes, the maintained endpoint ABI, and an
  invalid-diagnostic-code boundary derived from the current registry maximum.
- Focused native, live PocketIC, warning-denied lint, compile-surface,
  performance, formatting, Candid, export-mode, and four Wasm-report checks
  pass. Repository-wide validation remains part of the push workflow.

### 📊 Audit

- Raw final Wasm changes are +5 bytes for the dynamic-query control, +12 for
  the typed-query control, +19,055 for the SQL subject, and +31,216 for the SQL
  performance subject. Deterministic gzip remains secondary context.
- The 0.224 line changes approximately `+2,367/-268` lines across 42 maintained
  implementation, test, fixture, documentation, and evidence files. It adds no
  persisted state, mutation route, caller-tunable policy, exported endpoint,
  compatibility path, or second executor.
