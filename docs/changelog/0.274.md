# 0.274 — Canonical runtime contracts

## [0.274.1]

- Adopt Shared Tooling 0.13.3 with the reviewed fixture-probe extension,
  preserving the complete failure/retention roster and common tool selections.
  Shared completion admission and cleanup retain one owner
  ([#302 — Shared Tooling adoption](https://github.com/dragginzgame/icydb/issues/302)).

- Share bounded hexadecimal decoding between SQL blobs, scalar conversion and
  integrity IDs. Preserve allocation limits, diagnostic precedence, case,
  empty blobs and exact nonzero job identities; remove duplicate digit decoders
  ([#363 — Consolidate Core hex decoding](https://github.com/dragginzgame/icydb/issues/363)).

- Separate canister build and Wasm report tooling into the unpublished
  `icydb-testing-build` package in the existing workspace. Keep the PocketIC
  harness in integration and update build/report callers and CI directly.
  Preserve artifact, endpoint and report contracts
  ([#361 — Separate build/report support](https://github.com/dragginzgame/icydb/issues/361)).

- Reuse Host's method-mode type while retaining IcyDB's oneway rejection.
  Share Subaccount hex parsing in Schema, preserving exact bytes and optional
  `0x` defaults consistently in macros and sealed fragments; remove duplicate
  decoders
  ([#307 — Reuse Host owners](https://github.com/dragginzgame/icydb/issues/307),
  [#181 — Preserve literal diagnostics](https://github.com/dragginzgame/icydb/issues/181)).

- Follow Memory 0.38's current private allocation-policy contract and nested
  allocation summary in bootstrap fixtures. Remove obsolete no-op hooks;
  preserve IcyDB's explicit request factories, host pool, cold bootstrap and
  warm adoption contracts
  ([#355 — Maintain explicit Memory component admission](https://github.com/dragginzgame/icydb/issues/355)).

- Move buffered primary/index keys to their consumers instead of cloning them.
  Freeze primary raw keys once during decoding and copy only the final chunk
  boundary. Preserve ordering, continuation, physical-entry charging and typed
  corruption; direct row visitation keeps its existing owner
  ([#264 — Reduce physical scan key copies](https://github.com/dragginzgame/icydb/issues/264)).

- Reject malformed identity defaults and unrepresentable generated predicate
  literals with spanned compiler errors. Share literal parsing between validation
  and lowering; construct valid identity defaults directly from canonical bytes
  and propagate lowering failures without proc-macro panics. Map-shape errors
  identify the annotated declaration. Authoring syntax, valid values and
  persisted/wire contracts stay unchanged
  ([#181 — Preserve macro literal diagnostics](https://github.com/dragginzgame/icydb/issues/181)).

- Consume the canonical Cargo/post-link batch reports directly, preserving
  ordered identity, complete failure diagnostics and retained artifact ownership.
  Remove the intermediate report type and normalization pass
  ([#307 — Adopt split host owners in CLI and artifact helpers](https://github.com/dragginzgame/icydb/issues/307)).

- Reuse the shared exit injector for all maintained tooling fixtures, preserving
  the 126-case failure/completion roster and diagnostic-failure case. Pin the
  reviewed committed extension for IcyDB's fixture root names
  ([Shared #174 — Share fixture exit and retained-evidence probes](https://github.com/dragginzgame/shared-tooling/issues/174)).

- Use the shared regular-file opener for diagnostic artifacts and source
  metadata. Refuse Unix FIFOs before waiting for a writer, including through
  symlinks. Preserve regular-file symlink selection, the independent byte bound,
  provenance/schema validation and descriptor-relative publication
  ([#307 — Adopt split host owners in CLI and artifact helpers](https://github.com/dragginzgame/icydb/issues/307)).

- Continue diagnostic lookup through exact source metadata or numeric output
  when a live schema report cannot be validated. Preserve the warning, exact
  artifact priority and fail-closed validation of explicitly supplied files
  ([#134 — Preserve diagnostic fallback](https://github.com/dragginzgame/icydb/issues/134)).

- Correct the completed CLI feature baseline to queries, opt-in UPDATE,
  DDL and inspection. INSERT/DELETE dispatch remains unimplemented, with its
  intended 1.0 scope explicitly outstanding
  ([#242 — Correct CLI INSERT/DELETE completion claims](https://github.com/dragginzgame/icydb/issues/242)).

- Adopt the selected Testkit 0.40 fixture API: call the shared Candid extension
  on borrowed PocketIC with explicit canister identity. Move SQL fixture reuse
  to Testkit's recipe/baseline pool, preserving the existing 8/4 capacities and
  preserve-funding policy. Retain the managed instance/server owner through
  installation and direct fixture calls. Share borrowed-instance helpers between fresh and
  pooled tests, without recreating removed forwarding methods or a pool owner.
  Add a real write/restore/readback control. Production endpoints, database
  semantics and persisted formats are unchanged; Testkit retains simulator
  setup, admission and lifecycle ownership
  ([#302 — Adopt common repository-local IC tools](https://github.com/dragginzgame/icydb/issues/302)).

- Reject empty enum definitions, invalid local kinds in enum payloads and
  composite members, and nullable newtype elements before they become accepted
  catalog authority. Construction and codecs reuse the existing bounded kind
  validator; valid wire bytes, recursive references, and record/tuple nullability
  are preserved. Malformed persisted definitions return typed corruption
  ([#200 — Reject invalid catalog definitions](https://github.com/dragginzgame/icydb/issues/200)).

- Adopt committed Shared Tooling 0.12.5 with strict numbered, top-positioned
  release candidates and current delivered-source acceptance evidence. Reuse
  shared cleanup/failure retention in release lock, pin and note fixtures;
  remove empty detailed-note synthesis. Host/IC admission and CI failure-evidence
  collection use their shared owners. Tool catalogs, compiler selections and
  Testkit ownership are preserved. Native acceptance remains separately owned
  ([#302 — Adopt common repository-local IC tools](https://github.com/dragginzgame/icydb/issues/302)).

- Qualify the already selected IC Build 0.3 cache API. Its retired watched-input
  API has no IcyDB callers; descriptor locks and verified destination copying
  stay with upstream owners. Preserve existing single/batch build identity,
  retained outputs and partial-failure isolation
  ([#302 — Adopt common repository-local IC tools](https://github.com/dragginzgame/icydb/issues/302)).

- Document SQL DDL version intent, its position before filtered-index `WHERE`,
  no-op and validation-job distinctions, INSERT SELECT, verbose execution EXPLAIN
  and wide integer byte modifiers. Clarify that COUNT DISTINCT star rejects
  during lowering. Conflicting ADD COLUMN nullability still requires a separate
  parser acceptance correction ([#230 — Align SQL subset grammar documentation](https://github.com/dragginzgame/icydb/issues/230)).

- Preserve dotted nested paths in verbose field descriptions so repeated leaf
  labels remain distinguishable under their parent field. Compact columns keep
  their canonical full paths. Describe nested relation traversal as `List` when
  it visits lists or map values, `Set` for set-only traversal, and `Single` when

  since they constrain only matching rows; unconditional unique indexes retain

  ([#201 — Correct nested DESCRIBE output](https://github.com/dragginzgame/icydb/issues/201)).

- Share one product-owned Wasm subject roster between Rust admission and portable
  shell reports. Preserve canonical order, the default subset and explicit-only
  group-path actor. Reused-artifact audits remain independent of Cargo and tool
  downloads. Use IC Metrics' checked scaled ratio for post-link basis points,
  preserving floor rounding, zero/growth rejection and local thresholds while
  accepting representable full-width size ratios
  ([#307 — Shared tooling owners](https://github.com/dragginzgame/icydb/issues/307)).

- Preserve the current allocation diagnostics DTO when consuming Memory 0.37:
  project existing totals from its summary and detailed entries from its row

- Adopt committed Shared Tooling 0.12.8 while retaining the reviewed fixture
  extension. Refresh required setup/change-selection guides and release-document

  ([#302 — Shared tooling adoption](https://github.com/dragginzgame/icydb/issues/302)).

- Qualify the selected Host 0.18 and Testkit 0.41 graph. Existing diagnostic-file,

## [0.274.0] - 2026-10-13

### ⚠️ Breaking

- Remove the public `IndexStore::clear` reset. Use maintained database mutations
  or schema-owned index retirement/rebuild rather than changing index visibility
  independently of stored rows. Generated store constructors and read-only
  inspection remain available; commit, journal and recovery retain mutation
  ownership ([#240](https://github.com/dragginzgame/icydb/issues/240)).

- Replace the accepted schema snapshot profile with `ICYISNP\0`, version 1,
  and one ordered index-key item list for field-only, expression and mixed keys.
  Retire the prior `ICYUSNP\0` reader. Recreate affected databases before
  deploying this release; upgrading retained databases or restoring prior images
  is unsupported. Startup/replay rejects retired profiles rather than clearing
  storage or rebuilding runtime authority from generated models
  ([#358](https://github.com/dragginzgame/icydb/issues/358)).

### 🩹 Fixed

- Make repeated `VALIDATE CONSTRAINT ... AFTER page_sequence` acknowledgements
  resume safely when the finding page was already consumed. A different held
  page is returned unchanged until its exact sequence is acknowledged. CHECK,
  NOT NULL and UNIQUE validation retain their existing bounded progress and
  publication owners ([#208](https://github.com/dragginzgame/icydb/issues/208)).

- Fix macOS CI ShellCheck failures by following the shared installers' sourced
  helper. Keep the selected warning checks active and the immutable shared
  payload intact ([#302](https://github.com/dragginzgame/icydb/issues/302)).

- Make startup observation and admission agree on fresh control memory.
  Nonempty pages without a valid boot record fail with the existing typed
  database-control cause instead of appearing to need recovery. Fresh memory
  verification scans at most one page and does not write a receipt or mutate
  control memory ([#147](https://github.com/dragginzgame/icydb/issues/147)).

- Reject column rename and SET/DROP DEFAULT changes with the existing typed
  `LiveActivation` catalog cause while constraint validation is pending or
  running, before rebuilding metadata can lose candidate owners. Complete or
  abort validation before changing those fields; exact SQL no-ops are unchanged
  ([#211](https://github.com/dragginzgame/icydb/issues/211)).

- Reject persisted active relations whose IDs are repeated or out of order
  before proposal construction can sort them. Canonical snapshot and accepted
  bundle bytes retain their current format; proposal sorting remains supported
  ([#215](https://github.com/dragginzgame/icydb/issues/215)).

- Use registry IC Build 0.2.3 and the explicit Host 0.17 `candid-service`
  profile in native integration; retire the redundant Host 0.16 dependency graph.
  Retain Candid extraction and interface checks while the ordinary CLI dependency
  profile remains parser-free
  ([#307](https://github.com/dragginzgame/icydb/issues/307)).

- Run both public DELETE lanes through existing shared SQL preparation before
  classification. Policy and execution use the same normalized statement,
  preserving aliases, case-insensitive qualifiers and RETURNING fields while
  retaining primary-key, window, scan and write limits. Invalid qualifiers and
  unbound inputs reject before effects
  ([#218](https://github.com/dragginzgame/icydb/issues/218)).
- Correct the persisted-format inventory and witness documentation: Deep
  integrity checks diagnose stale secondary entries; startup replays admitted
  journal effects and does not repair the whole index. The witness wire is
  unchanged; removing the unwritten `Missing` state remains a separate hard cut
  ([#245](https://github.com/dragginzgame/icydb/issues/245)).

### 🔧 Changed

- Adopt Shared Tooling 0.11.1 snapshot-owned common tool catalogs with existing
  versions/digests, compiler selections and Testkit ownership unchanged. Reuse
  Cargo CI caches across unrelated literal catalog edits; retain tool/build
  invalidation, recovered failed-job logs and filesystem/path diagnostics.
  Route CI installation through the common installer, retire obsolete per-tool
  wrappers and reuse shared fixture cleanup and release tag checks.
  Qualify the already-selected Host 0.17.2 CLI and artifact/Candid consumers
  ([#357](https://github.com/dragginzgame/icydb/issues/357),
  [#307](https://github.com/dragginzgame/icydb/issues/307)).

- Adopt Metrics 0.9 producer overflow getters. Existing report fields, tracked
  overflow semantics, exact means and Candid output remain unchanged.

- Reuse the accepted contract’s frozen slot count for current-layout row opens;
  retain historical counting and corruption rejection for invalid layouts/counts.
  Keep the fixed page-output reservation at compile time instead of rebuilding
  it for each candidate. No retained state, budget limits or persisted encoding
  changes; broader row-cache and candidate-accounting work remains separate
  ([#257](https://github.com/dragginzgame/icydb/issues/257),
  [#293](https://github.com/dragginzgame/icydb/issues/293)).

### 🧹 Cleanup

- Prepare accepted index predicates and key/predicate dependency masks once in
  the existing synchronous commit context, shared by every row and both index
  families. Keep metadata bound to its accepted row contract; per-row membership,
  after-image admission, uniqueness and mutation deltas retain their existing
  behavior. No global cache, execution mode or persisted change is added
  ([#344](https://github.com/dragginzgame/icydb/issues/344)).

- Reuse accepted live-write readers across patching and row constraints; carry
  canonical row images into the common index/relation commit planner. Persisted
  replay and rebuild keep independent bounded admission. Reuse admitted scalar
  views and canonical structural values in the existing row cache, removing
  redundant decoding and conversion without another cache
  ([#114](https://github.com/dragginzgame/icydb/issues/114),
  [#115](https://github.com/dragginzgame/icydb/issues/115)).
- Derive field/index candidates through the existing snapshot owner, preserving
  unrelated catalog and allocator state by construction. Existing activation,
  physical-domain and publication checks remain in force
  ([#359](https://github.com/dragginzgame/icydb/issues/359)).
