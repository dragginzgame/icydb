# 0.274 — Canonical runtime contracts

## [0.274.0] - 2026-10-13

### ⚠️ Breaking

- Remove the public `IndexStore::clear` reset. Use maintained database mutations
  or schema-owned index retirement/rebuild rather than changing index visibility
  independently of stored rows. Generated store constructors and read-only
  inspection remain available; commit, journal and recovery retain mutation
  ownership ([#240](https://github.com/dragginzgame/icydb/issues/240)).

- Replace the accepted schema snapshot profile with `ICYISNP\0`, version 1,
  and one ordered index-key item list for field-only, expression and mixed keys.
  Retire the prior `ICYUSNP\0` reader. Recreate affected databases before
  deploying this release; upgrading retained databases or restoring prior images
  is unsupported. Startup/replay rejects retired profiles rather than clearing
  storage or rebuilding runtime authority from generated models
  ([#358](https://github.com/dragginzgame/icydb/issues/358)).

### 🩹 Fixed

- Make repeated `VALIDATE CONSTRAINT ... AFTER page_sequence` acknowledgements
  resume safely when the finding page was already consumed. A different held
  page is returned unchanged until its exact sequence is acknowledged. CHECK,
  NOT NULL and UNIQUE validation retain their existing bounded progress and
  publication owners ([#208](https://github.com/dragginzgame/icydb/issues/208)).

- Fix macOS CI ShellCheck failures by following the shared installers' sourced
  helper. Keep the selected warning checks active and the immutable shared
  payload intact ([#302](https://github.com/dragginzgame/icydb/issues/302)).

- Make startup observation and admission agree on fresh control memory.
  Nonempty pages without a valid boot record fail with the existing typed
  database-control cause instead of appearing to need recovery. Fresh memory
  verification scans at most one page and does not write a receipt or mutate
  control memory ([#147](https://github.com/dragginzgame/icydb/issues/147)).

- Reject column rename and SET/DROP DEFAULT changes with the existing typed
  `LiveActivation` catalog cause while constraint validation is pending or
  running, before rebuilding metadata can lose candidate owners. Complete or
  abort validation before changing those fields; exact SQL no-ops are unchanged
  ([#211](https://github.com/dragginzgame/icydb/issues/211)).

- Reject persisted active relations whose IDs are repeated or out of order
  before proposal construction can sort them. Canonical snapshot and accepted
  bundle bytes retain their current format; proposal sorting remains supported
  ([#215](https://github.com/dragginzgame/icydb/issues/215)).

- Use registry IC Build 0.2.3 and the explicit Host 0.17 `candid-service`
  profile in native integration; retire the redundant Host 0.16 dependency graph.
  Retain Candid extraction and interface checks while the ordinary CLI dependency
  profile remains parser-free
  ([#307](https://github.com/dragginzgame/icydb/issues/307)).

- Run both public DELETE lanes through existing shared SQL preparation before
  classification. Policy and execution use the same normalized statement,
  preserving aliases, case-insensitive qualifiers and RETURNING fields while
  retaining primary-key, window, scan and write limits. Invalid qualifiers and
  unbound inputs reject before effects
  ([#218](https://github.com/dragginzgame/icydb/issues/218)).
- Correct the persisted-format inventory and witness documentation: Deep
  integrity checks diagnose stale secondary entries; startup replays admitted
  journal effects and does not repair the whole index. The witness wire is
  unchanged; removing the unwritten `Missing` state remains a separate hard cut
  ([#245](https://github.com/dragginzgame/icydb/issues/245)).

### 🔧 Changed

- Adopt Shared Tooling 0.11.1 snapshot-owned common tool catalogs with existing
  versions/digests, compiler selections and Testkit ownership unchanged. Reuse
  Cargo CI caches across unrelated literal catalog edits; retain tool/build
  invalidation, recovered failed-job logs and filesystem/path diagnostics.
  Route CI installation through the common installer, retire obsolete per-tool
  wrappers and reuse shared fixture cleanup and release tag checks.
  Qualify the already-selected Host 0.17.2 CLI and artifact/Candid consumers
  ([#357](https://github.com/dragginzgame/icydb/issues/357),
  [#307](https://github.com/dragginzgame/icydb/issues/307)).

- Adopt Metrics 0.9 producer overflow getters. Existing report fields, tracked
  overflow semantics, exact means and Candid output remain unchanged.

- Reuse the accepted contract’s frozen slot count for current-layout row opens;
  retain historical counting and corruption rejection for invalid layouts/counts.
  Keep the fixed page-output reservation at compile time instead of rebuilding
  it for each candidate. No retained state, budget limits or persisted encoding
  changes; broader row-cache and candidate-accounting work remains separate
  ([#257](https://github.com/dragginzgame/icydb/issues/257),
  [#293](https://github.com/dragginzgame/icydb/issues/293)).

### 🧹 Cleanup

- Prepare accepted index predicates and key/predicate dependency masks once in
  the existing synchronous commit context, shared by every row and both index
  families. Keep metadata bound to its accepted row contract; per-row membership,
  after-image admission, uniqueness and mutation deltas retain their existing
  behavior. No global cache, execution mode or persisted change is added
  ([#344](https://github.com/dragginzgame/icydb/issues/344)).

- Reuse accepted live-write readers across patching and row constraints; carry
  canonical row images into the common index/relation commit planner. Persisted
  replay and rebuild keep independent bounded admission. Reuse admitted scalar
  views and canonical structural values in the existing row cache, removing
  redundant decoding and conversion without another cache
  ([#114](https://github.com/dragginzgame/icydb/issues/114),
  [#115](https://github.com/dragginzgame/icydb/issues/115)).
- Derive field/index candidates through the existing snapshot owner, preserving
  unrelated catalog and allocator state by construction. Existing activation,
  physical-domain and publication checks remain in force
  ([#359](https://github.com/dragginzgame/icydb/issues/359)).
