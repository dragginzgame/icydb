# 0.263 — Seek Integration Qualification

## 0.263.0 — 2026-10-01

### 📚 Design kickoff

Open the [design](../design/0.263-seek-integration/0.263-design.md) and
[delivery tracker](../design/0.263-seek-integration/0.263-status.md) for resolving
the dormant primary-key seek integration. At kickoff, the physical primitive
and native tests existed, but the pending-target adapter had no production
writer, including in the introducing 0.222.0 source. Qualification separates SQL
intersections, signed dynamic scans and native admitted resumed intersections;
S2 retires the prototype and S3 closes its full IC qualification.

Three landings cover frozen workload/baseline qualification, one production
decision with direct cleanup, and final end-to-end IC breadth qualification.
Existing cardinality admission, full-prefix integrity, ordering, cursor resume
and execution budgets remain required. All three landings are complete with
prototype retirement as the final outcome. No integrated seeking performance
benefit is claimed. Cargo versions, full-suite validation and publication remain
release-workflow owned.

### 🧪 S1 — Current query qualification

Reuse the SQL-perf streaming entity for seven bounded populations, two/three
children, both directions, sparse/disjoint/late overlap, dense controls and
payload-driven pages. Load four rows per update and discharge wide-row journal
debt outside samples. Record exact answers, repeated page work and every issued
cursor's suffix through maintained session and IC boundaries.

The matched signed dynamic filter chooses a full scan; SQL strict predicates
select logical intersections. Expression extraction uses numeric widening for
signed atoms, which secondary lookup admission conservatively declines.
Unsigned native fixtures independently qualify the bounded intersection and
resumed polling path. This documents current eligibility rather than changing
query semantics or enabling seek. The signed actor does not establish a resumed
admitted-intersection IC baseline.

The [baseline](../design/0.263-seek-integration/s1-baseline.md) and
[receipts](../design/0.263-seek-integration/s1-baseline.csv) retain 40 SQL samples
and 38 page steps with repeats. Frozen raw audit Wasm: 4,504,970 bytes. Sparse
warmed SQL samples use 4.57–9.85M instructions and 17.58–22.74M charged cycles;
dynamic scan controls use 20.10–21.36M instructions and 28.82–29.85M cycles.
These are different endpoints and instruction windows, not seek-only deltas.

Validation passed: 79 focused native tests, the manual PocketIC matrix,
required Clippy recovery and focused Clippy gates, layer authority, formatting
and documentation checks. Full suites remain user-owned;
signed schema-bound predicate admission is an independently reviewable follow-up.

Complexity: 13 files, approximately +940 net lines, chiefly fixture/test Rust
and baseline documentation. Runtime architecture and state-space are neutral;
qualification tooling grew. Prior 0.262 worktree changes are preserved.

### 🗑️ S2 — Retain polling and retire unused positioning

Remove the dormant seek protocol, pending-target adapter, dispatch variant,
held-key state and repositioning machinery from the physical stream owner.
Ordinary polling remains the one stream contract. Authenticated primary resume,
index anchors, complete-prefix integrity checks, admitted intersection bounds
and composite duplicate handling remain maintained. No public API, cursor or
persisted format changes.

S1 supplies no qualified resumed-intersection IC benefit to justify adding
alignment state. Retirement resolves the maintenance gap without speculative
integration. Port sparse suffix, total-limit, one-sided bounds, duplicate,
corruption and hard-budget checks to maintained polling calls; remove tests
whose only subject was the retired protocol. Reuse the existing IC matrix
runner for bounded matched sparse and rotated controls. S3 owns final breadth
qualification; signed schema-bound secondary lookup remains separate.

Validation passed: 143 focused native tests and bounded baseline/candidate
PocketIC controls, with a candidate repeat reproducing every cost sample.
Focused Clippy, formatting, authority and documentation checks pass. Full suites
remain user-owned. Raw audit Wasm shrinks 4,619 bytes to 4,500,351; six of eight
SQL controls are cost-identical and most dynamic page controls save 3,394
instructions/cycles. Two three-child shapes have mixed deltas, including up to
0.95% instruction and 0.21% cycle increases on second samples. The
[decision and receipts](../design/0.263-seek-integration/s2-decision.md) record
that tradeoff; no general speedup or admitted resumed-intersection IC benefit
is claimed. Three disposable PocketIC servers were started and stopped.

Complexity: 13 files, approximately −560 net lines; the stream subsystem alone
shrinks by 835 lines. One internal variant and the dormant protocol disappear.
Existing physical/composite owners converge on polling; the existing IC runner
is reused. Implementation structure is simpler and no new debt axis is added.

### 🧪 S3 — Full qualification and closeout

All three planned landings are complete and 0.263 is scoped-ready. Qualify seven
populations and 28 directional shapes on matched baseline/candidate artifacts,
including payload pages and every issued cursor's exact suffix. Three full
PocketIC runs pass; baseline reproduces S1 and all 116 candidate cost samples
repeat exactly. The [full closeout](../design/0.263-seek-integration/s3-closeout.md)
retains 232 before/after receipts and reconciles the maintained polling, cursor,
cardinality and complete-prefix integrity owners.

Raw Wasm remains 4,619 bytes smaller. Across second samples, instruction deltas
range from −278,804 to +145,069; cycle deltas range from −87,095 to +63,554.
Maximum increases are 2.56% instructions and 0.21% cycles; every payload page
saves 1,946–2,979 instructions/cycles. No uniform speedup is claimed. The signed
IC pages scan; admitted resumed-intersection IC costs and mainnet costs remain
unqualified. Signed secondary lookup admission is a separate follow-up.

Source is unchanged, so S2 native/Clippy receipts remain applicable. Formatting,
authority, documentation and diff checks pass; full suites and publication
remain user-owned. Three disposable PocketIC servers were started and stopped;
no ICP network changed. This landing adds evidence/docs only, without runtime
state-space changes.

S3 footprint: six files, approximately +390 documentation/receipt lines. No
runtime code, behavior axis or test harness is added; implementation shape is
unchanged from S2's simpler polling path.
