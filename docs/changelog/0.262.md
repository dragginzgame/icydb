### ➕ Added

Ordinary and generated schema proposals can add empty source-version-1 entities
to existing accepted stores, including initial indexes, checks and restrictive
relations. Populated existing entities retain their accepted identities, rows
and index entries. Placeholder declarations are unnecessary for these additions.
Added entities may use new or already accepted named value types. New enum,
record, wrapper and collection definitions use the existing accepted value
catalogs, including supported recursive and shared definitions. Their IDs are
allocated above current accepted IDs within each store. Existing definitions,
type IDs, record-member IDs and enum-variant IDs remain unchanged; redeclarations
require an exact match. Missing references, orphan definitions, occupied paths
and identity exhaustion reject the whole proposal. Creation may accompany
explicit adjacent migrations of existing entities. Metadata migrations publish
both together; physical migrations keep additions unpublished until their
existing final publication phase. Renamed predecessors retain their identity,
including when a new declaration reuses the former source name. New stores and
SQL CREATE TABLE are outside this line's scope.

### 🧭 Migration Notes

With the migration feature, existing entities must have adopted source lineage
before creation. A database created without the feature first needs the unchanged
schema deployed with that feature and adopted. New entity lineage, accepted
catalogs and exact application receipts use the existing compound publication
and interruption-recovery boundary. No format discriminator, endpoint or durable
phase is added; internal encodings remain version 1. Cargo version selection is
left to release tooling.

Mixed proposals retain version 1 for new entities and supply migration
transitions only for existing entities. Existing lineage still requires prior
adoption. Physical admission proves fresh row/index/reverse domains empty before
preparing the migration. Metadata publication and physical final publication
combine fresh lineage with transitioned lineage. Aborting before rewriting
leaves additions unpublished; ordinary operations retain the existing migration
gate during physical work.
