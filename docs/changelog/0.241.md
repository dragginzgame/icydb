# IcyDB 0.241 — Exact Indexed Distinct Cardinality

## 0.241.1

### 📝 Summary

`0.241.1` closes the exact indexed distinct-count implementation with stricter
failure handling and simpler ownership. SQL behavior, accepted-schema
authority, stable state, Candid and exports are unchanged.

### 🩹 Fixed

- Impossible zero multiplicity and checked metadata-count or budget-layout
  overflow now return typed invariant failures instead of looking like
  optional metadata unavailability and entering prepared fallback.
- Exact-success retained-state charges now come from the canonical
  scalar-DISTINCT reducer layout, including hash-entry and collision-promotion
  costs, rather than an executor-local reconstruction.
- Request and execution budget publication uses one checked atomic commit;
  rejected bundles leave both authorities unchanged.

### 🧹 Cleanup

- SQL lowering carries the admitted target slot as its immutable fact, so the
  session no longer re-derives the field from aggregate strategy shape.
- Planner-owner evidence now locks shortest-arity/stable-name selection,
  StoreReady visibility and nullable compound-suffix rejection.
- The 0.241 performance test is split into evidence-specific helpers and no
  longer requires a Clippy line-count suppression.

## 0.241.0

### 📝 Summary

`0.241.0` admits one evidence-bounded global aggregate:

```sql
SELECT COUNT(DISTINCT age) FROM Entity
```

When the direct non-nullable `Int32` field is the leading component of a
complete accepted user index, IcyDB counts exact synchronized
first-component metadata. Incompatible shapes and unavailable evidence enter
the existing prepared executor before it performs store work.

### 🔧 Changed

- SQL lowering owns one immutable exact-distinct eligibility fact, including
  the rejection of authored ordering and predicates.
- The accepted query planner selects one complete compatible index by shortest
  arity and stable name. Execution cannot reselect an index.
- The singular fingerprint-bound exact-or-prepared command slot gains one
  accepted `IndexId` target; no neighboring or nested cache was added.
- The former direct-count session owner is hard-cut to the broader
  `exact_count` owner without aliases or forwarding modules.
- Synchronized first-component metadata is formally exact result authority
  only while its decode state and data generation match the pinned store.
- Exact success charges DISTINCT state and result work atomically through the
  canonical execution/request budget owner. Unavailable or over-budget probes
  leave no semantic charge before prepared fallback.

The exact route fetches zero rows and reads zero physical index entries. A

Final production raw Wasm grew from 3,293,820 to 3,299,173 bytes (+5,353);

generated API and package versions are unchanged.

The maintained runtime delta is approximately +465 net lines across 13
touched production Rust files. The larger-than-forecast proof footprint spans
the existing lowering, planner, command, budget, executor and metadata
authority seams. It adds zero production types, cache slots, mutable owners,
persisted states or invalidation edges.
