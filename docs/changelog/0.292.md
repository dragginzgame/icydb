# IcyDB 0.292

## [0.292.1]

- Avoid allocating and serializing a second full heap-store schema checkpoint
  during decoding ([#102 — Heap identity checkpoint work](https://github.com/dragginzgame/icydb/issues/102),
  partial). Existing bounded reads, checksums, exact input consumption, identity
  tags/padding/order and accepted-candidate validation already enforce the same
  canonical bytes. Keep encoder comparison as a test oracle across identity
  widths, lifecycle/high-water states and repaired-checksum mutations. Stored
  bytes, corruption causes, preflight/apply and retained-data contracts remain
  unchanged; full-bundle identity rewrites and measured cost qualification remain
  open.
- Let corrected code retry recovery after an internal invariant error
  ([#59 — Startup receipts block corrected upgrades](https://github.com/dragginzgame/icydb/issues/59)). Stop publishing durable
  terminal receipts for those diagnostics and remove terminal authority from
  existing current-format invariant receipts after full bounded decoding.
  Preserve pure readiness observation; the existing replicated success path
  clears the obsolete memo. Corruption, format and deterministic schema failures
  keep their terminal bindings. No code-identity field, controller reset,
  receipt format or alternate recovery path is added.
- Enforce the existing mutation instruction ceiling against the current IC
  message ([#150 — Mutation trackers grant fresh instruction allowances](https://github.com/dragginzgame/icydb/issues/150)), including
  prior application work, earlier job advances and fresh maintenance budgets.
  Keep interval usage and read/telemetry counters unchanged; report typed
  exhaustion before publication rather than granting each tracker a fresh
  allowance. Reuse the existing limit, checkpoints and failure reserve without
  a new public policy, retained state or format. Reuse the canonical job error
  projection so entry exhaustion retains its resource facts; leave job progress
  unchanged and keep exact receipt replay available. Installed qualification of
  message-counter behavior remains open.
- Adopt published Platform 0.16.0 for direct consumers, retaining the same
  canonical Types 0.15.1 identities, enabled features and application Wire
  contracts. The selected IC0, Principal/Account and BLAKE3 modules are unchanged
  from Platform 0.15.3; this release's crypto/certification changes are not enabled.
  Memory/Storage's subsequent update converges their stable-structures substrate
  on the same Platform release; preserve the independent Canic qualification graph.
- Prevent a write from returning an ordinary failure after its recovery marker
  has published ([#152 — Errors after marker publication](https://github.com/dragginzgame/icydb/issues/152)). Apply,
  marker-observation and retirement contradictions now share the existing fatal
  commit policy: Wasm traps and native production aborts. Keep expected refusals
  before publication, preserve interrupted-state fault fixtures, and remove
  scattered mutation-stage handlers. No public outcome, marker format or recovery
  protocol is added; installed trap/observability qualification remains with
  [#154 — Production budget and recovery qualification](https://github.com/dragginzgame/icydb/issues/154).
- Diagnose colliding generated index names at the later macro declaration
  ([#203 — Colliding index names](https://github.com/dragginzgame/icydb/issues/203), partial), using the
  existing emitted-name function. Cover compound versus single-field labels,
  field versus expression labels and partial predicates; preserve distinct
  unique/non-unique names and valid filtered prefixes. Keep model/runtime
  uniqueness validation as independent intake checks. No name derivation,
  accepted name, public API or stored format changes; an unambiguous naming
  contract remains open.
- Emit only changed user-index entries during schema publication
  ([#86 — User-index replacement work](https://github.com/dragginzgame/icydb/issues/86), partial). Keep complete
  accepted-before/after projection, physical-domain equality, uniqueness and
  staging-budget checks before omitting identical key/value pairs from physical
  deletes and inserts. Reuse the sorted projections without a second key set;
  source/projection usage still reports the complete proof. Live apply and
  journal records consume the same effects with unchanged encodings and replay
  semantics. Maximum production-fold and matched cost qualification remain open.
- Keep multi-page constraint validation progressing while other entities in
  the same store receive writes
  ([#99 — Validation restarts on unrelated writes](https://github.com/dragginzgame/icydb/issues/99)). Reuse the journal's
  existing entity mutation sequence against the retained store-wide baseline;
  the unchanged-store case keeps its existing direct check. Target-entity
  changes still restart Forward, future baselines cannot promote, and missing
  revision authority fails closed. Job encoding, row/write gates, page limits,
  receipts, unique staging and promotion remain unchanged; no new persisted
  counter, cache, policy or recovery path is introduced.
- Qualify generated default conversions through the standard `Into` trait
  ([#180 — Generated-name collisions](https://github.com/dragginzgame/icydb/issues/180), partial), so an
  application's own `into` method cannot make macro expansion ambiguous. Cover
  newtype text and record text, Blob, Account, Principal, Subaccount and Ulid
  literals in actual consumers. Entity and record defaults share field
  construction, preserving database-owned Identity placeholders without invoking
  their generator. Public helper names and encoded formats are unchanged.
- Qualify standard types, Result/Option variants and macros in generated actor wiring,
  schema and SQL handlers, so caller aliases cannot capture startup or session
  code ([#180 — Generated-name collisions](https://github.com/dragginzgame/icydb/issues/180), partial).
  Compile actual heap/journaled actor output in the renamed-dependency fixture
  with shadowing types, variants and `thread_local!`, `vec!` and `concat!` macros,
  including optional SQL, migration and metrics capabilities. Keep the standard

  naming remains open.
- Adopt published Build/Host Foundation 0.73.3, Host Tools 0.76.0,
  Memory/Storage 0.60.6 and Wire/Derive 0.13.3. Raise the declared minimums to

### 🩹 Fixed

- Correct the same-width floating comparison portion of
  [#110](https://github.com/dragginzgame/icydb/issues/110). Float32/Float32 and
  Float64/Float64 pairs reuse the existing finite-wrapper ordering at the Value
  representation owner, as Nat128 pairs already do. Database numeric comparison,
  predicates and computed comparison expressions consume that decision instead
  of requiring Decimal admission. Subnormals, adjacent tiny values and finite
  extremes now compare throughout their supported domain; SQL NULL comparisons
  retain their existing unknown result. No atom, storage, index or Wire encoding
  changes. Same-width canonical ordering already used native comparison or its
  strict fallback and retains its result. Mixed-width/mixed-type comparisons and
  arithmetic retain their existing Decimal policy and remain unresolved in #110.
  No legacy comparison mode or new numeric representation is introduced.

- Complete the floating-point render/parse portion of
  [#232](https://github.com/dragginzgame/icydb/issues/232). The shared typed-number
  intake now accepts `FLOAT32 'value'` and `FLOAT64 'value'` alongside its existing
  `U256` form, using the existing finite atom constructors. Canonical float SQL
  uses these spellings, retaining type and precision through standalone predicates,
  full SQL and accepted CHECK render/rebinding, including nominal newtypes.
  Follow a type name with a string only when authoring a literal; ordinary fields
  named float32/float64/u256 keep their identifier meaning. Distinguish typed
  literals from right-hand fields before field-comparison dispatch as well.
  Malformed/nonfinite payloads reject before execution. Canonical SQL strings
  change; float atom storage/Wire encodings and accepted CHECK literal payloads
  do not. Ordinary number typing and existing comparison/coercion algorithms are
  unchanged. Mixed-type and floating comparison
  semantics remain separately tracked in
  [#110](https://github.com/dragginzgame/icydb/issues/110).

