# IcyDB 0.292

## [0.292.0]

### ⚠️ Breaking - Application Hooks

- Complete the remaining generator correction in
  [#68](https://github.com/dragginzgame/icydb/issues/68): record, entity, enum and
  tuple `ty` validators/normalizers receive the complete generated value, before
  attached field/payload callbacks and normal child traversal. Tuple and active
  enum payload callbacks reuse the existing scalar/optional/repeated cardinality
  owner; absent/empty payloads invoke no item callback. Preserve declaration order,
  concrete callback identities and tuple-position/variant diagnostics. An enum
  type normalizer may select a new variant before payload dispatch.
- These accepted directives previously had no effect. Rebuild consumers and review
  their hooks, which can now modify values or return application issues. Keep one
  generated implementation without a compatibility switch, new visitor route or
  automatic database hook. Existing newtype/collection hook targets, immutable
  sorted-key restrictions and database admission are unchanged. Seven actual
  generated-consumer regressions fail before the correction and pass afterward.

### 🩹 Fixed

- Correct the same-width floating comparison portion of
  [#110](https://github.com/dragginzgame/icydb/issues/110). Float32/Float32 and
  Float64/Float64 pairs reuse the existing finite-wrapper ordering at the Value
  representation owner, as Nat128 pairs already do. Database numeric comparison,
  predicates and computed comparison expressions consume that decision instead
  of requiring Decimal admission. Subnormals, adjacent tiny values and finite
  extremes now compare throughout their supported domain; SQL NULL comparisons
  retain their existing unknown result. No atom, storage, index or Wire encoding
  changes. Same-width canonical ordering already used native comparison or its
  strict fallback and retains its result. Mixed-width/mixed-type comparisons and
  arithmetic retain their existing Decimal policy and remain unresolved in #110.
  No legacy comparison mode or new numeric representation is introduced.

- Complete the floating-point render/parse portion of
  [#232](https://github.com/dragginzgame/icydb/issues/232). The shared typed-number
  intake now accepts `FLOAT32 'value'` and `FLOAT64 'value'` alongside its existing
  `U256` form, using the existing finite atom constructors. Canonical float SQL
  uses these spellings, retaining type and precision through standalone predicates,
  full SQL and accepted CHECK render/rebinding, including nominal newtypes.
  Follow a type name with a string only when authoring a literal; ordinary fields
  named float32/float64/u256 keep their identifier meaning. Distinguish typed
  literals from right-hand fields before field-comparison dispatch as well.
  Malformed/nonfinite payloads reject before execution. Canonical SQL strings
  change; float atom storage/Wire encodings and accepted CHECK literal payloads
  do not. Ordinary number typing and existing comparison/coercion algorithms are
  unchanged. Mixed-type and floating comparison
  semantics remain separately tracked in
  [#110](https://github.com/dragginzgame/icydb/issues/110).

  ```sql
  INSERT INTO Measurement (id, score)
  VALUES (1, FLOAT64 '1.2345678901234567e-20');
  ```

- Complete [#255](https://github.com/dragginzgame/icydb/issues/255)'s canonical
  `TypedAdapterError` / `TypedOperationError` conversion into `icydb::Error`.
  Preserve database payloads exactly, including facts, query-field context and
  Wire bytes. Assign adapter reasons E283–E292 with Interface origin: consumed
  batch rows and stale bindings are Conflict, inconsistent row cardinality is
  InvariantViolation, and unsupported binding/projection contracts are Unsupported.
  Existing leaf numbers remain unchanged and consecutive. Add the reasons to the
  canonical registry and CLI, without a new error field, numeric fact, codec or
  compatibility route. Generated source strings remain on the Rust cause instead
  of becoming accepted identities or public facts. Public handler examples use
  the canonical conversion; local callers retain the original source chain.
  Exhaustive `RuntimeBoundaryCode` matches need source updates for its ten new
  variants. Existing public error records and stored data are unchanged.

- Retain deterministic, detail-free Store/Unsupported allocation-registry refusals
  in the existing boot-local format admission cache. Read-only startup observation
  returns the existing `DatabaseControl` failure, so the existing driver terminal
  branch stops repeated reconciliation. Scope the refusal to its physical control
  allocation and drop it on upgrade; publish no failure receipt or control change.
  Entropy, resource failures, persisted corruption and schema-reconciliation
  classification retain their existing owners. Qualify retired-store reuse,
  omitted-store debt and a retained marker through the production logical-memory
  actor, including repeated observations and restoration of the original actor.
  [#87](https://github.com/dragginzgame/icydb/issues/87).
