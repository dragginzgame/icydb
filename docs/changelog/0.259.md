# IcyDB 0.259

## 0.259.3 — Leaner Grouped Preparation

### 🧹 Cleanup

- Borrow frozen aggregate specifications and DISTINCT strategy when assembling
  a grouped planning handoff. EXPLAIN no longer clones those payloads only to
  discard them; execution materializes its owned route metadata at the existing
  consuming boundary.
- Keep the DISTINCT target label only in its accepted field slot, removing
  the duplicate owned string and its cache-retention charge.
- Collect aggregate specifications without constructing discarded layout
  vectors. Derive layout against frozen aggregate slots instead of rebuilding
  owned expressions and filters, preserving first-seen ordering and semantic
  identity. No new cache, mode, public API or persisted format.
- Borrow aggregate target slots during fold setup and derive materialized
  direction from the aggregate kind. Remove unused lookup error callbacks and
  context arguments while preserving typed invariant failures and shared
  compiled-expression ownership.
- Centralize projection, HAVING and top-k setup in the existing grouped page
  selector. Ordered and materialized execution share setup without merging their
  execution paths, changing compilation order or adding another cache.
- Replace bounded COUNT and generic/top-k heap roots in place instead of
  popping and pushing. Filtering, strict ordering, admission charges and final
  sorting are unchanged. Unbounded candidate staging stays: removing it would
  change aggregate-finalization versus HAVING/projection error precedence.

### 🧪 Testing

- Extend cold/warm diagnostics coverage with compiled aggregate input and FILTER
  expressions, and verify the execution handoff retains the complete metadata.
- Cover repeated, computed, filtered and DISTINCT aggregate outputs, HAVING-only
  slots, and rejection when required frozen aggregate metadata is absent.
- Verify materialized MIN/MAX results and bucket lookup matching, absence,
  invalid-index rejection and comparison-error propagation.
- Cover empty and zero-bound COUNT windows, ascending/descending replacement,
  oversized bounds, and cold/warm aggregate top-k windows including ties.
  Add a manual matched-actor instruction/cycle probe using the existing audit
  actor and retained build flow; no production endpoint is added.

### 📊 Audit

- Ownership and intermediate construction are simpler; the unused combined
  scan-result type is removed. Layout keeps a transient seen-slot bitmap, not
  another retained artifact or expression copy. Seventeen files changed across
  the combined .3 worktree: thirteen Rust files (approximately -153 production
  lines and +313 test/measurement lines) and four documentation files.
- The preceding fold-cleanup qualification passed 108 focused test executions.
  Page-selector qualification passes 69 focused executions, none ignored, plus
  strict core all-feature/all-target lint, formatting and whitespace checks.
  The heap slice passes 62 focused core executions and both matched PocketIC
  runs. Full-suite validation remains user-owned.
- The isolated heap change reduces raw audit Wasm from 4,477,650 to 4,477,458
  bytes (-192). Six-group probes save 4,052–6,835 instructions and cycles per
  call across three cache phases; results and cursors match. These are small
  workload-specific gains, not measurements of the whole .3 cleanup or larger
  workloads. See the [matched measurement](../reports/investigations/2026/09/19/grouped-heap-replacement/01/report.md).

## 0.259.2 — Query Preparation and Routing Cleanup

### 🩹 Fixed

- Preserve unchanged server-issued grouped cursors for decimal keys, including
  decimals within collections. Accepted group-key validation permits exact,
  representable scale normalization without rewriting the boundary or weakening
  stored-value validation; rounding, overflow and invalid types still reject.
- Authenticate grouped continuation framing and values using the existing
  scalar HMAC/key owner, then validate boundary arity and accepted key types
  before execution. Scalar token bytes are unchanged. Breaking grouped
  version-1 hard cut: discard saved grouped cursors and restart pagination;
  no stored-data migration, new key, or compatibility decoder.
- Reject grouped continuation without LIMIT and unsupported global DISTINCT
  continuation as invalid cursor requests, with distinct typed numeric reasons,
  rather than internal failures. Supported grouped queries and pagination are
  unchanged; no cursor or stored-data migration.
- Preserve internal cursor failures as `InvariantViolation` with `Cursor`
  origin at the query/session boundary instead of reporting a caller planning
  error. External cursor rejections keep their existing code and numeric facts.
  Potentially breaking for callers matching the previous diagnostic; no API,
  cursor encoding or stored-data migration.

### 🧹 Cleanup

- Encode and authenticate each emitted grouped cursor once inside the execution
  budget, then move those bytes into the response. Charge the actual unpadded
  Base64 length instead of a hexadecimal-sized estimate; no additional wire or
  stored-data change beyond the grouped hard cut above.
- Store one retained-slot requirement per field instead of parallel flags.
  Avoid default-only override vectors and share scalar byte-length eligibility
  through the accepted row layout. Full-value projection, ordering and cursor
  requirements still take precedence over length-only decoding.
- Require planner-supplied grouped limits instead of retaining an unused
  executor default path. Return grouped pages without a debug-only result
  envelope; check cardinality at construction and preserve global DISTINCT's
  implicit group for empty input.
- Dispatch fast streams directly from their request variant, removing a second
  route tag and its mismatch-only failure. Share row-collector/page request
  data and construction while retaining separate execution paths, cursor policy
  and eligibility checks.
- Compare borrowed aggregate identities when checking grouped projection layout
  and collecting unique aggregate slots. Copy input/filter expressions only
  when retaining a new aggregate entry; preserve canonical identity and
  first-seen slot ordering without introducing another comparison policy.
- Borrow grouped HAVING expressions from the retained plan instead of copying
  them into runtime payloads. Read scalar residual filters from their existing
  preparation owner without storing a duplicate reference. Grouped compilation
  still rejects invalid plan shapes with a typed error.
- Remove unused prefix-length fields from covering-plan payloads and derive
  grouped route intent from its existing planner strategy. Ordering proofs
  still use prefix length during planning; pure/hybrid covering execution,
  grouped routing and retention accounting keep their existing owners.
- Remove the redundant retained-slot override flag and require accepted schema
  identity in prepared execution cores. Projection-specific handoffs now require
  their projection contract at construction. Genuinely optional aggregate,
  continuation and lazy-cache states remain unchanged; no public API or stored
  format changes.
- Require the grouped preparation/layout bundle from the existing prepared-plan
  owner and delete the unreachable runtime reconstruction fallback. Missing
  planner metadata remains a typed invariant error; successful runtime assembly
  is infallible. Cache admission and retention accounting remain with their
  existing owner, and execution still receives the bundle when retention is
  declined. No public API or stored-data changes.
- Remove the unused scalar-route probe override and its forwarding chain.
  Preserve aggregate probes, continuation/window-derived bounds and runtime
  pagination/retry hints with their existing owners.
- Borrow accepted authority during initial/resumed scalar route construction
  and warm route lookup. Remove temporary authority clones/boxes and the
  forwarding-only covering helper; retained plans and runtime authority keep
  their existing ownership.
- Classify covering eligibility and load explain directly from borrowed frozen
  predicate/index metadata. Remove the temporary owned preparation constructor;
  actual strict/conservative execution preparation and aggregate diagnostics
  keep their existing contracts and classifier.
- Compile covering predicates directly from borrowed plan inputs through the
  existing strict index compiler. Retain only its program instead of a full
  temporary preparation bundle; literal admission, unsupported results,
  typed failures and pure/hybrid route ordering remain unchanged.
- Remove unused strict predicate compilation from grouped route selection and
  grouped execution EXPLAIN. Grouped runtime filtering and scalar aggregate
  compilation remain intact; removed work no longer consumes construction
  allowance or produces compilation failures.
- Share immutable scalar execution preparation between cached plans and runtime
  handoffs instead of copying compiled programs, literal buffers and slot
  metadata. Keep the existing lazy-retention owner, including accounting for
  the shared allocation and its payload; declined retention still permits
  execution. Compilation policies are unchanged.
- Carry the existing shared grouped preparation/layout bundle through stream
  construction and folding, removing the handoff's deep copy. Share cached
  scalar-aggregate preparation while preserving strict compilation and current
  authority checks. Both continue to use the existing retention owner.
- Borrow the planner's access-choice snapshot for verbose EXPLAIN rather than
  copying candidate, alternative and rejection lists before rendering.
- Borrow the grouped projection during folding and reuse the existing fallible
  lazy initializer for projection shape, initial scalar routing and cursorless
  row layout. Failure and declined-retention behavior stay unchanged.
- Share immutable aggregate input/filter expressions between groups rather
  than copying them into each reducer. Accumulators and DISTINCT sets remain
  independent; inline group-state estimates follow the smaller representation.
- Retain only executable scalar projection metadata, not a second syntax tree
  used solely for its field count. Build direct-slot metadata from borrowed
  slots without a temporary vector; cache accounting follows the smaller
  contract through its existing visitor.

## 0.259.1 — Query Preparation Audit Follow-ups

### 🧹 Cleanup

- Narrow the initial point-read probe to equality and singleton primary-key
  membership. Multi-value lists, including duplicate-only lists, go directly
  through paged preparation; zero-limit requests skip the point-read probe.
  Operand validation, normalization and continuation remain with existing owners.
- Construct canonical ordering once when a plan is built, borrow it for access
  selection, then move it into the logical plan. Remove the redundant raw-order
  handoff and make final logical assembly infallible. Cache hits do not acquire
  new order construction; no API, persisted format or configuration changes.
- Remove the unused key-access override parameter chain, unreachable branch and
  internal diagnostic reasons identified by the complexity audit. Current key
  selection and explain output remain unchanged; no compatibility alias is kept.
- Use one plan-construction path for cold queries and parameterized-template
  rebinding, removing duplicate empty-result selection and forwarding methods.
  Current authority/index visibility, candidate retention, exact-bound memo reuse
  and failure-safe cache publication remain with the existing cache owner.
- Carry the first filterless cache-miss key into compilation instead of probing
  again. Preserve the early warm-hit shortcut and the final publication boundary.
  Borrow authority when assembling cache keys and remove the unused authority
  argument from template lookup.
- Require complete row and schema metadata in execution authority. Reuse the
  accepted root's schema directly instead of supporting partial metadata and
  rebuilding it during preparation. Remove impossible missing-metadata branches,
  the redundant cache snapshot wrapper and unused pinned-continuation arguments.
  Current-root, index-readiness, field and access-plan validation remain intact.
- Borrow authority while building prepared cores, rewriting scalar pagination
  and initializing lazy projection/covering/grouped/layout metadata. Remove
  temporary handle clones, including on warm lookups; owned runtime handoffs
  and cache-retention accounting remain unchanged.

### 🧪 Testing

- Cover empty, singleton, duplicate, multi-key and missing-key membership on cold
  and warm requests, including bounded pagination, zero limits and invalid
  operands. Assert that initial preparation does not compile a losing plan.
- Verify canonical order backing moves into the logical plan without further
  construction charges, retaining the existing grouped/composite ordering tests.
- Pin empty-key access and diagnostic precedence when a zero limit and a
  constant-false predicate both apply; reuse the maintained cold/rebound,
  changed-binding and cache-admission coverage.
- Cover compilation-budget rejection and warm reuse for both trivial and ordered
  filterless plans across public, trusted and diagnostic preparation.
- Verify expression-index preparation shares the complete accepted schema and
  value catalog; retain captured-root isolation and cold/warm expression-index,
  cache-accounting, aggregate and continuation coverage.

### 📊 Audit

## 0.259.0 — Migration Rehearsal

### 📚 Documentation

- Establish the [design and delivery plan](../design/0.259-migration-rehearsal/0.259-design.md)
  for reproducible current-format schema migration, reusing the existing fixture,
  typed commands and retained artifact pipeline. Application guidance covers
  exact actors, domain-owned seeds, expected results and permitted abort; no
  production migration tool or actual downstream qualification is claimed.
- Remove the delivered API-friction and logical-memory idea notes; their numbered
  designs remain the authorities. Promote migration rehearsal into its numbered
  design and update incoming links and the collection-materialisation baseline.
- Replace pre-0.218 adoption guidance with the current-format boundary. Schema
  migration does not provide a bridge across incompatible pre-1.0 formats.
- Mark 0.258 implementation closed without claiming its in-progress release has
  published. Preserve existing release notes and historical audit evidence.

### 🧪 Testing

- Replace manually supplied migration Wasms and the ignored closeout case with
  automatic retained builds from the current checkout. Reuse the same private
  variant-build helper as the logical-memory fixtures, without adding a cache
  or runner.
- Add paired uninterrupted/interrupted success assertions and a rejected
  checked-cast scenario. Rejection, zero row rewrites, unchanged accepted head,
  abort and source-row preservation after source redeployment pass, alongside
  successful publication and exact progress retention across upgrade.
- Deliver the existing startup watchdog after upgrades and remove the old
  field-alias absence assertion; maintain positive current-output contracts.
- Cover a restart in `Prepared`: preserve exact migration progress and read
  gating, stop background retries, then complete publication and verify rows.
- Record host-side whole-call migration cycle charges without changing actors.
  Preserve exact build/seed evidence and measurement boundaries in the
  [closeout report](../reports/releases/0.259/closeout/2026-09-18/01/report.md).

### 🩹 Fixed

- After existing preflight validates an adjacent migration, reuse the typed
  migration-pending signal instead of a terminal `RuntimeUnsupported` startup
  failure. Stop the startup watchdog while explicit controller commands own
  progress; do not persist a failure or busy-retry the pending plan. Invalid
  proposals still fail preflight and genuinely unsupported schema failures
  retain their terminal classification.
- Apply the same pending signal after a `Prepared` restart, removing the special
  success/deferral branch that made the watchdog retry indefinitely. Existing
  deployment/head checks and core row-operation admission remain unchanged.
- Repair two idea-document links after their design owners moved to the archive.
- Potentially breaking diagnostic correction: ordinary requests against this
  pending successor now receive typed startup recovery-pending rather than the
  erroneous terminal unsupported response. Migrations still require explicit
  advancement and retain the current-format boundary; no persisted format,
  public endpoint, configuration, compatibility repair or dependency is added.
