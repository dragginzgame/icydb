# IcyDB 0.259

## 0.259.6 — Leaner Write Preparation

### 🧹 Cleanup

- Move preflighted row keys and after-images into the existing journal record
  constructors instead of copying them. Canonical apply rows, relation/index
  preflight, journal validation, record ordering and recovery remain unchanged.
- Stage temporary preflight row/index changes only for subsequent rows, and
  release the overlay before journal preparation. All rows still run complete
  validation and contribute their commit-work charges and index guards.
- Keep mutation-progress before/after bytes only in the commit marker. Commit
  selection and normal application borrow that same operation; predecessor
  checks, publication order, persisted bytes and recovery are unchanged.
- Select synchronized stores directly from the registry instead of collecting
  all handles first. Paired data/index matching, registration order and
  post-commit readiness publication are unchanged.
- Ordinary and progress-bearing writes share one window-completion owner.
  Remove unused phase/key arguments; database access stays only where store
  selection needs it. Single-row and batch application share their production
  loop and finalization, retaining rollback setup and interruption controls
  under test-only compilation.

### 🧪 Testing

- Extend the unique-index batch test to reject a final-row collision and verify
  that both original rows remain unchanged before exercising swaps and deletes.
- Exercise absent and decoded progress through the marker's borrowing accessor
  in the existing bounded round-trip test.

### 📊 Audit

  use 150–160k more actor-interval instructions. Rejection-control savings

  [measurement report](../reports/investigations/2026/09/19/row-journal-ownership/01/report.md)

## 0.259.5 — Leaner Write Processing

### 🧹 Cleanup

- SQL `RETURNING field_list` pre-commit checks borrow full rows and copy only
  selected cells. Both response-size checking stages share the existing
  projection owner; final response construction still moves owned values.
  Field order, duplicate rejection, size policy and atomicity are unchanged.
- Replace bitwise CRC32C with a compile-time byte table at the existing format
  owner. Checksums and persisted bytes are identical; corruption checks stay in
  place, with no compatibility route or format change.
- SQL count-only INSERT, UPDATE and DELETE reuse the writer's existing
  no-output capture capability. RETURNING and dynamic mutation results still
  materialize values; row validation, constraints and matched counts remain.
- Update change detection no longer encodes preserved fields a second time
  merely to compare them with themselves. Canonical encoding still admits every
  preserved value and historical fill; assigned values and managed timestamps
  retain their existing comparison and validation rules.
- Keep one owned journal batch through mutation commit-marker publication and tail
  append instead of cloning all row payloads. Both stages borrow the same
  prepared marker; encoded envelopes, backlog admission, identity checks,
  publication order and recovery semantics are unchanged.
- Schema publication, constraint-validation publication and migration rewrite
  pages also borrow marker-owned batches instead of copying their payloads.
  Schema control operations reuse the marker's existing ownership. Mutation
  finalization consumes prepared schema-position keys at their final use.
  No new public mode, format or recovery path is introduced.
- SQL RETURNING byte checks count the maintained Candid encoder's output
  instead of allocating a final encoded buffer solely to measure its length.
  Row and full-response checks share the same checked counter. Candid's internal
  buffering, exact length facts, rejection order and pre-commit checks remain.

### 🧪 Testing

- Cover ordered, reordered, empty and misaligned selections, large unreturned
  payloads, and response-limit rejection before UPDATE commits.
- Add a manual matched-Wasm probe for selected-field, count-only and full-row
  responses, including oversized-response rejection and independent readbacks.
- Cover CRC32C vectors/byte transitions, count-only writes with independent
  reads and DELETE RETURNING, and absent/same-value patches across narrow integer
  kinds alongside their existing rejection boundaries.
- Compare counted row/envelope sizes against real Candid encoding at variable
  length boundaries and with a 1.05 MB value; cover exact-limit acceptance,
  one-byte-over rejection and counter overflow.

### 📊 Audit

  small rows and 2,113,876–2,116,417 cycles with a 1.05 MB unreturned field

  by 13,665–18,936 and 2,113,793–2,116,190 respectively. Count-only and full-row
  controls are unchanged. Raw actor Wasm increases 1,008 bytes (+0.024%).

  for exact inputs, message scopes and exclusions; this is not a general speedup claim.

  all 18 response hashes match. Raw Wasm grows another 1,255 bytes (+0.030%).
  The [write-cost report](../reports/investigations/2026/09/19/write-cost-reduction/01/report.md)
  records exact per-message results and exclusions; these are combined savings,
  not separate attribution to each optimization.
- F45–F48 touch nine Rust files (+51 net production lines,
  +390 test/measurement lines) and five release/tracker/report documents. The
  follow-up alone adds about 32 production and 119 test lines across six Rust
  files. Existing owners perform less work, with no new public mode, persisted
  state, recovery route or cache owner.
- F49 removes a full journal-batch clone from mutation preparation. Wide
  successful UPDATEs save 3.44–5.87 million cycles (0.856–1.503%); small-row
  results are mixed. Raw Wasm grows 22 bytes. One oversized-response rejection

- F50's counted Candid output saves 1.06–3.62 million cycles on wide response

  One Rust file adds 25 production and 66 test lines, with no new encoding

- F51–F52 extend single ownership through schema/migration publication and

## 0.259.4 — Leaner Runtime Preparation

### 🧹 Cleanup

- SELECT and EXPLAIN obtain execution authority directly from the accepted
  catalog already retained by the compiled context. Remove the duplicate
  optional authority, cold/warm fallback branches and unused cache argument.
  Current-schema checks, cache identity and bound-command cache bypass remain
  unchanged. No public API or stored-data migration.
- Borrow mutation source queries through projection planning instead of cloning
  their query intent. Exact updates retain primary-only planning and scanned-key
  bounds; prefix updates and INSERT SELECT retain their existing shared-plan
  path. Cached INSERT SELECT sources can now reuse their existing memoized
  structural key without caching row results.
- Lower same-entity insert batches directly against one accepted catalog,
  removing the per-row entity-name copies, repeated lookups and intermediate
  named-mutation vector. Single mutations also skip that batch wrapper. Both
  still use the existing lowering and atomic writer, with unchanged limits,
  diagnostic positions, identity allocation and result preparation.
- Check a captured schema-startup failure receipt once, before recovery gating,
  and carry only the reconciliation result afterward. Terminal failures retain
  priority over pending recovery and readiness; receipt matching and persistence
  are unchanged.
- Share aggregate execution-diagnostic construction between text and JSON
  EXPLAIN. Keep terminal ordering, admission and rendering at the existing
  boundaries without another mode or intermediate diagnostic buffer.

### 🧪 Testing

- Verify retained cold and warm SELECT/EXPLAIN contexts reject a superseded
  schema through both execution entrypoints, including cached prepared SELECTs.
- Cover exact-update rejection without mutation, exact and ordered-prefix
  selection, and repeated INSERT SELECT after changing its source row.
- Verify insert-batch count-check precedence, late lowering/value failures,
  atomicity, generated identity preservation and ordered results.
- Cover aggregate EXPLAIN terminal ordering, FILTER/admission metadata and
  cold/warm text/JSON output without fetching result rows.

### 📊 Audit

- Across 14 Rust files, production loses 110 net lines and tests add 245 lines.
  Three release/tracker documents are updated. Redundant optional authority,
  query copies, the named-insert wrapper and duplicate diagnostic construction
  disappear; no new behavior axis or owner is added.
- Wasm size, cycles and instruction deltas are unmeasured for this cleanup.

## 0.259.3 — Leaner Grouped Preparation

### 🧹 Cleanup

- Borrow frozen aggregate specifications and DISTINCT strategy when assembling
  a grouped planning handoff. EXPLAIN no longer clones those payloads only to
  discard them; execution materializes its owned route metadata at the existing
  consuming boundary.
- Keep the DISTINCT target label only in its accepted field slot, removing
  the duplicate owned string and its cache-retention charge.
- Collect aggregate specifications without constructing discarded layout
  vectors. Derive layout against frozen aggregate slots instead of rebuilding
  owned expressions and filters, preserving first-seen ordering and semantic
  identity. No new cache, mode, public API or persisted format.
- Borrow aggregate target slots during fold setup and derive materialized
  direction from the aggregate kind. Remove unused lookup error callbacks and
  context arguments while preserving typed invariant failures and shared
  compiled-expression ownership.
- Centralize projection, HAVING and top-k setup in the existing grouped page
  selector. Ordered and materialized execution share setup without merging their
  execution paths, changing compilation order or adding another cache.
- Replace bounded COUNT and generic/top-k heap roots in place instead of
  popping and pushing. Filtering, strict ordering, admission charges and final
  sorting are unchanged. Unbounded candidate staging stays: removing it would
  change aggregate-finalization versus HAVING/projection error precedence.

### 🧪 Testing

- Extend cold/warm diagnostics coverage with compiled aggregate input and FILTER
  expressions, and verify the execution handoff retains the complete metadata.
- Cover repeated, computed, filtered and DISTINCT aggregate outputs, HAVING-only
  slots, and rejection when required frozen aggregate metadata is absent.
- Verify materialized MIN/MAX results and bucket lookup matching, absence,
  invalid-index rejection and comparison-error propagation.
- Cover empty and zero-bound COUNT windows, ascending/descending replacement,
  oversized bounds, and cold/warm aggregate top-k windows including ties.
  Add a manual matched-actor instruction/cycle probe using the existing audit
  actor and retained build flow; no production endpoint is added.

### 📊 Audit

- Ownership and intermediate construction are simpler; the unused combined
  scan-result type is removed. Layout keeps a transient seen-slot bitmap, not
  another retained artifact or expression copy. Seventeen files changed across
  the combined .3 worktree: thirteen Rust files (approximately -153 production
  lines and +313 test/measurement lines) and four documentation files.
- The preceding fold-cleanup qualification passed 108 focused test executions.
  Page-selector qualification passes 69 focused executions, none ignored, plus
  strict core all-feature/all-target lint, formatting and whitespace checks.
  The heap slice passes 62 focused core executions and both matched PocketIC
  runs. Full-suite validation remains user-owned.
- The isolated heap change reduces raw audit Wasm from 4,477,650 to 4,477,458
  bytes (-192). Six-group probes save 4,052–6,835 instructions and cycles per
  call across three cache phases; results and cursors match. These are small
  workload-specific gains, not measurements of the whole .3 cleanup or larger
  workloads. See the [matched measurement](../reports/investigations/2026/09/19/grouped-heap-replacement/01/report.md).

## 0.259.2 — Query Preparation and Routing Cleanup

### 🩹 Fixed

- Preserve unchanged server-issued grouped cursors for decimal keys, including
  decimals within collections. Accepted group-key validation permits exact,
  representable scale normalization without rewriting the boundary or weakening
  stored-value validation; rounding, overflow and invalid types still reject.
- Authenticate grouped continuation framing and values using the existing
  scalar HMAC/key owner, then validate boundary arity and accepted key types
  before execution. Scalar token bytes are unchanged. Breaking grouped
  version-1 hard cut: discard saved grouped cursors and restart pagination;
  no stored-data migration, new key, or compatibility decoder.
- Reject grouped continuation without LIMIT and unsupported global DISTINCT
  continuation as invalid cursor requests, with distinct typed numeric reasons,
  rather than internal failures. Supported grouped queries and pagination are
  unchanged; no cursor or stored-data migration.
- Preserve internal cursor failures as `InvariantViolation` with `Cursor`
  origin at the query/session boundary instead of reporting a caller planning
  error. External cursor rejections keep their existing code and numeric facts.
  Potentially breaking for callers matching the previous diagnostic; no API,
  cursor encoding or stored-data migration.

### 🧹 Cleanup

- Encode and authenticate each emitted grouped cursor once inside the execution
  budget, then move those bytes into the response. Charge the actual unpadded
  Base64 length instead of a hexadecimal-sized estimate; no additional wire or
  stored-data change beyond the grouped hard cut above.
- Store one retained-slot requirement per field instead of parallel flags.
  Avoid default-only override vectors and share scalar byte-length eligibility
  through the accepted row layout. Full-value projection, ordering and cursor
  requirements still take precedence over length-only decoding.
- Require planner-supplied grouped limits instead of retaining an unused
  executor default path. Return grouped pages without a debug-only result
  envelope; check cardinality at construction and preserve global DISTINCT's
  implicit group for empty input.
- Dispatch fast streams directly from their request variant, removing a second
  route tag and its mismatch-only failure. Share row-collector/page request
  data and construction while retaining separate execution paths, cursor policy
  and eligibility checks.
- Compare borrowed aggregate identities when checking grouped projection layout
  and collecting unique aggregate slots. Copy input/filter expressions only
  when retaining a new aggregate entry; preserve canonical identity and
  first-seen slot ordering without introducing another comparison policy.
- Borrow grouped HAVING expressions from the retained plan instead of copying
  them into runtime payloads. Read scalar residual filters from their existing
  preparation owner without storing a duplicate reference. Grouped compilation
  still rejects invalid plan shapes with a typed error.
- Remove unused prefix-length fields from covering-plan payloads and derive
  grouped route intent from its existing planner strategy. Ordering proofs
  still use prefix length during planning; pure/hybrid covering execution,
  grouped routing and retention accounting keep their existing owners.
- Remove the redundant retained-slot override flag and require accepted schema
  identity in prepared execution cores. Projection-specific handoffs now require
  their projection contract at construction. Genuinely optional aggregate,
  continuation and lazy-cache states remain unchanged; no public API or stored
  format changes.
- Require the grouped preparation/layout bundle from the existing prepared-plan
  owner and delete the unreachable runtime reconstruction fallback. Missing
  planner metadata remains a typed invariant error; successful runtime assembly
  is infallible. Cache admission and retention accounting remain with their
  existing owner, and execution still receives the bundle when retention is

  Preserve aggregate probes, continuation/window-derived bounds and runtime

  actual strict/conservative execution preparation and aggregate diagnostics

- Compile covering predicates directly from borrowed plan inputs through the

  temporary preparation bundle; literal admission, unsupported results,

- Share immutable aggregate input/filter expressions between groups rather

- Retain only executable scalar projection metadata, not a second syntax tree
  used solely for its field count. Build direct-slot metadata from borrowed
