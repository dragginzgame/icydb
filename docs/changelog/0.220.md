# IcyDB 0.220 — Measured Runtime Footprint And Query Cost Contraction

## 0.220.0

### 📝 Summary

- Establishes one reproducible measurement authority for final deployable Wasm,
  SQL instruction profiles, schema-application lifecycle costs, and cumulative
  optimization budgets.
- Makes pinned, deterministic, complexity-bounded Binaryen output the sole Wasm
  installed by maintained build and integration paths.
- Removes global metrics work from generated synchronous query execution while
  retaining explicit scoped attribution and all update-side metrics.

### 🔧 Changed

- The canister artifact pipeline now applies Binaryen 108 `-Oz` with the exact
  accepted Wasm feature set and disables one-caller inlining of oversized
  functions. The transformed module is validated once and becomes the only
  deployable artifact; there is no compiler-output fallback or alternate
  post-link pipeline.
- Wasm reports fail closed unless source, tree, workspace, target, dependency,
  tool, feature, Candid, export, and final-artifact identities are complete.
  Controlled size comparisons also require a matched profile and common build
  provenance.
- Generated query wrappers enter a synchronous query-metrics context only
  around the authorized private handler. Global metric event construction,
  entity-path ownership, dispatch, and performance-counter reads are skipped in
  that context; explicit scoped sinks still observe events and update wrappers
  retain the existing durable metrics behavior.
- Query context is nesting-safe, restored during host unwinding, and ends before
  any returned future is polled. A trapped query cannot suppress later query or
  update metrics.
- Public Candid, IC method exports, query results, update behavior, accepted
  schemas, and persisted formats are unchanged. Query calls intentionally no
  longer contribute to the heap-only global metrics report.

### 📊 Audit

- Relative to the clean 0.219.2 opening matrix, final raw non-gzipped Wasm falls
  from 102,685 to 88,889 bytes for `default_empty`, 336,106 to 291,299 for
  `default_empty_metrics`, 2,657,049 to 2,339,214 for one-entity dynamic query,
  2,685,276 to 2,363,216 for one-entity typed query, 3,144,946 to 2,772,521 for
  one-entity SQL query, 2,686,725 to 2,364,515 for ten-entity typed query,
  4,189,460 to 3,660,100 for `sql_perf`, and 3,664,270 to 3,221,656 for the
  mutation-capable SQL actor. These are reductions of 11.84% through 13.44%.
- Across 32 generated SQL endpoint calls, the selected query cost falls from
  21,406,368 to 19,861,600 local instructions, or 7.22%. Exact-schema and
  ordered non-selected sentinels change by +0.0027% and +0.2848%, remaining
  within their 1% ceiling.
- Candid bytes and method export sets remain unchanged across the maintained
  production matrix. Deterministic transformation, final-module feature
  validation, populated upgrade, schema re-entry, query, mutation, DDL,
  metrics-context, formatting, invariant, and warnings-denied Clippy checks
  pass.
- The complete 0.220.0 line through Patch 3 affects roughly 43 source, build,
  test, and evidence files at approximately `+2,474/-260` lines before these
  release notes. Build and measurement infrastructure becomes more explicit;
  production query dispatch becomes simpler, while the pinned post-link stage
  adds bounded pipeline complexity.
- Full workspace tests, `make test`, and the ignored complete local/production
  artifact matrix remain user-owned push validation.
