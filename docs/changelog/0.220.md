# IcyDB 0.220 — Measured Runtime Footprint And Query Cost Contraction

## 0.220.2

### 📝 Summary

- Makes execution-plan decimal-scale metadata the sole authority for SQL
  projection formatting and removes the duplicated label parser.
- Records an evidence-backed no-change disposition for ordered-range execution:
  required row and key work dominates while selection is already bounded.
- Makes SQL witness scheduling and coverage metadata code-owned instead of
  compiling historical JSON or parsing the SQL contract document.

### 🔧 Changed

- Scalar and grouped SQL projection output now consume the exact fixed-decimal
  scale vector already produced by the execution plan. Successful values and
  labels remain unchanged.
- The current ordered-range path retains its existing row representation. P1
  and 2,048-row scale evidence show bounded `LIMIT + 1` candidate retention and
  attribute the dominant cost to required row decoding and key streaming.
- Thirty-two generated SQL witness declarations now live in one typed schedule,
  with independently derived structural signatures and a schedule-bound Tier C
  evidence format version 4. There is no compatibility decoder.
- The typed SQL coverage manifest now solely owns machine-readable feature
  identity, kind, status, and contract-section metadata. The SQL subset remains
  a human-readable behavioral contract without embedded parser directives.
- Typed replacement of the remaining source-path and test-symbol provider scan
  is explicitly deferred; its evidence check is retained until that replacement
  exists.
- Public Candid, method exports, successful query results, query ordering,
  cursors, accepted schema, persisted formats, and dependencies remain
  unchanged.

### 📊 Audit

- The one-entity typed-query control remains exactly 2,358,932 final raw bytes.
  The selected SQL actor falls from 2,768,673 to 2,767,862 bytes, a reduction of
  811 bytes or 0.0293%; its Candid and method exports are unchanged.
- Production SQL boundary code removes 33 net lines and one heuristic
  interpretation path. The evidence-authority cleanup removes a further 277
  lines while adding 11 explicit typed/documentation lines.
- The complete current P1 rerank passes 1,787 scenarios across eight shards,
  and the selected 2,048-row scale receipt confirms bounded peak retention of
  11. Focused SQL facade, generator, correctness-manifest, formatting,
  invariant, and warnings-denied Clippy checks pass.
- Full workspace tests, `make test`, the clean-source P2 confirmation, and the
  complete build/Wasm matrix remain user-owned push validation.

## 0.220.1

### 📝 Summary

- Keeps the existing metrics implementation after a complete compact-state
  candidate failed to improve final deployable Wasm.
- Simplifies schema field-type and named-composite lowering around one closed
  initial/accepted identity authority, removing accidental generic code
  generation and duplicated shape logic.

### 🔧 Changed

- Recursive field-type lowering no longer accepts arbitrary resolver closures.
  Initial proposals resolve only their freshly allocated candidate identities;
  existing schemas and runtime typed binding resolve only through accepted
  source bindings.
- Initial and existing named composites now share the same lowering for
  newtypes, lists, sets, maps, and tuples. Record identity allocation remains
  separate because initial and accepted catalogs perform different identity
  operations.
- `apply_schema` remains the sole catalog-native schema application path.
  Generated models, compatibility fallbacks, and alternate application routes
  were not introduced.
- Public Candid, endpoint exports, accepted schemas, persisted formats, query
  results, schema transitions, recovery, and error behavior remain unchanged.

### 📊 Audit

- The compact fixed-array metrics candidate passed focused behavioral checks
  but increased the released metrics actor from 291,903 to 291,948 raw bytes.
  It was removed completely; production metrics code and runtime cost remain
  identical to 0.220.0.
- The retained schema contraction reduces the one-entity typed-query actor from
  2,363,477 to 2,358,932 raw bytes (-4,545; 0.192%) and `sql_perf` from
  3,660,100 to 3,656,367 (-3,733; 0.102%). Candid hashes and method export sets
  are unchanged.
- First-create schema application moves by 514 instructions on a 50.6-million
  instruction path (+0.0010%). Exact post-update and post-upgrade re-entry are
  unchanged at 7,184,246 and 7,196,086 instructions.
- Focused initial/existing lowering, application, recovery, migration,
  dynamic-write, query-only bootstrap, lifecycle, no-default compilation,
  formatting, invariant, measurement-contract, and warnings-denied Clippy
  checks pass. Full workspace tests remain user-owned push validation.

## 0.220.0

### 📝 Summary

- Establishes one reproducible measurement authority for final deployable Wasm,
  SQL instruction profiles, schema-application lifecycle costs, and cumulative
  optimization budgets.
- Makes pinned, deterministic, complexity-bounded Binaryen output the sole Wasm
  installed by maintained build and integration paths.
- Removes global metrics work from generated synchronous query execution while
  retaining explicit scoped attribution and all update-side metrics.

### 🔧 Changed

- The canister artifact pipeline now applies Binaryen 108 `-Oz` with the exact
  accepted Wasm feature set and disables one-caller inlining of oversized
  functions. The transformed module is validated once and becomes the only
  deployable artifact; there is no compiler-output fallback or alternate
  post-link pipeline.
- Wasm reports fail closed unless source, tree, workspace, target, dependency,
  tool, feature, Candid, export, and final-artifact identities are complete.
  Controlled size comparisons also require a matched profile and common build
  provenance.
- Generated query wrappers enter a synchronous query-metrics context only
  around the authorized private handler. Global metric event construction,
  entity-path ownership, dispatch, and performance-counter reads are skipped in
  that context; explicit scoped sinks still observe events and update wrappers
  retain the existing durable metrics behavior.
- Query context is nesting-safe, restored during host unwinding, and ends before
  any returned future is polled. A trapped query cannot suppress later query or
  update metrics.
- Public Candid, IC method exports, query results, update behavior, accepted
  schemas, and persisted formats are unchanged. Query calls intentionally no
  longer contribute to the heap-only global metrics report.

### 📊 Audit

- Relative to the clean 0.219.2 opening matrix, final raw non-gzipped Wasm falls
  from 102,685 to 88,889 bytes for `default_empty`, 336,106 to 291,299 for
  `default_empty_metrics`, 2,657,049 to 2,339,214 for one-entity dynamic query,
  2,685,276 to 2,363,216 for one-entity typed query, 3,144,946 to 2,772,521 for
  one-entity SQL query, 2,686,725 to 2,364,515 for ten-entity typed query,
  4,189,460 to 3,660,100 for `sql_perf`, and 3,664,270 to 3,221,656 for the
  mutation-capable SQL actor. These are reductions of 11.84% through 13.44%.
- Across 32 generated SQL endpoint calls, the selected query cost falls from
  21,406,368 to 19,861,600 local instructions, or 7.22%. Exact-schema and
  ordered non-selected sentinels change by +0.0027% and +0.2848%, remaining
  within their 1% ceiling.
- Candid bytes and method export sets remain unchanged across the maintained
  production matrix. Deterministic transformation, final-module feature
  validation, populated upgrade, schema re-entry, query, mutation, DDL,
  metrics-context, formatting, invariant, and warnings-denied Clippy checks
  pass.
- The complete 0.220.0 line through Patch 3 affects roughly 43 source, build,
  test, and evidence files at approximately `+2,474/-260` lines before these
  release notes. Build and measurement infrastructure becomes more explicit;
  production query dispatch becomes simpler, while the pinned post-link stage
  adds bounded pipeline complexity.
- Full workspace tests, `make test`, and the ignored complete local/production
  artifact matrix remain user-owned push validation.
