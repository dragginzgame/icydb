# 0.278

## [0.278.0]

### ⚠️ Breaking

- Public principal conversions and read-authorization contexts now use the
  Platform-owned `ic_platform::Principal` from 0.4.0. Update the consumer
  dependency and explicitly convert external Agent/PocketIC/DTO identities with
  `.into()` at their boundary. PocketIC transport parameters retain
  `ic_platform::principal::ExternalPrincipal`. Principal text, Wire frames,
  stored bytes and authorization decisions are unchanged; no data rewrite or
  endpoint protocol migration is required.

### 🔧 Changed

- Keep the selected endpoint value through CLI request encoding and response
  decoding instead of converting its name back into an endpoint. Metrics,
  snapshot, schema and migration commands share call-and-decode helpers for
  their query/update lanes. Remove repeated command-level response plumbing
  and obsolete string lookup/closure helpers. Wire identities, admission limits,
  canister probes, transport versus application error context, migration budgets
  and SQL rendering remain unchanged. Process fixtures qualify all four report
  operations, while decoder cases reject wrong endpoint and direction frames.
- Disable `ctor`'s unused priority feature while retaining ordinary host
  registration before `main` and its procedural macro. Remove `link-section`
  from the lockfile. The complete schema-only fixture fragment remains
  byte-identical; graph sealing and diagnostics do not depend on registration
  order. Make Core's `ic-metrics` dependency optional under the existing
  `metrics` feature, removing it from metrics-disabled facade graphs without
  changing metrics-enabled selections or reporting behavior. Native macOS CI
  selects the actual constructor-produced schema fragment regression.
- Keep Proptest's standard property-testing support while disabling unused
  subprocess, timeout and bit-set features. Remove `rusty-fork`, `wait-timeout`,
  `quick-error`, `bit-set`, `bit-vec`, `borsh` and `borsh-derive` from the lockfile.
  Account, Decimal and ordered-index property strategies, case counts, shrinking
  and regression persistence remain supported. This trims test tooling;
  production dependency selections and database contracts are unchanged.
- Adopt published IC Platform 0.4.0 with its matching generator and owned
  Principal. Preserve IcyDB's principal bytes, text diagnostics, Wire frames
  and binary Serde representation, including identities beginning with `0x02`.
  Its `cdk` feature retains the Candid-free runtime adapters, registry executor
  2.0.0 and ic0 1.2.0 identities. Existing caller/argument helpers retain their
  imports; IcyDB adds no runtime or compatibility wrapper. The removed Candid
  call conveniences and changed runtime RejectCode/signature identities have no
  local consumers; external PocketIC rejects retain their existing types.
  Generated SQL/schema authorization accepts Platform's infallible external
  Principal conversion at the existing helper boundary. Application guards
  still receive the owned identity; anonymous rejection and trap propagation
  remain unchanged for the pinned Canic adapter.
  Select its native `pocket-ic` feature in integration support. Import PocketIC
  clients and rejection types through Platform instead of Testkit's broad
  upstream re-export. Native transport imports explicitly select Platform's
  `ExternalPrincipal`, preserving PocketIC's original parameter/DTO identities,
  PocketIC 16.1.0, Testkit setup/lifecycle and IC Wire protocols. The pinned Canic
  adapter still brings full CDK/Candid transitively; published Testkit 0.57.0
  still selects Platform 0.2.2. This adoption does not
  claim to remove those upstream edges or migrate Canic-owned entrypoints.
  Direct-dependency checks also cover Agent, PocketIC, certification, IC
  signature and ledger/management packages through their canonical identities.
- Adopt published IC Host 0.31.1 for filesystem, artifact, text and tool helpers.
  Explicitly select only the CLI's `temporary-file` backend; capability-backed
  filesystem operations remain disabled. The CLI uses Host's scoped temporary-file
  guard for binary ICP arguments, removing its direct `tempfile` dependency.
  Preserve private permissions, exact Wire bytes,
  argument-file lifetime through child completion, and cleanup after success,
  child/decoder errors and unwinding. Partial-write failures preserve their
  creation/write distinction and report a failed cleanup cause when present.
  Direct dependency checks prevent workspace-owned `tempfile` declarations;
  upstream packages retain their own dependency choices.
  Published IC Build 0.22.1 supplies the matching Host Process 0.31 child
  identity for single/batch spawners, resolving the reproduced Build 0.22.0
  compilation failure. Select Process 0.31.1 and prepare the locked 0.22.1
  release editor without adding child conversions or changing process custody
  ([Build #9 — Qualify consumers against the current Host boundary](https://github.com/dragginzgame/ic-build/issues/9)).
- Refresh the canonical Shared Tooling snapshot to 0.25.4, revision
  `db555ab6cf4a93af9a183f18d921d3b0ee97c725`. Bind explicit Cargo-tool features
  into immutable selections/receipts, preserve failed fixture evidence and
  improve offline admission diagnostics. Prepare tools once for the new installer
  policy; offline checks do not repair old selections. The retired Perl Cargo renderers
  leave the snapshot; IcyDB's release lock preparation and receipt admission use
  the explicitly prepared registry IC Build editor with a positive input bound.
  Failed Git or editor observations cannot authorize a receipt after emitting
  complete-looking bytes. Existing manifest preparation, pin exceptions,
  enclosing rollback and release effects remain with IcyDB.
- Make release adapters select the locked editor and an eight MiB input allowance
  without per-shell exports. Fresh setup prepares it with the other selected
  tools; offline and recovery callbacks check preparation before dispatch.
  Static and native macOS CI use the same Make selection for release fixtures.
  No release operation runs during setup. Qualify failed editor admission even
  when a producer emits a complete-looking executable path. Saved callbacks
  select from the committed source lock, preserving failed selection inputs;
  newer or partially prepared working metadata cannot replace that selection.

### 🩹 Fixed

- Supply an isolated editor selection to Cargo transport fixtures for release
  callbacks and compiled-invariant dispatch. Verify that metadata and receipt
  children receive the selected editor and eight MiB input allowance. The
  dedicated release fixtures retain real selector/admission coverage; production
  release admission remains unchanged.
- Apply generated and managed primary-key ownership to missing-row replacement
  in the shared structural mutation executor, replacing the Identity-only guard.
  Reject caller-chosen generated `Ulid`/`Timestamp` keys with the existing
  database-owned-field diagnostic. Existing-row replacement, caller-owned-key
  upserts, scalar/composite key ordering and typed/dynamic batch atomicity remain
  supported; no persisted format or accepted-schema changes
  ([#226 — Missing-row replacement authors generated keys](https://github.com/dragginzgame/icydb/issues/226)).
- Reject field-path separators in newly added DDL column names and rename
  targets at the schema mutation owner. SQL binding retains the existing DDL
  validation diagnostic, and accepted-after derivation also rejects manually
  constructed invalid candidates. Rejected statements leave accepted versions
  and rows unchanged. Retained dotted field names remain available for exact
  lookup, rename to a valid root and drop; no persisted reader or format changes
  ([#109 — DDL accepts unaddressable dotted column names](https://github.com/dragginzgame/icydb/issues/109)).
- Let `schema migration run` continue through identical public status pages:
  journal draining and final validation can advance private cursors without
  changing those pages. Reuse the existing abort ceiling of 1,024 update calls
  per invocation, report progress every 128 nonterminal replies, and print the
  latest status before stopping at the ceiling. Repeating the command resumes
  retained work; terminal results, identity checks and Wire failures retain
  their existing behavior ([#45 — Migration run mistakes unchanged status for a stall](https://github.com/dragginzgame/icydb/issues/45)).
  Both native macOS jobs select the CLI migration process regressions.
- Give Wasm-audit, read-admission and release-receipt fixtures explicit temporary
  directory templates. Darwin's implicit `mktemp` directory can ignore `TMPDIR`,
  placing failure evidence outside the collector's selected root. Completion
  qualification now exercises that behavior on every host while retaining all
  status, completion and evidence assertions
  ([#361 — Separate build and Wasm reporting from PocketIC](https://github.com/dragginzgame/icydb/issues/361)).
