# 0.278 release notes

## [0.278.0]

- **Breaking:** database access verifies an explicitly bound runtime instead of
  constructing memory through a pool callback. Composed hosts bind their committed
  runtime before participant startup; standalone lifecycle exports explicitly
  bootstrap before database startup. Generated actors and host adapters must
  update together. Allocation mappings, stored bytes and journal admission are
  unchanged. The Canic adapter is selected at the immutable runtime-handoff revision.

Standalone callers invoke generated `bootstrap_standalone_memory(pool)` once before
startup; composed callers bootstrap all declarations in their host and call
`bind_memory_runtime` before the IcyDB participant. Pool providers only describe
grants and exclusions and cannot stand in for runtime binding. Ordinary database
access only verifies authority and cannot create another manager.

Canic owns lifecycle exports and transport; the retired IcyDB lifecycle macros
are not restored. Native fixtures follow the same explicit binding contract.
