# IcyDB 0.213: Schema Authority And Application Separation

## 0.213.33

### 📝 Summary

- Maintained schemas, canisters, examples, and fixtures now consume
  `icydb-model` and `icydb-model-macros` directly.
- The final consumer cutover removes the temporary and retired implementation
  owners instead of preserving them behind compatibility layers.

### 🔧 Changed

- Typed reads now use accepted-schema-bound adapters, dynamic reads use the
  standalone accepted-schema lane, and fixture batch insertion uses the
  explicit structural insert boundary.
- Index-name normalization now has one canonical `icydb-schema` owner shared
  by model generation and runtime identity.
- Generated application writes use the distinct `<Entity>Insert`,
  `<Entity>Patch`, and `<Entity>Replace` inputs. `_Create` is not retained as
  an alias.
- Active examples, contracts, guides, audit subjects, and architecture guards
  now describe only the maintained package and API ownership.
- SQL contract coverage now cites maintained parser and public canister tests
  rather than deleted session-test modules, and the default facade compile
  contract executes a real structural-write fixture.

### 🗑️ Removed

- Removed `icydb-model-legacy`, `icydb-schema-derive`, `icydb-derive`,
  `icydb-build`, `icydb-utils`, the embedded `icydb::base` copy, and the
  obsolete macro re-exports.
- Removed the generated entity/fluent facade, callback-backed database
  behavior, generated persisted-row adapter, old response/pagination
  surfaces, and their implementation-coupled fixtures and tests.
- Removed negative compatibility guards whose only purpose was preserving
  retired names or pathways.

### ⚠️ Breaking

- Applications must import authoring types and macros from `icydb-model` and
  use the current typed, dynamic, SQL, or structural database boundaries.
- The removed packages, facade methods, generated `_Create` input, callbacks,
  and old cursor/response shapes have no aliases, shims, or fallback readers.
  Pre-1.0 callers should rebuild directly against the current surface.
- This cut changes source and generated API compatibility. It does not change
  accepted-schema, physical row, index, relation, journal, or commit-marker
  bytes.

### 📊 Audit

- The exact committed hard-cut range touches 1,163 files at
  `+5,288/-271,114` lines, a net removal of 265,826 lines. The bounded
  pre-push evidence correction touches 15 files at `+273/-264`.
- The workspace resolves to 30 current packages, and maintained-source
  searches find no retired package, fluent/entity authority, callback, or
  generated persisted-row path.
- Focused model, macro, facade, core, compile-UI, no-default-feature, consumer,
  Clippy, formatting, dependency/layering, and invariant checks pass. Full
  repository validation remains part of the human-owned push workflow.
- Raw non-gzipped `sql_perf` Wasm is 5,012,221 bytes with SHA-256
  `aaf1272c92ed3eaa564648489110ce603c5d0d7073d14a72bdc23296495b7f6e`.
  This is 40,306 bytes (+0.8107%) above 0.213.32 but 145,261 bytes (-2.8165%)
  below the 0.213 baseline. The canonical shrunk artifact is 4,664,671 bytes.
- The SQL performance target compiles, but sandboxed instruction collection
  cannot bind PocketIC. Final runtime instruction evidence therefore remains
  part of the human push workflow.

## 0.213.23

### 📝 Summary

- Applications can issue accepted-schema-driven structural insert, update,
  replace, and delete requests without defining a generated Rust entity.
- Trusted SQL mutations and structural writes now share one database-owned
  after-image path for defaults, constraints, relations, returned rows, and
  managed timestamps.

### ➕ Added

- `StructuralMutation`, `StructuralPatch`, and `WriteCell` preserve omitted,
  explicit-default, explicit-null, and authored-value intent until accepted
  policy resolves the final row.
- Structural mutations return canonical accepted rows through
  `DynamicMutationResult`.
- Opaque `TypedEntityBinding` values and IcyDB-owned typed row/write adapter
  traits establish the opt-in generated adapter boundary without exposing
  physical slots or accepted fingerprints.

### ⚠️ Breaking

- Trusted SQL mutation, exact-update, prefix-update, and resumable-update
  entrypoints no longer accept a generated entity type parameter. The entity
  is derived from the SQL statement; callers must remove the `::<Entity>`
  argument.
- Resumable update tokens now durably carry their frozen operation timestamp.
  Tokens created by the earlier development shape fail closed; no
  compatibility decoder is retained.
- The application time-sanitizer path is removed. Database-managed creation
  and update timestamps are resolved only by accepted field policy.

### 🔧 Changed

- Inserts assign one operation timestamp to both managed timestamp fields.
  Semantic no-ops preserve the existing update timestamp, real changes
  advance it, and a clock earlier than the stored value fails closed.
- Atomic and non-atomic batches reuse one request timestamp. Resumable updates
  bind the timestamp before the first chunk so retries cannot reevaluate time.
- Obsolete structural save projection and duplicated SQL returning machinery
  are removed. Count-only typed deletes retain their distinct accepted-row
  kernel because they deliberately avoid typed row materialization.
- Independent build and derive consumers now use `syn 3.0.3`.
  `icydb-schema-derive` keeps an explicitly named Syn 2 dependency at
  Darling's current AST boundary rather than mixing incompatible syntax-tree
  types.
- Accepted-schema, persisted-row, index, relation, journal, marker, cursor,
