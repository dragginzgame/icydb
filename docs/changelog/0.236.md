# 0.236 Exact-Cardinality Planner Tie-Breaking

## 0.236.1 - 2026-08-21

### 🩹 Fixed

- A SQL command first executed while exact cardinality was unavailable no
  longer retains that fallback in its command-local prepared-plan slot. It
  continues through the canonical shared cache until the existing lifecycle
  stamp observes Ready, then retains the exact-selected plan normally. Global
  aggregate and scalar SELECT lanes use the same rule.

### 📊 Audit

- A production-shaped PocketIC fixture returns the same two rows while reducing
  index entries read from 10,001 to 2 and local instructions from about 1.102
  billion to 2.67 million. An unchanged unavailable fallback remains within the
  5%/2-million hot-path gate; a warm exact selection costs about 1.44 million
  instructions; and the same pinned page before and after Ready differs by
  about 58 thousand instructions (1.28%).
- Maintained maximum shapes admit 64 tied candidates in about 56.1 million
  instructions and 256 exact probes carrying 3,072,000 logical component bytes
  in about 136.5 million instructions, both far below the 10-billion query
  ceiling and within the fixed memory envelope.
- A same-Wasm upgrade during Building preserves the exact stable-memory byte
  length, resumes existing cardinality construction, preserves an issued
  cursor route through Ready publication, and adds no stable representation.
  The final representative typed artifact is 2,118,856 raw Wasm bytes, only
  156 bytes above a fresh exact-`v0.235.1` build. The SQL-enabled artifact is
  3,284,381 raw bytes, a 17,128-byte / 0.524% increase; Candid and exports
  remain unchanged for both surfaces.
- Independent closeout proof now freezes structural and residual precedence,
  every first-over advisory-policy boundary, exact-one route-pin selection,
  foreign root/index rejection, target-write continuation, authenticated pin
  corruption, and the predecessor-layout hard cut.
- The shared SQL audit schema moved the unchanged maximum-fanout fixture to
  about 5.288 million instructions and the two-index sparse intersection to
  about 2.264 million. Their ceilings are re-frozen at 5.300 million and 2.300
  million while the independent 65-entry/zero-fetch and 41-entry/one-fetch
  physical-work gates remain unchanged.

## 0.236.0 - 2026-08-21

### ➕ Added

- The canonical planner may use the existing exact accepted-prefix
  cardinality proof to resolve only a final structural and residual tie among
  non-grouped `IndexPrefix`, `IndexMultiLookup`, or `IndexBranchSet` routes.
  Complete evidence chooses the fewest exact matching prefix entries; equal or
  unavailable evidence preserves the predecessor lexicographic decision.
- Structured and verbose explain report bounded selection-time candidate
  counts, the evidence state, and `exact_cardinality_tiebreak` without exposing
  encoded prefixes, row keys, cursor material, SQL, or parameter fingerprints
  through metrics or errors.

### 🔧 Changed

- Parameterized templates retain bounded accepted candidate authority so new
  values run the same single planner decision. Exact-selected cache entries
  remain advisory and may become cardinality-stale until ordinary cache
  replacement; only an unavailable fallback compares an opaque lifecycle stamp
  so a later Ready publication is observed.
- Scalar cursor version 1 is hard-cut in place to authenticate an optional
  accepted `IndexId`, access family, and consumed-prefix-arity route pin.
  Exact and structural fallback cursors therefore resume their issued route
  without fresh cardinality work. There is no predecessor decoder, alternate
  version, caller-selected route, or compatibility fallback.
- One StoreHandle call proves the complete bounded prefix batch. Fixed limits
  are 64 tied candidates, 256 probes, 4 MiB cumulative encoded components, 16
  prefixes per candidate, and 1 MiB per-candidate transient lowering including
  both raw scan bounds. Optional policy exhaustion preserves query admission
  and the predecessor route.

### 📊 Audit

- The implementation extends the existing planner, shared cache, exact
  cardinality owner, explain snapshot, and cursor codec. It adds no persisted
  statistics, stable allocation, optimizer mode, second cache, executor route,
  public endpoint, Candid type, caller hint, or generated-model authority.
- Focused native tests cover selective Prefix and BranchSet decisions,
  MultiLookup exact/equal fallback, range/grouped exclusion, parameter rebinding,
  cardinality-stale warm reuse, unavailable-to-Ready refresh, and pinned cursor
  resume without evidence probes. The preliminary representative artifact is
  2,118,711 raw Wasm bytes, 22 bytes smaller than a clean exact-`v0.235.1`
  rebuild, with identical 2,419,238-byte compiler Wasm, 64-byte Candid, and six
  exports. IC instruction, maximum-bound, recovery, and final closeout
  measurements remain assigned to the next 0.236 landing patch.
