# 0.272 — Tracked instruction metrics

## [0.272.0]

### ⚠️ Breaking

- Adopt Metrics 0.8 tracked aggregates for entity, schema-owner and journal-fold
  observations. Reports add actual sample/total overflow flags and a
  producer-projected exact optional instruction mean. Exactly reached sample
  caps remain valid; empty or overflowed windows have no mean. Update current
  Candid bindings and the CLI together. Heap windows clear on upgrade/reset;
  no stable format or compatibility decoder is introduced
  ([#354](https://github.com/dragginzgame/icydb/issues/354)).

### 🔧 Changed

- Consume the producer's admitted mean in the CLI and remove its direct Metrics
  dependency. Mark clipped entity counters with `+` and display actual overflow
  quality for journal-fold and startup observations. Keep measurement arithmetic
  and quality with one recording owner.
- Use Timers 0.20 typed retained starts in all direct startup-probe registrations,
  preserving initial schedules, callback lifetimes and rearming.
- Align the current upstream graph with Host 0.15.1, Memory 0.35.19, Metrics
  0.8.1, Timers 0.21.1 and Testkit 0.35.0. Consume generic Cargo/Wasm artifact APIs
  directly from published IC Build 0.1.1, retaining product recipes and cache
  formats. Testkit continues to own PocketIC infrastructure
  ([IC Build #1](https://github.com/dragginzgame/ic-build/issues/1)).
- Adopt Host 0.15's optional interface owner for artifact method inventories.
  Parser-backed Candid inspection replaces the local comment/declaration scanner
  and supports aliases, constructors and quoted names while rejecting invalid
  types, duplicate methods and imports. Keep empty-name and oneway refusal,
  expected actor methods, the exact CDK timer-executor exception and generated
  ABI local. Wasm method decoding reuses the existing structural facts; Candid
  extraction uses the new module path without changing retained text
  ([#307](https://github.com/dragginzgame/icydb/issues/307),
  [Host #71](https://github.com/dragginzgame/ic-host-tooling/issues/71)).

- Adopt committed Shared Tooling 0.9.4. Host/IC asset setup shares bounded
  transient download retries; permanent errors and checksum failures remain
  terminal. All installers reject supplied or resolved CR/LF consumer paths
  before setup. Evidence checksums reject NUL bytes before hashing, and snapshot
  and release recovery admit only complete 40- or 64-character Git identities.
  Keep existing selections and same-contract recovery
  ([#302](https://github.com/dragginzgame/icydb/issues/302),
  [Shared #133](https://github.com/dragginzgame/shared-tooling/issues/133),
  [Shared #138](https://github.com/dragginzgame/shared-tooling/issues/138)).
- Adopt Shared Tooling 0.9.1's common host/IC installation lifecycle. Both
  installers reuse shared locking, verified-cache activation and cleanup;
  checkout cleanup failure still releases the shared lock and preserves the
  original installation error. Cleanup-only failures return nonzero
  ([#302](https://github.com/dragginzgame/icydb/issues/302)).
- Align testing guidance with generated-model fixtures, PocketIC integration
  binaries and actual native/live/local CI selections. Clarify that CI's `check`
  aggregate is one of three required release checks
  ([#123](https://github.com/dragginzgame/icydb/issues/123)).
- Adopt committed Shared Tooling 0.9.0's common validated manifest reader.
  Snapshot refresh and integrity verification consume the same captured records,
  reject embedded NUL bytes and publish no parsed records on malformed input.
  Preserve the existing selected tooling closure and executable pins
  ([#302](https://github.com/dragginzgame/icydb/issues/302),
  [Shared #133](https://github.com/dragginzgame/shared-tooling/issues/133)).
- Adopt reviewed Shared Tooling 0.8.4. Snapshot refresh atomically replaces each
  admitted payload and derives the common Make installers and LOC helper from
  declared companions. Retain current command entrypoints and add the Cargo-tool
  freshness task document required by shared navigation; optional fleet helpers
  remain with Shared Tooling. Ignore interrupted payload scratch beside its
  destination so exact-source retry remains usable
  ([#302](https://github.com/dragginzgame/icydb/issues/302),
  [Shared #131](https://github.com/dragginzgame/shared-tooling/issues/131)).
- Formatting admission consumes the same selected Rust catalog as installation.
  Cargo-tool setup refuses redirected observed-identity files before writing
  diagnostics, preserving outside bytes and prior selections
  ([Shared #135](https://github.com/dragginzgame/shared-tooling/issues/135),
  [Shared #136](https://github.com/dragginzgame/shared-tooling/issues/136)).
- The canonical workspace LOC helper supports `--json`, projecting crate rows
  and numeric totals from the same counted inputs as its human-readable report.
  Partial failures retain their status without publishing an incomplete document.

### 🩹 Fixed

- Bound the initial row allocation for scalar and primary-covering reads even
  when trusted SQL uses the maximum limit. Preserve logical limits, offsets and
  typed execution-budget rejection; grow retained rows only as scanning proceeds
  ([#116](https://github.com/dragginzgame/icydb/issues/116)).
- Admit branch-ordered prefix families through the same child-count and
  construction-budget owner as merged families. Charge sort descriptors and
  lower-key copies before allocation; preserve direction, repeated operands and
  typed rejection before any index entry is visited
  ([#155](https://github.com/dragginzgame/icydb/issues/155)).
- Replace empty Tier A filters with actual native oracle samples. Reuse the
  scheduled fixture/runner owners with one seed/repetition per obligation and
  compare IcyDB against SQLite and the independent mutation model. Both Make
  selections fail when no passing test executes, including dispatch through the
  consumer adapter fixture; Tier C retains full repeated
  receipt coverage ([#41](https://github.com/dragginzgame/icydb/issues/41)).
- Annotate migration revisions and finding-page acknowledgements as Candid
  `nat64`, including absent acknowledgements. Advance, Abort and Adopt decode
  without a canister interface supplying numeric types; operator status
  presentation is unchanged ([#48](https://github.com/dragginzgame/icydb/issues/48)).
- Count actual key-plus-row bytes in both default and explicit per-entity
  storage rollups, matching physical data totals apart from malformed keys
  that cannot be assigned to an entity
  ([#172](https://github.com/dragginzgame/icydb/issues/172)).
- Reject a marker envelope whose encoded length disagrees with its precomputed
  frame before durable publication; valid marker bytes and recovery remain
  unchanged ([#139](https://github.com/dragginzgame/icydb/issues/139)).
- Credit automatic SQL coverage only to enabled tests registered by Cargo in
  maintained CI selections. Remove redundant credit from the separately requested
  artifact-profile test, reject direct or conditional ignoring, and qualify
  unfiltered workspace/Tier B execution in the existing CI topology guard.
  Include provider-to-CI bindings in the coverage identity and regenerate Tier C
  receipts for that maintained manifest; the evidence format remains version 1
  ([#118](https://github.com/dragginzgame/icydb/issues/118)).
- Preserve ICP status failures and identify failed executable launches. SQL
  preconditions and canister listing report the original child diagnostic;
  errors no longer imply a missing canister or a local network outage.
  Refresh admits deployment only after a successful JSON status probe and uses
  `module_hash` to distinguish installed Wasm from a created, empty canister.
  Failed or malformed probes stop before deployment
  ([#126](https://github.com/dragginzgame/icydb/issues/126),
  [#127](https://github.com/dragginzgame/icydb/issues/127)).
- Keep the interactive SQL shell usable when history loading or persistence
  fails. Report path-specific warnings and attempt history persistence after
  executing completed statements. Missing history is ordinary first use;
  SQL errors still render normally and unfinished input is discarded
  ([#132](https://github.com/dragginzgame/icydb/issues/132)).
