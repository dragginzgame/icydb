# 0.234 Downstream Schema And Facade Completion

## 0.234.0 - 2026-08-20

### ➕ Added

- `DbSession::execute_exact_count` returns exact visible `u64` cardinality for
  one dynamic query, and typed `Query::execute_exact_count` reaches the same
  accepted-schema-bound terminal through its immutable binding.

### 🔧 Changed

- Exact entity and user-index-prefix execution is now shared below the SQL
  adapter. SQL retains its ordinary aggregate fallback contract, while the new
  public terminals fail closed when exact metadata is unavailable.
- Public exact counts admit only a bare entity query or one strict equality or
  non-empty `IN` filter over the leading field of an accepted unfiltered
  field-path user index, including a leading prefix of a composite index. `IN`
  input is capped at the existing 16-prefix planner bound; projection,
  ordering, limits, grouping, cursors, residual predicates, and nonindexed
  filters are rejected.

### 📚 Documentation

- The maintained schema-authoring guide now lists the exact primary-key
  primitive and reserved field-name contracts, explains why text slugs and
  external principals normally remain indexed domain fields beside durable
  identity, and records the enforced `_id`/`_ids` relation suffixes.
- Single- and multi-canister layouts now show why the host build and Wasm target
  consume the same schema/model library while every canister retains its own
  accepted schema and database authority.

### 🧪 Testing

- Exact-count regressions cover empty and populated entity counts, indexed
  equality, deduplicated bounded `IN`, a leading composite-index prefix, zero
  matches, a larger matching population, unavailable cardinality metadata,
  stale typed bindings, and rejection of residual, nonindexed, over-limit, and
  non-scalar shapes.
- Physical-work evidence records zero row fetches and zero index-entry reads
  for both small and larger matching populations. The shared executor charges
  work by the admitted metadata target count, not matching row population.
- A no-SQL public compile contract reaches both dynamic and typed exact-count
  terminals. The schema/model invariant check derives the guide's primary-key
  and reserved-name lists from their canonical source registries and verifies
  links from maintained author entry points.
- Watchdog delivery in PocketIC advances the one-second cadence once and then
  gives the admitted message four zero-time completion ticks, matching ordinary
  fixture setup without admitting another scheduled wake-up. A residual-bound
  failure now reports bounded scheduler and work counters instead of an opaque
  timeout assertion.

### 📊 Audit

- One shared planner adapter and one exact-cardinality executor now serve SQL,
  dynamic, and typed callers. There is no scan fallback, alternate planner,
  caller-selected budget, continuation, or generated-model reconstruction.
- Existing exact-cardinality scale evidence remains applicable to the shared
  executor; this patch adds zero-physical-read facade evidence. The maintained
  one-entity typed-query control measures 2,117,584 final raw Wasm bytes
  (`+138`, `+0.0065%`), 810,720 deterministic gzip bytes (`-790`), 64 Candid
  bytes, and six unchanged exports against `v0.233.3`. The closeout patch
  changes documentation, tests, and CI guards only, so these are also the final
  0.234.0 artifact values; endpoint and instruction behavior do not change.
- The line remains one accepted mutation executor, one accepted-schema runtime
  authority, and one exact-cardinality metadata executor. It adds no persisted
  state, stable allocation, Candid method, export, scan fallback, or generated-
  model reconstruction route.
- Patch 4 touches 11 documentation, test, and CI files at approximately
  `+300/-5` lines. The closeout correction documents and directly proves the
  already-supported leading prefix of a composite index without changing
  production code. The final candidate touches 34 files at approximately
  `+1,020/-304` lines. Runtime state-space stays neutral, while maintenance
  complexity rises slightly for the two Rust terminals and source-derived
  documentation guard.
