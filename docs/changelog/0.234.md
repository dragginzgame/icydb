# 0.234 Downstream Schema And Facade Completion

## 0.234.0 - 2026-08-20

### ➕ Added

- `DbSession::execute_trusted_typed_write_batch` executes a non-empty vector of
  generated `TypedWrite` values atomically when every value carries the same
  exact current binding. It inherits the existing 4,096-operation, 16 MiB
  staged-byte, and 1 MiB result limits without adding a typed-only budget or
  executor.
- The carried mutation-job closeout adds bounded target-failure reasons,
  privacy-safe lifecycle/resource metrics, and exact retained-record byte
  reporting.

### 🩹 Fixed

- Generated entity check constraints now resolve schema-native enum literals
  through the maintained public `icydb_model::Path` trait, so downstream checks
  over one or more unit enums compile normally.
- The identity contract now matches compiler enforcement: singular and optional
  relation fields end in `_id`, while collection relation fields end in `_ids`.
- Deterministic admitted-page execution-budget failures now terminalize through
  `RestartRequired(ExecutionBudgetPolicyExceeded)`, and retained mutation jobs
  resolve their immutable entity source rather than an editable SQL name.

### 🔧 Changed

- The final mutation-job envelope examines up to 4,096 Forward keys, stages up
  to 240 rows, and verifies up to 4,096 keys under independent 16 MiB byte
  gates and fixed execution headroom. Its final policy identity is
  `0x195dc27a`; earlier-policy jobs terminalize through `BatchPolicyChanged`.
- Typed batching lowers immutable source-bound fields directly into the one
  accepted structural batch, sharing one operation timestamp, final-row
  overlay, constraints, relation checks, result ordering, marker publication,
  and recovery protocol.

### ⚠️ Breaking

- The carried mutation-job closeout changes exhaustive Rust/Candid shapes by
  adding bounded target and restart reasons, retained inventory bytes, and
  nested mutation-job metric facts. Current version-1 persisted records change
  in place without a predecessor decoder or fallback.
- The typed batch is an additive Rust facade only; it adds no Candid method,
  canister export, persisted field, continuation, or stable allocation.

### 🧪 Testing

- Added a downstream-shaped compile contract containing a Planet-style
  body/surface classification constraint over two schema-native enums.
- Corrected the frozen local SQL performance-canister policy to include its
  intentional test-admin-only extended-metrics query while production remains
  unchanged.
- Typed batch coverage exercises insert/update/replace ordering, empty and
  over-limit rejection, exact-binding enforcement, late duplicate-key
  all-or-nothing behavior, and marker-interrupted journal recovery.

### 📊 Audit

- The implementation changes one generated token path and adds no runtime
  branch, persisted state, public API, Candid method, endpoint, or compatibility
  alias. Production Wasm and instruction behavior are unchanged by construction.
- Before the typed facade addition, the carried mutation-job closeout measured
  4,412,796 raw Wasm bytes, 1,712,132 deterministic gzip bytes, 61,408 Candid
  bytes, and 70 exports: `+11,018` raw bytes (`+0.2503%`) over `v0.233.2`.
  Final 0.234.0 artifact attribution remains owned by the line closeout.
- The maintained one-entity typed-query canister remains byte-identical across
  Patch 2: 2,117,446 raw Wasm bytes, 811,510 deterministic gzip bytes, 64 Candid
  bytes, and six exports. The unused additive Rust terminal is eliminated from
  that production artifact.
