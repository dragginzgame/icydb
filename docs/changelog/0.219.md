# IcyDB 0.219 — Compact Structured Diagnostics

## 0.219.0

### 📝 Summary

- Replaces the optional rich constraint payload on public errors with one
  bounded sequence of compact numeric facts.
- Freezes a production-safe fact vocabulary while keeping diagnostic labels,
  prose, and unknown-tag fallback rendering in host tooling.
- Replaces private Candid/Serde encoding for constraint-validation jobs and
  schema-application records with direct bounded mappings over the maintained
  schema wire reader and writer.
- Establishes the common public contract for later diagnostic-family
  migrations without changing successful query, mutation, commit, or recovery
  behavior.

### ⚠️ Breaking

- Public `Error` now contains `facts: vec DiagnosticFact` instead of
  `constraint: opt ConstraintDiagnostic`. `DiagnosticFact` contains only a
  numeric `tag` and `value`; downstream Candid bindings must be regenerated.
- The removed error shape has no compatibility alias, decoder, or dual wire
  path. Existing error producers initially emit an empty fact sequence and
  move onto typed family projections in subsequent 0.219 patches.
- Constraint-validation jobs now use the checksummed `ICYCVJOB` version-1
  format. Schema-application records retain their `ICYSAR01` version-1
  envelope but use a new direct payload mapping. Pre-cut development stores
  containing either form must be recreated; no compatibility decoder or
  translation path is retained.

### 🔧 Changed

- `icydb-diagnostic-code` owns one contiguous registry of 89 numeric fact tags,
  an 80-fact public bound, and exact accepted-ID pair packing without acquiring
  Candid, labels, or subsystem formatting.
- CLI diagnostics render known tags through host-owned labels and preserve
  forward compatibility by displaying unknown tags numerically.
- Historical constraint-validation findings retain their separate operational
  payload; ordinary public errors can no longer expose the rich constraint
  diagnostic graph.
- Direct validation-job decoding checks the 64 KiB envelope and checksum before
  interpreting bounded strings, keys, revisions, findings, fields, and value
  paths, then reuses the canonical job invariants before accepting state.
- Direct application-record decoding validates its envelope, payload length,
  checksum, submission key, accepted-head and outcome tags, job identity, and
  bounded activation sequence before reconstructing the canonical record and
  exact storage key.
- Public schema-change methods and response types retain their existing Candid
  contracts. Rows, indexes, cursors, successful responses, and schema
  application state-machine semantics are unchanged.

### 📊 Audit

- Raw production Wasm changes are -3,098 bytes for the typed-query fixture,
  -815 bytes for the dynamic-query fixture, -1,341 bytes for `sql_perf`, and
  +157 bytes for the mutation-capable SQL fixture. Export sets are unchanged.
- Query-only Candid files remain byte-identical. SQL Candid files grow by 254
  text bytes for the compact fact declaration and field; this text growth is
  independent of the small raw-Wasm changes.
- Across the sequential deployable dynamic-query codec measurements, replacing
  the validation-job codec removes 99,612 bytes and replacing the application
  record codec removes a further 179,061 bytes: 278,673 raw bytes in total
  from that focused fixture. These are attribution measurements rather than a
  general canister-size guarantee.
- Registry, public wire-shape, numeric round-trip, CLI fallback, feature-row,
  transitive Candid, codec corruption and boundary tests, warnings-denied
  Clippy, production build, and repository invariant checks pass. The two
  internal persisted formats change as described above; public schema-change
  Candid and successful runtime formats do not.
