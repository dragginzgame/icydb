# IcyDB 0.219 — Compact Structured Diagnostics

## 0.219.1

### 📝 Summary

- Completes the staged migration of safe diagnostic context onto the compact
  numeric fact contract introduced in 0.219.0.
- Adds exact fingerprint-bound host resolution so CLI diagnostics can render
  accepted schema names without making generated models or local source a
  runtime authority.
- Consolidates scalar and authoring metadata, admits `Unit` as a trivially
  ordered scalar, and updates the isolated host integration harness without
  changing successful database execution.

### ⚠️ Breaking

- Explicit schema introspection adds the accepted entity tag, fingerprint
  method, and complete 128-bit accepted entity-schema fingerprint. Downstream
  bindings for schema-enabled actors must be regenerated.
- Historical constraint-validation progress now returns a dedicated bounded
  numeric finding record instead of the former rich constraint diagnostic.
  The immediate public `Error` record remains the compact 0.219.0
  `code`/`class`/`origin`/`facts` shape.
- These are direct pre-1.0 hard cuts. No legacy response alias, decoder,
  source-derived fallback, or dual representation is retained.

### ➕ Added

- `icydb schema diagnostic-artifact` writes a bounded current-format snapshot
  from the deployed explicit schema endpoint, and `icydb diagnostic` can
  resolve numeric facts against an exact artifact or live canister.
- Schema-aware rendering is bound to the fingerprint method, all fingerprint
  bits, and accepted entity tag. Missing, mismatched, or stale authority falls
  back to a complete numeric report instead of guessing names.

### 🔧 Changed

- Cursor, recovery, mutation, constraint, query, SQL, row-layout, commit-memory,
  index, and relation failures now preserve the bounded numeric positions,
  kinds, limits, and accepted IDs already owned by their canonical subsystem.
  Raw cursor and marker bytes, names, paths, SQL text, keys, rows, and values
  remain code-only.
- Constraint failures bind their accepted fingerprint, entity and constraint
  IDs, operation, batch position, and bounded typed value coordinates while
  keeping the historical row locator confined to the explicit validation
  workflow.
- Accepted schema and query planning now share canonical `ScalarKind` metadata;
  duplicate scalar classifications and unused model capability helpers are
  removed. `Unit` supports ordered SQL, dynamic, and typed predicates plus
  bounded singleton primary-key reads.
- Model and proc-macro authoring primitives share one catalog instead of
  maintaining duplicate classifications.
- Host integration tests use `ic-testkit` 0.2.2 and construct PocketIC
  explicitly before fixture installation, retaining structured rejection
  handling without process-global coordination.

### 📊 Audit

- No accepted schema, row, key, cursor, marker, journal, validation-job,
  migration-record, or other persisted database format changes in 0.219.1.
  The diagnostic artifact is a host-only version-1 tooling format and cannot
  apply schema or become runtime authority.
- Final raw non-gzipped Wasm is 2,681,477 bytes for the typed-query fixture,
  2,652,926 bytes for the dynamic-query fixture, 4,437,158 bytes for
  `sql_perf`, and 3,913,659 bytes for the mutation-capable SQL fixture. These
  are reductions of 39,891, 39,238, 54,477, and 45,524 bytes respectively
  from released 0.219.0, with unchanged IC method export counts.
- Query-only Candid remains byte-identical at 64 and 66 bytes. The SQL Candid
  surfaces are each 1,029 text bytes smaller overall: removing the rich
  historical finding shape saves 1,134 bytes and the accepted introspection
  identity adds 105 bytes.
- Focused registry, error-family, facade, CLI, feature-row, Candid, persisted
  format, production Wasm, invariant, dependency, and warnings-denied Clippy
  checks pass. Full workspace tests and `make test` remain user-owned push
  validation.

## 0.219.0

### 📝 Summary

- Replaces the optional rich constraint payload on public errors with one
  bounded sequence of compact numeric facts.
- Freezes a production-safe fact vocabulary while keeping diagnostic labels,
  prose, and unknown-tag fallback rendering in host tooling.
- Replaces private Candid/Serde encoding for constraint-validation jobs and
  schema-application records with direct bounded mappings over the maintained
  schema wire reader and writer.
- Establishes the common public contract for later diagnostic-family
  migrations without changing successful query, mutation, commit, or recovery
  behavior.

### ⚠️ Breaking

- Public `Error` now contains `facts: vec DiagnosticFact` instead of
  `constraint: opt ConstraintDiagnostic`. `DiagnosticFact` contains only a
  numeric `tag` and `value`; downstream Candid bindings must be regenerated.
- The removed error shape has no compatibility alias, decoder, or dual wire
  path. Existing error producers initially emit an empty fact sequence and
  move onto typed family projections in subsequent 0.219 patches.
- Constraint-validation jobs now use the checksummed `ICYCVJOB` version-1
  format. Schema-application records retain their `ICYSAR01` version-1
  envelope but use a new direct payload mapping. Pre-cut development stores
  containing either form must be recreated; no compatibility decoder or
  translation path is retained.

### 🔧 Changed

- `icydb-diagnostic-code` owns one contiguous registry of 89 numeric fact tags,
  an 80-fact public bound, and exact accepted-ID pair packing without acquiring
  Candid, labels, or subsystem formatting.
- CLI diagnostics render known tags through host-owned labels and preserve
  forward compatibility by displaying unknown tags numerically.
- Historical constraint-validation findings retain their separate operational
  payload; ordinary public errors can no longer expose the rich constraint
  diagnostic graph.
- Direct validation-job decoding checks the 64 KiB envelope and checksum before
  interpreting bounded strings, keys, revisions, findings, fields, and value
  paths, then reuses the canonical job invariants before accepting state.
- Direct application-record decoding validates its envelope, payload length,
  checksum, submission key, accepted-head and outcome tags, job identity, and
  bounded activation sequence before reconstructing the canonical record and
  exact storage key.
- Public schema-change methods and response types retain their existing Candid
  contracts. Rows, indexes, cursors, successful responses, and schema
  application state-machine semantics are unchanged.

### 📊 Audit

- Raw production Wasm changes are -3,098 bytes for the typed-query fixture,
  -815 bytes for the dynamic-query fixture, -1,341 bytes for `sql_perf`, and
  +157 bytes for the mutation-capable SQL fixture. Export sets are unchanged.
- Query-only Candid files remain byte-identical. SQL Candid files grow by 254
  text bytes for the compact fact declaration and field; this text growth is
  independent of the small raw-Wasm changes.
- Across the sequential deployable dynamic-query codec measurements, replacing
  the validation-job codec removes 99,612 bytes and replacing the application
  record codec removes a further 179,061 bytes: 278,673 raw bytes in total
  from that focused fixture. These are attribution measurements rather than a
  general canister-size guarantee.
- Registry, public wire-shape, numeric round-trip, CLI fallback, feature-row,
  transitive Candid, codec corruption and boundary tests, warnings-denied
  Clippy, production build, and repository invariant checks pass. The two
  internal persisted formats change as described above; public schema-change
  Candid and successful runtime formats do not.
