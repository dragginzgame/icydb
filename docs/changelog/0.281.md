# 0.281

## [0.281.0]

### ⚠️ Breaking

- Adopt registry Wire/derive 0.6.5, which removes the finite codec API. The public
  codec-error reexports now have Wire 0.6 identity; consumers that directly use
  Wire 0.5 errors must update together. The native application codec, endpoint
  IDs, canonical frames, decoder policy and persisted formats are unchanged.
- Migrate the two remaining audit protocols to native Serde/Postcard framing,
  preserving their scalar/unit payload bytes, method IDs, byte limits and
  rejection-before-query behavior. Allocation, node and depth allowances now
  account for native traversal charges. Remove the obsolete typed frame dependency
  from artifact inspection and keep Build's Wire metadata dependency in development
  only. This adds no codec wrapper, alternate protocol or compatibility reader.

### 🩹 Fixed

- Select the first record-path member during complete root validation instead
  of walking the root again after admission. Reuse canonical child traversal
  at the original depth and retain validation of every later sibling, duplicate
  key first-match selection, missing/null semantics and historical-slot fills.
  No execution mode, accepted schema, stored format or instruction ceiling changes.
  On the frozen local debug grouping fixture across 39 reported calls, cold path
  instructions fall from 5,897,544,692 to 5,786,860,404; its direct-control premium
  falls from 20.11% to 17.84%. Ordered path instructions fall from 6,383,122,226
  to 6,272,346,977; its premium falls from 16.19% to 14.16%. The retained pre-fix
  raw debug actor is 6,972,665 bytes and the rebuilt actor is 6,963,725 bytes
  (−8,940). These measurements do not qualify production-profile size or cycles.
- Validate each source/relation once against the complete target-delete set in
  the existing final batch overlay. Repeated reverse witnesses reuse successful
  checks, allowing update-away plus many-target-delete batches without multiplying
  raw-reference charges. Keep complete source identity, per-relation separation,
  witness decoding, corruption refusal and atomic rejection when any deleted
  target remains referenced. Bound temporary successful facts by the existing
  reverse-effect ceiling; preserve save-time target admission and before/after
  accounting. No public API, configuration, lifecycle or stored-format change;
  raw Wasm-size, IC cycle and instruction deltas are unmeasured
  ([#60 — Delete restriction repeats source projection](https://github.com/dragginzgame/icydb/issues/60)).
- Scope complete user-index replacement to the target entity in both row and
  index storage. Reuse the same canonical entity-index bounds as emptiness proofs,
  preserving every ordinal/generation and heap/journal overlay semantics. Foreign
  entries no longer consume the target projection allowance; selected-domain
  corruption, target budget exhaustion, exact before-image comparison and
  zero-write staging remain enforced. No public API or stored format changes;
  raw Wasm-size, IC cycle and instruction deltas are unmeasured
  ([#97 — Index rebuilds scan unrelated entities](https://github.com/dragginzgame/icydb/issues/97)).
- Prove empty entity user-index and reverse-relation domains with the canonical
  prefix bounds and merged index reader. Unrelated entities, generations, relation
  IDs and namespaces no longer consume the emptiness proof budget. Stop on the
  first physical witness; retain readiness, accepted relation authority, local
  corruption refusal and live/tombstone semantics. Probe every admitted component
  count so malformed relation shapes cannot evade refusal. Complete-domain
  replacement staging retains its existing inventory and budget. No public API,
  stored format, cache or lifecycle change is needed; IC cycle/instruction and
  raw Wasm-size deltas are unmeasured
  ([#62 — Empty relation removal scans unrelated indexes](https://github.com/dragginzgame/icydb/issues/62)).
- Classify deterministic migration-planning rejections as terminal generated
  schema failures through the existing bound startup receipt. Preserve their
  exact leaf diagnostics and fact validation so startup reports the cause instead
  of requesting another immediate planning attempt. Retryable schema errors
  reach the adapter's existing logged cadence instead of reporting progress.
  Controller-progress and publication-conflict classification is unchanged;
  corrected generated submissions use the existing receipt binding. No new retry policy,
  lifecycle state, public API or stored format is needed
  ([#117 — Startup repeatedly replans rejected migrations](https://github.com/dragginzgame/icydb/issues/117)).
- Refill verified store-local bundle and cardinality projections during the
  existing replicated startup preparation, even when the database runtime root
  already hits its cache. Folding can invalidate those store projections without
  changing the accepted root. Reuse the schema store's verification owner and
  preserve canonical-only cardinality construction, failure classification and
  query results without another cache, lifecycle state or stored-format change.
  IC cycle/instruction and Wasm-size deltas remain unmeasured
  ([#82 — Schema folding leaves admitted cardinality evidence unavailable](https://github.com/dragginzgame/icydb/issues/82)).
- Retain the existing commit wake-up after accepted schema publication even
  when a heap-store batch has no journal sequence. The installed startup driver
  can reconcile a completed metadata migration and prepare the accepted runtime
  root after SQL DDL. Keep ordinary heap row writes quiescent and preserve
  journal-debt scheduling, captured callbacks, typed errors and marker recovery.
  No new timer, lifecycle state or stored-format change is needed; IC
  cycle/instruction and Wasm-size deltas remain unmeasured
  ([#88 — Heap metadata migrations leave startup Recovering](https://github.com/dragginzgame/icydb/issues/88),
  [#196 — Heap schema publications leave the runtime root cold](https://github.com/dragginzgame/icydb/issues/196)).

### 🔧 Changed

- Adopt published Host/Tooling 0.66.0 for CLI, build and integration consumers.
  Replace Testkit's private PocketIC fields with borrowing accessors or explicit
  ownership transfer for mutable browser-gateway setup. Retain the server until
  client deletion, including unwinding. Host and Build Rust APIs are unchanged
  from 0.65.0. Keep the existing fixture endpoint/policy adapter and error
  behavior; application protocols stay on Wire. No IcyDB Wasm-size, cycle or
  instruction delta is measured for this tooling adoption.
- Refresh the canonical Shared Tooling snapshot to 0.26.8. Tolerate admitted
  setup-lock withdrawal and initialize the shared Cargo source cache without a
  global installation lock. Preserve malformed-owner refusal, bounded waits,
  immediate offline checks, foreign locks, tool pins and formatting/release
  policy. Rerun explicit Cargo-tool setup for the changed build-policy digest;
  previous generations remain retained.
- Reuse canonical grouped-value normalization directly when DISTINCT only
  retains an equality key. Global replay keeps its borrowed bucket hash without
  computing a second discarded hash; ordered adjacent DISTINCT and map-valued
  equality checks need no hash. Preserve decimal/map normalization, malformed-map
  refusal, collision equality, pagination and retained-state budget checks.
  The owned-map global route still computes the hash its bucket needs. No public
  API, protocol, execution mode or stored-format change; raw Wasm-size, IC cycle
  and instruction deltas are unmeasured
  ([#412 — A distinct key is hashed and then the hash is thrown away](https://github.com/dragginzgame/icydb/issues/412)).
- Compare ordered grouping rows as canonical values in the shared COUNT and
  generic aggregate transition owner. Compute a stable hash only after a row
  opens a retained group, avoiding discarded hashes for repeats and unused
  lookahead. Reuse grouped-value canonicalization for direct and path tuples;
  keep unordered bucket hashes, decimal/NULL equality, monotonicity refusal,
  group reservations and cursor boundaries. Retained-key hash failures keep
  their typed diagnostics. No public API, execution mode, cache or stored-format
  change; raw Wasm-size, IC cycle and instruction deltas are unmeasured
  ([#413 — An ordered group hashes every row and then drops that hash](https://github.com/dragginzgame/icydb/issues/413)).
- Use the codec's existing strict borrowed index frame for covering output and
  index-only predicates. Copy each requested component directly into its output
  buffer, without first copying every component into an owned key. Ordinary
  predicate scans use the same borrowed evaluator; primary-key suffix bytes stay
  borrowed until the output row identity is retained. Preserve complete framing,
  component selection, predicate short-circuiting, corruption/error precedence,
  budget charges, direction, resume and limits. Remove the obsolete owned-key
  accessor and adapter helpers. No public API or stored-format change; raw
  Wasm-size, IC cycle and instruction deltas are unmeasured
  ([#407 — A covering index entry copies its components twice](https://github.com/dragginzgame/icydb/issues/407)).
- Compare primary-key components using the reader's already-admitted scalar
  views or structural materializations, retaining them for later projection.
  Scalar and composite keys share the same per-component reader path; cached
  and direct byte readers share primary-key conversion and typed mismatch
  semantics. Preserve accepted key order, physical key-slot presence, malformed
  and NULL refusal, structural-codec diagnostics and retry after a mismatched
  identity. No new cache, public API, stored format or migration is introduced;
  raw Wasm-size, IC cycle and instruction deltas are unmeasured
  ([#404 — A row read decodes its primary key and then decodes it again](https://github.com/dragginzgame/icydb/issues/404)).
- Borrow cached raw data keys in grouped reads, hybrid projections, covering
  presence checks, primary-lookup filtering and structural existing-row loads.
  Keep owned keys for staged writes and retained results. Preserve complete key
  bytes, missing-row consistency, corruption diagnostics, ordering and existing
  execution-budget admission without another cache or lookup abstraction.
  No public API or stored-format change is needed; IC cycle/instruction and
  Wasm-size deltas remain unmeasured
  ([#406 — A row lookup clones a raw key it only borrows](https://github.com/dragginzgame/icydb/issues/406)).
- Move the encoded reverse-relation target identity into its consumer and borrow
  target and relation-ID segments when framing stored keys and prefix bounds.
  Reuse the canonical store-key framer without constructing a temporary decoded
  index key. Preserve stored bytes, namespace/generation, source identity, prefix
  bounds, the complete 512-byte key limit and existing typed error mapping.
  Compare direct framing with the general index codec across scalar/composite
  identities and admitted/refused wide keys. No public API or stored-format
  change is needed; IC cycle/instruction and Wasm-size deltas remain unmeasured
  ([#411 — A reverse-index key copies a primary key it already owns](https://github.com/dragginzgame/icydb/issues/411)).
- Prepare case-insensitive scalar and membership literals, including text
  contains needles, when compiling runtime predicate programs. Reuse those
  constants across borrowed/owned and structural readers, folding row text once
  per comparison instead of once per membership candidate. Preserve general
  field-to-field comparisons, Unicode matching, NULL/missing-field outcomes and
  corruption errors without a new coercion policy, cache or persisted state.
  Public predicates and stored formats are unchanged; IC cycle/instruction and
  Wasm-size deltas remain unmeasured
  ([#409 — A case-insensitive literal is folded again on every row](https://github.com/dragginzgame/icydb/issues/409)).
