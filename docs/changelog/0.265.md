# 0.265 — SQL Output and Shared Tooling

## [0.265.0]

### Changed

- Adopt the Shared Tooling formatting hook, pinned formatter setup and complete
  formatting checks in native CI. Release retries retain failed attempts, and
  numbered pending notes finalize without discarding earlier minor-line history.
- Adapt application timer callbacks to `ic-timers 0.12` while preserving retry,
  stop and recurrence behavior; retain the existing `ic-testkit 0.17` integration.
- Use published registry `ic-metrics 0.1.3` for saturating instruction and entity
  counters without a sibling checkout, preserving inclusive spans, report shapes
  and reset identity ([#298](https://github.com/dragginzgame/icydb/issues/298)).
- Standardize `make release-patch`, `release-minor` and `release-major` on the
  reviewed Shared Tooling runner, with exact-version resume, atomic branch/tag
  push and retained build artifacts.

Instruction and entity counters call `ic_metrics::record_sample`; maximum values,
Candid reports, registries, replication and journal debt remain IcyDB-owned.
Release preparation retains the selected dependency graph and uses UTC dates.
Consumer metadata adapters retain source-bound candidate and tag receipts.
Release preflight fills the repository-local Cargo cache through the existing
locked fetch target before offline validation. A stale cache can therefore admit
newly locked registry packages without changing versions or lockfile selections;
fetch failures stop before validation or release preparation.
The release adapter fixture sets its simulated preflight environment explicitly,
so inherited offline validation does not disable stubbed cache preparation.
Unexpected fixture failures print the inner Make output before scratch cleanup.

Lifecycle-participant deferred work and SQL audit startup polling return
`OnceRunResult` with `OnceDecision`; the timer probe's recurring application
callback returns `AfterCompletionRunResult` with `AfterCompletionDecision`.
Generated startup Watchdog wiring and timer snapshots retain their contracts.
The upstream ordinary callback API is a hard cut; application canisters using
`ic-timers` directly must select the result type matching their registration.
The selected `ic-testkit 0.17.2` library needs no consumer API migration.
The SQL policy-identity truncation assertion applies only on wider hosts,
avoiding an always-true comparison during strict Wasm Clippy checks while
preserving the same bounds and encoded policy identities.

### 🩹 Fixed

Interactive SQL input preserves whitespace, blank lines, Unicode and semicolons
inside multiline string literals, including unfinished text following a pasted
statement. Backslashes remain ordinary string characters; only doubled single
quotes escape a quote, matching the SQL lexer. Empty statement separators are
ignored outside strings, while help/exit controls, EOF and interruption retain
their shell behavior. GitHub [#125](https://github.com/dragginzgame/icydb/issues/125)
and [#136](https://github.com/dragginzgame/icydb/issues/136) own the saved findings.
No SQL grammar, endpoint, database state or persisted format changes.

SQL rejects unsupported scientific notation, numeric base prefixes and digit
separators with the existing invalid-numeric-literal diagnostic. For example,
`SELECT price * 1e3 FROM Product` previously multiplied by `1` and silently used
`e3` as an alias. The shared lexer now rejects the malformed token in statements
and standalone predicates. Supported numbers, whitespace-separated aliases,
strings, hex blobs and typed `U256` literals retain their behavior. GitHub
[#108](https://github.com/dragginzgame/icydb/issues/108) owns the finding; no public
API or persisted format changes.

Direct `ORDER BY` arithmetic uses the existing expression-depth limit before
retaining excessive recursion or arithmetic-tree depth. Deep parentheses,
long binary chains and nested combinations return the typed depth-limit error
across SELECT, UPDATE, DELETE and supported EXPLAIN routes. Supported arithmetic,
precedence, parameters, aggregate targets and window clauses retain their
behavior. GitHub [#106](https://github.com/dragginzgame/icydb/issues/106) owns the
finding. No grammar, public API, stored format or configured limit changes.

SQL display renders typed missing values as `NULL` and quotes text matching that
marker, including mixed case and surrounding whitespace. Projection and grouped
results decide this while values are still typed; the CLI uses the same decoded
response renderer for queries and mutations, including `UPDATE ... RETURNING`.
Ordinary text, fixed decimal scales, typed projection payloads and grouped
cursors retain their behavior. GitHub
[#129](https://github.com/dragginzgame/icydb/issues/129) owns the finding. Candid
shapes and stored data are unchanged; the SQL display correction requires no
regeneration or reinstall.
Live grouped-path fixtures check the current `NULL` display when preserving
nullable groups, admitting complete index paths and excluding null-only rows.

### Breaking

Release automation uses only `make release-patch`, `release-minor` or
`release-major`, with `make release-resume VERSION=X.Y.Z` for saved recovery.
Update scripts that used the manual `patch`, `minor`, `major`, `release-stage`,
`release-commit` or `release-push` targets. Their separate execution path and
confirmation helper are removed, along with the no-op `release` target and
internal directory-only `release-prepare` target. `make` now shows help, and
`make release-clean` remains a separately invoked cleanup command. The shared
runner retains validation order, exact source/index/tag receipts, confirmation
for minor/major releases, atomic branch/tag publication and recovery evidence.

SQL display uses uppercase `NULL` for missing values and quotes text equal to
that marker. Consumers comparing rendered SQL cells or CLI output must update
those expectations; typed Candid shapes and stored data stay unchanged. This
output change selects the next minor under the shared numbering rules. GitHub
[#129](https://github.com/dragginzgame/icydb/issues/129) owns the correction.
