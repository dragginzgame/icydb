# 0.270 — Host-owned memory allocation

## [0.270.0]

### 🩹 Fixed

- Release receipt fixtures execute Shared's Make admission probe without
  recording it as a release callback, preserving exact saved-commit and
  source-admission assertions. Failed fixtures retain their callback traces,
  receipts and diagnostics for review; successful runs clean up normally.
- Wasm post-link invariants leave CI tool setup admission to the parsed workflow
  gate, which checks complete setup and offline admission in each applicable
  lane. Remove the duplicate literal check for a combined Make invocation;
  setup and checking remain separate under Shared Tooling 0.3.

- Managed Tier B scopes explicitly select Testkit's operation-idle allowance
  as well as the existing hard lifetime, so pre-client compilation does not
  lose its server to the idle default. Testkit retains provisioning, admission
  and lifecycle ownership; failure status, signals, cleanup and retained streams
  stay on the existing wrapper path
  ([#340](https://github.com/dragginzgame/icydb/issues/340)).
- Native scheduled Tier C gives each independent SELECT case and mutation
  sequence its own existing request root. Keep each sequence's setup, writes
  and readback together, preserving accepted stores and the shared query cache
  while preventing unrelated scenarios from exhausting one aggregate budget.
  Production limits, oracle machinery and receipt formats are unchanged
  ([#341](https://github.com/dragginzgame/icydb/issues/341)).

- Normalize every boolean searched CASE condition, result arm and ELSE child
  before context-specific lowering. Compound AND/OR and field-bound range
  conditions, including nested CASE, now satisfy the planner's normal-form
  invariant. Preserve first-match behavior, NULL results and the separate
  scalar-WHERE/grouped-HAVING truth policies; charge preparation work for every
  child before traversal ([#337](https://github.com/dragginzgame/icydb/issues/337)).

- Diagnostic schema exports use Host durable create-only publication under an
  admitted parent descriptor, preventing partial final artifacts. Preserve exact
  bytes, size limits, ordinary permissions, parent symlink selection and
  missing-parent refusal. Reject targets ending in `/` or `/.` before path
  normalization can select a different filename. Errors distinguish already-published output from
  prepublication failure; no retry, overwrite or schema change is introduced
  ([#307](https://github.com/dragginzgame/icydb/issues/307)).

- Field-to-field ordering uses numeric widening only when both operands support
  it; other orderable SQL scalar pairs use their same-kind strict comparison.
  Share that decision across accepted predicate admission, expression inference,
  SQL normalization, and newly bound partial-index predicates. Field-bound
  `BETWEEN` and `NOT BETWEEN` follow the same rule, including grouped queries'
  pre-aggregation filters. Preserve NULL semantics and rejection of incompatible
  kinds or invalid explicit coercions. Qualify result rows across predicate and
  residual execution, CASE comparisons and ranges, and persisted partial-index
  round trips.
  Existing stored trees and codec layouts are unchanged; no data reset is
  required ([#333](https://github.com/dragginzgame/icydb/issues/333)).

### 🔧 Changed

- **Breaking:** adopt Memory 0.34's single host allocation pool. Components
  declare permanent requests; each maintained standalone host supplies
  `icydb_memory_pool` with explicit namespace grants and unmanaged-ID exclusions.
  The `ic_memory_range!` facade export is removed. Generated cold startup uses
  that pool, while adoption of an already committed host retains its policy and
  geometry without invoking the provider. Key-only opens preserve IcyDB's
  persisted key/ID agreement check. Public memory diagnostics expose upstream
  `pool_eligible: Option<bool>` instead of range claims. Regenerate maintained
  canisters and update host pool providers and diagnostic consumers together.
  Stable keys, ledger bytes, allocation records and bucket geometry are retained;
  this change does not require resetting storage
  ([#338](https://github.com/dragginzgame/icydb/issues/338)).

- **Breaking tooling change:** adopt canonical Shared Tooling 0.3.0. Setup and
  offline checks use one complete host → IC → Rust → Testkit sequence, with the
  product targets registered through Shared's ordered extension lists. The host
  installer always selects jq, yq, ripgrep and cloc. Prepare the Rust toolchain
  and locked dependencies, then run setup and checking as separate commands.
  Release preflight admits the source and fetches the locked graph before
  complete tool preparation; explicit offline callers only check existing tools.
  Native-only CI selects the complete common roster without the server extension;
  live lanes retain explicit Testkit setup. The canonical failure collector keeps
  aggregate logs, failed candidates, Rust builds and formatting diagnostics.
  Earlier bundles and receipts remain retained. Preserve Testkit's exclusive
  server ownership and stop before dependent gates under parallel Make.
  Carry prior newline-safe snapshot admission, selected-tool diagnostics and
  CI inspection's retained unavailable failed-step logs
  ([#339](https://github.com/dragginzgame/icydb/issues/339),
  [#327](https://github.com/dragginzgame/icydb/issues/327)).

- Follow the incoming Host 0.11 process API directly, retaining terminating
  1 MiB output caps, operational deadlines and typed cleanup evidence in Candid
  extraction, post-link optimization and Wasm reporting. The incoming Testkit 0.29
  consolidates its native helpers onto the same Host generation; no application
  compatibility layer is added. The later incoming Memory 0.34.1 and Metrics
  0.4.0 libraries retain the reviewed runtime and arithmetic sources; their
  changes converge release tooling and snapshot admission. Timers 0.16.7 retains
  the reviewed runtime sources.

- Earlier focused checks qualified published Host 0.10.2, Timers 0.16.5 and Testkit 0.28.1
  graph without changing its lock selections. Host's directory-suffix repair
  complements IcyDB's descriptor-relative diagnostic adapter; its raw-path
  admission remains local. Timers' library sources are unchanged from 0.16.2.
  Prepare and admit the locked Testkit CLI through the shared installer before
  offline wrapper qualification; no server version policy moves into IcyDB
  ([#307](https://github.com/dragginzgame/icydb/issues/307),
  [#340](https://github.com/dragginzgame/icydb/issues/340)).

- The carried Shared Tooling 0.2.11 formatting repair runs derive sorting,
  manifest sorting and rustfmt through one shared reporter, preserving tool
  admission, check flags and local Cargo directories. Success is one summary
  line; failures stop the sequence and retain complete stdout/stderr logs,
  which static and native CI upload. Replace IcyDB's supplementary Make flag
  parser with canonical execution admission, including cleared/replaced flags.
  Hook, release, setup and Testkit fixtures carry the new companions
  ([#336](https://github.com/dragginzgame/icydb/issues/336),
  [Shared #30](https://github.com/dragginzgame/shared-tooling/issues/30),
  [Shared #92](https://github.com/dragginzgame/shared-tooling/issues/92)).
