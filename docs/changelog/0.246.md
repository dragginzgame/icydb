# IcyDB 0.246 — Query And Recovery Convergence

## 0.246.1

### 🧪 Testing

- Tightened the fail-closed finalized non-gzipped Wasm entity-scale ceiling
  from 4 KiB to 2 KiB per added generated entity. The corrected equivalent
  one-to-ten-entity subjects currently measure 145 bytes per entity, leaving
  more than fourteen times the observed headroom under the stricter ceiling.
- Consolidated the startup-watchdog performance response, armed-state query,
  and bounded ready-driving loop in the shared integration harness instead of
  maintaining duplicate contracts in recovery and SQL performance tests.

### ⚡ Performance

- Removed the dependency that serialized Wasm-size reporting behind MSRV and
  validation. MSRV, validation lanes, and Wasm reporting now proceed
  independently, while release artifact publication explicitly requires all
  three successful results. This removes the serial validation-to-Wasm edge
  without weakening branch protection or release gating.

### 🧹 Cleanup

- Consolidated diagnostic, schema and migration lowercase-hex display into one
  allocation-exact CLI rendering helper. Candid blob escaping and inbound hex
  decoding remain separately owned, and rendered output is unchanged.
- Removed three stale facade lint suppressions, upgraded the intentional hot
  scalar-route layout suppression to an enforced expectation, and documented
  every retained feature-dependent allowance emitted into generated canisters.
  Runtime code generation and public behavior are unchanged.
- Aligned dependency manifests with their real owners: the integration harness
  no longer declares `flate2` or PocketIC directly, while macro-required
  fixture and canister dependencies are explicitly classified for dependency
  auditing. The resolved transitive graph and runtime behavior are unchanged.
- Removed the deployment-local synonym for the canonical 16-store ceiling.
  Format convergence, memory-range proof, and generated-store admission now
  refer directly to `MAX_PERSISTED_STORE_ALLOCATIONS`; no second capacity
  vocabulary or independently adjustable limit remains.
- Made successful release pushes delete only transient release, SQLite
  comparison, and PocketIC port state while preserving the validated Cargo
  target cache. Explicit `make release-clean` reuses the canonical `clean`
  target before the same transient cleanup, so full cleanup remains deliberate
  and has one Cargo-cleaning owner.
- Production behavior, stable format, Candid, timer scheduling, backlog limits,
  query execution, production Wasm and the resolved transitive dependency graph
  are unchanged.

## 0.246.0

### 📊 Audit — Baseline

- Captured one exact clean `v0.245.1` SQL performance subject across all 1,787
  P1 scenarios, 210 scale observations and 521 P2 confirmations. Every shard
  and strict merge passed.
- Located one broad candidate shared by prepared aggregate and scalar
  `DISTINCT` execution: both currently retain complete source rows before their
  separate semantic consumers run. Aggregate folding and scalar `DISTINCT`
  identity, order, pagination and budget behavior remain separate owners.

### 🧪 Testing

- Raised the fail-closed P2 candidate ceiling from 512 to 544 after the frozen
  top-20-per-metric union produced 521 candidates. Selection remains complete
  and fails rather than truncating; scenario membership and fixtures are
  unchanged.
- Patch 1 changes no production runtime, public API, Candid, export, stable
  format or query behavior.
- Removed a redundant same-type cast from the bounded-sort test fixture so the
  all-target schema clippy gate remains clean, and aligned the schema/model
  architecture guard with the shared bounded-sort owner. Production behavior
  is unchanged.
- SQL performance audits now install fresh timer-owning fixtures instead of
  restoring canister snapshots that cannot recreate external timer-provider
  handles. Parallel audit execution remains enabled without retaining ghost
  watchdog wake-ups.
- Re-derived three final-tree query ceilings after the bounded-sort hard cut;
  exact results and row/index work remain unchanged.

### 🔧 Changed

- Retained-slot scans over an eligible primary-map stream now consume the raw
  row already opened by the owning store visitor instead of encoding each key
  and performing a second tree lookup. Paginated and unsupported streams keep
  the predecessor path.
- Expression-backed ordering caches the same canonical order values and uses
  the same comparator, but sorts compact source positions and moves each large
  retained row once instead of sorting complete row payloads.
- At 2,048 rows, the prepared aggregate `DISTINCT` plus `FILTER` control falls
  from 109.235M to 70.759M instructions. Nullable and expression-order scalar
  `DISTINCT` controls fall from 118.739M to 87.602M and from 109.376M to
  78.239M respectively, with unchanged results and physical visits.
- Adopted `ic-timers 0.7.0` and its watchdog-specific reconciliation contract.
  Lifecycle and commit-pressure work now schedule immediately, and successful
  bounded recovery continues immediately while more work remains. Retryable
  failure still waits for the one-second cadence.
- Capped each incarnation at 16 active-plus-retired journaled store quartets
  and gave backlog admission an independent 64-batch ceiling. The existing
  16,384-record and 16-MiB limits remain unchanged.
- Made positioned schema retirement use overlay provenance as its ownership
  boundary. Canonical-only cardinality metadata created by an earlier row fold
  is left to that canonical fold, while a live value or tombstone without a
  position remains a strict E17 store-invariant failure. There is no retry,
  compatibility route or second retirement mode.
- Replaced repeated general-purpose unstable-sort monomorphs on bounded schema,
  startup, recovery, integrity and metrics control-plane collections with one
  compact in-place heapsort owner. Stable-order operations and large user
  value, row and index-key sorts retain Rust's optimized sorters.
- Made the one-entity and ten-entity Wasm subjects use the same exact-key
  endpoint body. The size-report workflow now fails when finalized non-gzipped
  Wasm grows by more than 4 KiB per additional generated entity.

### 📊 Audit — Candidate

- The candidate production SQL Wasm is 4,517,281 raw bytes, 3,837 bytes above
  the exact predecessor and within the frozen 4,096-byte limit. Production
  state space is unchanged: no new type, module, cache, mutable owner,
  persisted state or execution mode.
- The frozen predecessor P2 selection correctly rejects the candidate Wasm's
  different subject identity. Complete candidate P1 selection and P2
  confirmation remain release-validation work; the identity check was not
  bypassed.
- Prepared-fallback tests now identify execution through the scalar-aggregate
  owner and ingested-row count instead of requiring redundant point gets. The
  existing prefix-family control retains its exact 65-entry physical work and
  a narrowly rebased ceiling after repeated 5.301M-instruction measurement.

### 📊 Audit — Recovery Convergence And Capacity

- Cold and populated 64-batch backlogs each drain in 64 bounded callbacks over
  145 ns of PocketIC time, then admit the rejected retry. Upgrade reconstruction
  retains the same behavior and existing instruction and memory bounds.
- The 16-head selector and maximum retirement probe costs 287,890,767
  instructions, 5,727,601 below the prior 38-head measurement. A repeated
  16-MiB-class fill drains and refills at a stable 513-page high-water.
- Against the exact 0.246 query candidate, the production one-entity SQL
  canister's final raw non-gzipped Wasm grows by 5,837 bytes after Patch 4
  removes 3,029 bytes from the timer-only candidate. Recovery retains one page
  per callback, one watchdog owner, and no new IcyDB state or mode.
- Before the later Wasm hard cut, closeout removed tests and one audit-only
  endpoint whose sole contract was an
  externally visible one-second gap between healthy recovery pages. Tests now
  count IcyDB work callbacks independently from scheduler deliveries and retain
  the one-second clock advance only for application-owned retry cadence. The
  resulting production one-entity SQL Wasm was 3,181,557 raw bytes, 44 bytes
  below the Patch 4 measurement.
- Updated the memory-ID architecture invariant to require the hard-cut
  16-store ceiling; it no longer rejects the maintained limit by requiring the
  retired derived value 38. Removed the private derived 38-store memory-range
  constant as well; a compile-time assertion now proves directly that the one
  canonical 16-store ceiling fits the available allocation range.
- The bounded-sort hard cut reduces that same finalized production SQL subject
  from 3,181,557 to 3,077,777 raw bytes (-103,780, or 3.26%) without changing
  its six exported methods. On the SQL-off typed subject, raw Wasm falls by
  93,460 bytes and code-section bytes fall by 93,353.
- The corrected one-to-ten-entity comparison adds 1,301 finalized raw bytes
  across nine entities, or 145 bytes per entity; code grows by only 37 bytes in
  total. The former large directional delta came from unlike endpoint routes,
  not per-entity generated code.
- The final bounded-sort subject moves maximum-fanout prefix work from
  5,301,284 to 5,317,622 instructions (+0.31%), exact entity count from 855,091
  to 865,427 (+1.21%), and indexed extrema from 1,713,408 to 1,742,673 (+1.71%).
  Their 65-entry, zero-traversal, and one-entry/one-row structural gates remain
  unchanged; this is the measured instruction tradeoff for the 103,780-byte
  raw-Wasm reduction.

### ⚠️ Breaking

- The singular current version-1 registry now rejects a seventeenth
  active-plus-retired journaled store. Before 1.0 this is a hard cut: databases
  that already persisted more than 16 store quartets must be recreated.

### 🧭 Migration Notes

- Generated canisters must be rebuilt against `ic-timers 0.7.0`. There is no
  public API or Candid migration. Existing databases at or below 16 persisted
  store quartets retain the same current version-1 encoding shape.
