# IcyDB 0.246 — Query And Recovery Convergence

## 0.246.0

### 📊 Audit — Baseline

- Captured one exact clean `v0.245.1` SQL performance subject across all 1,787
  P1 scenarios, 210 scale observations and 521 P2 confirmations. Every shard
  and strict merge passed.
- Located one broad candidate shared by prepared aggregate and scalar
  `DISTINCT` execution: both currently retain complete source rows before their
  separate semantic consumers run. Aggregate folding and scalar `DISTINCT`
  identity, order, pagination and budget behavior remain separate owners.

### 🧪 Testing

- Raised the fail-closed P2 candidate ceiling from 512 to 544 after the frozen
  top-20-per-metric union produced 521 candidates. Selection remains complete
  and fails rather than truncating; scenario membership and fixtures are
  unchanged.
- Patch 1 changes no production runtime, public API, Candid, export, stable
  format or query behavior.

### 🔧 Changed

- Retained-slot scans over an eligible primary-map stream now consume the raw
  row already opened by the owning store visitor instead of encoding each key
  and performing a second tree lookup. Paginated and unsupported streams keep
  the predecessor path.
- Expression-backed ordering caches the same canonical order values and uses
  the same comparator, but sorts compact source positions and moves each large
  retained row once instead of sorting complete row payloads.
- At 2,048 rows, the prepared aggregate `DISTINCT` plus `FILTER` control falls
  from 109.235M to 70.759M instructions. Nullable and expression-order scalar
  `DISTINCT` controls fall from 118.739M to 87.602M and from 109.376M to
  78.239M respectively, with unchanged results and physical visits.
- Adopted `ic-timers 0.7.0` and its watchdog-specific reconciliation contract.
  Lifecycle and commit-pressure work now schedule immediately, and successful
  bounded recovery continues immediately while more work remains. Retryable
  failure still waits for the one-second cadence.
- Capped each incarnation at 16 active-plus-retired journaled store quartets
  and gave backlog admission an independent 64-batch ceiling. The existing
  16,384-record and 16-MiB limits remain unchanged.

### 📊 Audit — Candidate

- The candidate production SQL Wasm is 4,517,281 raw bytes, 3,837 bytes above
  the exact predecessor and within the frozen 4,096-byte limit. Production
  state space is unchanged: no new type, module, cache, mutable owner,
  persisted state or execution mode.
- The frozen predecessor P2 selection correctly rejects the candidate Wasm's
  different subject identity. Complete candidate P1 selection and P2
  confirmation remain release-validation work; the identity check was not
  bypassed.
- Prepared-fallback tests now identify execution through the scalar-aggregate
  owner and ingested-row count instead of requiring redundant point gets. The
  existing prefix-family control retains its exact 65-entry physical work and
  a narrowly rebased ceiling after repeated 5.301M-instruction measurement.

### 📊 Audit — Recovery Convergence And Capacity

- Cold and populated 64-batch backlogs each drain in 64 bounded callbacks over
  145 ns of PocketIC time, then admit the rejected retry. Upgrade reconstruction
  retains the same behavior and existing instruction and memory bounds.
- The 16-head selector and maximum retirement probe costs 287,890,767
  instructions, 5,727,601 below the prior 38-head measurement. A repeated
  16-MiB-class fill drains and refills at a stable 513-page high-water.
- Against the exact 0.246 query candidate, the production one-entity SQL
  canister's final raw non-gzipped Wasm grows by 5,837 bytes after Patch 4
  removes 3,029 bytes from the timer-only candidate. Recovery retains one page
  per callback, one watchdog owner, and no new IcyDB state or mode.

### ⚠️ Breaking

- The singular current version-1 registry now rejects a seventeenth
  active-plus-retired journaled store. Before 1.0 this is a hard cut: databases
  that already persisted more than 16 store quartets must be recreated.

### 🧭 Migration Notes

- Generated canisters must be rebuilt against `ic-timers 0.7.0`. There is no
  public API or Candid migration. Existing databases at or below 16 persisted
  store quartets retain the same current version-1 encoding shape.
