# 0.268 — Testkit-owned PocketIC tooling

## [0.268.0]

### ⚠️ Breaking

- Testkit now owns PocketIC provisioning and offline admission. Shared Tooling
  0.2.0 prepares/checks five IC tools and no longer supplies a PocketIC server.
  Run `make fetch install-tools tools-check` explicitly after adoption; the
  existing six-tool bundle cannot satisfy the new offline check. Retain old
  bundles, receipts and failed evidence; no conversion or cleanup occurs.
  `install-testkit` replaces `install-pocketic-runner` and prepares both the
  locked CLI and server. `testkit-check` prints Testkit's admitted server path.
  Tests never download a missing server. This tooling contract change requires
  the explicitly selected minor line; product APIs and stored data are unchanged
  ([#327](https://github.com/dragginzgame/icydb/issues/327),
  [Shared #76](https://github.com/dragginzgame/shared-tooling/issues/76)).

### 🔧 Changed

- Install the locked Testkit CLI through Shared's selected Cargo installer,
  using its package/profile receipts and byte admission. Make, workstation
  setup and CI use the same explicit preparation and offline checks. Ordinary
  test lanes obtain the server path from Testkit; the managed Tier B wrapper
  keeps its output retention, signal handling and single-server topology.
  Explicit external server selections retain Testkit's admission.
- Let the managed Tier B runner perform server admission once instead of
  resolving the server in Make first. Treat an empty server override as the
  owner-managed selection, while retaining failure logs and signal cleanup.
  Remove consumer fixture checks for shared bundle retention; that boundary
  remains with Shared's canonical fixtures
  ([#327](https://github.com/dragginzgame/icydb/issues/327)).

### 🩹 Fixed

- Shared Tooling 0.2.1 includes the 0.1.38 fixes, adopted through its canonical
  exporter. Dependency
  exceptions must be one validated JSON document, closing the bypass where a
  trailing empty array admitted malformed exceptions from the first document.
  Hooks and isolated formatting checks find the original checkout's prepared
  tools without a user PATH export. Selected Cargo binary/example installation
  retains package/profile receipts, offline byte checks and failed attempts
  ([#309](https://github.com/dragginzgame/icydb/issues/309),
  [Shared #86](https://github.com/dragginzgame/shared-tooling/issues/86),
  [Shared #85](https://github.com/dragginzgame/shared-tooling/issues/85)).
- Install and verify every selected IC executable when a pin matrix lacks a
  trailing newline, closing the shared installer's last-record omission without
  rewriting pins or retained receipts
  ([Shared #87](https://github.com/dragginzgame/shared-tooling/issues/87)).
- When accepted indexes match the same constrained prefix, prefer the index
  that supplies the requested order before fully consumed keys and other
  structural tie breakers. A public read constrained by `robot_id` and
  `location_id`, ordered by `serial_number DESC` with `LIMIT 1`, now selects
  `(robot_id, location_id, serial_number)` instead of the shorter scope index.
  It needs no extra serial-number predicate and no materialized sort. Selected
  and rejected EXPLAIN reasons report the same ordering preference. Longer
  constrained prefixes retain priority; unsupported sorting and whole-index
  scans retain their public admission checks
  ([#332](https://github.com/dragginzgame/icydb/issues/332)).

### 🧪 Testing

- Qualify the consumer's locked CLI selection, explicit server setup, offline
  refusals before invoking a caller, and external-server overrides in the
  existing portable lane. Canonical shared fixtures cover the five-tool
  installation and retained-bundle boundaries; actual product startup remains
  part of the native host qualification flow.
- Add the canonical shared dependency fixture to the existing portable CI lane,
  including refusal of multiple JSON documents and preservation of exception,
  manifest, lockfile and index bytes. Reuse the shared checker and fixtures;
  no consumer exception parser or separate CI flow is added.
- Qualify empty and populated accepted schemas with unique and nonunique
  serial indexes, ascending/descending top-1 and resumed traversal, repeated
  keys, cold/warm plans, owner/location isolation, and maximum `Nat64` serials.
  Compare public and trusted top-1 results and check unchanged no-order,
  materialized-sort and whole-index-scan controls.
