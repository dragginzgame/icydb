## Patch 1 — Required Generated-Trait Authority

Status: complete.

The required set for every generated application value type is:

- `Clone`;
- `Debug`;
- `Path`;
- `CandidType`;
- `Deserialize`;
- `Eq`;
- `PartialEq`;
- `NormalizeAuto`;
- `ValidateAuto`; and
- `Visitable`.

The compiler already emits this set by default. Patch 1 makes that ownership
explicit and rejects both redundant addition and forbidden removal before
token generation. It does not change `Default`, `From`, `NormalizeCustom`,
`ValidateCustom`, collection, dereference, arithmetic, wrapper, enum, or other
shape-derived behavior.

### Implementation

  and default set before applying the remaining configurable directives.
- Entity, enum, list, map, newtype, record, set, and tuple generation all use

- Explicit `add` and `remove` directives for every frozen required trait fail
  before token generation with action-specific diagnostics.
- `Default`, `From`, `NormalizeCustom`, `ValidateCustom`, and all node-specific
  ergonomic and shape-derived traits retain their previous ownership.
- Compile-fail fixtures exercise representative redundant-add and
  forbidden-remove diagnostics through the public macros.

## Patch 2 — Contract And Inventory Freeze

Status: complete.

The repository audit corrected one design assumption before semantic work:
`RuleSourceKey` is the bounded local rule name, not a hash of the containing
type and rule names. Source declaration identity is
`(TypeSourceKey, RuleSourceKey)`, while each accepted constraint proposal key
is the frozen domain-separated hash of the persisted root field, target type,
and local rule keys. The accepted design now matches that simpler maintained
architecture.

### Frozen Contract

- The target grammar has five closed typed forms: inclusive length range,
  numeric minimum, numeric maximum, numeric range, and exact integer/decimal
  multiple-of.
- One rule contains exactly one operation with closed named operands. The
  string `kind` and positional `Args` transport disappear together in Patch 3.
- All 15 maintained declarations, 19 normalizer definitions, 37 validator
  definitions, 15 maintained normalizer attachments, 14 maintained validator
  attachments, and five intentional custom validator hooks are classified in
  the inventory.
- The callback map freezes one explicit application traversal boundary and one
  accepted database evaluator; database writes, retries, recovery, replay,
  derived work, and integrity invoke no application callback.
- `ProposalContractVersion::CURRENT` remains 1. Patch 4 hard-cuts its nested
  operation shape in place and changes the accepted version-1 snapshot profile
  from `ICYT` to frozen `ICYU`, with no old decoder or version-2 wrapper.
- Existing targeted-operation fingerprint tags 1 through 3 stay fixed;
  maximum and multiple-of append tags 4 and 5. The accepted semantic
  fingerprint domain remains unchanged because it consumes the exact snapshot
  bytes.
- Same-identity semantic rule edits are assigned to the existing
  catalog-native transition owner in Patch 6. The audit found that the current
  path otherwise rejects such an edit; 0.216 must not describe that transition
  as already implemented.

### Evidence

- The 16 audited source-rule, schema, lowering, evaluator, and visitor owner

- Markdown links and diff hygiene pass.

### Scope And Complexity

## Patch 3 — Typed Rule Grammar And Key Preservation

Status: complete.

### Implementation

- `rule(...)` now requires exactly one of the five frozen typed operations:
  length range, numeric minimum, numeric maximum, numeric range, or
  integer/decimal multiple-of.
- Each operation owns its named operands. Missing, repeated, unknown, and
  cross-operation operands reject during macro parsing; invalid, empty, or
  duplicate local rule names reject at the same boundary.
- The generated source model stores one `SourceRuleAuthoringOperation` rather
  than `SourceRuleKind` plus general `Args`. Direct model construction retains
  the same shape checks during schema validation.

  declarations. Their target-bound exact lowering remains deliberately

- The version-1 proposal shape, accepted `ICYT` snapshot, accepted evaluator,

## Patch 4 — Exact Rule Lowering And Codec Cut

Status: complete.

### Implementation

- All five typed operations now lower through the single model-to-fragment
  owner and bind to closed accepted operations. Numeric maximum uses the
  existing exact comparison path; integer and fixed-scale decimal
  `MultipleOf` use one exact remainder evaluator and reject floats and zero.
- Rule operands use a rule-specific exact number node. Unsuffixed decimal text
  remains textual until the declared primitive is resolved, so rule lowering
  neither passes decimal operands through binary floats nor rounds values to
  the target scale. Generated and directly constructed proposals apply the
  same exact target-kind admission.
- Accepted integer multiple-of covers every signed and unsigned width plus
  bounded big integers. The evaluator also handles the signed minimum divided
  by `-1` without primitive remainder overflow.
- The version-1 proposal operation enum now contains maximum and multiple-of
  directly. `ProposalContractVersion::CURRENT` remains 1; its current digest
  vector changes with that hard-cut nested shape and no old decoder exists.
- The accepted version-1 snapshot profile is now `ICYU`. Maximum and
  multiple-of use activation-fingerprint tags 4 and 5; the existing semantic
  fingerprint domain remains unchanged.
- Constraint description retains its existing public shape and reports the
  two new operation semantics. Rows, keys, indexes, relations, journals,
  markers, cursors, integrity progress, and public response types are
  unchanged.

## Patch 5 — Explicit Application Behavior

Status: complete.

### Implementation

- The existing `icydb_model::normalize(&mut value)` and
  `icydb_model::validate(&value)` operations remain separate and explicit.
  Direct validation still observes the supplied value and never normalizes a
  copy first.
- `NormalizeAndValidate` is blanket-implemented for every sized `Visitable`.
  Its consuming `normalize_and_validate()` method normalizes first, stops on a
  normalization error, validates only the normalized value, and returns the
  same concrete value without cloning.
- `VisitorError` now carries a typed `ApplicationOperation`. Every issue
  emitted through a top-level application traversal carries a typed callback
  class plus the concrete static Rust callback/type path, alongside the
  existing logical value path and ordered child messages. The former
  `VisitorError`-to-`VisitorIssues` conversion is removed so an error cannot
  silently discard its operation identity.
- Declared normalizer and validator attachments override the surrounding
  generated auto-hook identity through nested callback contexts. Custom hooks
  retain the concrete application-value type identity. Successful traversals
  allocate no callback-path string.
- Application diagnostics are Rust application state, not a persisted or wire
  contract. Their former unused `Deserialize` surface is removed rather than
  accepting forged dynamic strings as static callback identity.
- Generated typed adapters still contain no normalize, validate, or composed
  call. SQL, structural writes, mutation retries, recovery, replay, derived
  work, and integrity retain no application callback path.

## Patch 6 — Evolution And Accepted-Authority Convergence

Status: complete.

### Implementation

- A targeted-rule operation or operand edit under one existing source key now
  stages one catalog-native activation under the accepted rule's existing ID,
  name, origin, and target. The non-reusing constraint allocator does not
  advance.
- The prior accepted operation remains present and authoritative while the
  paired activation evaluates the candidate operation as an additional
  new-write gate. The exact accepted/activation collision is valid only for a
  generated targeted rule with a different operation; every other ID or name
  collision remains invalid.
- Direct bounded proof replaces the accepted operation immediately. Historical
  proof uses the existing validation job, marker publication, continuation,
  finding, promotion, and recovery owners. Promotion removes the activation
  and replaces the accepted operation without changing its identity.
- Continuation now distinguishes a completed accepted rule from a paired old
  accepted rule plus live candidate. It cannot finalize a semantic edit merely
  because the old accepted owner still exists.
- Abort removes only the candidate activation for a semantic edit and retains
  the old accepted operation and source binding. Abort of a newly added rule
  still removes its binding and permanently retires its reserved ID.
- A local rule-name replacement remains an explicit removal plus fresh
  addition. No inferred rename, alias, source-specific scanner, staging store,
  publication path, or recovery path was added.
- Constraint introspection orders the validated operation before its same-ID
  candidate activation. This changes only pending-edit projection cardinality;
  the public response shape is unchanged.
- Validator and normalizer attachment edits lower to an identical database
  fragment. They therefore change neither accepted fingerprints nor persisted
  state and remain application-only.

### Evidence

- Ten targeted-rule core tests passed together, covering accepted lowering,
  stable-ID semantic edits, candidate new-write admission, direct promotion,
  explicit remove/add naming, typed diagnostics, codec operations, frontend
  convergence, and bounded evaluator limits.
- Eight schema-application tests passed together. The semantic-edit lifecycle
  proves direct empty-domain publication, staged accepted publication, guarded
  recovery, durable job start, bounded continuation, promotion, stable source
  identity, and terminal accepted state without a generated source model.
- Focused abort coverage passed for both same-ID semantic edits and newly added
  generated checks. The former retains accepted authority and binding; the
  latter retains its non-reuse behavior.
- The current accepted snapshot codec round-trips the paired same-ID
  accepted/activation representation, and transition policy accepts only its
  exact allocator-neutral generated activation shape.
- Five model fragment tests passed, including the proof that changing only
  validator and normalizer attachments produces the same database fragment.
- `icydb-core` compiled without default features. Warnings-denied production
  Clippy passed both with all features and without defaults; warnings-denied
  all-targets Clippy reached one unrelated concurrent schema-mutation test
  redundant-clone finding after Patch 6's own test lint was corrected.
- Formatting and diff-hygiene checks pass. Full workspace and push-time suites
  remain user-owned under repository policy.
- The maintained SQL performance Wasm build passed its single focused test.
  The current mixed worktree artifact is 5,326,809 raw bytes with SHA-256
  `7236f5441cbffc464d67ccf7b939d810907c94f2f21140f34c4c8ec6ce3f5be0`.
