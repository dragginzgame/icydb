# IcyDB 0.216 Final Closeout Audit

Date: 2026-07-31

## Verdict

**Ready to close, with one recorded non-blocking performance follow-up.**

All eight planned patches are implemented. The audit found no correctness,
authority, recovery, compatibility, or format blocker in the released 0.216.1
boundary. The most serious remaining finding is a broad 12–13% instruction
increase on the no-rule mutation/guard cohort relative to 0.215.7. It is not
specific to accepted-rule evaluation, and the obvious empty-rule shortcut did
not reduce it. The release record therefore keeps it visible rather than
claiming no-rule cost neutrality or landing an unproven optimization.

The eight patches are demonstrably complete. The accepted schema remains the
only database authority. Generated model data is proposal/application

normalizers and validators execute only when application code calls them.
Typed, structural, SQL, retry, recovery, replay, derived work, and integrity
paths do not invoke application callbacks.

## Rule, Trait, And Evolution Assessment

- The maintained catalog contains 15 durable rule declarations, all using the
  closed typed grammar.
- `RuleSourceKey` remains the bounded local rule name. Source declaration
  identity is `(TypeSourceKey, RuleSourceKey)`, and each persisted-root use
  derives its accepted constraint key from root field, target type, and rule.
- Length range, numeric minimum, numeric maximum, numeric range, and exact
  integer/fixed-scale-decimal multiple-of each have one canonical lowering and
  accepted evaluator. Zero, float, inexact, and wrong-kind divisors reject.
- Same-name semantic edits retain accepted identity and use catalog-native
  activation. Name changes remain removal plus addition; 0.216 adds no rename
  inference or migration framework.
- Required traits are compiler-owned. `Default`, `From`, custom normalize and
  validate, collection, dereference, arithmetic, wrapper, and shape-derived
  behavior retain their independent grammar and output ownership.
- Searches found no live old `kind = "..."`/`args(...)` authoring, dual
  expansion, old `ICYT` decoder, callback registry, source-model evaluator, or
  compatibility alias. Historical and recreation documentation is retained as
  documentation only.

## Persisted And Public Format Assessment

The complete 0.216 line changes these current-form contracts:

- the version-1 proposal's nested durable-rule operation is now one of five
  typed operations with named operands;
- the version-1 accepted schema profile is `ICYU`, with fingerprint tags 4 and
  5 appended for numeric maximum and multiple-of;
- `Date` keeps its `i32` epoch-day representation in rows, cursor tokens, and
  Candid while current construction and decoding accept only years 0000
  through 9999;
- public Rust application diagnostics carry typed operation, callback, and
  bounded value-path identity, and removed Rust conveniences have no aliases.

Rows, primary/secondary keys, layouts, relations, commit markers, journal
records, Identity state/ranges, integrity progress, database-error wire, and
public database Candid response layouts otherwise remain unchanged. The Date
domain restriction is nevertheless a behavioral hard cut: out-of-domain
development state must be recreated and has no fallback decoder.

## Findings And Corrections

### Medium — no-rule mutation cost is not neutral

The released 0.216.1 artifact compared with an isolated 0.215.7 build shows:

| Cohort | 0.215.7 | 0.216.1 | Delta |
| --- | ---: | ---: | ---: |
| Heap first insert | 27,089,674 | 30,820,407 | +13.772% |
| Heap steady insert | 20,465,034 | 23,073,074 | +12.744% |
| Journaled first insert | 27,331,411 | 30,894,947 | +13.038% |
| Journaled steady insert | 21,083,607 | 23,681,836 | +12.323% |

Steady update, delete, and write/read increases range from 11.857% to 12.687%.
In contrast, the matched incremental cost of one accepted rule is 0.778% to
1.371%. Symbol comparison shows only a modest increase in the shared mutation
preparation functions and a larger rule evaluator, while query cost is nearly
neutral. A temporary early return for an empty targeted-rule program changed
steady measurements only within noise and was discarded. No speculative code
change was made.

This is the only unmet original checklist target. It is a performance risk,
not evidence of a second authority or a semantic defect, and remains an
explicit follow-up.

### Low — final release evidence drifted from pre-release measurements

The status and detailed changelog recorded the pre-release artifact and crate
package. They now record the released outputs:

- SQL performance Wasm: 5,328,072 raw bytes, SHA-256
  `16b4e4527e5380157f474ecd9a58dfa3c76b4b3720efb143fa2cf8f952d15587`;
- delta from the 5,302,780-byte Patch 2 artifact: 25,292 bytes, 0.477%;
- `icydb-model` crate: 101,382 compressed bytes, 109 files, SHA-256
  `b8f6d3c4679d1ac72a562aa692df150e6383ab57683dc7e909d44b569fedae14`.

The design status, release diff, Date domain inventory, and missing detailed
changelog separator were corrected. The implementation was not changed.

### Inherited — advertised dependency MSRV is not independently provable

`icydb` advertises Rust 1.88, while unconditional model/macro dependencies use
the workspace Rust 1.96 declaration. The focused Rust 1.88 check fails during
dependency admission rather than compiling the facade. This mismatch already
exists at `v0.215.7`; it was neither introduced nor widened by 0.216 and is not
a 0.216 correction. It remains a repository-level release concern.

## Remaining Risk

The 12–13% common mutation/guard regression still lacks exact attribution. It
should be profiled from the frozen `v0.215.7` and `v0.216.1` artifacts before a
future performance-sensitive release, but it does not justify reopening the
0.216 authority design or landing an unmeasured shortcut. Concurrent
post-release time/scalar cleanup must receive its own focused validation and is
not covered by this report.
