## Current Boundary

0.226 provides framework-neutral, application-scoped authorization of
generated SQL and schema reads. Patches 2-3 added the Rust-only authorization
contract, bounded allowlist, guarded generated SQL and accepted-schema
declarations, and E281/E282. Patch 4 closes the line with one combined
least-privilege canister and same-release lifecycle proof. Public Candid,

framework/application remains motivating incident evidence only. Canic, Explorer, reference application,
and other frameworks/tools are not predecessors, release gates, runtime
dependencies, or lifecycle owners for 0.226.

## Frozen Guard Grammar

Patch 1 corrected the provisional custom "identifier-only" grammar. The
implementation must use Rust's standard macro `path` fragment and then coerce
the captured value to the exact safe `ReadAuthorizationGuard` function-pointer
type. IcyDB must not parse, normalize, qualify, or rewrite a guard path itself.

A Rust 1.97.1 compile probe produced this exact matrix:

| Form | Outcome |
| --- | --- |
| bare, ordinary module, `crate::`, `self::` | Accepted |
| leading `::` absolute path resolving through a named crate | Accepted |
| raw-identifier segments | Accepted |
| associated function, re-export, named function-pointer constant | Accepted |
| inferred generic and explicit turbofish resolving to the exact type | Accepted |
| `super::` at the required crate-root declaration site | Context-invalid: too many leading `super` keywords |
| qualified-self `<Type as Trait>::function` | Rejected by the macro `path` fragment |
| closure, block, literal, call expression, multiple arguments | Rejected by the macro grammar |
| unsafe, async, reference-argument, richer-result, non-Rust ABI function | Rejected by exact function-pointer coercion |

Explicit turbofish is therefore maintained compiler grammar, not a security
exception. The exact function-pointer type remains the semantic gate.

## Patch 2 Guarded SQL Implementation

The public Rust-only contract is `ReadAuthorizationContext { caller, surface }`,
`ReadAuthorizationSurface::{Sql, Schema}`,
`ReadAuthorizationDecision::{Allow, Deny}` and the exact safe-Rust function
pointer `ReadAuthorizationGuard`. The `Schema` discriminator is part of the
single frozen contract and is wired by Patch 3 to the dedicated schema method.

`icydb_sql_query(..., authorization = guard(path))` captures a standard Rust
`path` and immediately coerces it to `ReadAuthorizationGuard`. Its generated
wrapper rejects anonymous callers without invoking application code, then
invokes the guard exactly once. Only `Allow` proceeds into query metrics,
request-root construction, startup admission and the existing SQL handler.
`Deny` returns E281. Guarded mode replaces controller policy; it does not union
with it. The two omitted-authorization SQL declarations remain byte-for-byte
the existing controller path.

The maintained allowlist accepts at most 64 principals, rejects anonymous and
over-cap input before scanning, uses exact principal equality and allocates or
persists nothing. There is no new policy store, cache, remote call, session,
cursor, executor or compatibility path.

The compile contract accepts bare, module, `crate::`, `self::`, leading
absolute, raw-identifier, associated-function, re-export, named-constant,
inferred-generic and explicit-turbofish paths. The final audit routes every
accepted spelling through the production endpoint macro grammar as well as an
active exact function-pointer coercion. Twelve focused compile-fail fixtures
reject context-invalid `super::`, qualified-self, closure, block, literal,
call, multiple argument, unsafe, async, reference argument, richer-result and
non-Rust-ABI forms.

PocketIC exercises the real generated endpoint. A distinct reader succeeds;
an outsider and the canister controller receive E281 before invalid SQL can be
parsed; an authorized `INSERT` still receives the existing read-lane mutation
diagnostic. Anonymous is rejected before a deliberately trapping guard,
application traps propagate without data, and a query-local sentinel proves
one invocation on success.

## Patch 4 Framework-Neutral Closeout

The final evidence actor declares both generated read surfaces from one source.
Its production profile uses the maintained controller policies; its guarded
profile replaces both with local synchronous application guards. Two fixed
heap-local application booleans are initially false and can be changed only by
one fixed application administrator. The guards only read the current boolean,
verify their exact `Sql | Schema` discriminator, and invoke the maintained
one-reader allowlist. They allocate no policy state, make no call, and touch no
stable memory.

PocketIC replaces the installation controller with the principal of a newly
created canister. That non-human controller remains the sole controller before
and after upgrade. The distinct reader cannot inspect status, change
controllers, stop, or upgrade the database canister. It is initially denied by
E281/E282 and cannot grant itself access. The administrator can independently
allow SQL and schema, and the next reader call observes each allow or revoke
without a cached decision. SQL authority never implies schema authority.

The stable-memory byte vector is identical from before controller delegation
and every initial denial through the complete allow/query/revoke sequence. The
non-human controller itself receives E281/E282, while the distinct reader
cannot grant itself access. This runtime proof agrees with the source audit:
IcyDB owns zero persisted authorization bytes, zero decision-cache bytes, and
zero query-time remote authorization calls.

The same guarded Wasm is then installed through a same-release upgrade by the
control-canister principal. Both heap-local application policies reset to deny.
After the administrator re-enables them, SQL and schema return E280 until the
maintained startup watchdog completes; guard success therefore remains only
authorization and cannot bypass startup admission. Once Ready, the reader
receives the exact pre-upgrade typed SQL result and accepted-schema vector.

## Frozen Architectural Direction

- Add `guard(path)` to the established authorization field; do not add a new
  declaration system.
- Guard replaces controller authority; it is never an implicit union.
- Applications wanting controller access include `is_controller` explicitly in
  guard policy.
- SQL and dedicated schema use separate guards and E281/E282 denial leaves.
- The exact context contains caller plus `Sql | Schema`; it contains no static
  `introspection_enabled` flag.
- Candid decodes first; each non-anonymous invocation then calls the guard once
  before request-root, readiness, parser, database, or handler construction.
- Guard `Allow` means authorization only; normal 0.225 admission remains
  authoritative afterward.
- Anonymous is rejected without application code; mutation rejection is
  independent of authorization mode.
- IcyDB persists/caches no policy or decision and exposes no policy engine.
- `icydb::guards::allowlist(context, readers)` owns bounded static-principal
  matching; the application supplies a one-line function-pointer adapter.
- Denials are intentionally excluded from IcyDB database request metrics;
  security auditing remains application/authorization-framework authority.
- Standard calls and success/E25/E26/E281/E282/method-not-found outcomes are
  the only discovery contract; no manifest, sidecar, digest, or custom section.
- Lifecycle participation remains wholly outside 0.226 and belongs to 0.227.
