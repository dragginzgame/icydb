## Design Reconciliation

The source idea proposed a new key/row streaming architecture. The current
engine already owns concrete `OrderedKeyStream` execution, merge/intersection,
top-N seek contracts, resumable pages, late primary-row loading, and shared
structural slot decoding. 0.222 therefore contracts remaining eager ownership
inside those maintained owners instead of adding a parallel iterator or
executor framework.

Patch 1 audited these materialization owner families:

- materialized physical key resolution and bounded prefix families;
- one-key-at-a-time sparse intersection;
- covering/hybrid projected-row vectors;
- structural `RowView::into_owned` boundaries;
- scalar retained/order rows before the page boundary;
- distinct retained output rows; and
- grouped/hash state that may retain more source data than its aggregates need.

The machine-readable inventory classifies each family before behavior changes.
Each entry records a primary semantic reason plus lifetime, size authority,
backing ownership, resumability, and action owner. Complete retained backing
bytes remain explicitly unmeasured until Patch 5; a small borrowed slice may
not hide a large retained payload.

## Contract Review Resolution

The pre-implementation audit is accepted. The design now requires:

- `seek_head_at_or_after` held-head semantics, with positioning separate from
  consumption and direction defined by traversal order;
- an interruption-by-interruption intersection continuation proof and strict
  monotonic progress before planner eligibility;
- bounded per-child operator state as a separately reviewed cursor-format
  outcome if the current scalar continuation cannot prove progress;
- ordered-adjacent versus complete global distinct strategies and closed
  ordered-group versus complete hash-group strategies;
- compact owned values at blocking boundaries or accounting for the complete
  retained backing payload;
- an indivisible page-work-unit rule, typed oversize failure, and a prohibition
  on unchanged successful empty-page cursors;
- bounded prefix-family fan-out, deterministic conservative planner costing,
  complete seek/storage charging, and typed accepted-index corruption; and
- fixed named performance fixtures requiring both physical-counter and
  instruction evidence.

Patch 1 is a contract/inventory/baseline patch, not a behavioral optimizer. It
publishes the cursor-feasibility and blocking-route matrices before later
routes can rely on them.

## Patch 2 Evidence

- `HeldHeadKeyStream` separates `ensure_head`,
  `seek_head_at_or_after`, and `consume_head`; seeking returns a borrowed held
  key and therefore cannot consume or repull it accidentally.
- `RepeatedPullHeldHeadKeyStream` is the reference implementation. It makes no
  physical range jump and is not planner-visible, so successful production
  queries and physical routes remain unchanged.
- A finite pull-attempt envelope returns `PageStop` before starting the next
  indivisible pull unit. Exhaustion is distinct, while hard-budget and
  corruption failures return typed errors with no page.
- Checked counters cover pull attempts, comparisons, skipped occurrences, and
  total consumption. Failed accounting leaves a held key intact; partial work
  before an upstream failure remains charged.
- Ten focused tests cover concrete-envelope composition, ASC/DESC
  behind/equal/ahead targets, duplicates,
  page-stop resume with a changed envelope, held-head interruption, exact-once
  consumption, hard failure, entity/order corruption, overflow, and 128
  deterministic randomized sequence/direction cases against a suffix oracle.
- The frozen query fixtures retain identical index-entry, store-get, row, and
  peak-retention counters. Representative instruction movement is within
  `-0.0379%` to `+0.1092%`, below the 1% control-review threshold and with no
  claimed optimization.
- The production dynamic-query fixture remains exactly 2,479,797 raw final
  Wasm bytes and 973,166 deterministic gzip bytes (`0` byte delta). Candid and
  generated method modes are unchanged.
- Patch 2 spans seven implementation, test, contract, and documentation files
  at approximately `+910/-0` lines. Internal complexity grows by one concrete
  staged protocol and its oracle; the production execution shape remains
  unchanged until Patch 3 supplies a physical consumer.

## Patch 3 Evidence

- Primary and eligible primary-key-ordered index range leaves implement the
  held-head contract with direct raw-bound repositioning. Finite-window leaves
  retain repeated logical progress so a seek cannot bypass offset/limit work.
- Repositioning charges cursor work and checked bound bytes, distinguishes
  logical skips from physical seeks, and preserves the first qualifying key as
  an unconsumed head. Accepted index entries that are malformed or name a
  missing row remain typed corruption rather than exhaustion.
- The eager prefix-family candidate vector, sort, deduplication, and truncation
  route is removed. Construction now checks the canonical 128-child limit and
  descriptor/bound bytes before allocation; a bounded merge heap owns one head
  per concrete child and handles ASC/DESC duplicates deterministically.
- Focused heap-store tests cover ASC/DESC primary repositioning, exact
  primary-key-ordered index jumps, finite-window fallback, page stop before a
  store pull, maximum/max-plus-one fan-out, and malformed index propagation.
  The frozen PocketIC fixture also passes through the journaled backend with
  every expected row and counter shape unchanged.
- The final frozen `prefix_family_max_fanout` measurement is 6,437,409
  instructions and 68 index entries, versus 6,438,154 and 68 after Patch 2
  (`-0.0116%`). The old eager fallback was dormant for this 16-child fixture;
  the bounded heap improves merge complexity from a linear child-head scan per
  output to logarithmic child-count work but does not claim the line's 20%
  performance gate. Physical seek value remains staged for Patch 4's sparse
  intersection alignment.
- Sparse intersection controls remain planner-unchanged: two-child sparse is
  2,545,172 instructions with 21 index/store reads, while three-child DESC is
  7,970,504 with 120 index/store reads. Patch 4 must prove cursor progress and
  improve the required structural counters before enabling a new route.
- The production dynamic-query canister is 2,529,166 raw final Wasm bytes and
  991,865 deterministic gzip bytes. Against the Patch 2 baseline this is
  `+49,369` raw bytes (`+1.99%`) and `+18,699` gzip bytes; its 4,670-byte Candid
  and exported method modes remain unchanged.
- Patch 3 touches eight executor/contract files plus its status, design,
  inventory, and Unreleased evidence at approximately `+950/-160` lines.
  Internal complexity grows moderately through two physical seek state
  machines and a bounded heap, while the row-count-owned eager prefix path is
  deleted.

## Patch 4 Evidence

- The planner admits only two or three distinct exact accepted-index prefixes
  whose remaining suffix is the complete primary key and whose requested order
  is absent or primary-key-only. Exact compound access is formed first and
  remains preferred.
- Synchronized prefix cardinalities must prove every child and their checked
  sum fit the 256-entry atomic envelope. Missing, stale, overflowing, or
  over-cap authority keeps the planner-preferred first index and the complete
  residual predicate, so fallback cannot change results.
- The exact overlap probe retains only ordered primary keys. Its maximum vector
  slots are precharged, every encoded key backing is charged, and the total is
  capped by the persisted primary-key maximum. The retained keys become the
  execution stream, eliminating the initially measured duplicate child scan;
  no row, payload, or projected value crosses this boundary.
- Frozen PocketIC evidence moves two-child sparse execution from 2,545,172 to
  2,535,426 instructions (`-0.38%`) while row fetches fall from 21 to 1; its 41
  index entries replace the removed residual row reads. Three-child DESC moves
  from 7,970,504 to 5,394,711 instructions (`-32.32%`), with 161 index entries
  and one row fetch instead of 120 index entries plus 120 row fetches.
- The empty overlap completes at 2,474,603 instructions with 41 index entries
  and zero row fetches. The dense range route remains ineligible and unchanged
  at 2,048 index/row reads; the exact compound control still uses one index
  entry and zero row fetches. The two-child 20% line-wide instruction target
  remains open even though its payload-work target is satisfied.
- `EXPLAIN JSON` reports `planner_exact_index_intersection`, the complete
  residual predicate required by fallback, and distinct compound-index
  selection. Focused tests also cover worst-case dense costing and arithmetic
  overflow fail-closed behavior.
- The production dynamic-query canister is 2,533,360 raw final Wasm bytes and
  993,818 deterministic gzip bytes. Against Patch 3 this is `+4,194` raw bytes
  (`+0.166%`) and `+1,953` gzip bytes; its 4,670-byte Candid and exported method
  modes remain unchanged.
- Patch 4 touches planner, traversal, cardinality, diagnostics, focused tests,
  and design evidence at approximately `+500/-30` lines. Complexity grows
  moderately through one bounded runtime-costed access strategy; public and
  persisted formats remain unchanged.

## Patch 5 Evidence

- Cursor-emitting scalar projections now use `SlotsOnly` whenever the compiled
  retained layout owns the projection and order boundary. A 300 KiB unrelated
  payload is fetched and decoded at most once for the current row, then dropped;
  it no longer stays attached to every page candidate until cursor assembly.
- Model-identity, nested field-path, and outward entity-row consumers retain
  the full raw-row modes because their successful output still requires that
  payload. Focused mode tests pin both sides of this ownership decision.
- Ordinary non-`DISTINCT` projection now creates its final owned value row
  directly. The reusable borrowed `RowView` and subsequent deep `to_vec` clone
  are removed; `RowView` is an owned-only blocking transport left to Patch 7's
  `DISTINCT` contract.
- Hybrid covering projection replaces per-row component/field `BTreeMap`s with
  compact `(slot, value)` vectors and one query-shape ownership plan. Tests
  prove a 300 KiB final-use blob keeps the same allocation while repeated-use
  values clone only until their final owned use.
- A live-page test resumes a projection with hidden nullable/mixed ordering
  values through the compact slot payload. The materialization inventory now
  classifies ordinary candidate rows as output ownership and keeps only the
  owned `DISTINCT` transport assigned to Patch 7.
- Frozen PocketIC controls remain within the 1% review threshold: empty,
  two-child, three-child, dense, and compound intersection fixtures move by
  `+0.079%`, `+0.067%`, `-0.014%`, `+0.059%`, and `+0.157%` respectively, with
  their physical counters unchanged.
- The production dynamic-query canister contracts from 2,533,360 to 2,525,393
  raw final Wasm bytes (`-7,967`, `-0.315%`). Deterministic gzip is 994,998
  bytes (`+1,180`), while the 4,670-byte Candid and exported modes remain
  unchanged.
- Patch 5 changes eleven implementation/contract files at approximately
  `+252/-377` lines. The shape becomes simpler overall: three borrowed visitor
  families and two per-row maps are removed in favor of explicit owned output,
  compact current-row values, and one payload-mode decision.

## Patch 6 Evidence

- A scalar route whose access order already satisfies final order now stops the
  row scan immediately after residual filtering produces the requested matched
  window. An added early residual-match control reads one stored row and
  returns one row; the absent-match and existing last-row controls still read
  all 2,048 rows and therefore cannot hide incomplete exhaustion.
- One-shot execution keeps exactly `offset + limit` rows and performs no
  unneeded lookahead. Cursor-emitting execution keeps the one lookahead needed
  by the existing authenticated continuation, while resumed non-primary order
  remains uncapped because its progress is not physically reconstructible from
  the current cursor.
- Incompatible-order projection retains compact canonical order/tie/output
  slots. The fixed top-N fixture peaks at ten candidates and 4,000 complete
  backing bytes, below its smallest unrelated 40 KiB payload; the complete-sort
  control still retains all 2,048 candidates as required.
- Full-entity ordering now selects its bounded winners during the scan instead
  of collecting every raw row first. Only outputs that genuinely require a
  complete entity retain winner payloads, and diagnostics charge the complete
  retained allocation rather than the size of a borrowed order field.
- Ordering entries, comparisons, and complete backing bytes remain charged for
  every candidate before it crosses the blocking boundary. The implementation
  deliberately keeps immediate monotonic accounting so a later row-read error
  cannot discard a partially buffered accounting frame.
- The frozen `topn_wide_payload` cost moves from 81,990,155 to 81,855,556
  instructions (`-0.16%`) and its retained count moves from eleven to ten. This
  is an instruction and structural improvement, but it does not meet the fixed
  20% line gate; that gate remains explicitly open for closeout rather than
  being weakened or moved to a friendlier fixture.
- Frozen 1% controls remain inside their review threshold: full sort moves by
  `+0.53%`, while point get, ordered empty scan, and dense full return move by
  `+0.20%`, `+0.23%`, and `+0.24%` respectively.
- Against the Patch 5 handoff, the production dynamic-query canister grows from
  2,525,393 to 2,526,613 raw final Wasm bytes (`+1,220`, `+0.048%`) while gzip
  shrinks by 195 bytes. Against published `0.222.0`, raw Wasm remains 6,747
  bytes smaller (`-0.266%`); its 4,670-byte Candid and exported modes are
  unchanged.
- Patch 6 adds the scalar cap, direct full-entity winner window, retained-byte
  attribution, and focused contracts across thirteen implementation/test
  files at approximately `+680/-250` lines over the Patch 5 handoff. Complexity
  grows moderately through explicit bounded ownership/accounting, while the
  unbounded raw-row collection route is removed.

## Patch 7 Evidence

- Projection DISTINCT now chooses between two explicit contracts. Direct
  projected slots use adjacent execution only when their complete equality
  tuple leads the resolved total order; hidden order fields before that tuple,
  expression projections, and other unproven shapes use complete global
  replay. Model identity remains adjacent-safe through primary-key uniqueness.
- Adjacent execution retains one canonical current-group key and publishes a
  representative only after its group is closed. Its continuation boundary is
  the final duplicate in that group, so the next group remains an unconsumed
  lookahead on resume.
- Global execution completes its bounded canonical set before output. Replay
  skips the authenticated prior-output count and retains projected rows only
  for the requested output window; later unique keys retain canonical key
  state but not unused source or projected rows.
- Focused operator tests cover nonadjacent duplicates across two replayed
  pages, adjacent closed-group resumption, hidden-order rejection, deterministic
  representatives, null/nested canonical keys, and typed retained-state budget
  exhaustion. The real SQL fixture selects both strategies over 2,048 rows.
- `distinct_nonadjacent_cross_page` completes at 89,638,376 instructions while
  retaining one canonical key at a time and 196 complete key/output backing
  bytes. The
  conservative global control completes at 118,401,465 instructions, discovers
  19 unique tuples, retains ten output rows plus the canonical set, and peaks at
  2,704 backing bytes. Neither route retains the fixture's unrelated payload.
- A clean-tag comparison build completed, but its PocketIC server failed to
  bind an ephemeral socket before query execution. The frozen Patch 7
  instruction-delta gate therefore remains open; no inferred speedup is
  recorded in place of measured before/after evidence.
- The production dynamic-query canister is 2,532,160 raw final Wasm bytes and
  997,233 deterministic gzip bytes. This is `+5,547` raw bytes from Patch 6,
  within the 8,192-byte patch allowance, and `-1,200` bytes from published
  `0.222.0`; Candid remains 4,670 bytes with unchanged exported modes.
- Patch 7 changes the projection coordinator, DISTINCT state owner, bounded
  metrics/attribution, focused fixtures, and contracts across roughly fifteen
  implementation/test files at approximately `+700/-150` lines. Internal
  complexity grows moderately through two explicit progress state machines,
  while full source-row retention and ambiguous early global completion are
  removed.
