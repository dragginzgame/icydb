## Outcome

Patch 1 fixes the names, data distribution, SQL, review thresholds, structural
counters, materialization owner families, and progress questions that later
0.222 patches must answer. It adds a dedicated audit-only schema surface and
canister loader but does not change planner eligibility, stream behavior,
cursor encoding, row loading, or successful database results.

The fixture contains 2,048 rows in each of two equivalent entities:

- `PerfAuditStreamingRow` has independent `(lane_a, id)` and `(lane_b, id)`
  indexes plus `(group_key, id)`;
- `PerfAuditStreamingCompoundRow` has the exact `(lane_a, lane_b, id)` compound
  control;
- `lane_a = 0` selects 21 rows;
- `lane_b = 0` selects 20 rows;
- their sparse overlap contains exactly one row;
- `lane_a = 0 AND lane_b = 1` has no overlap;
- 17 group values recur noncontiguously; and
- the first three primary rows carry 300 KB, 150 KB, and 40 KB payloads.

The generator version, seed, row count, payload lengths, exact SQL, expected
row counts, directions, continuation modes, structural evidence, 20%
improvement gates, and 1% control-review thresholds are constants. Later
patches may extend measurement, but they may not silently replace a named
fixture with a friendlier query or dataset.

## Held-Head State Matrix

Patch 2 must implement this state machine before any physical seek claim.

| Current state | Operation | Required next state | Consumption |
| --- | --- | --- | --- |
| Unpositioned | ensure head | Held or Exhausted | no qualifying head consumed |
| Held(20), ASC | seek target 10/20 | Held(20) | no-op |
| Held(20), ASC | seek target 30 | first Held(key >= 30) or Exhausted | only keys `< 30` consumed |
| Held(20), DESC | seek target 30/20 | Held(20) | no-op |
| Held(20), DESC | seek target 10 | first Held(key <= 10) or Exhausted | only keys before 10 in DESC consumed |
| Held(key) | consume head | Unpositioned | exactly one physical occurrence consumed |
| Any live state | page stop | reconstructible checkpoint | no uncheckpointed head published |
| Any live state | hard/corruption failure | no page | completed work remains charged |

Duplicate physical occurrences remain distinct until an owning operator
deduplicates them. `next_key` means ensure, return, then consume exactly one
held occurrence.

## Intersection Continuation Audit

Current intersection state is not yet eligible for resumable seek planning.

`IntersectOrderedKeyStream` retains one held item per child internally. A
three-child route nests pairwise intersections, so divergent state exists at
more than one level. The current authenticated scalar progress carries one
logical boundary, one consumed physical anchor, and one unconsumed lookahead;
it has no bounded per-child checkpoint. The intersection owner also exposes no
route-progress receipt to the page coordinator.

| Interruption point | Logical safety | Monotonic no-replay proof with current cursor |
| --- | --- | --- |
| Before initial pulls | Yes | Initial state only |
| After one initial child pull | In-memory only | Not representable |
| During a child physical seek | In-memory only | Not representable |
| Divergent held heads | No result skipped in memory | Not representable by one child-neutral anchor |
| All heads aligned before row evaluation | Candidate known in memory | Not representable without consuming/skipping decision |
| After residual rejection | Safe only after common progress commits | Not yet exposed |
| After emitted row | Logical boundary is safe | Existing row boundary can resume |
| During lookahead | Safe only when lookahead remains unconsumed | Scalar lookahead exists, child heads do not |
| Empty page on envelope stop | Requires strictly greater route rank | Not currently proved |

Replaying from the last emitted primary key could remain logically correct, but
Patch 1 cannot bound that replay or prove that a small work envelope will not
return the same empty-page continuation forever. Therefore Patch 4 may not
make seek-aware intersection planner-visible until Patches 2-3 provide a
checkpoint proof. If a child-neutral safe watermark cannot prove monotonic
progress, the work stops for the separately reviewed per-child cursor format
already required by the design.

Borrowed values are current-row-only. Any value retained by a blocking route
must become compact owned canonical state or keep an explicitly bounded owner
whose complete unique backing allocation is charged.

## Page-Progress Authority

The maintained coordinator already separates hard failure from page-envelope
stop and preflights indivisible units. Patch 1 freezes these additional review
rules:

- a successful empty page must advance an authenticated monotonic rank;
- an oversized first unit returns typed failure, never an unchanged cursor;
- qualifying lookahead remains unconsumed or explicitly represented;
- operational work envelopes may change on resume, while semantic query
  windows remain authenticated; and
- page receipts are page-local while the request root remains cumulative.

The named continuation fixtures declare the final >10,000-unit requirement,
but the Patch 1 audit dataset remains 2,048 rows to keep baseline sampling
bounded. Patch 8 must realize the >10,000 live and exhaustive variants using
the same generator formula and query identities before closeout.
