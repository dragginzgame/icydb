## Decision Summary

0.222 contracts the remaining eager materialization in query execution without
changing the public page API. Access paths continue to produce concrete ordered
key streams; key-level operators prune candidates before row loading; row views
remain borrowed until a semantic ownership boundary; and only the final page or
an explicitly blocking operator owns result state.

The internal target is:

```text
accepted physical plan
  -> concrete resumable key stream
  -> key-level pruning / seek / intersection
  -> one late row load for surviving keys
  -> borrowed residual and projection evaluation
  -> bounded blocking state only when semantics require it
  -> owned page rows + authenticated continuation
```

The public contract remains:

```text
{ rows, continuation, work }
```

and, for revision-strict reads:

```text
{ rows, continuation, work, proof }
```

0.222 does not add a public iterator, a second executor, joins, or a vectorized
analytical engine.

## Why This Line Follows 0.221

0.221 established the authority and safety foundations this work needs:

- one accepted runtime root and bounded parameterized planning;
- direct bounded exact-key batches;
- one non-resettable request execution budget;
- charged concrete ordered key streams, including merge and intersection;
- authenticated live and exhaustive page progress;
- key-only primary traversal and decode-once row access; and
- bounded request diagnostics.

The older streaming idea predates several of those changes. Its proposed new
stream framework is therefore not adopted literally. The maintained owners are
`OrderedKeyStream`, `OrderedKeyStreamBox`, access traversal, the scalar/grouped
row runtimes, route planning, and the page coordinator. 0.222 extends those
owners and removes remaining convenience collections; it does not create
parallel traits or route dispatch.

## Current Executor Reality

The engine already has:

- concrete primary and index key streams;
- a concrete enum-backed stream envelope instead of a hot-path trait object;
- merge, flat-merge, distinct, concatenation, and intersection streams;
- scalar and grouped streaming routes;
- route-owned top-N and aggregate seek contracts;
- page work envelopes and physical continuation anchors; and
- one terminal row runtime that shares decoded structural slots.

The remaining problem is narrower than the original idea:

- some physical access leaves still materialize key vectors before adapting
  them back into a stream;
- intersection advances one child key at a time and cannot seek across sparse
  gaps;
- some covering, hybrid, ordering, distinct, grouped, and projection paths own
  rows or values before the final semantic boundary;
- convenient `Vec` boundaries obscure whether `LIMIT` can stop upstream work;
  and
- diagnostics report rows and bytes but do not yet make avoidable peak
  materialization or seek effectiveness obvious.

The first implementation patch must publish a complete, reviewed inventory.
This design names the classifications and contracts that inventory must use;
it does not assume every current `Vec` is defective.

## Materialization Classification

Every retained allocation in the maintained read executor must record one
primary reason:

| Classification | Meaning |
| --- | --- |
| `OUTPUT_BOUNDARY` | Owned rows or token bytes returned from the public page boundary |
| `SEMANTIC_BLOCKING_STATE` | Sort, distinct, grouping, deduplication, or other state required by query semantics |
| `BOUNDED_INPUT_CONTRACT` | A caller-supplied bounded list such as exact keys or `IN` values |
| `SMALL_STRUCTURAL_STATE` | Bounded planner/operator topology whose size is independent of row count |
| `TEST_OR_DIAGNOSTIC_ONLY` | Non-production state or bounded opt-in evidence |
| `AVOIDABLE_CONVENIENCE` | Ownership introduced only to connect two internal stages |

An allocation is not acceptable merely because it is capped. A cap provides
safety; the classification determines whether the work is necessary.

The primary reason is not a complete lifetime or memory-accounting model. Each
entry also records orthogonal properties:

- lifetime: current-row, operator, page, request, or persisted;
- size authority: fixed, query-shape bounded, caller-input bounded, or
  row-count dependent;
- backing ownership: compact owned value, borrowed row slot, shared payload
  owner, or reusable scratch storage;
- resumability: reconstructible, deterministically replayed, continuation
  encoded, or non-resumable blocking work; and
- accounting: logical bytes plus the complete unique backing allocation kept
  alive at peak.

`SMALL_STRUCTURAL_STATE` therefore cannot describe row-count-dependent child
discovery merely because every individual descriptor is small. Likewise,
`SEMANTIC_BLOCKING_STATE` does not permit a tiny borrowed slice to hide a large
retained payload owner.

The audit records, for each materialization point:

- canonical owner and function;
- data retained and maximum count/bytes;
- which semantic rule requires ownership;
- whether upstream `LIMIT`, cursor, or key pruning can stop it earlier;
- whether it causes row fetch, decode, clone, sort, or duplicate traversal;
- lifetime, backing-owner, replay, and peak-allocation properties;
- chosen action and measurement fixture; and
- whether removing it would change ordering, duplicate, missing-row, or cursor
  semantics.

## Maintained Stream Spine

### Concrete dispatch remains authoritative

`OrderedKeyStreamBox` remains the owned execution envelope. New hot-path
`Box<dyn Iterator>`, `Box<dyn OrderedKeyStream>`, async stream, or public stream
surfaces are prohibited.

Adding a new concrete stream variant is allowed only when it represents a real
physical operator with distinct state. Mechanical adapters must stay owner
local and bounded.

### Leaf outputs

The target output for each simple access leaf is:

| Access leaf | Target output |
| --- | --- |
| `ByKey` | zero/single key stream; bounded direct materialization remains acceptable |
| `ByKeys` | bounded canonical key input; sort/dedup may remain a bounded input contract |
| Primary range | resumable key stream |
| Exact index prefix/range | resumable key stream |
| Prefix family | merged concrete child streams, not one collected candidate vector |
| Full scan | resumable primary-key stream followed by late row loading |

Materialized exact-key inputs are deliberately not forced into a streaming
rewrite. They are already bounded by count and bytes and their sort/dedup is a
semantic input contract.

Prefix-family construction is admitted only after checking finite limits for:

- child-stream count and the product of multi-column fan-out;
- encoded child descriptors and bound-key bytes;
- merge-heap entries and retained heap bytes;
- construction/probe work before the first key; and
- cursor reconstruction work on every resumed page.

Count and byte arithmetic is checked before allocation. Max-plus-one input and
overflow return typed boundary errors. Child discovery whose size depends on
data rows is not `SMALL_STRUCTURAL_STATE` and cannot use this route without a
separate bounded paging design.

Patch 3 removes the eager prefix-family candidate-vector route. Prefix
families now construct concrete child streams only after a canonical 128-child
limit and checked descriptor/bound-byte accounting pass. A bounded merge heap
retains at most one decoded head per child and performs deterministic
direction-aware merge/deduplication in logarithmic child-count work. The
former row-count-owned `materialized_prefix_family` inventory entry is retired;
finite child descriptors, stream slots, and heap entries remain explicit
`SMALL_STRUCTURAL_STATE`.

## Seek Contract

0.222 adds an internal monotonic held-head protocol to maintained ordered
streams. The operation is named `seek_head_at_or_after` in this design;
`advance_to` is not used because it conflates positioning with consumption.

Conceptually, each child stream is in exactly one state:

```text
Unpositioned
Held(key, physical_progress)
Exhausted(final_progress)
```

`seek_head_at_or_after(target, work)`:

1. skips only occurrences that compare strictly before `target` under the
   stream comparator;
2. leaves the first qualifying occurrence as the unconsumed `Held` head;
3. returns that held head or exhaustion, but does not consume the held head;
4. is a no-op when `target` compares behind or equal to the current held head;
5. never moves backward relative to consumed or physically checkpointed
   progress;
6. produces the same remaining sequence as repeated pull-and-discard;
7. preserves duplicate occurrences until an owning operator deliberately
   deduplicates them; and
8. never makes a held occurrence appear again as a newly pulled occurrence.

`consume_head` removes exactly the held occurrence. `next_key` is defined as
ensure a head, return it, then consume it. The next pull advances strictly past
that physical occurrence, which may still yield an equal logical key when the
source contains duplicates.

Direction is defined by traversal order, not by numeric terminology:

| Direction | Current head | Target | Result |
| --- | ---: | ---: | --- |
| ASC | 20 | 10 or 20 | hold 20; no movement |
| ASC | 20 | 30 | skip before 30; hold first key >= 30 |
| DESC | 20 | 30 or 20 | hold 20; no movement |
| DESC | 20 | 10 | skip before 10 in DESC order; hold first key <= 10 |

Every ensure, seek, and consume boundary distinguishes four outcomes:

- held head or exhausted;
- successful page-envelope stop with strictly reconstructible progress;
- hard-budget failure with no partial page; and
- typed corruption/internal failure.

Partial work before a hard or corruption failure remains charged. A live
stream comparator or accepted-authority mismatch is an internal error; an
authenticated resume token that names incompatible semantics is rejected by
the existing cursor-validation boundary before stream construction.

A stream may implement seek as repeated pulls in the reference adapter, but
only physical leaves with a proven range jump may claim seek savings. Charging
includes bound construction, B-tree path probes, comparator work, decoded
keys, cursor repositioning, leaf entries actually visited, and any replay.
Diagnostics distinguish logical occurrences skipped from physical leaf visits
and storage probes. Hard-budget checks remain inside potentially long access
loops rather than only around the outer seek call.

The seek contract is internal and current-form only. No persisted or public
cursor token field is added merely to expose it.

Patch 2 implements this contract as an owner-local
`RepeatedPullHeldHeadKeyStream`. One pull attempt, monotonicity validation, and
publication of its held/exhausted state form the indivisible reference unit;
page stop occurs only before that unit begins. The adapter preserves duplicate
occurrences, rejects entity or ordering drift, keeps failed work charged, and
retains a held head when accounting fails before consumption. It records pull
attempts, comparisons, skipped occurrences, and total consumed occurrences
with checked arithmetic.

This is deliberately a semantic oracle rather than an optimization. It calls
the existing destructive `next_key` repeatedly, exports no planner capability,
and claims no B-tree, storage, decode, or instruction savings. Patch 3 must
prove each physical leaf equivalent to this adapter before replacing the
reference path or claiming physical seek capability.

Patch 3 supplies the first physical implementations. Primary ranges advance
their raw data-store bounds directly; eligible exact index-prefix leaves build
a new raw bound from the frozen prefix plus the target primary key. Both charge
cursor repositioning and bound bytes, preserve the first qualifying key as the
held unconsumed head, and fall back to repeated logical progress when a finite
window means a physical jump could change offset/limit semantics. Physical
index seek is admitted only when accepted route facts prove primary-key suffix
order. These leaves remain planner-internal building blocks: Patch 3 does not
make multi-index intersection eligible.

## Intersection Contract

The existing `IntersectOrderedKeyStream` remains the key-intersection owner.
0.222 makes it seek-aware for sparse overlaps.

An intersection route is eligible only when:

- every child yields the same entity identity;
- child output has compatible canonical primary-key ordering;
- direction is identical;
- each child predicate is completely represented by its index access contract
  or remains correctly present as a residual;
- the accepted runtime root proves every participating index current and
  planner-visible;
- every nonterminal operator state has a written proof that it can be
  reconstructed by the current logical boundary and physical primary-key
  anchor without skipping results, unbounded replay, or repeated
  no-progress pages;
- cursor feasibility is established before the route is costed; and
- estimated and hard-budgeted work is finite.

The algorithm selects the child head furthest ahead in stream order and seeks
every child whose head compares before that target under the shared comparator.
A key is emitted once only when all children agree. Empty and exhausted
children terminate immediately.

| Direction | Held heads | Alignment target |
| --- | --- | ---: |
| ASC | 10, 20, 30 | 30 |
| DESC | 30, 20, 10 | 10 |

Before planner eligibility is added, the continuation proof must cover every
interruption point:

- before and after each initial child pull;
- during and immediately after a physical seek;
- while children hold divergent heads;
- after all heads agree but before row/residual evaluation;
- after emission but before child consumption;
- after residual rejection;
- during lookahead; and
- page-envelope exhaustion with no emitted output.

Every successful continuation must either return a row or advance a monotonic,
route-specific progress rank. Replaying from the last emitted row is acceptable
only when the proof bounds that replay and proves a subsequent empty page
cannot return the same rank. Cancellation may discard in-memory state; it must
not manufacture a successful continuation from an uncheckpointed child seek.

Patch 1 records the proof matrix and Patch 2's reference protocol supplies its
interruption tests. Patch 4 must not make intersection planner-visible until
the matrix passes. If one logical boundary and physical anchor cannot represent
the required rank, stop the patch and design a bounded, versioned per-child
operator continuation as a separately reviewed current-form hard cut. No
compatibility decoder is permitted.

0.222 does not add general multi-index planning merely because the executor can
intersect streams. The planner must compare one accepted index, a compound
index, and an eligible intersection using deterministic integer costs from a
documented authority. Accepted schema/index structure and exact maintained
metadata are valid facts; unversioned estimates, opportunistic sampling, and
unsupported selectivity guesses are not. Any persisted statistics must bind
database incarnation, accepted-root generation, index identity, and their own
freshness generation.

When trustworthy cardinality facts are unavailable, selection is conservative:
exact compound prefix, then a selective single accepted index, then
intersection only when hard structural facts prove a benefit, then
primary/full traversal. Deterministic ties prefer the simpler single route.
A compound index remains preferable unless an eligible intersection is
demonstrably cheaper. Supporting intersection in the executor is never itself
cost evidence.

Patch 4 uses no estimated cross-index selectivity. Synchronized exact-prefix
cardinalities must first prove that every participating child and their checked
sum fit one fixed atomic-intersection envelope. The executor may then perform
one exact bounded overlap probe over the concrete child streams. This is a
complete traversal of the admitted candidate set, not sampling; its work is
charged and included in the integer cost comparison. The probe retains only
the exact overlapping primary keys in one fixed-cap execution buffer, and that
buffer becomes the selected execution stream. It never retains rows, payloads,
or projected values. Admission proves both the maximum key count and maximum
encoded-key/backing bytes before allocation; every retained key byte and vector
slot is charged. This bounded key exception avoids rescanning every child after
the exact proof has already performed the same physical work.

The atomic envelope makes every intermediate held-head state non-publishable:
completion, hard failure, or cancellation occurs inside one page unit, and no
successful page stop is permitted between child pulls or seeks. Therefore the
existing emitted-row continuation remains sufficient and no operator cursor
format is added. Unknown, stale, overflowing, over-cap, or changed cardinality
authority rejects the intersection candidate and executes the conservative
single-index route with the complete residual predicate intact. Exact compound
access is selected before this candidate is formed and always wins ties.

## Row Loading And Borrowed Evaluation

The row runtime remains the single payload owner after key pruning.

For each surviving key:

```text
key
  -> at most one stored payload read
  -> one bounded structural row reader
  -> lazy accepted-kind validation by required slot
  -> borrowed residual/order/group/projection access
  -> owned output only if emitted or retained by a semantic blocking operator
```

Requirements:

- rejected index candidates fetch no row;
- residual rejection fetches at most one row and does not materialize unrelated
  fields;
- filter, ordering, grouping, distinct, and projection reuse one slot cache;
- a filtered-out row never becomes an owned public entity or output tuple;
- returned rows keep the existing owned public DTO and Candid shape; and
- nested values remain bounded and fallible.

Borrowed slots are valid only while their row payload owner is alive and has
not been reused. No reference crossing a blocking boundary may point into a
reused scratch buffer. A blocking operator must choose one of two charged
representations:

1. compact owned canonical keys plus the minimal owned output fields required
   to avoid rereading a winning row; or
2. an explicitly bounded payload owner/handle, charged by the complete unique
   backing allocation kept alive rather than by the visible borrowed slice.

A 20-byte borrowed order value that retains a 300 KB payload therefore counts
as 300 KB of retained backing memory. Retaining only a primary key and rereading
the winning payload during the same execution is not compatible with the
one-payload-read contract. Aliases to one backing allocation are deduplicated
for byte totals but its full lifetime contributes to peak retained bytes.

Recursive list/map values may remain owned if every legal consumer requires an
owned `Value`. A borrowed nested visitor is permitted only after the audit
proves a real retained-byte or instruction win while preserving recursive
depth, collection bounds, accepted-kind validation, and deterministic map
semantics.

Patch 5 settles the ordinary scalar ownership boundary as follows:

- cursor-emitting non-field-path projections retain only the compiled
  projection/order/index-anchor slots; cursor construction does not require
  the complete raw row to survive the current-row decode;
- model identity, nested field-path projection, and outward entity-row
  consumers retain raw payloads because their output semantics require them;
- ordinary non-`DISTINCT` projection creates each final owned value row once,
  with no reusable borrowed `RowView` followed by a second deep clone;
- `RowView` is now an owned-only blocking transport reserved for `DISTINCT`,
  whose global pagination contract remains assigned to Patch 7; and
- hybrid covering projection holds compact `(slot, value)` entries, compiles
  last-use ownership once per query shape, and moves a value on its final use
  instead of rebuilding per-row maps or cloning its backing unnecessarily.

## Page And Early-Termination Contract

The page builder is the ordinary ownership boundary. A streamable scalar query
must stop as soon as it has:

- satisfied the initial offset;
- emitted the total/page limit;
- performed the bounded lookahead required to prove or preserve continuation;
  or
- exhausted its page work envelope.

It must not collect the remaining candidates to prove exhaustion. An empty page
with continuation remains valid when physical progress was made without a
matching row.

Page work is charged through one primitive that makes separate decisions for
the hard execution budget and the page work envelope. Predictable units are
precharged. An unpredictable unit must be a bounded framed operation with
checks inside its loop. Counter arithmetic is checked and request-cumulative
hard charges are never replaced by page-local totals.

The production scalar path treats candidate inspection and output emission as
separate indivisible units. Candidate inspection starts before the access
stream is polled and covers the complete bounded physical pull, row read,
decode, retained-slot work, and residual evaluation. Every admitted stream
shape must publish a finite per-pull access bound; a missing proof is an
execution invariant failure, not permission to bypass the page envelope.
Page-aware physical leaves may reduce their refill size to make that proof
true. Projection, response-value materialization, and result bytes belong to
the later emission unit, and an inspection receipt must never be presented as
proof that emission was admitted.

The engine does not grant an unbounded first-unit allowance. If one storage
entry, row, ordering tuple, or cursor component cannot fit into an otherwise
empty page envelope while remaining below the hard safety limit, execution
returns a typed `PageWorkUnitTooLarge` failure identifying the resource and
bounded unit. It must not return an unchanged continuation. Headroom for the
typed failure, cursor, page metadata, and final IcyDB result encoding remains
reserved from the hard budget.

A successful empty page is legal only when its authenticated continuation has
a strictly greater monotonic progress rank than the input continuation. A
non-null continuation means exhaustion is not yet proven; it does not promise
another matching row. Returning the same successful empty-page continuation is
an invariant failure.

Lookahead uses the same held-head rule as intersection. A qualifying lookahead
row is either left unconsumed at a reconstructible frontier or represented by
already authenticated continuation state. The physical anchor never advances
beyond an unreturned match.

Semantic query `LIMIT`, offset/window, order, and comparison authority remain
bound by the continuation. The operational `PageWorkEnvelope` may change on
resume within the approved profile because it controls work per call, not
result semantics; the formal progress rank must be envelope-independent.
Changing an output/query window is rejected as the existing typed cursor/query
mismatch. Any operator that requires an identical envelope to reconstruct
state is ineligible under the current cursor format.

The public page `work` receipt reports the page-local charged delta. The root
request scope retains request-cumulative hard counters, including failed work,
across every session in that call. A new approved request boundary receives a
new root; resuming a cursor never resets counters inside the current request.

0.222 preserves the existing distinction between live keyset pages, which see
current data under their documented mutation semantics, and revision-strict
exhaustive pages, which compare their read-set proof. An optimized route must
not silently strengthen or weaken either contract.

Safe `LIMIT` pushdown requires a proof that no later operator can change
membership, multiplicity, or order. It is allowed through an already-satisfied
access order and forbidden through unresolved residual filters, distinct,
grouping, incompatible ordering, or multiplicity-changing operators unless a
specialized rule proves equivalence.

Patch 6 settles scalar termination and ordering ownership as follows:

- when the selected route already satisfies final scalar order, the row scan
  stops after residual evaluation has produced exactly `offset + limit`
  matches; the access stream is never truncated before an unresolved residual
  predicate decides membership;
- one-shot reads perform no speculative lookahead, while cursor-emitting pages
  retain exactly one qualifying lookahead; `LIMIT 0` reads no candidate rows;
- a resumed secondary-order route remains uncapped until its current cursor
  can physically reconstruct that route's progress. Primary-key continuation
  binds the authenticated primary-key boundary into the raw range before the
  page-local fetch hint is applied, without changing cursor format;
- incompatible-order projections retain only compact canonical order/tie and
  required output slots. Full-entity output retains complete payloads only for
  the bounded winning window, and charges those backing bytes in full;
- complete sorts remain complete blocking routes, while bounded top-N owns at
  most its semantic winner/lookahead count; and
- every ordering candidate is charged monotonically before it crosses the
  blocking boundary, so an unrelated later row-read failure cannot refund
  already completed sort work.

## Blocking Operators

Blocking state is explicit, bounded, charged, and minimal.

### Ordering

- Access-compatible ordering performs no explicit sort.
- `ORDER BY ... LIMIT N` uses the existing bounded top-N route when eligible.
- Retained state owns compact canonical order keys, deterministic tie-break
  values, and the minimal owned projected output needed to avoid a winner
  reread. It never retains an uncharged borrowed row reference.
- Full-row sort remains legal only when the requested expressions cannot be
  evaluated or replayed from smaller retained state.

### Distinct

- Ordered adjacent distinct is legal only when input order makes equal complete
  canonical distinct keys contiguous. It resumes from a proven source frontier
  plus the last distinct key and deterministic representative order tuple.
- Global or unordered distinct completes a bounded blocking build before any
  page is emitted. Under the current no-new-persisted-state scope it may
  deterministically replay that build for later pages, but may not forget the
  seen set between physical pages or emit partial results from an incomplete
  build.
- Hidden ordering fields and the primary-key tie-break participate in choosing
  one deterministic representative. A projected distinct key alone is not a
  sufficient continuation boundary when representatives can differ.
- Retained keys and winner output are compact canonical owned state. Do not
  retain a full source row solely to decide duplicate membership.
- Page continuation binds the distinct strategy, source frontier, normalized
  window, representative ordering, and tie semantics.

Patch 7 settles that contract without a cursor-format or SQL-grammar change:

- model-identity projection is adjacent-safe because primary-key identity makes
  duplicate rows impossible; a direct projection is adjacent-safe only when
  its complete projected-slot equivalence tuple is the leading resolved order
  prefix before any hidden order slot;
- adjacent execution owns one canonical current-group key and does not publish
  its representative until a different key or exhaustion proves the group
  closed. Its continuation boundary is the final source row in that closed
  group, so a lookahead from the next group is re-read rather than skipped;
- global execution scans to exhaustion, retains the complete bounded canonical
  key set, and owns projected output only for the requested window. A later
  page deterministically rebuilds the set and skips the authenticated count of
  completed output rows;
- the maintained continuation signature already binds DISTINCT, projection,
  resolved order, query window, and accepted-root identity. Strategy selection
  is a deterministic consequence of that bound contract; and
- current public dynamic-query grammar remains unchanged. The executor owns
  resumable DISTINCT progress for maintained internal callers, while the
  existing SQL surface continues to execute one-shot DISTINCT through the same
  two strategies.

### Grouping and aggregates

- Ordered grouping may emit only a group proven closed by contiguous input
  order. Interruption inside a group must replay from a bounded group-start
  checkpoint or use continuation-encoded state; it may not emit the group
  early.
- Hash grouping completes its bounded aggregate build before page emission. It
  may deterministically replay across page calls under current formats, but it
  cannot suspend by discarding its aggregate table or return partial groups.
- `COUNT(*)`, index-edge `MIN`/`MAX`, and existence-like shapes must not load
  rows when accepted index coverage proves they do not need them.
- Group state owns only canonical group keys, aggregate accumulator state, and
  compact fields required by `HAVING`/output/order. Borrowed current-row slots
  never survive into the next input row.
- A route that cannot prove closed-group output, bounded replay, and monotonic
  continuation progress remains a complete blocking route; 0.222 does not add
  persisted aggregate state implicitly.

Patch 8 settles that contract without a cursor-format or SQL-grammar change:

- ordered execution owns one canonical active group, never emits it before a
  key transition or exhaustion proves it closed, and resumes through the
  maintained source boundary rather than persisting a partial accumulator;
- hash execution consumes its complete bounded input and owns the complete
  canonical aggregate table before it emits any group;
- both strategies charge group-key and accumulator backing; hash routes also
  precharge conservative table, collision-vector, and output-capacity
  reservations before fallible allocation, while grouped top-K separately
  charges every owned key, aggregate, and order value crossing the blocking
  boundary;
- diagnostics expose peak estimated grouped-state bytes alongside live group
  and state counts; and
- scalar aggregate `DISTINCT` uses stable hash buckets with exact collision
  equality instead of linearly rescanning every retained value on admission.

Patch 1 froze the ordered fixture without a predicate and the hash fixture
without a SQL `LIMIT`; later patches may not replace either SQL statement with
a friendlier measurement. The ordered query must select the accepted
`(group_key, id)` index because trailing tie-break fields preserve grouped-key
contiguity. SQL has no grouped-work-budget syntax, so SQL lowering attaches one
planner-owned conservative ceiling of 10,000 groups and 16 MiB of complete
grouped state. This ceiling is a hard error boundary, never a truncation limit.
A canonical group-key order may omit a result-row `LIMIT` only when both hard
limits are finite and non-zero; aggregate-driven top-K ordering still requires
an explicit row `LIMIT`. The frozen no-`LIMIT` hash query therefore completes
under finite state authority without changing its text. Public dynamic grouped
queries continue to require explicit `grouped_limits`, and operator-local
exhaustion preserves the active execution scope, lane, and normalized query
shape in typed `ExecutionBudgetExceeded` diagnostics.

No patch may combine ordering, distinct, and grouping rewrites unless the
materialization audit proves they share one owner and one reviewable contract.

## Budgets, Progress, And Failure

All new work uses the 0.221 hard execution and page-envelope contracts.

The maintained counters must cover:

- child keys pulled;
- seek calls, bound/range construction, B-tree path probes, comparator steps,
  decoded keys, cursor repositioning, and physical leaf entries visited;
- logical keys skipped by seek;
- candidate keys before/after intersection;
- rows fetched;
- stored and decoded bytes;
- structural slots validated/materialized;
- retained blocking entries and peak retained bytes;
- rows owned before the output boundary; and
- cursor/lookahead work.

Hard-budget exhaustion returns the existing typed execution-budget failure and
no partial page. Page-envelope exhaustion returns successful progress plus a
continuation. Failed attempts and seeks are not refunded.

The guarantee remains limited to maintained charged IcyDB work. Arbitrary
application work and final endpoint encoding remain outside the engine claim.

### Persisted access corruption

Late row loading and physical seek must not turn inconsistent accepted indexes
into ordinary filtering or exhaustion. The following are typed persisted-index
or storage-corruption failures:

- an accepted index key whose primary row is missing;
- a malformed index tuple or a tuple incompatible with accepted field kinds;
- an index key whose embedded entity/primary key disagrees with the row;
- a source that violates its declared stream order; and
- heap and journaled authority disagreeing for the same accepted progress.

The executor never hides these cases through a fallback scan or residual
rejection. All work completed before discovery remains charged. Planner/runtime
authority mismatches that are not persisted corruption remain typed internal
errors rather than panics.

Ordinary absence from an exact primary-key lookup is not corruption. A
composite union that contains both exact-primary and accepted-index branches
therefore removes absent exact-primary candidates before its final strict row
boundary. A key that reaches that boundary through an accepted index still
owes authoritative row presence. This provenance-preserving step is bounded
and charged; it must not turn a normal missing point lookup into an error.

## Diagnostics And Explain

Feature-gated diagnostics remain bounded, redacted, charged, and fail-soft.

0.222 adds enough evidence to answer:

- Did the route materialize candidate keys before streaming?
- How many keys did each child pull?
- Did seek skip logical keys without visiting them physically?
- How many candidates survived intersection?
- How many rows were fetched, decoded, owned, and returned?
- What was peak blocking-state size?
- Which semantic boundary required the retained state?

Explain output may name the selected physical operator and blocking boundary,
but diagnostics must not change route choice or successful query semantics.

## Public And Persisted Contract

The intended 0.222 line is internal and additive:

- no SQL grammar change;
- no public query iterator;
- no successful page/result shape change; the typed
  `PageWorkUnitTooLarge` terminal error is current-form safety behavior;
- no accepted-schema or generated-model authority change;
- no persisted row, index, journal, proof, progress-record, or cursor-format
  change; and
- no compatibility decoder or legacy execution path.

If implementation discovers that a correct intersection resume requires a new
cursor format, that is a new independently reviewable outcome. Stop and update
the design/tracker before changing the format.

Current continuations remain route-independent: they bind normalized query,
ordering/window, envelope profile, accepted authority, and logical/physical
progress, but not an optimizer choice merely for cache convenience. An
intersection is eligible only if those fields reconstruct it safely. If
per-child operator state becomes necessary, the reviewed format change must
bind route kind, participating index identities and generations, comparator,
and every bounded child checkpoint; it cannot be smuggled into an opaque field
without updating the contract.

## Cross-Patch Acceptance Matrix

### Access and seek

- every maintained access leaf produces a concrete key stream or is documented
  as a bounded exact-input exception;
- randomized seek is monotonic, direction-correct, charged, and
  output-equivalent to repeated pulls for ASC/DESC, duplicate keys, and targets
  behind, equal to, or ahead of a held head;
- a held head is consumed exactly once, and cancellation or interruption after
  a physical seek cannot publish uncheckpointed progress;
- heap and journaled sources produce identical logical keys and continuations;
- prefix-family child count, descriptor/bound bytes, merge heap, construction,
  reconstruction, max-plus-one, and overflow limits are enforced before
  allocation; and
- no hot path reintroduces trait-object stream dispatch.

### Intersection

- all children share accepted entity/index authority and compatible primary-key
  order;
- sparse intersections skip work without skipping results;
- duplicates emit once and residual predicates remain correct, including a
  match rejected after all heads align;
- ASC and DESC two/three-child routes pass injected interruption at every pull,
  seek, divergent-held-head, aligned-head, residual, emit, and lookahead state;
- every successful empty page advances the formal route-progress rank;
- cursor feasibility precedes costing, and deterministic conservative costing
  makes a compound index beat a merely tempting intersection; and
- continuation after divergent heads, empty pages, lookahead, and page-envelope
  exhaustion is complete and deterministic or the route remains ineligible.

### Row access and materialization

- rejected index candidates fetch zero rows;
- every remaining candidate fetches its payload at most once;
- filtered-out rows validate/decode only required slots and never become owned
  output rows;
- returned pages own exactly their output plus required cursor state; and
- a tiny borrowed key cannot hide a retained large payload or reusable scratch
  reference;
- missing rows, malformed tuples, order inversion, and accepted key/row
  disagreement return typed corruption rather than exhaustion/fallback; and
- every retained allocation records a primary semantic reason plus lifetime,
  size, backing-owner, resumability, and finite byte/count bounds.

### Blocking operators

- access-compatible order avoids sorting;
- top-N state is bounded by N plus deterministic tie/lookahead requirements;
- ordered distinct stores compact canonical keys while global distinct proves
  a complete bounded build across multiple output pages;
- ordered grouping emits only closed groups while hash grouping proves a
  complete bounded build; repeated groups far apart never split output;
- hidden order values and representative tie-breaks remain deterministic;
- blocking state owns compact values and charges complete backing allocations;
  and
- state exhaustion returns a typed budget error before uncontrolled allocation.

### Safety and authority

- accepted schema/runtime root remains the only execution authority;
- request counters cannot be reset by sessions, retries, or nested calls;
- page work and hard failure remain distinct;
- exact hard/page thresholds, oversized first units, and counter overflow have
  typed outcomes;
- a changed work envelope preserves results/progress, a changed semantic query
  window is rejected, and a successful empty page cannot repeat its input
  cursor;
- live and revision-strict mutation semantics remain distinct;
- diagnostics are bounded, redacted, charged, and fail-soft; and
- no public or persisted format changes without a tracker update and explicit
  review boundary.

`prefix_family_max_fanout`, `intersection_2_sparse`,

primary-key limit are already bounded controls; seek value is measured through
intersection alignment rather than by requiring an artificial standalone win.

`point_get_control`, `ordered_empty_scan_control`, and
`dense_full_return_control` use 1% as a review threshold, not an automatic
failure. Small absolute counts, measured toolchain variance, or newly correct
charging may justify movement when the evidence is recorded. No performance
gate permits weaker correctness, progress, or accounting.

## Non-Goals

- A public `query_iter`, `Stream`, or borrowed result API.
- Joins, semi-joins, anti-joins, or new SQL grammar.
- A general vectorized or analytical execution engine.
- Unbounded batches, sort state, distinct state, groups, caches, or diagnostics.
- Snapshot isolation or historical-version replay.
- New persisted cursor/proof/progress formats.
- Rewriting bounded direct `get_many` input semantics as a stream.
- Automatically creating compound indexes from planner evidence.
- Implementing Toko's batch context, schema index, or application validation.
- Zero-copy nested collections without an evidence-backed bounded consumer.
- Compatibility aliases, dual execution, or legacy cursor decoding.
