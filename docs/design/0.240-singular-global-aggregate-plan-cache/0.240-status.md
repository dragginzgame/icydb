## Assignment

The user explicitly requested selection of a 0.240 design focused on reducing
code complexity, raw Wasm and query cost. The selected outcome is the smallest
current convergence opportunity with direct evidence: replace the SQL global
aggregate command's separate prepared-plan and exact-count cache slots with one
fingerprint-bound exact-or-prepared cache entry.

The user explicitly authorized implementation against the validated but
unpublished 0.239.1 candidate. It remains the exact predecessor; no version
bump, commit, tag, release or publication is authorized.

The first design review approved the direction but held implementation until
prepared-fallback and populated-`OnceLock` ownership were explicit. The design
now names the existing registry-scoped `QUERY_PLAN_CACHES` owner and its full
freshness key, prohibits nested or direct ephemeral fallback caches, and names
`SQL_COMPILED_COMMAND_CACHES` as the new-command owner after publication.

## Opening Evidence

- `CompiledSqlCommand::GlobalAggregate` currently carries both `plan_cache`
  and `count_plan_cache` `OnceLock` slots.
- The flow has separate prepared and exact-count cache-entry types plus
  measured/unmeasured direct-count resolution branches. The design now lists
  the exact fields, types, accessors, helpers and branch families to remove.
- The six principal session/cache files in scope contain 1,515 lines; this is a
  discovery signal, not a deletion target.
- Retained 0.237 performance evidence places optimized 2,048-row exact counts at
  815,629–854,348 instructions and a true-warm count at 731,475 instructions.
- The controlled 0.239.1 predecessor build reproduced a final SQL audit Wasm
  of 8,204,964 raw bytes with SHA-256 `66c4061888838261483bd55d40ce01333199bba79e5e70eebc550312bbd8a82a`.
- Prepared fallback already belongs to `QUERY_PLAN_CACHES`, keyed by registry,
  entity, complete accepted-schema identity, visibility and structural query;
  cardinality lifecycle stamps receive an additional hit-time freshness check.
- `SQL_COMPILED_COMMAND_CACHES` keys commands by the complete accepted schema
  identity and raw SQL, so publication creates a new empty command rather than
  replacing a populated inner `OnceLock`.

## Implementation Evidence

- `CompiledSqlCommand::GlobalAggregate` now owns one `OnceLock` entry.
- The entry contains either an exact entity/index-prefix target or a prepared
  shared plan; the separate count entry, measured-only outcome type and
  prepared-plan resolution wrapper are removed.
- An exact entry whose metadata is unavailable still reaches only the existing
  shared query-plan cache for fallback.
- The owner-local proof covers exact and prepared entry installation,
  fingerprint rejection and immutable occupied-slot behavior.
- Warning-denied no-default, SQL-only, SQL+diagnostics and all-feature package
  checks pass.
- Focused cardinality lifecycle tests and the cache-owner test pass.
- At 2,048 rows the four exact cold queries improve by 192–203 instructions;
  true-warm improves by 6, with unchanged zero row/index work.
- Candidate final raw Wasm is 8,196,454 bytes, 8,510 bytes below the
  predecessor; deterministic gzip is 2,479 bytes smaller. A repeat reproduces
  the exact raw size and SHA-256 `37c420b19444a996ff831896df1920e1a857174cfeb051bae354186111b0de9c`.
- Isolated predecessor comparison keeps ordinary aggregate cold/warm deltas
  between -33,411 and +29,995 instructions; the largest regression is 0.026%.
- Unavailable-metadata fallback, Ready publication, live maintenance and
  same-Wasm recovery pass their focused PocketIC proof.
- Persistent unavailable fallback now proves one shared-plan miss followed by
  one shared-plan hit with identical 512-entry physical work. Cold/warm costs
  regress by only 0.058%/0.251% against the exact predecessor, below the frozen
  5% gate.
- Candid is byte-identical and the normalized 70-method export set is
  unchanged. No stable-memory owner or format was touched.
- Production cache slots fall from two to one, production types fall by three,
  and the production SQL runtime is net 22 lines smaller.
- A closeout attempt to carry the prepared plan directly in the transient
  target was reverted after it increased final raw Wasm by 15,761 bytes over
  the selected implementation.
