# 0.256 slice 3 — Owned generated decoding

## Outcome

The existing generated row decoder consumes fields rather than borrowing values
that it then copies. Scalars and nested collections, records, tuples and enum
payloads use one owned model-adapter contract. Accepted bindings, source lookup,
field evaluation order, exact record membership, tuple arity and typed errors
remain the semantic owners. Saved-row decoding remains after publication.

Record output now reorders the existing map entries into accepted member order.
Equal cardinality, unique requested names and a successful match for each name
establish an exact permutation before any member is decoded. Duplicate requested
names are checked against the already visited prefix; no temporary tree or
optional-value buffer remains. Worst-case member matching stays quadratic.

Row extraction replaces its scratch slot with NULL after binding/field checks;
generated code requests each field once and then drops the row. No second row
buffer, decoder route, runtime configuration, cache or persisted state is added.
Ordinary generated query/write call sites are unchanged. Handwritten low-level
output adapters/context implementations must adopt owned values, and handwritten
row adapters use `take_row_value`; this is a hard cut without compatibility aliases.
Neither Toko Miner nor Toko was edited, built or deployed.

Baseline production source: published `v0.255.3`, commit
`70bb74b3c743c7be09289c20078c19da69521ad5`. Earlier 0.256 changes affect only
documentation and an enrollment compile fixture. Both variants build sequentially
at the same isolated source path using Rust 1.97.1 and the same locked dependencies.
Cargo.lock SHA-256:
`daae20b35f6d7cafde57f7e2c34f9718d1531649fd6e7af97a944afb185dee08`.

The one-entity typed actor uses the maintained production `wasm-release` pipeline,
SQL off, Candid export off and the build policy's U256 reachability. Identical
temporary seed/read update endpoints make cycle debits observable. These endpoints
and the native allocation probe exist only in the isolated source, not the repo.
The probe uses OneSimpleEntity01, not U256. These are instrumented actor deltas,
not a measurement of either application or every maintained actor.

Predeclared ceilings: fewer allocation requests/bytes for heap-bearing decoding,
at most +1 KiB final raw Wasm, +4 defined functions and +1% cycles per control.
The first implementation missed the Wasm gates (+1,716 raw bytes/+6 functions).
Removing the intermediate optional-value buffer brought it to +1,135 bytes/+3
functions, still above the byte ceiling. Removing the temporary name tree at the
same record owner produced the final smaller artifact below. No ceilings changed.

Initial harness errors (an unsupported fixture default, allocator lint and direct
invocation of a non-executable shell script) were corrected. A zero-test native
run caused by shared-target reuse is explicitly excluded. The valid native
baseline was rebuilt from the isolated sources, with affected owners recompiled;
subsequent variants were built sequentially there without concurrent native
validation. Logs preserve rejected attempts separately. The local PocketIC server
needed permission to bind loopback outside the sandbox.

## Native allocations

Three samples agree exactly at 1/64/256 rows for both shapes. Row creation, writes
and accepted projection preparation are outside the measured region. Measurement
covers generated row decoding, result-vector construction and consumed scratch
cleanup, not the full database operation. Counts include allocation/reallocation
requests and cumulative requested bytes, not peak memory or elapsed time.

Both shapes have a 512-character name plus row-specific prefix. Nested rows also
have four records, each containing a 64-character label, a weighted enum and a
64-character optional note. Representative 256-row results:

| Shape | Allocation requests before → after | Requested bytes before → after |
| --- | ---: | ---: |
| Text with empty profile list | 257 → 1 | 153,490 → 20,480 |
| Text with nested profiles | 6,657 → 1,281 | 669,586 → 135,168 |

The remaining text-only allocation is the final typed-row vector. Nested Rust
containers and accepted-name lookup still allocate; this is not allocation-free.
The allocation gates pass for both shapes at every measured size.

## End-to-end cycles

All 432 measured reads return the expected results. The 72 control groups have
three exactly agreeing samples per variant. Both text-only and nested fixtures
cover 1/64/256 positions, unique present keys, repeated present keys, mixed
present/missing keys, repeated missing keys, unique missing keys and single get.
Each variant/workload gets a fresh installation; its first read and repeated
warm read are recorded separately, alternating variant order between samples.
Setup writes and installations are outside the cycle debit measurement.

| Unique 256-position read | Baseline cycles | Final cycles | Delta |
| --- | ---: | ---: | ---: |
| Text, cold | 219,121,254 | 219,235,976 | +0.0524% |
| Text, warm | 238,357,345 | 238,001,361 | −0.1493% |
| Nested, cold | 309,009,670 | 311,379,618 | +0.7669% |
| Nested, warm | 330,696,252 | 332,390,086 | +0.5122% |

The largest decrease is 0.4944% (warm 64-position unique-missing control in the
text fixture); the largest increase is 0.8614% (warm 64-row unique-present text
read). Every +1% cycle ceiling passes without an exception. Allocation savings
are not a universal cycle improvement: in particular the large nested read is
slightly more expensive. No decoder-only IC instruction attribution is claimed.
The maintained wrapper started/stopped one temporary PocketIC 16.0.0 server;
the successful measurement command took 189 seconds. Existing networks were
untouched.
