# IcyDB 0.213 Application-Behavior Classification

Status: implemented boundary and complete disposition inventory; physical move
to `icydb-model` remains part of the final Patch 6 hard cut.

## Authority Rule

Application normalization and validation are explicit Rust operations. IcyDB
write admission, SQL, structural writes, commit replay, recovery, and integrity
inspection never invoke them. Accepted schema remains the sole database owner
of durable defaults, generation, management, and constraints.

The public spelling is `normalizer`; `sanitizer` is removed rather than
retained as an alias. Generated callback-presence profiles are also removed
because the database no longer branches on application behavior.

Existing opaque `source_key` literals retain their authored bytes even when
their text contains the former source-directory name. They are immutable
identity, not a callable spelling or compatibility path; rewriting them during
the file move would replace the declaration instead of renaming its source.

## Behavior Implementation Disposition

| Current family | Disposition |
| --- | --- |
| `normalizer::text::{Trim, ascii::*, case::*, color::*}` | explicit application normalization |
| `normalizer::intl::{iso::*, phone::*}` | explicit application normalization |
| `normalizer::web::*` | explicit application normalization |
| `normalizer::num::{Clamp, RoundDecimalPlaces}` | explicitly selected application conversion; never automatic database coercion |
| `validator::{bytes, hash, intl, text, web}` | application validation unless and until a separate frozen accepted constraint can represent the exact rule |
| `validator::len::*` | replace durable uses with accepted length constraints; do not generate a second evaluator |
| `validator::num::{Lt, Gt, Lte, Gte, Equal, NotEqual, Range, MultipleOf}` | replace durable uses with accepted check expressions; retain only genuinely application-specific use |
| `validator::decimal::MaxDecimalPlaces` | accepted decimal field-kind/scale authority; no generated database-rule mirror |
| `validator::collection::InArray` | application validation; it is not the accepted enum-membership contract |

## Maintained Boundary Evidence

- Database save preflight consumes the already resolved accepted after-image and
  never normalizes or validates a generated entity.
- Typed and structural writes therefore persist the same accepted bytes as SQL
  for equivalent input.
- Commit recovery replays resolved bytes and cannot invoke application
  behavior.
- `MutationMode` and the operation timestamp now live in a database-owned
  accepted-write context that application visitors cannot observe.
- A layer-authority guard rejects application normalizer/validator traits from
  production database modules.
- Renamed fixtures preserve their pre-move source-key bytes.
- The remaining Patch 6 work may move these declarations and delete generated
  persistence adapters, but it must not restore automatic callback execution.
