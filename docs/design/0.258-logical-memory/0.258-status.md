## L1 findings

- `ic-memory 0.13.3` already owns keys, history, range policy, persistence and
  committed capabilities. It still requires explicit IDs for declarations/opens.
- Extend that owner; do not build a parallel allocator inside IcyDB.
- Allocation absence differs from IcyDB store retirement. Preserve journal and
  pending-marker safeguards; do not promise removable/reintroducible stores.
- Pre-allocation ledger/history bounds, host pool grants and populated-memory
  identity admission need evidence before the macro/API cut.
- L1 implementation changes: none. No application/dependency edits,
  network lifecycle actions, Cargo version changes, commits or pushes.
- Validation: repository invariants, changed-document local file links and
  whitespace checks pass. No runtime tests or performance probes were run for
  this documentation-only slice; full release validation remains user-owned.

## Completed L3 qualification

Direct-upgrade fixture decision: use one test-only generated actor with a single
`omit-retiring-store` build choice. Existing unit substitutes cannot establish
generated historical-journal access after upgrade; existing maintained actors do
not remove a store. The fixture uses normal typed writes and the generated driver,
with timer delivery controlled by the test. For pending-marker coverage, capture
the actual last committed marker bytes before their storage is reused, then
restore that frame after folding. This adds no production injection API, format,
allocator or runtime mode. The integration test owns this two-shape test axis;
current codecs and production startup retain semantic ownership.

- Canisters declare only namespace/profile; journaled stores declare permanent
  keys. Three controls and four store roles use logical dependency requests.
  Physical IDs come from committed allocation authority, not generated models.
- Explicit host grants use `mode = Allowed`; the dependency macro defaults to
  `Reserved`, which is not a logical placement grant. Generated read/write
  coverage with a 10–99 host pool passes, proving schema no longer owns a floor
  of 100. Convergence still checks the dependency's governance/slot boundaries.
- Standalone and composed hosts share the admission hook. Startup/integrity
  opens use keys directly; persisted store identities still retain resolved IDs
  for consistency checks. No new ledger, migration mode or fallback is added.
- Focused model, macro, bootstrap/admission, 13 startup/receipt tests and existing
  convergence tests pass.
  A generated actor reads/writes through the production runtime, and another
  advances convergence across 129 write messages. These are not upgrade tests.
- Repository lint and invariant gates pass, including focused all-feature builds
  for affected SQL/typed actors. Profile, migration/rule and typed-identity
  compile contracts pass; diagnostic snapshots retain the same type errors at
  their updated source lines. No full test suite was run.
- All three [generated upgrade tests](../../../testing/logical-memory/README.md)
  passed on PocketIC 16 through production memory access. Empty-journal removal
  preserves surviving rows and slot assignments, declares only the historical
  journal, and rejects reintroduction after retirement. Journal debt and a valid
  pending marker both reject removal twice without publishing a new database
  control frame; restoring the full actor recovers successfully. The pending
  marker also passes an unchanged-actor recovery control after journal folding.
  A local PocketIC server was started for these tests; unrelated networks were
  left alone. Ordinary suites skip this artifact-dependent target unless it is
  explicitly selected with both Wasm builds and `--ignored`.
- Fixture lint passes for full and omitted builds, and integration-target lint,
  formatting, memory/dependency/deployment invariants and whitespace checks pass.
  The initial sandbox could not bind a local port; the authorized local-server
  retry ran all three tests, with none ignored. This completes L3, not L4 or the
  full user-owned release gate.
- At the L3 handoff, L4 and cost measurements were pending; see the completed
  qualification above. Full suites/publication remain user-owned; no sibling
  application was edited.
- Complexity snapshot: approximately 90 implementation/fixture/guide files and
