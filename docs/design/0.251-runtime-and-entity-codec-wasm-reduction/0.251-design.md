# IcyDB 0.251 — Runtime And Entity Codec Wasm Reduction

- **Status:** Design ready; implementation not started
- **Date:** 2026-08-31
- **Target line:** 0.251, explicitly requested after the 0.250 closeout
- **Released predecessor:** `v0.250.0`
- **Pending predecessor candidate:** the uncommitted 0.250.1 recursive
  `InputValue` landing slice
- **Primary proving shapes:** the controlled empty metrics actors, the
  maintained one-to-ten reachable-entity pair and the supplied Toko
  `project_instance` actor
- **Evidence tracker:** [0.251-status.md](0.251-status.md)

## 1. Summary

0.250 established that the 2 KiB entity budget measured dead-strippable schema
growth, not the complete generated adapter surface. After the concrete page,
exact-key and write terminals landed, the maintained reachable comparison still
adds 40,188 final raw bytes across nine added entities: 4,466 bytes per entity
after `wasm-opt -Oz`. The exact baseline is retained in the
[0.250 Landing Slice 6 receipt](../0.250-generated-entity-specialization-reduction/0.250-landing-slice-6-receipt.md#maintained-reachable-entity-result).
Eleven similarly reachable entities therefore retain roughly 48 KiB of linear
entity-related Wasm.

Reaching a genuine 2 KiB full-adapter budget on that recorded comparison
requires removing at least 21,756 final raw bytes. The pending 0.250.1 candidate
refreshes the same pair at 40,196 bytes, which would require 21,764 bytes; Landing
Slice 1 freezes the exact published predecessor before either number becomes a
0.251 acceptance baseline.

A separate controlled empty-actor comparison attributes up to 179,251 final raw
bytes, 163,872 code bytes, 14,086 data bytes and 551 defined functions to the
basic metrics surface. This is an upper bound for a large application because
other endpoints already retain shared Candid and runtime machinery, but it
qualifies metrics state and dispatch as the first experiment for total Wasm.

The line has two ordered objectives:

1. retain only compact metrics state and event handling in basic-metrics builds;
2. reduce the complete reachable entity slope with binding-owned row and write
   codecs, then measure whether compact generated descriptors close the
   remaining gap.

These objectives share a final-Wasm discipline but not an implementation
owner. They are separate landing slices and must not be combined into one
multi-domain change.

## 2. Demonstrated Need And Smallest Owners

### Basic Metrics

The public basic response is a sparse vector over 24 numeric metric codes, but
the current implementation reaches the full `EventState`, `EventOps`, detailed
entity counters, rich event enum and exhaustive dispatch. SQL counters are also
represented in SQL-disabled builds.

The smallest semantic owner is the compile-time metrics state/sink selection:

```text
basic endpoint only -> compact state + compact sink -> CompactMetricsReport
extended enabled    -> rich state + rich sink      -> compact and rich reports
```

There is one selected state and one selected global sink in a build. Basic and
rich states must not coexist, mirror each other or synchronize at runtime. The
existing endpoint declaration cannot by itself specialize already-compiled
dependency internals, so the initial design uses one explicit
`metrics-extended` Cargo feature forwarded from `icydb` to `icydb-core`.
Declaring `icydb_metrics_extended` without that feature is a compile error.
This is a pre-1.0 hard cut; no stub report, fallback sink or compatibility
feature spelling is retained.

The compact state stores only the values required to produce the basic report,
its window metadata and required per-entity grouping. Rich-only event variants,
payload fields, counters, summaries and dispatch arms are compiled only for the
extended build. Existing `sql` selection separately owns SQL-only internal
state and dispatch. An SQL-disabled rich response may synthesize established
zero-valued output fields when required for Candid compatibility; it must not
retain mutable SQL counters solely for that response shape.

### Bound Row Decode

Generated row decode currently calls `TypedEntityBinding::row_value` once per
field. Every call rechecks binding identity and entity identity, resolves the
source key to an accepted slot and searches the row projection.

One concrete `BoundRowDecoder` should instead:

- consume or borrow one `OutputRow` with its `TypedEntityBinding`;
- validate binding, entity and complete projection once;
- resolve descriptor order to row positions once; and
- expose values by binding-owned descriptor ordinal to generated leaf decode.

The ordinal is not a physical accepted-schema slot and is never caller-authored
runtime authority. It is meaningful only through the opaque current binding.
Generated code retains final `TypedOutputValue` conversion for each Rust field.
No callback, trait object, function pointer, vtable or runtime registry is
introduced.

### Bound Write Encode

Generated insert, patch and replace adapters currently build named
`(field, WriteCell<InputValue>)` collections. Generic facade constructors then
allocate strings and resolve those source names through the binding for every
write.

One concrete `BoundWriteEncoder` should accept a bounded collection of
descriptor-ordinal cells, validate the binding once and lower them in one
non-generic loop. Generated code retains only final Rust-to-`InputValue`
conversion and operation-specific key construction. Patch and replace must use
the same field-cell encoding owner; insert differs only where database-owned
primary keys are structurally absent.

The encoder does not expose accepted physical slots, bypass authored/default/
null semantics or add another mutation terminal. It feeds the source-bound
typed mutation contract and canonical atomic executor established by 0.250.

### Compact Static Descriptor

The 0.250 static descriptor removed executable binding construction but added
approximately 11.4 KiB of data in the exact Toko A/B. It currently repeats
recursive `TypedFieldType`, nullability and source-key structures per entity.

After the codec slices, one measured descriptor experiment may retain source
names while comparing:

- a compact static byte/word description decoded by one concrete binding
  validator; and
- a domain-separated fingerprint of ordered identities, field types,
  nullability and primary-key membership, accompanied only by the names needed
  to issue the binding.

Accepted schema snapshots remain runtime authority and must validate the full
generated contract before issuing an opaque binding. The descriptor is not a
catalog, runtime schema fallback, persisted format or registry. A compact byte
shape needs no format-version discriminator because it is regenerated and
compiled together with its sole decoder; if later evidence demonstrates a
genuine versioned boundary, the only allowed pre-1.0 version is `1`.

## 3. Frozen Measurement Contract

Landing Slice 1 records the exact tagged predecessor after 0.250.1 is either
published or explicitly abandoned. It must not treat the current dirty 0.250
worktree as a release baseline.

The metrics matrix contains controlled actors for:

- no metrics endpoint;
- basic compact metrics and reset;
- basic metrics with SQL disabled and enabled; and
- extended metrics, with the exact feature and endpoint selection recorded.

The entity matrix retains the existing one-to-ten reachable-operation pair.
Every entity must reach bounded page decode, exact-key decode, single insert,
single patch, same-entity batch and delete through the same harness. The
schema-only pair remains a separate 2 KiB control and must not be relabelled.

The heterogeneous Toko actor remains read-only downstream evidence for complex
field shapes, descriptor data and real generated code. Each accepted A/B must
freeze source revision/tree, generated-source hash, lockfile, feature set,
Rust/Cargo, Canic, Binaryen and ordered post-link commands. No application,
schema, endpoint or toolchain change may occur within an IcyDB source A/B.

Every report records, at minimum:

- final raw non-gzipped Wasm and code-section bytes;
- data bytes, defined/total functions and `call_indirect`;
- exports, Candid bytes and hashes;
- deterministic gzip as secondary context;
- named monomorphization/top/retained evidence for the targeted family; and
- focused instruction and allocation controls where the operation harness
  exposes them.

Raw final Wasm is the acceptance authority. Named/Twiggy attribution qualifies
an owner but is not an additive saving claim.

## 4. Retention And Regression Gates

### Metrics Candidate

The compact basic-metrics candidate is retained only when it:

- removes at least 32 KiB of final raw Wasm from the controlled basic-metrics
  actor relative to the frozen predecessor and also reduces code bytes;
- removes rich-only state/dispatch from named basic artifacts rather than
  merely moving code into data;
- does not add indirect calls or runtime sink selection;
- preserves the exact basic Candid response and all 24 code meanings;
- preserves extended Candid and behavior when `metrics-extended` is selected;
- preserves reset, window filtering, query-context and scoped-sink behavior;
  and
- proves SQL-disabled builds do not retain SQL-only mutable state or dispatch.

The 32 KiB gate qualifies the new compile-time feature axis; it is not a claim
that all 179,251 upper-bound bytes are removable.

### Codec Candidates

Each row/write codec slice must reduce both final raw and code bytes in the
maintained reachable pair, keep `call_indirect` flat and not create an
entity-scaled function family outside final Rust conversions. The exact Toko
actor must also improve or remain byte-neutral while preserving its normalized
exports and embedded Candid.

The cumulative codec/descriptor objective is a nine-entity raw delta no larger
than 18,432 bytes, rounded up to at most 2,048 bytes per additional reachable
entity. Against the recorded 0.250.0 closeout this requires at least 21,756 raw
bytes of reduction. Landing Slice 1 recalculates the exact required reduction
from the published predecessor and that value becomes authoritative.

The descriptor candidate is retained only if final raw and code both improve;
a data reduction that grows code or a fingerprint that weakens accepted
validation is rejected.

For any affected live control, a regression is material when it adds both more
than 250,000 instructions and more than 3%. Candidates crossing both limits are
removed unless explicitly reconsidered with exact evidence. Allocation class,
stable writes and cycle charges are reported where available.

## 5. Landing Plan

The initial 0.251 line contains six ordered landing slices. Each is one
reviewable worktree handoff with its direct tests, docs, measurements and active
changelog note.

| Slice | Bounded outcome | Canonical owner | Required evidence |
| ---: | --- | --- | --- |
| 1 | Freeze the published predecessor, controlled basic/extended/SQL metrics matrix and refreshed one-to-ten/Toko codec baselines | Wasm measurement contract | Exact identities and raw/code/data/function/indirect/export/Candid receipts; no production behavior change |
| 2 | Compile basic metrics against one compact state/sink and gate rich state behind explicit extended selection | Metrics state and sink | At least 32 KiB basic raw saving, lower code, flat indirect calls, exact basic/extended reports, reset/window/query/override parity, SQL-off exclusion |
| 3 | Validate each prepared row once and decode generated fields by binding-owned descriptor ordinal | Typed binding and prepared-row facade | Scalar/list/map/named/enum/null/composite coverage, stale/entity/projection errors, page/exact/write-row parity and improved reachable raw/code |
| 4 | Lower insert, patch and replace cells through one concrete ordinal write encoder | Typed binding over existing typed mutation admission | Omitted/default/null/value, primary-key policy, stale/duplicate/invalid ordinal, single/batch parity, atomic errors and improved reachable raw/code |
| 5 | Compare compact static descriptor encodings and retain only a raw/code-positive accepted-authority-validated shape | Generated descriptor plus core binding validator | Heterogeneous Toko shapes, rename/name reuse, nullability/named/list/key mismatch, data/code/raw deltas and no runtime registry |
| 6 | Qualify cumulative total-Wasm and reachable-entity results; tighten the full-adapter gate only if achieved | Measurement/status owner | Exact sequential/cumulative A/B, Candid/export/format parity, residual ledger and at most 2 KiB per reachable entity |

## 6. Slice Boundaries

### Landing Slice 1 — Baselines Only

This slice may add or correct audit actors, report fields and receipts. It does
not change metrics production state, generated descriptors or typed adapters.
It explicitly resolves whether 0.250.1 is the published predecessor before
freezing measurements.

### Landing Slice 2 — Compact Metrics Only

This slice does not touch generated entity codecs or the reachable-entity
budget. It selects exactly one compile-time state/sink, updates the extended
feature contract and removes rich-only basic-build reachability. It does not add
a runtime mode, persisted metrics format or dual state.

### Landing Slice 3 — Row Decode Only

This slice replaces repeated `row_value` validation/search in generated decode.
It does not change typed write construction, output value conversion, query
execution, projection production or descriptor representation.

### Landing Slice 4 — Write Encode Only

This slice replaces named generated field collections with binding-owned
ordinals and shares patch/replace field lowering. It does not add a write path,
change atomic admission or combine row decode and write encode behind a generic
codec trait.

### Landing Slice 5 — Descriptor Experiment

This slice begins from the accepted codec boundary. It compares compact
descriptor alternatives and retains at most one. If neither lowers final raw
and code bytes, both are removed and the existing descriptor remains.

### Landing Slice 6 — Qualification Only

Closeout changes no production behavior. The reachable full-adapter ceiling is
tightened from 8 KiB to 2 KiB only when the exact pair already passes. Failure
is recorded as an incomplete objective; the gate is not weakened, rounded down
or reinterpreted.

## 7. Deferred Lower-Confidence Candidates

Two supplied opportunities are recorded but are not initial landing slices:

- a private generated no-removal schema-proposal lowering path, with roughly
  31.5 KiB of named retained code; and
- consolidation of approximately 67.3 KiB of named stable/unstable sort bloat.

The no-removal path may be added as a later independent slice only after a
controlled experiment saves at least 32 KiB final raw while preserving the
canonical proposal validator and accepted-schema authority. It must not become
a second mutation semantics path.

Sort consolidation may be added only when identical semantic call sites can
share an existing concrete implementation. Dynamic comparators, erased item
types, indirect calls or a new sorting abstraction are not accepted merely to
improve named attribution.

Neither candidate is silently folded into codec or closeout work. New evidence
and explicit authorization may extend this tracker without renumbering the six
planned slices.

## 8. Non-Goals

0.251 does not:

- revisit the 0.250 prepared-page, exact-key or atomic-batch terminals;
- remove entities, endpoints, generated application behavior or schemas;
- add callbacks, trait-object codecs, function-pointer descriptors or vtables;
- add a runtime entity/metrics registry or caller-selectable sink mode;
- expose accepted physical slots or make generated ordinals schema authority;
- reconstruct runtime schema from generated descriptors;
- change Candid, Serde, cursor, catalog or persistence encodings;
- retain predecessor constructors, metrics fallbacks or other compatibility
  shims;
- remove required final Rust field conversion; or
- change compiler profiles, LTO, codegen units, panic policy or Binaryen flags.

## 9. Authority And State-Space Delta

| Concern | Canonical owner after 0.251 | State-space delta |
| --- | --- | ---: |
| Basic metrics state/report | Compact metrics state and sink | One compile-time build selection; no runtime mode or duplicate state |
| Extended metrics | Rich state/sink selected by explicit feature | Existing extended behavior becomes explicit at compile time; no fallback |
| SQL metrics internals | Existing `sql` feature | 0 new axes; SQL-off state/dispatch removed |
| Accepted schema | Accepted snapshot | 0; remains sole runtime authority |
| Generated field order | Validated static descriptor | 0 runtime choices; ordinal is binding-local metadata |
| Row projection validation | Concrete bound row decoder | 0 execution routes; repeated checks converge once |
| Typed write lowering | Concrete bound write encoder over existing admission | 0 mutation/commit routes |
| Final Rust conversion | Generated `TypedInputValue` / `TypedOutputValue` leaves | 0; remains specialized where types differ |
| Descriptor representation | One regenerated static contract | 0 persisted/runtime format states |

## 10. Exit Criteria

0.251 is complete only when:

- the published predecessor and all controlled artifacts are frozen;
- basic metrics builds retain one compact state/sink and exclude rich-only and
  SQL-disabled internals;
- extended metrics remain available only through the explicit current feature
  and preserve their established Candid and behavior;
- generated row decode validates one binding/projection once per row;
- generated writes no longer build or resolve repeated field-name collections;
- patch and replace share one field-cell lowering owner;
- accepted snapshots still validate every generated descriptor fact before a
  binding is issued;
- no callback, dynamic dispatch, registry, compatibility path or new execution
  route remains;
- metrics and codec candidates pass their raw/code, structural and focused cost
  gates; and
- the maintained reachable pair is at most 2,048 raw bytes per added entity, or
  closeout explicitly records the objective as incomplete without weakening the
  existing 8 KiB gate.

The compact-metrics result is reported separately from the entity-slope result;
their savings are not added into a single attribution claim.
