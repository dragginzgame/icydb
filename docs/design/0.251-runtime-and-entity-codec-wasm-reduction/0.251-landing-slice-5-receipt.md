# IcyDB 0.251 Landing Slice 5 Receipt

## Disposition

Landing Slice 5 is complete. The lossless compact static descriptor candidate
is rejected and removed because it grows both final raw Wasm and code in the
authoritative maintained pair. The existing generated `TypedEntityDescriptor`
remains the sole compiled contract presented to accepted-schema binding
validation.

No public API, Candid shape, generated entity surface, persisted representation,
runtime registry or schema-authority boundary changes remain from this slice.

## Candidate

The measured candidate replaced each recursive static `TypedFieldType` tree and
separate primary-key source-key list with:

- one static source-key table containing the entity, fields and referenced named
  types; and
- one compact byte contract containing field count, primary-key descriptor
  ordinals, scalar/list/named tags, named-source ordinals and nullability bits.

One concrete bounded cursor decoded that contract during typed-binding issuance.
The decoder was fallible, rejected trailing or malformed bytes and reconstructed
the complete logical field contract before the existing accepted snapshot
validated entity identity, ordered field identity, type, nullability and
primary-key membership. The bytes were generated and compiled with their only
decoder; they were not a public, persisted, cursor, catalog or runtime format
and therefore added no format-version discriminator.

The candidate did not add callbacks, trait objects, function pointers, vtables,
a runtime registry or caller-authored physical slots.

## Rejected Fingerprint Alternative

A fingerprint-only descriptor was also rejected before implementation.
Generated named-field contracts refer to associated
`TypedNamedType::SOURCE_KEY` constants, so the entity macro cannot precompute an
exact whole-entity fingerprint from source literals. Computing the same digest
at runtime would still require retaining and traversing every source identity,
type, nullability and primary-key fact, adding hashing code and a second
validation representation without removing the measured descriptor traversal.

A shortened or non-cryptographic fingerprint would additionally weaken exact
accepted-schema validation through collisions. A custom compile-time hash,
runtime registry or accepted-snapshot-derived fingerprint would add a new
semantic authority or complexity boundary for no demonstrated final-Wasm gain.
The lossless byte candidate was the smaller and stronger experiment; its failed
raw/code result closes this alternative for 0.251.

## Allocation, Specialization And Complexity

Both retained and candidate forms are static generated data. The candidate did
not add per-row or per-write allocation, but binding issuance gained a byte
cursor, tag vocabulary, bounds checks and reconstruction branches. Those two
additional optimized functions were shared rather than entity-scaled, while the
encoded data itself still grew with entity count.

The experiment changed the descriptor and generated-token contract across the
core validator, facade exports, macro emission and focused fixtures. It was
materially more complex than the retained direct typed static contract. Removal
returns production and focused-test code exactly to the seven-file Slice 4
shape (`+159/-167` lines relative to the line's predecessor); Slice 5 retains
documentation only and adds no runtime state or execution route.
