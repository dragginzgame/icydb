# IcyDB 0.251 Landing Slice 3 Receipt

Date: 2026-09-01

Disposition: binding-owned ordinal row-decoder candidate rejected; no
production decoder, generated API, projection shape or public surface retained.

## Outcome

The strongest candidate replaced generated source-name lookup with a borrowed
`BoundRowDecoder`, mapped accepted output columns to generated descriptor
ordinals once per shared projection and removed a duplicated entity string from
that projection. It reduced function count but grew both authoritative actors
and made the nine-entity slope worse.

The frozen raw delta is 40,190 bytes across nine added entities. The candidate
measured 40,277 bytes, an 87-byte regression, and its code delta increased from
38,604 to 38,693 bytes. Both actors retained the exact 190-byte Candid contract
with SHA-256
`f8d63096cbc2d7ff9d22b9de8d880ee5b5acc7d7fd2e96b19f46a3b75ad21045`.

An earlier forced shared-call shape produced 2,871,911 and 2,912,095 raw bytes.
Its 40,184-byte slope was six bytes smaller than the baseline, but both
artifacts grew by 381 and 375 bytes. It likewise failed the rule that a codec
candidate must reduce final raw and code bytes rather than merely move function
boundaries.

## Candidate Shape

The experiment retained accepted snapshots as runtime authority:

- binding issuance kept generated descriptor order and resolved accepted
  labels to binding-owned ordinals;
- the shared output projection built one ordinal-to-value-position vector and
  rejected missing or duplicate generated fields;
- one borrowed concrete decoder checked exact binding identity once per row;
- generated fields used numeric descriptor ordinals and retained only their
  existing `TypedOutputValue` conversion; and
- page, exact-key, single-write, same-entity batch and mixed-batch terminals
  continued to produce the same owned `OutputRow` contract.

No physical accepted slot, callback, trait object, function pointer, vtable,
registry, persisted format or alternate execution route was introduced.

## Behavioral And Allocation Evidence

Focused tests proved accepted output labels preserve descriptor order, generated
scalar/list/named/nullable field leaves use numeric ordinals and a real accepted
row decodes correctly when its output columns are reversed. The same boundary
rejected missing, duplicate, foreign-entity, malformed and out-of-range
projections with typed adapter errors. Existing page, exact-key and write-row
call sites compiled through the unchanged `TypedRowAdapter` terminal. Broader
map, enum and composite coverage was not run after the primary Wasm gate failed.

The candidate added no per-row allocation. Each shared projection still owned
one vector; its entries changed from accepted-slot/search pairs to direct
positions. The borrowed decoder held only two slices. Removing the projection's
duplicated entity string narrowed retained state, although the upstream result
still necessarily owned its accepted entity label.

The prototype touched eight files with approximately 220 inserted and 59
deleted lines including focused tests. It added one generated-code-visible type
and a descriptor-ordinal contract. This was a modest but real complexity
increase, and the final raw/code regressions provided no maintenance or size
benefit to justify it.

## Rejected Alternatives

- Per-row construction of an ordinal map would add allocation to every decoded
  row instead of sharing projection preparation.
- Trusting an `OutputRow` without checking the caller-supplied binding could be
  smaller, but would weaken the stale/cross-binding failure boundary.
- Callback, trait-object and function-pointer decoders would add indirect
  machinery already rejected by the 0.251 design.
- Retaining the six-byte slope-only forced-call result would optimize a
  reporting technicality while making both deployable artifacts larger.

## Validation And Restoration

The prototype passed strict facade linting, owner-local binding-order and
generator tests, and the focused native row-projection behavior test. The
authoritative raw/code pair then failed, so the Toko build and broader release
matrix were short-circuited rather than spending their cost on a rejected
candidate.

All eight implementation and test files were restored to immutable
`v0.250.1` content. Runtime behavior, allocations, generated APIs, Candid and
the 40,190-byte reachable slope are unchanged. Only this evidence receipt and
tracker/changelog updates remain.
