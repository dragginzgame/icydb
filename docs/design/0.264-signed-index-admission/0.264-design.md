# 0.264 — Signed Filter Index Admission

Authorized 2026-10-01 after the user reported 0.263 pushed and directed work on
0.264. Delivery owner: [status](0.264-status.md).

## Outcome and demonstrated need

Let schema-canonical signed equality and membership filters use maintained
secondary indexes. The 0.263 qualification proves that dynamic Int32 filters
scan all 160 fixture rows while equivalent strict SQL predicates select logical
intersections. Expression extraction retains NumericWiden for signed atoms;
secondary index lookup correctly requires strict key semantics.

Accepted schema normalization owns the proof that an extracted comparison is
equivalent to strict comparison. The planner, index compiler, diagnostics and
executor then consume the existing strict predicate. Do not relax their
coercion gates independently or add an executor route.

## Bounded semantic contract

Initially admit positive Eq and In for accepted signed Int8/Int16/Int32/Int64
query fields whose normalized operands are Int64 atoms. Accepted newtype
projection and relation key metadata may establish that same scalar contract.
Every stored signed value in this family has an exact decimal representation,
so strict and widening equality agree, including negative values and extrema.
For In, every member must meet the proof and its inspection must be charged.
Unknown fields, mismatched operands, null/mixed sets, wider kinds, collections,
field comparisons and ordered comparisons retain their existing semantics.

Keep the semantic expression, accepted schema, index lifecycle admission,
cardinality bounds, corruption checks, result ordering, residual filtering and
execution budgets authoritative. Cursor encodings remain current version 1;
changed plan identities may reject pre-change continuations. Restart affected
pagination rather than adding compatibility dispatch.

The coherent initial surface includes single-index equality, compact membership,
same-field OR equalities, composite equality prefixes and two/three-child AND
intersections. They share the normalization proof and maintained execution
flows. Ranges and wider integers need their own boundary proof and are outside
this line; no sequence of spelling-specific executor optimizations is planned.

## Simplicity decision

SQL already provides a usable workaround, but requiring callers to change
frontends leaves a demonstrated dynamic-query cost gap. Changing only the top
planner guard is insufficient: key-item matching and index literal compilation
also reject NumericWiden. Changing all gates would distribute semantic authority
and admit unproved conversions. Normalize a proved comparison once instead.

No independent mode, configuration, persisted state, protocol, cursor shape or
execution strategy is added. Existing full scans remain the canonical route
when the proof is absent. Maintenance cost is one narrow normalization rule and
direct semantic/session qualification using existing fixture owners.

## Delivery and measurement

Two landings cover the implementation with focused native and bounded IC
qualification, then the complete existing IC matrix and closeout. Reuse the
0.263 SQL-perf actor, entity, host runner and frozen polling artifact; do not
introduce a canister or benchmark framework. Match raw Wasm bytes, IC
instructions and charged cycles at identical endpoints, schemas and populations.
SQL samples are controls, not substitutes for a dynamic baseline. Verify actual
dynamic access selection, exact results and issued cursor suffixes separately.

Full repository validation, Cargo version changes and publication remain
user-owned. No mainnet throughput or cost conclusion follows from PocketIC.

## Signed-query completion

S1 implements the narrow proof and S2 completes the existing IC matrix; see the
[full qualification](s2-qualification.md). Selective small and wide workloads
benefit, while dense matches cost more under the maintained planner. The line
does not add cost heuristics to mask that tradeoff. Dense selection can be
assessed separately using matched IC instruction/cycle evidence.

The parallel A1/A2 cleanup has separate tracker entries. The signed-query scope
is complete; final combined-release qualification and publication remain
separate from the frozen normalizer comparison.
