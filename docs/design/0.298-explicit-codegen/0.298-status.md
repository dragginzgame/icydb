# 0.298 explicit native code generation

The maintainer accepted the delivered 0.297 source closeout and authorized this
minor on 2026-11-04. Package versions and release execution remain unchanged.

## Intended landing slices

1. Require `build` for native schema collection and actor generation. Keep
   application declarations, typed adapters, normalization and validation usable
   without the authoring graph. Forward build selection through reused schema
   libraries and update direct build-script callers.
2. Require `wire-schema` for native Wire metadata independently of generation.
   Keep runtime Serde codecs and accepted-schema authority unchanged. Update
   metadata consumers without enabling metadata in ordinary runtime consumers.
3. Qualify external runtime, model-only, generator and metadata boundaries,
   including renamed dependencies and mixed build/runtime use. Update active
   docs and the pending database release notes.

## Scope and validation

This is a source/build API cut, not a database format change. No new crates,
automatic native registration fallback or package version edits are authorized.
Use focused Linux checks and public Wasm type/lint checks. Broad workspace,
release, installed-IC and native macOS qualification remain user-owned.
No resource savings are claimed without permitted measurements.

Canic owns an independent framework build-feature change. Its current handoff
explicitly retains an unaccepted 0.114 closeout; this IcyDB line does not change
that source batch or authorize a Canic minor boundary.

## Completed implementation and focused closeout

All three IcyDB landing slices are complete. `icydb/build` forwards to
`icydb-model/build`; the model dependency owns expansion selection, collection,
whole-graph validation, descriptors and actor generation. No-build declarations
retain their application types, behavior and typed adapters. The graph's former
Wasm-only placeholder branches and allowances are removed because the entire
authoring graph now belongs to the explicitly selected host build.

`wire-schema` forwards through facade, Core and Schema to upstream native
metadata generation. Every maintained metadata derive and manual implementation
uses that selection. Runtime Serde code and byte contracts are unchanged.
Build-script entries explicitly select `build`; shared schema libraries forward
it through reused declarations. Native binding examples explicitly select their
metadata providers. CI retains nonempty schema-generation checks with the new
feature and checks the four selected dependency graphs independently.

Qualification on pinned Rust 1.99.1/Linux passes strict default-runtime,
explicit-build/metadata and public Wasm lint, renamed mixed build/runtime
adapter lint and tests, model-only lint with build both disabled and enabled,
graph sealing controls, explicit fragment lowering and invalid declaration
diagnostics. Native binding generation succeeds for all 12 methods, 228 native
types and 91 exact vectors; output is under
`target/evidence/native-codegen/bindings/`. Graph, schema/model boundary,
ShellCheck, workflow syntax, documentation/link and diff checks pass. One
default-feature fixture warning was corrected by gating its build-only test
support with its graph tests, then the selected lint passed.

The isolated Canic facade consumer check refuses during dependency resolution:
its retained Platform 0.8.3 selects `ic-cdk-executor` while Storage 0.64 selects
Platform Runtime 0.17.1 and its guard, with conflicting executor `links`
identities. It never reached source compilation and was not rerun. The older
integration stack and lock remain unchanged; this is not successful Canic or
installed-canister qualification.

The focused closeout was subsequently extended by the requested release
qualification below. Native macOS and installed-IC remain unqualified. Cycles,
instructions and total/code-section Wasm changes are unmeasured. No network
lifecycle, package version edit, staging, commit, push or release was performed.
