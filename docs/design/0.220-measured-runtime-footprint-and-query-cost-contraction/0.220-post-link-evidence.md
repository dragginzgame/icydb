report validator parses every final module with only the three named proposal
features, compares compiler and final method exports, and compares extracted
Candid byte-for-byte.

unbounded one-caller inlining to produce an invalid debug/local dynamic actor
with one function above the IC complexity limit. The current v2 identity
hard-cuts that output by setting the maximum to zero. The corrected dynamic and
typed local actors install and execute in PocketIC; v1 is not retained as an
alternate pipeline.

## Runtime And Upgrade Proof

Two transformations of identical `sql_perf` compiler bytes produced identical
final bytes. PocketIC installed the pre-optimization compiler artifact,
persisted the accepted schema, loaded normal committed fixture rows, and read
them through SQL. Upgrade to the final optimized artifact preserved those rows,
accepted-schema exact re-entry, further fixture mutation, and subsequent SQL
reads.

Fresh matched instances measured exact-schema application at 7,676,331 local
instructions for compiler output and 7,440,723 for optimized output, a 3.07%
reduction. The ordered SQL sentinel fell from 1,107,997 to 1,094,622
instructions, a 1.21% reduction. Exact re-entry after compiler-to-optimized
upgrade measured 7,466,427. Focused optimized runtime checks also passed for
query-only typed and dynamic actors, chained aggregate expressions,
schema/index publication plus EXPLAIN/read behavior, and bounded ordered
mutation.

No public Candid, exported method, accepted schema, persisted format, cursor,
successful query result, mutation rule, or authorization behavior changed.
