# IcyDB 0.220 Schema-Application Contraction Evidence

Status: Patch 5 complete

## Authority And Selected Shape

The released comparison baseline is `v0.220.0` at commit
`dec7990ca0038e277330a614164126b15bd4b08a`. Patch 4 documentation was already
present in the dirty worktree for both baseline and candidate builds and does
not enter the canister dependency graph.

Patch 1 attributed a large retained owner family to schema application and
application lowering. The selected repeated shape was recursive source
`FieldType` lowering: it accepted an arbitrary closure, so distinct initial,
existing, migration, and runtime-binding call sites generated closure-specific
copies. Initial and existing named-composite lowering also separately encoded
the same newtype, list, set, map, and tuple match.

The retained implementation has one closed named-type identity resolver:

- initial proposal lowering resolves only freshly allocated candidate
  identities;
- existing-head and runtime binding checks resolve only through the accepted
  source-binding catalog; and
- scalar migration targets use the same non-fallible scalar lowering owner.

One non-record composite helper now serves both initial and existing catalogs.
Record field identity allocation remains deliberately separate because initial
and accepted catalogs own different identity operations. `apply_schema`
remains the sole semantic application path, accepted snapshots remain runtime
authority, and no generated shortcut, fallback, or second schema route exists.

## Complexity And Compatibility

The production implementation paths remove nine net source lines before the
focused regression test is counted. More importantly, arbitrary resolver
closures and one complete duplicated composite-shape match are gone. The
implementation is simpler and the authority set is closed.

No public API, Candid type, accepted schema, persisted row, index, relation,
journal, marker, migration, cursor, authorization, or error semantic changes.
Focused lowerer, application, recovery, migration, dynamic-write, query-only,
and lifecycle evidence passes under all-feature and no-default builds.
