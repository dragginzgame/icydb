## Schema-Application Lifecycle

The audit-only probes are absent from production Wasm feature rows. Under
PocketIC 15 they observed:

| Lifecycle point | Outcome | Local instructions |
| --- | --- | ---: |
| first query after install | first create; rolled back | 53,252,186 |
| second query after install | first create; rolled back | 53,252,186 |
| first update initialization | first create; persisted | 53,252,218 |
| query after update initialization | exact accepted head | 7,640,820 |
| first query after same-Wasm upgrade | exact accepted head | 7,653,309 |
| repeated query after upgrade | exact accepted head | 7,653,309 |

The query-only typed actor separately returns a typed failure rather than
collapsing schema/query initialization failure into an empty result. The
production footprint actor retains its prior `u32` result through an
audit-only local feature.

This evidence makes schema application both a footprint and query-cost target:
query-only actors repeatedly pay first-create work until an update persists
the accepted head.

## Frozen Budgets

Per-patch gates are machine-owned by `wasm_measurement.rs` and the SQL
performance profile. The cumulative raw-Wasm reductions are 0% for
`default_empty`, 5% for `default_empty_metrics`, `sql_perf`, and `sql`, and 7%
for each dynamic, typed, SQL-query, and entity-scale query actor.

The cumulative SQL instruction budgets require at least a 3% complete-matrix
aggregate reduction and 5% selected-hotspot reduction, while permitting no
final regression in any maintained sentinel or normalized scale cohort.
Individual patches retain their explicit selected-owner improvement and
non-selected regression ceilings; those allowances do not reset cumulative
budgets.
