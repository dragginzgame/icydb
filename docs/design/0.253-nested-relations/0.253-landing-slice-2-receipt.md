- **Date:** 2026-09-04

- **Outcome:** Direct relations now use the current tagged source shape,

## Implementation

- Accepted snapshots persist one entity-local `RelationId` high-water and an
  explicitly tagged `Direct { field_ids }` source locator.
- Candidate planning reserves new IDs from that high-water; snapshot rebuild,
  mutation, fingerprint, and codec paths preserve it after relation removal.
- Reverse keys use one reserved relation-system index namespace plus the exact
  four-byte big-endian relation ID. Physical generation remains disjoint and
  still identifies rebuilds of the same semantic relation.
- The database boot identity and relation codec hard-cut predecessor state.
  Current format discriminators remain exactly version `1`; no legacy decoder,
  fallback, translator, or in-place upgrade path is retained.
