# 0.255 slice 15 — Projection validation reachability

Date: 2026-09-07. Baseline: published 0.255.2,
`a479ebaf04c413035edab7445f42463fa4c8c937`.

This records the pre-removal baseline finding. Source references below describe
`v0.255.2`, not the subsequent cleanup authorized as slice 16.

## Finding

The proposed discarded-result clone optimization is not supported as a production
performance improvement. The copying function exists, but tracing its callers
found no maintained production entry point that executes this validation pass.
The earlier recommendation inspected the local copy without establishing that
reachability; this preflight corrects it.

## Source evidence

- [Projection validation](../../../crates/icydb-core/src/db/executor/projection/materialize/plan.rs)
  calls the borrowed-value evaluator, obtains an owned result and discards it.
  Its only call is the post-scan validator in
  [page finalization](../../../crates/icydb-core/src/db/executor/terminal/page/post_scan.rs).
- That tail receives a validator only when `validate_projection` is true.
  [Execution inputs](../../../crates/icydb-core/src/db/executor/pipeline/contracts/execution/inputs.rs)
  derive that flag exclusively from `ProjectionMaterializationMode::SharedValidation`.
- [Initial and resumed scalar runtime setup](../../../crates/icydb-core/src/db/executor/pipeline/entrypoints/scalar/runtime.rs)
  selects `None` or `RetainSlotRows`, never `SharedValidation`. The SQL scalar
  aggregate row-sink entry point also explicitly selects `RetainSlotRows`.
- The sole production construction of `SharedValidation` is
  [grouped key-stream setup](../../../crates/icydb-core/src/db/executor/aggregate/runtime/grouped_fold/mod.rs).
  It supplies an empty prepared-projection bundle and calls
  `resolve_execution_key_stream_without_distinct`, then constructs a grouped
  stream for the separate grouped fold.
- [The key-stream resolver](../../../crates/icydb-core/src/db/executor/pipeline/runtime/fast_path/mod.rs)
  resolves access streams; it does not call scalar page materialization or the
  post-scan validation tail. Grouped fold owns its actual expression evaluation.

This is a source call-path finding, not a claim that projection expressions or
accepted-row validation are unnecessary. Those maintained checks must remain.

## Disposition

A provisional success/error-only evaluator terminal was added locally, then
removed along with its export and caller change after the reachability check.
No Rust change remains. Do not add a new helper or synthetic benchmark solely
to optimize this dormant route, and do not enable it to manufacture a workload.

The proposed follow-up is deletion of the dormant mode and validation tail,
`ProjectionValidationRow` and its adapters, plus the associated flag propagation
and never-selected `shared_validation_emit_retained_slot_layout` resident.
Before deleting, check each shared contract for retained-slot/materialization
consumers; the prepared projection contract itself is still needed. Preserve
typed errors, row validation, ordering, pagination and actual expression
evaluation. No replacement mode, evaluator or cache should be introduced.

This is a separate cleanup outcome requiring approval, not an implementation
expansion silently included in the authorized clone fix.

## Validation and evidence limits

- The isolated production baseline actor builds successfully from published
  0.255.2 with the same toolchain, lockfile and canonical post-link pipeline.
  It includes a temporary query-as-update wrapper only in the isolated source.
  Evidence is under `/tmp/icydb-0255-projection-validation.UmnIto`.
- The reachability gate stopped candidate measurement. No allocation, cycle,
  throughput or Wasm delta is claimed. No PocketIC server was started.
- Formatting was run after removing the provisional edits; the final Rust diff
  is empty. Documentation whitespace checks pass. Focused tests and full suites
  were not run because no implementation remains; full suites stay user-owned.
- Only design/status and this finding document change. Cargo versions, lockfile,
  published changelog entries and runtime behavior remain unchanged.
