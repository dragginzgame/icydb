# IcyDB 0.255 — Owned Value Handoff

Status: authorized after the reported 0.254 closeout and publication of 0.254.2.

## Scope and decision

The nested-materialization preflight found two consumers that deep-clone an
already-owned admitted value and immediately drop the original: persisted-row
canonical decoding and accepted input normalization. First remove those copies
at the existing admission owner. Do not introduce streaming, borrowed collection
APIs, a second decoder, caches, or predicate execution modes.

The simplest alternative is to retain the copies. A consuming accessor on
`AdmittedOwnedValue` can instead move out the canonical value, dropping the
proof's authority handle. It returns a plain runtime value, not reusable schema
authority. Both consumers already discard that authority after cloning; all
normalization, strict validation, resource budgets and errors must run unchanged
before the move. Schema temporal-payload rendering also consumes its admitted
value through the catalog-backed public-output converter in slice 10; the owned
proof needs only its consuming accessor. The separate borrowed proof,
`AcceptedValueRef`, remains unchanged.

State-space delta: none. One internal ownership operation replaces two copies;
no public API, persisted format, diagnostic code or admission policy changes.
Canonical owner: accepted-value admission. Persisted decoding and normalization
only consume its result. No change to Cargo package versions is authorized.

## Planned landing slices

1. **Owned-value handoff:** consuming admission accessor, both caller changes,
   direct ownership/validation regression tests, native and IC/Wasm controls,
   documentation and release notes. Stop for handoff after this outcome.
2. **Collection emptiness boundary:** verify the suspected map-admission mismatch
   against stored queries and the full admission path, correcting runtime only
   if reachable. Preserve current query capabilities, add regression coverage
   and clarify the structural/SQL contracts. This is not part of slice 1.
3. **Borrowed constraint operands (authorized extension):** remove deep copies
   from selected-slot handoff into row-local constraint evaluation. Cover normal
   write admission, constraint activation, migration validation and execution,
   plus mechanical integrity-caller propagation in one handoff.
4. **Owned full-row output (authorized extension):** consume the reader at the
   full-row output boundary instead of cloning its cached values. Preserve eager
   validation and primary-key checks; include ownership/error tests and matched
   allocation, instruction and Wasm measurements. Direct projections are excluded.
5. **Owned direct-projection operands (authorized extension):** move the first
   owned output for each raw-row source slot out of the reader cache. Preserve
   scalar fast paths and the existing output clones for repeated fields. Cover
   paged dynamic and SQL consumers with direct tests and matched cost controls.
6. **Single canonical materialization (authorized extension):** eliminate the
   discarded canonical decode/admission immediately before cached materialization.
   Preserve eager whole-row and noncanonical validation, add corruption coverage,
   and measure allocation, IC instruction and production Wasm deltas.
7. **Decoder-owned materialization (authorized extension):** remove storage
   dispatch and redundant noncanonical prevalidation from lazy materialization
   after verifying decoder/validator parity. Keep eager validation separate;
   cover accepted by-kind scalar/collection/relation and malformed-wire behavior.
8. **Borrowed nested-relation roots (authorized extension):** borrow the decoded
   root during relation traversal rather than deep-copying it. Preserve path
   semantics, raw-reference/traversal budgets and owned target-key output; include
   direct and journaled tests plus matched native and populated IC/Wasm controls.
9. **Owned retained-row output (authorized extension):** consume the opened
   reader after filtering and move normal retained values from its cache.
   Preserve scalar byte-length overrides, selected-slot admission and predicate/
   primary-key ordering; include ownership, corruption and query regression
   tests plus matched allocation and production IC/Wasm controls.
10. **Consuming public-output conversion (authorized after 0.255.0):** move
    owned runtime payloads through the existing catalog-backed output converter.
    Propagate all callers, preserving enum resolution, result order and budgets;
    cover owned heaps, errors, response surfaces and matched cost gates.
11. **Key reconstruction handoff (authorized extension):** move persisted-row
    key values from the discarded reader and borrow SQL key projections directly
    at the existing key-codec owner. Remove temporary SQL vectors and duplicated
    session key assembly; preserve key ordering, validation and encoding.
12. **Reuse validated insert reader (authorized extension):** reconstruct the
    after-image key from the caller's existing validated reader, retaining its
    cache for Identity checks. Remove the second row-open/validation pass; cover
    accepted key order, corruption and Identity behavior with matched cycle and
    raw-Wasm measurements.
13. **Owned mutation-result handoff (authorized after 0.255.1):** move final
    cached values from save/delete readers into mutation output, replacing both
    copying loops with one session-owned handoff. Preserve accepted field order,
    Identity checks and precommit result limits; cover ownership, corruption and
    batch boundaries with matched allocation/cycle/Wasm measurements.

Slice 2 inspection found the preflight premise was false: `ensure_field` rejects
maps before the operator's `is_collection` check. SQL also has no structural
emptiness function; its `LENGTH` function is text-only. No runtime correction or
map capability expansion is justified. See the [boundary receipt](0.255-slice-2-receipt.md).

General collection predicate streaming remains an unpromoted idea. Scalar path
projection already traverses borrowed bytes and untouched fields already defer
materialization. Collection predicates can still materialize complete values;
that observation alone does not authorize another execution path. In particular,
wire length is not always logical cardinality (relation-list decoding omits null
items), and early predicate success cannot bypass required corruption checks.

## Slice 1 validation and cost gates

- Preserve owned nested payloads without a replacement heap allocation at the
  consuming handoff; preserve scalar/NULL values and rejection before handoff.
- Exercise accepted recursive normalization, persisted decoding, malformed input,
  schema authority and maintained nested relation integration behavior.
- Native allocation measurements distinguish cumulative requested bytes from
  peak/live memory and isolate setup from the measured operation. Report any
  timings as diagnostic host samples, not IC latency forecasts.
- Freeze baseline `v0.254.2` and candidate to the same lockfile/toolchain, actor
  shape, production features, Wasm profile and post-link pipeline. Use maintained
  repeated nested-relation actor operations for IC instructions and an empty
  actor as a fixed-cost Wasm control. Report raw/compiler/gzip bytes and defined
  function counts, not just compressed size.
- Before implementation, the bounded acceptance ceilings are: no more than
  1 KiB additional final raw Wasm or four defined functions per control; no more
  than 1% extra instructions for each measured maintained operation. These are
  review ceilings, not predicted improvements; a miss requires investigation
  and an explicit report, not a compensating unrelated optimization.
- Require measured allocation savings on heap-owning handoff workloads and
  unchanged outcomes. Report files/lines and implementation complexity alongside
  cost results. Full repository tests remain user-owned.

## Slice 3 ownership decision and gates

The selected-slot reader currently clones each cached value into a full-layout
vector used read-only by constraints. Keep the same slot preparation and eager
validation sequence, but borrow those cached values. Integrity inspection also
calls the evaluator and legitimately owns its decoded snapshot. Use the existing
standard `Cow<Value>` pattern for one shared slot-vector/evaluator shape: borrowed
entries for selected-slot readers and owned entries for integrity snapshots.
The evaluator never mutates or upgrades these entries to owned values.

The simplest alternative is retaining copies. A reference-only vector would
also remove them but require another allocation/adaptation for the integrity
owner. Do not add an evaluator trait, lazy callback, second evaluation flow,
cross-request cache or new persisted state. `Cow` describes storage ownership,
not a selectable runtime behavior. State-space delta: no behavioral axis.

All required slots must still decode before constraint evaluation. Preserve
fingerprint checks, missing/NULL distinctions, targeted-rule limits, stable
violation ordering and reader-owned corruption failures. Slots not selected by
the constraint program retain their existing validation behavior.

Baseline is the current unpushed slices 1–2, not the pre-0.255 clone path.
Require native allocation savings on heap-owning selected-slot workloads and
unchanged outcomes. Freeze the same production empty/repeated actor controls
and toolchain as slice 1. Before runtime edits, set ceilings of +1 KiB final raw
Wasm, +4 defined functions per actor and +1% instructions per maintained measured
operation. Report any miss rather than tuning unrelated code to compensate.
Measure a real constraint-evaluation path natively; the maintained actor IC
control is an end-to-end regression control, not attribution of constraint cost.

## Slice 4 ownership decision and gates

Full-row output currently clones every cached value and immediately drops the
reader. The existing persisted-row reader is the canonical owner of decoding;
add a consuming full-row handoff there, reusing its required-value admission.
Keep the executor's eager validation and primary-key checks before the handoff.
The simplest alternative is retaining the copies. No new decoder, cache state,
execution route or public API is needed. State-space delta: none. Borrowing and
repeated direct projections are not changed by this slice.

Baseline is the staged slices 1–3. Require lower cumulative allocation requests
for heap-owning full rows and unchanged values/errors. Measure the actual
full-row executor boundary with setup excluded, and distinguish diagnostic host
timings from production IC results. Reuse the same matched production controls,
toolchain and predeclared ceilings: +1 KiB final raw Wasm, +4 defined functions
per actor and +1% instructions per maintained measured operation. Record misses
without unrelated tuning. Full-suite validation remains user-owned.

The initial SQL-disabled controls produce byte-identical artifacts: they do not
establish the changed full-row query path's reachable cost. Add a matched
`one_entity_sql_query` production actor with SQL enabled, under the same raw
Wasm/function ceilings, before closing this slice. The actor is an existing
measurement fixture, not an endpoint or feature addition.

## Slice 5 ownership decision and gates

Direct raw-row projection currently clones cached values even though it only
needs one owned value per distinct source slot. Its repeated-field executor
already copies subsequent occurrences from the first output value. Change the
existing reader operation into an exclusive `take_direct_projection_value`,
reusing required-value admission and leaving the scalar byte-view fast path
intact. The simplest alternative is retaining those copies; decoding separately
would duplicate authority and validation choreography.

Canonical owner: the structural slot reader. No new enum variant, configuration,
format or execution route is added. A take returns a materialized cell to its
existing empty state under an exclusive borrow; subsequent reads still use the
existing lazy materialization authority. Test that transition and retain current
primary-key, selected-slot, error-order and output-budget behavior. Unselected
fields must remain untouched. Full-row consumption and expression projection
are outside this change.

Baseline is the complete unpushed slices 1–4. Measure the real direct-row
materializer for unique/repeated nested outputs and scalar fast-path controls,
with layout/row construction excluded. Counts are cumulative allocation
requests, not peak memory; host timings are diagnostic only. Match production
empty, dynamic-query (SQL off) and SQL-query actors with the same toolchain and
pipeline. Before runtime edits, retain ceilings of +1 KiB final raw Wasm, +4
defined functions per actor and +1% instructions per maintained measured
operation. Require allocation savings for heap-owning copied operands, preserve
outcomes and report misses. IC empty-query controls are not attribution for
populated projection cost. Full-suite validation remains user-owned.

## Slice 6 validation decision and gates

The deferred reader currently invokes the same canonical decode/admission twice
on first access, discarding the first owned result. The row-contract decoder
already performs strict admission against accepted authority. Skip the separate
prevalidation only for fields using canonical wire; leave its noncanonical
counterpart intact. Canonical owner: the existing row-contract decoder and
accepted-value admission. The simplest alternative is retaining duplicate work.
No new decoder, cache state, configuration or runtime behavior axis is needed.

Keep eager all-field validation and its error ordering unchanged. Do not retain
all eagerly validated values: selective consumers would retain otherwise unused
allocations. This reduces complete canonical decode/admission calls from two to
one on lazy first access, and three to two after eager validation, not all byte
walks inside the decoder. Preserve limits, NULL/missing behavior, malformed-wire
rejection, accepted enum/collection typing and cache take/reread behavior.

Baseline is the complete unpushed slices 1–5. Measure real unique/repeated direct
projection and eager full-row materialization with setup excluded, including
scalar controls. Report cumulative allocation requests, not peak memory; host
timings are diagnostic only. Reuse matched empty, dynamic-query and SQL-query
production actors and the existing IC regression controls. Predeclared ceilings
remain +1 KiB final raw Wasm, +4 defined functions per actor and +1% instructions
per measured operation. Require heap-owning canonical allocation savings and
unchanged outcomes. Full-suite validation remains user-owned.

## Slice 7 ownership decision and gates

The reader's slice 6 guard repeats the row-contract decoder's storage decision.
By-kind scalar validation invokes the same scalar decoder, leaf validation uses
the same leaf decoder, and collection validation/decoding use the same complete
wire walkers recursively. Relation null elements are decoded and checked before
being omitted from output. Verify this equivalence at the accepted field and
reader boundaries, then remove the guard and prevalidation call entirely.

Canonical owner: the existing row-contract decoder, which returns a validated
owned value. The reader only controls access and caching. Keep the distinct eager
validation-only operation for rejecting unselected malformed fields without
retaining their values. Do not replace validation-only collection walks with
full materialization, add another decoder/helper/mode, or move the duplicated
branch behind a wrapper. State-space delta: none; one redundant flow is removed.

Baseline is completed slices 1–6. Measure actual direct and eager full-row
materializers with by-kind nested payloads plus canonical/scalar controls;
report cumulative allocation requests separately from peak memory or latency.
Reuse matched production empty/dynamic/SQL actors and maintained IC controls.
Before runtime edits retain +1 KiB final raw Wasm, +4 functions per actor and +1%
instructions per measured operation as regression ceilings, not the objective.
Success is simpler ownership with identical maintained validation outcomes and
no new execution choice. Full-suite validation remains user-owned.

## Slice 8 ownership decision and gates

Nested relation traversal reads an owned copy of a cached root, then only walks
references into that value before producing independent target keys. Use the
existing borrowed value accessor instead. The structural reader remains the
decode/cache owner and the existing relation path interpreter remains the sole
traversal owner. The simplest alternative is keeping the unnecessary copy; no
new helper, mode, decoder, cache state or lifetime-bearing output is needed.

Keep validation before traversal, path order, optional/enum selection, collection
fan-out, raw-reference charging before deduplication, shared image/batch limits,
and key ordering unchanged. The reader must remain usable after projection, and
returned keys must remain valid after it is dropped. Retained-row output is a
separate candidate and is not included in this slice.

Baseline is completed slices 1–7. Measure actual nested target-key projection
with warm reader and cold/eager-reader costs separated. Exclude fixture setup;
report cumulative allocation requests, not peak memory or latency forecasts.
Use matched production empty and maintained nested-relation repeated actors,
SQL disabled, including populated relation IC operations. Before runtime edits,
retain +1 KiB final raw Wasm, +4 defined functions per actor and +1% instructions
per measured operation as regression ceilings. Require allocation savings for
heap-owning roots and unchanged outcomes. Full suites remain user-owned.

## Slice 9 ownership decision and gates

output. Consume it at that boundary. Extract the existing cache-taking portion
of direct projection as the reader's shared required-value take operation;
normal retained slots use that operation without adopting direct projection's
distinct scalar-storage shortcut. ScalarOctetLength continues to borrow bytes.
The simplest alternative is keeping the deep copies. No new mode, decoder,
cache state, output format or runtime behavior axis is needed.

Preserve filter-before-output and primary-key checks, retained slot order,
NULL/empty values, corruption rejection and unselected-slot laziness. Existing
repeated-slot reads remain valid through the reader's current refill behavior;
do not add another memoization layer. Non-filtered direct sparse/dense decoders
and full-row output are outside this slice.

Baseline is completed slices 1–8. Measure the actual retained decoder with
pre-materialized and cold-reader costs separated, including nested payloads,
scalar blobs and byte-length controls. Report cumulative allocation requests,
not peak memory or endpoint latency. Match production empty/dynamic-query
actors, SQL/Candid export disabled, with the same toolchain and pipeline.
Predeclared ceilings remain +1 KiB final raw Wasm, +4 defined functions per
actor and +1% instructions per maintained IC control operation. Require
allocation savings for copied heap values and identical outcomes. Empty-result
IC controls are not evidence of populated retained-output savings. Full suites
remain user-owned.

## Slice 10 ownership decision and gates

Owned query/mutation result rows currently borrow their values for public output
conversion and then drop the originals. Replace the existing converter's
borrowed input with an owned input, not a second recursive converter. Move
text/blob/big-integer leaves and recurse through owned lists/maps/enum payloads.
Public collection containers and catalog-owned enum labels still require their
own representation; this is not a zero-allocation output promise.

Keep the accepted enum catalog as the sole ID-to-label authority and retain
unknown-type/variant failures and traversal order. Express label borrows with
their catalog lifetime so enum bodies can move after resolution; add only the
consuming body accessors needed at the value owner. Exact-key output can take
cached values from its discarded reader, and schema payload rendering can
consume its admitted value. All other callers already own their rows.

The simplest alternative is retaining copies. State-space delta: none; no
borrowed/owned runtime mode, compatibility converter, format, cache or admission
path is added. Key reconstruction and mixed expression projection are separate
audit findings, not included here.

Baseline is published 0.255.0 with its current lockfile. Before runtime edits,
freeze production empty/dynamic/SQL actors under the same toolchain, feature
selection and post-link pipeline. Retain ceilings of +1 KiB final raw Wasm, +4
defined functions per actor and +1% instructions per maintained measured IC
operation. Measure the actual output converter on owned scalar/nested/enum
inputs with setup excluded; require fewer allocation requests for heap-owning
leaves. Report cumulative requested bytes, not peak memory or endpoint latency.
Preserve catalog errors, public wire values, typed/exact-key/grouped/SQL/mutation
response semantics, and precommit result limits. Full suites remain user-owned.

## Slice 11 ownership decision and gates

Session key reconstruction clones selected cached values and clones a singleton
again; SQL UPDATE/DELETE copy borrowed projection slices into temporary vectors.
Supported key components are fixed-size, so these are unnecessary value copies
and vector allocation, not large accepted text/blob payload copies. Add a
borrowed component-slice constructor at the existing data-key codec, sharing
its scalar/composite validation and compact encoding. Persisted-row assembly
moves values from its discarded reader; SQL borrows its existing projection.
Remove the session-owned assembly helper and its re-export. Eager row validation,
component order, supported kinds, arity errors and wire bytes must be unchanged.

The simplest alternative is retaining the copies. State-space delta: none;
no new execution mode, key format, decoder, cache or runtime authority. Generic
iterator-based key codecs and new borrowed row views are unnecessary here.
Mixed-expression projections and access-boundary key copies remain separate.

Baseline is the unpushed slice 10 worktree, not published 0.255.0. Freeze matched
production empty/dynamic/SQL artifacts before runtime changes; retain +1 KiB raw
Wasm, +4 defined functions per actor and +1% IC-control instruction ceilings.
Measure actual row and projected-key reconstruction with setup excluded; SQL
projection must eliminate its temporary allocation while row reconstruction must
not add allocations. Run focused key, row-validation and mutation regressions.
Full repository/workspace validation remains user-owned.

## Slice 12 reader-reuse decision and gates

The write owner validates the resolved after-image, then its no-expected-key
branch opens and validates the same row again for key reconstruction. Reuse the
first reader and its accepted contract. The reader remains live for Identity
checks, so copy its fixed-size key components into the existing key-codec input
without taking and rematerializing cached values. SQL projected keys continue
to borrow their existing slices; no iterator codec or alternate assembly path
is needed. Keep the original whole-row validation before either key branch.

The simplest alternative is retaining duplicate row work. Canonical owners stay
the structural reader for accepted decoding and the data-key codec for key
construction. State-space delta: none; remove a reader lifetime and independent
contract argument without new modes, formats, authority or cache state. Preserve
Identity verification, expected-key validation, duplicate detection, accepted
component order and malformed non-key rejection.

Baseline is the complete unpushed slice 11, not an ablation or published 0.255.0.
Freeze the same production mutation actor, lockfile, toolchain, SQL features and
post-link pipeline. Use the identical temporary exact-UPDATE wrapper on both
sides for PocketIC balance-delta measurements at 1, 64 and 256 rows, three samples
each; retain ceilings of +1 KiB final raw Wasm, +4 defined functions and +1% cycles
per measured operation. Require fewer insert cycles and native row-preparation
allocation requests, while retaining all outcomes. Report raw/compiler/gzip
bytes, function counts and scoped complexity. Full suites remain user-owned.
