# 0.255 slice 8 — Borrowed nested-relation roots

Date: 2026-09-06. Explicitly authorized extension; active release 0.255.0.

## Outcome and ownership

Nested target-key projection now obtains its decoded root through the existing
borrowed reader accessor. The path interpreter already walks references and
emits owned keys, so its former deep copy served no ownership requirement.
The reader remains the decode/cache owner; the relation interpreter remains the
traversal owner. No helper, execution route, cache state, public API or storage
format is added. Filtered retained-row output is outside this slice.

Validation still precedes traversal. Optional/enum selection, accepted path
resolution, collection fan-out, traversal charging and raw-reference charging
before deduplication are unchanged. Direct tests cover reader reuse, independent
output lifetime, NULL/empty roots and rejection when repeated references exceed
the image limit even though the distinct target count would fit.

## Native allocation measurements

Baseline is completed slices 1–7. The temporary optimized core-test probe calls
the actual raw target-key projector. The accepted canonical root is a nullable
map from text to lists of Nat64 targets. Each text key contains a four-character
prefix plus 1 KiB of padding; lists repeat two target keys. The relation path
selects map values, not those large text keys, but the old root copy duplicated
all of them.

Fixture construction/encoding is excluded. Warm measurements start with a
materialized reader; eager measurements include validated reader creation and
selected-field decoding. Both include traversal, budgets, owned key generation,
sorting/deduplication and output cleanup. Nine batches of 100 operations have
identical allocation/reallocation counts and requested bytes in each shape;
expected output cardinality is asserted before timing.
