# 0.255 slice 12 — Reuse the validated insert reader

Date: 2026-09-06. Authorized after the slice 11 cycle audit identified a second
reader opening and validating the same resolved after-image. Active release
notes remain 0.255.1; published 0.255.0 and package versions are unchanged.

## Decision and boundaries

The write owner already validates every after-image slot before choosing between
an expected key and reconstruction. Pass that reader to key reconstruction and
derive accepted key-slot order from its own contract. Remove the second reader
and independent contract/row arguments. The expected-key branch, Identity
verification, collision checks, mutation staging and publication are unchanged.

Unlike slice 11's discarded reader, this reader remains live for Identity checks.
Retain its cached values and copy the fixed-size key components into the existing
codec input vector, avoiding cache take/refill. Do not introduce a generic key
iterator, alternate scalar assembly, validation bypass or new schema authority.
SQL UPDATE/DELETE continue borrowing their projection slices unchanged.

## Baseline and method

Baseline is the complete unpushed slice 11 implementation over published
`v0.255.0`, commit `a057a80b62d70227d39f2b60cdedb05928ba8869`, not either temporary
ablation from the diagnostic audit. Existing public-output and unrelated
Wasm-audit changes are preserved and not credited to this slice.

Evidence is archived at `/tmp/icydb-0255-reader-reuse.Cucnvm`, including the
pre-edit source/docs, matched Wasm, cycle log, allocation scaffold and validation
logs. Production compilation uses the same isolated source path as the earlier
baseline, Rust 1.97.1, unchanged lockfile, SQL enabled, Candid export disabled,
wasm-release profile, Binaryen 132 and canonical post-link pipeline.

The maintained `group_path_sql_query` actor has scalar Int64 keys and nested row
payloads. Both cycle subjects include the identical temporary exact-UPDATE
wrapper from the earlier audit, using the maintained internal API. No endpoint
is added to repository actors. Native allocator instrumentation is absent from
both production artifacts.

Predeclared ceilings: at most +1 KiB final raw Wasm, +4 defined functions and
+1% cycles for each measured operation; require lower insert cycles and fewer
native allocation requests. All ceilings and required improvements pass.

## Native allocation results

The temporary probe measures the existing caller's validated-reader construction
plus key reconstruction. For the baseline it uses a frozen copy of slice 11's
helper, which creates the second reader; the candidate calls the new production
helper. Both run in one native test binary with the same accepted contracts,
rows and allocator. Fixture setup and the harness's returned-key assertions are
outside the allocation window. A scalar case also measures reading and comparing
the Identity slot after reconstruction.

Nine samples of 100 operations agree on allocation counts and requested bytes.
These are cumulative allocation/reallocation requests, not peak memory or
whole-endpoint allocation counts. Native timing is diagnostic only.

| Key shape | Allocations before → after | Requested bytes before → after |
| --- | ---: | ---: |
| One component | 7 → 4 | 3,568 → 1,912 |

| Four components, accepted order differs from slot order | 7 → 4 | 3,568 → 1,912 |

That removes three allocation requests and 1,656 requested bytes per measured
preparation. The key operand vector remains; no zero-allocation claim is made.

## PocketIC cycles

PocketIC 16.0.0 uses an Application subnet, Normal cycle schedule and Production
instruction limits. Measurements are actual canister balance differences around
completed update calls, including call overhead and reply encoding. Installation
and startup are excluded. Each variant/population/sample uses a fresh installation;
variant order alternates across three repetitions. Every measured call advances
simulated time by exactly 1 ns, with no live-time mode or explicit time advance.

Insert/load is the maintained fixture-load call: an empty cleanup DELETE followed
by structural INSERT batches of at most 64 rows. UPDATE-one, UPDATE-all,
DELETE-one and DELETE-rest then run on that fixture in order. Returned counts,
updated values and the final empty state are checked. All 90 calls and data

## Validation and handoff

108 focused tests pass, including key codec/order/wire parity, malformed non-key
row rejection, shared reader values, Identity allocation/recovery, collision and
batch/result boundaries, and RETURNING coverage. One unrelated Identity recovery
timing benchmark remains ignored. All-feature test-target lint, SQL-disabled
library checking, formatting and whitespace checks pass. The native measurement
test and all 90 PocketIC measured calls/data checks also pass.

The initial native invocation used an unqualified name with exact matching and
selected zero tests. Its corrected targeted invocation selected and passed the
one measurement test without recompilation; only that run supplies allocation
evidence. The temporary allocator module was archived and removed from the
isolated source afterward. The temporary PocketIC server was stopped by its
wrapper; no existing network was restarted.

Full repository/workspace suites remain user-owned. No commit, push, release
tag, Cargo version or lockfile change was made. Slice 12 is ready for handoff;
no additional landing slice is started.
