# 0.255 slice 2 — Collection emptiness boundary

Date: 2026-09-06. Release entry: 0.255.0, alongside the unpushed first slice.

## Finding and decision

The suspected map-emptiness bug is not reachable through admitted queries.
The preflight examined `is_collection` and the runtime classifier, but missed
`ensure_field` in `db/query/predicate/validate.rs`: it rejects map fields with
`ValidateError::MapPredicateUnsupported` before operator-specific admission.
Map persistence does not imply predicate support. No runtime correction is
needed, and enabling map predicates would be a separate capability decision.

The proposed SQL parity assumption was also incorrect. SQL has no `IS_EMPTY`
or `IS_NOT_EMPTY` functions. Its maintained `LENGTH` function measures text,
not collection cardinality. The first test attempt used the unsupported names
and failed at parsing; the corrected tests exercise admitted SQL syntax and
its actual type boundary. No SQL function or fallback was added.

## Maintained regression coverage

The tests reuse the existing session fixture and publish accepted operand
schemas before inserting real rows. Eight isolated cases cover empty and
populated text, lists, sets and maps, without generated-model runtime authority.

- Both structural emptiness predicates select the expected text/list/set rows.
- Both map cases fail the shared predicate validator with the specific typed
  map rejection and also fail end-to-end structural query execution.
- Direct and parsed SQL `LENGTH(operand) = 0` / `<> 0` agree for stored text.
  Both routes reject lists, sets and maps with matching diagnostics; parsing
  succeeds, so the test cannot mistake a syntax failure for type admission.

The contracts now distinguish structural collection operations from SQL
functions and explicitly exclude maps. Production predicates, decoding,
normalization, NULL/missing behavior and storage formats remain unchanged.

## Validation and cost

All 33 focused tests pass, including both new stored-boundary tests, existing
session SQL/structural contracts, filter construction and slice 1 ownership
tests. All-feature core test-target lint, the SQL-disabled library check,
formatting and whitespace checks pass. No failures remain after correcting the
initial SQL fixture assumption above. Full repository/release validation remains
user-owned.

This slice adds no production code. Its cost is test and documentation coverage,
not another execution path: no runtime mode, authority, cache or state is added.
Nine files change in this slice, approximately +230 net lines: +139 test/module

Performance, IC instructions and raw/gzip Wasm/function deltas were not
