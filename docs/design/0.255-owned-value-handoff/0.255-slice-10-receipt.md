# 0.255 slice 10 — Consuming public-output conversion

Date: 2026-09-06. Explicitly authorized after the redundant-clone audit;
active release 0.255.1. Published 0.255.0 notes remain unchanged.

## Outcome and ownership

The existing accepted-catalog output converter now consumes runtime values.
Text, blobs and big integers move into their public variants; list/map elements
and enum bodies recurse by ownership. No borrowed fallback, second converter,
decoder, admission policy, public API, cache state or storage format is added.

Enum type/variant IDs still resolve once through the accepted catalog, before
payload traversal. Label accessors now expose their actual catalog lifetime,
independent of the runtime value. Two consuming body accessors allow the resolved
payload to move; public labels remain independently owned. Unknown-type/variant
errors and list/map/enum error order are unchanged.

Owned dynamic pages, structural projections, grouped rows, mutation results and
SQL/RETURNING rows pass their values directly. Exact-key output takes selected
values from its discarded reader after existing eager validation and key checks.
Schema descriptions consume their admitted value, removing its now-unused
borrowing accessor. The separate borrowed admission-proof type is unchanged.
Key reconstruction and mixed-expression projection remain outside this slice.

## Native allocation measurements

Baseline is published `v0.255.0`, commit
`a057a80b62d70227d39f2b60cdedb05928ba8869`. The temporary optimized core-test probe
invokes the actual converter with an owned input on both sides. Baseline borrows
that input for conversion and then drops it; candidate consumes it. Input
construction/cloning and expected-output checks are outside measurement. Output
and remaining input destruction are included; Candid encoding is excluded.

Nested fixtures contain N maps in a list, each holding a short text key and a
1-KiB blob. Enum fixtures wrap the same payload in a catalog-resolved variant.
Scalar text/blob fixtures contain 64 KiB; big integers have 4,096 decimal digits.
Nine batches of 100 operations have identical allocation/reallocation counts
and requested bytes for each shape.

| Input | Calls, before → after | Requested bytes, before → after |
| --- | ---: | ---: |
| Empty list | 0 → 0 | 0 → 0 |
| Enum containing empty list | 3 → 3 | 90 → 90 |
| 1 nested item | 4 → 0 | 1,799 → 0 |
| Enum containing 1 item | 7 → 3 | 1,889 → 90 |
| 16 nested items | 51 → 0 | 26,480 → 0 |
| Enum containing 16 items | 54 → 3 | 26,570 → 90 |
| 128 nested items | 390 → 0 | 213,632 → 0 |

The current optimized build also reuses collection backing storage during the
owned conversion. Zero allocations apply to these measured non-enum shapes,
not every possible output or a stable allocator/API guarantee. Enum output
still allocates its catalog labels and public payload box. These are cumulative
requested bytes, not peak memory, full-response cost or endpoint latency.
Host timing is diagnostic only; unchanged empty controls also vary, so no
production latency percentage is claimed.

## Production Wasm and IC gates

Matched production gates pass. Both sides use the published lockfile,
Rust 1.97.1, Binaryen 132 and ic-wasm 0.11.1, production feature selection and
the wasm-release/post-link pipeline. Candid export is off; empty/dynamic actors
have SQL disabled, and the SQL-query actor has SQL enabled. Candidate Rust is
frozen with temporary allocator instrumentation removed before builds.

| Actor | Final raw bytes, before → after | Raw delta | Gzip delta | Defined functions, before → after |
| --- | ---: | ---: | ---: | ---: |
| Empty, SQL off | 1,704,617 → 1,704,617 | 0 | +1 | 4,273 → 4,273 |
| Dynamic query, SQL off | 2,703,822 → 2,703,151 | −671 | −149 | 7,102 → 7,098 |
| SQL query, SQL on | 3,052,259 → 3,051,710 | −549 | +7 | 7,905 → 7,900 |

Compiler-stage raw bytes change by 0 / −785 / −682 respectively. Final raw
bytes are the primary size gate; gzip is secondary. All actors satisfy the
predeclared +1-KiB / +4-defined-function ceilings. The empty artifact is equal
in raw size and function count, not byte-identical. Full compiler/final sizes,
gzip sizes, defined-function counts and SHA-256 identities are in `wasm.jsonl`
in the evidence directory. The unchanged lockfile SHA-256 is
`ce0f4b967f998892752865242b05a057428344c468608b6a7887225f9443f3af`.

PocketIC 16.0.0 runs the maintained dynamic-query measurement against the saved
baseline and candidate artifacts, twice per variant with fresh installations.
Both samples agree exactly; each operation has 200 successful empty results.

| Operation | Instructions, before → after | Delta |
| --- | ---: | ---: |

These empty-result controls measure overhead, not populated-output savings;

stopped by its wrapper afterward. No existing network was restarted.

## Validation and complexity

Direct tests preserve text/blob backing addresses through recursive conversion,
public value and Candid-byte parity, enum payload ownership, labels surviving
catalog drop, unknown IDs and first-error order. Initial fixture compilation
used unsupported big-integer constructors; switching to the maintained parsing
API fixed it before the successful baseline/candidate runs. All 91 focused
regressions pass, including the three new tests. The initial parallel run was
terminated by SIGKILL with no failed assertion; the same selection passes with
one test thread after artifact builds, avoiding concurrent large schema fixtures.
SQL-disabled checking, all-feature test-target lint, formatting and whitespace
checks pass. Full repository/workspace suites remain user-owned.

Fourteen Rust files add 213 net lines: ten runtime lines, four test-module wiring
lines and a 199-line regression file. Five release/design/status/receipt files
accompany the change. The file count mostly reflects mechanical caller
propagation; ownership is simpler and one conversion authority remains.
These counts exclude the independently arriving Wasm-audit shell-test fix and
its release note, which were preserved without modification.

Evidence is retained under `/tmp/icydb-0255-public-output.5dQPA2`. No Cargo
version change, commit, push, next slice or minor-line closeout is included.
