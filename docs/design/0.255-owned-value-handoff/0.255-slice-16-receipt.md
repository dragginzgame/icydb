# 0.255 slice 16 — Dormant projection-validation removal

Date: 2026-09-07. Explicitly authorized after the slice 15 reachability finding.
Baseline: published `v0.255.2`, commit
`a479ebaf04c413035edab7445f42463fa4c8c937`. Release notes belong to 0.255.3;
Cargo versions and published notes remain unchanged.

## Decision and boundaries

The discarded-result validator had no maintained execution caller. Scalar paths
selected the no-projection or retained-output modes; the sole shared-validation
mode construction resolved grouped keys without running scalar materialization.
The [preflight](0.255-slice-15-preflight.md) records that baseline evidence.

Remove that mode, validator, row-read trait and adapters, validator references and
flags, validation-only slot requirements, and the unused layout cache resident.
Payload finalization uses its existing strategy directly instead of a wrapper
whose other responsibility was the dormant validation pass. Grouped key-stream
setup selects the existing no-projection mode.

Prepared projection metadata still serves actual output evaluation and raw-row
selection for field paths. Retained slots for output, ordering and cursor anchors
remain. Scalar/grouped expression evaluation and accepted-row decoding keep their
existing owners. No API, format, authority, cache, mode or alternate evaluator is
added. This is a simplification, not evidence of saved per-row validation clones.

## Matched method

The maintained `group_path_sql_query` actor is built sequentially at the same
isolated source path, first from published 0.255.2 and then with the complete
candidate. Both include the identical temporary query-as-update wrapper solely
to measure actual PocketIC cycle debits. The wrapper invokes the existing trusted
query API and is not committed or added to any production endpoint. No endpoint
security or transport surface is widened.

Both builds use Rust 1.97.1, unchanged package versions and dependencies, SQL on,
Candid exports off, the production `wasm-release` profile and the canonical
Binaryen 132 post-link pipeline. Cargo.lock SHA-256:
`a3696bf10cc778399a488ea8f781abe58466ed94117a9a6a13dd7b4497045a3e`.
Toolchain file SHA-256:
`559f488c181e0e9e77cf17c29de663977f036ec7ff2e2060585714bf53c52d62`.

Predeclared ceilings: +1 KiB final raw Wasm, +4 defined functions and +1% cycles
per control. Slice 14's function-count exception does not apply. No synthetic
allocation reduction is required or claimed for the unreachable row walk.

The cycle matrix uses fresh instances, alternating baseline/candidate order,
three samples at 1/64/256 rows, and cold/warm executions of six controls: direct
nested projection, repeated nested output, mixed expression, nullable field path,
empty result and grouped COUNT. Output parity is checked between subjects;
counts, repeated values, arithmetic, nullable values and grouped frequencies are
also checked against the fixture. Cycle balances surround only the measured call,
excluding setup and host-side checks. These are local matched controls, not a
general throughput or endpoint-latency claim.

Evidence roots: `/tmp/icydb-0255-projection-validation.UmnIto` (isolated source,
build logs and artifacts) and `/tmp/icydb-0255-dead-validation.JTHVVP` (probe,
lint/test logs and measurement reports).

## Cycle result

All 216 measured calls pass the fixture checks and baseline/candidate output
parity. Three samples agree exactly for every cell on PocketIC 16.0.0 with
Application/Normal/Production settings. The following absolute deltas are
identical at 1, 64 and 256 rows:

| Control | Cold cycle delta | Warm cycle delta |
| --- | ---: | ---: |
| Direct nested, repeated nested, mixed expression, empty result | −47 | +9 |
| Nullable field path | −65 | −9 |
| Grouped COUNT | −136 | −94 |

Baseline calls cost between 12,183,389 and 88,846,332 cycles. The largest increase
is **9 cycles (+0.00006877%)**, well within +1%; the largest relative decrease is
0.00100337%. Treat performance as effectively unchanged. The size-independent
deltas do not support a per-row clone-saving claim.

The maintained wrapper started and stopped the temporary localhost PocketIC
server for both the initial probe and corrected run; no local network is left
running by this measurement. The corrected run completed successfully in
24 seconds. Host probe edits did not alter either measured Wasm artifact.

## Validation and complexity

- 110 focused tests pass across projection output, compiled-expression errors,
  nullable/repeated/nested values, accepted admission and corruption, session
  cache reuse, grouped fold/output, retained slots and page coordination.
  One unrelated native timing benchmark is ignored. Existing maintained tests
  are reused; no tests are added for the absence of the removed mode.
- Compilation, SQL-disabled checking and focused lint pass. Lint identified one
  helper newly eligible for `const`; the qualifier is corrected. The required
  repository-wide lint recovery and focused rerun pass. Full test suites remain
  user-owned and were not run.
- The first temporary cycle probe expected Int64 arithmetic output, but the
  published baseline correctly returned Decimal. The probe expectation was
  corrected to the existing contract; this did not require a runtime change.
  The failed probe log is retained separately from the matched rerun.
- Sixteen Rust files: 36 added and 304 removed lines, net **−268**. The flow is
  simpler: one fewer mode, one fewer cache resident and no validator forwarding
  or post-scan validation wrapper. Documentation and release-note changes are
  tracked separately from this runtime footprint.

All slice 16 gates pass. Mixed-expression ownership remains an independent
follow-up; this receipt does not authorize another slice or minor line.
