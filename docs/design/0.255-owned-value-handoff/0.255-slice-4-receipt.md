# 0.255 slice 4 — Owned full-row output

Date: 2026-09-06. Explicitly authorized extension; active release 0.255.0.

## Outcome and scope

`StructuralSlotReader::decode_all_values_into` consumes the reader, materializes
all slots through its existing required-value authority, then moves the cached
values into the caller's output buffer. No clone, alternate decoder or new cache
state is needed. The caller still clears stale output, eagerly validates the row
and checks the authoritative primary key before handing over ownership. Buffer
capacity is reused. A consumed reader cannot expose emptied cache cells later.

The production caller is the full-row identity projection used by SQL's
non-paged projection request. Ordinary paged dynamic requests use output-work
admission and their existing projection path. Direct projections, duplicate-field
output copies, retained-slot reads and borrowed constraint operands are unchanged.
This is not a general read-speedup claim or a new SQL endpoint.

Accepted authority, strict canonical admission, resource bounds, NULL semantics,
field order and typed failures stay with their existing owners. No format,
package version or public API changes.

## Native full-row measurement

Baseline is the staged slices 1–3, not 0.254.2 runtime behavior. The temporary
probe uses the maintained accepted targeted-rule fixture, but measures full-row
decoding rather than constraint evaluation. The row has scalar, named recursive
record, tuple, enum, list, set, map, text and blob values; N controls the recursive
record's child count. Expected values are checked before measurement.

Accepted layout preparation, fixture/program construction and canonical row
encoding are excluded. Each measured operation includes validated reader
creation, primary-key checks, all-slot materialization, ownership handoff and
output/reader cleanup. Each shape has nine batches of 100 operations on the
optimized all-feature native core test target. Allocation counts include
allocation/reallocation requests; bytes are cumulative requested storage, not
peak/live memory. Counts and bytes are identical across all samples.

| N | Calls per row, before → after | Bytes per row, before → after | Median time per row, µs, before → after |
| --- | ---: | ---: | ---: |
| 0 | 61 → 50 | 12,784 → 11,998 | 7.267 → 7.203 |
| 1 | 77 → 62 | 15,464 → 14,344 | 8.561 → 8.759 |
| 16 | 257 → 197 | 46,448 → 40,318 | 29.247 → 26.903 |

N=128 saves 43,538 requested bytes (-15.43%) and 396 allocation calls (-24.73%).
Host timing is diagnostic: the largest case is about 7.4% lower, while the
small N=1 case is about 2.3% higher. These short samples do not establish
application latency or IC instruction savings. The reported candidate timing
comes from a separate precompiled-binary run without competing Cargo builds;
the initial concurrently compiled samples are retained but not used for timing.

## Validation, complexity and handoff

110 focused tests pass across persisted-row ownership/admission, projection,
page work/cursor boundaries, stored query parity, row materialization, composite
key contracts and malformed persisted formats. One unrelated existing scalar
expression native microbenchmark remains ignored. All-feature core test-target
lint, SQL-disabled library check, formatting, whitespace and local doc links pass.
The user owns full-suite/release validation.

Four new tests cover heap identity at nested list/map/text/blob layers and scalar
blob slots, buffer reuse, nested/empty/NULL values, canonical scalar bounds,
wrong kinds, truncated rows and mismatched primary keys. The existing enum test
also covers consuming full-row output. No compatibility fixtures are added.

Measurement setup corrections: the first native probe had an incorrect import;
the first rejection fixture used by-kind storage instead of the intended strict
canonical storage contract. Both were corrected without changing runtime
admission. An initial Wasm build correctly rejected changing source inputs while
tests were being edited; frozen-source builds subsequently passed. A sandboxed
gzip subprocess probe failed, so the retained script uses in-process zlib.
No failures remain open.

Three Rust files add 204 net lines: +18 at the production boundary and +186 in
test/helper changes. Five release/design/status/receipt documents accompany them.
The eight-file slice adds approximately 390 lines overall, mostly tests and docs.
Ownership becomes simpler at the handoff; the reader performs a final consuming
cache pass but adds no behavioral state or parallel semantic authority.

Temporary native and IC probes are removed from the worktree; sources, logs,
snapshots and artifacts remain in `/tmp/icydb-0255-full-row.T3oLFA`. One isolated
PocketIC server was started with approved local access and stopped afterward.
Existing networks and the user's staged changes were left untouched. No commit,
push, version bump, direct-projection change or subsequent slice is included.
