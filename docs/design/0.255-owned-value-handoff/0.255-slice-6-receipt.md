# 0.255 slice 6 — Single canonical materialization

Date: 2026-09-06. Explicitly authorized extension; active release 0.255.0.

## Outcome and authority

The deferred structural reader skips separate prevalidation only when the
accepted field uses canonical wire. Its existing row-contract decoder already
decodes and strictly admits that value against the same accepted authority,
with a fresh standard admission budget. Previously prevalidation invoked that
same operation and discarded its owned result immediately before repeating it.

Lazy first access now invokes canonical decode/admission once rather than twice;
an accessed structural canonical slot after eager row validation invokes it
twice rather than three times. These counts describe complete operations, not
internal byte walks. Canonical wire scanning, recursive bounds and strict
accepted admission remain within the unchanged decoder.

Eager all-field validation, primary-key/error ordering, historical missing-slot
handling, noncanonical prevalidation and scalar fast paths are unchanged.
Eager validation still discards its temporary values: caching every field would
increase retention for selective consumers. Cache hits and exclusive take/reread
use the existing states. There is no new decoder, public surface, persisted
format, configuration or runtime behavior axis.

## Complexity and handoff

Two Rust files add 110 net lines: eight production lines for the documented
guard, one test-module declaration and 101 regression lines. The implementation
removes repeated work without introducing a new abstraction or state; the
existing canonical/noncanonical dispatch remains the only storage choice.
Five release/design/status/receipt documents accompany this slice.

The temporary allocator probe is removed from the worktree and retained with
logs and artifacts under `/tmp/icydb-0255-canonical.0VWa9M`. Initial probe setup
required a probe-local unsafe allocator allowance and exclusion of the synthetic
scalar/catalog fixture from eager full-row measurement. Both were corrected
before the successful matched runs; no lint exception remains in project code.
The user's staged snapshot and unrelated edits remain unchanged. No commit,
push, package version change, further slice or closeout is included.
