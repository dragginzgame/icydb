# IcyDB 0.219 Diagnostic Fact Inventory

Status: Patch 7 authority

Baseline: `v0.218.1` / `e05f4a9707952545402284c4933b27276f2b97b9`

This inventory freezes the numeric vocabulary available to every 0.219
subsystem projection. The code-owned registry in `icydb-diagnostic-code` is
authoritative; this document records its intended meaning and staged owners.

The leaf E-code remains the error reason. A fact supplies only one numeric
parameter for that reason. No fact may contain or identify arbitrary prose,
names, principals, SQL text, values, keys, rows, persisted bytes, cursor bytes,
or hashes of caller data.

## Global Contract

- Public representation: `tag: u8`, `value: u64`.
- Global error bound: 80 facts.
- Tags 1 through 89 are assigned below. Zero and 90 through 255 are unknown.
- Unknown tags remain numeric. They are never translated or treated as aliases.
- Two accepted `u32` identities use the registry-owned high/low packing helper.
- Successful execution does not allocate a fact sequence.
- Patch 1 changed the public record. Patches 2 through 5 activate the
  cursor, recovery, mutation-admission, batch-bound, stale-authority,
  query-planner, SQL, and accepted-constraint schemas recorded below; all
  other current E1 through E268 producers continued to emit an empty sequence
  until their owning patch. Patch 6 adds no engine fact producer: it resolves
  the existing exact schemas in host tooling only. Patch 7 activates the
  selected row, commit, index, and relation schemas recorded below; every
  unlisted producer remains deliberately code-only.

## Per-Code Schema Inventory

At the Patch 5 boundary only E6, the typed recovery/format leaves, E196,
E223, E225, E233-E240, the accepted stale-authority conflict, and the
query/SQL leaves described below emit facts. Every other existing E1 through
E268 producer has the exact schema `[]`.
This is intentional staged ownership, not an implicit fallback. Each following
patch activates exact required, optional, repeatable, and ordered tags at one
typed authority.

| Patch | E-code owners | Planned schema family |
| --- | --- | --- |
| 2 | E6, E18, E19, and typed recovery/format subreasons | active schemas frozen below |
| 3 | E196, E233-E240, and accepted stale-authority conflicts | active schemas frozen below; E232 remains code-only because it has no live typed producer |
| 4 | query/planner/SQL leaf codes whose typed variants already retain positions or bounds | clause/term/projection/group/aggregate/argument/branch/parameter indexes, arity, width, count, compact kinds |
| 5 | E223 and E225 | exact accepted fingerprint, entity/constraint identity, kind/context, operation, batch position, repeatable targeted-value path |

| 7 | selected storage, row, commit, index, and relation corruption leaves | layouts, slots, lengths, components, memory IDs, logical IDs, generations, arity, compact value/key kinds |

Errors not explicitly activated by their owning patch remain code-only. A
later patch may select fewer safe facts than this inventory permits, but it
must not introduce another tag, reinterpret a value, expose forbidden data, or
construct facts outside the typed subsystem that already owns the context.

## Ordering And Repetition

- Common authority facts precede operation/location facts.
- Expected/actual and bound facts follow location facts.
- Compact kind facts follow the identities they classify.
- Targeted-value path facts are the only generally repeatable family and form
  one final ordered suffix whose traversal order is semantically significant.
- Duplicate-position pairs use `First*` before `Duplicate*`.
- Unknown, disallowed, missing, repeated, or noncanonical facts are rendered
  numerically by host tooling and never change the E-code classification.

## Patch 7 Code-Only Storage Families

The following remain fact-free because their retained context is either
already categorical in the E-code or unsafe/unactionable at the public error
boundary:

- commit-memory stable-key collisions, whose only distinguishing values are
  internal stable-memory key strings;
- generic commit marker, journal, control-slot, replay, and checksum corruption
  where the failing identity exists only as raw bytes or a formatted invariant;
- persisted scalar and structured-value decode failures that retain only an
  authored name, raw payload, value, primary key, or field-kind debug string;
- index codec failures originating from arbitrary raw key bytes or a generic
  query prefix with no retained accepted index authority;
- reverse-relation corruption whose only locator is an index key, source or
  target path, field name, store path, row, or decoded value; and
- generic store, executor, index, relation, identity, and recovery invariants
  without one accepted numeric owner at the construction boundary.

No Patch 7 constructor stores a `String`, `&str`, arbitrary `Vec<u8>`, row,
value, or key as immediate public error context. Existing human-readable
arguments at compact constructors remain discard-only and do not cross the
public boundary.
