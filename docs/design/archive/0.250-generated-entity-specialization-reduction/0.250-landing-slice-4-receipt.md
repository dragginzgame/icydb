## Retained Outcome

The typed leaf now converts generated identifiers to the existing bounded
`PrimaryKeyValue` representation, then calls one concrete prepared exact-key
terminal. Core owns exact-key count and byte-budget validation, duplicate
lowering, store lookup and execution budgets. The facade-owned prepared-query
boundary validates the accepted binding and projects distinct present rows to
bound `OutputRow` values once.

Only the final `E::decode_row` loop and bounded reconstruction of duplicate and
input-order positions remain entity-generic. `get` remains a one-item
convenience over `get_many`; missing keys, duplicates and input ordering retain
their established semantics.

This hard-cuts the generic structural exact-key wrapper rather than retaining
two routes. It adds no cache, key format, unbounded lookup, execution mode,
persisted state or compatibility surface. Composite keys use the existing
`PrimaryKeyValue` encoding and the existing exact-key limits.

## Complexity Delta

The implementation and focused tests touch nine files at approximately
`+220/-100` lines. Most additions are direct exact-key boundary and semantic
tests. Production removes the entity-generic core lookup path and facade
structural wrapper, replacing them with one concrete `PrimaryKeyValue` input
and one prepared distinct-row result carrying bounded position metadata.

tested, while execution flow is simpler: encode once, execute and prepare once,
then decode distinct rows and reconstruct positions. Runtime state space stays
neutral, with no new behavior axis, route, registry, cache, persisted state,
callback or compatibility layer.
