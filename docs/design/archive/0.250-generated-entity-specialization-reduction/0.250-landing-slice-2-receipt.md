# IcyDB 0.250 Landing Slice 2 Receipt

Date: 2026-08-31

Disposition: retained by explicit user decision after simplification and a
second exact A/B. The final concrete prepared-page cursor missed the original
32 KiB code target by 1,799 bytes but removed 35,345 raw bytes, 30,969 code
bytes and 12 defined functions without increasing `call_indirect`.

## Retained Outcome

`PreparedLivePageCursor<C>` owns the non-entity part of bounded typed page
execution: one accepted binding and `DynamicQuery`, explicit public or trusted
execution, repeated-continuation validation, prepared-row construction, and
optional cursor-owned continuation for all-page consumers. Only final
`E::decode_row` remains entity-generic.

The retained shape has no lane enum, callback, trait object, function pointer,
generated vtable, compatibility path, or second query-builder surface.
`Query<E>` keeps its existing session, binding and `DynamicQuery` fields and
moves them into the concrete cursor only at a live-page terminal. Exhaustive,
grouped and exact-count terminals retain their existing owners.

Stateless `execute_page` and `execute_trusted_page` preserve caller-owned retry
semantics. Stateful `next_page` and `next_trusted_page` adopt a continuation
only after execution and preparation succeed; a downstream typed decode error
requires the consumer to discard that cursor. The existing `LivePageStep`
remains the one repeated-token validator.

## Candidate Evolution

The first candidate stored a public/trusted lane and duplicated the typed
query builder surface on the cursor. It reduced final Toko code by 27,201
bytes and raw Wasm by 31,578 bytes, with 13 fewer defined functions and flat
`call_indirect`, but missed the original code target by 5,567 bytes. It was
removed under the initial stop rule.

The user then explicitly directed that the useful work not be rejected solely
for that threshold miss and asked for a less-complex implementation. The
reopened candidate removed stored lane state, exposed explicit public/trusted
methods, and kept query construction with the existing `Query<E>` owner. That
improved the saving while reducing source and state-space complexity.

## Semantic And Cost Qualification

Focused tests cover caller-owned retry versus cursor-owned progress, stable
exhaustion, generated public/trusted adapter compilation and the maintained
live-page contracts. Selected package checks pass.

The frozen PocketIC operation controls remain well inside the material
regression boundary. Live-page calls changed by only +690 instructions on the
one-entity actor and +754 on the ten-entity actor. Exact-key, insert, patch,
batch and delete were unchanged or slightly lower, with the largest movement
being -244 instructions. No result, error, work, cursor, Candid, export or
persisted-format contract changed.

## Gate Decision

The original target was 32,768 final code-section bytes. The retained candidate
saves 30,969 bytes, or 94.5% of that target, and misses by 1,799 bytes. The user
explicitly approved reconsidering the candidate rather than rejecting it on
that threshold alone.

This is a recorded candidate-specific exception, not a reduction of the 32 KiB
design target. Retention is justified by the simultaneous raw/code/function
improvement, flat indirect calls, byte-identical Candid/export surface, passing
cost controls, and removal of the candidate's extra lane and builder
abstractions.
The alternative was to discard a measured 35 KiB raw saving despite no
demonstrated technical regression.

Production state space adds one transient cursor owner and no behavioral axis,
persisted state, execution route, format, or compatibility layer. The source
shape is modestly larger but the execution flow is simpler: old parallel typed
page wrappers and page-preparation ownership are replaced by one concrete
cursor, and the existing query builder remains the sole builder owner.

Implementation and focused-test changes touch nine files at approximately
`+312/-122` lines, including the new cursor module. With the root/detailed
changelog and design/status evidence, the complete slice touches 14 files at
approximately `+500/-235` lines. The implementation classification is simpler
execution with a modestly larger source surface.
