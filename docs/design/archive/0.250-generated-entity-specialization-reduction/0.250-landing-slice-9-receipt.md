# IcyDB 0.250 Landing Slice 9 Receipt

Date: 2026-08-31

## Outcome

Recursive caller-authored input values now stay inside the input root:

```rust
InputValue::list(Vec<InputValue>)
InputValue::map(Vec<(InputValue, InputValue)>)
```

Both constructors move their owned transparent wrappers into the existing
`PublicValue` recursive kernel. `InputValue` and `OutputValue` remain distinct
roots, and enum payloads still cross accepted-schema admission before becoming
runtime values. This is a pre-1.0 hard cut; the prior list/map signatures are
not retained through aliases, adapters or a dual API. Performing the safe
owned conversion means the two constructors are no longer `const`; no
maintained call site used them in a constant context.

Read-only inspection of Toko Miner found recursive `into_public()` noise only
in its industry and NFT-collection input builders. Both list and map forms can
remove every such call with this API. No downstream files were edited.

## Alternatives

| Shape | Evidence and disposition |
| --- | --- |
| Keep `Vec<PublicValue>` | Zero implementation delta, but exposes the shared kernel at every nested input call site; rejected. |
| Generic `IntoIterator` constructors | Removes caller-side `collect`, but specializes constructor/collection code for iterator, item and closure shapes; measured and rejected. |
| Owned concrete `Vec<InputValue>` constructors | One conversion owner, bounded code generation and direct recursive composition; retained. |
| Builder, macro or second input tree | Adds another public surface or recursive representation without owning new semantics; rejected. |
| Unsafe vector reinterpretation | Avoids a conversion expression at the cost of layout-sensitive unsafe code; unnecessary and rejected. |

The generic candidate happened to be 42 final raw/code bytes smaller than the
concrete candidate in the demo subject. That subject reaches only two list
iterator shapes, so it cannot bound specialization in larger generated
consumers. The concrete public signature is retained to keep code generation
independent of downstream iterator choices.

## Allocation And Representation

The constructors consume owned vectors and move nested values without cloning.
On the pinned Rust 1.97.1 toolchain, focused pointer-identity tests prove that
the outer list and map vector allocations are reused by the in-place collect
path. This observed optimization is not promoted to a new public allocation
contract. No second recursive value tree, box, callback, vtable or runtime
registry is added.

## Compatibility Evidence

- `PublicValue` remains the sole recursive Candid/Serde kernel.
- `InputValue` and `OutputValue` retain their transparent root layouts and
  shared Candid type/serialization shape.
- The focused demo Candid remains byte-identical at 29,007 bytes with SHA-256
  `d09fd58f56d66824b661db5faf7665ab855498a84bf501238998ac9c91e91042`.
- Accepted-schema round-trip coverage passes for nested maps, lists, unit enum
  variants and enum payloads authored entirely through `InputValue`.
- No schema, persistence, cursor, runtime `Value` or endpoint representation
  changes.

## Validation And Complexity

Focused value, accepted-admission, generator-macro, typed-adapter and demo
checks pass, as do focused all-target Clippy and both maintained Wasm gates.
Formatting and diff hygiene pass. Repository policy leaves the complete
release validation workflow user-owned.

The implementation touches seven Rust files and one maintained API guide. It
changes one existing public constructor owner in place and adds no independent
state, representation, execution route or generic convenience layer. The
implementation shape stays neutral while downstream call sites become simpler.
