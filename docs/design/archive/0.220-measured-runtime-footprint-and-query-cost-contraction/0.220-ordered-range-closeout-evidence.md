# IcyDB 0.220 Patch 7 — Ordered-Range Closeout Evidence

## Decision

Patch 7 selects the general `materialized_order` scalar-row family and retains
its current implementation. Complete current P1 evidence and the matching
2,048-row scale observation show that required key traversal, store access,
row validation, filtering, and required-slot decode dominate the family. The
bounded order and page windows are already a small fraction of the measured
work.

No benchmark-specific route, second materializer, inline/heap retained-value
variant, planner hint, or compatibility path is added. The remaining plausible
allocation candidate would add another retained-row representation without
evidence that it can meet the frozen 5% selected-family instruction gate. That
is the design's evidence-backed no-production-change outcome.

## Canonical Owner Trace

The current executor already applies the relevant contractions at one shared
authority boundary:

- the planner resolves one retained-slot layout before scanning;
- residual predicates execute against the opened raw-row reader;
- only projection and order slots needed after filtering are decoded;
- direct-field ordering borrows decoded slot values rather than cloning keys;
- scan-time top-K retains only `offset + limit + lookahead` candidates; and
- post-access ordering remains the sole final ordering authority.

The selected leading query requires its primary key and age for ordering and
its name for filtering or projection. Deferring those values would require a
second raw-row lifetime/re-read path. Replacing the current compact value
vector with an inline/heap variant would add a second storage shape across
scalar and grouped consumers. Neither change removes the measured mandatory
store/get and decode work, and neither has evidence for the required 5% total
instruction reduction.

## P2 And Clean-Source Gate

The current P1 and scale receipts are complete and environment-identical. The
maintained P1-to-P2 selector rejected their merge because the source worktree
is dirty, reporting `unclean P2 selection current subject`. This is the
intended fail-closed provenance behavior and was not weakened or bypassed.

Repeated P2 confirmation and the complete final build/Wasm matrix therefore
remain clean-source, user/CI-owned validation after the pending work is
committed. Until those results are recorded, the line status is
`implementation complete; awaiting full validation`, not complete.

## Impact

Patch 7 changes no production file and adds no runtime line. Relative to the
accepted Patch 6 handoff, raw Wasm, instructions, Candid, method exports,
dependencies, allocations, successful query results, ordering, cursors,

runtime simpler.
