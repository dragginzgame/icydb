## Stable-Tree Calibration And Limits

The high-cardinality calibration prefills 3,276 targets and direct sources,
then measures stable hit, miss, insert, replacement, reverse delete, target
delete and `RESTRICT` paths. Convergence is drained between phases so backlog
admission is not confused with the measured commit boundary.

| Phase | Rows | Instructions |
| --- | ---: | ---: |
| 64-step × 5,460-reference traversal | 349,440 work units | 16,778,809 |
| Prefill target | 3,276 | 778,605,943 |
| Prefill source / target hit / reverse insert | 3,276 | 2,818,658,711 |
| Target insert | 2,730 | 987,813,108 |
| Replacement target insert | 2,730 | 996,695,870 |
| Source insert | 2,730 | 2,843,979,256 |
| Source replacement / old+new reverse deltas | 2,730 | **4,928,211,587** |
| Source delete / reverse delete | 2,730 | 2,335,155,592 |
| Target delete | 2,730 | 1,383,032,951 |
| Replacement target delete | 2,730 | 1,370,812,064 |
| Stable target miss | 1 | 1,835,985 |
| Target `RESTRICT` | 1 | 2,646,943 |

The existing 16,384-unit commit window charges four units per row, one per
inserted reverse delta, and two per replacement's old/new reverse deltas.
Therefore:

```text
one-delta rows = floor(16,384 / (4 + 1)) = 3,276
two-delta rows = floor(16,384 / (4 + 2)) = 2,730
raw references / reverse deltas = 2,730 * 2 = 5,460
traversal work = 5,460 * 64 path steps = 349,440
```

The first 3,277th one-delta row and first 2,731st two-delta row both reject
through the typed commit-work boundary. This freezes the relation contract at:

| Counter | Exact limit |
| --- | ---: |
| Per-image traversal work | 349,440 |
| Per-image raw references | 5,460 |
| Per-batch traversal work | 349,440 |
| Per-batch raw references | 5,460 |
| Per-batch unique target lookups | 3,276 |
| Per-batch reverse deltas | 5,460 |

The worst measured admitted phase consumes 4,928,211,587 instructions. Against
the 40-billion IC update ceiling, 35,071,788,413 instructions remain; the
required 10-billion (25%) surrounding-work reserve is therefore preserved by
a wide margin. The existing 30-billion mutation execution ceiling remains
unchanged.

## Current-Form Identity And Path Fixtures

Both candidate schemas allocate relation IDs from `1` in canonical rooted
proposal order. `target_id` is ID 1 and keeps the direct fast path. The shallow
candidate freezes IDs 2–4 for enum-payload, optional-member and required-member
paths. The repeated candidate freezes IDs 2–4 for list items, map values and
set items. Optional and named transitions are explicit in every path program;
map keys and enum unit variants remain excluded.

The exact actor, identity, display path and instruction sequence live in the
single measurement contract used by focused tests. This manifest is the
implementation target for Slices 2–4; generated models do not become runtime
path authority.

## Validation Boundary

Focused actor compilation, build-policy/measurement-contract tests, both
real-canister measurement tests, and all four optimized production Wasm builds
pass. Full repository/workspace validation remains user-owned.
