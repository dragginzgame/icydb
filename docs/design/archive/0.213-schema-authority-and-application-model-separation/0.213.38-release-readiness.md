## 1. Verdict

**Ready after bounded corrections.**

The current code at `3ec85260a08ca2b7e442d8fda294fca5cf474ac9`

## 3. Feature And Dependency Matrix

| Selection | Effective contract | Result |
| --- | --- | --- |
| no features | accepted-schema runtime and structural mutation; no query or SQL frontend | passes |
| `query` | engine-neutral intent, planning, cache, executor, dynamic reads, and typed adapter | passes without `sql` |
| `sql` | `query` plus SQL parse/lower, SQL mutation/DDL, and SQL response adapters | manifest and tree prove `sql -> query` |
| `sql-explain` | `sql` plus SQL EXPLAIN execution/rendering | passes |
| `diagnostics` | independent runtime diagnostics; SQL attribution requires both features | passes alone and with SQL |

The relevant manifest edges are:

```text
icydb-core: query = []
icydb-core: sql = ["query"]
icydb-core: sql-explain = ["sql"]

icydb: query = ["icydb-core/query"]
icydb: sql = ["query", "icydb-core/sql"]
icydb: sql-explain = ["sql", "icydb-core/sql-explain"]
icydb: diagnostics = ["icydb-core/diagnostics"]
```

No reverse `query -> sql` feature edge exists. The one- and ten-entity typed
query canisters set `default-features = false, features = ["query"]` on both
runtime and build dependencies. Their generated code therefore compiles
without SQL. No-default production checks exclude both query and SQL.

The surviving SQL gates inside query-owned modules are scoped SQL extensions:
primary-only visibility for exact mutation selectors, resumable-update
fingerprinting, SQL lowering/error conversion, literal preview/rewrite
helpers, grouped SQL session orchestration, and SQL diagnostics. None is
required by typed or dynamic reads. Conversely, no shared scalar planner,
cache, executor, projection payload, or accepted value conversion remains
gated solely by SQL.

`icydb-core` intentionally expects dormant internal imports/dead code in a
production `query`-without-`sql` build because SQL is currently the only
frontend for some engine-neutral grouped, aggregate, cursor, and diagnostic
extensions. Call-site inspection confirms those items remain neutral rather
than importing SQL DTOs. This expectation weakens dead-code evidence for that
one build combination, but it is not a dependency reversal.

## 4. Frontend Convergence

### Typed

```text
DbSession::query::<E>
  -> TypedEntityAdapter::typed_binding
  -> Query<E> / DynamicQuery
  -> execute_public_typed_dynamic_query
  -> execute_public_dynamic_query_for_typed_binding
  -> current_typed_entity_binding_catalog
  -> StructuralQuery + accepted EntityAuthority
```

The generated type is used only for immutable source binding and final row
decode. It is absent from planning, execution, and persistence.

### Dynamic

```text
DynamicQuery
  -> accepted_schema_catalog_context_for_entity_name
  -> StructuralQuery
  -> execute_structural_projection_from_query
```

Public dynamic reads add `QueryAdmissionPolicy::default_bounded_read`;
trusted dynamic reads deliberately leave caller authorization/resource policy
to the trusted caller while retaining the same accepted planner and executor.

### SQL

```text
SQL parse/lower
  -> StructuralQuery + accepted EntityAuthority
  -> sql_select_prepared_plan_for_accepted_authority
  -> shared accepted query-plan cache
  -> shared prepared planner/executor
```

SQL retains a frontend compiled-command cache above convergence. That cache
does not replace the accepted-schema-bound shared prepared-plan cache.

### Shared lower flow

For overlapping scalar reads, all frontends converge no later than
`StructuralQuery` plus accepted `EntityAuthority`:

```text
StructuralQuery + accepted snapshot/fingerprint
  -> cached_shared_query_plan_for_accepted_authority_*
  -> SharedPreparedExecutionPlan
  -> StructuralProjectionContract
  -> execute_structural_projection_rows
  -> StructuralProjectionPayload
  -> output_value_from_runtime
```

Dynamic reads adapt the payload to `DynamicQueryResult`; typed reads decode
that result through the already-verified binding; SQL adapts the same payload
to `SqlStatementResult::Projection`. This is the latest scalar divergence.

SQL-only grouped queries use `StructuralGroupedProjectionResult`, the same
planner/executor expression machinery, and the same accepted public-value
converter, but retain a distinct grouped page/cursor envelope because typed
and dynamic APIs do not expose grouping. SQL write `RETURNING` likewise keeps
mutation-specific atomic row/byte bounds. These are necessary distinct
response lifecycles, not replacements for the deleted scalar projection DTOs.

| Concern | Canonical owner | Evidence |
| --- | --- | --- |
| semantic query | `db::query::intent::StructuralQuery` | all three lower flows reach it |

`PreparedProjectionContract` remains executor-owned prepared
materialization validation; it is not a second frontend projection contract.
`RowProjectionOutput`, `SqlStatementResult`, and `DynamicQueryResult` are
outward DTOs at different public boundaries and carry no planner authority.

Exact active-source searches found no `SqlProjectionContract` or
`SqlProjectionPayload`. Historical design/changelog references correctly
describe their removal. No structurally equivalent SQL scalar runtime carrier
was found.

## 6. Accepted-Schema Authority

Typed currentness is resolved through `current_typed_entity_binding_catalog`,
which rechecks database incarnation, entity source identity/tag, field source
identities/IDs/slots, accepted revision/fingerprint, and layout generation.
Dynamic and SQL name resolution both return an accepted catalog context before
planning. Shared cache identity includes the accepted schema revision,
version, fingerprint method/version, fingerprint, entity path, store
visibility, and structural query key.

No `EntityModel`, `IndexModel`, Rust `TypeId`, generated entity descriptor,
generated row codec, or authored proposal appears in the query planner,
executor, cache, or query session. `PhantomData<E>` remains only in the public
typed adapter object. Recovery reconstructs accepted catalogs/layouts and the
same cache is rebuilt lazily from accepted authority; no SQL-specific recovery
assumption or generated fallback was found.

## 7. Bounds, Atomicity, And Formats

- Public typed/dynamic reads use the same post-plan admission evaluator and
  reject missing limits, full scans, materialized sorts, unsafe routes, or
  row bounds above 100 before row execution.
- Trusted dynamic and generated/controller SQL are intentionally trusted
  lanes. They share engine hard bounds and the accepted planner/executor, but
  caller-specific final encoded-response limits remain the endpoint's
  responsibility as documented in `docs/contracts/READ_ADMISSION.md`.
- Scalar projection conversion collects all rows fallibly before constructing
  the outward DTO; conversion failure returns an error rather than a partial
  result.
- Grouped execution retains hard group and memory limits; SQL mutation
  `RETURNING` retains its separate atomic row/encoded-byte bounds.
- Null and nested value conversion is centralized through the accepted enum
  catalog. Corrupt conversion maps to a typed query invariant failure.

`git diff --exit-code v0.213.37..HEAD` reports no change to
`SqlStatementResult`, SQL shared result types, or facade SQL conversion DTO
definitions. `DynamicQueryResult` has the same fields and derives before and
after R7. A format-constant diff search found only new version-1 test stable
keys; it found no changed magic, method version, format version, or
discriminant. No accepted schema, row, index, cursor, commit, marker, journal,
receipt, recovery, or existing public response format changed.

## 9. Findings

### P1 — Query-only canister runtime proof was invalid

Evidence: both audit endpoints used `ORDER BY id LIMIT 1` without a predicate.
Their first focused PocketIC run failed with E184
(`UnboundedFullScanRejected`).

Consequence: the canisters proved feature compilation but not executable
query-only typed behavior; the planned release claim would have overstated
negative-space coverage.

Correction: both endpoints now use exact `id = Ulid::MIN` primary-key access,
and `testing/integration/tests/query_canister.rs` installs and executes both.
The final tagged-HEAD run passes.

### P3 — Stale SQL-owned projection terminology

Evidence: comments in SQL select/runtime modules still described a “SQL
projection contract/payload” after ownership moved to the query session.

Consequence: no behavior defect, but misleading ownership documentation.

Correction: comments now name the shared structural projection contract and
execution handoff.

### P4 — Post-fix Wasm measurements were stale

Evidence: exact-access endpoint code adds 5,368 raw bytes to each maintained
query audit artifact relative to the pre-correction figures.

Consequence: the tagged detailed changelog and R7 status/design figures are
incorrect unless the current documentation corrections are included.

Correction: all three maintained 0.213 documents now use the measured raw
sizes and explicitly distinguish focused PocketIC evidence from the skipped
full integration suite.

### P4 — Published delivery reference omits final documentation

Evidence: remote `v0.213.38` was pushed before this report and the corrected
size documentation.

Consequence: the published tag omits required release-readiness evidence and
retains stale figures.

Remaining action: commit the four documentation files, then follow the
release owner's explicit policy for an already-published tag. Do not silently
force-move the tag.

No P0, additional P1, or P2 finding remains.
