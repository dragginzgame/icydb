## Authority Goal

0.213 establishes this one-way boundary:

```text
icydb-model declarations
        |
        v
host-only application model
        |
        v
bounded icydb-schema fragments/proposal
        |
        v
catalog-native reconciliation
        |
        v
accepted schema
        |
        v
runtime planning, admission, persistence, recovery, and integrity
```

Generated application metadata remains proposal and adapter input. It never
becomes accepted or runtime database authority.

### N1 Completion

N1 inspected current source-rule lowering, source expressions, accepted
constraint kinds and row-program compilation, accepted enum/composite/source
binding identities, and finite cyclic-value admission. The old boundary is
confirmed fail-closed: only top-level newtype-to-primitive chains lower, while
rules below records, enums, collections, tuples, or repeated fields reject.

The frozen correction identifies each constraint by persisted root field,
ruled nominal type, and rule source. Accepted binding replaces the source
field/type identities with `FieldId` and `AcceptedNamedTypeIdentity`. It does
not persist or expand the route through a recursive schema graph. Runtime
evaluation walks each finite admitted value and applies the rule to every
occurrence of the target type, using accepted record-member and enum-variant
IDs for traversal and diagnostics.

Top-level source rules will move to the same targeted-rule representation in
N2; the old lowering to a general source check will not survive in parallel.
Manual row `CHECK` expressions remain distinct but share scalar comparison and
length semantics with the targeted evaluator. Application validators,
normalizers, defaults, timestamps, unique proofs, and relations retain their
separate authority and lifecycle.

N1 changes the design, status tracker, and originating audit disposition only.
It changes no Rust code, public API, persisted bytes, runtime instructions, or
Wasm. Formatting and documentation-link/diff checks are the applicable
validation. Root `Unreleased` remains empty because this is a design-only
landing patch under the changelog governance rule.

### N4 Completion

Accepted row-constraint compilation now builds one
`CompiledAcceptedTargetedRules` artifact from the accepted snapshot and value
catalog. Rules sharing a persisted root use one finite value walk rather than
repeating structural traversal per constraint. Each rule still retains its
accepted constraint ID, source-bound name, target identity, and closed
operation; the compiled catalog handle exists only when targeted rules are
present.

Traversal is iterative and uses no Rust call-stack recursion or runtime
visited-type set. Records visit stable `CompositeFieldId` order, tuples visit
declaration order, enums visit only the selected accepted variant payload,
lists preserve element order, sets use admitted canonical order, and maps use
canonical entry order with each key before its value. Newtypes remain nominal
coordinates over their canonical underlying value. Finite values admitted
against cyclic named-type graphs therefore terminate without suppressing
repeated runtime occurrences.

Targeted numeric minimum/range operations use the same strict accepted-value
comparison primitive as row `CHECK` constraints. Text character length, blob
octet length, and list/set/map cardinality likewise share the check
evaluator's length primitive. Null occurrences pass vacuously and empty
collections still evaluate a rule attached to the nominal collection itself.

Violations retain the first deterministic identity-only path: root `FieldId`,
record member ID, tuple ordinal, newtype ID, selected enum/variant IDs,
list/set index, or map entry and key/value side. Display names are neither
stored nor parsed. Evaluation is bounded by the existing accepted depth of 64,
at most the 4 MiB admitted-value work ceiling in visited nodes and scalar
operations, and 64 path components. Depth, node, operation, path, and
value/catalog shape failures remain distinct typed internal errors.

At the N4 handoff, the production row program ran the compiled targeted
evaluator and preserved typed internal violation paths, while compliant values
still returned the explicit integration-pending failure. That temporary
fail-closed boundary prevented bypass before N5 integrated final-after-image
ordering and the public mutation diagnostic.

Focused validation passes for all 19 accepted check/row-program tests and all
19 application-lowering tests. No-default and all-feature core Clippy pass
with warnings denied, the public facade checks at both feature extremes, and
formatting plus diff hygiene are clean. Full repository tests remain
user-owned. Runtime instruction performance and raw non-gzipped Wasm were not
measured at the N4 boundary; N7 owns comparable release evidence.

## 0.213 Addendum: Cyclic Graph And Payload-Enum Completeness

0.213 must not close while accepted schema requires every named-type contract
graph to be acyclic. The reference application has maintained entities whose finite persisted values
use a recursive declaration shape: a record or map contains an enum, and one
of that enum's indirect payloads contains the owning record or map again. The
concrete regression shape is:

```text
Values = Map<FieldKey, FieldValue>
FieldValue = One(Box<Value>) | Many(Vec<Box<Value>>)
Value = ... | Record(Box<Values>)
```

This is a required database capability, not only a diagnostic correction.
Generated Rust indirection makes each runtime value finite, while the declared
named-type graph is cyclic. Accepted schema must represent the graph through
stable enum/composite IDs instead of recursively inlining it.

Patch 9 must also retain a separate acyclic payload-enum correction. IcyDB
0.202.1 omitted structural payload metadata when an enum variant's named
payload used a qualified Rust path, causing the accepted catalog to classify
the payload variant as unit. The maintained reference application regression is:

```text
ClaimCostTiers = Map<Tier, ClaimCost>
ClaimCost = Unspecified | Free | Icp(Tokens) | Icrc1(TokenAmount)
```

When `ClaimCostTiers` is nested in a persisted `Collection` or `Vendor`,
`Free` persists but `Icp(...)` and `Icrc1(...)` reach admission with a payload
against a unit catalog contract and collapse to Serialize-origin `E24`. The
model declaration is valid. The specific qualified-path metadata defect was
corrected in IcyDB 0.208.0, but the 0.213 compiler/catalog transfer must carry
that behavior forward and lock it with direct regression coverage.

## 0.213 Addendum: Single Durable-Rule Authority

0.213 must not close with one logical restriction implemented independently as
both an `icydb-model` Rust validator and an accepted database constraint. That
would create two evaluators, two diagnostic paths, and an inevitable semantic
drift risk across typed, structural, and SQL writes.

A rule has exactly one semantic owner:

- a durable row invariant is declared once as bounded source-rule metadata,
  instantiated as an ordinary accepted constraint at each persisted field
  use, and evaluated only by IcyDB's accepted constraint evaluator; or
- a rule that is contextual, external, transformation-dependent, or outside
  the frozen accepted expression language remains an explicit application
  validator and makes no database-enforcement claim.

Patch 10 must replace, rather than supplement, current built-in validator
attachments whose numeric range, comparison, multiple-of, or bounded length
semantics are representable by accepted constraints. It must not infer
durable semantics from a Rust callback body, function path, or validator name.
Early typed validation of a durable rule must use the live accepted-schema
validation API instead of a generated Rust mirror.

Reusable rules receive one current source name. Each persisted field use
derives a deterministic `ConstraintSourceKey` from that rule name and the
consuming `FieldSourceKey`; accepted schema remains the only runtime
authority. Pre-1.0 migration is a hard cut: no dual declaration, fallback
callback, compatibility evaluator, or silent validator-to-constraint guess is
retained.
