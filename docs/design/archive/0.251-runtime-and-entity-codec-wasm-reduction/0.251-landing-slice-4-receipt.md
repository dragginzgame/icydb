# IcyDB 0.251 Landing Slice 4 Receipt

Date: 2026-09-01

Disposition: retained. One concrete binding-owned ordinal write encoder removes
generated field-name construction and resolution, improves both maintained
reachable actors and reduces the exact disposable Toko actor by 11,170 final
raw bytes and 11,174 code-section bytes. `call_indirect` remains flat.

## Retained Outcome

Generated insert, patch and replace adapters now create one pre-sized
`BoundWriteEncoder`, append authored `WriteCell<InputValue>` values by static
descriptor ordinal and finish through one concrete owner. The generic
name-driven `TypedWrite::insert`, `update` and `replace` constructors are
removed as a pre-1.0 hard cut. Typed delete remains the key-only terminal.

The ordinal is binding-local metadata, not accepted-schema authority or a
physical slot. The opaque binding requires canonical increasing ordinals and
rejects duplicate, out-of-order and out-of-range input. Existing typed mutation
admission verifies the complete binding against the current accepted snapshot,
resolves each ordinal to its accepted field ID and slot, checks that identity
against the accepted row contract and lowers into the unchanged canonical
mutation executor.

Insert, patch and replace share the same cell encoder. Generated leaves retain
only operation-specific key construction and final Rust-to-`InputValue`
conversion. No callback, trait object, function pointer, vtable, registry,
runtime mode, mutation terminal or alternate commit/recovery route is added.

## Measured Alternatives

Two earlier concrete shapes improved the slope but grew both deployable actors,
so they were rejected before downstream qualification:

| Candidate | One raw delta | Ten raw delta | Raw slope | Disposition |
| --- | ---: | ---: | ---: | --- |
| Accepted-ID/slot vector plus ordinal input vector | +1,627 | +1,500 | 40,063 | Rejected: two retained vectors and absolute growth |
| One ordinal vector plus set-based duplicate validation | +718 | +586 | 40,058 | Rejected: absolute growth |
| One ordinal vector plus canonical-order scalar validation | -340 | -477 | 40,053 | Retained |

The retained form uses generated descriptor order as the duplicate-proof and
needs only one previous-ordinal scalar. It seals the existing vector into the
typed patch without copying it. Erased callbacks, trait objects and
function-pointer tables were not attempted because they add the indirect
machinery already rejected by the line design.

## Semantic, Allocation And Complexity Evidence

Focused coverage preserves omitted/default/null/value cells, database-owned
primary-key rejection, insert/update/replace lowering, accepted rename and
name-reuse resolution, stale and cross-store binding rejection, same- and
mixed-entity batch ordering, bounds, atomic late failure and one-marker
recovery. Generated macro coverage proves managed fields stay absent and all
three authored operations use the concrete encoder. The public identity compile
contract and the disposable Toko design package check pass.

Before this slice, a generated write allocated its field vector, the generic
facade allocated a second vector plus one owned source-name string per field,
and core binding allocated a third accepted-ID/slot vector. The retained form
allocates one pre-sized ordinal/cell vector and moves it through binding and
execution. It therefore removes two vector allocations and all per-field name
allocations without adding a per-row or per-field replacement allocation.

Production plus focused tests touch seven files at `+159/-167` lines. The
implementation adds one hidden concrete generated-code boundary while deleting
three public generic constructors and the name-binding helper. Source and
execution flow are both narrower; runtime state space remains neutral.

No separate instruction benchmark was added because encoding allocates less
and the canonical mutation executor, stable writes and cycle charging are
unchanged. The maintained raw/code gates and heterogeneous downstream artifact
are the cost authorities for this slice.
