# IcyDB 0.251 Landing Slice 2 Receipt

Date: 2026-09-01

Disposition: compact metrics candidate rejected; no production metrics feature,
state, sink, event vocabulary or endpoint behavior retained.

## Outcome

The compile-time compact-state candidate reduced the frozen SQL-off basic actor
from 1,923,249 to 1,915,489 final raw bytes. The 7,760-byte saving is well below
the 32 KiB retention gate, so the candidate and its `metrics-extended` feature
axis were removed in full.

Relative to the frozen basic actor, removing all observable report/reset work

delta belong to the exact endpoint/Candid boundary rather than the authorized
compact state/sink owner. The probe was restored immediately and never formed
a production candidate.

## Candidate Shape And Complexity

The rejected implementation selected one state and one global sink at compile
time. Basic builds used fixed common counters, SQL counters only under `sql`,
and an insertion-ordered `Vec` of reference-counted entity paths. Extended
builds retained the established rich state and dispatch. Report construction
borrowed state directly and emitted sparse code/value pairs without cloning the
whole state.

For existing entity rows, the compact sink introduced no per-event allocation;
the first event for an entity allocated one shared path and counter row. This
traded the rich state's ordered-map machinery for linear entity lookup and
insertion ordering at report time. The candidate affected about thirty
production, test and manifest files and added an independent Cargo feature
axis. That is materially more complex than the retained implementation, while
recovering only 7.6 KiB raw.

The following alternatives were considered and rejected:

- keeping both compact and rich states would add synchronization and runtime
  state instead of removing it;
- runtime sink selection, callbacks, trait objects or function-pointer tables
  would add indirect execution machinery;
- changing the compact response or numeric meanings would violate the exact
  public Candid contract; and
- removing scoped-sink, query-context, reset or window behavior would trade
  public behavior for size.

## Validation And Restoration

The final SQL-off candidate passed strict library linting and four focused
compact metrics tests covering counter meanings, error collapsing, ignored
rich-only events, reset/window/query behavior and scoped-sink precedence.
Earlier compile variants also exercised SQL-selected compact counters and the
extended rich metrics suite. The raw-Wasm gate then short-circuited the wider
candidate matrix, as required by the retention rule.

After rejection, every change under `crates/` and every production feature
forwarding change was restored to the immutable `v0.250.1` source. Only this
measurement receipt and the existing Landing Slice 1 harness/documentation
remain. Runtime allocation behavior, Candid, metrics semantics and public API
are therefore unchanged.

## Next Slice
