# IcyDB 0.251 Runtime And Entity Codec Wasm Reduction Status

Status: COMPLETE — LANDING SLICE 6 QUALIFIED; 8 KIB REACHABLE GATE RETAINED

Last updated: 2026-09-01

## Decision

The user explicitly requested a 0.251 design from the post-0.250 Wasm evidence.
The line addresses two separately measured costs in order:

1. basic metrics retaining the rich state and event pipeline; and
2. generated row/write leaf work remaining above a genuine 2 KiB reachable-
   adapter budget.

The initial line contains six substantive landing slices. Lower-confidence
schema no-removal and sorting candidates are recorded as conditional follow-up,
not folded into the planned work.

Landing Slice 1 froze IcyDB 0.250.1 at immutable tag `v0.250.1`, added the
controlled metrics matrix and refreshed the maintained and downstream codec
controls. Landing Slices 2 and 3 measured and removed compact metrics and
ordinal row-decoder candidates that did not pass their raw/code gates. Landing
Slice 4 retained one concrete binding-owned ordinal write encoder after both
maintained actors and the exact heterogeneous Toko control improved. Slice 5
measured and removed a lossless compact descriptor after it grew both
authoritative raw/code artifacts and worsened the entity slope. Exact evidence
is in the
[Landing Slice 1 receipt](0.251-landing-slice-1-receipt.md),
[Landing Slice 2 receipt](0.251-landing-slice-2-receipt.md) and
[Landing Slice 3 receipt](0.251-landing-slice-3-receipt.md); the retained write
result and rejected descriptor result are in the
[Landing Slice 4 receipt](0.251-landing-slice-4-receipt.md) and
[Landing Slice 5 receipt](0.251-landing-slice-5-receipt.md). Landing Slice 6
reproduced the final controls and closed the line; see the
[Landing Slice 6 receipt](0.251-landing-slice-6-receipt.md).

The 2 KiB gate was a schema-generation budget. It does not describe an actor
where every generated adapter is reachable. The source measurement is the
[0.250 Landing Slice 6 receipt](../0.250-generated-entity-specialization-reduction/0.250-landing-slice-6-receipt.md#maintained-reachable-entity-result).

| Final raw Wasm | 2,871,318 | 2,911,506 | 40,188 | 4,466 |
| Code section | 2,706,204 | 2,744,808 | 38,604 | 4,290 |
| Defined functions | 7,451 | 7,524 | 73 | 9 |
| `call_indirect` | 717 | 717 | 0 | 0 |

At most 18,432 raw bytes may remain across nine added entities to establish a
2,048-byte full-adapter ceiling. The recorded comparison therefore requires at
least 21,756 raw bytes of additional reduction.

The published 0.250.1 runtime rebuilds the same pair at 40,190 raw bytes, or
4,466 rounded bytes per entity. This is the authoritative 0.251 baseline and
requires 21,758 bytes of additional reduction to reach 18,432 bytes across the
nine added entities.

For eleven similarly reachable entities, the recorded 4,466-byte slope
represents roughly 48 KiB of linear entity-related Wasm.

## Metrics Baseline

The supplied controlled empty-actor delta for enabling basic metrics is:

| Metric | Delta |
| --- | ---: |
| Final raw Wasm | +179,251 bytes |
| Code section | +163,872 bytes |
| Data section | +14,086 bytes |
| Defined functions | +551 |

This is an upper bound, not a promised Toko saving. The basic report exposes 24
compact numeric codes, while its current reachability includes rich
`EventState`, detailed event/error/SQL counters and the full dispatch match.

The frozen 0.250.1 SQL-off comparison measures 178,740 final raw bytes, 163,358
code bytes, 14,081 data bytes and 550 defined functions above the no-metrics
actor; SQL on measures 178,746 raw and 163,360 code bytes. The extended report
adds another 44,265 raw and 38,759 code bytes with SQL off. Basic and extended
Candid are stable across SQL selection.

The measured candidate selected one compile-time state/sink per build. Basic
builds used compact fixed counters and an entity vector; an explicit
`metrics-extended` feature selected the rich state. It reduced the SQL-off basic
actor from 1,923,249 to 1,915,489 raw bytes: 7,760 raw and 7,686 code bytes,
with exact Candid and flat indirect calls. That is below the 32 KiB gate, so the
candidate and feature were removed.

An inert exact-Candid endpoint probe still measured 1,912,536 raw bytes, or
168,027 bytes above the no-metrics actor. At most 10,713 bytes of the frozen
basic result disappear when report, reset and query-context behavior are all
removed. The original attribution therefore mostly measures endpoint/Candid
machinery, not removable rich state or dispatch.

The following alternatives are rejected:

- storing compact and rich state together or mirroring events between them;
- runtime sink/profile selection or a sink registry;
- using endpoint reachability alone to configure dependency internals;
- retaining a zero-filled rich internal state in basic builds; and
- changing basic or extended Candid to make code stripping easier.

## Codec Baseline

The residual 0.250 named attribution includes:

| Family | Duplicate bloat |
| --- | ---: |
| Runtime-selected per-entity operation/conversion wrapper | 17,217 bytes |
| Single typed write encode/decode leaf | 7,213 bytes |
| Same-entity typed batch encode/decode leaf | 4,365 bytes |

These values are an attribution lens and are not additive final-Wasm savings.
Row decoding is additionally obscured by inlining: generated fields repeatedly
call `row_value`, which revalidates binding/entity identity and searches the
projection by accepted slot.

The candidate boundary was concrete:

- `BoundRowDecoder` validates binding and projection once, then serves values
  by descriptor ordinal;
- `BoundWriteEncoder` lowers ordinal-indexed authored cells in one non-generic
  loop; and
- generated leaves retain final Rust field conversion only.

No callback, trait object, function-pointer table, vtable, runtime registry or
caller-authored physical slot was introduced.

The strongest row candidate reduced defined functions by 26 and 25 in the one-
and ten-entity actors, but final raw grew by 79 and 166 bytes and code grew by
64 and 153 bytes. Its nine-entity raw delta was 40,277 bytes, 87 bytes worse
than the frozen 40,190-byte baseline. Exact Candid and 717 indirect calls were
preserved. The candidate was removed because the existing concrete
`row_value` path was already compiler-shared; named repeated lookup did not
translate into entity-scaled final Wasm.

Slice 4 retained one concrete `BoundWriteEncoder`. Generated insert, patch and
replace leaves now append binding-local descriptor ordinals and already-lowered
cells to one pre-sized vector. The current opaque binding rejects invalid,
duplicate and out-of-order ordinals; canonical typed mutation admission then
resolves accepted IDs/slots and preserves authored/default/null,
database-owned primary-key and batch atomicity rules.

| Metric | Frozen one | Slice 4 one | Frozen ten | Slice 4 ten | Slope change |
| --- | ---: | ---: | ---: | ---: | ---: |
| Final raw Wasm | 2,871,530 | 2,871,190 | 2,911,720 | 2,911,243 | -137 |
| Code section | 2,706,408 | 2,706,072 | 2,745,012 | 2,744,539 | -137 |
| Defined functions | 7,451 | 7,422 | 7,524 | 7,495 | 0 |

The reachable raw slope is now 40,053 bytes across nine entities, or 4,451
rounded bytes per entity. This is a real but small 137-byte cumulative
improvement; another 21,621 bytes must be removed to reach the 18,432-byte
line objective. The exact Toko control improved by 11,170 raw and 11,174 code
bytes after its disposable parallel generator was migrated to the same hard
cut. The original downstream worktree was not edited.

## Descriptor Baseline

The 0.250 static descriptor remains the accepted design. Its roughly 11.4 KiB
Toko data increase was a ceiling, not a promised saving.

Slice 5 measured a lossless source-key table plus compact byte contract decoded
by one bounded validator. It grew the one-entity actor by 1,382 raw/1,414 code
bytes, the ten-entity actor by 1,829 raw/1,592 code bytes and the nine-entity
raw slope by 447 bytes. Data grew by 7 and 268 bytes respectively. Exact Candid
and 717 indirect calls were preserved, but the candidate failed both primary
retention gates and was removed.

A fingerprint-only descriptor was rejected before implementation because exact
validation must still retain and traverse all ordered identities, types,
nullability and primary-key facts. Associated named-type source keys prevent
the entity macro from precomputing the whole exact contract from literals, and
a shortened digest would introduce collision-based validation. The existing
direct static descriptor remains simpler and accepted snapshots still validate
the complete generated contract before issuing a binding.

## Nested Storage Direction Moved To 0.252

The downstream Toko Miner `ICYDB-017` and `ICYDB-018` audit exposed an
independent product-boundary question: whether nested values are aggregate-only,
single-valued queryable composites, or the beginning of a document/relational
hybrid.

The product decision is accepted and moved to the
[0.252 nested-storage contract](../0.252-nested-storage-contract/0.252-design.md).
Direction B retains first-class scalar paths through single-valued records while
treating repeated collections as named bounded aggregates with whole-field
replacement. Repeated member traversal, multikey indexes, subpath mutation,
nested relations/uniqueness and author-selected capability tiers are explicit
pre-1.0 non-goals.

This acceptance added no 0.251 landing slice and authorized no nested runtime
feature. The six-item 0.251 ledger is complete. The 0.252
documentation/contract correction may land independently; its separately
measured generated structural-input candidate must not displace, weaken or
consume the acceptance budget of this closed line.

## Acceptance Summary

The line tracks two independently reported outcomes:

- a compact-metrics experiment, now rejected because it did not reach the
  32 KiB final-raw threshold required for an explicit feature boundary; and
- a maintained reachable-entity delta reduced by the retained write slice from
  40,190 to 40,053 raw bytes, while the descriptor candidate worsened it to
  40,500 and was removed. The required result remains no greater than 18,432
  bytes across nine entities, rounded up to at most 2 KiB per entity.

The metrics candidate contributed no retained saving and does not count toward
the entity budget. Final qualification reproduced the six-actor metrics matrix,
the 1,301-byte schema-only slope and the 40,053-byte reachable slope. Schema-only
growth keeps its existing separate 2 KiB control. The full-adapter pair did not
pass its stronger objective, so the existing 8 KiB reachable gate remains
unchanged.
