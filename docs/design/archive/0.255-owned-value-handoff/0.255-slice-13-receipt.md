# 0.255 slice 13 — Owned mutation-result handoff

Date: 2026-09-06. Authorized after the published 0.255.1 closeout identified
last-use payload copies in save and delete result capture. Active notes are
0.255.2; package versions and published release notes are unchanged.

## Decision and boundaries

Both result-capture loops now consume their finished reader through one private
session helper. It selects accepted fields in snapshot order and uses the
reader's existing required-value take operation. The output vector retains the
same exact preallocation. No physical-slot dump, alternate decoder, public API,
cache, flag, encoding or execution route is added.

Whole-row validation, expected-key/Identity checks, mutation staging, output
capture policy, public conversion and precommit result-size validation keep their
existing ordering. Save takes values only after Identity verification and staging;
delete takes values after staging its canonical before-image. Neither reader is
used again. Capture-disabled behavior is unchanged. Owned batch-input lowering
and mixed-expression projection are not part of this slice.

## Baseline and method

Baseline: published v0.255.1, commit
`5158525e1d30177488d28bafcebdd006a5429193`. A fresh isolated source archive builds
both subjects at the same path with unchanged Cargo.lock and package versions,
Rust 1.97.1, SQL enabled, Candid export disabled, wasm-release profile,
Binaryen 132 and the canonical post-link pipeline.

The maintained `group_path_sql_query` actor uses scalar Int64 keys and nested
profile values. Both subjects include the same temporary exact-UPDATE wrapper,
calling the maintained internal API. Repository actors and endpoints are not
changed. Temporary native allocator instrumentation is absent from both Wasm
artifacts. Evidence is archived under `/tmp/icydb-0255-mutation-output.NfTZ1J`.

Predeclared ceilings: +1 KiB final raw Wasm, +4 defined functions and +1% cycles
per measured call. Require fewer native allocation requests for heap-bearing
output and unchanged results; scalar output is a separate control.

## Native allocation evidence

The isolated native test compares a frozen copy of the published result-copy
loop with the actual new helper in the same binary. Row construction and eager
validation are outside the allocation window. Warm cases also populate every
selected cache cell before measurement; cold cases measure ordinary required
materialization during handoff. Returned values are compared outside the window.
Three samples of 20 operations agree for each of 16 configurations (960 total
handoffs). Counts are cumulative allocation/reallocation requests and requested
bytes, not peak memory or endpoint latency.

| Fixture | Cache | Allocations before → after | Requested bytes before → after |
| --- | --- | ---: | ---: |

| One nested map, 1 KiB blob | Warm | 6 → 1 | 1,418 → 192 |
| 128 nested maps, 1 KiB blob each | Cold | 776 → 390 | 362,194 → 205,901 |
| 128 nested maps, 1 KiB blob each | Warm | 387 → 1 | 156,485 → 192 |

The large nested fixture removes 386 allocation requests and 156,293 requested
bytes in both cache states. Warm output needs only its result vector; cold output
still allocates decoded payloads. The NULL fixture's remaining text label explains
its five-byte saving. Scalar allocation equality is not a scalar cycle-neutrality
claim. All required allocation, cycle and Wasm gates pass.

calls, including call overhead and reply encoding; installation and startup are
excluded. Every variant/population/sample uses a fresh installation. Variant
order alternates across three repetitions; corresponding cycle samples agree
exactly, with each measured call advancing simulated time by the same 1 ns.

## Validation and handoff

93 focused tests pass, including all session write tests, public output parity,
Identity/result boundaries and RETURNING coverage. All-feature test-target lint,
SQL-disabled library checking, formatting and whitespace checks pass. One
unrelated Identity timing benchmark remains ignored; full repository/workspace
suites remain user-owned.

Initial test scaffolding required two corrections: an error assertion assumed
the successful reader type implemented Debug, and the synthetic initial layout
included a gap rejected at row opening with a typed slot-count mismatch. Tests
now use a valid dense layout with accepted fields ordered differently from
physical slots. No reader admission, schema rule or production validation was
weakened to accommodate the fixture. The final focused run has no failures.

The temporary PocketIC server was stopped by its wrapper. No existing network
was restarted. The native allocator scaffold was archived outside the repository
and removed from the isolated source after measurement. No commit, push, tag,
Cargo version or lockfile change was made. Slice 13 is ready for handoff; no
additional landing slice was started.
