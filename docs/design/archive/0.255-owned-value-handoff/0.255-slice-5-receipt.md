# 0.255 slice 5 — Owned direct-projection operands

Date: 2026-09-06. Explicitly authorized extension; active release 0.255.0.

## Outcome and authority

`StructuralSlotReader::take_direct_projection_value` replaces the previous
copying operation. It retains the accepted scalar byte-view fast path. Otherwise
it first invokes the existing required-value decoder, then takes that value from
the materialized cache cell under an exclusive borrow. No borrowed value can
survive that take. Later reads can refill the same existing empty cell through
the same accepted contract; tests hold the moved output alive while rereading.

Unique and repeated raw-row projection loops use this operation. Repeated fields
still clone the first projected output, using the existing prepared prior-output
index. They do not decode the source again. Order, NULL/empty values, primary-key
checks, selected-slot validation, unselected-field laziness, error propagation,
projection-step charges and page/output budgets are unchanged.

Paged dynamic reads and SQL use this shared materializer. Retained-slot output
already moves values and is unchanged. Full-row consumption, expression
projection and validation/materialization work inside the decoder are also
unchanged. There is no new public API, endpoint, format, mode, decoder or cache
variant. Ownership permits a populated cell to return to its existing empty
state, not an additional behavioral axis.

## Native measurement

Baseline is the complete unpushed slices 1–4. The temporary probe invokes the
actual direct raw-row materializer with accepted row contracts and prepared
unique `[payload]` or repeated `[payload, id, payload]` slot layouts. The nested
payload is a list of N maps, each containing a text key and a 1-KiB blob.
Scalar controls use a 64-KiB blob through by-kind cached storage or the existing
catalog-value scalar byte fast path, plus a fixed-width natural value.

Fixture construction, accepted metadata, row encoding and projection preparation
are excluded. The measured interval includes row opening, primary-key checks,
selected decoding, output shaping and reader/output cleanup. Each shape has nine
batches of 100 operations in the optimized all-feature core test target. Expected
outputs are asserted before measuring. Allocation/reallocation counts and
cumulative requested bytes repeat exactly across all nine samples; bytes are not
peak/live memory or total endpoint allocations.

Host timing samples remain in the logs but are not used to claim a speedup:
background build activity during baseline collection could distort timing.
No production latency claim is made from these allocation measurements.

## Complexity and handoff

Seven Rust files add 349 net lines: 13 production/documentation lines and 336
test/helper/wiring lines. The existing private prepared-slot constructor becomes
visible to its parent module so direct materializer tests use the real repeated
slot metadata. It does not add an alternative preparation path. Five release,
design, status and receipt documents accompany this change. The ownership
handoff is simpler; execution choices and semantic authority are unchanged.

The temporary allocation probe is removed from the worktree. Sources, logs,
snapshots, artifacts and the focused IC runner are retained under
`/tmp/icydb-0255-direct.6j8SNd`. One isolated PocketIC server was started with
approved local access and stopped after measurement. Existing networks, unrelated
user edits and the user's staged snapshot were left untouched. No commit, push,
version bump, further slice or 0.255 closeout is included.
