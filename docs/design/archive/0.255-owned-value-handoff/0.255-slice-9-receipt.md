# 0.255 slice 9 — Owned retained-row output

Date: 2026-09-06. Explicitly authorized extension; active release 0.255.0.

## Outcome and ownership

The opened-reader retained decoder now consumes its reader. Normal slots move
their cached values into output; scalar byte-length overrides continue to use
borrowed scalar views. All three callers already discarded the reader after
this boundary. Filter evaluation and primary-key validation still run before
the handoff.

The cache-taking portion of direct projection is extracted into the reader's
shared `take_required_value` operation. This reuses ordinary required-value
materialization without adopting direct projection's separate scalar-storage
shortcut. One cache owner, one take operation and the existing refill behavior
remain. No decoder, admission policy, mode, cache state, public API or storage
format is added. Non-filtered sparse/dense decoding is unchanged.

Maintained retained-layout compilation emits each required source slot once
from its requirement flags; repeated projections consume that shared retained
value. Synthetic duplicate-slot coverage verifies existing refill behavior,
not a new repeated-slot optimization or another cache.

Tests preserve nested and scalar heap identity, independently owned repeated
outputs, retained slot order, NULL/empty values, UTF-8 byte lengths, mixed
normal/length modes and key checks. Selected accepted-bound violations reject
with the existing diagnostic, while unselected fields remain lazy. Stored
empty/populated nested projections also run through accepting and rejecting
collection filters. Returned output is independent of the source row.

## Native allocation measurements

Baseline is completed slices 1–8. The temporary optimized core-test probe invokes
the actual retained decoder. Fixtures use accepted canonical lists of maps,
each containing a short text key and a 1-KiB blob, plus a 64-KiB by-kind scalar
blob control. Construction and encoding are excluded.

Warm measurements prepare a fresh reader and materialize its selected value
outside the measured region, then consume it once. Cold measurements include
reader creation, key validation and selected materialization. Both include
output construction and destruction of output/reader. Length-only warm setup
does not materialize its blob. Nine batches of 100 operations have identical
allocation/reallocation counts and requested bytes per shape; output values are
asserted before measurement.

destruction still cost work. These are cumulative allocation requests, not peak
memory or endpoint latency. Host timings are diagnostic only; unchanged controls
also vary, so no production latency percentage is claimed.
