# 0.255 slice 11 — Key reconstruction handoff

Date: 2026-09-06. Authorized continuation after the slice 10 handoff; active
release notes remain in the next unpushed patch on 0.255.

## Decision and boundaries

Reconstruct keys at the existing data-key codec from borrowed selected values.
Move persisted-row key operands out of the discarded reader, rather than
cloning its cache and cloning a singleton again. SQL UPDATE/DELETE already
borrow their projection rows and need no temporary owned vector. Remove the
session assembly helper and its re-export; scalar and composite codec checks
remain the semantic authority. No key kind, encoding, schema authority, cache,
runtime mode or public API changes.

Supported key components are fixed-size. This slice removes temporary allocation
and value copies, not large accepted text/blob key payloads. Persisted-row
reconstruction still eagerly validates the whole row before selecting key slots;
component order follows the accepted contract, not storage slot order.

## Native measurements

The temporary native probe calls the actual row/key constructors, with fixture
construction and output equality checks outside measurement; no wire encoding is timed. Report
allocation/reallocation calls and cumulative requested bytes, not peak memory
or endpoint latency. Nine samples of 100 operations cover scalar, two-component
and maximum-four-component keys.

| Input | Allocation/reallocation calls, before → after | Requested bytes, before → after |
| --- | ---: | ---: |
| Projected scalar key | 1 → 0 | 64 → 0 |
| Projected two-component key | 1 → 0 | 128 → 0 |
| Projected four-component key | 1 → 0 | 256 → 0 |
| Persisted-row scalar key | 4 → 4 | 1,912 → 1,912 |
| Persisted-row two-component key | 4 → 4 | 1,912 → 1,912 |

All nine samples agree exactly. The row fixture always has four Nat64 fields
and one eight-byte blob, with only accepted primary-key selection changing.
Row reconstruction retains its reader and collection allocations; moving
fixed-size values is not an allocation reduction. Host timing is diagnostic,
not a production latency claim. Temporary allocator instrumentation was archived
outside the repository and removed before final checks and Wasm builds.

## Validation and complexity

Four new tests pass: projected scalar/composite key values and encoded bytes,
arity/kind/error-precedence parity, accepted key order independent of row slots,
and truncated non-key payload rejection before key return. The focused
key/mutation/RETURNING selection passes 110 tests with one benchmark ignored;
all-feature test-target lint passes.
Formatting, whitespace and SQL-disabled checks pass. The ignored test is the
unrelated Identity recovery-closeout timing probe, not a skipped key regression.

Seven Rust files add 187 net lines: 185 test lines, three test-wiring lines and
one fewer runtime line. Five release/design/status/receipt files accompany the
change. A session helper and re-export disappear; one borrowed slice constructor
at the existing key-codec owner serves row and SQL reconstruction. No behavior
axis or parallel codec is added. Shape is simpler despite mechanical propagation.

The initial temporary probe failed to compile because an unrelated function
header was copied with the allocator scaffold; the scaffold was corrected
before measurement. A new baseline test also incorrectly assumed the scalar
ByKind reader enforced an accepted blob length limit; the unchanged baseline
accepted that fixture. The test now covers truncated non-key payload rejection,
not a new admission policy. No scalar-validation behavior is changed by this
slice. Full repository/workspace validation remains user-owned.
