## Outcome and complexity

The existing get_many decoded-row table records each row's final output position.
A linear pass finds that position; caller-order assembly takes the row at its
last use and clones only earlier duplicate occurrences. Single get continues
through the same batch path. There is no separate counter allocation, special
single-key route, cache, public API change or new execution authority.

All distinct rows still decode before output assembly. Missing keys retain None
positions, duplicate inputs share physical lookup and decode, and their owned
outputs remain independent. Accepted binding, key admission, resource bounds
and result ordering are unchanged. The Clone bound remains necessary for
duplicate present outputs.

This is an ownership improvement with slightly more local bookkeeping, not a
source-size reduction: two Rust files add 108 and remove 11 lines, **+97 net**.
The facade adds 12 net lines; tests/imports add 85. The runtime adds one linear
pass and one ordinal per distinct row to the existing table, with no new flow.
Native measurements include eight extra table bytes per distinct key, including
missing keys; this is not described as allocation-free or universally faster.

## Cycle results

All **216 measured calls** pass expected output checks, with exact agreement
across three samples per cell. Fresh installations for each operation/size/variant
separate the first read from its repeated warm read. Baseline/candidate order
alternates. Controls cover 1/64/256 positions: unique present, repeated present,
mixed, repeated missing, distinct missing and single get. The main 180-call run
and additional 36-call distinct-missing run use the same saved Wasms.

The largest reduction is **0.242494%**, for the cold 256-row distinct-present
batch (219,691,639 → 219,158,900 cycles). Its warm read improves 0.121246%.
The largest increase is **0.252559%**, for the warm single-get control in the
256-row populated fixture (29,719,444 → 29,794,503 cycles). Warm 256-position
duplicate-present reads increase 0.167028%; distinct-missing reads decrease
0.225779% cold and 0.141949% warm. This is not a universal throughput win.

All unchanged +1% cycle ceilings pass, as do clone/allocation and Wasm gates.
No exception is needed. The maintained wrapper started and stopped a temporary
PocketIC 16.0.0 server for each run (72 seconds and 14 seconds); no other network
was changed. The changed runtime source matches the measured isolated source.
