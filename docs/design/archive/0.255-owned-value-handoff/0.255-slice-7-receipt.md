# 0.255 slice 7 — Decoder-owned materialization

Date: 2026-09-06. Explicitly authorized extension; active release 0.255.0.

## Outcome and ownership

The deferred reader now calls the existing row-contract decoder once and caches
its returned value. The canonical/noncanonical guard and separate prevalidation
call are deleted, not relocated behind a helper. The decoder selects storage and
validates its payload. Eager validation-only operations remain separate because
they must reject malformed unselected fields without retaining their values.
No new production function, decoder, mode, cache state, format or public surface
is added.

Source inspection establishes the by-kind parity needed for this deletion:

| Boundary | Shared validation authority |
| --- | --- |
| Scalar fast path | The validator calls the scalar decoder itself |
| Other supported leaves | Both operations invoke the same leaf decoder |
| Lists / sets / maps | Both use the same complete wire walkers and recursively check every item/key/value |
| Relations | Both check the target key; list materialization omits NULL only after decoding it |
| Nullable structural fields | Both use the same outer nullable-sentinel check |

Thus decoding does not rely on a preceding validation-only walk. Canonical
strict admission is unchanged. This consolidates responsibility at the reader
boundary; it does not replace the two legitimate operations with a configurable
decoder or claim that validation-only traversal no longer exists.

There is a resource-ordering difference on invalid noncanonical lazy reads:
materialization can allocate a valid prefix before a later malformed item or
trailing byte rejects. No partial value is returned or cached. Eager all-field
validation, accepted contract selection, raw-row/depth bounds and error taxonomy
are unchanged. The cumulative allocation results below are not a claim of
unchanged peak memory on rejected payloads or a new allocation-safety proof.

the actual unique/repeated direct materializer and eager full-row executor.
Fixtures contain id plus a list of N maps, each holding a text key and 1-KiB blob,
now including by-kind storage alongside the canonical/scalar controls from slice

## Validation

197 focused tests pass across persisted rows, structural codecs, accepted
enum/constraint boundaries, projections, stored queries, page/output budgets,
cursor resumes, composite keys and malformed persisted formats. New tests
compare decoder/validator acceptance for mutated scalar, typed-leaf, set and
nested map/list wire, require rejection of every proper truncation and trailing
bytes, and check relation NULL filtering followed by invalid data. Reader tests
cover eager/lazy rejection, unselected-field laziness, failed rereads, successful
NULL/empty/nested output and cache take/refill.

All-feature test-target lint, SQL-disabled library check, formatting, whitespace,
local documentation links and matched native runs pass. One unrelated
scalar-expression microbenchmark stays ignored; full suites
remain user-owned. The temporary allocator probe is removed before final tests
and artifact builds. All declared cost and validation gates pass.

## Complexity and handoff

Four Rust files have a net 169-line increase: production/documentation removes
six net lines, while direct parity and reader/output regression coverage adds
175. Five release/design/status/receipt documents accompany the change. The
semantic ownership is simpler: no reader-side storage decision or duplicate
validation pass remains in deferred materialization. Validation-only traversal
continues to reuse scalar/leaf decoders and container walkers.

Evidence is retained under `/tmp/icydb-0255-decoder-owner.bSzTvv`. Existing staged
changes and unrelated user files are preserved. No package version edit, commit,
push, next slice or 0.255 closeout is included.
