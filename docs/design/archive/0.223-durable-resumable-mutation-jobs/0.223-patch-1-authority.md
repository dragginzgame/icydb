## Outcome

Patch 1 fixes the current owner inventory, collection-scale data size, exact
SQL intents, step bounds, failpoint identities, instruction ceilings, and raw
Wasm review limits before durable mutation behavior exists. It changes no
runtime route, persisted format, public Rust API, Candid, target row, marker,
or progress record.

The incident fixture contains exactly 10,001 matching rows for each of two
one-entity jobs:

- token tier reset to one fixed default value; and
- scoring-state invalidation to one fixed Boolean value.

At the maintained 64-update and 256-key envelopes, an all-stale fixture needs
at least 157 Forward calls and a clean sweep needs at least 40 Verify calls.
The current one-shot exact update ceiling is 4,096 rows, so the eager 10,001-row
control cannot masquerade as a complete safe operation.

| Identity | Current owner | 0.223 disposition | Patch |

| Generic pre/post proof coordinator | `compare_proof_and_advance` | keep separate | 2 |

| Aggregate request budget | request execution root | reuse | 3 |

The generic coordinator deliberately verifies the protected read-set proof
both before and after its closure. Mutating that protected target therefore
invalidates the job. That is correct for exhaustive reads and makes the generic
coordinator unsuitable for durable mutation progress. Patch 2 must add a
separate mutation record family; Patch 4 must add the marker-owned atomic
target/progress transition. Neither patch may add a flag that weakens the
generic proof protocol.

The current commit marker is format version 2 and owns journal batches plus
bounded database-control operations. It owns no progress replacement today.
The current progress store uses one 512 KiB physical record envelope, a global
64-record capacity, a distinct generic resumable-job key domain, and bounded
fallible codecs. The new mutation record must fit its narrower 64 KiB bound
inside that existing allocation.

## Atomicity And Recovery Matrix

| Interruption | Required recovered state |
| --- | --- |
| Before start progress insert | no job and no target change |
| After start progress insert | sequence-zero job and no target change |
| Before Forward marker persistence | exact before-state |
| After marker persistence | recover exact target plus progress after-state |
| After target apply | recover exact progress after-state |
| After progress replacement | retain exact after-state and replay receipt |
| After marker clear | exact after-state |
| Before read-only Verify replacement | exact before-state |
| After read-only Verify replacement | exact after-state |

No failure point permits a committed target batch with an older visible job
sequence after recovery. A mismatch against neither the marker's before-state
nor exact after-state is corruption, never a guessed recovery branch.

## Instruction Baseline And Gates

The existing application-custodied 512-row control reproduces as:

| Operation | Instructions |
| --- | ---: |
| Prepare | 430,996 |
| Forward 1-8 | 25,553,863; 25,761,479; 26,037,553; 26,174,501; 26,396,047; 26,686,886; 26,826,814; 27,190,572 |
| Verify 1-2 | 6,431,179; 6,440,484 |

It scans and updates 512 rows through eight 64-row Forward calls, then scans
512 keys through two 256-key Verify calls. These are comparison evidence, not
permission to retain caller-custodied SQL or continuations.

Before implementation, the fixed review ceilings are:

| New operation | Review ceiling |
| --- | ---: |
| Durable start | 5,000,000 instructions |
| 64-update Forward | 30,000,000 instructions |
| 256-key Verify | 8,000,000 instructions |
| State, exact replay, or acknowledgement | 2,000,000 instructions each |

Crossing a ceiling requires investigation and an explicit design correction;
later patches may not weaken it after seeing results. Exact replay additionally
must show zero target scans, planning, or mutation regardless of instructions.
State, replay, acknowledgement, and stable-growth values are intentionally not
borrowed from the generic revision-strict job: its record and coordinator have
different semantics and limits. Their first real mutation-job measurements are
Patch 2 evidence at the identities and ceilings frozen here.

## Wasm And Interface Gates

The published dynamic-query canister measures 2,607,381 raw final Wasm bytes
with deterministic gzip of 1,021,818 bytes. The typed-query canister measures
1,792,657 raw bytes with deterministic gzip of 681,772 bytes. Raw Wasm is
authoritative.

Any single 0.223 patch moving a maintained subject by more than 64 KiB requires
symbol attribution and explicit review. The complete line may not grow a
maintained subject by more than 256 KiB without redesign. Gzip is secondary
context, not a substitute for raw-byte evidence.

Patch 1 adds no production method, changes no exported mode, and changes no
production Candid or persisted bytes. Later additive trusted Rust types may be
Candid-compatible for applications to embed, but IcyDB still exports no
automatic mutation-job canister endpoint.
