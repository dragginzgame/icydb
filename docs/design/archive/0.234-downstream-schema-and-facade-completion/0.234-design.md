# IcyDB 0.234 Downstream Schema And Facade Completion

Status: complete; all four planned patches implemented

Design cut: 2026-08-20

## Objective

0.234 closes four demonstrated downstream adoption gaps without adding another
schema authority, query engine, or mutation executor:

- generated enum literals in entity check constraints name the wrong public
  trait path and fail downstream compilation;
- generated typed inputs can execute only one write even though IcyDB already
  owns a bounded same-entity atomic mutation batch;
- exact indexed prefix cardinality is available to SQL but not to the typed or
  dynamic non-SQL facade; and
- maintained schema-authoring documentation disagrees with relation validation
  and does not make key/name or host-build boundaries discoverable early.

The work is additive or corrective. Before 1.0, every changed generated and
runtime surface moves directly to one current form; no alias, legacy decoder,
dual route, or fallback is retained.

## Accepted Baseline

The released predecessor is `v0.233.3` at
`14c8ff9970f1dee262524fca23c3cfdf3de04761`. Patches 1 and 2 landed in that
release, so 0.234.0 begins with Patch 3 and uses the exact `v0.233.3` artifact
as its final delta baseline.

## Current-State Findings

### Generated enum checks

`icydb-model-macros` emits enum check literals through
`icydb_model::node::Path`, but the maintained public trait is
`icydb_model::Path`. Parsing, source-expression lowering, accepted binding, and
runtime evaluation already support unit-enum equality and bounded membership.
Only the generated trait path is wrong.

The fix changes the emitted path in place and adds a downstream-style compile
fixture with a constraint over two schema-native enums. It does not add a
re-export under the wrong module because that would preserve a compatibility
surface for a path that never formed a valid contract.

### Atomic typed writes

`TypedWriteAdapter` already lowers generated insert, update, and replace inputs
to immutable source-key-bound `TypedWrite` values. The facade executes one such
value at a time. Separately, the accepted structural writer already owns the
bounded same-entity atomic batch, one operation timestamp, final-row overlay,
constraint and relation enforcement, marker publication, recovery, result
ordering, and operation/staged-byte/result limits.

0.234 adds one homogeneous typed mutation-batch adapter. It must:

- reject an empty batch through the existing batch diagnostic;
- require every item to carry the same exact current `TypedEntityBinding`;
- lower each typed mutation through its immutable source-key binding;
- retain distinct-key and same-entity admission, existing limits, one operation
  timestamp, result ordering, and all-or-nothing publication; and
- delegate to the existing accepted structural save-batch authority.

The typed facade must not translate back through editable entity or field SQL
names, duplicate structural writer accounting, or introduce a typed-only
transaction engine or budget.

### Exact indexed scalar count

The query planner and cardinality generation already prove exact entity and
user-index-prefix counts. SQL `COUNT(*)` owns an adapter that may fall back to
ordinary aggregate execution when an exact shortcut is unavailable. A public
exact scalar terminal has a different contract: it either consumes planner-
proved exact cardinality metadata or rejects the query shape.

0.234 moves the reusable exact-prefix planning and execution authority out of
the SQL-specific adapter, then exposes it through dynamic and typed query
terminals. Admission is limited to the already-supported exact shapes,
including exact entity cardinality and strict indexed-prefix equality or
bounded `IN` prefixes without residual predicates. Unsupported, incomplete,
or residual shapes fail closed; no scan fallback is permitted.

The primary surface returns an exact `u64` count. Boolean existence is derived
from that count unless implementation evidence demonstrates a distinct cheaper
authority; it does not receive another execution route merely for convenience.

### Authoring documentation

The compiler requires singular and optional relation fields to end in `_id`
and collection relation fields to end in `_ids`, while the maintained identity
contract currently recommends suffix-free schema names. Validation remains the
authority and the contract is corrected.

The final authoring guide also derives and documents:

- the complete primary-key-compatible primitive set from canonical scalar
  metadata;
- the maintained Rust, Candid, and IcyDB reserved identifier set;
- why text is not a primary-key domain and how indexed slugs or external
  principals coexist with durable generated identity; and
- why Cargo compiles `build.rs` for the host and therefore both host generation
  and Wasm runtime depend on one shared schema/model library, with small
  single-canister and multi-canister layouts.

Documentation describes existing authority; it adds no runtime inference,
generated-model reconstruction, or shared database authority between
canisters.

## Ownership And State-Space Rules

- `icydb-model-macros` remains the only generated schema-expression owner.
- Accepted schema snapshots remain runtime authority.
- `TypedWrite` remains an adapter payload; the accepted structural batch stays
  the only mutation executor and atomicity owner.
- Exact cardinality generation and query planning remain the only count proof;
  SQL and public facades become adapters over that shared owner.
- No persisted format, stable allocation, cursor, continuation, endpoint,
  caller-selected budget, or lifecycle state is added.
- No generated model participates in runtime schema reconstruction.

## Validation Strategy

Each landing runs only focused package, target, named integration, recovery, or
artifact checks. Repository-wide validation and release publication remain
user-owned.

Patch 2 must prove that typed batching changes only adapter ownership: the same
accepted batch stages and commits all rows, and interruption cannot publish a
typed-only partial prefix. Patch 3 must prove that cost depends on the bounded
number of admitted exact prefixes rather than matching population and that an
unsupported query never enters ordinary row execution.

Raw non-gzipped Wasm is the primary artifact measure. Every patch reports files
touched, approximate line delta, and whether implementation complexity became
simpler, stayed neutral, or increased.

## Non-Goals

0.234 does not add:

- cross-entity or cross-canister transactions;
- rollback, compensation, or multi-job atomicity;
- a general aggregate facade or unbounded count scan;
- approximate counts or caller-selected query budgets;
- inferred relation storage primitives;
- runtime schema reconstruction from generated models;
- compatibility aliases for the incorrect trait path or relation naming; or
- a prescriptive multi-canister workflow protocol before a real application
  supplies interruption-tested evidence.

## Completion Criteria

0.234 is complete only when:

- downstream enum check constraints compile through the maintained public
  trait and their accepted constraint is produced normally;
- maintained relation naming documentation matches compiler enforcement;
- generated typed same-entity batches inherit existing structural atomicity,
  limits, diagnostics, recovery, and result order without another executor;
- exact typed and dynamic counts use only planner-proved cardinality metadata
  and reject every fallback shape;
- author-facing key, reserved-name, and host-build/model boundaries are linked
  from active entry points;
- focused negative, recovery, instruction, public-API, documentation, and
  artifact evidence passes; and
- no deferred cross-canister protocol or storage inference is pulled into the
  line.
