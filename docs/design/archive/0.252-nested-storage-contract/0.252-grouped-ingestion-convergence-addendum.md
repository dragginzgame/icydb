# IcyDB 0.252 — Tentative Generic Grouped-Ingestion Convergence Addendum

- **Status:** Closed; Landing Slice 2 rejected with no production change
- **Date:** 2026-09-02
- **Minor line:** `0.252`; no release patch is assigned by this design
- **Required predecessor:** immutable annotated tag `v0.252.1`
- **Parent contract:** [0.252 Nested Storage Contract](0.252-design.md)
- **Delivery tracker:** [0.252 Status](0.252-status.md)

## 1. Decision Summary

IcyDB already has one canonical generic grouped reducer and finalizer. It does
not retain duplicate end-to-end typed, dynamic, SQL, or scalar-record-path
executors. The remaining credible cleanup candidate is narrower: the unordered
generic runner repeats source-key iteration, row-view decoding, residual-filter
evaluation, and scanned/filtered accounting in three probe-specific loops.

This addendum tentatively assigns that common row-admission work to one
concrete private owner inside the generic grouped runner. The direct borrowed,
direct owned, and path-aware strategies continue to own only their distinct
group-key probe and bundle-update semantics. Strategy selection remains outside
the source-row loop, and the allocation-free direct borrowed hot path remains
structurally available.

The preferred experiment is a concrete eligible-row feed that owns:

- advancing the resolved data-key stream;
- reading one retained `RowView` under the route's consistency policy;
- skipping absent rows;
- evaluating the already compiled effective runtime filter; and
- maintaining the existing scanned and filtered row counts.

Each specialized ingest loop would consume the same feed and call its existing
bundle method. The feed is private to the generic grouped runner unless later
evidence demonstrates an existing smaller owner. It is not a general query
iterator or another executor stage.

This is a measured simplification candidate, not a required feature. If the
concrete feed adds a hot-loop branch or call premium, requires cloned row/key
state, grows reachable Wasm, or merely moves duplication behind generic or
dynamic machinery, the correct result is no production change plus a rejection
receipt.

Landing Slice 2 reached that no-build result. The shared non-inlined feed saved
306 final raw and 307 code bytes but added one defined function and raised the
path cold-runtime premium from 17.48% to 21.26%, above the maintained 20% gate.
Inlining removed the function increase but grew final raw and code by 1,465
bytes. The candidate was removed completely; the exact evidence is in the
[Landing Slice 2 receipt](0.252-grouped-ingestion-convergence-slice-2-receipt.md).

## 2. Exact Existing Duplication

`GenericGroupedFoldRunner::fold_rows_into_bundle` selects one of three paths:

1. `fold_rows_into_bundle_borrowed` keeps allocation-free direct existing-group
   probes;
2. `fold_rows_into_bundle_owned` materializes a canonical direct key where the
   accepted field kinds cannot use the borrowed probe; and
3. `fold_rows_into_bundle_path_aware` hashes and compares accepted scalar-path
   values by reference, materializing a key only for a new group.

Those paths intentionally differ after a row is admitted. Before admission,
they repeat the same stream, decode, filter, and counter contract. That repeated
prefix is the only implementation shape this addendum may try to converge.

The following neighboring execution paths are not duplicate cleanup targets:

- ordered generic grouping owns streaming group transitions, early stop, and
  incremental page selection;
- the single grouped `COUNT(*)` route owns its compact count state and direct
  single-field decode fast path; and
- global grouped `DISTINCT` owns a different semantic state and terminal.

Scalar and grouped query pipelines likewise remain separate because they have
different result cardinality, cursor, memory, and finalization contracts.

## 3. Canonical Owner And State-Space Delta

The smallest semantic owner is the private generic grouped runner module. It
already owns the repeated loops, the selected `GroupProbeKind`, generic bundle
construction, and finalization handoff. Moving row admission into the general
pipeline runtime would widen a cleanup local to one grouped route into a
cross-executor abstraction.

The maximum retained state-space delta is one concrete private feed value. It
may borrow the already split row runtime, execution preparation, and resolved
key stream and carry the two existing counters. It must not introduce:

- a public API or generated surface;
- a planner strategy, execution route, mode, feature, or configuration;
- a callback, trait object, function-pointer table, or runtime registry;
- a generic closure-based convenience driver;
- a new cursor, persisted state, recovery state, or format discriminator; or
- a second filter, consistency, row-decoding, or accounting authority.

The existing `GroupProbeKind` remains the sole runner-local selection. No new
enum variant or independently variable state is justified.

## 4. Preserved Contracts

The candidate must preserve exactly:

- accepted schema as runtime authority;
- direct and scalar-record-path group-key identity, hashing, equality, ordering,
  and missing/null behavior;
- direct borrowed probes without per-row key allocation;
- path-aware borrowed probes with owned materialization only for a new group;
- residual-filter evaluation before aggregate-state mutation;
- scanned and filtered row accounting, including absent and rejected rows;
- execution-budget charging and typed error propagation;
- complete hash grouping, ordered grouping, pagination, and cursor behavior;
- Candid, public Rust APIs, generated APIs, schema, persistence, and recovery;
  and
- SQL-on, SQL-off, and downstream entity-specialization slopes.

No compatibility alias, fallback, predecessor adapter, or dual route is
permitted.

## 5. Candidate Order

The implementation slice must proceed in this order:

1. freeze a same-tool baseline from the immutable `v0.252.1` tag;
2. introduce one concrete private eligible-row feed in the generic runner;
3. retain all three existing probe-specific bundle calls and select their loops
   outside row admission;
4. compare optimized Wasm, function/indirect-call counts, allocation-sensitive
   behavior, and paired runtime controls; and
5. retain the candidate only if the semantic, cost, and complexity gates all
   pass.

If Rust ownership requires the feed to clone a data key or row, allocate an
intermediate envelope, move probe dispatch into every row, or acquire a
callback boundary, the candidate is rejected rather than widened.

## 6. Acceptance Gates

### 6.1 Semantic gate

Focused coverage must exercise direct borrowed, direct owned, and path-aware
generic hash grouping with and without a residual filter. Results, cursors,
scan counts, filtered counts, live-group peaks, estimated bytes, budget
failures, missing rows, and typed errors must remain exact.

Ordered generic grouping, dedicated grouped count, and global distinct tests
must remain passing controls even though their implementations are out of
scope.

### 6.2 Allocation and runtime gate

The direct borrowed path must add no row-local allocation or owned group-key
materialization. The path-aware path must continue to allocate a canonical key
only when opening a group.

Three paired same-tool runs of the direct complete-hash control and the cold
path-aware control may regress by no more than 1%. A candidate whose helper is
not inlined and produces a measurable call premium is rejected; a candidate
whose helper is inlined back into equivalent duplicate Wasm must still satisfy
the complexity and Wasm gates.

### 6.3 Wasm and interface gate

The immutable `v0.252.1` artifacts become the baseline once that tag exists.
The maintained feature actor, `default_empty`, SQL actors, SQL-off one/ten
entity controls, and frozen read-only Toko subject may not grow in final raw or
code bytes. Defined functions and `call_indirect` may not grow. Exports and
Candid must remain exact, and SQL-off raw/code/function slopes may not worsen.

Raw non-gzipped Wasm is authoritative. Any apparent source cleanup that grows
the maintained reachable artifacts is rejected.

### 6.4 Complexity gate

The retained result must have one implementation of generic unordered
scan/read/filter/accounting, fewer duplicated production statements, no net
production-line growth, and no new behavior axis. Moving the same loops into a
new file or generic instantiation does not pass.

## 7. Rejected Alternatives

- **One per-row `match` over all probe strategies:** removes source repetition
  but taxes the direct borrowed hot loop for an owner-local cleanup.
- **A generic closure or trait helper:** encourages multiple monomorphized
  copies and can preserve the same reachable duplication under a tidier source
  shape.
- **Trait objects, callbacks, or function pointers:** add indirect dispatch and
  repeat the vtable/function-shim cost already rejected by earlier erasure
  experiments.
- **A general executor row cursor:** widens ownership and lifetimes across
  scalar, grouped count, distinct, ordered, and generic semantics without a
  demonstrated cross-route benefit.
- **Converging dedicated count or distinct into the generic bundle:** discards
  measured compact-state fast paths and changes more than the duplicated row
  admission prefix.
- **Converging ordered and unordered folds:** mixes early-stop/page-selection
  semantics with complete-hash state and creates a larger route branch.
- **Retaining both old and new loops:** violates the hard-cut and single-owner
  rules.

## 9. Slice 1 Result

This slice changes design and status documentation only. It records that IcyDB
has one canonical generic grouped execution flow and isolates the remaining
duplicate-shaped implementation prefix without misclassifying semantic fast
paths as duplicate executors.

No production code, test, fixture, public API, Candid, generated surface,
schema, persistence, cursor, recovery, Wasm, or release note changes. The
implementation shape remained unchanged until Landing Slice 2 started from the
required immutable predecessor.

## 10. Slice 2 Result

The concrete private feed converged the three generic unordered admission
prefixes and removed roughly 40 net production lines. Its strongest
non-inlined form reduced the optimized feature actor by 306 raw and 307 code
bytes with exact data, Candid, exports, and indirect calls, but added one
defined function. More importantly, it raised the cold path runtime from the
restored tag's 5,897,214,596 instructions to 6,086,526,381 instructions while
the direct control remained within 0.01%. The resulting 21.26% path premium
failed the existing 20% gate.

Inlining the feed body restored the function count but grew final raw and code
by 1,465 bytes. Inlining either related single-caller wrapper did not remove the
additional function. No candidate satisfied the combined source, raw-Wasm,
function, and runtime gates, so production source was restored exactly to
`v0.252.1` and the addendum is closed as rejected. No active-version changelog
entry is required because no production or behavioral change remains.
