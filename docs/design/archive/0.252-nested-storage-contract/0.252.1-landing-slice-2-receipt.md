## Rejected Production Shapes

The first candidate introduced a nominal direct/path group-key enum and
propagated it through planner, fingerprint, cache, explain, prepared, cursor,
route, projection, and runtime consumers. It added no public behavior but grew
the SQL-off one/ten reachable actors by approximately 3.8 KiB each.

Two successively narrower alternatives were measured:

| Candidate | Best observed unaffected cost | Disposition |
| --- | ---: | --- |
| Nominal direct/path enum and source iterator | about +3.8 KiB raw per SQL-off reachable actor | Rejected: premature path machinery and fixed cost |
| Transparent direct-only newtype | about +215 raw bytes per SQL-off reachable actor | Rejected: wrapper cost without behavior |
| Erased direct-only alias | exact Toko +27 raw / +37 code | Rejected: downstream no-growth gate |

Moving the alias below reachable definitions removed source-location noise in
the smaller SQL actor but did not remove the exact normalized-path Toko delta.
The final candidate therefore removes the alias as well. The IcyDB production
source is byte-identical to `v0.252.0`; the group-key owner moves into Slice 3
with the scalar-path semantics that use it.

No parallel field list, compatibility alias, fallback, callback, trait object,
function pointer, registry, runtime mode, persisted state, or new execution
route remains.

## Complexity And Validation

The retained implementation touches 20 files and adds approximately 350 lines
of actor, schema, native workload, and measurement support plus approximately
200 lines of receipt, status, and changelog evidence. Production complexity is
neutral: zero production files and zero production lines remain changed. The
repository test surface becomes slightly more complex by one bounded audit
actor, while the rejected production candidate reduced from an enum/iterator
and cross-layer propagation to a newtype, then an alias, then no premature
owner.

Focused formatting, core all-feature checks and Clippy, actor/integration
checks, the direct grouped PocketIC regression, controlled Wasm builds, and the
exact disposable Toko qualification passed. The disposable B0 build and
post-link transform also passed and produced the exact candidate artifact; its
report wrapper stopped after artifact creation because that source overlay has
no Git metadata, so section counts were verified directly from the identical
Wasm instead. The user-owned full repository suite was not run.
