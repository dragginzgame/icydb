# IcyDB 0.252 Landing Slice 3 Receipt

Status: COMPLETE — CLOSEOUT EVIDENCE CORRECTED

Date: 2026-09-01

## Outcome

Structural writes can now consume generated records, enums, and collections
without applications reconstructing accepted record-member maps.
`DbSession::bind_typed_input` takes one exact `TypedEntityBinding`, proves that
it is current, invokes the existing generated `TypedInputValue` implementation,
and returns one ordinary `InputValue` for the unchanged structural mutation
pipeline.

The session is the smallest semantic owner because it alone can compare the
opaque binding with current accepted authority. The binding remains the name
resolution context, generated code remains the final Rust-value converter, and
accepted write admission remains the complete-field and final-row authority.

## Retained API

```rust
let binding = Robot::typed_binding(&db)?;
let inventory = db.bind_typed_input(&binding, stacks)?;
let patch = StructuralPatch::new().field(
    Robot::CORE_INVENTORY.as_str(),
    WriteCell::Value(inventory),
);
```

The method returns `InputValue`, not `WriteCell<InputValue>`. This preserves the
existing owner of `Omitted`, `Default`, `Null`, and authored `Value` intent and
keeps the result usable by single, same-entity batch, and mixed-entity batch
structural writes.

## Rejected Alternatives

- A method on `TypedEntityBinding` alone could resolve source identities but
  could not prove that the binding was still current. It was rejected rather
  than weakening the stale-binding contract.
- Per-generated-type `into_input` methods or a new generated structural
  encoder would duplicate the existing `TypedInputValue` leaves and restore
  downstream monomorphization.
- A new binding-carrying public value or write-cell wrapper would add another
  mutation representation and state dimension to preserve identity until
  execution. The existing session check plus ordinary structural admission is
  sufficient.
- Returning `WriteCell<InputValue>` would conflate value conversion with write
  intent and provide no useful way to represent `Omitted`, `Default`, or
  explicit `Null`.
- A reusable cursor, registry, callback, trait object, or function-pointer
  descriptor would be disproportionate for one root conversion and recreate
  the indirect-function side effect rejected by earlier erasure experiments.

## Allocation And Monomorphization

`InputValue::from_public` is a newtype move and allocates nothing. The adapter
adds no intermediate map, list, registry entry, callback box, or binding-owned
value wrapper. Existing `TypedInputValue` implementations retain their normal
owned conversion costs: list conversion allocates its public-value vector,
records allocate the public map and accepted member-name strings, and enum
payloads retain the existing recursive representation. These are the same
allocations used by generated typed writes.

The public method is generic over the canister kind and root Rust value type,
not the runtime entity identity. A downstream application therefore retains
one thin monomorph for each actually used root type; two entity bindings using
the same `Vec<InventoryStack>` share that root specialization. The only
type-specific work remains the pre-existing final `TypedInputValue` conversion.

The maintained closeout probe now supplies an accepted generated
`Vec<ReachableInputProfile>` containing scalar text, a unit enum, an enum
payload and a null optional. Shared entity 01 writes that value through both
the single structural terminal and the atomic two-row batch terminal. Every
selected entity also makes the same binding-owned conversion reachable.

An initial method-isolation probe used `String` to measure only the wrapper and
current-binding check. It remains useful attribution evidence, but the
closeout audit correctly rejected it as the sole proof for a generated
composite/collection root. A separate unbound generated record now proves the
public `FieldUnavailable` mapping at runtime.

## Authority And Compatibility

- the existing binding lifecycle regression proves that renamed or superseded
  accepted authority makes an issued binding stale, and the public adapter
  invokes that exact currentness owner before conversion;
- unavailable named-type, record-member, or enum-variant source identities map
  to `TypedAdapterError::FieldUnavailable`, including the executable unbound
  generated-record control;
- malformed generated/public shape maps to `ValueShapeMismatch`;
- accepted enum and exact-composite admission remain unchanged after the
  adapter returns its ordinary input root; and
- single, same-entity batch, and mixed batch mutation paths consume the same
  `StructuralPatch` and existing atomic executor.

There is no Candid method or payload change, public recursive-value shape
change, schema/catalog encoding change, persisted row/index/journal change,
cursor change, mutation variant, recovery route, compatibility shim, or
predecessor decoder.

Binaryen 132 `-Oz`. Both actors share one representative nested entity and the
same executable nested-input operation; the ten-entity actor adds nine simple
entities. Raw non-gzipped bytes remain the decision metric.

| --- | ---: | ---: | ---: |
| Raw Wasm | 2,910,803 | 2,952,157 | 41,354 |

The raw slope is 4,595 bytes/entity and passes the retained 8,192-byte gate.
The final pair proves the actual generated record/list specialization and its
accepted single/batch structural admission, not merely the facade wrapper.

The earlier method-isolation probe remains the narrow attribution for the API
itself. Relative to the completed Slice 2 tree it changed:

| Metric | One entity | Ten entities | Scaled change across nine entities |
| --- | ---: | ---: | ---: |

Replacing that scalar probe with the representative generated model and
executable write controls adds 39,564 and 40,250 raw bytes, and 38,800 and
39,403 code bytes, to the one- and ten-entity actors respectively. This is a
whole-fixture activation cost: it includes the accepted named enum/record,
the additional nested entity field, generated typed adapters, successful
single/batch writes, and the unbound-source control. It must not be attributed
solely to `bind_typed_input`, and it is not a downstream delta for an
application such as Toko Miner that already retains its generated nested
model.

The representative fixture adds only 686 raw and 603 code bytes to the
nine-entity delta relative to the scalar probe. It adds two scaled defined
functions and no scaled indirect calls. Both final actors contain one more
fixed `call_indirect` than the scalar fixture because the representative model
and control are now reachable; this is shared fixed fixture cost, not
entity-scaled adapter dispatch.

## Validation

Focused generated nested-input behavior, typed input error mapping, no-SQL
generated facade compilation, accepted binding rename/staleness, composite
targeted-rule convergence, and warning-denied Clippy checks pass. The focused
PocketIC regression executes the generated nested root through current
binding, single write and atomic batch admission, then verifies the unbound
source error class. The final representative Wasm scale gate passes with exact
unchanged Candid. Repository formatting, invariant, and whitespace checks also
pass.

The full repository test suite was not run; repository policy leaves that
explicit release validation to the user.

## Complexity Delta

Production shape adds one public generic method and one private concrete
current-binding check, while reusing that check in an existing structural row
terminal. It adds no semantic state or execution flow. The closeout correction
changes only test schemas, audit operations and evidence. The implementation
is slightly larger at the facade but remains complexity-neutral at the
architecture level because it replaces application-owned record-map
construction with the existing accepted-binding authority.

Toko Miner can replace its `InventoryStack` map builder and enclosing list
builder with one `bind_typed_input` call. No recursive `into_public()` or
hand-authored record-member map remains necessary.
