# 0.254 — NULL-Typing Closeout Correction

Date: 2026-09-06. Landing slice 3: complete worktree handoff after approved
read-only closeout findings. Final minor-line closeout remains a separate audit.

## Outcome And Boundary

Known SQL NULL now has the same shared expression classification in production
and unit-test builds. Scalar function admission, comparisons, boolean conditions,
CASE and COALESCE consume that classification instead of build-specific or
literal-AST exceptions. Unresolved types remain distinct; this is not a cast or
an instruction to admit every unknown value.

The cleanup also corrects a directly related CASE defect: the original implicit
NULL ELSE could erase an already accumulated result type, hiding incompatible
result arms. Unification now consumes only the accumulated type and diagnostic
branch position, not the original ELSE expression.

No binder-local normalization, cache policy, transport, runtime mode, persistence
format or production export was added. A fixed no-argument regression probe is
gated by the existing SQL test actor's `test-admin-api`; callers cannot supply
SQL or bindings. The maintained measured audit actors remain unchanged.

## Red/Green Evidence

- Before the runtime fix, the non-test Wasm probe failed on bound `LOWER(?)`
  with NULL, while equivalent literal SQL returned stored rows. Afterward all
  seven pairs returned identical projections: LOWER, ABS, OCTET_LENGTH, ROUND,
  nested all-NULL COALESCE, NULLIF and CASE.
- The same Wasm test rejects a bad SUBSTRING sibling despite a NULL argument
  and a false surrounding branch, and incompatible CASE result arms despite
  an implicit NULL ELSE and a true surrounding OR branch.
- A new owner-local CASE test failed before the fix and passed afterward.
  Function tests distinguish NULL from unresolved inputs and retain invalid
  sibling/scale rejection.
- Focused native selections passed: 46 expression, 21 session/binding and seven
  diagnostic tests. The non-test core/facade library compilation passed.

## Validation Completion

Final validation passed: both `make clippy` lanes, focused core/facade
all-feature/all-target lint, the SQL test actor with `test-admin-api`, and the
integration SQL target. The final expression selection passed again after the
lint cleanup, as did the SQL-disabled core/facade library check, formatting and
diff whitespace. Both matched production Wasm builds completed successfully.
Full test suites and release validation remain user-owned.

The first focused lint gate found identical unification match arms. The required
`make clippy` run reproduced it; its next run requested a nested or-pattern.
Both were fixed without suppressions, and both `make clippy` lanes then passed.

Baseline builds initially encountered stale schema/diagnostic compiler artifacts
left by prior exact-release controls. Scoped Cargo cache cleanup removed 828.4 MiB
of native schema artifacts and 7.1 MiB from the custom Wasm profile; these are
rebuildable, not source or measurement receipts. The successful controls were
rebuilt afterward. An initial sandboxed PocketIC launch could not bind localhost;
the approved local-server run produced the red/green evidence. All temporary
PocketIC servers were stopped; no ICP network lifecycle change was needed.
