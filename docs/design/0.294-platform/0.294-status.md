# Platform 0.17 adoption

## Accepted scope

The maintainer authorized the next minor, 0.294.0, on 2026-11-01 after
reviewing Platform's public Types identity change. Adopt registry Platform
0.17.0, Types 0.16.0 and its IC0 Runtime 0.17.1 dependency. Do not edit IcyDB
package versions or execute release actions. Preserve the pending #81 fairness
correction and the independent Canic qualification stack.

## Landing slices

1. Adopt published Platform 0.17.0 for root consumers. Select external Principal
   conversions explicitly in facade tests; preserve existing application Wire
   codecs, Principal/Account bytes, errors and IC0 behavior. Qualify affected
   identity, authorization, hash and metrics contracts, strict focused lint,
   dependency boundaries and Rust 1.91 Wasm compilation. Memory/Storage adoption
   is separately scoped in slice 7; their stable substrate remains independently
   owned and is not replaced locally.
2. Carry forward the completed #81 cross-store fairness correction, its direct
   tests and startup documentation. Keep the remaining per-store source-drift
   liveness limitation open.
3. Document the existing generated public-name contract and close #180's
   remaining helper-relocation/customization proposal. Preserve conventional
   names, supported prelude shadowing and the delivered hygiene corrections;
   qualify existing generated consumers and documentation. No new public option,
   namespace layout or runtime behavior. Correct stale Account schema-feature
   guidance to its existing Wire owner while updating the same authoring guide.
4. Finish direct owner adoption: Schema uses Types; the facade uses Types and
   Runtime; Core uses Runtime for IC0 and Platform only for BLAKE3. The IC0-only
   actor uses Runtime. Preserve the selected published package identities and
   all bytes/behavior. Restrict direct dependencies to the corresponding local
   consumers, qualify alias/build/dev/target policy cases and affected contracts.
   Auth remains read-only evidence. No new crate, wrapper, runtime feature,
   persisted state or execution route is introduced.
5. Adopt published Host Tools 0.77.0 for the CLI response decoder and native
   artifact-interface consumers. The selected response/interface sources are
   unchanged from 0.76.2; Platform-backed features remain unselected. Preserve
   Foundation, Testkit, product and independent Canic dependency selections.
   Qualify strict consumer lint, response and artifact contracts, tooling MSRV
   and dependency boundaries without broad gates or delivery actions.
6. Adopt published Wire 0.14.0 and Metrics 0.25.0 together after the supplier
   fixes native schema composition. Preserve codec bytes, limits, errors,
   generated browser contracts and metrics/reset ownership. Qualify the actual
   generator, browser vectors, affected metrics contracts, strict consumer lint
   and Rust 1.91 Wasm compilation. Keep the independent Canic graph unchanged.
7. Adopt published Memory/Storage 0.62.0 to align their public codec-error
   identity with Wire 0.14. Preserve retained bytes, exclusive leases, admission
   and recovery; qualify actual runtime bindings, storage reopening/refusals,
   typed error projections, focused lint and Rust 1.91 Wasm compilation.
   No data reset, new storage framework or Canic upgrade is included.

## Contract and ownership

Published Types 0.16.0 owns identity and Runtime 0.17.1 owns IC0. Schema selects
Types directly; the facade uses Types/Runtime; Core keeps Platform 0.17.0 only
for BLAKE3 and selects Runtime for IC0. Platform's re-exports and Runtime's IC0
bodies use those exact identities. IcyDB selects no executor, CDK, Candid, parser or native PocketIC client.
No local facade, executor, codec, compatibility identity or storage migration is
introduced. Types' new self-authentication feature no longer enables external
Principal conversions implicitly. Those conversions remain test-only here.

Public conversions involving Platform Principal/Account now require matching
Types 0.16 identities and consumer rebuilds. The canonical representation and
retained database bytes do not change. Canic qualification retains its older
aligned dependencies and is not upgraded or claimed qualified by this slice.
