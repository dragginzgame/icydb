## Implemented Authority And Flow

Patch 1 adds one optional, bounded query-field diagnostic context without a
second error taxonomy:

```text
failing accepted-schema resolver
  -> existing leaf planner/lowering error
  -> PlanError::attach_query_field(role)
  -> QueryError::query_field_context()
  -> icydb::Error::query_field
  -> generated Candid Error record
```

- `icydb-diagnostic-code::QueryFieldRole` is the sole six-role registry.
- `validate_query_field_schema` is the sole public E-code/role/field validator.
- `PlanError` is the sole planner carrier and owns one closed attachment
  adapter; leaf error families did not gain parallel role state.
- SQL lowering carries role only until it enters that same planner carrier.
- `QueryError` exposes, but does not derive, the bounded context.
- `icydb::Error` performs the last server-side schema validation before Candid
  construction.
- A malformed decoded client context remains attached to the base error but is
  unavailable through `validated_query_field()` with a typed mismatch.

Patch 3 moves direct unknown aggregate field targets onto the same
`ExprPlanError::UnknownField -> PlanError` carrier already used by aggregate
input expressions. `COUNT(field)`, `SUM(field)`, `AVG(field)`, `MIN(field)`,
and `MAX(field)` therefore report E3 plus `AggregateTarget` instead of the
former context-free E11. The obsolete E11 construction helpers are removed;
no second carrier or compatibility path is introduced.

The retained field is the exact post-normalization resolver input. Tests cover
matching and nonmatching qualifiers, nested paths, projection aliases, SQL and
dynamic predicate/order parity, and grouped/aggregate roles. The field is
retained only at 1 through 256 UTF-8 bytes; zero and 257 or more bytes are
omitted without truncation.

The shared CLI now consumes only `validated_query_field()`. It renders the
typed role, single-line escaped field, and existing numeric facts. Unknown
roles, invalid bounds, disallowed E-code/role pairs, and fact-schema mismatch
all preserve the base diagnostic while withholding the untrusted field and
reporting a context mismatch. No CLI parser, schema lookup, or suggestion path
was added.

## Closed Producer Matrix

The internal attachment test exhausts all six roles for each maintained leaf
producer:

| Leaf producer | Admitted roles |
| --- | --- |
| predicate `ValidateError::UnknownField` | `Predicate` |
| expression `UnknownExprField` | `Projection`, `OrderBy` |
| SQL expression or direct aggregate `UnknownField` | `Predicate`, `Projection`, `GroupBy`, `AggregateTarget` |
| direct `OrderPlanError::UnknownField` | `OrderBy` |
| `UnknownGroupField` | `GroupBy` |
| `HavingNonGroupFieldReference` | `Having` |
| `UnknownAggregateTargetField` | `AggregateTarget` |

Every other producer/role pair omits context. SQL lowering construction is
separately closed to `Predicate`, `Projection`, `GroupBy`, and
`AggregateTarget`; `Having` and `OrderBy` must arise from their planner-owned
producers. Producer identity is not added to the public record.

## Complexity Assessment

Complexity increases narrowly at the intended boundary: one compact registry,
one root carrier field, one closed attachment adapter, one facade record, and
mechanical attachment calls at existing resolver seams. There is no new mode,
state machine, persistence, scheduler, or generalized typed-error framework.
The public and planner state-space delta is one optional bounded record; all
other state spaces are unchanged.

Patch 3 removes one separate E11 construction route and two obsolete helpers,
so the implementation shape becomes simpler while behavior converges on the
existing planner carrier. It adds no mode, state machine, persistence,
scheduler, format, or public state-space axis. The current 0.232.1 slice
touches four implementation/test files plus status and changelog evidence;
the production code shrinks while the net line increase comes from direct
regression coverage and documentation.
