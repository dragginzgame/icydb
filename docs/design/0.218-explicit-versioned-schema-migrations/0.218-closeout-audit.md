# IcyDB 0.218 Final Closeout Audit

Date: 2026-08-03

## Verdict

**Complete after bounded corrections; ready for the release owner's 0.218.0
push validation.**

All eight accepted landings are present. IcyDB now has one explicit adjacent
per-entity migration authority, one accepted-ID planner, one bounded durable
offline lifecycle, and one marker/journal publication path. Generated models
remain proposal inputs; accepted snapshots, accepted source bindings, durable
lineage, and the active migration record remain runtime authority.

The most serious closeout defect was an accepted-ID uniqueness check applied
across an entire store instead of within the owning entity or named type. A
real maintained `rank` to `score` migration therefore failed when an unrelated
entity used the same local field ID. The check is now owner-scoped and has a
regression proving both permitted cross-owner reuse and rejected same-owner
aliasing.

The final raw v1 and v2 Wasm artifacts complete every migration phase under
PocketIC, preserve exact progress across a same-plan upgrade, publish three
rewritten rows and one rebuilt index, and reject the predecessor field name.

## Findings And Corrections

### High — store-wide local-ID collision blocked a valid rename

The generic rekey helper treated local accepted IDs as globally unique across
one source-binding map. Fields, variants, members, constraints, indexes, and
relations are scoped identities. Rekeying now validates uniqueness only inside
the exact entity or named-type owner, preflights before mutation, and preserves
the predecessor binding on failure.

### High — a same-field cast could create a noncanonical layout

Physical lowering assigned the successor layout version to an existing field
whose scalar kind changed in place. Unchanged later fields still carried their
older introduction versions, producing invalid canonical order. Existing
fields now retain their accepted introduction version; only a genuinely new
target field receives the successor version. A realistic generated,
timestamped, indexed fixture covers rename plus same-field cast.

### Medium — terminal publication could look like deployment drift

Generated startup validated an active predecessor-bound plan before checking
whether the durable record was already `Applied` or `Aborted`. Since final
publication rebases the accepted head, the next ordinary call could return
`PlanChanged`. Terminal state is now recognized first, and the physical
migration regression proves that generated startup proceeds against the
terminal accepted head.

### Low — migration-disabled recovery retained unnecessary fallibility

The migration-disabled feature row compiled a helper whose only outcome was
`Ok(false)`. The no-capability branch is now a direct constant at the caller,
while the fallible record lookup exists only for tests or migration builds.
This keeps both all-feature and production-style no-migration Clippy clean.

### Low — release invariants contradicted accepted current spellings

The active persisted-format policy and guard still required every current
format number to be 1. They now preserve that default while recognizing one
exact documented exception: commit-marker version 2 with the version-1 decoder
deleted. The guard rejects every other format/version constant above 1 and no
longer mistakes capability bit names for codec versions or silently skips its
scan when ripgrep lacks PCRE2. The schema/model boundary guard now follows the
canonical `sort_unstable_by` spelling without weakening its ownership proof.

## Public And Persisted Format Inventory

The 0.218 line intentionally changes these current contracts:

- schema proposal transport is sole current version 2 and includes declared
  entity versions plus an optional canonical migration plan and digest;
- `ICYSLIN1` version 1 adds bounded, checksummed per-store/entity accepted
  source lineage in the generalized schema-control map;
- `ICYSMIG1` version 1 adds the bounded, checksummed exact-plan phase, cursor,
  counter, finding, generation, and terminal-receipt record;
- the commit-marker envelope is sole current version 2 with at most four
  canonical exact database-control operations and no version-1 decoder;
- journal batch version 1 adds current tags 8 and 9 for exact plan-bound
  migration row and candidate-index effects;
- public Candid adds controller update `icydb_schema_migrate`, query
  `icydb_schema_migration`, and their closed command/status/finding DTOs;
- public Rust adds the corresponding migration contracts and session APIs,
  while CLI adds deployed-only `status`, `adopt`, `advance`, `run`, and
  pre-rewrite `abort` operations.

Existing row envelopes, primary keys, secondary and reverse keys, accepted
snapshot codec, cursor wire, Identity state, and ordinary SQL/query responses
retain their current formats. A rename replaces its source binding; no old
name alias remains. Proposal version 1 and marker version 1 have no decoder,
translation, dual read, or fallback.

## Remaining Risks And Deferred Work

- Old physical index/relation generations remain inert after publication and
  require later explicit bounded maintenance; they are not runtime authority.
- Physical transforms remain journaled-store-only. Heap-backed state must be
  recreated rather than migrated.
- Raw backup, restore, import, online rolling schemas, multi-step version gaps,
  arbitrary transform callbacks, and SQL-authored migrations remain outside
  0.218.

These are explicit boundaries rather than hidden compatibility behavior. No
remaining 0.218 correctness or design blocker was found.
