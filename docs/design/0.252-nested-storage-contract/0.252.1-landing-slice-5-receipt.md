runtime, SQL, entity-scale, downstream, Candid, export, and indirect-call
gates. No public or persisted contract changed during closeout.

The first frozen Toko closeout build exceeded the fixed 4 KiB raw/code ceiling
at +5,011 raw bytes, +4,943 code bytes, and +22 defined functions. Rather than
widening that gate, the closeout retained three concrete simplifications:

- grouped plan/explain fingerprinting hashes borrowed field owners directly
  instead of allocating an intermediate field vector;

  recursive expression walker instead of parallel walkers; and
- direct group fields resolve without allocating dotted-path segments.

registry, mode, or generic convenience layer. It preserves the exact grouped
fingerprint byte contract while deleting duplicate traversal code. Relative to
the first closeout candidate, it removes 1,415 final raw bytes, 1,403 code
bytes, nine data bytes, and three defined functions from the frozen Toko
subject.

## Complexity And Validation

The closeout correction touches three production files and removes roughly 85
net lines. Its implementation shape is simpler: two duplicate recursive
fingerprint walkers and one allocated projection are replaced by concrete
borrowed owners, while the direct resolver gains a no-allocation fast path. No
behavior or state-space axis is added.

Focused fingerprint and group-field tests, the complete nine-test path
contract, three direct runtime runs, strict core/integration Clippy,
formatting, repository invariants, whitespace checks, the maintained optimized
Wasm matrix, and the frozen Toko A/B pass. One sandboxed PocketIC launch could
not bind its ephemeral loopback port; the same focused control was rerun
outside the network sandbox and passed three times.

The full repository/workspace suite was not run because repository policy
reserves it for the user-owned release workflow. With that remaining external
gate, 0.252.1 implementation is complete and ready for release validation.
