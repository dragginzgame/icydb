## Outcome

The concrete eligible-row feed is rejected. It made the generic unordered
runner smaller in source and final Wasm, but its shared non-inlined admission
call caused a reproducible scalar-path cold-runtime regression and added one
defined Wasm function. Inlining the feed restored the function count but grew
the optimized actor. No evaluated shape passed all declared gates.

The production runner was restored byte-for-byte from `v0.252.1`. No feed,
wrapper, callback, trait object, function pointer, strategy, route, allocation,
format, API, test fixture, or compatibility path remains.

## Concrete Feed Candidate

The candidate introduced one private `EligibleGroupedRowFeed` in the generic
runner. It owned data-key advancement, retained-row decode, absent-row skip,
effective residual filtering, and scanned/filtered accounting. The existing
`GroupProbeKind` remained selected before three small strategy-specific loops,
which continued to call the direct-borrowed, direct-owned, and path-aware
bundle methods without a per-row strategy branch.

The strongest source shape deleted the three repeated admission methods and
roughly 40 net production lines. It added no row/key clone, intermediate
envelope, callback, trait object, function pointer, registry, public type, or
behavior axis.

## Rejected Variations

- Inlining the feed's three-caller `next` body removed the additional function
  but duplicated enough optimized code to grow final raw and code by 1,465
  bytes each.
- Inlining the single-caller outer `execute` wrapper retained the extra
  function and saved only 290 raw and 291 code bytes.
- Inlining the unordered fold wrapper also retained the extra function and
  saved only 264 raw and 265 code bytes.
- Removing the feed constructor simplified source but did not change the
  optimized binary; the constructor was already eliminated.
- Per-row strategy matching, generic closures, macros, callbacks, trait
  objects, function pointers, and a cross-executor cursor were not introduced
  because they violate the design's hot-path or complexity boundary.

The wider SQL, SQL-off entity, and read-only Toko matrices were not rebuilt
after the primary feature actor and runtime gates rejected the candidate. Once
production source was restored exactly to the immutable tag, those subjects
have zero source-attributable delta by identity; rebuilding them could not
qualify a candidate that no longer exists.

## Validation And Complexity

Before rejection, all 44 focused core aggregate tests passed and eight of nine
end-to-end scalar-path grouping tests passed. The single failure was the
declared cold-runtime gate. After restoring production source, the exact cold
sentinel passed.

The final production complexity and Wasm delta are both zero because the
candidate was fully removed. This receipt and tracker updates are the only
retained changes. The full repository/workspace suite was not run under the
repository's user-owned release-validation policy.
