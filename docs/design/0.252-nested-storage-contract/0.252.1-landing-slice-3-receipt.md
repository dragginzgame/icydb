# IcyDB 0.252.1 Landing Slice 3 Receipt

- **Date:** 2026-09-01
- **Disposition:** accepted after explicit bounded shared-cost tradeoff
- **Baseline:** immutable `v0.252.0` (`B0`)

## Outcome

The candidate admits accepted scalar record paths as grouped keys through the
existing complete-hash executor. SQL and structural query construction converge
on one accepted-schema resolver. Grouped projection, expressions over the key,
raw-key `HAVING`, order, limits, cursor emission, and row-local aggregate path
inputs all use the same structural identity.

The canonical owner is `GroupFieldSet`:

- `Direct(Vec<FieldSlot>)` preserves the existing direct-only representation
  and hot loops;
- `PathAware(Vec<GroupField>)` is selected only when the query contains a
  scalar path; and
- `ScalarGroupPath` retains the normalized path, accepted root slot, diagnostic
  label, and only the derived canonicalization fact needed at execution.

The complete-hash runtime hashes and compares borrowed row values. It allocates
an owned tuple only when opening a new group. A prepared single-path raw-row
decoder avoids decoding the containing record for the common path-plus-COUNT
shape. Other aggregate inputs reuse the existing compiled-expression reader;
the candidate closes its former missing nested-path reader capability rather
than adding another aggregate route.

There is no new public mode, configuration, endpoint, Candid payload, generated
type, runtime registry, callback, indirect dispatch, persisted representation,
cursor encoding, or compatibility path. Ordered path-index selection remains
entirely outside this slice.

## Semantic Evidence

The frozen 2,048-row actor proves:

- required `profile.rank` groups equal the mirrored direct scalar groups;
- missing/null optional ancestors collapse into one null group;
- mixed direct/path tuples preserve declaration order and equality;
- path-key arithmetic, raw-path `HAVING`, grouped ordering, limits, and cursor
  emission execute with exact expected rows;
- `SUM(profile.rank)` remains a row-local aggregate input when a direct key owns
  grouping; and
- sibling projection, record-valued terminals, and unknown members fail closed
  under their maintained diagnostic classes.

Distinct required and optional path queries execute sequentially through the
same actor, which also exercises cache/fingerprint separation. The frozen actor
source, generated schema source, endpoint inventory, and 11,644-byte Candid are
unchanged from Slice 2.

## Rejected And Narrowed Alternatives

- A page callback or second path executor saved code but introduced indirect
  machinery and many vtable shims.
- A dedicated path-only COUNT terminal duplicated reducer policy and was
  removed; the existing generic grouped bundle owns the shape.
- Removing the prepared single-path decoder raised the path premium above the
  20% gate, so that concrete optimization remains.
- A compact direct descriptor inside the path-aware tuple grew the SQL-off
  actor by another 1,213 raw bytes and was reverted.
- Forcing no-inline field resolution was size-neutral and was reverted.
- Retaining full recursive accepted field kinds in each path descriptor cost
  740 raw bytes; the candidate now stores only the derived semantic bit and
  re-borrows exact type authority from `SchemaInfo` where required.
- A dedicated grouped cache-key enum was removed in favor of the existing
  projection-expression identity. The enclosing cache key already carries
  accepted schema identity, so a repeated root-slot discriminator added no
  safety.
- Two mutually exclusive single-row decoder options were collapsed into one
  prepared decode choice, removing an impossible runtime state without adding
  dispatch machinery.

## Complexity And Validation

Production implementation is moderately more complex: one internal group-key
source axis and one prepared raw path decoder are propagated mechanically
through planner, fingerprint, projection, and grouped-runtime owners. The
candidate touches about 62 production files with approximately 1,550 additions
and 390 deletions, plus the focused integration contract. It creates no public,
persisted, or operational state-space axis.

Focused core tests, the complete four-test group-path integration target, the
maintained direct ordered/hash control, strict core and integration Clippy,
formatting, repository invariants, and optimized Wasm measurements pass. The
full repository/workspace suite remains user-owned and was not run. The bounded
shared cost is accepted, the changelog is advanced, and Slice 4 remains the
next independent landing boundary.
