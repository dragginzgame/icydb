# IcyDB 0.252.1 Landing Slice 4 Receipt

- **Date:** 2026-09-02
- **Disposition:** accepted
- **Baseline:** immutable `v0.252.0` (`B0`)
- **Previous candidate:** accepted Landing Slice 3 (`B3`)

## Outcome

Accepted scalar record paths can now use the existing ordered grouped strategy
when one accepted semantic index contract structurally matches the declared
group-key prefix and is complete for the query. The route planner owns this
decision before execution:

- required non-null index keys are complete without an additional predicate;
- an omission-capable nullable key requires the existing predicate-implication
  proof that matching rows cannot contain null or missing values;
- accepted filtered-index guards retain their existing implication gate;
- mixed direct/path group keys require one matching composite prefix in
  declaration order; and
- a gap, order mismatch, expression mismatch, or uncertain completeness retains
  complete hash grouping.

Execution reuses the existing ordered grouped fold, one-live-group lifecycle,
closed-group emission, early scan stop, and current version-1 cursor boundary.
There is no third grouping strategy, path executor, runtime rediscovery of
completeness, callback, registry, or indirect dispatch.

The prerequisite index-key correction treats a null intermediate record as an
omitted index key instead of persisted-row corruption. Accepted incremental
writes and DDL rebuilds share one field-path resolver for that rule.

## Canonical Owner And Simplification

Accepted-schema construction already reduces every index to one
`SemanticIndexAccessContract`. Ordinary access planning and access-choice
reranking now derive order terms and completeness from that same contract.
This deletes the parallel accepted-field-path selector, its index-name lookup,
and the planner authority switch.

Nested accepted-field lookup and omittability checks walk dotted segments by
borrowed string slices. They do not allocate path vectors. The only new
completeness allocation is the small planner-time `IS NOT NULL` proof predicate;
there is no per-row retained allocation. The ordered runtime reuses Slice 3's
prepared single-path decode and owns a key only at the existing group boundary.

## Semantic Evidence

The frozen 2,048-row actor proves:

- a complete required `profile.rank` index selects `ordered_group` and returns
  the same 127 groups as the mirrored direct field;
- a complete mixed `(direct_rank, profile.rank)` index supplies one matching
  ordered prefix;
- the nullable `profile.optional_rank` index cannot serve an unfiltered complete
  grouping because its accepted shape can omit null/missing rows;
- `profile.optional_rank >= 0` supplies the accepted non-null implication proof,
  admits that index, and returns the same rows as the unindexed query;
- an actual composite `(direct_rank, optional_profile.rank)` index omits six
  matching null-root rows under `direct_rank = 0`; it is rejected until an
  additional path non-null predicate proves the stream complete;
- bounded ordered path grouping returns the exact first 17 groups and an opaque
  continuation cursor;
- deleting a row with a null intermediate record succeeds after the index is
  accepted, proving ordinary index maintenance shares rebuild omission rules;
  and
- unknown, sibling, and record-valued paths retain their typed fail-closed
  diagnostics.

## Rejected And Removed Alternatives

- A dedicated path-only COUNT dispatch duplicated reducer policy. It was
  removed; every path-aware aggregate uses the existing generic grouped bundle.
- Parallel accepted-path and semantic-contract order selectors produced the
  same canonical terms. The accepted implementation deletes the former and
  keeps one semantic authority.
- A narrower custom non-null proof added another implication implementation and
  grew Wasm, so the existing predicate implication authority is reused.
- Borrowing complete recursive accepted field kinds through the index matcher
  increased Wasm and reopened more schema structure than the proof needs; the
  candidate retains the compact semantic contract plus allocation-free schema
  lookup.
- Retaining separate accepted/rebuild path resolvers or the deleted planner
  authority solely to force exact `default_empty` bytes would preserve
  duplicate semantic owners. The accepted shared owners instead make that
  unaffected actor smaller.
