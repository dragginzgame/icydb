# IcyDB 0.252 Nested Storage Contract Status

## Decision

The user explicitly started 0.252 after reporting `v0.251.0` pushed. Direction
B is the accepted pre-1.0 product boundary: named-record scalar paths retain
their exact supported cells, while lists, sets, and maps remain bounded
owner-local aggregates with whole-field replacement.

Accepted schema remains the sole runtime authority. This line adds no document
mode, repeated-member traversal, multikey index, subpath mutation, nested
relation or uniqueness, capability tier, cursor format, or persisted state.

## Entry Audit

The released implementation already fails closed for unsupported nested paths:

- accepted nested-leaf metadata admits only scalar paths through named records;
- SQL and dynamic query lowering reject unresolved paths before execution;
- index DDL rejects unresolved or non-indexable paths before catalog mutation;
- generated fluent APIs expose no rooted repeated-member reference; and
- structural mutation resolves only complete root-field names.

The entry audit found one diagnostic-classification defect:
`mutation_structural_field_unknown` mapped an unknown root name, including a
dotted subpath spelling, to the compact executor invariant. Landing Slice 2
removes that special constructor and routes failed accepted-root lookup through
the existing executor-origin `RuntimeUnsupported` boundary.

The read-only source evidence is:

- accepted scalar-path lookup is owned by
  [`SchemaInfo::nested_sql_capabilities`](../../../crates/icydb-core/src/db/schema/info.rs);
- SQL projection and grouping consume that accepted lookup in
  [`sql/lowering/select`](../../../crates/icydb-core/src/db/sql/lowering/select/mod.rs);
- index DDL consumes it in
  [`sql/ddl/index`](../../../crates/icydb-core/src/db/sql/ddl/index.rs);
- structural patches resolve complete field names in
  [`session/write`](../../../crates/icydb-core/src/db/session/write.rs); and
- the shared executor-unsupported boundary is classified in
  [`error/mod`](../../../crates/icydb-core/src/error/mod.rs).

## 0.252.1 Slice 1 Result

The accepted design fixes one single-valued scalar-path contract and one
converged grouped execution flow. Direct-only queries keep the existing
`Vec<FieldSlot>` representation and hot loops. Only queries containing a path
use the path-aware key set, whose prepared reader hashes, compares, and
materializes values through the existing scalar path and `GroupKey` authorities.

The implementation plan separates the direct-preserving enabling change,
complete hash semantics, ordered path-index proof, and cumulative closeout into
independent measured handoffs. This adds no runtime code in Slice 1. The design
touches documentation only, leaves the 0.252.0 changelog unchanged, and keeps
Candid, generated APIs, formats, persistence, recovery, and Wasm reachability
unchanged.

## 0.252.1 Slice 2 Result

The retained `group_path_sql_query` actor freezes one direct scalar, required
and optional nested records, complete and omission-capable path-index workloads, a
2,048-row bounded loader, SQL query/DDL/mutation entry points, and no public
performance instrumentation. Its actor and generated schema source SHA-256
values are respectively
`e014f79760c79259e58630ee514b74174dddb7175480dd906ca77907f8f56283`
and
`b33429d5140d8c53d06e79da8fa3ddec471dd8cc746888904d9c49f3434f3b6c`.

The first candidate propagated a nominal direct/path owner through planner and
runtime DTOs. It stayed within the SQL actor ceiling but grew the SQL-off
reachable controls by about 3.8 KiB each. A transparent newtype reduced that
to about 215 raw bytes, and an erased alias reduced the exact normalized-path
Toko comparison to +27 raw/+37 code bytes. All three production candidates
were rejected because Slice 2 adds no user-visible behavior and its downstream
gate permits no growth. No owner, branch, wrapper, callback, registry, or
runtime route remains.

The final production source is identical to `v0.252.0`. The maintained
`one_entity_sql_query` artifact is byte-identical at 3,053,099 raw and
2,881,728 code bytes. The frozen comparable actor and its exact B0 source
overlay are byte-identical at 3,551,458 raw, 3,358,917 code, and 177,879 data
bytes, with 9,014 defined functions, 793 indirect calls, nine exports, and
11,644-byte Candid. Direct ordered/hash controls preserve exact rows and
resources while measuring 61,306,251 and 69,489,431 instructions, both below
the frozen controls.

The workload contract executes the direct control and freezes required,
optional, and mixed path-grouping rejection before Slice 3. Executing either
frozen nested-index DDL workload exposed the predecessor's structural
index-value serialization boundary as `RuntimeCorruption`, both during
backfill and subsequent indexed writes. Slice 2 does not freeze that defect as
expected behavior or widen into an index-storage repair; it is an explicit
precondition for the ordered-index work in Slice 4.

Slice 3 now owns the group-key representation and scalar-path hash semantics
as one atomic review boundary. This keeps Slice 2 simpler, avoids a
zero-benefit execution axis, and does not change public APIs, accepted schema,
persistence, cursors, formats, Candid, or runtime behavior.

## 0.252.1 Slice 3 Result

Accepted scalar record paths now execute through complete hash grouping with
exact required/optional/null, mixed-key, projection-expression, raw-key
`HAVING`, ordering, limit, cursor-emission, and row-local aggregate-input
behavior. Direct-only queries retain their existing key representation and
hot loops. Path-aware probes borrow row values and allocate an owned tuple only

## 0.252.1 Slice 4 Result

Matching complete path indexes now select the existing ordered grouped route.
The route planner proves stream completeness from accepted field omittability
and the existing predicate-implication authority before execution: required
non-null paths admit directly, nullable omission-capable paths require a query
proof excluding null/missing rows, and mixed direct/path keys require one
matching composite prefix. Uncertain cases retain complete hash grouping.

The ordered path workload returns exact rows and cursors at a 14.82% instruction
premium over its mirrored direct workload, below the 15% gate. The comparable
actor adds 3,131 raw and 3,144 code bytes while removing six functions from
Slice 3; cumulative growth from `v0.252.0` is 12,548 raw, 12,344 code, and 31
functions.
The SQL-off reachable pair stays inside its fixed 4 KiB/24-function allowance
with raw/code slopes 10 bytes below `v0.252.0` and an exact function slope.

Converging accepted/rebuild path traversal on one resolver also makes
`default_empty` smaller by 646 raw, 625 code, 13 data bytes, and 16 defined
functions. This favorable result does not meet the original literal
byte-identity wording. The accepted simplification direction rejects retaining
duplicate semantic owners solely to reproduce larger predecessor bytes;
indirect calls, exports, Candid, and empty-actor behavior remain unchanged.

Planner simplification removed a duplicate accepted-path order selector and a
separate authority switch. Planning and reranking now consume the same reduced
accepted-schema-derived semantic index contracts. No strategy, cursor form,
public API, persisted state, generated type, callback, or indirect dispatch was
added. Slice 4 was accepted; the cumulative SQL/Toko rebuild and closeout are
recorded in Slice 5 below.

## 0.252.1 Crate-Family Cohesion Correction Result

Runtime-enabled downstream crates can now use `icydb::model::prelude` with one
direct `icydb` dependency. Model macro expansion prefers a direct
`icydb-model` package for standalone schema tooling and otherwise resolves the
facade re-export, including renamed facade dependencies. The facade already
depended on the model package, so the re-export adds no dependency edge or
cycle.

The root workspace pins `icydb`, `icydb-core`, `icydb-diagnostic-code`,
`icydb-model`, `icydb-model-macros`, and `icydb-schema` to the exact current
version. Published member manifests inherit those requirements, and release
versioning advances the pins atomically with workspace package versions. A
future mismatched patch family therefore fails dependency resolution instead
of compiling incompatible macro output.

One facade-only workspace fixture proves model declarations and generated
runtime adapters with no direct model/core/schema dependency. This correction
changes no database semantics, Candid, persistence, cursor, recovery, or
runtime execution route. It adds no reachable production body; Wasm and
instruction measurements are not applicable to the package-resolution and
compile-time facade boundary.
