# IcyDB 0.252 Nested Storage Contract Status

Status: COMPLETE — READY FOR USER-OWNED 0.252.0 RELEASE VALIDATION

Last updated: 2026-09-01

## Decision

The user explicitly started 0.252 after reporting `v0.251.0` pushed. Direction
B is the accepted pre-1.0 product boundary: named-record scalar paths retain
their exact supported cells, while lists, sets, and maps remain bounded
owner-local aggregates with whole-field replacement.

Accepted schema remains the sole runtime authority. This line adds no document
mode, repeated-member traversal, multikey index, subpath mutation, nested
relation or uniqueness, capability tier, cursor format, or persisted state.

## Entry Audit

The released implementation already fails closed for unsupported nested paths:

- accepted nested-leaf metadata admits only scalar paths through named records;
- SQL and dynamic query lowering reject unresolved paths before execution;
- index DDL rejects unresolved or non-indexable paths before catalog mutation;
- generated fluent APIs expose no rooted repeated-member reference; and
- structural mutation resolves only complete root-field names.

The entry audit found one diagnostic-classification defect:
`mutation_structural_field_unknown` mapped an unknown root name, including a
dotted subpath spelling, to the compact executor invariant. Landing Slice 2
removes that special constructor and routes failed accepted-root lookup through
the existing executor-origin `RuntimeUnsupported` boundary.

The read-only source evidence is:

- accepted scalar-path lookup is owned by
  [`AcceptedSchemaInfo::nested_sql_capabilities`](../../../crates/icydb-core/src/db/schema/info.rs);
- SQL projection and grouping consume that accepted lookup in
  [`sql/lowering/select`](../../../crates/icydb-core/src/db/sql/lowering/select/mod.rs);
- index DDL consumes it in
  [`sql/ddl/index`](../../../crates/icydb-core/src/db/sql/ddl/index.rs);
- structural patches resolve complete field names in
  [`session/write`](../../../crates/icydb-core/src/db/session/write.rs); and
- the shared executor-unsupported boundary is classified in
  [`error/mod`](../../../crates/icydb-core/src/error/mod.rs).

## Slice 1 Result

The contract now publishes the exact shape matrix, scalar member-path cells,
whole-list/set predicates, optional missing/null and omission-index behavior,
whole-field write boundary, named-list durable maximum, and entity-modeling
decision. The maintained README, foundations, query, SQL, write,
schema-authoring, and diagnostics entry points converge on that owner.

The change is documentation-only: no production function, generated artifact,
public payload, persisted format, or Wasm reachability changed. Repository
complexity stays neutral: one canonical contract and one short status ledger
replace duplicated or implicit guidance, while the known diagnostic defect is
isolated instead of adding a second execution path.

Focused formatting, invariant, and whitespace checks pass. Full repository
tests and Wasm measurement are intentionally not applicable to this
documentation-only slice.

## Slice 2 Result

Unknown structural root fields and dotted subpath spellings now return the
existing executor-origin `RuntimeUnsupported` diagnostic. The obsolete
invariant constructor and unused entity-path plumbing are removed. No new
diagnostic enum, fact schema, public payload, registry branch, mutation mode,
or execution route is retained.

Focused coverage proves the same classification for a single mutation and a
late invalid item in an atomic batch, verifies the earlier batch item remains
uncommitted, and confirms complete root-field replacement still succeeds.

The maintained reachable actors both shrink against `v0.251.0`: one entity by
568 raw/558 code bytes and ten entities by 506 raw/494 code bytes. Exact Candid
and 717 indirect calls are unchanged. The raw entity slope is 40,115 bytes,
only 62 bytes above baseline, and continues to pass the 8 KiB gate. Full
evidence is recorded in the
[Landing Slice 2 receipt](0.252-landing-slice-2-receipt.md).

Focused core regression and all-feature Clippy checks pass, as do repository
formatting, invariant, and whitespace checks. The full repository suite remains
user-owned and was not run.

## Slice 3 Result

`DbSession::bind_typed_input` now converts an authored generated value through
one exact current `TypedEntityBinding` into the ordinary structural
`InputValue` boundary. It reuses the sole generated `TypedInputValue` encoder,
rejects stale bindings before conversion, maps unavailable accepted source
identities to `FieldUnavailable`, and leaves complete-field accepted admission
as the mutation authority.

The API adds no bound-value wrapper, second write cell, registry, mutation
variant, callback, persisted state, or compatibility route. Returning
`InputValue` also leaves `Omitted`, `Default`, `Null`, and `Value` intent with
the existing `WriteCell` owner.

The final representative pair now executes a generated nested record/list
through accepted conversion plus single and atomic-batch writes. The
one-entity actor is 2,910,803 raw bytes and the ten-entity actor is 2,952,157
raw bytes. The nine-entity delta is 41,354 bytes, or 4,595 bytes/entity, and
passes the 8 KiB gate. The earlier scalar isolation probe still attributes only
about 61 raw bytes per added entity to the adapter wrapper itself. Exact
190-byte Candid remains unchanged. Full evidence is recorded in the
[Landing Slice 3 receipt](0.252-landing-slice-3-receipt.md).
