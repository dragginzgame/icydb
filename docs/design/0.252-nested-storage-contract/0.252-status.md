## Entry Audit

The released implementation already fails closed for unsupported nested paths:

- accepted nested-leaf metadata admits only scalar paths through named records;
- SQL and dynamic query lowering reject unresolved paths before execution;
- index DDL rejects unresolved or non-indexable paths before catalog mutation;
- generated fluent APIs expose no rooted repeated-member reference; and
- structural mutation resolves only complete root-field names.

The entry audit found one diagnostic-classification defect:
`mutation_structural_field_unknown` mapped an unknown root name, including a
dotted subpath spelling, to the compact executor invariant. Landing Slice 2
removes that special constructor and routes failed accepted-root lookup through
the existing executor-origin `RuntimeUnsupported` boundary.

The read-only source evidence is:

- accepted scalar-path lookup is owned by
  [`SchemaInfo::nested_sql_capabilities`](../../../crates/icydb-core/src/db/schema/info.rs);
- SQL projection and grouping consume that accepted lookup in
  [`sql/lowering/select`](../../../crates/icydb-core/src/db/sql/lowering/select/mod.rs);
- index DDL consumes it in
  [`sql/ddl/index`](../../../crates/icydb-core/src/db/sql/ddl/index.rs);
- structural patches resolve complete field names in
  [`session/write`](../../../crates/icydb-core/src/db/session/write.rs); and
- the shared executor-unsupported boundary is classified in
  [`error/mod`](../../../crates/icydb-core/src/error/mod.rs).

## 0.252.7 C28 Execution-Trace Hard-Cut Result

`DbSession::debug()` set an internal trace flag, but all maintained scalar,
grouped, dynamic, exact-key, and SQL boundaries discarded the constructed
trace. C28 removes that misleading public method and the public trace DTOs
instead of preserving an API that could not produce an observable result.

The trace module, executor diagnostics node, profiler, timing helpers, scan and
rejection counters, and trace-only optimization labels are deleted. DISTINCT
and index predicates return to their direct execution forms. SQL `EXPLAIN`
still reports plan, access, and cache-reuse facts; the optional metrics report
still ranks entity hits and instruction cost; Canic still attributes endpoint
cost; and normal execution budgets remain enforced. A future actual-runtime
query profile would need a separate bounded result surface with a real
consumer, not a restoration of this discarded side channel.

Removing the diagnostic-step budget resource canonicalizes the remaining
resource codes in place. The current version-1 scalar page-profile identities
therefore change, and older in-flight scalar page cursors fail closed and must
be restarted. No predecessor identity, decoder, bridge, or alias remains.

Production and test source changes span 74 files and remove 1,884 net lines.
No feature, mode, persisted state, execution route, or compatibility path is
added, so implementation shape and state space are materially simpler.

Against immutable `v0.252.6` under the same maintained one-entity typed-query
production `wasm-release` policy, final raw Wasm falls from 1,906,076 to
1,905,935 bytes: 141 raw bytes removed. Gzip falls by 11 bytes, function count
is unchanged, and Candid is byte-identical. The result is primarily a
source-complexity reduction rather than a Wasm optimization.

Focused core, facade, diagnostic-code, CLI, execution, page-profile, compile
contract, strict lint, and maintained Wasm checks pass. The full
repository/workspace suite remains user-owned.
