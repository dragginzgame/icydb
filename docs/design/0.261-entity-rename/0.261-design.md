# 0.261 — Entity Rename Qualification

Authorised 2026-09-20 after the reported scoped-ready closeout of published
0.260.0. Delivery owner: [status](0.261-status.md).
Promotes only entity rename from the
[lifecycle idea](../ideas/entity-lifecycle-and-relation-ddl.md).

## Outcome and concrete transition

Qualify renaming a populated `Item` declaration to `CatalogItem` in the same
store, preserving rows, accepted identities, indexes and relationships. The
application reason is source/domain naming cleanup without delete-and-reinsert.
This is the example the user selected, not a claim that Toko Miner requires
this change. No downstream schema, source, dependency or deployed data is in scope.

Use a small journaled fixture: `Item` has a primary key, an indexed unique key,
a label and an optional self-reference; a second entity references `Item`.
The successor changes the entity name and dependent reference spelling only.
Do not combine field renames, casts, index redesign or store movement with it.
Freeze exact fixture declarations and inputs in E2 before implementation.

The existing source-migration mechanism already represents entity rename:
`EntityMigration::from_name`, generated as
`entity_migration(entity = "CatalogItem", from = 1, from_name = "Item")`.
This declaration fragment is not a complete compiled example. The target
entity declares the next application source version; internal encodings remain
their current version-1 form. Source versions are not format discriminators.

The initial need is a focused populated-rename qualification, not a missing
rename opcode. Reuse the existing mechanism first. If it satisfies the complete
contract, retain tests and guidance without adding production behavior.

## Required contract

- Preserve the database/store identity and logical memory allocation, entity
  tag, field IDs, unchanged constraint/relation/index IDs, row keys and bytes,
  row layout and unchanged physical index/reverse generations.
- Publish the current source name and accepted display/path metadata together
  with lineage and receipt. Resolve reads and generated successor bindings
  through accepted authority, with no generated-model fallback or old-name alias.
- Preserve indexed lookup, self/inbound relation validation, reverse lookup and
  delete restrictions on populated data. Determine the exact coordinated
  transition needed by the referencing entity; do not assume its digest stays
  unchanged or force a fake no-op rename to satisfy declaration admission.
- Reject missing predecessors, occupied target names, wrong stores, stale
  heads/versions and unexplained schema changes through existing typed errors,
  before changing accepted authority or row data.
- Preserve exact replay after a lost response and recovery across the compound
  publication boundary. Test stale bindings/cursors against maintained current
  authority rules; a stable entity tag alone must not grant admission.
- A pure name change should not rewrite rows or rebuild equivalent physical
  indexes. Establish this with counters/byte comparisons, not the absence of
  a transform declaration alone. Do not skip required preflight validation.

The tracker distinguishes native qualification from the remaining generated-actor
and IC-cost qualification; these requirements do not imply the latter is complete.

## E2 admission refinement

The populated probe demonstrated that an inbound relation changes its owner's
source digest. The user approved the narrow companion declaration on 2026-09-20,
subject to checking design drift. The explicit affected-entity/version contract
still applies; the original assumption that every transition needs its own
rename or row transform does not cover this real dependency change.

Admit `entity_migration(entity = "Holder", from = 1)` with Holder source version
2 only when reversing relation-target names from explicit entity renames in the
same plan reproduces Holder's exact accepted source digest. Keep every other
field, relation, index, constraint and reachable type meaning in that comparison.
Reject meaningless bumps and any other unexplained difference. This is a
current-format comparison proof, not a predecessor-format decoder or fallback.

Canonical owners remain the source digest, declaration and migration planner.
The simpler alternative (self-reference-only qualification) drops the selected
inbound workload. No implicit version bumps or artificial transforms are added.
State-space delta: one narrowly admitted existing declaration shape; zero new
opcodes, persisted states, formats or execution routes. Publication and recovery
remain unchanged. E2 includes this correction and its direct tests; E3 stays
separate.

## Simplicity, measurements and exclusions

Persisted/runtime state-space delta: zero; E2 admits one narrowly checked
declaration shape as described above. Keep one migration declaration,
accepted catalog, source lineage, publication marker and recovery flow. Do not
introduce rename modes, aliases, caches, tombstones, new persisted phases,
new format versions or a second migration command. Do not add rejection-only
scaffolding or tests solely policing removed compatibility surfaces.

Qualification may add test declarations and bounded fixtures. Report their
file/line delta separately from production changes. No performance improvement
is promised. E3 records raw non-gzipped Wasm and IC instructions/cycles; separate
fixture reachability overhead from runtime deltas. Any runtime optimization
claim needs matched inputs, outputs and build settings. Set numerical acceptance
criteria from the baseline before evaluating a candidate; no wall-clock proxy.
Unavailable measurements remain explicitly unmeasured.

No dynamic entity creation/removal, arbitrary SQL entity/relation DDL, store
rename/movement, primary-key change, relation-semantic change, rename swaps or
multi-hop rename programme is included. No deployed old-format migration bridge:
qualification actors use the same current internal version-1 formats. Preserve
the existing field/cast rehearsal; do not replace its coverage with this case.

Cargo version edits, commits, pushes and release publication remain user-owned.
Only focused tests/lints run here; full repository validation is user-owned.
Any local PocketIC lifecycle work is reported. Published 0.260 notes stay frozen.
