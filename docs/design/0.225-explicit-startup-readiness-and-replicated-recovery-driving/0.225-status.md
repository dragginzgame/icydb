### Fixed Observation Reads

The Patch 2 observer may read only this deployment-bounded set:

1. one startup receipt cell;
2. the 15-byte database boot record and one database-control frame/marker
   presence field;
3. the volatile recovered/in-progress witness for the exact recovery domain;
4. one fold watermark/cursor control and one tail proof identity for each
   statically generated journaled store; and
5. the one exact generated schema-application record selected by the generated
   submission key and accepted head/fingerprint.

It may not decode a journal record/batch, iterate retained history, load rows
or indexes, construct identity high-water state or constraints, run schema
proposal lowering, schedule a timer, or mutate stable state. The number of
reads may depend on the compile-time registered journaled-store count, never
row or journal cardinality.

### Actionable-Tail Authority

The current volatile recovery witness is keyed by commit allocation plus the
registered runtime-store domain. After it is established, a successful commit
appends its marker-bound journal batch, synchronously applies the live data,
index, schema, and database-control effects, then clears the marker. That tail
is historical durability input and is not startup-actionable in the same
recovered epoch.

After upgrade the volatile witness is absent. The same retained tail is then
startup-actionable and the lifecycle must register the watchdog. A marker or
fold cursor is always actionable. Tail non-emptiness alone must never move a
currently recovered domain back to `Recovering`.

### Exhaustive Commit-Exit Audit

Maintained marker-opening/finishing families are:

| Family | Marker/finish owner | Normal-success state | Normal-error state |
| --- | --- | --- | --- |
| Row, structural, SQL, and mutation-job target/progress writes | `executor::mutation::commit_window` through `begin_commit` or `begin_mutation_progress_commit` and `finish_commit` | journal/database-control effects and live projections applied; marker cleared; retained tail non-actionable in current epoch | apply error deliberately retains the marker and is an actionable transition |
| Accepted schema publication, identity range, constraints, and schema-application receipt | `commit::schema_publication` through the same guard | all marker effects applied; marker cleared; retained tail non-actionable | apply error retains marker and is actionable |
| Explicit schema migration page/control | `schema::migration_execution` through the same guard | migration effects/progress applied and marker cleared | apply error retains marker and is actionable |

`finish_commit` has one exact rule: `Ok` clears and verifies empty; `Err`
verifies the marker remains. Pre-commit failures occur before marker creation
or before target apply and do not create recovery work.

The guarded maintained runtime sources contain no `.await`, async function,
spawn, thread, or IC call boundary. Patch 1 extends the source guard to the
schema-migration executor as well as commit, mutation, SQL-write, and session
write paths. Generated maintained endpoint handlers are synchronous around
their database calls. Consequently:

- a trap or instruction exhaustion before normal return rolls the current
  message back to its start because no outgoing call boundary exists inside a
  commit window;
- returned success leaves no current-epoch actionable control; and
- returned apply error may commit a retained marker and therefore Patch 4 must
  atomically register the watchdog before that error is allowed to return.

Successful normal commits do not need 0.227 convergence scheduling for 0.225
readiness. Returned-error registration is the only exceptional post-`Ready`
transition owned by this line. Any future await/outgoing call inside these
windows reopens the promotion gate.

The pinned dispatcher:

- rejects once `ALL_CALLS >= 250` canister-wide;
- uses a self-call to `<ic-cdk internal> timer_executor`;
- increments the outstanding-call counter and reschedules a repeated/serial

- rejects external callers whose principal differs from the canister; and
- restores a serial closure after normal completion while duplicate/delayed
  callbacks must remain idempotent.

The IC execution contract rolls back state changed by a trapping message; an
earlier outgoing-call boundary is a commit point. The maintained IcyDB driver
will be synchronous, so its callback has no such internal boundary. Timers are
best effort, use self-calls, are subject to normal update limits, and disappear
on upgrade. One second is a requested minimum cadence, not a delivery SLA.

watchdog callbacks perform only fixed no-op control checks.

The watchdog remains operational only while the canister has enough liquid
cycles to dispatch its self-call. Insufficient cycles is not corruption and
cannot produce a failure receipt.

### Fixed Read And Failure Authority

The observer opens no request root or database session. It reads the startup
cell, the fixed boot and commit-control headers, the exact volatile recovery
witness, one proof/watermark/cursor control per statically registered
journaled store, and the exact generated schema-application record. It never
calls the recovery engine, decodes a journal batch, scans retained history,
loads rows/indexes/constraints/identity state, schedules a timer, or writes
stable state.

State priority is implemented directly:

1. directly readable control corruption or one exact binding-matched receipt
   returns its typed `StartupFailure`;
2. a marker, cursor, absent completed recovery witness, or unreconciled exact
   generated submission returns `Recovering`; and
3. only a completed current recovery witness plus an exact terminal generated
   application receipt returns `Ready`.

An allocation-only database receipt matches only when its persisted binding
has no readable control proof. A readable-control receipt must match the exact
incarnation and proof; journal receipts additionally match the generated store
allocation, tail proof, and existing fold cursor; schema receipts match the
incarnation, submission key, and accepted head. Stale bindings are ignored.

### Durable Receipt Contract

The sole current envelope uses magic `ICYSUP01`, format version 1, a bounded
payload length, and deterministic checksum. Its statically calculated largest
valid encoding is 960 bytes, below the frozen 2,048-byte cell maximum. The
first publication may grow exactly one 65,536-byte virtual-memory page; a
second page is rejected. All-zero is the sole absence representation.

Decoding is current-only, bounded, fallible, and canonical. It rejects future
versions, maximum-plus-one envelopes and fact counts, unknown diagnostic
codes/origins/fact tags, invalid fact schemas, invalid UTF-8, noncanonical
stable keys, invalid schema-submission keys, impossible kind/binding pairs,
invalid accepted-head revisions, malformed journal proof/cursor state,
trailing bytes, and arithmetic failure. Exact replay performs no write;
changed valid bindings replace the one receipt; clearing restores all-zero
absence. Publication remains dormant until Patch 3 supplies the complete
driver and authoritative clearing policy.

## Patch 3: Dormant Driver And Trap-Safe Watchdog

Disposition: complete.

### One Coordinator Over The Existing Engine

The hidden coordinator performs one pure observation, invokes at most one
existing bounded `continue_recovery` page, and returns exactly one of
`Terminal`, `Recovering`, or `ApplyGeneratedSchema`. It does not own journal
decoding, cursor movement, mutation application, schema lowering, request
policy, or a second execution route. The generated terminal branch calls the
existing generated fragment boundary synchronously only after recovery is
complete. An exact prepared/running migration continues to return
`Recovering`; only the maintained migration-control lane advances it.

Returned page errors are re-observed first. Directly readable corruption or an
existing matching receipt is terminal without copying another receipt.
Otherwise only the closed deterministic journal-recovery set may publish after
freshly capturing the current incarnation, sorted actionable journal
allocation, tail proof, and fold cursor. Generated-schema rejection similarly
re-captures the current accepted head and submission binding. Pending,
resource, bootstrap, and other retryable failures return without allocating or
replacing the receipt. Successful authoritative handoff clears a stale
receipt.

The observer was tightened so a matching schema-reconciliation receipt has
priority even when the failed reconciliation retained a commit marker.
Without that ordering, the callback could retire its watchdog while the public
state still reported only `Recovering`. A focused marker-plus-receipt
regression now proves the terminal failure remains visible.

### Dormant Generated Watchdog

Generated wiring now contains one retained `Option<TimerId>`, one re-entry
flag, and one same-IC-time cadence value. Registration uses only
`set_timer_interval_serial(Duration::from_secs(1), ...)`; duplicate
registration is idempotent, callback work is synchronous, and retryable normal

driver and therefore rolls back with a trap or instruction exhaustion. A
same-time duplicate, inactive logical registration, active callback, terminal
receipt, or `Ready` state performs no recovery page.

The implementation found one important pinned-library detail: removing a
serial task from inside its own callback causes the executor's completion guard
to restore a missing slot and trap, rolling back successful recovery. Terminal
completion therefore retires the logical `TimerId` immediately and schedules
one zero-delay cleanup message that calls `clear_timer` after the serial future
has returned. Already-dispatched callbacks see the retired logical
registration and no-op. The design authority now records this exact protocol.
