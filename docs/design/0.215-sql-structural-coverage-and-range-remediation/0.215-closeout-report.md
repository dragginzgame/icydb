# IcyDB 0.215 Final Closeout Audit

Date: 2026-07-30

Status: **ready after bounded corrections**

## Verdict

0.215 is ready for user-owned full push validation after the bounded closeout
correction in this worktree.

The adversarial audit found three P1 release-blocker classes in the original
0.215.0 proof:

1. generated structural signatures were parallel recipe-authored labels rather
   than identities derived solely from validated typed authority, required
   signatures were not frozen independently in the catalog, and the signature
   was redundantly serialized beside the replay AST;
2. the native Tier C Make target named a nonexistent test, so Cargo succeeded
   after running zero tests; and
3. scheduled mutation semantics were mislabeled: the accepted
   insert-from-query witness actually derived duplicate primary keys, while
   three intentional mutation rejections emitted ordinary passing receipts.

All are corrected. The current native evidence executes all 512 scheduled
scenarios through IcyDB, compares SELECT results with SQLite and mutation
results with an independent state model, and merges exactly eight clean shard
receipts:

- 512 observed scenarios;
- 448 passing scenarios;
- 64 expected typed rejections; and
- zero failures.

All six published 0.215 patch outcomes are now demonstrably complete within the
repository's focused-validation policy. Full workspace and push-time
validation remain explicitly user-owned.

The catalog contains 39 required obligations:

- 15 generated mutation witnesses; and

Roots, repetitions and generator output cannot add, remove or renumber that
universe. Unexpected observations do not satisfy scheduled obligations.
Every requirement now carries one full expected signature in catalog format 3.
The 32 generated requirements obtain it from a deterministic typed
construction that does not read the checked projection; the seven direct
requirements use explicit code-owned canonical constructions. Scheduled cases
must derive the same signature before they can execute, and observations remain
separate receipt-owned evidence.

`StructuralSignature` now stores one bounded canonical typed structure
(`testing/sql-generator/src/structure.rs:155`). SELECT and mutation signatures
derive from the validated typed trees
(`testing/sql-generator/src/structural_derivation.rs:145` and
`testing/sql-generator/src/structural_derivation.rs:205`).

Generated SELECT and mutation replay cases do not contain a structural
signature field (`testing/sql-generator/src/model.rs:1438` and
`testing/sql-generator/src/mutation/model.rs:2189`). Their public derivation
boundaries first validate the complete embedded declaration and then return a
new signature on demand (`testing/sql-generator/src/model.rs:1494` and
`testing/sql-generator/src/mutation/model.rs:2270`). Reports may serialize that
derived evidence; replay never treats it as authority.

The derivation:

- preserves repeated-same-field versus distinct-field relationships;
- preserves alias definition/reference topology while erasing authored alias

Prepared parameters are not an admitted generated shape: the current manifest

Seventeen SELECT obligations produce sixteen unique structural signatures.

(`testing/sql-generator/src/structure.rs:81`). Product observations use the
separate `ObservedExecutionFacts` type
(`testing/sql-generator/src/structure.rs:114`).

receipts obtain observed access and covering facts from IcyDB's accepted

facts are not embedded in, or inferred from, structural identity.

Native execution corrected three false scheduled assumptions:

- aggregate `DISTINCT` and aggregate `FILTER` are scheduled independently

- the generated alias rejection now uses an unknown projection-alias target,
  which IcyDB actually rejects; and

- one entity;
- at most 4,096 operations;

- at most 1 MiB of encoded public result;
- synchronous between admission and publication; and
- routed through the ordinary accepted mutation, marker, journal and recovery

It adds no compare-and-set, row revision, invisible retry, cross-entity

Duplicate target keys across operation kinds reject. For admitted distinct-key
mixtures, uniqueness and relation validation read the canonical final overlay.
Focused proof covers unique swaps and delete release, relation update-away and
source deletion, target recreation visibility, retained-reference rejection,
cross-entity rejection, missing targets, replacement semantics and managed
timestamps.

Caller key, accepted entity, primary-key scalar, final row slot and storage key
remain exactly bound. Generated Identity allocation occurs only for admitted
generating inserts. Update, delete, existing-row replace, recovery and derived
work allocate nothing. Rejected batches publish no row, marker, journal range
or Identity advance.

## Findings and corrections

### Corrected P1 — unfrozen, parallel and redundantly persisted structural identity

Evidence before correction: the generator constructed recipe labels separately
from the query, generated declarations supplied their own expected signatures,
and replay serialized the resulting signature beside the authoritative typed
declaration.

Correction: the label matrix was deleted and replaced by canonical derivation
from validated typed SELECT and mutation trees. Catalog format 3 freezes one
full required signature for every obligation before scheduled evidence runs.
Generated cases no longer own or serialize a signature; observations derive it
on demand and compare it with the frozen requirement. Focused relationship and
current-shape replay tests prove field identity, alias binding, numeric rank,
typed-null and text/prefix classes without redundant replay state.

### Corrected P1 — accepted insert-from-query witness rejected

Evidence before correction: the source predicate admitted two rows whose
number field was `40`, while that field became the inserted primary key. The
independent model therefore produced a duplicate-key rejection even though the
catalog classified the witness as accepted.

Correction: the bounded source range excludes the duplicate derived key. A
focused regression requires no modeled rejection and six final rows, and all
eight native shards pass with the accepted frozen signature.

### Corrected P1 — mutation rejections counted as passes

Evidence before correction: the mutation harness correctly required IcyDB and
the independent model to agree, but emitted `Passed` even when the modeled
outcome was a typed rejection. Generated declarations likewise classified all
mutation sequences as accepted.

Correction: declarations and native observations now derive acceptance from
the typed modeled steps. The focused mutation merge records 48 expected
rejections and 192 passes; the final combined native merge records 64 expected
rejections and 448 passes.

### Corrected P1 — fail-open zero-test Tier C gate

Evidence before correction: the shard Make target exited zero with `running 0
tests`.

Correction: exact native shard, merge and replay tests now exist. Every shard
run reports exactly one selected test, emits a current artifact, and the merge
requires complete clean evidence.

### Corrected P1 — scheduled claims disagreed with production SQL

Native execution exposed an unsupported aggregate pairing, an accepted
duplicate-alias query classified as a rejection, and unobserved covering
claims.

Correction: the catalog now schedules maintained independent aggregate forms,
one real typed rejection and exact observed row-backed execution facts.
Production SQL was not widened or altered.

### Remaining P2 — adapter negative matrix depth

The source-bound adapter architecture is complete, but maintained negative
compile fixtures do not independently enumerate every missing/wrong path,
mutual recursion and cross-module terminal-name collision.

### Remaining informational risk — full user gate

Repository policy reserves full workspace, live canister, performance and
push-time validation for the user. Focused closeout evidence cannot substitute
for that gate.
