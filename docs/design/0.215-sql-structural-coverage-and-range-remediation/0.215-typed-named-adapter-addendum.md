# IcyDB 0.215 Typed Named-Value Adapter Addendum

Status: complete, including the default-adapter hard cut.

## Problem

The first 0.215 implementation made runtime adapter generation an authored
schema choice named `typed_adapters`. That confused a package capability with
schema semantics and left the named types shipped by `icydb-model` without
runtime adapters: the model crate correctly has no dependency on the `icydb`
runtime facade, so its own declarations could not emit runtime-owned trait
implementations.

## Final Ownership

Typed value conversion is model-owned and generated for every named enum,
record, newtype, list, set, map, and tuple. The model contract is abstract over
its input/output context and therefore has no dependency on accepted catalogs,
runtime values, storage, or persistence.

The `icydb` facade implements that context for `TypedEntityBinding`. It maps
immutable authored source keys to current accepted type, member, and variant
names, and crosses the existing public `InputValue` / `OutputValue` boundary.
The facade re-exports the model-owned adapter traits for generated-code and
downstream compile contracts.

Entity row/write adapters remain runtime-owned. They are emitted automatically
when the declaring package has a direct `icydb` dependency, including a
Cargo-renamed dependency. A schema-only package with only `icydb-model`
continues to compile declarations and proposals without pulling in runtime or
persistence code.

## Conversion Contract

- Newtypes convert through their inner value.
- Lists, sets, and maps use the model-owned recursive collection adapters.
- Tuples use exact ordered list values.
- Records use exact maps whose accepted member names are resolved from source
  keys.
- Enums use exact accepted type paths, variant names, and optional payloads.
- `Option`, `Box`, and repeated values retain finite recursive conversion.

Output conversion rejects duplicate, missing, extra, non-text, or wrong-shaped
record fields; wrong tuple cardinality; wrong enum path or variant; and payload
presence mismatches. These are boundary failures, not accepted-schema
validation or persistence behavior.

## Hard Cut

- `typed_adapters` is no longer accepted by any model macro.
- There is no legacy alias, ignored option, or compatibility fallback.
- All authored named types, including `icydb_model::base::types`, implement the
  model-owned adapter traits automatically.
- Runtime entity adapters are a package capability, not schema metadata.
- No generated physical codec, runtime schema descriptor, validator callback,
  or persistence implementation is introduced.
- No persisted value, accepted catalog, or public response format changes.

## Required Proof

- compile coverage for every named form;
- direct facade-trait coverage for representative built-in record and enum
  types;
- nested payload and collection coverage;
- an admitted recursive named graph;
- renamed dependency paths;
- `X` and `XEntity` coexistence without synthesized-name collision;
- schema-only native and Wasm compilation without `icydb`;
- focused macro proof that named adapters contain no runtime crate path;
- focused entity adapter and facade checks.

The maintained SQL-free `one_entity_typed_query` subject measures 3,745,688
raw non-gzipped bytes. That is 1,567 bytes (`0.042%`) above the 3,744,121-byte
0.215 closeout artifact. The boundary is simpler overall: one model-owned
conversion family replaces the parallel model-macro/runtime implementations;
the modest net release growth makes that abstract contract and its focused
proof explicit.
