# IcyDB 0.215 Typed Named-Value Adapter Addendum

Status: complete for 0.215.3.

## Problem

The opted-in entity adapter emits accepted field contracts and calls
`TypedInputValue` / `TypedOutputValue` for concrete Rust field types. Scalar
and standard collection implementations exist, but generated enums, records,
newtypes, lists, sets, maps, and tuples implement none of:

- `TypedNamedType`;
- `TypedInputValue`;
- `TypedOutputValue`.

An entity field that references a named type therefore lowers into a valid
schema proposal but fails when the typed runtime adapter is compiled.

## Ownership

The accepted schema remains runtime authority. Named Rust types provide only
source-bound conversion between their authored Rust shape and the existing
engine-neutral `InputValue` / `OutputValue` boundary.

Each named declaration must opt in explicitly with `typed_adapters`. This keeps
schema-only model crates free of an `icydb` runtime dependency. Every named
type reachable from an opted-in entity field must opt in.

The macros implement the adapter traits directly on the authored type. They do
not synthesize an `Entity`-suffixed type or any other sibling type, so authored
types such as `X` and `XEntity` remain independent and collision-free.

## Conversion Contract

- Newtypes convert through their inner value.
- Lists, sets, and maps convert through the maintained standard collection
  adapters.
- Tuples convert through exact ordered `List` values.
- Records convert through exact `Map(Text(member_name), value)` entries.
- Enums convert through `Enum`, including exact optional payload shape.
- `Option`, `Box`, and repeated values retain their existing recursive
  adapters.

Named-type paths, enum variants, and record members resolve through immutable
source keys in the current `TypedEntityBinding`. Generated Rust identifiers
and authored display names are not runtime lookup authority. Output enum paths
and record/tuple cardinality must match exactly; duplicate, missing, extra, or
wrong-shaped values fail with `TypedAdapterError::ValueShapeMismatch`.

Finite values in admitted named-reference cycles are supported through the
existing indirect `Box` / collection shapes. No generated physical codec,
runtime schema descriptor, validator callback, or persistence implementation
is reintroduced.

## Hard Cut

This is a pre-1.0 additive authoring hard cut:

- no fallback to the retired generated row bridge;
- no blanket serde or Candid conversion;
- no compatibility facade;
- no automatic runtime dependency for schema-only named declarations;
- no new persisted or public-value format.

## Required Proof

- compile coverage for every named form;
- nested payload and collection coverage;
- an admitted recursive named graph;
- renamed dependency paths;
- `X` and `XEntity` coexistence without synthesized-name collision;
- macro-token proof that source-bound type/member/variant lookups are used;
- unchanged schema-only model compilation;
- focused entity adapter and facade checks.
