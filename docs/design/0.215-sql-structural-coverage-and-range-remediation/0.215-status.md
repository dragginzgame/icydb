## Bounded Native Runtime Isolation Correction

Status: complete.

A downstream generated canister exposed one native ownership mismatch:
`ic-memory` supplies thread-local default stable memory, while generated
bootstrap/schema readiness and several IcyDB recovery hints survived
process-wide. Ordinary libtest runs each test on a distinct thread even with
`--test-threads=1`, so one test could discard its memory while leaving a later
test an invalid initialized-state claim.

The current runtime now scopes every memory-derived readiness fact to the
existing thread-local generated store substrate. On single-threaded IC Wasm
that remains canister-lifetime state; in native libtest each memory-owning
thread receives matching bootstrap, schema-application, database-format,
recovery and marker-hint state. Allocation declarations remain process-wide
because they describe the linked binary rather than one memory instance. No
reset API, target-specific fallback, dependency downgrade, persisted-format
change or compatibility path was added.

Focused proof executes two one-row inserts in distinct libtest tests inside
one generated-canister test binary; both pass under ordinary libtest with one
worker. The generated target-scope test, native no-default core check and
maintained Wasm canister check also pass. The focused `wasm-release` build is
3,735,463 raw bytes, 1,027 bytes smaller than the locally staged
pre-correction artifact; that comparison is informational rather than a clean
release baseline. No performance benchmark was rerun because the hot path
retains one runtime-local readiness lookup and adds no storage work.

Complexity is seven files and approximately `+194/-169` lines overall, with
the net increase carried by the regression and documentation.
The production shape is simpler: three process-global readiness registries
were deleted and all memory-derived readiness now follows one ownership rule.
This correction is independent of the SQL structural slices and does not
authorize Slice 4 before the pending clean performance cohort.

## Slice 1 — Structural Authority And Typed SELECT Breadth

Status: complete.

`StructuralSignature`. Closed typed witness recipes derive the observed
signature independently, and generation fails when it differs from the frozen
required signature. Receipts retain the full signature; the distribution uses
its canonical digest only after full-signature receipt validation. Raw
declaration counts and repeated seeds are no longer presented as structural
breadth.

The fixed eight-family/eight-slot authority is deleted. The frozen catalog now
drives exactly 17 stable SELECT witnesses: 16 accepted witnesses and one
scheduled singly-invalid alias witness. Eight roots and two repetitions produce

scheduled accepted set executes 256 SQLite reference cases with no silent

Generation has exactly two accepted profiles:

- `reference_scalar`, with the maintained generated primary key and

bounded windows. Each AST-derived contract feature resolves to the existing
manifest; non-AST surface and route facts remain connected through the frozen
interaction-to-signature obligation rather than duplicated as generator labels.

Typed invalid generation expands from five templates to nine current rejection

target, limit overflow, unknown field, function signature, and operator type.
The full Tier C invalid profile produces 144 independently seeded,

SELECT generator and replay identities hard-cut to version 2. The shared

Every current shard and merged receipt carries catalog hash

## Slice 2 — Mutation Structure And Intent Provenance

Status: complete.

The four authored-scalar sequence vectors are replaced by the 15 frozen
catalog mutation witnesses. Each witness owns one full structural signature,
one exact profile, one primary intent class, and one SQL or SQL-and-typed
ingress requirement. Eight roots and two repetitions produce 240 exact Tier C
scenarios while retaining 15 distinct mutation structures.

Mutation generation now admits exactly two accepted test snapshots:

- `authored_scalar`, retaining the required `id`, `name`, and `age` profile;
  and
- `accepted_default`, with required caller-authored `id` and `name`, indexed
  `tier DEFAULT 'bronze'`, `score DEFAULT 7`, and nullable
  `note DEFAULT NULL`.

The typed mutation AST preserves authored, omitted, insert-`DEFAULT`,
update-`DEFAULT`, and update-preserve intent per field. The independent state
model resolves only the frozen accepted snapshot policy and derives affected
counts, normalized RETURNING rows, complete post-state, and complete logical
secondary-index state. Duplicate-primary-key batches reject atomically;
policy-free primary-key `DEFAULT` and required-field omission retain their
typed rejections; no-match update/delete preserves state.

Bundled SQLite executes every eligible witness from the exact modeled
pre-state and compares rows, RETURNING, affected counts, and the indexed
`tier` entries. Its adapter uses real table defaults for omitted and explicit
insert defaults and substitutes the same accepted constant only for SQLite's
lack of `SET field = DEFAULT`; typed IcyDB policy rejections and IcyDB-only
ordered mutation grammar retain explicit exclusions.

Mutation generator and replay identities hard-cut to version 2. Current
identities seed the frozen witness and repetition directly, and canonical
replay embeds the exact intent-bearing AST, full structural signature,
accepted snapshot, row/index outcomes, and minimized derivative. The old
fixed-family/case partition and collapsed omission/default representation have
no live owner.

Full-signature Tier C receipts now cover all 240 scheduled mutation scenarios.
Coverage distributions record both accepted profiles, SQL versus

## Slice 3 — Current Performance Profile And Attribution

Status: in progress — implementation and focused proof complete; clean
three-run P1/P2/scale calibration pending.

The current performance authority hard-cuts from version 1 to profile version
2 with stable identity `icydb-sql-performance/0.215/v2`. Comparable
environment receipts now carry that identity and diagnostics schema
`icydb-sql-attribution/0.215/v2`; the new required fields and structural sample
fields make old reports fail decoding or profile validation instead of
entering comparison.

Diagnostics-enabled attributed SQL queries now own one query-scoped structural
sample. It records:

- compatible compound-range conjunctions, extracted lower/upper bounds, and
  physical range children;
- effective runtime residual-predicate evaluations;
- authored, normalized, distinct, and null membership cardinalities;
- canonicalization passes and members revisited;
- prefix branches before and after deduplication;
- exclusion tests and pruned branches; and
- branch-cap admissions and rejections.

The scope resets before compile and is consumed after execution, so a warm
cache hit cannot inherit cold-query facts. Repeated perf endpoints average the
same structural counters as their existing instruction and store counters.
The matrix JSON retains every counter as a required current-schema field.

Focused live-canister evidence confirms the post-0.214 planner shape found by
Slice 0: the accepted equality-prefix plus compatible lower/upper query
examines one range conjunction, extracts one lower and one upper bound, emits
one physical range child, executes one index range scan, and performs zero
runtime residual evaluations. The historic two-one-sided-child shape therefore
does not reproduce in current source. No production range rewrite has been
started.

Focused membership and prefix evidence also proves that:

- SQL `IN` and `NOT IN` retain authored, normalized, distinct, null, pass, and
  revisit facts;
- duplicate membership distinguishes authored from distinct cardinality;
- admitted and over-cap branch sets report typed cap decisions; and
- exclusion-pruned over-cap work reports exact exclusion tests and removed
  branches before admission.
