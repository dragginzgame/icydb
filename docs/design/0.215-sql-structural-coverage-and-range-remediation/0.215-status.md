## Final Structural-Proof Closeout Correction

Status: complete.

The closeout audit found that Slice 1's maintained signature duplicated typed
query structure through recipe-authored labels, while the native Tier C Make
target selected a nonexistent test and passed after executing zero tests. The
bounded correction now:

- derives relationship-preserving canonical SELECT and mutation signatures
  directly from validated typed authority;
- freezes one full expected signature on every catalog requirement before
  scheduled generation or execution can emit observed evidence;
- removes the redundant serialized signature from generated SELECT and
  mutation replay cases so the typed declaration remains the sole authority;
- canonicalizes field, index, alias, literal-equality and literal-order
  relationships without retaining authored names or payload values;
- carries reviewed access/materialization requirements separately from
  product-observed plan facts;
- executes every scheduled SELECT through IcyDB and SQLite and every scheduled
  mutation through IcyDB and its independent state model;
- emits one exact receipt per scenario and rejects missing, stale, mismatched,
  duplicate or failed evidence; and
- makes shard and merge Make targets require one exact selected test plus a
  non-empty current artifact.

The native eight-shard merge is complete and clean: 512 observed scenarios,
448 passes, 64 expected typed rejections and zero failures. The catalog has 39
required obligations, including 17 generated SELECT and 15 generated mutation
witnesses. Seventeen SELECT obligations resolve to sixteen unique typed query
structures because cold-cache and full-window execution obligations
intentionally share one query structure.

Native execution also corrected three false catalog assumptions without
widening production SQL: aggregate `DISTINCT` and aggregate `FILTER` are
scheduled independently; an unknown alias target owns the generated rejection
case; and generated indexed witnesses record the row-backed materialization
actually selected by IcyDB. The obsolete regression input for the unsupported
pairing was deleted under the pre-1.0 hard-cut rule.

Freezing the expected signature independently exposed a fourth catalog defect:
the accepted insert-from-query witness selected two source rows with the same
derived primary key and therefore modeled a uniqueness rejection. Its bounded
source range now selects distinct derived keys, and focused plus native proof
requires the witness to commit.

The same audit found that three typed mutation-rejection witnesses emitted
ordinary passing receipts when IcyDB and the independent model agreed on
rejection. They now emit `ExpectedRejection`; the clean final merge records 48
mutation and 16 SELECT rejection receipts separately from 448 passes.

Current hard-cut test artifact versions are catalog 3 and generator, replay,
corpus, Tier C evidence, failure and distribution 3. No production SQL,
persisted database, Candid, public Rust API, dependency or package version
changed. Core additions are test-only plan inspection and the native harness,
so production raw Wasm is structurally unchanged.

## Bounded Native Runtime Isolation Correction

Status: complete.

A downstream generated canister exposed one native ownership mismatch:
`ic-memory 0.11.1` supplied thread-local default stable memory while its
bootstrap capability, generated schema readiness, and several IcyDB recovery
hints survived process-wide. Ordinary libtest runs each test on a distinct
thread even with `--test-threads=1`, so one test could discard its memory while
leaving a later test an invalid initialized-state claim.

`ic-memory 0.12.1` now owns its default memory manager, ledger cell, bootstrap
lifecycle, committed capability, opens, and diagnostics in one thread-local
`MemoryRuntime<DefaultMemoryImpl>`. IcyDB scopes every additional
memory-derived readiness fact to the same thread-local generated store
substrate. On single-threaded IC Wasm that remains canister-lifetime state; in
native libtest each memory-owning thread receives matching bootstrap,
schema-application, database-format, recovery and marker-hint state.
Allocation declarations remain one sealed process-wide snapshot because they
describe the linked binary rather than one memory instance. No reset API,
target-specific fallback, dependency downgrade, persisted-format change or
compatibility path was added.

The 0.12.1 floor also binds idempotent bootstrap to the exact sealed
declaration snapshot and semantic policy identity, preserves late constructor
registration failures in the registry lifecycle, and removes the redundant
snapshot-publication lock without changing the stable ledger format.

Focused proof executes two one-row inserts in distinct libtest tests inside
one generated-canister test binary; both pass under ordinary libtest with one
worker. The generated target-scope test, native no-default core check and
maintained Wasm canister check also pass. The focused `wasm-release` build is
3,738,307 raw bytes after the `ic-memory 0.12.1` floor, 701 bytes (`0.019%`)
larger than the 3,737,606-byte 0.12.0 artifact and 2,844 bytes (`0.076%`) above
the immediately preceding 3,735,463-byte local artifact. The increase reflects
the explicit runtime-state, typed memory-open, and repeat-bootstrap binding
boundaries; that comparison is informational rather than a clean release
baseline. No performance benchmark was rerun because the hot path retains one
runtime-local readiness lookup and adds no storage work.

The current workspace floor is `ic-memory 0.12.3`. This dependency-only hard
cut adds typed construction failure for foreign or unsupported memory-manager
headers plus bounded, fallible policy identity and policy-aware diagnostics.
The upstream stable ledger fixtures remain unchanged. The same generated
two-libtest reproduction passes, and the focused `wasm-release` artifact is
3,743,965 raw bytes: 5,658 bytes (`0.151%`) above the 0.12.1 artifact. This
follow-up changes only the workspace dependency, lockfile, and release/status
documentation; production structure and hot-path complexity remain neutral.

Complexity is seven files and approximately `+194/-169` lines overall, with
the net increase carried by the regression and documentation.
The production shape is simpler: three process-global readiness registries
were deleted and all memory-derived readiness now follows one ownership rule.
This correction is independent of the SQL structural slices and does not
alter the detached clean performance subject or Slice 4's measured no-change
disposition.

## Atomic Mixed Structural Mutation Addendum

Status: complete.

Before Slice 6, the maintained structural facade could not publish a
heterogeneous same-entity mutation set atomically. Conservation-sensitive
split and merge operations therefore could not migrate safely by composing
separate calls.

Slice 6 generalizes the existing accepted mutation scheduler and mixed
`CommitRowOp` journal boundary. It owns one final-row overlay, per-item save or
delete intent, relation validation against final staged state, interleaved
Identity allocation ordinals, bounded precommit result preparation, and
generic mixed-operation recovery proof. It introduces no cross-entity
transactions, new persisted format, or generated typed persistence path.

Slice 6 freezes the following admission limits before implementation:

- at most 4,096 submitted operations;
- at most 16 MiB of cumulative staged structural bytes, counted with checked
  arithmetic across every encoded target key and canonical before/after row
  image;
- at most 1 MiB for the exact Candid-encoded `DynamicMutationResult`;
- the existing 4 MiB per-row limit remains independently enforced; and
- the exact encoded marker and journal must independently fit the existing
  16 MiB commit window. A 4,096-operation Identity batch needs at most 4,097
  journal records, below the existing 16,384-record journal ceiling.

The focused implementation targets are the core mixed structural-mutation
module tests, journal Identity-range tests, relation final-overlay tests,
generic commit-interruption/recovery tests, and the SQL-free plus SQL-enabled
public facade compile contracts. The full contract and closeout checklist are in
[0.215-atomic-mixed-structural-mutation-addendum.md](0.215-atomic-mixed-structural-mutation-addendum.md).

The implementation adds one public
`execute_trusted_structural_mutation_batch` facade and makes the single and
insert-only helpers delegate to it. One per-item accepted intent and scheduler
now stages insert, update, replace, and delete operations, rejects duplicate
keys across operation kinds, and hands one mixed row set plus delete-key set to
the existing commit window. That window constructs one final primary-row
overlay, uses it for delete relation proof and normal save-side preflight, and
publishes one unchanged marker/journal format.

Public result conversion and exact Candid sizing run in the precommit closure.
Identity allocation counts only interleaved generating inserts, while journal
proof filters existing-key puts and deletes from the contiguous new range.
The generic interruption harness now covers marker, journal, first-row prefix,
complete rows, and state materialization even when a batch owns no Identity
range.

Focused proof covers mixed update/insert/delete result order, duplicate-target
state neutrality, exact item/staging/result boundaries, filtered mixed
Identity journal proof, and every journaled caller-key publication boundary.
Accepted-catalog final-overlay tests prove relation source deletion,
update-away release, retained-reference rejection, batch-final target
visibility, unique swap/release, cross-entity rejection, missing targets,
insert collisions, ordinary replacement, one managed timestamp, and late
durable-rule failure neutrality.

Focused validation passes:

  state-neutrality, duplicate targets, deterministic rows, interleaved
  Identity, and exact item/staging/result bounds;
- two final-overlay visibility tests, the maintained exact Identity journal

  journaled recovery;

At handoff, the worktree diff excluding the independently owned `Cargo.toml`

## Typed Named-Value Adapter Addendum

Status: complete.

Before Slice 7, an opted-in typed entity could bind a named accepted field but
the authored named Rust type had no generated `TypedNamedType`,
`TypedInputValue`, or `TypedOutputValue` implementation. Valid schemas
therefore lowered successfully and then failed when their typed runtime
adapters compiled.

Every named enum, record, newtype, list, set, map, and tuple may now opt in
explicitly with `typed_adapters`. The macros implement those three traits
directly on the authored type. They do not derive a public sibling name from
the authored identifier, so independent declarations such as `X` and
`XEntity` cannot collide through adapter generation.

The conversion boundary remains the existing public `InputValue` /
`OutputValue` contract. Accepted source bindings resolve current named-type,
enum-variant, and record-member names. Record decoding uses one exact helper
that rejects duplicate, missing, extra, non-text, and wrong-shaped members;
tuples and enum payloads likewise require exact cardinality and shape.
Newtypes and collection wrappers delegate to the maintained recursive
adapters, including finite values in admitted indirect named-reference cycles.
No generated physical codec, persistence implementation, schema fallback, or
runtime callback was added.

Focused proof covers every named form, nested enum and record values, nullable
tuple members, a recursive record, renamed `icydb-model` and `icydb`
dependencies, and simultaneous `X` / `XEntity` declarations. Macro tests prove
that type/member/variant lookup is source-bound, facade tests prove exact
record output admission, and the schema-only model fixture still compiles
without the runtime facade. Affected warnings-denied Clippy, `icydb` and
`icydb-core` no-default checks, formatting, and diff hygiene pass. Full
workspace validation remains user-owned.

The maintained `one_entity_typed_query` artifact remains exactly 3,743,965 raw
non-gzipped bytes, unchanged from the 0.215.2 baseline because that scalar-only
fixture does not instantiate a named adapter. The slice spans 19 files and is
approximately `+891/-22`; generated macro implementations, focused fixtures,
and design/release documentation carry the increase. Runtime ownership stays
neutral: the only facade addition is exact record public-value decoding, while
the supported boundary becomes moderately broader.
