# IcyDB 0.219 Diagnostic Fact Inventory

Status: Patch 1 authority

Baseline: `v0.218.1` / `e05f4a9707952545402284c4933b27276f2b97b9`

This inventory freezes the numeric vocabulary available to every 0.219
subsystem projection. The code-owned registry in `icydb-diagnostic-code` is
authoritative; this document records its intended meaning and staged owners.

The leaf E-code remains the error reason. A fact supplies only one numeric
parameter for that reason. No fact may contain or identify arbitrary prose,
names, principals, SQL text, values, keys, rows, persisted bytes, cursor bytes,
or hashes of caller data.

## Global Contract

- Public representation: `tag: u8`, `value: u64`.
- Global error bound: 80 facts.
- Tags 1 through 89 are assigned below. Zero and 90 through 255 are unknown.
- Unknown tags remain numeric. They are never translated or treated as aliases.
- Two accepted `u32` identities use the registry-owned high/low packing helper.
- Successful execution does not allocate a fact sequence.
- Patch 1 changes the public record but emits an empty sequence from all current
  E1 through E268 producers. Later patches activate facts only at their typed
  subsystem owners and within this frozen vocabulary.

## Per-Code Schema Inventory

At the Patch 1 boundary every existing E1 through E268 producer has the exact
schema `[]`: it emits no facts. This is intentional staged ownership, not an
implicit fallback. The public hard cut removes the former special constraint
payload first; each following patch activates exact required, optional,
repeatable, and ordered tags at one typed authority.

| Patch | E-code owners | Planned schema family |
| --- | --- | --- |
| 2 | E6, E19, and typed recovery/format subreasons | decode reason, lengths, offsets, versions, signatures, component/state kinds |
| 3 | E196, E232-E240, and accepted stale-authority conflicts | accepted identity, mutation operation, batch positions, counts/limits, expected/current revision |
| 4 | query/planner/SQL leaf codes whose typed variants already retain positions or bounds | clause/term/projection/group/aggregate/argument/branch/parameter indexes, arity, width, count, compact kinds |
| 5 | E223 and E225 | exact accepted fingerprint, entity/constraint identity, kind/context, operation, batch position, repeatable targeted-value path |
| 6 | host tooling only | no new engine fact schema; validates and humanizes schemas activated by prior patches |
| 7 | selected storage, row, commit, index, and relation corruption leaves | layouts, slots, lengths, components, memory IDs, logical IDs, generations, arity, compact value/key kinds |

Errors not explicitly activated by their owning patch remain code-only. A
later patch may select fewer safe facts than this inventory permits, but it
must not introduce another tag, reinterpret a value, expose forbidden data, or
construct facts outside the typed subsystem that already owns the context.

## Ordering And Repetition

- Common authority facts precede operation/location facts.
- Expected/actual and bound facts follow location facts.
- Compact kind facts follow the identities they classify.
- Targeted-value path facts are the only generally repeatable family and form
  one final ordered suffix whose traversal order is semantically significant.
- Duplicate-position pairs use `First*` before `Duplicate*`.
- Unknown, disallowed, missing, repeated, or noncanonical facts are rendered
  numerically by host tooling and never change the E-code classification.
