## Frozen Cross-Patch Invariants

- E-code values remain stable.
- The E-code owns the reason; facts carry parameters only.
- One `tag: u8, value: u64` fact representation serves every immediate error.
- The public fact sequence has a global bound of 80 and tighter per-code bounds.
- No fact contains a name, path, principal, SQL text, value, key, row, arbitrary
  bytes, hash of user data, or rendered/debug text.
- Full accepted-schema fingerprints may be carried only to bind schema-owned
  numeric identities to exact host metadata.
- `ConstraintDiagnostic` does not remain as a second immediate-error payload.
- Historical validation findings retain the bounded row locator required by
  their explicit operational lifecycle but do not constrain ordinary errors.
- No feature changes the public error ABI.
- Host renderers and artifact parsers do not enter production canister
  dependencies.
- Successful execution paths allocate no diagnostic facts.
- No persisted database format changes.
- No compatibility alias, dual decoder, or legacy fact spelling is added.

## Patch 1 — Compact Fact Contract And Public Hard Cut

Status: complete.

### Implementation

- `icydb-diagnostic-code` owns one contiguous fixed registry of 89 numeric fact
  tags, the global 80-fact bound, and exact big-endian accepted-ID pair packing.
  It retains no Candid dependency, fact labels, prose, or subsystem renderer.
- Public `Error` is now exactly `code`, `class`, `origin`, and
  `facts: Vec<DiagnosticFact>`. `DiagnosticFact` is exactly `tag: u8` and
  `value: u64`; the former optional immediate `ConstraintDiagnostic` field and
  `constraint_diagnostic()` accessor are removed without an alias or dual wire
  shape.
- Existing producers emit an empty fact sequence at this landing. Typed family
  projections activate in Patches 2 through 7 at their existing subsystem
  owners; Patch 1 does not manufacture context at the facade.
- The CLI renders every known tag with one host-owned numeric label and every
  unknown tag as `tag#N=value`. Production canister crates do not acquire the
  label table or formatting path.
- Historical constraint-validation output retains its separate operational
  `ConstraintDiagnostic` payload until the Patch 5 finding split. It is no
  longer reachable through ordinary `Error`.
- Both maintained transitive Candid goldens carry the current public hard cut.
  The migration-only golden drops the rich constraint types that were
  reachable solely through the retired error field.

### Format And Behavior

- This is a breaking public Candid change. Downstream actors must regenerate
  bindings for the sole current pre-1.0 error record.
- E-code values 1 through 268, class/origin semantics, authorization, success
  responses, execution behavior, and every persisted database format are
  unchanged.
- Fact construction is error-path-only. Patch 1 adds no allocation or new
  branch to successful query, mutation, commit, or recovery execution.

## Patch 3 — Mutation, Bounds, And Stale-Authority Context

Status: complete.

### Implementation

- `icydb-diagnostic-code` owns one fixed four-value mutation-operation registry:
  insert, replace, update, and delete. The facade reexports the same numeric
  vocabulary; no frontend owns a second operation mapping.
- Accepted runtime field contracts retain their durable `FieldId` only when
  they are built from accepted schema. Synthetic decode contracts do not invent
  a sentinel ID. Typed, dynamic structural, and SQL-backed writes continue to
  converge on the same accepted row resolver.
- Required-field, database-owned-field, and managed-timestamp failures retain
  accepted entity/field identity, operation, and zero-based input position.
  Batch admission retains exact counts and byte limits; mixed-entity failures
  retain the offending position and expected/actual entity tags.
- The mixed-batch scheduler retains the first input ordinal beside each staged
  key, allowing E240 to report first/duplicate positions without retaining the
  key in the error. The existing bounded scheduler remains the sole duplicate
  authority.
- Stale accepted-authority failures preserve the expected revision and optional
  current revision at their typed query-owned boundary.
- Numeric context is stored behind one cold, thin, error-only allocation. An
  attribution check caught and removed an intermediate representation that
  enlarged central error enums; the final `InternalError`, `ErrorDetail`,
  executor-detail, and query-detail layouts exactly match the Patch 2 sizes.

### Format And Behavior

- Public and transitive Candid are byte-identical to Patch 2. No persisted
  format, E-code, class/origin, mutation decision, accepted schema, or success
  response changes.
- E232 generated-constraint-activation staleness has no live typed producer and
  remains code-only. E196, E233-E240, and accepted stale-authority conflicts
  use the exact schemas frozen in the fact inventory.
- Successful execution allocates no diagnostic facts. The bounded mixed-batch
  scheduler now retains one `u32` first ordinal per distinct staged key, and
  accepted field runtime contracts now carry one `u32` durable field ID;
  successful mutation semantics are unchanged. No success-instruction delta is

## Patch 5 — Accepted-Constraint Hard Cut And Finding Split

Status: complete.

### Implementation

- `icydb-diagnostic-code` now owns fixed numeric constraint-kind and
  constraint-context registries. E223 and E225 emit one canonical sequence:
  full method-bound accepted fingerprint, entity tag, entity-local constraint
  ID, kind, write-admission context, optional mutation operation and input
  position, then the bounded typed path for targeted rules.
- Check, not-null, targeted-rule, unique-index, relation-save, relation-delete,
  and activation-write blockers converge on the same fact owner. Unique and
  relation detection retain `Executor` origin and do not create physical-layer
  public error variants.
- The mutation scheduler annotates each transient commit row with operation
  and batch position. That context is deliberately absent from marker and
  journal encoding, so recovery replays current durable bytes and allocates no
  new diagnostic identity.
- The compiled row-constraint program no longer stores or clones accepted
  constraint names or rendered field paths for failures. Deep integrity
  resolves its human-readable finding lazily from the accepted snapshot only
  after corruption is observed.
- Explicit validation progress now returns
  `ConstraintValidationFindingOutput`: exact accepted fingerprint, entity tag,
  constraint ID, bounded primary-key locator, accepted field IDs, optional
  typed value path, and numeric error code. Ordinary errors cannot inherit the
  finding locator, names, keys, values, or rows.

### Format And Behavior

- The SQL-enabled transitive Candid hard-cuts the historical finding response
  from the former rich constraint record to the dedicated numeric repair
  record. The common immediate `Error` shape remains the Patch 1 fact shape;
  E223/E225 now populate it without a second payload.
- The version-1 durable validation-job golden bytes are unchanged. Commit
  markers, journals, accepted schema, rows, keys, cursors, and every other
  persisted format are unchanged; no legacy decoder or compatibility alias is
  retained.
- Validation acknowledgement, activation promotion, recovery, write
  admission, and successful mutation semantics are unchanged. The change is
  confined to failure projection and the explicit historical finding output.
