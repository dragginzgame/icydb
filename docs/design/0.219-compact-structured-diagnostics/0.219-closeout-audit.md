# IcyDB 0.219 Final Closeout Audit

Date: 2026-08-04

## Verdict

**Complete after bounded corrections.**

The Compact Structured Diagnostics implementation is functionally complete
after one bounded closeout correction: the design's per-E-code fact schemas
are now executable at the core, public-facade, and host-tooling boundaries.
Malformed projections fail as compact E20 errors without partial facts, and
malformed host input remains numerically renderable without name resolution.

The two persisted-codec replacements shipped in 0.219.0 are valid pre-1.0
current-only hard cuts. They are bounded, explicitly documented, covered by
current golden/corruption tests, and retain no predecessor decoder or
translation path. They do not alter successful runtime semantics.

The maintained CLI now implements the complete resolver order: exact deployment
artifact, explicit live introspection, exact fingerprint-bound source metadata,
then complete numeric fallback. Source metadata can be created only by rebinding
a validated exact accepted artifact; it preserves the accepted artifact mapping
and uses a distinct non-interchangeable provenance kind. It never infers
accepted identity from source names.

## Authority, Registry, And Projection Assessment

The immediate public diagnostic shape is unique:

```text
Error { code: u16, class: u8, origin: u8, facts: Vec<DiagnosticFact> }
DiagnosticFact { tag: u8, value: u64 }
```

`ConstraintDiagnostic`, `Error.constraint`, its accessor, aliases, and dual
decoders are absent from maintained code and generated Candid. The only
remaining `.constraint()` methods belong to relation-edge internals and are
unrelated to the retired public error payload. Public fields are private;
public constructors accept only fixed diagnostic codes/classes/origins, and
the sole numeric fact constructor remains private to the facade.

The E-code registry and detail mapping files are byte-identical to the 0.218.1
baseline. Therefore E1 through E268 retain their frozen numeric identity,
class, default origin, and categorical meaning. The fact-tag registry owns 89
unique contiguous `u8` identities. Its compact enum registries own constraint
kind/context, operation, decode reason, component, type, function, operator,
and aggregate meanings; accepted-ID pairs use explicit big-endian `u32`
packing.

The closeout correction adds one allocation-free per-E-code validator beside
that registry. It owns each currently fact-bearing leaf code's exact allowed
sequence, required order, legal repetition, compact-value domain, and tighter
maximum. E223 permits at most 73 facts (seven authority facts, two operation
facts, and 64 accepted path components), E225 permits nine, and every other
current producer has a maximum of zero through six. The global maximum remains
80. Unknown raw tags remain printable by tooling but invalidate a known code's
schema; there is no heuristic reinterpretation.

Core construction validates before storing a fact-bearing detail. Failure
returns E20 at the original origin with no fact payload. The public facade
validates again before allocating `Vec<DiagnosticFact>`, covering direct
`QueryError` projection independently. Host tooling validates before artifact
or introspection lookup; malformed context is rendered numerically and name
resolution is withheld. All maintained fact counts arise from fixed local
projections or already-bounded accepted paths, so no untrusted count controls
production allocation. Successful paths never call a fact builder or schema
validator.

Representative tracing confirms one projection boundary:

- validation, intent, planning, grouping, expression, projection, cursor, and
  execution variants expose facts through `QueryError::diagnostic_facts` and
  cross the facade once;
- SQL lowering and SQL-write boundary errors project at their typed owners;
- dynamic, structural, generated typed, and SQL writes converge on core
  mutation errors and do not construct public facts themselves;
- mutation batch duplicate-key errors retain entity tag plus first and
  duplicate input positions only; and
- store, row, commit, index, and relation code projects only compact numeric
  context through canonical `InternalError` constructors.

## Constraint And Historical-Finding Assessment

E223 and E225 carry fingerprint method, both exact 64-bit fingerprint halves,
entity tag, entity-local constraint ID, constraint kind/context, optional
mutation operation and batch position, and an optional bounded packed accepted
value path for E223 targeted rules. Immediate errors carry no entity, field,
constraint, index, or relation names; no row, primary key, conflicting key,
literal/value, arbitrary bytes, or diagnostic prose.

Check, not-null, relation, targeted-rule, and unique violations remain
distinguishable by compact kind under E223. Activation barriers remain E225.
The unique-index planner produces E223 with `ErrorOrigin::Executor`; its
entity path is retained only in an internal metrics wrapper and never enters
the public error. The closeout regression now asserts the exact code, executor
origin, nine-fact payload, operation, and batch position.

Historical activation/integrity findings remain a distinct
`ConstraintValidationFindingOutput` containing exact fingerprint, entity and
constraint IDs, durable primary-key locator, field IDs, optional typed value
path, and error code. Immediate `Error` has no route to the finding's primary
key. Focused finding tests prove bounded path rejection, round-trip, and
activation binding. Acknowledgement/replay behavior was not changed by the
diagnostic correction.

Relative to 0.218.1 the validation job changes from Candid/Serde to checksummed
`ICYCVJOB` version 1, and the `ICYSAR01` version-1 envelope retains its version
while replacing its payload mapping. These are deliberate pre-1.0 hard cuts:
only the bounded current encodings are accepted, current golden/corruption
tests pass, and no compatibility decoder remains.

## Tooling, Security, And Negative Space

All human labels, reasons, hints, and schema-name resolution reside in
`icydb-cli`. Exact artifact resolution requires fingerprint method, every
fingerprint bit, entity tag, and, when present, constraint ID. Explicit live
introspection is attempted only when an exact supplied artifact did not
resolve. A wrong version, unknown artifact field, wrong provenance, wrong
method/fingerprint/entity, missing complete identity, or malformed fact schema
fails closed to numeric output. E223 remains useful without any resolver.

`icydb schema diagnostic-source-metadata` binds a validated exact deployment
artifact to one bounded source label without changing any accepted identity or
numeric mapping. `icydb diagnostic --source-metadata` reads only that provenance
kind and consults it after deployment artifact and live resolution. Exact
fingerprint method, all fingerprint bits, entity tag, and requested constraint
identity must match; otherwise names are withheld and numeric rendering remains
complete. Generated models therefore never become runtime authority, and a
deployment artifact cannot impersonate source metadata or vice versa.

Production dependency trees contain neither `icydb-cli`, `ic-testkit`, Clap,
nor the CLI terminal stack. Raw production-Wasm string inspection finds none
of the host diagnostic headings, fallback/hint prose, component labels, or
artifact-parser messages. Ordinary schema, SQL, and dynamic-API strings do
remain, as expected; this audit does not overclaim that production Wasm is
globally string-free.

Repository searches find no public diagnostic constructor accepting prose,
principals, SQL text, values, keys, row/cursor/marker/stable-memory bytes,
arbitrary hashes, or unrestricted byte vectors. Internal rich typed errors may
retain data needed by their subsystem, but the sole facade projection ignores
anything outside the code-owned numeric schema. No renderer or artifact parser
enters a canister dependency graph, no feature changes `Error` Candid, and no
generated-model metadata is consulted as diagnostic runtime authority.

## Post-Closeout Codec Audit

A focused inventory covered the core/schema/model encoding modules, production
uses of Candid and Serde codecs, current magic/version gates, and exported
schema codec entry points. Private and crate-visible codec functions remain
reachable through their maintained owners; warnings-denied compilation found no
unused current codec implementation. The public `icydb-schema` fragment,
proposal, and migration codecs each have multiple production consumers.

Two pieces of retired-format sediment were removed:

- the accepted-schema snapshot decoder no longer recognizes the retired Candid
  `DIDL` prefix merely to return a special incompatibility classification; any
  non-current magic now follows the one current corruption path; and
- the commit-marker suite no longer constructs a retired envelope solely to
  prove its absence. Current version, future-version, malformed-length,
  checksum, truncation, and trailing-byte coverage remains.

The final persisted Candid payload has now been removed. Deep integrity jobs
use one direct big-endian mapping inside the bounded checksummed `ICYIJPTH`
version-2 envelope. Closed variants have explicit numeric tags; proof, finding,
verifier, path, string, and key lengths are checked before allocation; and the
fully decoded job still passes the invariant-bearing cross-field validator.
The version-1 Candid envelope fails as incompatible before payload decoding,
with no compatibility reader or translation path. Retained development jobs
must therefore be recreated.

The other production Candid encodes in mutation and SQL returning paths are not
persisted codecs: they calculate the exact public response byte size required
by admission. Removing them would weaken the maintained response-bound proof.
Model graph JSON hashing is host-only under `cfg(not(target_arch = "wasm32"))`.
No other compatibility decoder, dual-read path, or mechanically unused codec
was found.

The exact maintained production/Candid build of the one-entity typed-query
fixture is 2,685,276 raw non-gzipped bytes after cleanup, 44 bytes below the
previous audited 2,685,320-byte artifact. Its single IC method export and
64-byte Candid remain unchanged; the final Wasm SHA-256 is
`fde7f231472567a0b19cc9574bdfb28bd95bd0c42f030bee5ab50f7626eb0c50`.
The host resolver does not enter that dependency graph.

## Candid And Format Inventory

Both checked-in transitive ABI goldens and the rebuilt SQL DIDs declare exactly
`DiagnosticFact { tag : nat8; value : nat64 }` and
`Error { code : nat16; class : nat8; origin : nat8; facts : vec
DiagnosticFact }`. `constraint` and `ConstraintDiagnostic` are absent. The two
query-only custom actors do not expose `Error` and retain their 64-byte and
66-byte Candid files.

Public 0.219 hard cuts are:

- immediate `Error.constraint` becomes `Error.facts`;
- `DiagnosticFact` becomes transitively public;
- historical validation progress uses its separate bounded numeric finding;
- explicit schema introspection adds fingerprint method, exact entity-schema
  fingerprint, and entity tag; and
- the host diagnostic artifact is a current-only version-1 tooling format.

Persisted changes actually present in the range are the `ICYCVJOB` direct
validation-job codec, the direct `ICYSAR01` payload mapping, and the
`ICYIJPTH` version-2 direct Deep-job payload described above. Rows, indexes,
relations, journals, commit markers, cursors, accepted schema snapshots,
migration records, and successful query/mutation response formats show no
0.219 diagnostic-driven change. No compatibility decoder, alias, dual
read/write path, or fallback for the retired public or durable shapes exists.

## Findings And Corrections

### High — accepted per-code fact schemas were documentation only (corrected)

The released implementation froze tags and an 80-fact constant but had no
executable owner for required/allowed tags, canonical order, repetition,
compact-value meaning, or tighter code maxima. E223 relied on a debug-only
length assertion, and tooling could resolve names from malformed context.
The new diagnostic-code registry validator, core/facade fail-compactly gates,
and CLI fail-closed resolution correct the accepted contract with focused
regressions.

### No defect — three persisted codecs use valid pre-1.0 hard cuts

The validation-job, schema-application, and Deep integrity progress payload
replacements are explicit, bounded, documented current formats. Reverting
them or adding compatibility would weaken the repository's pre-1.0 policy.
The design/status wording records the hard cuts instead of incorrectly
treating format stability as a release invariant.

### Corrected — exact source resolver tier was absent

The initial closeout had exact artifact, explicit live introspection, and
numeric fallback but no qualified source/generated provider. The CLI now binds
only a validated deployment artifact to source metadata, preserves its accepted
mapping unchanged, distinguishes provenance structurally, and requires the
same exact identity facts before rendering names. It still never guesses from
source declarations.

### Low — detached raw-Wasm hashes are build-path-sensitive (residual risk)

Sizes, Candid, and exports reproduce exactly, but raw hashes do not when the
same source is built under a different absolute directory. The final artifact
hashes are exact for this worktree; a release provenance process should either
freeze the build root or normalize generated paths before treating hashes as
cross-machine reproducible.

## Corrections Made

- added executable global/per-code fact-schema validation with fixed compact
  value domains and exact E223/E225 grammar;
- made core and public projections fail compactly without partial facts;
- prevented malformed host facts from enabling artifact/live name resolution;
- added exact source-metadata binding and resolution without runtime or
  generated-model authority;
- replaced the final persisted Candid payload with one direct bounded Deep-job
  codec, removed private Candid/Serde derives, and hard-cut its envelope to
  version 2 without a fallback decoder;
- removed retired schema-Candid recognition and a retired marker-only sentinel
  test while retaining current malformed-format coverage;
- added registry, malformed-projection, malformed-rendering, and unique-index
  origin/payload regressions; and
- recorded the correction in the root Unreleased notes and status tracker.

The initial fact-schema correction affects nine production/test source files at
891 added and 25 removed lines. The host resolver follow-up affects roughly 18
implementation, test, and authority-note paths at approximately 400 added and
35 removed lines. The Deep-job hard cut affects seven core code files at about
1,572 added and 56 removed lines, including the explicit mapping and focused
tests. This is more source at one durable boundary but a simpler runtime owner:
the reflected persistence graph disappears, no dependency is added, and the
two integrity-bearing production actors lose roughly 170 generated functions
and more than 250 KiB each. The fact guard's raw production cost remains
approximately 3.5–3.9 KiB per measured actor; the host-only resolver does not
enter production Wasm.
