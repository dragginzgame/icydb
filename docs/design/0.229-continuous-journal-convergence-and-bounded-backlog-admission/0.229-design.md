## Planning Status And Authorization

This line reuses the accepted 0.228 convergence engine during normal operation,
bounds all new journal debt, and proves future startup residue independent of
database history. It does not authorize implementation.

Implementation requires a completed 0.228 closeout, Patch 1 reconciliation
against that exact predecessor, review of the seven-patch tracker and fixed
backlog policy, and explicit user authorization for 0.229.

## Decision Summary

One convergence engine serves both startup and normal online folding. The
accepted 0.225 driver supplies replicated single-flight scheduling; the
accepted 0.228 engine supplies raw inspection, Validate, Apply, watermark, and
retirement. 0.229 adds no second decoder, cursor, page policy, or timer
mechanism.

After a normal commit clears its marker, runtime wiring records that convergence
work exists and requests the existing driver. Scheduling is idempotent and
does not change the already-committed user result. The driver may also run when
a pressure rejection finds existing debt.

Online convergence reads canonical predecessors and applies batches in journal
order while the current live overlay remains query authority for newer effects.
Every volatile row, tombstone, index entry, and other query-visible overlay
effect needed for safe retirement is tagged with its exact journal position.
Folding position `P` retires an overlay effect only when that effect is exactly
`P`; a newer position remains visible. Thus canonical state may catch up without
exposing an older value or retaining overlay entries after their authority is
fully folded.

Each journal tail owns exact aggregate metadata for its current batches,
records, and encoded bytes. Database-level admission derives the exact bounded
sum across registered journaled stores; no second persisted global estimate is
introduced.

One fixed engine-owned database backlog ceiling is a tuple of batch, record,
and encoded-byte maxima. Before marker persistence, mutation admission proves
the complete proposed commit plus current tail remains within every component.
Failure returns one typed retryable convergence-pressure error before the
marker exists and requests the driver. The mutation is not partly admitted.

The ceiling is selected from measured maximum commit and convergence-page
costs. It implies a fixed maximum number of residual startup pages. New debt,
live-overlay debt, and future time-to-ready therefore remain bounded
independently of historical rows, indexes, commits, and already folded journal
history.

## User Outcome

- Healthy normal operation continuously retires journal and volatile-overlay
  debt.
- A successful write never relies on a later unbounded upgrade to pay its
  accumulated history.
- A write that would exceed the fixed backlog ceiling fails before marker
  persistence with a typed retryable pressure result.
- Queries continue to observe the latest committed live value while older
  canonical batches fold.
- Same-key updates, deletion/reinsertion, schema effects, and index effects do
  not expose intermediate canonical state.
- Any future same-schema upgrade has at most a fixed number of residual startup
  convergence pages.

## Canonical Ownership

1. accepted schema snapshots own row, index, relation, constraint, and layout
   semantics;
2. the commit marker owns atomic mutation publication;
3. immutable journal batches own committed effects not yet folded;
4. the accepted 0.228 cursor and watermark own convergence progress;
5. canonical stores own folded stable state;
6. journal-positioned live overlays own latest visible effects ahead of the
   watermark;
7. each journal tail owns exact batch/record/byte aggregate controls;
8. commit admission owns the fixed database backlog check before marker
   persistence; and
9. the accepted 0.225 driver owns scheduling and replicated invocation.

The database backlog is a derived exact sum of owner-local tail controls. It is
not stored again as an advisory estimate. Overlay provenance is volatile and
derived from current journal publication/replay; it does not become a second
durable mutation log.

## Online Visibility And Retirement

Normal publication records the exact journal position beside each live
overlay effect. Query precedence remains newest live value/tombstone over
canonical state.

When Apply folds a record:

- canonical row and derived-index state advance under 0.228 invariants;
- an overlay effect at a newer journal position remains untouched;
- an overlay effect at the exact folded position is retired only after the
  canonical transition and cursor advance are durably safe; and
- no overlay effect can survive after its position is folded unless a newer
  committed position still needs it for visibility.

If one logical batch can contain multiple effects for the same key, the
position includes enough batch/ordinal identity to distinguish them. Patch 1
must prove whether existing commit canonicalization already guarantees one
final effect per logical target; the implementation must not assume it from
prose.

After upgrade volatile overlays are absent. Any remaining tail or cursor keeps
startup `Recovering` until the same engine reconstructs/folds the current state.

## Tail Aggregates And Admission

Each tail control stores exact current:

- batch count;
- record count; and
- encoded batch bytes.

Append, idempotent marker replay, watermark retirement, cleanup, and reopen
must preserve or reconcile those facts without scanning the tail. Malformed,
underflowed, overflowed, or mismatched controls fail typed and closed; they are
not repaired from generated models or silently estimated.

Before marker persistence, the commit coordinator calculates all marker-bound
tail additions and checks the database-wide sum against one fixed tuple. A
single maximum admitted commit must fit. The ceiling is a small measured
multiple of that maximum and at least one complete convergence-page envelope;
Patch 1 freezes the exact values and proof.

Pressure rejection happens before identity reservation or any state that would
make the rejected mutation externally committed. Existing predecessor debt is
drained by startup recovery before `Ready`; it is not declared invalid merely
because it exceeds the new steady-state ceiling.

## No-Build And Alternatives Gate

- Startup-only bounded pages limit one message but not the number of future
  messages.
- Synchronously folding every complete commit can move recovery-sized work
  into an ordinary mutation response.
- A background fold without admission still permits writers to outrun it
  indefinitely.
- A batch-count-only ceiling ignores record and byte skew.
- Clearing all overlays only when the complete tail is empty allows volatile
  overlay debt to grow under continuous non-idle writes.
- A second online compactor or caller-tuned policy duplicates semantics and
  multiplies states.

Patch 1 must stop or narrow this line if the accepted predecessor already
maintains exact tail aggregates, safely retires online overlay positions, or
bounds total debt through an equivalent singular authority.

## Scope

0.229 includes:

- reuse of the 0.228 engine for startup and online folding;
- journal-positioned live-overlay visibility and bounded retirement;
- exact per-tail aggregate batch, record, and byte metadata;
- idempotent post-commit scheduling through the 0.225 driver;
- one fixed database-wide backlog ceiling;
- one pre-marker typed convergence-pressure rejection;
- pressure-triggered driver scheduling; and
- proofs that steady-state debt and residual startup pages are bounded
  independently of database history.

## Non-Goals

0.229 excludes:

- another cursor, decoder, convergence engine, timer, or page policy;
- synchronous full-commit folding as a success condition;
- caller-configurable backlog or compaction settings;
- durable exact cardinality;
- approximate statistics or general planner work;
- application ingestion/upsert primitives;
- aggregate jobs, rollups, partitions, or archive routing; and
- compatibility paths for predecessor controls or overlay shapes.

## Persisted And Public Hard Cuts

- Tail aggregate controls are one current persisted shape and become mandatory
  for current admission.
- Live overlay entries/tombstones move directly to the current journal-position
  representation where Patch 1 confirms it is required.
- Mutation admission gains one current convergence-pressure error before marker
  publication.
- There is no legacy aggregate reconstruction during ordinary startup, dual
  overlay representation, old admission route, or unlimited fallback.
- Malformed aggregate metadata fails typed and closed; explicit integrity work,
  not generated models, owns diagnosis.
- No automatic public endpoint or successful query-result change is introduced.

## Non-Negotiable Invariants

1. One 0.228 convergence engine owns startup and online fold semantics.
2. Normal commit atomicity and marker order remain unchanged.
3. Post-commit scheduling cannot turn an accepted mutation into a reported
   failure.
4. Queries always observe the latest committed overlay effect while canonical
   state catches up.
5. An overlay effect is retired only when its exact journal position is safely
   folded and no newer effect is hidden by that retirement.
6. Canonical row and index transitions remain ordered and exact.
7. Tail batch, record, and encoded-byte controls equal the live tail.
8. New commits cannot exceed any fixed backlog-ceiling component.
9. Pressure rejection occurs before marker persistence and committed side
   effects.
10. Existing pressure causes driver scheduling without a second scheduler.
11. The fixed ceiling implies a fixed maximum residual startup-page count.
12. Steady-state durable and volatile convergence debt is independent of
    database history.
13. Missing or malformed controls never produce guessed admission.
14. Generated models never reconstruct journal or overlay authority.
15. Production commit, convergence, and scheduling paths contain no panicking
    operations.
16. Raw non-gzipped Wasm is the authoritative footprint measure.

## Baseline And Acceptance Measurements

Patch 1 records normal commit instructions before/after scheduling, online
Validate/Apply instructions by record family, tail batches/records/bytes,
volatile overlay entries/bytes, driver cadence, pressure frequency, time and
pages to quiescence, residual startup pages, stable control bytes, raw Wasm,
deterministic gzip secondary, Candid/method modes, and complexity signals.

Acceptance requires one fixed backlog tuple; exact O(1) tail facts; no
history-dependent tail scan in admission; bounded overlay entries attributable
only to unretired/newer positions; constant residual-page maximum; no
visibility regression; no second scheduler/engine; and raw-Wasm growth within
the frozen review gate.

Measurements distinguish historical rows `N`, live tail batches `B`, records
`R`, encoded bytes `Y`, overlay effects `O`, convergence pages `P`, and
instructions `I`. The proof must hold as `N` and historical commit count grow
while the fixed debt tuple remains unchanged.

## Complexity And Maintenance Gate

Demonstrated need: bounded startup pages still permit database-lifetime debt,
and online folding without exact admission or overlay retirement cannot prove a
bounded steady state.

Simplest alternative rejected: a timer alone does not bound a writer that
outpaces it.

Canonical owners: existing convergence engine, journal-positioned live
overlay, per-tail exact aggregates, commit admission, and existing driver.

State-space delta: exact aggregate controls, journal-position provenance for
volatile effects, and one within-ceiling/pressure outcome. It adds no
configuration, cursor, engine, scheduler, cardinality generation, or statistics
epoch.

Promotion fails if implementation introduces a second online fold route,
database-global duplicate aggregate authority, full-tail scans, unbounded
overlay retention, after-marker pressure rejection, or compatibility formats.
Every handoff reports files/line delta, domains, states, duplicate flows,
instruction/stable/heap/raw-Wasm effects, and complexity direction.

## Promotion Gate

0.229 becomes implementation authority only when:

1. 0.228 has a reported ready/complete closeout;
2. Patch 1 confirms recurring tail debt, missing exact aggregates, and unsafe or
   unbounded overlay retirement remain gaps;
3. the one fixed batch/record/byte ceiling and derived page maximum are frozen;
4. post-commit scheduling is proven to reuse the 0.225 driver and 0.228 engine;
5. every pressure and overlay hard cut is reviewed; and
6. the user explicitly authorizes 0.229 implementation.

Until then, this document is proposed design authority only.
