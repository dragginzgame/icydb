## Patch 1 Findings

The review feedback is accepted. Reconciliation found one necessary scope
contraction and otherwise confirmed the proposed semantic solution.

- Accepted schema remains the sole runtime authority. v0.230.3 accepts unique
  indexes whose nullable key sources can omit physical membership without an
  explicit matching guard.
- Every accepted unique index must have exactly one accepted unique constraint.
  The smaller consistent correction is to expose its backing index and exact
  predicate through constraint descriptions and `SHOW CONSTRAINTS`, not to
  remove filtered indexes from constraint identity closure.
- Predicate execution binds top-level fields only. Dotted parser spelling is
  not nested-path execution. Patch 2 will reject omit-capable nested unique
  sources rather than add a new predicate language.
- Omission is now frozen as a bounded schema-only classification:
  `NeverOmits`, `TerminalNullOmits`, `UnsupportedNullableAncestor`, or
  `InvalidSourcePath`. Rows are never inspected to derive it.
- Accepted records require exact member shape. Missing members and type
  mismatches remain errors. A nullable intermediate ancestor currently causes
  typed traversal failure, not omission, and is rejected for affected unique
  indexes instead of being guessed or reclassified.
- The integrity call graph does not justify a global typed refactor. Patch 2 is
  limited to `Structural`, `Predicate`, and `NullableUnique` acceptance
  outcomes across the eight direct production `has_valid_integrity` call sites,
  while existing base/index/relation/constraint `Option<()>` owners remain
  unchanged.
- Root rename currently has a stale-text fallback after predicate rewrite
  failure. Patch 2 removes that acceptance fallback and rebinds root rename,
  record-member rename, generated reconciliation, candidate creation, and
  promotion against the complete final schema revision.
- Candidate promotion already constructs and integrity-checks the final
  accepted-after snapshot. Patch 2 keeps that revalidation point and adds no
  persisted proof bit.
- v0.230.3 has no maintained public write-quiescence or accepted
  constraint-reference-transfer route. Reinstall/recreation is the sole
  supported remedy for noncompliant active or candidate state.

## Frozen Patch 2 Boundary

Patch 2 may add:

- one schema-owned nullable-unique validator;
- one ephemeral fallible top-level predicate binder over a structurally valid
  candidate;
- one narrow three-category snapshot-acceptance result;
- exact generated and SQL error projection;
- exact final-revision rename and promotion revalidation;
- constraint-description predicate projection; and
- focused tests, documentation, and artifact measurements for those changes.

Patch 2 may not add nested predicate execution, a persisted proof, a new
uniqueness mode, a compatibility path, a replacement workflow, or a general
typed diagnostic hierarchy.

## Exact Persisted-State Boundary

A well-formed current version-1 snapshot that violates only the new semantic
contract maps to `InternalError::serialize_incompatible_persisted_format()`,
`ErrorClass::IncompatiblePersistedFormat`, `ErrorOrigin::Serialize`, and
`RuntimeIncompatiblePersistedFormat`. Structural or predicate corruption stays
corruption. The format discriminator remains version 1.

## Patch 2 Outcome

Patch 2 implements the reconciled contract without creating a second schema,
predicate, uniqueness, or persistence authority.

- `validate_schema_snapshot_acceptance` is the canonical boundary. It composes
  the unchanged structural integrity owners with one bounded nullable-unique
  validator and preserves only the three frozen result categories:
  `Structural`, `Predicate`, and `NullableUnique`.
- `source_omission_class` derives omission from accepted schema metadata only.
  It covers field-path and expression sources, deduplicates repeated sources,
  admits only terminal-null omission, rejects nullable ancestors, and leaves
  missing members, non-map ancestors, and type mismatches as row-admission or
  row-decode errors rather than guessing from values.
- Exact top-level `IS NOT NULL` conjuncts are the only guards. Duplicate guards
  are canonicalized; incomplete composite guards, OR/NOT/comparison forms,
  unbound fields, malformed predicates, and dotted nested spelling fail
  closed.
- Generated initial lowering, SQL DDL binding, accepted/candidate publication,
  nullability mutation, promotion, codec ingress/egress, and reopen all consume
  that authority. Existing frontends only project its result.
- A production defect exposed during implementation was corrected: field
  nullability mutation previously updated the field but left accepted index
  source metadata stale, causing structural rejection before semantic
  validation. Active and candidate field-path/expression sources now receive
  the exact top-level nullability transition before final validation.
- Root rename now rewrites predicate text fallibly and rebinds the complete
  final snapshot. Rewrite failure rejects; the former stale-text fallback is
  gone. Generated migration uses the same fallible rule.
- Unique constraint descriptions retain the accepted backing constraint and
  index identities. They now expose the backing index name and exact optional
  predicate, with `unique_index_v1` versus `partial_unique_index_v1` semantics;
  `SHOW CONSTRAINTS` projects the same facts.
- Well-formed current version-1 active state that violates only this semantic
  rule reopens as incompatible persisted format. Structural or predicate
  corruption stays corruption. No legacy decoder, migration, or repair path
  was added; reinstall/recreation remains the supported hard cut.

## Patch 3 Outcome

Patch 3 closes planner usability without adding a route, optimizer, predicate
representation, persisted proof, or configuration axis.

- `predicate_implies_predicate_for_planner` remains the sole filtered-index
  implication owner. Its existing bounded conjunction collector now also
  recognizes exact `IS NOT NULL` clauses.
- Supported strict equality and ordered comparisons prove the matching
  non-null guard only for a concrete non-null bound value. `NULL` and the
  internal unknown/unit value fail closed.
- Every composite guard and every additional accepted index-filter comparison
  must still be implied. Extra query conjuncts do not invalidate an otherwise
  complete proof.
- `OR`, `NOT`, cross-field comparisons, expression-to-source inference, null
  uncertainty, and unsupported predicate families remain conservative. A
  query that can observe rows omitted from the filtered index cannot select
  that index.
- The existing residual-filter owner now removes an exact non-null clause only
  when the accepted filtered guard itself guarantees it. Access-bound stripping
  remains unchanged.
- One real-canister test creates and validates the guarded nullable unique
  index through SQL DDL, proves the new `IndexPrefix` route, proves an `IS NULL`
  query and unsupported `OR` proof stay off that index, and checks indexed
  output against both the pre-index scan and an equivalent conservative route.
