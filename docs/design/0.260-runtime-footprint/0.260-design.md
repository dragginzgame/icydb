## D1: exact-count diagnostic distinction

Toko Miner's observability count fallback cannot distinguish unavailable exact
metadata from an unsupported count shape because both currently expose generic
`RUNTIME_UNSUPPORTED`. Keep the existing exact-count execution owner and add one
`QueryErrorDetail`/public diagnostic identity for its unavailable-metadata result.
The simpler generic error is insufficient for typed caller handling; a new count
API, scan fallback or diagnostic reason family is unnecessary. Unsupported shapes
retain their existing rejection. The state-space delta is one observable error
identity, emitted only after an admitted metadata plan returns no exact count;
there is no new execution route, configuration, persisted state or format.
The diagnostic registry owns the numeric identity and the CLI owns its prose.
Application fallback removal and proof of metadata availability remain downstream.

## W2: smallest-change gate

Before editing runtime code, name the demonstrated cost, canonical owner,
simplest deletion/reuse alternative and expected effect. No public mode,
configuration, persisted state, compatibility path or weakened check is planned.
If a candidate needs any such expansion, stop for a separate scope decision.

Retain a footprint change only with a matched raw-Wasm reduction and neutral or
simpler implementation structure. Measure relevant query/write or lifecycle
instructions/cycles and report any regression for explicit acceptance. Set any
numerical tolerances from the measured baseline before evaluating the candidate;
there is no new production ceiling and no unsupported percentage-saving promise.
Do not disable metrics, remove types, bypass relations or erase recovery to shrink
the subject. Correctness and failure ordering take precedence over size.

## C1: avoid unnecessary collection ownership

Promotes the investigation question in
[collection materialization](../ideas/streaming-materialization.md), not its
unproven implementation. Begin at the existing structural value decoder and
predicate/slot-reader consumers. Identify a real consumer and accepted schema
before choosing list/map cases; materializing an owned public result is not
redundancy merely because it allocates.

Reuse existing walkers and semantic comparison owners. Preserve accepted-kind
checks, recursive-depth/collection bounds, deterministic map semantics, null
handling and relation-list logical cardinality. A predicate finding an early
match must still reject malformed trailing data where current whole-value
validation requires it. Add no borrowed public collection API, codec, planner
route or materialization mode without a new demonstrated need and approval.

Compare equivalent outputs and errors for early/late/absent matches and relevant
empty/null cases. Use one scalar/non-collection control to detect collateral cost.
Decisions use raw Wasm and IC cycles/instructions, never native or elapsed timing.
Requested allocation bytes may explain ownership but are not peak/live memory or
a substitute performance gate. If consumers need ownership or no worthwhile
benefit is measured, retain the current decoder and record that result.
