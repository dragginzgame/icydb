## Patch 1 Evidence — Accepted Runtime Root

- One `AcceptedSchemaRuntimeRoot` now captures every registered store root and
  compiles all accepted entity inspection plans, `SchemaInfo` tables, row
  layouts, fingerprints, and executor authority before publishing one `Rc`
  handle. A context retains that complete root revision.
- Runtime-root identity binds the durable database incarnation plus the
  canonical ordered set of present and absent store roots. Structural plan and
  SQL compile cache keys also bind that complete identity, so unchanged entity
  fingerprints cannot reuse a plan across a different accepted root.
- Warm lookup revalidates compact persisted store-root records. It does not
  encode or hash accepted entity snapshots. SQL DDL invalidates the whole root,
  while ordinary publication/recovery drift is detected by root revalidation.
- The former per-entity query cache, per-context lazy `SchemaInfo`, repeated row
  layout construction, and projection-time accepted snapshot fingerprinting
  are removed. Accepted schema snapshots remain the sole runtime authority.
- Counter-backed native coverage executes 1,000 point queries after warm-up
  and observes zero accepted snapshot fingerprint builds, runtime-root identity
  hashes, entity-runtime compilations, or root publications. Separate tests
  prove atomic replacement, retained old-root contexts, canonical store-root
  identity, and mixed-root plan-cache rejection.

The maintained audit canister now exposes bounded point and ordered empty-scan
loops for this fixed-cost workload. The baseline subject uses the exact
`v0.220.2` core plus the same measurement endpoint and Candid contract. PocketIC
15 reports local canister instructions inside each 1,000-query loop:

## Patch 2 Evidence — Native Bounded Key Batches

- `DbSession::get` and `DbSession::get_many` accept entity-bound `Id<E>` values
  and execute their primary-key reads directly against the accepted store.
  They do not construct a `DynamicQuery`, compile a plan, or populate the
  general plan cache.
- Generated scalar and composite entities implement the existing `EntityKey`
  contract. `get_many` returns exactly one `Option<Row>` per input key in
  request order. Missing positions remain `None`; duplicate positions remain
  duplicated in the result while sharing one stored-row fetch and decode.
- One batch admits at most 1,024 positions, 256 KiB of canonical stored-key
  bytes before deduplication, 4 MiB of raw rows across distinct keys, and
  4 MiB of logical projected result bytes. Count and input bytes charge the
  original request; physical reads/raw bytes charge distinct keys; result
  bytes charge every original position, including duplicates.
- Exact reads validate one current accepted typed binding, borrow the Patch 1
  row contract and schema tables, resolve one store handle, and validate each
  found row's persisted primary key before projection. Typed-binding issuance
  and currentness checks also stopped rebuilding accepted row-layout state.
- New bounded numeric diagnostics distinguish item, input-byte, stored-byte,
  and result-byte exhaustion. The CLI renders each boundary explicitly rather
  than relying on a wildcard. Stale bindings fail closed without accessing a
  store. No persisted schema, row, index, journal, or cursor format changed.
- Focused coverage proves scalar and generated composite key wiring, exact
  ordering, missing and duplicate positions, one physical read per distinct
  key, stale-root rejection, every admission bound, and matching heap and
  journaled behavior. The maintained generated adapter test exercises both
  `get` and `get_many` without SQL.

PocketIC 15 measures the old per-key dynamic loop and one native batch inside
the same canister binary. Both workloads request 1,000 missing keys:
