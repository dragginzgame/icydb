# IcyDB 0.245 Generated Query Dispatch Convergence

Status: COMPLETE — BUILD AND CLOSEOUT GATES PASSED

Last updated: 2026-08-27

Measurement baseline: the completed 0.245 Patch 2 candidate atop exact tag
`v0.245.0` (`b6b5c287de5d3fcca3fc6dbe9acbe7c4026236b9`). Patch 2 is defined by the
[0.245.1 parse-once design](../0.245-sql-parse-once/0.245.1-design.md).

## Decision

Promote one bounded implementation candidate for review: make the existing
opaque `SqlStatementDispatch` carry the one parsed statement and its parse
attribution from generated query admission into the existing compiled-command
ingress, bound to the exact borrowed SQL text that produced it.

This is a request-local flow contraction. It must not add an AST cache, a new
parsed-command type, a second execution route, a runtime mode or any schema
authority.

## Measured Result

The implementation passed every frozen gate. `SqlStatementDispatch` retains
the current AST, its exact borrowed input and parser-owned attribution;
generated admission borrows it, and the existing compiled-query ingress
consumes the same syntax authority and cache text.
Parser-owned tokenization, statement-shell, expression and predicate buckets
sum directly to the exhaustive parse total, avoiding a redundant outer timing
pair.

| Matched handler | Predecessor | Candidate | Saving |
| --- | ---: | ---: | ---: |
| Cold | 66,617,344 | 66,564,769 | 52,575 |
| Persisted-cache warm | 4,191,442 | 4,166,905 | 24,537 |

Every five-sample set was deterministic and produced the same result as its
direct control. The final production `sql_guard` actor is 3,361,467 raw bytes
and 8,709 functions, 890 bytes and seven functions below exact `v0.245.0`.
Candid and exports are byte-for-byte unchanged. Gzip is 1,337,731 bytes, 469
above the exact tag and secondary to the raw-size gate.

The retained Patch 3 shape is +90 net production Rust lines over
Patch 2, with no new production type or module. It adds no cache, mutable
owner, invalidation edge, persisted state, runtime choice or compatibility
path. All temporary measurement endpoints and integration fixtures were
removed.

The read-only closeout found that the first implementation still accepted raw
SQL text and its dispatch as two independent hidden arguments. The correction
made that disagreement unrepresentable: the request-local dispatch borrows its
originating text, and downstream cache and compiler owners accept only the
sealed artifact. The unused entity observation and full-AST `Debug` surface
were removed at the same generated boundary.

## Observed Current Flow

Generated SQL query endpoints currently execute:

```text
endpoint authorization
  -> sql_statement_dispatch(sql): full parse
  -> introspection admission
  -> generated entity/no-entity branch
  -> db()
  -> trusted compiled-query ingress: full parse
  -> accepted-catalogue selection
  -> fingerprint-bound compiled-command cache
  -> execution and response projection
```

The first parse determines only syntax-owned endpoint facts. It cannot select
or prove accepted schema authority. The second parse produces the AST consumed
by semantic compilation.

Source inspection also establishes:

- when the generated actor has entities, both entity and no-entity branches
  call the same query facade;
- when it has no entities, both branches return the same fixed no-entity
  error; and
- the only remaining semantic use of generated query dispatch is the
  `introspection = false` rejection before `db()` and store access.

The duplicate parse is therefore real. The admission boundary is also real and
must not be deleted or moved behind database acquisition merely to remove it.

## Authority-Preserving Design

The proposed flow is:

```text
endpoint authorization
  -> sql_statement_dispatch(sql): one current AST + parse attribution
  -> introspection admission from that AST
  -> db()
  -> trusted compiled-query ingress consumes the same opaque artifact
  -> accepted-catalogue selection from its entity fact
  -> existing fingerprint-bound compiled-command cache
  -> existing compiler, executor and response projection
```

`SqlStatementDispatch` already owns the generated endpoint's parsed dispatch
facts. Its private representation may be changed in place to retain:

- the parser-owned current `SqlStatement`;
- the exact borrowed SQL input that produced that statement;
- the measured parse-local instruction count; and
- the parser subphase attribution.

Its sole public-hidden observation remains derived from that statement.
An owner-local consuming method may expose the private parts only inside
`icydb-core`. Generated code and the facade pass the artifact opaquely; neither
may inspect the AST or derive schema facts from it.

The compiled-query ingress seeds its existing compile-attribution builder from
the carried parse measurement, derives the entity from the same statement,
uses the artifact's originating text for the cache key, selects accepted
catalogue authority exactly as it does now, and borrows the statement on a
cache miss. Direct non-generated query APIs construct the same artifact
internally, retaining their existing one-parse behavior.

No derivative can establish freshness. Accepted catalogue identity and
fingerprint remain in the existing cache key, and publication behavior remains
unchanged.

## Alternatives Rejected

| Option | Disposition | Reason |
| --- | --- | --- |
| Keep both parses | Rejected | Measured repeated work and incomplete generated-endpoint attribution remain |
| Skip dispatch only when `introspection = true` | Rejected | Smallest edit, but retains two query ingress flows and the defect for the restricted endpoint mode |
| Move introspection admission behind `db()` | Rejected | Changes failure order and permits database acquisition before a syntax-owned public admission decision |
| Carry the existing opaque dispatch artifact | Preferred | One parser owner, unchanged admission order, no cache or new type |
| Add an AST/entity-routing cache | Rejected | Introduces freshness, invalidation and retained-state obligations for a 23,978-instruction warm ceiling |

## Frozen Invariants

1. Endpoint authorization still completes before SQL parsing.
2. Malformed SQL and forbidden introspection reject before `db()`, accepted
   catalogue selection, store access or execution.
3. `introspection = true` and `introspection = false` each invoke the canonical
   parser exactly once on success and failure.
4. Empty generated actors retain their exact typed no-entity behavior and
   failure order.
5. The parsed artifact is request-local and cannot be cached, cloned into
   retained state or reconstructed from generated models.
6. The cache-key SQL text and compiled AST come from the same sealed artifact;
   callers cannot supply them independently.
7. Accepted schema snapshots remain runtime authority. The artifact carries
   syntax only.
8. Cache lookup remains after accepted-catalogue selection and stays bound to
   the accepted fingerprint.
9. Cache hit, miss, insertion and publication behavior remain unchanged.
10. Compile attribution includes the generated dispatch parse exactly once.
11. Results, typed errors, ordering, row/index work, response bounds, Candid,
    exports, stable formats and package versions remain unchanged.

If the opaque handoff cannot preserve error order, exhaustive attribution and
the singular accepted-catalogue authority within these budgets, close the
candidate as a measured no-build. The gates must not be weakened for a 0.572%
warm improvement.

## Required Proof

- parser-call counts for cold miss and warm hit through generated query ingress;
- generated tokens and facade/core APIs with no independent raw-SQL argument;
- ordinary projection, scalar, grouped, membership and entity-less
  introspection queries;
- both introspection modes;
- malformed SQL, mutation-on-query-surface and forbidden-introspection errors;
- empty generated actor and unavailable-database failure ordering;
- compiled-command hit/miss and accepted-fingerprint behavior;
- target and unrelated accepted publication;
- result, physical row/index work and response-envelope equality;
- compile-attribution completeness;
- generated-token and one real-canister endpoint proof;
- no-default, SQL-only and all-feature focused checks; and
- matched final raw/gzip Wasm, function count, Candid and exports.

## Landing Boundary

This completed 0.245 Patch 3 is one end-to-end landing patch across the
existing parser/session handoff and generated canister glue. Write, DDL,
resumable-update and shell routing parse-once opportunities remain separate
findings and were not folded into this patch.
