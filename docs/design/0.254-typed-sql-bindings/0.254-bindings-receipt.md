## Implemented Contract

Application code retains the existing immutable `SqlStatementDispatch`, then
passes `&[InputValue]` to `execute_trusted_sql_query_dispatch` on a fresh session.
The dispatch owns syntax, not values, a session borrow or accepted authority.
The old one-argument Rust arity is hard-cut; generated handlers pass `&[]`.
No new export, request type, Candid binding decoder or SQL-string rendering is
introduced. The existing text convenience method still parses each call.

`db/sql/lowering/bindings.rs` admits at most 64 scalar operands and 64 KiB of
logical payload before cloning caller values. Big-integer magnitude length is
read without digit allocation. These are admission bounds, not a bound on caller
construction, deserialization, allocation capacity or execution temporaries.
Containers and enum inputs reject by tag before recursive conversion.

Identifier normalization produces an execution-owned SQL AST. Slots become
`SqlExpr::Literal(Value)` directly, preserving scalar representations. Existing
planner compare compilation, query normalization and predicate validation admit
field comparisons and each IN element before any destructive fold. Other scalar
expressions use existing expression inference. Boolean wrappers keep the existing
WHERE truth-shape contract. All original slot-bearing siblings are visited,
including unreachable branches. Query operands follow query rules, not write
constraints: for example, a negative comparison boundary for Nat64 can be valid.

Admission covers maintained WHERE expression operands and individual IN entries.
It does not widen literal-only grammar slots such as LIKE patterns or rounding
scales. Projection, ordering, grouping, limits, HAVING, mutation/DDL and bound
EXPLAIN remain outside the contract. Bound WHERE may filter aggregate inputs;
literal HAVING remains unchanged. SQL block-comment syntax is not introduced.

Bound calls return through the existing compilation/execution context before
SQL cache-key creation, lookup or insertion. No binding digest or concrete bound
command resident exists. Eligible shared plans still use slice-2 accounting.
Literal calls retain concrete-command caching, but now also perform the bounded
placement/count/depth walk before lookup. A valid hit skips normalization,
lowering and semantic compilation, not current authority/execution admission.
Bound calls repeat those compilation steps even when values are identical.

## Application And Validation Evidence

The maintained `one_entity_sql_query` actor initializes its fixed query in init
and post-upgrade using a `OnceCell`. Its existing no-argument export calls a
private domain helper with a typed Ulid. Missing initialization returns the
test-visible failure sentinel; it cannot lazily succeed inside a discarded query
heap. Three separate queries before upgrade and three after upgrade passed in
PocketIC. No export was added. The temporary local server stopped after the run;
no ICP network was changed.

Native tests cover A/B/A values across fresh sessions with zero extra parser
calls, unchanged SQL cache resident count, literal cache reuse, current-authority
rejection after accepted-field rename, aggregate-WHERE/null parity, CASE,
COALESCE, ranges, and invalid dead-branch operands. Scalar handoff tests cover
every admitted non-null scalar family without SQL text conversion; these are
handoff proofs, not by themselves end-to-end structural execution parity.
The follow-up [cost/parity controls](0.254-cost-controls.md) add stored-value
structural parity across 20 families and correct explicit-null inference in
CASE/COALESCE and other boolean wrappers without bypassing operand validation.

Focused binding, parser, predicate lowering, session/authority, schema-CHECK,
diagnostic registry and generated-handler selections pass, together with the
no-default-features core library check. Required repository clippy lanes and the
final focused all-feature/all-target core/facade/model/CLI lint gate passed.
Formatting and whitespace checks passed.
The SQL-only test build retains 64 existing dead-code warnings. Full repository
suites and release validation remain user-owned.

Initial new-test failures were corrected: unsupported block-comment syntax in
the lexical fixture, heap-only DDL capability in the authority fixture, and a
space in an expected generated-token string whose helper removes whitespace.
The successful authority test publishes through the existing accepted-catalog
test owner, not a generated-model runtime fallback.

(net roughly +1,000), excluding prior slice-2 accounting, docs and unrelated
archive moves. Implementation complexity increases with contextual admission,
AST membership leaves and direct coverage. Operational complexity is unchanged:
no registry, cache mode, transport, persisted state or execution route was added.

across five files, mostly tests, as detailed in the cost controls.

preparation owners, session compiler/cache ingress, public Rust facade, generated
handler propagation, scalar magnitude helpers, diagnostic registry/CLI rendering,
and the fixed-query audit actor plus its lifecycle test. Existing slice-2 changes
