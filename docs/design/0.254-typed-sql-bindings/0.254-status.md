## Intended Outcome

Optional application-owned fixed SQL, typed values, and reuse of the existing immutable
parsed-dispatch artifact through the Rust/session API. Keep accepted authority,
whole-slot admission and execution semantics in their existing owners. Compare
the resulting application use and implementation cost with maintained
typed/structural queries; do not introduce another prepared-statement system.
SQL need not replace structural queries or demonstrate production adoption in
the user's projects. Its benefit is ecosystem capability without interpolation
or repeated parsing; shared-engine costs still require independent review.

No new SQL export, bound endpoint request, Candid decoder, CLI binding UX,
remote statement handle, statement registry, parse cache or execution route.
Existing endpoint wire contracts stay unchanged; any Rust signature propagation
to their handlers supplies empty bindings internally.

Bound invocations always bypass SQL concrete-command lookup and insertion.
No original-binding digest, bound SQL cache resident, SQL cache-weighting project
or bound HAVING is included. Existing literal HAVING and aggregate queries with
bound WHERE filters remain in scope. Downstream retained-plan safety is covered
by prerequisite slice 2; cache bypass is not a claim that nothing retains values.
