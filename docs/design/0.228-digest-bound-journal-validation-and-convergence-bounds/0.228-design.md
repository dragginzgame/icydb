## Planning Status And Authorization

This line replaces the predecessor's apply-while-validating fold cursor with
one current digest-bound Validate/Apply protocol. It also makes physical and
instruction limits truthful before batch materialization. It does not authorize
implementation.

Implementation requires a completed 0.227 closeout, a Patch 1 reconciliation
against the exact maintained tree and accepted 0.225 recovery authority,
review of the seven-patch tracker and hard-cut format plan, and explicit user
authorization for 0.228.

## Decision Summary

Every immutable journal batch passes a complete read-only Validate phase before
any record in that batch mutates canonical state. Canonical Apply starts only
after the exact batch identity and complete record set have been proved.

The sole current durable cursor is:

```text
ConvergenceCursor {
    batch_sequence,
    batch_id,
    batch_digest,
    record_count,
    phase: Validate | Apply,
    next_record_ordinal,
}
```

The cursor binds sequence, ID, digest, count, phase, and next ordinal. It never
reconstructs missing fields from the batch, a generated model, or a retired
cursor shape.

The current journal envelope exposes bounded header facts before record
materialization: encoded length, sequence, batch ID, record count, and digest.
The digest covers the canonical current logical batch encoding and all header
identity needed to prevent substitution. A bounded raw inspection rejects
oversized, truncated, mismatched, or unsupported envelopes before allocating or
decoding their records.

Validate advances durably across bounded pages but is read-only with respect to
canonical data, indexes, schema, identity, validation jobs, and cardinality.
After complete validation, one durable transition changes the cursor to
`Apply { next_record_ordinal: 0 }`.

Apply recomputes one prepared canonical transition at a time from the immutable
batch and canonical predecessor. Every fallible decode, lookup, schema check,
key derivation, and transition preparation occurs before the store mutation.
The mutation and cursor advance must be interruption-safe. The terminal
protocol publishes the watermark and clears the exact cursor and batch without
ever losing an unapplied record or replaying a non-idempotent transition.

## User Outcome

- Corruption in the final record is reported before the first canonical record
  changes.
- Recovery can resume at every Validate and Apply ordinal without guessing.
- No page decodes a batch whose raw envelope already violates its byte limit.
- Batch, cumulative bytes, record count, instruction work, index fanout, and
  worst-record overshoot are separate measured bounds.
- A trap or upgrade at cursor creation, phase transition, record publication,
  watermark publication, cursor clear, or batch clear resumes exactly.
- Startup readiness continues to use the 0.225 driver and state contract.

## Canonical Ownership

Authority order is:

1. accepted schema snapshots own record semantics;
2. the commit marker owns interrupted publication into the journal;
3. immutable current envelope bytes plus sequence, ID, count, and digest own
   the batch being converged;
4. `ConvergenceCursor` owns validated phase and ordinal progress;
5. canonical data, index, schema, identity, and validation-job stores own folded
   state;
6. the fold watermark owns the highest completely applied sequence; and
7. the accepted 0.225 driver owns replicated invocation only.

The convergence engine owns one flow:

```text
raw inspect -> digest-bound Validate -> phase transition -> prepared Apply
            -> watermark publication -> cursor/batch retirement
```

Journal storage owns raw envelope access and control codecs. Record-family
owners supply validation and prepared canonical transitions. The convergence
coordinator orders them; it does not absorb schema, identity, or index
semantics.

## Validate Contract

Validate proves, in bounded pages:

- envelope magic/version, encoded length, sequence, ID, count, and digest;
- one-store routing and required storage capabilities;
- accepted and candidate schema identity where relevant;
- every row key, row payload, field wire, and commit schema fingerprint;
- exact derived index transition evidence;
- constraint-validation job and candidate-index closure;
- identity range owner, expected high-water, count, and record ordering;
- current schema/migration plan identity when that record family is enabled;
- complete known record-family coverage; and
- canonical final batch closure with no trailing or missing bytes.

Validation reads canonical predecessors only when needed to prove that a later
Apply transition can be prepared under the same gated fold order. It writes no
canonical or derived state. Durable cursor publication is the only Validate
write.

## Apply And Terminal Contract

Apply starts only from a completely validated digest-bound cursor. For each
ordinal it:

1. re-reads the immutable record under the cursor digest;
2. recomputes the exact prepared canonical transition;
3. performs all fallible work before mutation;
4. applies one transition under its record-family idempotency proof; and
5. durably advances the cursor.

After the final ordinal, terminal recovery must distinguish and reconcile every
possible interruption around watermark publication, cursor retirement, and
batch retirement. The watermark never advances past an unapplied record. A
cleared batch is never the only remaining authority for an unadvanced
watermark. A retained batch at or below the watermark is cleanup-only and
cannot be applied again.

## Truthful Bounds

The engine freezes distinct fixed limits for:

- maximum encoded bytes in one journal batch;
- maximum cumulative encoded batch bytes admitted by one page;
- maximum records advanced by one page;
- maximum instructions used by one page;
- maximum derived row/index/schema fanout of one admitted record; and
- measured overshoot after the last safe instruction check.

Raw inspection precedes record allocation. The page reserves measured headroom
for header and digest work, record decode, maximum prepared fanout, cursor
publication, terminal transitions, driver/runtime overhead, and overshoot.
Host tests use explicit deterministic limits and do not treat a zero host
performance counter as instruction evidence.

The logical batch remains the decode unit unless Patch 1 measurements prove
that the maximum admitted current commit cannot fit the frozen memory and
instruction envelope. If physical chunking is required, it is one current
format and must preserve a single logical digest and record order. Chunking is
not added merely to retain the historical 8 MiB label.

## No-Build And Alternatives Gate

- Raising the page ceiling does not make post-decode byte accounting truthful.
- Validating each record immediately before Apply does not protect earlier
  records from later corruption.
- Re-validating the complete batch on every page is bounded only by batch size
  and discards durable progress.
- Copying decoded records into a second durable prepared log duplicates journal
  authority and write cost.
- A legacy cursor decoder or inferred phase makes two formats current before
  1.0 and is prohibited.

Patch 1 freezes the smallest current envelope encoding that supplies these
facts and decides only whether the measured maximum logical batch remains one
decode unit or needs physical chunks. It must not invent a parallel envelope.

## Scope

0.228 includes:

- one current raw journal envelope and bounded inspection path;
- digest, sequence, ID, count, phase, and ordinal cursor binding;
- complete durable read-only Validate before Apply;
- prepared canonical Apply across every current record family;
- interruption safety at cursor, phase, record, watermark, cursor-clear, and
  batch-clear boundaries;
- fixed truthful batch, cumulative-byte, record, instruction, fanout, and
  overshoot limits; and
- focused host and real-canister evidence for the convergence engine.

## Non-Goals

0.228 excludes:

- online convergence after normal commits;
- post-commit scheduling or live-overlay visibility rules;
- tail aggregate metadata, backlog pressure, or pre-marker rejection;
- exact entity or index-prefix cardinality;
- application readiness changes beyond reusing 0.225;
- caller-selected convergence limits;
- general repair, compaction modes, or integrity jobs; and
- approximate statistics, planner policy, ingestion, rollups, or partitions.

## Persisted And Public Hard Cuts

- `FoldRecordCursor` moves directly to the sole current
  `ConvergenceCursor` format.
- The journal envelope moves directly to the current digest-bearing form with
  bounded pre-materialization header inspection.
- A predecessor with an unfinished old cursor/tail must finish recovery before
  upgrade, or development state must be recreated under the reviewed release
  procedure.
- Unknown, malformed, retired, or mismatched cursor/envelope forms fail typed
  and closed.
- No legacy decoder, cursor synthesis, alias, shim, dual format, tag fallback,
  or generated-model reconstruction is added.
- This line adds no public endpoint and does not change successful query
  results or accepted schema meaning.

## Non-Negotiable Invariants

1. No canonical record changes before complete validation of its exact batch.
2. The cursor binds sequence, ID, digest, count, phase, and next ordinal.
3. Validate mutates only its own durable progress.
4. Apply cannot begin before the durable completed Validate transition.
5. Every Apply transition is fully prepared before canonical mutation.
6. Canonical row and derived index effects advance together under accepted
   schema semantics.
7. Identity, schema, validation-job, and migration record families retain their
   existing singular authorities.
8. A watermark never advances past an unapplied record.
9. Cursor and batch retirement cannot erase the only authority for incomplete
   work.
10. A batch at or below the watermark is never applied again.
11. Raw byte admission happens before record materialization.
12. Every stated physical and instruction limit includes measured worst-unit
    overshoot and fanout.
13. Malformed or unsupported state fails typed and closed.
14. Generated models never reconstruct runtime authority.
15. Production convergence contains no panicking operations.
16. Raw non-gzipped Wasm is the authoritative footprint measure.

## Baseline And Acceptance Measurements

Patch 1 records maximum and representative encoded batch bytes, raw-header
bytes, record count, per-family encoded size, maximum row/index fanout, cursor
bytes, Validate and Apply instructions, terminal instructions, overshoot,
stable growth, final raw Wasm, deterministic gzip secondary, Candid/method
modes, and complexity signals.

Acceptance requires rejection before materialization when raw bounds fail;
complete validation before canonical mutation; fixed memory and instruction
headroom below the maintained message envelope; exact resume at every durable
boundary; no history-dependent per-page work; no method-mode drift; and
reviewed raw-Wasm growth.

Performance claims distinguish batches `B`, encoded bytes `Y`, records `R`,
derived fanout `F`, and instructions `I`. A page limit expressed in only one of
those quantities is insufficient.

## Complexity And Maintenance Gate

Demonstrated need: the predecessor can mutate early records before discovering
late corruption and cannot truthfully claim a pre-decode page byte bound.

Simplest alternative rejected: per-record validate/apply with a larger page
does not solve either invariant.

Canonical owner: one convergence cursor and coordinator over existing
record-family semantics and canonical stores.

State-space delta: one phase bit plus digest in the current cursor and one
current raw envelope revision. The old cursor and old envelope do not remain
current. No scheduler, backlog, visibility, cardinality, statistics, or
configuration axis is added.

Promotion fails if the implementation needs a second prepared log, separate
startup/online decoders, legacy formats, generated authority, or unbounded
validation. Each handoff reports files/line delta, domains, state axes,
duplicate flows, instruction/stable/raw-Wasm effects, and the resulting
complexity direction.

## Promotion Gate

0.228 becomes implementation authority only when:

1. 0.227 has a reported ready/complete closeout and Patch 1 confirms it did not
   redefine the accepted 0.225 recovery authority;
2. Patch 1 confirms the late-validation behavior and freezes the current raw
   envelope cut;
3. exact current envelope, cursor, record-family, and hard-cut transitions are
   recorded;
4. batch, byte, record, fanout, instruction, overshoot, stable, and raw-Wasm
   gates are frozen;
5. every interruption boundary has an explicit expected durable state; and
6. the user explicitly authorizes 0.228 implementation.

Until then, this document is proposed design authority only.
