# 0.269 — Bounded writes and SQL assignments

The maintainer explicitly selected 0.269 on 2026-10-09 after focused 0.268
closeout, carrying the unpublished 0.268.1 tooling work. Native acceptance
remains at its existing issue owners. Published 0.268.0 is the release base;
Cargo versions and publication stay with the shared workflow and maintainer.

## Landing slices

1. **Shared installer and package convergence (prepared):** carry the canonical
   Shared 0.2.2 exact-path publication fix and selected IC-package qualification
   from 0.268, under [#309](https://github.com/dragginzgame/icydb/issues/309),
   [#307](https://github.com/dragginzgame/icydb/issues/307) and
   [Shared #88](https://github.com/dragginzgame/shared-tooling/issues/88).
2. **Public write scan ceiling (prepared and qualified):** reuse the executor's scanned-key budget for
   prefix UPDATE and bounded DELETE under
   [#217](https://github.com/dragginzgame/icydb/issues/217). One shared write-policy
   owner supplies 4,096 keys to exact and bounded selectors. Exhaustion refuses
   before mutation staging/publication; primary-key selectors retain their
   existing admission. This introduces no configuration or execution engine.
   The new refusal for previously accepted long scans is a breaking semantic
   change, requiring this minor. Qualify exact/+1 scans, late/no matches,
   no effects on refusal, ordinary completion and existing exact-update behavior.
3. **AVG DISTINCT independent evidence (prepared and qualified):** extend the current generator and
   SQLite reference owner under
   [#330](https://github.com/dragginzgame/icydb/issues/330). Reuse SUM aggregate
   traversal/modifier/shrink support, receipts and manifest obligations.
   Bounded exact integer/half/quarter results preserve explicit normalization;
   non-overlapping results reject instead of using tolerance. Cover global,
   grouped, computed, filtered, nullable and empty inputs with cold/warm checks.
   No production numeric semantics or second oracle framework.
4. **UPDATE assignment expressions (prepared and qualified):** extend the existing SQL expression and
   accepted-write owners under
   [#324](https://github.com/dragginzgame/icydb/issues/324). Evaluate bounded
   scalar RHS expressions from each original row, retaining one atomic commit
   and existing field/type restrictions. Reuse expression binding/evaluation;
   fixed resumable assignments remain fixed, and row-dependent assignments must
   reject there before job effects. No new persisted format, retry mode,
   compatibility wrapper or independent expression interpreter. Qualify field
   copies, self-reference, simultaneous assignments, NULLs and failure atomicity.

## Contract and state delta

- The scan ceiling uses the existing executor budget and one-key overflow probe;
  successful selection fits 4,096 keys and observed key 4,097 produces E194
  before effects. There is one policy constant, no caller configuration, and no
  new traversal or persisted state. E194 keeps its numeric/fact wire layout;
  only its Rust variant and constant names broaden to SQL writes.
- AVG adds one current private expression variant, five scheduled witnesses and
  one closed fixture fact needed to keep independent SQLite averages exact.
  Existing aggregate traversal, generation, shrinking, receipts and manifests
  remain the owners. The overlap is bounded integer/half/quarter values, not
  approximate floating-point agreement. Current evidence formats remain version 1.
- UPDATE adds one private authored-expression variant to the parsed write model.
  Existing SQL input/preparation budgets bound it, scalar projection binds and
  evaluates it, and accepted write admission owns target conversion. The durable
  job format still stores one fixed patch. E282 is an explicit SQL write-boundary
  leaf for expression refusal, matching existing job preparation diagnostics;
  the public job API projects it to existing `MutationJobError::IneligibleIntent`.
  There is no new job mode, retry branch, compatibility path or persisted layout.
