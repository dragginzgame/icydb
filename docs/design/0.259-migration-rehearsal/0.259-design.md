# 0.259 — Migration Rehearsal

Status: M1–M4 complete; focused qualification of the closeout corrections passes.
Full release validation remains user-owned.
Started: 2026-09-18. Delivery owner: [status](0.259-status.md).

## Outcome

Make one maintained schema migration reproducible against populated, disposable
data, including rejection and interrupted recovery. Give application authors a
small example they can adapt to their own exact artifacts and expected results.
This release does not add a migration engine, production dry-run API or generic
workflow framework. A documented integration test may be the entire product.

The demonstrated starting gap was manual qualification: the existing
[migration closeout test](../../../testing/integration/tests/schema_migration_closeout.rs)
was ignored and required two externally supplied Wasms. It exercised a successful
transition and one interrupted execution, but did not supply an automated
current-source build recipe, a paired uninterrupted control or a rejected-data
case. M2 replaces that manual setup; its passing execution and corrected startup
interaction are recorded in the status tracker.

Begin with the maintained `SqlTestUser` transition: preserve IDs and the name
index, rename `rank` to `score`, and convert `age` from Int32 to Nat16 using the
existing checked cast. Build both source shapes from the same current checkout,
lockfile, toolchain and internal formats. The fixture already owns both shapes;
do not copy an old library release into the repository.

This is an application-shaped example, not a selected Toko Miner migration.
Do not claim actual downstream data coverage. Application repository edits,
deployment, production data acquisition and Canic adoption are outside this line.
SQL is an existing fixture frontend, not a new application endpoint requirement:
the rehearsal procedure consumes typed migration commands and can be adapted to
ordinary domain seed/read endpoints. Do not add a second fixture simply to erase
SQL from a qualification example that already uses it.

## Hard-cut and identity contracts

- A supported adjacent entity source revision is not an internal encoding
  version. The existing source revision 1-to-2 example does not change any
  ledger, schema encoding, protocol or cursor discriminator from version 1.
- Both actors must use the maintained current storage representation. Rehearsal
  does not make old incompatible IcyDB/ic-memory formats readable; those require
  recreation, reinstall or explicit regeneration. No old-format readers, release
  bridges, aliases or compatibility fixtures may be added.
- Accepted database/head/plan identities from status must be passed into the
  existing commands. Do not infer authority from local files or regenerate a
  different plan during interrupted execution.
- Resume uses the exact same successor artifact and plan. Incompatible artifacts
  are rejected, not repaired or translated by the harness.
- Internal fixture seeding follows maintained write admission. No raw stable
  memory importer or hand-built journal/marker codec is part of this release.

## Required evidence

Reuse one transition and three bounded scenarios, not a cross-product of every
migration phase, entity kind and field type:

1. **Successful control:** seed explicit representative values and retain their
   expected identities, execute bounded Advance commands to publication, and
   check final typed values, field identity where exposed, and indexed reads.
2. **Interrupted success:** start from the same seed, interrupt one observed
   durable gated phase with the exact successor Wasm, verify retained progress,
   finish, and compare final rows and accepted authority with the control.
   Compare logical outcomes, not random canister IDs or incidental allocation.
3. **Rejected data:** seed an Int32 value outside Nat16's range, require typed
   transform findings before rewriting/publication, and verify accepted source
   authority/data have not been replaced. If the maintained pre-rewrite Abort
   contract applies, exercise it and verify the resulting permitted state;
   do not assume every failure or late phase is abortable.

A terminal phase alone is insufficient. Keep ordinary-work gating assertions,
exact plan/head bindings and bounded progress/finding pages. Remove the existing
negative old-field-alias assertion rather than maintaining an anti-resurrection
test; successful current-field output and preserved identity are the contract.
Choose finite fixture-specific advancement/page limits before execution. Limit
exhaustion is incomplete qualification, never successful migration or evidence
of corruption. Do not add another runtime budget to support this host loop.

## Build and reporting contract

Build both shapes through the existing retained Cargo/post-link flow, with
explicit features. Hold owners until bytes have been read; never reconstruct
private cache paths or read mutable destinations after dropping retention.
Make the qualification an ordinary focused integration target, not a manual
environment-variable-only test. Do not add a build system, cache or runner.

The completed example records source revision/dirty state, lock and fixture
identity, exact artifact hashes, compiler/profile/features, PocketIC version,
seed coverage, typed outcomes and passed/failed/ignored counts. Use one existing
report location and ordinary test assertions, not a persisted receipt protocol
or public report DTO family. Keep payloads out of evidence unless necessary.

Measure raw Wasm bytes for both current actors and per-message IC instructions
or cycles where the existing harness can attribute them. Do not compare source
and successor artifact differences as a runtime optimisation. Never use native
or wall-clock timing as a performance metric. Unsupported measurements remain
explicitly unmeasured; stable pages do not establish encoded metadata size.

No performance gain or new numerical runtime ceiling is promised. M2 reproduced
a valid pending migration being recorded as a terminal startup failure; the
user authorised its direct correction at existing admission/watchdog owners.
Existing preflight now produces the existing migration-pending signal, and the
watchdog stops while controller commands own progress without recording a
failure or polling the plan. No startup mode, failure encoding or schema
authority is added. Further runtime defects require the same evidence and scope
decision; do not silently bundle an optimisation or central migration redesign.

## Simplicity decision

Need: an ignored manually assembled proof is hard to reproduce and does not
show the selected rejection/control cases. The smallest alternative is the
existing application-style integration test with automatic exact builds and
better assertions. Choose that before extracting any reusable runner or adding
public APIs. A second real consumer with duplicated orchestration is required
before generalising the helper into an application framework.

Expected production state-space delta: zero new endpoints, modes, persisted
phases, configuration or formats. Host-only delta: the existing migration fixture
becomes routinely executable and gains two meaningful scenario controls. The
existing migration, allocation and accepted-schema owners remain authoritative.

## Delivery and closeout

The [tracker](0.259-status.md) groups the initial line into three end-to-end landing
slices, plus the user-approved M4 correction of the closeout findings. Each has
its direct code/tests/docs/evidence; they are not SemVer patches.
Stop after each handoff. Closeout requires the automatic target's actual passing
execution with no ignored mandatory cases, final-data and failure evidence, and
an honest adaptation guide. Full repository validation and publication remain
user-owned. A successful local rehearsal is not production deployment approval
or a proof that all production rows satisfy the proposed schema.
