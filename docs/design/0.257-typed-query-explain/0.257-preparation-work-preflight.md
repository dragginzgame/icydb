# 0.257 — Preparation-work preflight

Status: two-part implementation split approved by the user; slice 10 in progress.
Approval does not itself complete slice 10 or change runtime accounting.

## Findings

The existing request root is the correct counter authority. Actual preparation
charging is not a matter of adding calls to the active execution-budget helper.

| Boundary | Initial preflight evidence | Required contract |
| --- | --- | --- |
| Request lifetime | `session/request.rs` retains monotonic counters in every derived session. `RequestExecutionScope::charge` charges them directly. | Borrow the session's existing scope for preparation; no new request root, reset, optional metering mode or retained budget in a cached plan. |
| Execution lifetime | `executor/projection/facade.rs` installs `with_read_execution_budget` around an already-prepared projection. `executor/budget.rs::charge_current_execution_budget` returns success without charging when no tracker is active. | Preparation cannot depend on this ambient execution tracker. Having a current request scope is not the same as having an active execution budget. |
| Units | `session/query/cache.rs` charges one `PlanningSteps` unit per planning operation and separately charges compilations. The request limit is 1,024 planning operations; the read execution profile's corresponding limit is 2,000,000. | Do not reinterpret the 1,024-operation limit as expression-node work. Name the resource and unit at each actual work owner before implementation. |
| Frontend preparation | `session/query/dynamic.rs` lowers filters before shared-plan lookup. SQL normalization and alias substitution run before ordinary lowering/cache resolution. | Charge the work actually performed on each call, including failed preparation and warm rebinding. Retained syntax alone does not make semantic preparation free. |
| Canonicalization | `query/plan/expr/canonicalize/mod.rs` returns `Expr`/`CanonicalExpr`, not a result. Intent append and SQL predicate normalization consume those infallible functions. | Hard-cut the current owners and propagate typed exhaustion. Do not add a second metered normalizer or return a partially normalized artifact. |
| Ordering | `canonicalize/normalize.rs` calls `sort_by` with a comparator that allocates scalar labels and, on ties, Debug strings. Neither that comparator nor its renderer can return a budget error. | Bound/charge key construction and comparison work with an abortable owner while preserving successful ordering. An exhausted comparator must not substitute `Equal` or a common error key. |
| Produced-tree ownership | The canonicalizer deliberately reconstructs left-associated junctions. The authored depth ceiling therefore does not also cap canonical depth. Typed-request and SQL-syntax destructors do not own every intermediate planner `Expr`. | Qualify traversal and disposal of partially produced planner trees on exhaustion, not only rejection of caller input. Keep current successful canonical association and identity. |
| Access planning | `query/plan/access_choice/mod.rs` evaluates visible indexes and builds/clones candidate plans. `session/query/cardinality_tiebreak.rs` receives the candidate vector before applying its 64-candidate admission check. | Charge candidate evaluation/construction at its existing owner. The tie-break cap is not an early construction check; accepted-schema bounds remain relevant and must not be bypassed. |

These are missing enforcement contracts, not evidence that every admitted query
currently exhausts memory or overflows the stack. No new failure probe was used
to claim such an outcome in this preflight.

## Recommended resource policy

Keep the existing fixed request profile initially; do not silently increase a
ceiling merely because the new accounting starts reaching it. The following
existing resources are candidates for owner-local charging, not new counters:

| Existing request resource | Current limit | Intended preparation attribution |
| --- | ---: | --- |
| `PlanningSteps` | 1,024 | Preserve current planning-operation charges. |
| `PlanCompilations` | 256 | Preserve actual compilation charges and cache-hit savings. |
| `PredicateExpressionSteps` | 16,000,000 | Expression visits/rewrite work, with exact units established at the owner. |
| `NestedValueSteps` | 16,000,000 | Traversal of nested operand values. |
| `SortComparisons` | 32,000,000 | Actual canonical-order comparisons, without changing ordering on exhaustion. |
| `TemporaryBytes` | 128 MiB | Cumulative transient construction/copies under the existing resource semantics, not a live-heap gauge. |

The allocation/check sequence and instruction-watermark handling still need an
explicit owner contract. Raw node charges do not account for arbitrarily long
string comparisons or allocation peaks. Reuse retained accounting where it
describes a concrete copy; it is not an estimator of all normalization work.
Use the existing typed exhaustion facts and literal-free attribution.

The request budget decides success or failure, never canonicalization policy.
CASE's fixed content-based rewrite decision remains independent of remaining
request resources. Successful results must match the completed slice-9 baseline.

## Approved delivery adjustment

Split the original slice 10 into two substantive, end-to-end outcomes without
renumbering any completed slice:

1. **Slice 10: fallible expression preparation.** Connect existing request
   counters to the current typed/SQL preparation owners; hard-cut normalization,
   folding and alias-copy error propagation, including canonical ordering and
   safe intermediate cleanup. Include cold/warm exhaustion, cumulative retry,
   successful canonical/fingerprint parity, and direct cost qualification. No
   standalone plumbing-only handoff or unmetered compatibility path.
2. **Slice 11: access-planning and cache-work charging.** Charge current
   access candidate construction, scoring and actual cache validation/rebinding
   work using the same request authority. Include readiness/invalidation and
   cold/warm resource tests. Do not force fresh optimization on every cache hit
   or scan rows to create cardinality evidence.

Then resume bounded diagnostic construction/rendering (slice 5) and the typed
terminal (slice 1). Diagnostic-only projection remains in slice 5; ordinary
access-planning work must not become dependent on explain admission. This is a
delivery split within the already-approved shared-preparation scope, not a new
feature or a proposal to weaken its limits.

The design's rescope gate applies: fallible canonicalization/ordering and
access-planning construction are separate owner changes, not incidental error
propagation from a small counter insertion. The user approved this split
before production edits. No implementation choice should make the current
infallible helper the fallback for an exhausted metered helper.

## Implementation progress

The user approved the split. Expression-owned iterative destruction and in-place
child transfer are implemented and qualified in the
[status record](0.257-status.md). This removes the request-specific planner-tree
cleanup walk and repeated CASE-child clones.

Typed filter lowering now borrows the session's existing scope through a
short-lived `PreparationWork` context. It never creates a request root, installs
an optional ambient tracker or retains budget state in a query/cache artifact.
The existing owner is fallible; it has no unmetered fallback. Current units are:

- One `PredicateExpressionSteps` charge per frontend filter node visited.
- One `NestedValueSteps` charge per raw filter literal visited, before descent.
- `TemporaryBytes` for raw literal text bytes and requested `Value` vector
  backing storage, charged before cloning/reserving. This is cumulative
  construction accounting, not a live-heap or allocator-capacity proof.
- `TemporaryBytes` for every copied typed-filter field-name byte and introduced
  `Expr` box/argument-vector slot. Constructor-local checks precede allocating;
  binary children and function arguments move into their backing storage without
  cloning. Text/collection operations converge on one charged construction flow.
  Nonempty membership uses the existing shared constructor after charging its
  two argument slots and optional NOT box; its value vector is not charged twice.
  Empty sets, constants and empty junctions do not allocate planner storage.
- Instruction watermarks at segment entry, every 64 successful charges and
  segment completion, including rejected work. The segment begins after shared
  input admission and ends before access planning/row execution.

Public/trusted reads, grouped conversion, exact-key candidate/fallback conversion
and filtered exact-count preparation use the same context. Repeated conversions
charge repeated work. No-filter exact-count metadata shortcuts still skip the
conversion they do not need. Existing planning-operation units are unchanged.

Canonical normalization and scalar-WHERE/grouped-HAVING canonicalization now
return typed errors and require this same borrowed context. Typed intent and SQL
lowering propagate it; no alternate infallible normalizer remains. Predicate-only
intent additions do not require expression normalization. HAVING append has one
shape-preserving behavior instead of an unused CASE-policy switch.

Canonical sorting uses an abortable stable merge of indices. Expression operands
are permuted only after comparisons succeed, without cloning them. Keys use the
existing streaming label grammar followed by Debug on ties; a rejected write or
comparison returns the original typed error, never a partial key or `Equal`.
The sort-local table renders each label once and caches each Debug key lazily on
its first tie. Table/string construction is charged before allocation, and the
table is dropped before permuting operands; keys never escape into a session or
command cache. Repeated comparisons charge byte comparison work without charging
or repeating rendering that did not occur. Retaining keys increases concurrent
key storage while reducing cumulative construction, not adding a budget mode.
Additional owner-local charges are:

- `PredicateExpressionSteps`: normalizer/CASE-context visits, merge placements,
  permutation work, emitted key bytes, and the shorter byte length before each
  string comparison (a conservative comparison-work bound).
- `SortComparisons`: each actual fallible canonical comparator invocation.
- `TemporaryBytes`: requested backing allocations for collected terms, sort
  index buffers, the sort-local key table and strings, including retained
  prefixes on growth; final associative-node reconstruction is charged before
  allocating its boxes.

Comparison reorientation and function-argument normalization reuse their existing
boxes/vectors. Filter labels render already-canonical intent/residual trees
directly: rendering and fingerprint consumers neither clone/re-normalize nor
acquire request state. This does not introduce diagnostic-only limits or the
public explain-renderer hard cut ahead of slice 5.

SQL compilation borrows the current session scope on cache misses and bound
invocations. Valid concrete-command hits still skip semantic compilation and its
normalization charges. Explain binding and mutation-selector preparation use
diagnostic/mutation attribution; SQL read compilation uses the existing trusted
read lane. Aggregate trial-lowering propagates query errors rather than treating
exhaustion as evidence for another SQL route. No new request root or cache-held
budget is introduced.

Accepted-schema filter conversion now returns a short-lived borrowed-or-owned
value: unchanged text/blob scalars and recursively unchanged collections borrow
the current invocation's value, never session/schema authority. Typed lowering
moves its existing raw value forward when unchanged. The first converted list
element triggers a separately charged output vector and charged prefix copies;
subsequent children move or copy into it. A failed element preserves the complete
original input, not a partially converted list. New list buffers, materialized
text/blob children, hex decoder output and loose enum-label copies charge before
allocation. Conversion/copy traversal consumes nested-value steps; scalar parsing
charges an input-byte work allowance, including rejected input. This allowance
is not a bound on all parser-internal operations or allocations.

Grouped HAVING keeps its existing partial element-normalization semantics and
propagates the shared converter's errors through SQL lowering. Its new result
vectors and shared scalar copies are charged; copying an unconverted grouped
element remains uncovered. No exhaustion becomes an ordinary conversion miss.

Big-integer literal conversion now uses allocation-free exact LEB128 lengths at
the shared atom owner. Filter text is parsed once and handed to the maintained
literal canonicalizer without cloning the parsed result. Already-typed big
integers borrow unchanged storage after a charged size check. A necessary
container copy precharges magnitude storage rounded conservatively to 64-bit
words, covering the dependency's initialized 32-/64-bit limbs, not its retained
capacity. Exact-atom size checks charge a conservative 32-bit limb visit
allowance before the signed boundary scan. The existing text-byte work allowance
remains in place; no claim is made that it bounds all decimal-parser internals.
Strict SQL still owns its wider integer-cast family, but shares the same exact
atom length calculation and checks exact input sizes before cloning.

Accepted catalog normalization and strict canonical validation now reuse those
exact atom lengths too. Four size-only encodings are removed, with field-bound
checking and the existing five-byte overhead charge shared on
`ValueAdmissionBudget`. This preserves encoded-size accounting and error
precedence; it does not attach request-work accounting to deeper admission or
claim that encoded bytes bound CPU work, retained capacity or parser allocation.
Direct structural-write measurements are recorded in the
[catalog-admission receipt](0.257-catalog-admission-perf.md).

Slice 10 remains open. SQL AST conversion/folding/alias copies, parser-internal
allocations (including decimal big-integer parsing), necessary catalog encoding/copy work, deeper accepted-catalog
normalization and grouped fallback copies, field-name copies outside typed filter construction,
CASE expansion copies, predicate projection,
normal-form classification/deduplication and remaining construction sites need
owner-local work/allocation accounting. The read-only normal-form classifier is
not a fallback normalizer and is not yet fully charged. Recursive traversal and
formatting are not newly stack-bounded; periodic instruction checks are not an
early bound on every uncharged operation. Formatter-internal allocations are
not covered merely by charging emitted key bytes. Slice 11 has not started.
