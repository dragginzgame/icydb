# SQL arithmetic construction convergence

Date: 2026-09-08. Active release: 0.257.1, expression-preparation slice 10.
Incremental baseline: the preceding [CASE expansion candidate](0.257-case-expansion-perf.md),
not published 0.257.0.

## Change and contract

SQL field/literal arithmetic previously constructed NumericProjectionExpr, then
cloned its Expr and discarded the wrapper. The dynamic numeric-family check now
lives at SQL expression lowering, followed by ordinary binary construction.
This removes two field-string copies, one literal copy and two temporary Expr
boxes per admitted field/literal arithmetic expression. Four SQL-only wrapper
constructors and their private dynamic constructor are deleted. Public fluent
construction continues to use NumericValue; it has no API change.

The SQL dynamic family remains the same thirteen variants, including dates,
big integers and U256. It is deliberately not replaced by Value's narrower
numeric-coercion classification. The same nonnumeric projection error remains
at this boundary; comparison operators do not acquire that restriction. Tests
compare the exact planner tree across all four operators and lowering phases.
Numeric-scale validation also borrows its literal instead of cloning values
that it only inspects, including rejected containers.

These allocations are removed, not newly charged. Necessary SQL-to-planner
construction and other preflight accounting gaps remain in slice 10. There is
no new runtime mode, conversion authority, cache policy or compatibility path.

## Matched measurement

The unchanged SQL-perf actor uses WasmRelease/LocalTest, SQL enabled and Candid
enabled. Only the two production files differ between the frozen actor builds;
the new native probe does not add actor instrumentation. Each operator has a
fresh six-row fixture and three literals, with a compilation followed by an
identical-query concrete-cache hit:

```sql
SELECT id FROM PerfAuditUser
WHERE age <operator> <1, 2 or 3> >= -100
ORDER BY id LIMIT 100
```

Every call returns six rows, with compilation/hit result equality. There are
24 records per run. Deterministic settling ticks run outside the cycle interval,
without auto-progress or time advance. Local instructions cover session
acquisition, SQL preparation/execution and output conversion, excluding endpoint
Candid decoding/encoding; whole-update cycle-balance deltas include platform
costs. Each cell below uses independent medians of three samples, including the
first compilation after setup rather than only steady state.

## Validation and complexity

66 focused native passes: SQL lowering (33), fluent numeric projection (3),
fingerprints (26), SQL/prepared/fluent U256 parity (1), SQL-disabled numeric
projection (3). The four new direct tests include all thirteen families across
four operators and four phases, nonnumeric rejection, comparison controls and
scale bounds. Initial float-fixture and test-only diagnostic import propagation
errors were corrected. Final three-lane repository lint, focused all-feature
lint, formatting, admission/branch/authority/panic invariants and whitespace
checks pass. Full test suites remain user-owned.

Nine handoff files: four Rust and five docs, approximately 80 fewer
production/wiring lines and 188 net test/probe additions relative to this turn's
starting worktree. The implementation is simpler: one SQL binary construction
flow replaces the temporary fluent-wrapper detour. No applications, Cargo
versions, commits or pushes changed. Slice 10 remains open; this does not expose
typed `.explain()` or start a subsequent planned slice.
