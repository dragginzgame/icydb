# Big-integer literal validation: copy and encoded-size cleanup

This slice-10 checkpoint removes the clone of a freshly parsed big-integer
filter literal and the encoding allocated solely to check its byte limit.
Exact typed big integers borrow unchanged storage; strict SQL checks exact
inputs before cloning. Filter admission remains narrower than SQL integer
casting. The existing decimal parser and persisted/canonical encoders are
unchanged; no compatibility path or new normalization route is introduced.

## Size and accounting contract

`IntBig::leb128_len` and `NatBig::leb128_len` own allocation-free exact length
calculation. Unsigned values use seven data bits per byte, with one byte for
zero. Signed values reserve a sign bit; negative powers of two need one fewer
bit than positive values. A scan for that exception is needed only at a
seven-bit boundary. The maintained encoder is the independent test oracle:
58,443 comparisons cover dense small signed values and signed/unsigned powers
of two plus/minus one through bit 2,048, including zero and limb boundaries.

Already-typed filter size checks consume a conservative 32-bit limb visit
allowance before the signed boundary scan. Necessary container copies precharge
magnitude storage rounded to 64-bit words, conservatively covering initialized
32-/64-bit dependency limbs. This does not claim retained capacity or allocator
overhead. The existing scalar text-byte work allowance remains; decimal-parser
internal allocations and unrelated catalog encoding/copy work remain open.

## Measurement contract

The maintained `sql_perf` actor gains one empty-table `IntBig`/`NatBig` fixture
and a test-admin-only, bounded measurement endpoint. The baseline was built
**after** adding this instrumentation but **before** production changes. The
same frozen probe and actor/fixture source measure both modules. This establishes
conversion cost without an application edit or an engine execution mode.

- Canonical `wasm-release`: Rust 1.97.1, Binaryen 132, maintained local-test
  profile, SQL/Candid enabled; PocketIC 16.0.0 application subnet.
- Fresh installed canister per family/width; all-9 decimal literals of 20, 80
  and 300 digits, unsigned or negative signed. The 256-byte accepted field limit
  admits all measured values. The magnitude text excludes its optional minus sign
  from the digit count.
- Construct one typed equality query, select `id`, limit one, execute through
  the normal trusted query pipeline against the empty dedicated entity.
  All calls return zero rows. These are valid empty-table queries, not row-scan
  throughput measurements or a direct call to an isolated arithmetic helper.
- Four successive updates: report the first cold call separately, then the
  median of the three warm calls. Cold includes lazy runtime/schema setup; do
  not attribute all cold cost to literal conversion or promise fresh planning
  on every warm call.
- Settle 64 deterministic rounds before each interval. No auto-progress or
  manual time advancement. The local instruction counter includes query
  construction/preparation/planning/execution, excluding input text construction
  and Candid decoding. Whole-update cycles include those and platform overhead.
  They are different measurement windows, not interchangeable quantities.

Warm instruction medians improve in all six cells, but this is **not a blanket
cycle speedup**. The unsigned 300-digit warm cycle increase is retained, not
explained away by the narrower instruction improvement. Allocation/history
effects are included; no phase-specific attribution has been established.

instruction sample increases 63,006 (about 2.03%). No sample crosses both the
existing 250,000-instruction and 3% material-regression thresholds.
Both frozen-artifact replays reproduce all 24 records per module exactly.

growth is about 300 lines: 46 engine/atom lines, 179 test/wiring lines and 75
fixture/measurement lines. One exact size authority replaces encoded-size
materialization, and existing conversion ownership is reused. There is more
explicit ownership/accounting code but fewer redundant copies and no additional
parser, engine route, request root or persisted state.
