# In-place SQL qualifier reduction

Date: 2026-09-08. Active release: 0.257.1, preparation slice 10.
Baseline: the preceding [owned-path candidate](0.257-identifier-move-perf.md),
not published 0.257.0.

## Ownership and admission

The existing shared `normalize_identifier_to_scope` consumes a String. It now
removes a matching prefix from that allocation rather than creating a new
suffix String. Both direct-prefix matching and the existing qualified-tail
matching branch use owned compaction. There is no new normalization route,
configuration, compatibility path or matching rule.

Direct matching still takes the first matching scope candidate, not necessarily
the longest candidate. Prefix slicing checks UTF-8 boundaries and the ASCII dot
before removal; tail matching derives its removal boundary from the existing
valid split. Nonmatching input remains untouched. Unicode field names and empty
suffix behavior are preserved.

This removes suffix allocation, not byte movement: retained bytes still shift
to the beginning of the original allocation. Original capacity is preserved,
which can exceed the suffix length. It is not complete request-work or retained
cache accounting. Scope matching, joins and remaining normalization/alias work
still need owner-local accounting before slice 10 can close.

## Validation and measurement contract

Focused tests cover matching/nonmatching qualifiers, record paths, candidate
order, Unicode boundaries, empty suffixes and preservation of owned pointer and
capacity. Broader SQL lowering and session tests exercise current authority,
binding and query behavior. Clippy initially requested inclusive range notation;
the equivalent spelling was corrected and the repository clippy gate was run
before resuming qualification.

The unchanged native identifier probe and phase-instrumented SQL-perf actor use
the same canonical WasmRelease/LocalTest settings as the baseline. Three aliased
queries with distinct literals each compile then immediately hit the concrete
command cache. Every result has six rows, with exact compile/hit parity. Local
read counters retain absolute request readiness/completion boundaries; cycles
cover the whole update. Deterministic settling ticks are outside the interval.
Page-charge redistribution remains relevant; local-counter flags are not
silently removed or corrected by subtracting guessed page costs.

87 focused native tests pass on the lint-corrected source: identifier handling
(5), SQL lowering (40) and session authority/preparation/bindings (42). The full
repository clippy gate, formatting and focused admission/branch/authority/panic
and whitespace checks pass. The initial range-notation warning is resolved;
full repository test suites remain user-owned.

The change touches six files: one Rust owner (including its direct tests) and

without a new execution path; capacity reuse is the explicit memory trade-off.
No application, Cargo version, commit or push changes are made.

## Final matched results

Four final qualification runs pass: baseline and lint-corrected candidate, each
with an exact six-record frozen replay. An earlier pre-lint candidate run also
passed but is superseded and excluded from the following comparison. Both
isolated PocketIC servers were stopped.

| Phase | Baseline local instruction median | Final local instruction median | Whole-update cycle median delta |
|---|---:|---:|---:|
| Compile | 4,995,493 | 4,991,534 | -3,763 (-0.01998%) |
| Hit | 4,314,781 | 4,470,227 | -1,395 (-0.00769%) |

These are independent medians of three samples. Individual cycle deltas are
all nonpositive: compile -407/-4,215/-3,763; hits 0/-3,149/-1,395. This is a
small workload-specific improvement, not a general database speedup.

The third hit crosses the existing positive local-counter review threshold:
+479,096 instructions (+12.004%). Its counter before the read falls 479,962;
the absolute counter through request cleanup falls 868 and whole-update cycles
fall 1,395. Thus the large local delta is offset by work before the measurement
window, consistent with the prior phase/page-charge findings. Keep this flag
visible rather than modifying totals or thresholds; it does not establish a
comparable whole-message regression. Prior CASE and other shape qualifications
remain separate.
