# Shared planner accounting: retained-key handoff

Date: 2026-09-09. Active line: 0.257. This is a source-backed sequencing
correction, not implementation or a preparation-boundedness verdict.

## Ownership correction

The tracker made slice 11 depend on finishing shared preparation in slice 10.
Recent retained-key work exposed the reverse dependency: the current FieldSlot
and GroupField owners also serve ordinary planner consumers that do not receive
PreparationWork. Metering only a frontend copy would leave those consumers
uncovered or introduce two versions of the same resolver.

Retained planner construction and comparison therefore belong in the already
planned shared-planner/cache slice 11. Its request-authority propagation is the
next implementation. Frontend-only residuals remain in slice 10. This neither
closes 10 nor expands `.explain()`; both preparation outcomes still gate bounded
diagnostics and the terminal. Do not insert another bookkeeping-only landing
between the authority and the work it must actually charge.

The retained key owners are
`FieldSlot::resolve_with_schema` in `plan/semantics/group_model.rs` and
`GroupField::resolve_with_schema` in `plan/group_field.rs`. As of the 0.257.2
metadata handoff, FieldSlot shares its accepted query kind from SchemaInfo and
resolves slot/type authority in one lookup: recursive kind copying is removed,
not assigned a second metered implementation. In active 0.257.3, direct labels
also share the accepted schema's immutable allocation: resolving/rebinding and
cloning a FieldSlot no longer copy label bytes. Schema construction remains the
label allocation owner. GroupField's path label/root/segment construction now
receives the same PreparationWork in frontend materialization and planner
rebinding. Its copies, key-vector backing, promotion and duplicate insertion
comparisons charge existing resources before work. Unresolved expression labels,
schema lookup internals and other planner copy/validation owners remain open.
GroupFieldSet insertion and validation share borrowed identity comparison;
validation-only comparison work remains open. The previous handoff
already removed throwaway retained-key construction from validation.

## Implementation contracts

- Executor handoff consumes finalized planner metadata. Active 0.257.3 removes
  its static-contract construction fallback and duplicate route-profile
  projection; incomplete handoffs fail before executor lowering. All five
  maintained shared-plan callers already finalize in the canonical planner.
  Future preparation authority is propagated through that owner, not an
  executor-side reconstruction path.
- Borrow the existing request execution scope. Frontend preparation and planner
  segments may have separate short-lived PreparationWork guards, but must share
  cumulative counters. No new root, optional mode, thread-local accounting route
  or budget retained in plans/templates is needed.
- Keep PlanningSteps and PlanCompilations as their current operation counts.
  Use the existing fine-grained work and TemporaryBytes resources for actual
  traversal/copy/comparison work, with exact units specified at each owner.
  Do not present cache retained-capacity accounting as a complete construction
  bound or add an uncharged recursive premeasurement pass before copying.
- Make exhausted work a typed error. Owners currently returning Option for
  unsupported/ineligible plans must distinguish that outcome from budget
  exhaustion; exhaustion must not become None, a scan fallback, an empty plan,
  an invariant error, or a fabricated fingerprint.
- Charge before allocations and abort comparisons without inventing equality
  or ordering. Preserve successful key spelling, slot identity, duplicates,
  aggregate order, canonical fingerprints and cursor identity.
- Keep current accepted authority, readiness and cardinality invalidation
  checks. Do not promise fresh optimization on every data/cardinality change.
  Do not scan rows to produce evidence for explain.
- Failed construction must not publish partial plans or new bound memos.
  Existing legitimate cache invalidation is not forbidden merely because a
  later preparation operation fails.
- Keep the forthcoming diagnostic-only limits out of ordinary fingerprint and
  cursor construction. This accounting remains ordinary query behavior, not
  an explain-specific planner route.

## End-to-end qualification

0.257.3 fused scalar compiler update: scalar ASTs now compile directly to
CompiledExpr. The temporary scalar representation and preview-specific recursive
lowering are removed; schema-backed compilation and single-value preview share
one recursive owner with their existing leaf admission/error policies. Every
CASE condition/result/ELSE compiles before parent specialization, so discarded
branches cannot hide an invalid field or aggregate. Final shapes, retained
accounting and exact projection-vector capacity stay unchanged. Source literal/
label copying, final containers and path encoding remain unmetered construction;
this simplification does not close preparation or implement typed `.explain()`.

0.257.3 scalar aggregate compilation update: terminal input/FILTER preparation
no longer performs a separate unknown-field scan before scalar compilation.
The shared compiler owns availability; missing fields and unsupported shapes
keep the same payload-free invariant. This removes duplicate successful-path
traversal/lookups, not compiler construction. Late invalid operands may now
discard a compiled prefix; accounting that actual construction remains open.
There is no alternate checked compiler or execution mode.

0.257.3 index-order comparison update: candidate scoring, order-only selection
and boolean route checks no longer construct canonical index-label vectors.
Borrowed accepted keys and owned scalar diagnostic labels share the classifier;
primary-key suffix stripping happens once. Accepted expression rendering and
comparison share one label grammar; grouped prefix/trailing-key rules stay
distinct and unchanged. Remaining comparison work still needs charging, but
the removed lists/strings require no construction budget. Actual diagnostic text
and ORDER BY contract construction remain separate unfinished owners.

0.257.3 secondary-key ownership update: the common secondary-order constructor
retains accepted Rc key-name storage across candidate scoring, order-only access
selection and final route projection. Primary-key vector/label copies and their
clone copies are removed. Existing retained accounting includes shared headers,
backing and capacity per resident. Remaining non-primary label rendering and
comparison work must receive shared authority through both candidate scoring and
access-choice projection; a finalization-only bounded constructor would leave a
parallel unbounded flow. This is not a preparation-boundedness closeout.

0.257.3 secondary-order reuse update: covering classification, ordered DISTINCT
seeking and execution-explain order satisfaction borrow PlannerRouteProfile's
finalized contract rather than reconstructing it. These downstream checks no
longer allocate order labels/key names. Initial finalization and candidate-time
contract construction remain open bounds work; current schema authority, access
classification and legitimate cached-plan freshness are unchanged.

0.257.3 borrowed primary-key update: planner order selection/validation, covering
reads and runtime route/continuation checks consume the accepted name slice
directly. The finalized-plan getter borrows its existing backing and no longer
allocates a reference vector. Removed temporary lists need no construction
charge; tuple/suffix semantics, current authority and missing-contract errors
remain unchanged. Retained secondary-order contract strings still allocate as
before, so this is not a closeout of planner construction or diagnostic bounds.

0.257.3 scalar-admission update (frontend slice 10): aggregate input/FILTER
validation consumes existing field-root and aggregate-presence analysis, removing
discarded scalar compilation. Current authority checks and unknown-field precedence
are unchanged. The execution compiler remains in place; analysis construction,
schema lookup accounting and actual compiler allocations still need qualification.

0.257.3 primary-key ownership update: accepted schemas and static contracts share
one immutable key-name list. The owning schema/plan chain uses Rc consistently
with thread-local accepted roots, caches and executor residents; grouped handoffs
use the same ownership. No IC/native mode or cross-thread contract is added.
Refinalization selects current names; detached older artifacts retain their view.
Existing retained accounting includes the shared header, backing and string
capacity per resident. Removed copies need no construction charge; initial schema
construction and temporary reference-vector helpers remain open.

0.257.3 order-slot update: ResolvedOrder's stable first-reference list now charges
field/node/slot visits, duplicate comparisons and backing growth before insertion.
CompiledExpr shares one traversal between fallible preparation and infallible
runtime marking; both node and slot errors stop immediately, including in CASE
and specialized programs. Missing order remains absent metadata, not an error;
exhaustion propagates before cache publication. No new identity or route. Source
expression compilation and other planner construction remain open.

0.257.3 projection-identity update: full accepted field count plus strictly
increasing resolved slots replaces an allocated/sorted schema-name comparison.
Unaliased direct fields remain required, including for sparse physical layouts.
Count/shape checks, label bytes and slot comparisons charge existing work units;
the check allocates no temporary backing. Typed exhaustion is distinct from
non-identity and propagates before static-contract/cache publication. Schema
lookup internals remain open; identical memo hits still skip construction.

0.257.3 direct-layout update: both executor projection layouts now share one
budgeted field pass over the frozen ProjectionSpec. Exact backing, label visits,
uniqueness comparisons and the conditional unique-vector copy are charged.
Duplicate-preserving versus unique-only availability remains unchanged; missing
layouts are not budget failures. Initial projection lowering/schema lookup
internals remain open, but duplicate selection/schema-ordering flows are removed.

0.257.3 projection-slot update: the existing projection owner now charges node
visits, field labels, sorted insertion comparisons/shifts and vector growth.
One field/path-root lookup branch replaces duplicate handling; sorted insertion
removes the final unmetered sort while preserving the canonical slot list.
Typed rejection propagates before static-contract/cache publication. Schema
lookup internals and other projection/compiler construction remain open.

0.257.3 scalar ownership update: the fused compiler above supersedes the initial
owned-temporary-tree handoff. There is now no intermediate scalar tree or duplicate
path wrapper. Final containers, source payload copies and path-label/byte encoding
remain allocation owners requiring accounting; final IR/cache shapes are unchanged.

0.257.3 binary-specialization update: consume owned compiled operands instead
of borrowing them into optional probes and cloning successful labels/literals.
The same specialized and generic programs remain; source payload copying
and compiler container allocation still need shared accounting. Removed copies
do not need replacement resource charges; retained payload accounting is unchanged.

0.257.3 order update: order-term vector backing and scalar-seam validation now
charge the same PreparationWork. Removed unused diagnostic rendering and the
validator's duplicate schema slot resolution; compilation remains the field
authority for expressions. Expression compilation/copies, referenced-slot
construction and schema lookup internals still require accounting.

0.257.3 static-index update: execution slots and predicate compile targets now
share one accepted-key traversal. Both vector allocations and the field-label
scan charge the existing PreparationWork before construction. Unknown slot
resolution remains unavailable metadata; budget failure remains a typed error.
The broader static projection and schema lookup owners are still open.

0.257.3 construction-boundary update: ordinary/trivial cache-miss construction,
parameterized cold construction and changed-binding rebuilds finish one
PreparationWork instruction interval before publication. Pinned construction
finishes it before returning either a plan or unavailability. The previous
cold-template-only guard is absorbed, not nested. Fast artifact/memo hits skip
these construction intervals. Earlier schema/planning-state work, cache
validation, allocation and fine-grained retained-key/candidate work remain open;
completion watermarks cannot interrupt an oversized uncharged inner operation.

Use exact/one-below allocation and work budgets for direct and nested key
construction. For accepted kinds, prove shared immutable metadata and complete
retained-size accounting instead of introducing a recursive metered copy.
Exercise public and trusted reads, cold
compilation, early filterless hits, identical-bound reuse, changing bindings,
pinned continuations and current-authority/readiness transitions. Failed and
repeated calls must consume the same request counters; a fresh request can
reuse the unchanged authored input. Prove no row execution on preparation
exhaustion and no partially constructed cache artifact.

Measure matched Rust 1.98.1 artifacts after the concurrent planner bug fix is
stable. Keep scalar controls, repeated identical bindings, changing bindings
and grouped direct/path inputs separate. Report raw Wasm first, then gzip,
defined function count, instructions or measured cycles, and source complexity.
Neither fewer clones nor the size of a request wrapper establishes a cost win.

Full candidate construction, scoring and cache validation/rebinding coverage
remain slice 11 completion requirements; wiring one retained-key call does not
close the whole outcome. Frontend residuals remain slice 10 work, and numeric
diagnostic admission/rendering gates remain slice 5 work.

## This handoff

Four design documents change. There are no runtime, test, public API, resource
policy, Cargo version, application or changelog changes. No new behavior axis
is proposed. Read-only caller inspection and local document checks qualify the
record; tests, lint, Wasm and performance measurements were not rerun. No local
network was started or stopped. Concurrent sparse-index work is left intact.
