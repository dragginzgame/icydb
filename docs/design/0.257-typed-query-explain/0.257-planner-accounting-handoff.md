# Shared planner accounting: retained-key handoff

Date: 2026-09-09. Active line: 0.257. This is a source-backed sequencing
correction, not implementation or a preparation-boundedness verdict.

## Ownership correction

The tracker made slice 11 depend on finishing shared preparation in slice 10.
Recent retained-key work exposed the reverse dependency: the current FieldSlot
and GroupField owners also serve ordinary planner consumers that do not receive
PreparationWork. Metering only a frontend copy would leave those consumers
uncovered or introduce two versions of the same resolver.

Retained planner construction and comparison therefore belong in the already
planned shared-planner/cache slice 11. Its request-authority propagation is the
next implementation. Frontend-only residuals remain in slice 10. This neither
closes 10 nor expands `.explain()`; both preparation outcomes still gate bounded
diagnostics and the terminal. Do not insert another bookkeeping-only landing
between the authority and the work it must actually charge.

The retained key owners are
`FieldSlot::resolve_with_schema` in `plan/semantics/group_model.rs` and

already removed throwaway retained-key construction from validation.

## Implementation contracts

- Borrow the existing request execution scope. Frontend preparation and planner
  segments may have separate short-lived PreparationWork guards, but must share
  cumulative counters. No new root, optional mode, thread-local accounting route
  or budget retained in plans/templates is needed.
- Keep PlanningSteps and PlanCompilations as their current operation counts.
  Use the existing fine-grained work and TemporaryBytes resources for actual
  traversal/copy/comparison work, with exact units specified at each owner.
  Do not present cache retained-capacity accounting as a complete construction
  bound or add an uncharged recursive premeasurement pass before copying.
- Make exhausted work a typed error. Owners currently returning Option for
  unsupported/ineligible plans must distinguish that outcome from budget
  exhaustion; exhaustion must not become None, a scan fallback, an empty plan,
  an invariant error, or a fabricated fingerprint.
- Charge before allocations and abort comparisons without inventing equality
  or ordering. Preserve successful key spelling, slot identity, duplicates,
  aggregate order, canonical fingerprints and cursor identity.
- Keep current accepted authority, readiness and cardinality invalidation
  checks. Do not promise fresh optimization on every data/cardinality change.
  Do not scan rows to produce evidence for explain.
- Failed construction must not publish partial plans or new bound memos.
  Existing legitimate cache invalidation is not forbidden merely because a
  later preparation operation fails.
- Keep the forthcoming diagnostic-only limits out of ordinary fingerprint and
  cursor construction. This accounting remains ordinary query behavior, not
  an explain-specific planner route.

## End-to-end qualification

Use exact/one-below allocation and work budgets for direct and nested keys,
including recursive accepted kinds. Exercise public and trusted reads, cold
compilation, early filterless hits, identical-bound reuse, changing bindings,
pinned continuations and current-authority/readiness transitions. Failed and
repeated calls must consume the same request counters; a fresh request can
reuse the unchanged authored input. Prove no row execution on preparation
exhaustion and no partially constructed cache artifact.

Measure matched Rust 1.98.1 artifacts after the concurrent planner bug fix is
stable. Keep scalar controls, repeated identical bindings, changing bindings
and grouped direct/path inputs separate. Report raw Wasm first, then gzip,
defined function count, instructions or measured cycles, and source complexity.
Neither fewer clones nor the size of a request wrapper establishes a cost win.

Full candidate construction, scoring and cache validation/rebinding coverage
remain slice 11 completion requirements; wiring one retained-key call does not
close the whole outcome. Frontend residuals remain slice 10 work, and numeric
diagnostic admission/rendering gates remain slice 5 work.

## This handoff

Four design documents change. There are no runtime, test, public API, resource
policy, Cargo version, application or changelog changes. No new behavior axis
is proposed. Read-only caller inspection and local document checks qualify the
record; tests, lint, Wasm and performance measurements were not rerun. No local
network was started or stopped. Concurrent sparse-index work is left intact.
