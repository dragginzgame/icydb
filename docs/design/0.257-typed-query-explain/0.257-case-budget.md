# 0.257 — Bounded CASE Rewriting

Tracker slice 7, explicitly authorized with a hard cut on 2026-09-08.

## Implementation contract

The existing CASE canonicalizer owns the optimization decision. Retain compact
CASE when constructing the boolean expansion would exceed 256 structural work
units. Charge each expression, value and path segment once, plus one unit per
started 64 bytes of variable payload. Charge both copies of each condition and
all introduced guard/junction nodes before the first expansion clone. The
existing eight-arm limit remains. This admits eight simple field-based arms
while preventing small nested CASE from manufacturing successively larger trees.

This is one fixed rewrite budget, not a new query-admission limit or exact
allocator/peak-memory guarantee. It bounds each admitted expansion's structural
nodes (and hence depth) and variable payload, not total query work or caller
construction/cleanup. Larger inputs remain compact and use the existing CASE
compiler/evaluator. No new mode, configuration, runtime route or format.

Predicate compilation previously contained another CASE expansion. Remove that
duplicate: a retained CASE is expression-backed, not an opportunity to redo the
rewrite downstream. This is direct propagation of the one-owner policy.
Predicate projection is currently whole-expression admission, not independent
conjunct extraction. Consequently even an adjacent indexable comparison may lose
its predicate access opportunity when CASE remains compact. Existing execution
admission still applies to the resulting plan; this slice adds no scan exemption
or separate partial-extraction planner. The initial conjunct test disproved the
stronger index-preservation assumption and is qualified against that maintained
boundary instead.

The decision must depend only on logical contents, never container capacity,
pointer width, allocation history or cached state. Consequently the retained
capacity walker is unsuitable: equal values with different spare capacity must
produce identical canonical models. The existing primary-key payload estimate
also allocates big-integer encodings and does not bound recursive traversal.
Use a narrow, allocation-free, budget-short-circuiting walk at the CASE owner;
big integers use existing nonallocating magnitude-bit access.

First-match and three-valued semantics must remain intact. Qualify repeated
canonicalization, copied large/container values, small unchanged expansions and
compact execution. Affected access paths, fingerprints and continuation
signatures may change: restart affected pagination, retain version 1 and current
signature rejection only. This approved representation change does not make
the remaining diagnostic bounds complete.

## Qualification plan

Use the existing matched nested-CASE native probe at levels 0, 2, 4 and 6, opt
level 1 with debug assertions disabled. Baseline is completed slice 6, not the
earlier reentrant comparator. Require reduced six-level preparation time and
no more than 50% regression at level 2 across repeated runs; level 0 is a noisy
no-CASE control, not an optimization claim. These are slice-local native gates,
not the still-open diagnostic Wasm/function/cycle gates. No new Wasm/cycle claim
without measurements. Focused correctness/lint checks and active 0.257.0 notes
are required before handoff; full suites remain user-owned.

## Results and measurement receipt

Complete. One canonicalizer owns CASE expansion; predicate compilation no longer
contains a second expansion. Six-level preparation improves by 91.8%; the
two-level case is about 17.1 microseconds in both binaries and passes the fixed
50% regression ceiling. Four levels are about 173 microseconds in both. No
claim is made for the sub-microsecond zero-level control.

Matched protocol: Rust 1.97.1, x86_64 Linux, opt-level 1, debug assertions off,
SQL/migration/metrics off. Baseline is the frozen slice-6 candidate from the
[ordering receipt](0.257-ordering-perf.md); its production normalizer hash still
matches the worktree. The existing timing test and loop are unchanged. Each
process warms a shape once, then takes the median of three batches of three
calls. Input construction/cloning is outside the timer; scalar canonicalization,
temporary allocations and output disposal are inside. No row execution, IC,
allocation instrumentation or Wasm measurement. Five sequential baseline /
candidate pairs run after compilation without an agent-launched concurrent
build, each under a 20-second external guard. Every process passes.

## Validation and complexity

Final focused validation passes 174 all-feature tests (one manual benchmark
ignored) across expression preparation/evaluation, SQL lowering, accepted-row
execution, fingerprints and cursors. The SQL-free expression selection passes
58 tests with two manual benchmarks ignored; the timing probe passes explicitly
in all ten final matched processes. Maintained three-lane lint and focused
all-feature library/test lint pass. Formatting and whitespace pass. Full suites
remain user-owned. No application, Cargo-version or network lifecycle changes.

Twelve files in this landing slice, approximately 122 net production lines and
227 test/wiring lines, plus documentation. The production shape has less
duplication (one CASE rewrite instead of two) and a new private bounded-accounting
walk; it is not a claim of fewer total lines. The full pending worktree spans
24 files including previous slices. Active root/detailed 0.257.0 notes are current.

approved hard-cut representation as the baseline; typed `.explain()` is not
