## Current owner and representation decisions

- S1: the schema-owned `Ulid` atom owns both public Candid and Serde. The
  demonstrated waste is formatting 16 bytes into 26 ASCII characters for every
  binary transport value. Reuse the atom's current byte representation; do not
  introduce another public wrapper, flag, or alternate Candid decoder.
  Human-readable Serde retains canonical text as its existing display contract;
  binary transports accept only the current bytes representation. State-space
  delta: replace one Candid shape, add no format version or selectable mode.
- S2: the accepted field kind selects one fixed little-endian integer width.
  Add six scalar codec identifiers for signed/unsigned 8-, 16-, and 32-bit
  fields, including relation targets, and persist them in the current version-1
  catalog. The scalar owner checks representability before writing 1/2/4 bytes
  and widens decoded values into the existing runtime integer family. The
  two-byte null/value envelope stays unchanged. This replaces the unconditional
  eight-byte payload; it adds no adaptive encoding, width configuration, runtime
  value variant, or format version. Row/default/catalog bytes require recreation.
- S3: the shared Structural Binary owner writes one existing `TAG_BYTES` frame
  containing a minimal little-endian magnitude. Signed payloads prefix a single
  sign byte (0 = zero, 1 = positive, 2 = negative); zero has an empty magnitude.
  Reject redundant high zero bytes and inconsistent sign/zero combinations.
  Emit directly from borrowed limbs, trimming only the high limb; decode only
  after the complete byte frame and canonical magnitude are validated. Existing
  generic byte skipping needs no new tag or traversal route. Accepted bigint
  bounds retain their LEB128 meaning. This internal pre-1.0 hard cut replaces
  the shared ordinary-field/nested representation, adds no selectable mode or
  format version, and requires affected data/default artifacts to be recreated.
- S4: existing fixed-width local value tags directly precede their raw payload.
  One tag-to-width table owns skip/decode boundaries: Account 62, Date/Float32
  4, Duration/Float64/Timestamp 8, Int128/Nat128/Ulid 16, Subaccount/U256 32,
  Decimal 17. Keep existing big-endian scalar byte order. Decimal's typed
  payload owner retains the full i128 mantissa plus one scale byte (0–28),
  rejecting larger scales instead of normalizing invalid persisted metadata.
  Ordinary ByKind Decimal wraps that same 17-byte payload in the existing byte
  frame so generic structural traversal needs no new tag. Date's nested day
  count narrows to i32. Account's fixed 62 bytes remain intact. Variable-width
  Principal and bigint frames keep their current grammar. This replaces the
  current version-1 forms without a new tag, format version, or runtime mode;
  affected persisted rows/defaults/snapshots require recreation.
- S5: cursor `token/value.rs` owns current scalar/grouped boundary values and
  mutation-job literal payloads. Replace bigint decimal text with minimal
  little-endian magnitude bytes under the existing u32 length; signed values
  prefix 0/1/2 for zero/positive/negative. Stream borrowed limbs, reject redundant
  high zero bytes and inconsistent signs. Remove Account's redundant u32 length
  (its payload remains 62 bytes), and narrow Decimal scale to one byte (0–28).
  These are the same fixed-width opportunities already qualified in S4, applied
  to the cursor value owner. `cursor/string.rs` replaces hex with unpadded
  URL-safe Base64 using the already locked base64 0.22.1 crate; only canonical
  trailing bits are admitted. Preserve surrounding-whitespace trimming, exact
  8 KiB binary limit, HMAC, mode/authority/progress and resume policy. Diagnostic
  length/encoding reasons move directly to the current names. Simplest alternative
  (keeping text/hex) retains demonstrated storage expansion. No new format,
  mode, runtime authority, fallback, or compatibility alias; replace current
  version-1 bytes. Regenerate saved cursors and recreate affected mutation-job
  records; checksums cover the new payload at their existing owners.
- S6: `index/key/ordered/normalize.rs` remains the canonical ordered bigint
  encoder used by index construction, predicates and range lowering. Decimal
  digit magnitudes waste 46 bytes for a full 256-bit value. The simplest
  alternative, retaining digits, keeps both this expansion and the intermediate
  decimal chunk allocation. Encode minimal big-endian magnitude from borrowed
  limbs under the existing big-endian u16 length. Signed buckets remain
  negative/zero/positive (0/1/2); invert length and magnitude for negatives.
  Signed zero is tag plus zero bucket; unsigned zero has a zero byte length.
  Outer 4 KiB component/key bounds and accepted schema admission stay in place.
  Index components remain opaque canonical bytes at the framing owner: no
  runtime semantic decoder, new tag, mode, authority, or format version is added.
  Cursor/row binary encodings have distinct purposes and remain separate.
  This internal pre-1.0 hard cut requires affected databases/index artifacts
  and saved continuations containing physical index positions to be recreated
  or regenerated; no old-form decoder or translation path is retained.
- S7: canonical collection recursion currently retains child Vecs and then
  combines them; enums additionally stage their payload, while row assembly
  concatenates slots before copying them into a container and final envelope.
  Replace these copies with append operations at existing structural/enum/row
  owners. ByKind scalar/typed leaves append into their enclosing field; canonical
  lists/maps share their root buffer. The enum owner reserves its header and
  backfills body length after recursive emission, preserving its 4 MiB bound
  and typed failures. The row-envelope owner validates the known total byte
  length before allocation and lets the slot owner append directory and payloads
  directly. Existing admitted field images remain owned where patch/provenance
  consumers require them. No sink framework, new mode/format/authority or second
  execution route is added; standalone entrypoints allocate only their result.
  Simplest alternative (retaining child/combined buffers) keeps demonstrated
  duplicate payload storage. This is not a persisted-format change: exact
  current version-1 bytes, depth/size limits and admission semantics are retained.
  No additional recreation/regeneration requirement arises from S7.
- S8: Candid nat/int already compress small integers. Fixed bytes can expand
  them; short Decimal text can also be smaller than a structured value. Record
  that trade-off and close with no format change where it is the simpler result.
  The measured scalar/batch comparison retains Decimal text and native integer
  Candid. Decimal's Serde owner reads only the text emitted by its current
  serializer; delete its unused tuple ingress instead of retaining a second
  shape. This simplifies ingress without adding a mode, authority or format.
- S9: the S8 probe demonstrated that IntBig CBOR output cannot round-trip through
  its own decoder, and that bigint limb lists/U256 decimal text retain avoidable
  generic binary-Serde bytes. This newly demonstrated outcome belongs to the
  authorized all-storage audit, but is independently reviewable from public
  Candid qualification. The schema atoms remain the canonical owner; qualify
  one maintained binary shape and its Candid/JSON ingress before implementing.
  Retaining the existing derived serialization leaves both the round-trip defect
  and measured waste. No new selectable mode or persisted runtime authority is
  needed; internal row/index/cursor codecs stay separate.
  Implementation decision: human-readable Serde uses decimal strings. Binary
  Serde uses native i64/u64 where representable, otherwise a byte string carrying
  the same marker and canonical little-endian body as Candid's existing integer
  visitor (0 plus signed two's complement; 1 plus unsigned magnitude). This
  avoids inventing a transport discriminator to distinguish Candid from CBOR.
  A private integer visitor shares that grammar across the three atoms; field
  size/admission limits remain at their existing owners, and U256 rejects more
  than 32 magnitude bytes before conversion. Retaining native small integers
  avoids a fixed-blob small-value regression. Current outputs replace predecessor
  Serde shapes; no sequence/text fallback is kept in the binary visitor.
  No public type variant, mode, format version or accepted-schema authority is
  introduced. Existing native Candid subtype/coercion behavior is tested.

All incompatible persisted changes require recreation/regeneration of current
version-1 data. No predecessor decoder, alias, translator, or fallback is kept.

## S1 — ULID binary transport

Canonical public type: `blob` (`vec nat8`), exactly 16 bytes in the same order
as `Ulid::to_bytes()`. Rust typed IDs and public input/output values delegate
to this schema-owned encoding. Display, SQL text literals, and JSON continue
to use canonical ULID text; these are human-facing representations, not binary
compatibility paths. Binary Serde emits a byte string and validates its exact
width; its sequence visitor consumes at most 17 bytes before rejecting length.
Sequence decoding also checks the Candid element type before exposing values;
the fixed buffer avoids allocating a variable-length ULID at ingress.

Client bindings must be regenerated and calls must supply ULID bytes.
IcyDB's custom row/key/cursor/schema ULID payloads already use 16 bytes, so
this slice does not change database bytes or require database recreation.
External binary-Serde snapshots containing ULIDs must be regenerated.

## S3 — Structural big-integer magnitudes

Classification: internal pre-1.0 hard cut. Both accepted `ByKind` fields and
canonical nested `CatalogValue` values now share one byte-string magnitude
codec. The existing byte-string header is a tag and a four-byte big-endian
payload length. Unsigned contents are the minimal little-endian magnitude;
signed contents prefix sign 0/1/2 for zero/positive/negative. Zero's magnitude
is empty. A nonzero magnitude ends in a nonzero byte. Invalid signs, redundant
high zeros, sign/zero mismatches, truncated/deceptive frames, and trailing
bytes reject before bigint allocation. Construction is bounded by the fully
validated input slice; accepted size admission retains its LEB128 semantics.

The encoder streams borrowed limbs into the destination and trims the high
limb, without allocating a separate magnitude vector. The decoder no longer
constructs a temporary limb vector or traverses a structural list for each
bigint. Generic byte-string skipping already covers the new boundary, so no
new structural tag, walker branch, runtime mode, or format version is needed.
Nested values retain their existing one-byte local bigint tag. Account, public
Candid/binary Serde, decoded bigint representation, cursors and ordered index
keys are outside this slice and retain their existing representations.

Before sizes are calculated from the replaced encoder: unsigned = 5 + 9L,
signed = 19 + 9L, where L is the number of nonzero-normalized 32-bit limbs.
Current exact sizes are asserted by the maintained encoding tests: unsigned =
5 + B, signed = 6 + B, where B is the minimal magnitude byte length. All rows
below include the structural byte/list framing but exclude unchanged outer
row/slot framing. Nested canonical values add one byte on both sides, leaving
the same absolute saving.
