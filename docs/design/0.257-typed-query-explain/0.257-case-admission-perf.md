# 0.257.1 — CASE admission work

## Outcome and boundary

The fixed CASE rewrite-admission walker now charges the current request before
each fixed-budget accounting operation, and before each nested operand-value
visit. Content-based refusal short-circuits without refunding completed work.
Request exhaustion propagates as a typed error; it never selects compact CASE
as a successful fallback. The existing eight-arm/256-unit content policy and
successful canonical identities remain unchanged.

This closes admission-walk accounting, not CASE expansion-copy accounting or all
expression preparation. It adds no diagnostic-only limit, alternate estimator,
request root, cache-held context, or new public API. Necessary copied operands
and wrapper allocation in the subsequent rewrite remain separate unfinished
work within slice 10. Typed `.explain()` is not implemented by this change.

## Matched measurement

Baseline is the preceding borrowed-HAVING candidate, including all earlier
0.257.1 changes. The unchanged `sql_perf` actor uses the same configured
WasmRelease/LocalTest build, SQL and Candid enabled. No actor instrumentation,
endpoint, dependency, Cargo version or optimizer setting changes are included.
The maintained native probe adds only an ignored CASE matrix.

Each depth (1, 4, 8) gets a fresh installed fixture containing six users. Three
distinct SQL strings vary the innermost comparison literal; each is compiled
once through an update, then immediately repeated to measure a concrete-command
hit. All return identical six-row projections. The first comparison is
`age >= -repeat`; each CASE layer uses `THEN age >= 0 ELSE age < 0`.

interval. No auto-progress or IC-time advance occurs. Local instructions cover
session acquisition, SQL preparation/execution and result conversion, excluding
endpoint argument decoding/reply encoding. Cycle balance differences cover the

## Validation and complexity

93 focused native passes: 18 canonicalization controls, 26 query fingerprints,
40 session regressions, and nine SQL-disabled CASE controls. New coverage checks
exact request-work boundaries, unchanged content decisions, short-circuiting,
cumulative retry charges, nested-value exhaustion, absent cache insertion on
failure, warm command savings and no row execution during compilation. Focused
all-feature core/integration lint and admission/branch/authority/panic invariants
pass. The native timing microbenchmark remains ignored; full suites are
user-owned. Four matched Wasm matrix runs pass.

Ten files change: five Rust files (CASE caller, admission walker, CASE tests,
session CASE tests, SQL performance probe) and five docs (root/minor changelogs,
preflight, status, this receipt). Approximately +53 production and +204
test/probe lines are added. The execution structure stays neutral: the existing
single walker becomes explicitly fallible, with no second traversal or new
behavior mode. Earlier dirty work, including the unrelated installer edit, is
preserved and excluded from these incremental counts.
