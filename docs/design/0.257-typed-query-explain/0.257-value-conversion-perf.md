# Accepted-schema filter conversion: ownership and accounting

This slice-10 checkpoint removes repeat copying of unchanged typed-filter
text/blob scalars and recursively unchanged collections. One shared converter
returns a short-lived borrowed-or-owned result; no borrow enters a cache or
retains accepted-schema authority. Converted lists allocate separately at their
first changed element. Rejected conversions leave the full original value
unchanged, while failed work remains charged to the current request.

## Accounting contract and remaining coverage

- Conversion and materialization visits consume `NestedValueSteps`.
- Scalar text conversion charges an input-byte allowance to
  `PredicateExpressionSteps`, including rejected text. This is not a proof of
  linear parser cost or complete parser-internal instruction accounting.
- New list backing storage, borrowed prefix/suffix copies, hex output buffers
  and loose enum-label copies charge `TemporaryBytes` before allocation.
  Unchanged text/blob collections introduce no second vector or element copies.
- Hex length rejection precedes allocation; malformed digits may reject after
  allocating a buffer and still consume its charge. Subaccount parsing charges
  the same shared decoder's temporary buffer even though its final value is fixed-size.
- Grouped HAVING propagates the shared converter's errors without treating
  exhaustion as a conversion miss. Its established per-element fallback
  semantics remain distinct from whole-list typed-filter conversion.

This does **not** complete schema-directed allocation accounting. Big-integer
parsing/cloning/encoding, other scalar parser internals, deeper accepted-catalog
normalization and copying an unconverted grouped-HAVING element remain open.
The existing counters describe cumulative requested construction, not live heap,
allocator overhead or a complete stack-safety proof. Remaining SQL/CASE copies,
predicate work and traversal qualification still belong to slice 10.
