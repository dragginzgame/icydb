# Request-metered normalization scope construction

Date: 2026-09-08. Active release: 0.257.1, preparation slice 10.
Baseline: the preceding [qualifier candidate](0.257-qualifier-move-perf.md),
not published 0.257.0.

## Scope and qualification

Preparation carries the existing request work through ordinary, bound and nested
SQL normalization. Exact/prefix UPDATE policy and resumable UPDATE start open
preparation segments on their existing mutation request scope. No new budget,
request root, optional accounting path or query mode is introduced.

Scope construction charges vector backing, candidate visits, source-byte search
allowance and copied text before allocation. It reserves the four/six candidate
slots once and preserves candidate order and duplicates. Warm concrete commands
still skip preparation. Initial statement cloning, classification, expression
traversal and alias replacement are not fully metered by this change.

119 focused native tests pass: SQL lowering (42), session preparation/cache and
bindings (44), UPDATE policy (26), and input admission (7). New tests cover exact
scope work/backing limits, retry accumulation, nested statements, cold/warm and
bound preparation, and both UPDATE policy classifiers. Formatting, core clippy,
read-admission invariants/fixtures and whitespace checks pass. A test-only String
argument mismatch was fixed before the final runs. Full repository suites are
user-owned; end-to-end mutation-job publication rejection qualification remains
part of completing normalization, not a claim made by the classifier tests.

The unchanged frozen native probe uses the canonical SQL-perf actor with
WasmRelease/LocalTest settings and PocketIC 16. Aliased queries cover three
distinct values, each compiled then immediately reused. Literal-only controls
cover four arithmetic operators and three values, also compile/hit pairs.
Each call returns six rows; deterministic settling ticks are outside the cycle
interval. Local counters and whole-update cycles are reported separately.

Artifacts/logs: `/tmp/icydb-scope-budget.p8DtlR/`. Eight qualification runs cover
both matrices, baseline/candidate and frozen replay. Both isolated local servers
are stopped after their runs. This does not add production performance probes.

## Matched results

| Workload / phase | Baseline cycle median | Candidate cycle median | Delta |
|---|---:|---:|---:|
| Aliased compile | 18,828,520 | 18,832,598 | +4,078 (+0.02166%) |
| Aliased hit | 18,146,678 | 18,145,341 | -1,337 (-0.00737%) |
| Literal-only compile | 18,080,378.5 | 18,080,383.5 | +5 |
| Literal-only hit | 17,608,372 | 17,608,372 | 0 |

These are independent medians, not universal performance estimates. Individual
aliased compile cycle deltas are +3,189/+5,246/+4,078; hits are 0/-241/-1,337.
Every literal-only compile adds five instructions and cycles; every control hit
is unchanged. Thus the normalizer fast path and concrete-cache bypass remain
effective in this workload.

Aliased local instruction medians change from 4,991,534 to 4,996,499 on compile
and 4,470,227 to 4,229,556 on hits. The larger hit-local changes are not equivalent
whole-message speedups: phase/page-charge distribution still affects the local
window. No individual positive local delta crosses the existing joint review
threshold of 250,000 instructions and 3%. Earlier shape-specific review flags
remain separate and are not closed by this measurement.
