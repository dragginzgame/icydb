# Request-metered scalar clause construction

Date: 2026-09-09. Active release: 0.257.1, preparation slice 10.

## Scope and ownership

Dynamic/typed scalar intent construction reserves known-length ORDER BY and
selected-field vectors once, charging destination backing before allocation.
The expression copier's existing text/vector helpers now serve these clauses
as well. Explicit order operands, selected names and implicit accepted-primary-key
order names consume the current request's preparation budget. Complete clauses
move into the existing intent setters. Three incremental ordering helpers are
removed, with no replacement compatibility path. The remaining field-selection
convenience is limited to its SQL consumers.

Authored ordering, duplicate projections and absent ordering are preserved;
pagination still obtains its implicit order from accepted schema authority.
No new public API, resource counter, cache mode or execution route is introduced.
Grouped clause vectors, group-key resolution and downstream planner/cache work
remain open; this is not typed `.explain()` completion.

Incremental complexity: ten Rust files, approximately +10 production and +150
test lines, plus five documentation files. Helpers move rather than duplicate;
one owned order-spec handoff replaces the append flow. Implementation shape is
simpler despite the additional fallible checks and regression coverage.

## Qualification and exclusions

70 all-feature focused tests and six SQL-free copier tests pass, including
exact vector budgets, first rejected allocation, duplicate/order preservation,
public/trusted cold/warm rejection, cumulative request retries, unchanged cache
residency and zero row execution on exhaustion. Focused all-feature test-target
Clippy, formatting, read-admission invariants and whitespace checks pass.

Initial cargo checking exposed unused incremental ordering helpers; these were
removed before the passing lint gate. Two isolated PocketIC servers were started
and stopped by the governed wrapper. Full suites and whole-message cycles remain
unrun. No application edits, Cargo version changes or lockfile edits were made
for this change.
