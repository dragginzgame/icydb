## C1 — explicit scope decision

**Accepted by the user on 2026-09-17.** Both C1-N and C1-M are deferred with
the limitations below explicitly recorded, subject to C2. Preserve existing limits and checks. Do not claim
that 0.257 completely bounds every preparation allocation or guarantees
mid-operation interruption before an IC instruction limit.

### C1-N — complete shared normalization admission

Defer further complete work/scratch admission for predicate simplification,
canonicalization and sorting, including the normalization-specific write/replay
propagation previously approved for investigation. Authored query limits remain
depth 128, 4,096 nodes and 2 MiB; schema/parser and existing request checks remain.
These are not derived-work proofs. Replay correctness tests do not establish
a replay resource ceiling.

Reason: blanket and screened allowance proposals failed useful-input admission;
changing the shared owner affects durable replay error semantics. No new failure
warrants silently widening recovery work. Reopen on a reproduced admitted
workload exhausting resources here, a stronger interruption requirement, or
an approved useful boundary contract. Keep one semantic owner.

### C1-M — aggregate accepted-metadata preparation

Defer a complete database-wide construction/work guarantee beyond maintained
per-entity admission and current root validity/publication checks. This includes
cold root compilation, resolver scratch and grouped static metadata assembly.
A small query can still incur preparation of many entities.

Reason: entity-level admission and copy removal are qualified; a universal
database-wide budget is not. Do not invent another cache or schema profile to
declare completion. Reopen on a reproduced cold-start/query resource failure,
materially larger supported schema scale, or a requirement for a hard aggregate
construction bound. C2 samples maintained scale, not arbitrary database size.

Any reopening requires its bounded implementation contract to be agreed before
coding. Generic continuation must not authorize an unlimited redesign. These
decisions do not weaken existing runtime checks.

## C2 — one integrated qualification

One reviewable verification outcome using maintained actors/tests; no production
optimization or new policy. Freeze source, locked inputs, Rust/toolchain, actor
features and any comparison baseline in the receipt.

| Fixed case family | Checks |
| --- | --- |
| Scalar point / indexed range / IN; grouped aggregate | Cold/warm typed explain, logical SQL parity where available, matching ordinary-read results; no result-row execution by explain. |
| Authority and reuse | Warm same-authority reuse, accepted-root/binding change, index evidence unavailable-to-ready, ordinary cardinality updates permitting reuse. No forced-reoptimization promise. |
| Admission and retention | Repeated calls under one request root, lowered-budget rejection, over-retention ineligibility without partial publication, render rejection preserving ordinary identity. Existing errors/caps only. |
| Schema / payload scale | One maintained multi-entity actor cold/warm, existing per-entity projection boundary and one large admitted predicate/operand case. No open-ended Cartesian product or new application fixture. |

Reuse existing lifecycle, prepared-explain, ordering, codec and cache tests.
Add a focused test only for a concrete uncovered assertion. Distinguish executed
cases from existing receipts. Record whole-call IC instructions/cycles and raw
Wasm for representative actor cases, not native timing or kernel extrapolation.
Use existing gates; missing measurements stay unmeasured and require an explicit
resolution before a closeout verdict.

Exit: semantic/authority/no-row-execution checks pass; rejection preserves state
and error categories; admitted inputs remain useful under maintained gates;
costs and limitations are reported honestly. Finite samples do not prove a
universal preparation bound. Previously accepted diagnostic cost trade-offs
remain accepted, not silently tightened or relabelled as passing.

If a case fails, report its reproducer, violated invariant and smallest repair
before separately approving a repair item. Performance differences do not
automatically open another optimization chain.
