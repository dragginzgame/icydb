# Owned SQL identifier normalization

Date: 2026-09-08. Active release: 0.257.1, preparation slice 10.
Baseline: the preceding [phase-instrumented candidate](0.257-aggregate-phase-perf.md),
not published 0.257.0.

## Ownership change

Field/path normalization consumes its segment vector instead of borrowing a
slice and cloning every retained String into a new result. After removing the
same longest matching qualifier, it moves the root string and retains the
remaining segment vector. Plain field identifiers retain their input string.
Scope matching, case-insensitivity, nested-path shape and empty-path behavior
are unchanged. No new owner, runtime mode or normalization fallback is added.

Compacting the vector still moves String handles. Retained vector capacity can
exceed the remaining suffix length; this is not a promise of minimum retained
capacity. Initial splitting, scope candidate construction, qualifier joins,
alias expansion and their accounting remain separate work. This removes
unnecessary copies rather than claiming normalization is now fully metered.

## Measurement contract

The new native probe uses the unchanged phase-instrumented SQL-perf actor,
canonical WasmRelease/LocalTest configuration, SQL and Candid enabled. One fresh
six-row fixture executes an aliased query with qualified SELECT, WHERE and
ORDER BY fields; three distinct literals each compile and immediately repeat
for a concrete-command hit. Every result contains six projected rows and each
hit equals its preceding compile result.

Counter readings retain request readiness/completion as well as the local read
sample. Whole-update cycles are measured separately, with deterministic settling
ticks outside each interval. Phase/page-charge caveats from the baseline receipt
still apply. The query exercises identifier normalization, not just the
already-local canonical fast path. Nested-field performance is not qualified by
this alias-only actor workload. No actor instrumentation changes in this step.
