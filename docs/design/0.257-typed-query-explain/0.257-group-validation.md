# Borrowed grouped-key validation

Date: 2026-09-09. Active release: 0.257.1, preparation slice 10.

## Outcome and boundary

Grouped structural validation previously called the retained-key resolver for
each declaration, compared its root slot and identity, then dropped the key.
Direct keys copied a field label and accepted type metadata; path keys copied
the diagnostic label, root name and segment vector/strings. Those temporary key
constructions are removed from validation.

GroupFieldRef now checks current accepted eligibility and identity through
borrowed data. Direct identity remains a slot identity; a dotted label cannot
masquerade as a direct key. Paths retain exact root and segment spelling and
current accepted nested-key eligibility. The existing eligibility helper remains
the semantic owner. Insertion and duplicate validation share one borrowed
identity comparator instead of separate owned/borrowed comparisons.

The check deliberately does not compare or replace retained type metadata or
the group-canonical flag: the prior validation compared only accepted key
eligibility, root slot and identity. The planner's existing rebinding still
refreshes execution metadata. Unknown and duplicate key diagnostics keep their
roles and positions; failed validation never substitutes an identity.

## Remaining accounting

This change removes work rather than adding a second metered key resolver.
Retained-key copying and duplicate-comparison accounting remain unfinished.
FieldSlot construction is also used by covering and aggregate projection;
GroupField construction is used by logical rebinding and SQL projection. The
shared planner consumers do not yet receive PreparationWork. That request
authority must reach the owning pipeline before retained construction can be
hard-cut consistently. No unmetered fallback for exhausted preparation is added.

This does not close preparation slice 10 or expose `.explain()`. Planner/cache
bounds and diagnostic construction/rendering remain prerequisites.

## Qualification

The new test compares the borrowed check with maintained current key resolution
across direct and path-aware representations, wrong slots, mismatched path
roots/segments, empty/missing path components and changes to accepted nested
leaf types. A current accepted slot change rejects a previously valid retained
key. Existing session, fingerprint, grouping and accepted-schema tests protect
successful results and error contracts.

87 focused all-feature tests and the new SQL-free parity test pass. Initial
focused Clippy found two warnings in the other session's sparse-index work
(boolean simplification and test-function length), not in this change. Those
files remained with their owner, who corrected the warnings. The required
repository lint gate and focused recheck now pass. Formatting, read-admission
invariants and whitespace checks also pass.

Incremental complexity: three Rust files, approximately +20 production and +86
test lines, plus four documentation files. Explicit borrowed checks add source
while eliminating temporary owned keys and converging identity comparison.

Raw Wasm, gzip, defined functions, instructions and cycles are unmeasured for
this handoff: concurrent planner-eligibility edits prevent clean attribution to
this change. Previous receipts describe their frozen subjects, not this source
candidate. A matched measurement after concurrent work settles is a follow-up;
fewer copies alone do not establish a net speedup or smaller Wasm.

Full suites were not run. No local network was started or stopped. No application,
Cargo version or lockfile edits were made for this change. The sparse-index bug
fix and its documentation were left intact.
