# Request-metered grouped clause containers

Date: 2026-09-09. Active release: 0.257.1, preparation slice 10.

## Scope and ownership

Typed/dynamic and SQL preparation construct complete grouped key and aggregate
vectors before moving them into shared intent. A charged name scan selects the
existing direct/path-aware key representation before reservation, avoiding
promotion of a direct prefix when a later key is a path. The existing accepted
key resolver and identity/deduplication code are reused unchanged. Aggregate
operands move through the existing raw-shape conversion. One reservation helper,
extracted from the existing copier, charges known backing before allocation.

Incremental frontend append methods are removed in place. Low-level key
insertion remains needed for resolution/rebinding and is not a legacy fallback.
No new semantic authority, execution mode, cache policy or public API is added.
Fourteen Rust files add approximately 40 production, 190 test and 30 audit-probe
lines; five documentation files complete the handoff. The construction flow is
simpler, with additional fallible reservation checks.

Reservation uses authored key count, including duplicates. Deduplication retains
the first accepted identity and order, but duplicate-heavy clauses can leave
spare capacity. Existing cache accounting counts that capacity. Avoiding growth
is not a claim that every query allocates fewer bytes.

This closes container construction only. Recursive accepted-kind copying in
FieldSlot, path/name payload copying in GroupField, duplicate-comparison work
and downstream rebinding/planning remain open. No second key resolver was added
to hide that shared-owner work. This is not `.explain()` closeout evidence.

## Matched measurement

Artifacts and logs: `/tmp/icydb-group-clause.IaYzdt/`.
The maintained SQL-free `one_entity_dynamic_query` actor gains a grouped empty
query probe. That identical probe is present in both baseline and candidate;
the baseline was captured before library edits. Consequently this comparison
does not attribute the probe's newly reachable grouped execution code to the
container change. The actor must not be compared directly with the earlier
scalar-only measurement subject for incremental attribution.

Both artifacts use Production/WasmRelease, SQL off, Candid export on, Rust
1.98.1 (`48a229cea`, LLVM 22.1.8), wasm-opt 132 and lockfile SHA-256
`fc5a5743e57a4f83a13ee041eabff82195a8768c965dd5a0820de9626766daf2`.
Source revision is `6e60aaf85ee51d3e414f05248e2b0384d6eac6b8`, dirty in both
reports; frozen artifact hashes distinguish the subjects. Inputs stayed frozen
during each build. The same native probe binary installs each exact Wasm.

Each probe performs 200 reads per shape within one request, including initial
planning and repeated warm work. Grouped reads use one direct key and COUNT on
an empty entity. Two baseline and two final candidate runs produce identical
repeats, zero failures and zero result rows. These are local instruction windows,
not whole-message cycles or isolated compiler costs. Mixed path keys and
populated grouping have focused semantic coverage; their costs and larger
clauses are not benchmarked here.

candidate only. This correction adds no new query route or runtime mode.

## Qualification and exclusions

102 focused all-feature tests pass across preparation, grouped containers,
session reads, fingerprints and cache/cursor controls. Nine copier/group-key
tests pass without SQL. New tests cover exact reservation, rejection before
symbol resolution, direct/path representation parity, duplicate keys and
aggregate order, public/trusted cold/warm exhaustion, cumulative retries,
unchanged cache residency and zero row execution on rejected construction.
Focused core, audit actor and integration-probe Clippy, formatting,
read-admission invariants and whitespace checks pass.

An initial test invocation supplied multiple Cargo filters and was corrected
to a focused native-binary selection. New test authoring also needed the current
query-field diagnostic accessor and a larger explicit fixture grouping budget
for two aggregate outputs; production resource limits were not changed. All
final selected tests pass. No Clippy failure occurred.

Three isolated PocketIC servers were started and stopped by the governed
wrapper (baseline, initial candidate and corrected candidate). Full suites and
whole-message cycle measurements remain unrun. No application, Cargo version
or lockfile edits were made for this change.
