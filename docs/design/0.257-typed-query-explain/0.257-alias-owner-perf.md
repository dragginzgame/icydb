# Shared projection-alias normalization

Date: 2026-09-08. Active release: 0.257.1, preparation slice 10.
Baseline: the preceding [normalization-scope candidate](0.257-normalization-scope-perf.md),
not published 0.257.0.

## Change and contract

ORDER BY and HAVING had identical projection-alias resolvers. Both now use one
resolver with the same case-insensitive, first-match lookup and one copied
replacement expression. Recursive scalar traversal visits original children
only: it does not expand aliases inside a replacement or aggregate input.
Clause-specific normalization order is unchanged.

HAVING now normalizes and resolves one clause before proceeding to the next,
removing an intermediate collect and its separate traversal. This is a source
flow simplification, not proof of one fewer heap allocation: Rust may already
reuse consumed vector backing. The change adds no modes or rejection policy.
Actual traversal and copied-subtree accounting remain unfinished; this cleanup
gives that work one alias lookup owner rather than two.

## Qualification

88 focused native tests pass: SQL lowering (44), and session preparation/cache,
bindings and accepted authority (44). New tests cover field, scalar expression
and aggregate aliases, case-insensitive matching, unmatched fields, clause
order, non-recursive replacements and opaque aggregate inputs. Core and probe
clippy, formatting and read-admission invariants/fixtures pass. Full repository
test suites remain user-owned.

The new audit-only probe runs ORDER BY aliases and grouped HAVING aliases on
three distinct values each, followed by immediate concrete-cache hits. Every
query returns six rows; compile/hit results are equal. It reuses the existing
phase-instrumented actor and canonical WasmRelease/LocalTest settings. Cycles
cover whole updates, with settling ticks outside the interval; local instruction
windows retain request-ready and request-complete boundaries.

Local artifacts and logs: `/tmp/icydb-alias-owner.PUXgMs/`.

The incremental change touches seven files: one production owner, native tests,
an audit probe and four documentation files. Production shrinks 34 lines;
tests/probe add 121 lines. One lookup owner and one HAVING traversal replace the
duplicate flows. Earlier dirty-worktree work, applications and Cargo versions
are untouched. No commits or pushes are performed.

## Matched results

Baseline and candidate each pass the 12-record matrix and an exact frozen replay.
Both isolated PocketIC servers are stopped after qualification.

| Shape / phase | Baseline cycle median | Candidate cycle median | Delta |
|---|---:|---:|---:|
| ORDER BY compile | 19,062,377 | 19,062,191 | -186 (-0.00098%) |
| ORDER BY hit | 18,194,311 | 18,194,311 | 0 |
| HAVING compile | 18,475,956 | 18,475,424 | -532 (-0.00288%) |
| HAVING hit | 17,765,425 | 17,765,425 | 0 |

Every individual ORDER BY compile saves 186 instructions/cycles; each HAVING
compile saves 532. All hit instruction/cycle results are identical. There are no
positive local-counter review flags in this comparison. Prior shape-specific
flags remain separate. These tiny workload-specific savings are not a general
database speedup.
