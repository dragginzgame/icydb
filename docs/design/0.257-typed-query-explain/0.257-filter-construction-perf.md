# Typed filter construction: accounting cost

Slice 10 now charges field-name copying and introduced planner-expression
backing storage at the existing typed filter constructors. It does not change
accepted-schema coercion, canonicalization policy, cache identity or query results.
Text/collection lowering shares one construction flow instead of repeating seven
operand-building branches. This is additional safety accounting, not a claimed
speedup or completion of the remaining preparation work.

## Measurement contract

The baseline is the completed metered sort-key reuse checkpoint, **not** the
unmetered canonicalizer or 0.256.1. Reuse the exact audit actor, isolated-workload
probe and canonical Wasm release configuration from the
[preceding receipt](0.257-canonical-wasm-perf.md): Rust 1.97.1, PocketIC 16.0.0,
Binaryen 132, local-test SQL/Candid features, identical six-row fixtures and
balanced SQL at widths 4/16/64/128. No harness, endpoint or feature changes enter
this comparison. Each workload has a fresh fixture; 64 deterministic rounds
settle work before each measurement interval.

Typed/structural calls construct filters in the actor, prepare against accepted
schema and execute rows. The local instruction window excludes Candid decoding;
cycle deltas cover the whole update. SQL cold query instructions and first-update
cycles are separate observations; warm SQL updates retain command-cache savings.
Report medians of the three typed/warm updates, including the initial typed call
and its distinct cache/allocator state. These are end-to-end inner-call metrics,
not a preparation-only microbenchmark or a steady-state-only sample.
The frozen baseline rerun reproduces all 36 records from the preceding receipt;
the candidate rerun reproduces its first 36 records exactly. The review flag
therefore persists across matched replays and is not dismissed as timing noise.

All cold SQL instruction and first-update cycle samples match the baseline.
Warm SQL cycle medians change by at most 0.017%; some instruction samples differ
after typed calls in the same fixture. Compact typed IN adds exactly 904
instructions/cycles at each measured width, consistent with its constant-sized
field/argument construction rather than per-member expression expansion.

**Open performance-review flag:** 16-term typed AND increases by 275,370
instructions (+4.655%), crossing both the existing 250,000-instruction and 3%
review thresholds. Its cycle increase is 35,512 (+0.240%). Neither the smaller
cycle increase nor other improving instruction samples waive that threshold.
The measurement includes cache/allocator-history effects and does not attribute
all instruction movement solely to counter arithmetic. Further isolation or an
explicit cost acceptance is needed before declaring the cost gate clean.

## Validation and remaining work

192 focused native tests pass: 179 all-feature and 13 SQL-free, including
constructor-limit, cumulative cold/warm public/trusted rejection, semantic
parity, canonical model/fingerprint/cursor and intent coverage. The maintained
three-lane lint gate, focused all-feature library/test lint, formatting and
whitespace checks pass. Three complete Wasm matrix runs pass their functional
checks; the numerical performance-review flag above remains open.

Full-suite validation stays user-owned. Manual native timing selections were
not run; no native latency claim is made. The two measurement-owned PocketIC
servers were started/stopped by the existing wrapper; no existing local network
was touched. No application, Cargo version, commit or push changes were made.
Remaining schema-directed conversions, SQL/canonical copies, projection work
and traversal qualification stay within unfinished slice 10.
