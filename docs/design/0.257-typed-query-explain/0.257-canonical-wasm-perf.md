# Canonical ordering: matched Wasm cost qualification

This is a slice-10 comparison against the immediately preceding **metered**
canonical sorter, not against 0.256.1 or an unmetered normalization path.
The previous native binaries cannot establish an isolated historical Wasm
baseline; this run freezes the current metered module before changing ordering.

## Change and trade-off

Canonical sorting now constructs each label once per term and constructs a typed
Debug key only when labels tie, also at most once per term. Emitted text bytes,
requested output/table allocations and comparisons still charge the existing
request before that work. The stable, abortable index merge and final operand permutation are
unchanged. Failure never substitutes a partial key or ordering, and operands
are not moved until the sort succeeds.

One temporary key table replaces repeated string construction. Its table and
strings are charged and discarded before permuting the expression operands;
nothing enters a session or compiled cache. This retains more keys concurrently
than the comparator-local implementation, in exchange for less cumulative
construction. It is not an allocator peak-memory measurement. There is no new
normalizer, execution route, budget root, feature option or persisted state.

## Matched configuration and workload

- Actor: maintained `sql_perf`, identical source and fixtures in both modules,
  with one bounded test-admin-only application-built filter measurement.
- Cargo `wasm-release`: opt-level `z`, fat LTO, one codegen unit, aborting panics;
  maintained local-test features, SQL enabled, Candid export enabled, normal
  release path trimming and canonical Binaryen 132 post-link flags.
- Rust: `1.97.1 (8bab26f4f 2026-07-14)`; PocketIC server/client `16.0.0`, default
  application subnet. No live-network cycle-price conversion is inferred.
- AND, OR and compact IN: 4, 16, 64 and 128 reverse-ordered values on `age`;
  select `id`, order by `id`, limit 100, six maintained fixture rows. AND uses
  nonnegative-age lower bounds; OR and IN use equality to the listed values.
  OR/IN return zero rows at widths 4/16 and six at 64/128; AND returns six.
- SQL syntax is balanced to isolate width without exceeding the input-depth
  limit. The first flat 128-term SQL attempt correctly rejected and is excluded.
- Cold SQL query: parse, compile and execute without persisting query-call cache
  changes. First SQL update: warm that same command and record whole-call cycles.
  Three subsequent warm SQL updates and application-built typed/structural
  updates record local instructions and whole-update cycle-balance deltas.
- Typed timing includes constructing the filter/query, accepted-schema
  preparation, planning and row execution. SQL timing includes session lookup
  and execution, but excludes Candid decoding. These are end-to-end inner-call
  samples, not normalization-only instruction measurements.
- Drain 64 deterministic rounds before each measured interval, without manually
  advancing time or enabling auto-progress. Setup/background work and deferred
  query charges are outside the cycle intervals. Whole-update cycles still
  include ingress, response and platform overhead; they are not interchangeable
  with the inner instruction counter.
- Each workload uses a fresh fixture so earlier shapes cannot change its
  allocator/cache history. Earlier shared-history runs are investigative only:
  they showed a 4.1% IN instruction regression. In isolated fixtures, every IN
  sample matches exactly between artifacts, including both instruction and
  cycle counts; this resolves the apparent direct IN regression as a
  cross-workload history effect. It does not prove all mixed histories identical.

The ignored `preparation_wasm_cost_matrix` integration probe is the maintained
reproduction entry point. With no override it builds the canonical actor;
`ICYDB_PREPARATION_WASM` accepts a frozen audit module for matched comparisons.
This is harness-only artifact selection, not a runtime execution mode. The
existing prebuilt-fixture installation owner is reused instead of introducing
another build or network owner.

Warm literal SQL retains its concrete-command compilation savings: median
instruction counts are unchanged except 16-term AND (+77,579 / +1.83%); median
cycle changes across all cells stay within 0.023%. Cold and warm SQL IN samples
match exactly at every width. The isolated matrix has no increase exceeding
both the maintained 250,000-instruction and 3% material-regression thresholds.
This is not a promise of identical mixed-workload allocator history, nor a
bound-parameter performance qualification.

The practical gain is concentrated in larger boolean groups. Four-term typed
AND instructions rise 0.26%, despite a small cycle reduction; compact IN does
not enter this sorter. No general small-query or IN speedup is claimed.

## Qualification boundary

Successful canonical-model/label, fingerprint and cursor identity remain
unchanged. Direct tests cover typed Debug ties, budget failures without operand
reordering, repeated comparisons retaining work charges without reconstructing
text, and small-stack rejection cleanup. SQL execution includes retained syntax,
changing bindings and current accepted authority through the existing focused
tests.

Validation: 524 focused native tests pass (460 all-feature, 64 SQL-free), plus
four complete isolated Wasm matrix runs. The maintained three-lane lint gate,
focused all-feature core/test and audit-actor lint, probe lint, formatting and
whitespace checks pass. Initial harness name/length lint errors were corrected;
the rejected flat-SQL fixture and unsettled/shared-history runs are excluded
from final figures. Full repository/workspace suites remain user-owned. Local
PocketIC servers were started and stopped only by the measurement wrapper;
no existing ICP network, application, Cargo version, commit or push was changed.

Complexity relative to the frozen metered checkpoint: nine files, +36 net core
Rust lines, +33 audit-actor lines and +180 test/harness lines, plus documentation.
Repeated rendering is removed and one local key table is added; semantic and
execution owners are unchanged. The implementation is less repetitive, with a
small explicit memory-for-work trade-off rather than a second execution flow.

Slice 10 remains open for the uncharged construction/classification owners named
in the preparation preflight. This optimization does not establish complete
allocation or stack bounds, or authorize starting slice 11 or typed explain.
