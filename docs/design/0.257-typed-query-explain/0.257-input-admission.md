# 0.257 — Shared query input admission

Status: typed/dynamic and SQL boundaries complete in slices 8–9.
Planner-produced work/resource qualification remains slice 10.

## Decision and ownership

The user approved shared bounded preparation, rather than a diagnostic-specific
predictive layer. Slice 8 lands the typed/dynamic boundary, slice 9 integrates
SQL, and slice 10 charges preparation work at actual owners. This preserves
completed normalization work and gives each frontend's ownership/error paths a
reviewable end-to-end handoff.

Demonstrated need: typed preparation clones and recursively lowers unchecked
caller filters, and consuming rejection can recursively drop an arbitrarily deep
request. The simplest alternative, checking only inside explain, would leave
ordinary reads unsafe and duplicate admission. The canonical owner is query
input admission, below the typed wrapper and before structural conversion.
State-space delta: one fixed policy and typed rejection diagnostics, no mode,
configuration, retained proof, schema authority or execution route.

## Fixed policy

- Maximum authored expression/value depth: 128, root at depth 1. Values in a
  filter or expression continue the containing expression's depth.
- Maximum visited input nodes: 4,096 across the whole request, including values,
  field/path names, projection/group/order entries and aggregate children.
- Maximum variable input payload: 2 MiB across the whole request, including
  identifiers, text/blob bytes, big-integer magnitude bytes and cursor text.
  Fixed-width scalar storage is covered by the node ceiling. Allocated capacity
  is not counted; this is a content limit, not retained-cache accounting.

Walk borrowed data, charging before descent; never clone, encode or format it
to decide admission. Walk siblings incrementally, without allocating a frontier
proportional to their count. Inspect all supplied branches before simplification.
Each invocation checks the request, including warm/reused execution paths.
Limits are schema-independent; accepted-schema normalization remains the sole
semantic authority after input admission succeeds.

Owned dynamic-request cleanup must detach recursive filter, expression and value
children before dropping their parents, including rejected requests. This covers
consuming typed terminals through their existing DynamicQuery owner. Caller-side
construction, explicit Clone/Debug on unadmitted DTOs, standalone DTO destruction
and deserialization are outside this execution-boundary guarantee. Cleanup still
takes work proportional to the already-owned input; it is not bounded by the
admission walk's early-exit budget or a decoder allocation proof.
Iterative cleanup can use temporary heap storage for outstanding children; it
does not promise a fixed allocation or cycle ceiling for disposing of input that
the caller already constructed beyond the admission limits.

These are input limits, not a proof of all planner-produced depth, allocation,
normalization work or stack safety. In particular, canonical left association
and candidate expansion remain obligations of shared preparation slice 10.
CASE's deterministic rewrite budget remains separate from request exhaustion.

## Qualification

### SQL integration decision (slice 9)

Replace the lowering-only depth walker with one SQL input adapter over the
shared budget. Check parsed SELECT/DELETE/INSERT/UPDATE/EXPLAIN and introspection
inputs before preparation and on warm compilation ingress. CHECK's SQL expression
syntax uses the same input floor; DDL semantic admission remains catalog-owned.
Parser byte/token/recursion limits remain separate and use the same depth constant.
Parsing may allocate within those lexical limits before whole-query admission.

Keep the existing 64-slot/64-KiB scalar binding contract. Shared input accounting
also counts effective operand copies at every placeholder occurrence, including
BETWEEN duplication, before substitution. Do not hash bindings or cache concrete
bound commands. Missing-slot and scalar-family checks stay typed and payload-free.

Demonstrated ownership gap: parser errors can destroy partial expression trees
before a dispatch exists, and postfix parsing clones its accumulated left side.
Use one iterative SQL-expression destructor rather than dispatch-specific cleanup;
remove the avoidable postfix clone and admit BETWEEN operands before its required
copy. Owned normalizers must transfer children in place instead of destructuring
a Drop-owning enum. This is direct ownership propagation, not a new normalization
policy or compatibility route. Reuse the existing runtime-value disposal walk
from the value owner. State-space delta: no new mode or authority; one parser
error carrier preserves the existing shared input-limit diagnostic.

The cleanup guarantee remains stack-oriented, not an allocation/cycle ceiling
for arbitrary already-constructed internal ASTs. Planner-produced expansion,
including alias substitution, remains slice 10 rather than an input-size proof.

SQL qualification passes exact node/payload and bound-value depth boundaries,
cumulative statement-family accounting, BETWEEN pre-copy admission and retained
dispatch A/B/A execution with intervening oversized-binding rejection and no
reparse. A 512-KiB native thread rejects/destroys 10,000-level postfix syntax,
partial parser errors and a 20,000-level runtime value attached to an internal
SQL expression. Existing SQL, fingerprint and cursor regression checks pass.
No IC/Wasm stack or performance measurement is inferred from these tests.

### Typed boundary qualification (slice 8)

Test exact depth/node/payload boundaries, cumulative fields and values, a large
IN list, a discarded invalid branch, and deeply nested rejected owned requests
on a deliberately small native stack. Test ordinary session execution, not only
the private walker. Preserve admitted results/fingerprints; no compatibility
path or cursor version change. SQL qualification is separate from these typed
tests; IC/Wasm measurements remain pending. No performance improvement is claimed merely
from removing the pre-lowering filter clone.

Qualification passes: eight direct input/cleanup tests in both SQL-free and
all-feature builds, stored-row cold/warm public/trusted rejection coverage, and
