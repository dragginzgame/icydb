# IcyDB 0.257 — Typed Query Explain

Status: forward design requested after the 0.256 closeout and ICYDB-022 repair.
This document does not start runtime implementation. Delivery state and open
gates belong to [the tracker](0.257-status.md).

## Outcome

Application code can inspect a typed query's logical access plan without
enabling SQL, constructing a SQL string, or executing the query. Reuse the
existing accepted-schema planner and `ExplainPlan`; do not create a parallel
planner, diagnostic DTO family, or SQL translation adapter.

Proposed API, not yet available:

```rust
let plan = db.query::<Planet>()?
    .order_by(asc(Planet::ID))
    .limit(3)
    .explain()?;

let text = plan.render_text_canonical();
```

The terminal consumes `Query` and returns
`Result<ExplainPlan, TypedOperationError>`. Existing canonical text/JSON rendering
stays separate from planning. Default and no-default-feature consumers must work
without `icydb/sql`. No Candid transport is added.

## Evidence and scope

Inspection baseline: IcyDB `837aa030a` (`v0.256.0`) plus the separately pending
0.256.1 SQL-handler lint repair. That repair changes no planner or query behavior.
Freeze an immutable source baseline again before implementation measurements.

Toko Miner's ICYDB-021 records the application need. Its dirty working-tree
[demonstration](../../../../toko-miner/apps/toko_miner/game_shard/src/database_demo/inspect.rs)
at HEAD `35f90ca7e40eca45f98c2869af7283e90769f2c6`, pinned to IcyDB `v0.255.1`,
constructs fixed `EXPLAIN SELECT` statements for accepted catalogue entities.
This is source evidence, not downstream adoption or build qualification.
The [upstream ledger](../../../../toko-miner/docs/upstream/icydb.md#icydb-021-typed-query-plan-inspection-without-enabling-sql)
owns the application request. Neither application repository is in mutation scope.

Include scalar and grouped logical queries already expressible by typed `Query`.
Do not add aggregation syntax, selected-field typed rows, exact-count explain,
cursor-resume explain, execution descriptors, `EXPLAIN ANALYZE`, tracing, runtime
cost predictions, SQL endpoints, or an application query abstraction.

## Existing owners and converged flow

| Boundary | Existing owner | Required reuse |
| --- | --- | --- |
| Typed syntax and binding | [typed Query](../../../crates/icydb/src/db/query/typed.rs) | Consume its existing request and opaque binding; no generated-model planning. |
| Current authority | [typed binding catalog](../../../crates/icydb-core/src/db/session/write.rs) | Recheck incarnation, accepted identity and binding freshness on every invocation, including cache hits. |
| Structural conversion | [dynamic session queries](../../../crates/icydb-core/src/db/session/query/dynamic.rs) | Reuse `structural_query_from_dynamic_request`; retain schema-directed conversion and existing shape errors. |
| Plan and metadata visibility | [shared cache](../../../crates/icydb-core/src/db/session/query/cache.rs) | Reuse `cached_shared_query_plan_for_accepted_authority_with_catalog` and the existing diagnostic accounting lane. |
| Diagnostic projection and rendering | [ExplainPlan](../../../crates/icydb-core/src/db/query/explain/plan.rs) | Project from a borrowed logical plan, without cloning the complete prepared plan. |
| Existing SQL frontend | [SQL explain adapter](../../../crates/icydb-core/src/db/session/sql/execute/explain.rs) | SQL retains parsing/lowering; any shared bounded logical projection belongs below this adapter. |

The typed facade should only map the existing stale-binding and query errors.
One session-owned, non-generic planning/projection helper owns the operation.
Do not add a public dynamic explain terminal solely to expose that internal seam.
If shared shape validation must be extracted, make both maintained callers use
it; do not copy grouped/scalar terminal checks into a second semantic authority.

Reuse existing bounded plan caching. Do not cache rendered strings or returned
diagnostic DTOs, add cache configuration, or create an explain-specific cache key.
Current validity follows the execution planner's existing invalidation contract;
it does not promise fresh optimization after every cardinality change. The cache
resolves current index visibility and checks retained unavailable-evidence
lifecycle stamps in `cached_cardinality_tiebreak_is_current`. That function does
not invalidate every `ExactAtSelection` plan when counts change. Keep that policy:
explain may report a still-valid previously selected route. Do not add a forced
replan, cardinality refresh, or an explain-specific freshness option.

Warm tests must distinguish an ordinary cardinality update that permits reuse
from schema/index-visibility or unavailable-to-ready transitions that require
the existing invalidation/recheck behavior. Compare diagnostics with the ordinary
planner under the same cache state, not an independently forced fresh plan.
Diagnostic admission still runs on warm calls. Cache retention limits are
not invocation admission limits: an oversized uncached plan can still execute
planning work, so cache rejection alone does not establish safety.

### Protect ordinary query identity and admission

Diagnostic admission limits must not change ordinary query admission, query
fingerprints or cursor identity. A query too large to explain may remain a
valid ordinary query. Bounds rejection must not install a placeholder or
truncated model in a shared cache or fingerprint path, and must not substitute
a common error value into identity hashing. Existing request-budget consumption
from performing diagnostic work is intentional; it is not a change to ordinary
query admission policy.

The [explain fingerprint entry](../../../crates/icydb-core/src/db/query/fingerprint/fingerprint.rs)
uses [shared hash profiles](../../../crates/icydb-core/src/db/query/fingerprint/hash_sections/profile.rs),
including `filter_expr_model_for_hash` and `predicate_model_for_hash`. Inventory
all callers of changed projection/model helpers, not only `.explain()` callers.
Preserve model content and hash profiles exactly. Keep diagnostic admission at
the diagnostic boundary rather than making ordinary identity construction
depend on it; any shared helper change must retain this separation.

Qualification must compare baseline/candidate fingerprints and continuation
signatures for maintained scalar, grouped, parameterized, and typed/SQL parity
fixtures. Include an ordinary query exceeding only the diagnostic ceiling,
and ordinary execution before/after a rejected explain. Use matched authority,
request budgets and state; do not confuse expected global budget exhaustion
with changed query semantics. This is current-contract parity, not an old-format
decoder, compatibility fixture or format-version change.

## Semantic contract

| Input/context | Required behavior |
| --- | --- |
| Valid indexed predicate | Return the current accepted planner's access choice and alternatives. |
| Valid full scan, materialized sort, or absent row limit | Permit logical inspection even if ordinary public execution would reject it. A returned plan is not an execution permit. |
| Unknown field, incompatible value, invalid ordering/grouping | Return the existing typed semantic failure; do not stringify or suppress errors. |
| Grouped query | Preserve group/aggregate declaration order and explicit positive grouped limits. Reuse existing shape validation; do not invent default execution limits for explain. |
| Grouped limits on a scalar query | Reject rather than discard the incompatible configuration. |
| Any supplied `.cursor(...)`, including an empty string | Reject explicitly before conversion. Current structural conversion omits this field; ignoring it would misrepresent the request. |
| Stale binding or changed accepted authority | Reject through the existing adapter contract before returning cached diagnostics. |

The terminal has no continuation or read-set proof arguments. It describes the
logical request before live/exhaustive-page machinery adds total ordering,
lookahead, page limits or a continuation boundary. It does not describe the
specialised exact-count or direct-key terminal. Test parity against the same
logical query, not an execution-shaped page that has been rewritten internally.

Execution-only public admission is not imposed on diagnostics. This does not
waive semantic validation, request work limits, or diagnostic construction bounds.
Do not grow an admission-report DTO or a policy-selection option in this slice.
Document the distinction next to the terminal, not only in implementation notes.

## No row execution and disclosure

Explain must not traverse result rows, invoke typed row decoders, advance a
cursor, publish mutations, or create a new execution scope to reset budgets.
Use current session/request ownership. Planning may inspect accepted catalog,
store/index readiness and maintained cardinality metadata, and populate existing
in-memory plan caches. This is not a promise of zero stable-memory access or zero
lifecycle work at the existing session boundary.
Never scan result rows to manufacture missing cardinality evidence; retain the
planner's existing metadata-unavailable behavior.

Returned plans are informational snapshots, not authority retained for later
execution. Predicates, values, field names and index metadata can appear in their
structured fields or renderings. Do not describe them as redacted or safe for
arbitrary public exposure. Application authorization and response transport stay
application-owned; no redaction mode or generated endpoint is introduced.

## Diagnostic bounds: mandatory preflight

### Renderer contract selected for this design

Choose conservative pre-admission of eventual canonical text and JSON output,
not new fallible public renderers. Before `.explain()` returns, establish checked
upper bounds on both render lengths and relevant intermediate allocations,
including repeated fields, punctuation, numeric/enum formatting, Debug output,
JSON escaping and nesting. Reuse the existing projection and formatter owners;
do not render a large string merely to measure it or implement a second renderer.
Retained bytes alone are not the rendering bound.

This choice is supported by `ExplainPlan`'s private model fields, read-only
accessors, and closed framework-owned rendering representation. It remains
conditional on proving a tractable conservative bound in preflight. The guarantee
applies to plans successfully returned by typed `.explain()` and their unchanged
clones, not every plan produced by internal or other public surfaces. Do not
infer this guarantee for arbitrary extracted subobjects or caller formatting.

The returned DTO remains owned and detached: no session borrow, budget handle,
stored render cache or new budget lifecycle. Repeated `.explain()` invocations
charge the existing request; later formatting allocates at the caller and has a
per-call structural size guarantee, not cumulative session accounting. Repeated
formatting can allocate repeatedly. Preserve the existing `String` return types
and canonical bytes. If conservative expansion bounds require a broad formatter
rewrite, stop and rescope; do not silently switch to a new fallible public API.

### Construction and resource obligations

Current `AccessPlannedQuery::explain()` is infallible and allocates expression
models, projected collections and diagnostic strings. Its canonical renderers
allocate further strings. The SQL endpoint's 3-MiB Candid reply check runs after
encoding and does not bound these allocations; do not reuse it as a construction
proof or introduce Candid merely to measure this Rust result.

The existing [retained accounting](../../../crates/icydb-core/src/retained.rs)
has checked byte accounting and a depth ceiling, with owners for expressions,
predicates and values. Reuse applicable accounting rather than inventing another
generic object walker. It measures retained capacity, not formatter expansion,
allocation peaks or all traversal work; it is not sufficient by itself.

Before production edits, record numerical limits and enforcement owners for:

- Input expression/value depth, visited nodes and bytes, checked before recursive
  conversion/cloning. Caller construction has already happened; no decoding or
  caller-allocation guarantee is claimed.
- Accepted-schema/index candidate expansion and planner-produced structures,
  bounded conservatively before construction or charged during construction,
  not only checked after planning finishes.
- Diagnostic model copies, candidate lists, and string expansion, bounded before
  allocation or incrementally as existing projection/render owners build them.
- Canonical text/JSON output under the pre-admission contract above, including
  escaping, large literal values and Debug formatting. Checking an already-created
  string is not a peak-memory bound.
- Cumulative work for repeated explains sharing one request, including cache hits.

Prefer one fixed policy and existing typed budget resources. Record any genuinely
missing diagnostic code at its current owner; do not match error strings or add
a broadly consumed mode enum. Return a typed failure, never silent truncation.
Depth rejection must also consider error cleanup/drop behavior: do not claim
arbitrary nesting is stack-safe solely because a validation walk is bounded.

Any bounded logical projection needed by both SQL and typed explain must converge
at the existing explain owner; do not maintain two projection implementations.
Inventory non-frontend callers, including fingerprint-related model access,
before changing existing infallible helpers or public renderer signatures.
The implementation technique and exact numbers remain unproven. If bounding this
path requires a general planner/rendering redesign, report and rescope before
implementation rather than quietly expanding this feature.

## Complexity decision

Demonstrated need: fixed application queries currently require SQL solely for
logical introspection. Simplest alternative: retain that opt-in SQL dependency.
Chosen direction: one consuming terminal over existing authorities. State-space
delta: one public terminal, no runtime mode, config, persisted state, cursor
format, endpoint or compatibility path. Diagnostic bounds may require a narrow
fallible handoff at the existing owner; they do not justify a second planner.

## Qualification and cost gates

Before implementation, freeze Rust/toolchain, source, dependencies, features,
actor shapes, workload counts and numerical ceilings. No empirical cost ceiling
has been established for this feature yet; 0.256 clone-removal thresholds are
not automatically applicable.

Measure separately:

- SQL-free actor not calling explain: unexpected decoder/renderer reachability.
- SQL-free actor calling typed explain: incremental capability cost.
- Matched fixed-query actor using SQL explain versus typed explain: actual
  substitution benefit, not an assumed saving from deleting a SQL string.
- A consumer retaining SQL for another reachable operation: incremental typed
  explain cost when the parser cannot be removed. Do not apply the SQL-free
  substitution saving to this actor.

Report raw Wasm bytes first, then defined function count and gzip. Measure cold
and warm planning, allocation count/bytes, and matched IC request cycles where
applicable. Separate planning from rendering/response encoding. Retain ordinary
typed-read controls; no correctness or cost gate may be relaxed after a miss.
Report files/line deltas and execution-flow complexity alongside measurements.

Focused tests must cover SQL-free consuming compilation; scalar/grouped logical
parity with SQL where representable; accepted metadata/index lifecycle changes;
stale bindings; semantic errors; supplied cursors; scalar/grouped misuse;
full-scan inspection versus execution rejection; cold/warm bounds and oversized
input/candidate/rendering cases; unchanged ordinary admission/fingerprints/cursor
identity; and valid-cache reuse versus lifecycle-driven invalidation. Verify
detached rendering after the originating session ends and after metadata changes:
the returned DTO remains a snapshot. Prove no result-row traversal, decoder invocation
or mutation using maintained instrumentation on a ready fixture, without
confusing metadata reads with row execution. Full suites and downstream adoption
remain user-owned.
