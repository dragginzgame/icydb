# IcyDB 0.257 — Typed Query Explain

Status: user explicitly authorized starting 0.257 on 2026-09-08 after reporting
0.256.1 committed and pushed. Initial boolean/membership lowering was subsequently
selected as a bounded prerequisite. The user subsequently approved shared input
and preparation-work limits, followed by bounded diagnostics and fallible rendering.
Delivery state and open gates belong to [the tracker](0.257-status.md).

Delivery order revised with user authorization: logical diagnostic construction
and rendering, then typed `.explain()`, then the unfinished shared preparation
and recovery-safe accounting outcomes. None is dropped; all remain required
for line closeout. Typed explain inherits the shared planner's existing limits
and accounting gaps until those outcomes finish. Do not describe diagnostic
bounds as a complete planning/callback bound. This supersedes earlier statements
that completion of slices 10/11 gates diagnostic or terminal delivery.

## Outcome

Accounting follows the approved
[boundary-based contract](0.257-explain-remaining.md#boundary-based-accounting--2026-09-11):
remove unnecessary work, admit cheaply bounded batches before construction,
and retain incremental checks only where expansion needs them. Complete bounds
do not require observing every internal operation. Diagnostic projection performs no identity hashing; charge-frequency-driven instruction sampling remains a simplification
target, not a pattern to extend. Current authority, ordinary identity, cumulative request
limits and write/recovery safety remain intact.

Application code can inspect a typed query's logical access plan without
enabling SQL, constructing a SQL string, or executing the query. Reuse the
existing accepted-schema planner and `ExplainPlan`; do not create a parallel
planner, diagnostic DTO family, or SQL translation adapter.

Proposed API, not yet available:

```rust
let plan = db.query::<Planet>()?
    .order_by(asc(Planet::ID))
    .limit(3)
    .explain()?;

let text = plan.render_text_canonical()?;
```

The terminal consumes `Query` and returns
`Result<ExplainPlan, TypedOperationError>`. Existing canonical text/JSON rendering
stays separate from planning. Default and no-default-feature consumers must work
without `icydb/sql`. No Candid transport is added.

### Shared preparation limits and diagnostic isolation

The user approved shared bounded preparation after the post-CASE review. Input
limits and preparation-work charges apply to ordinary queries as well as explain;
they are not an explain-specific prediction of planner behavior. For admitted
queries, preserve canonical identity against the completed slice-7 baseline.
Diagnostic-only limits remain isolated as described below. The fixed CASE rewrite
budget remains independent of request exhaustion; never return a partially
normalized or request-budget-dependent canonical expression.

Diagnostic admission limits must not change ordinary query admission, query
fingerprints or cursor identity. A query too large to explain may remain a
valid ordinary query. Bounds rejection must not install a placeholder or
truncated model in a shared cache or fingerprint path, and must not substitute
a common error value into identity hashing. Existing request-budget consumption
from performing diagnostic work is intentional; it is not a change to ordinary
query admission policy.

Diagnostic projection builds only the detached plan DTO. Identity remains at the
ordinary planner/cache/cursor owners, with no diagnostic source adapter or hash
budget lifecycle. Tests compare actual plan fields and canonical reports, and
separately pin continuation bytes before and after successful/rejected projection.

Qualification must compare baseline/candidate fingerprints and continuation
signatures for maintained scalar, grouped, parameterized, and typed/SQL parity
fixtures. Include an ordinary query exceeding only the diagnostic ceiling,
and ordinary execution before/after a rejected explain. Use matched authority,
request budgets and state; do not confuse expected global budget exhaustion
with changed query semantics. This is current-contract parity, not an old-format
decoder, compatibility fixture or format-version change.

## Semantic contract

| Input/context | Required behavior |
| --- | --- |
| Valid indexed predicate | Return the current accepted planner's access choice and alternatives. |
| Valid full scan, materialized sort, or absent row limit | Permit logical inspection even if ordinary public execution would reject it. A returned plan is not an execution permit. |
| Unknown field, incompatible value, invalid ordering/grouping | Return the existing typed semantic failure; do not stringify or suppress errors. |
| Grouped query | Preserve group/aggregate declaration order and explicit positive grouped limits. Reuse existing shape validation; do not invent default execution limits for explain. |
| Grouped limits on a scalar query | Reject rather than discard the incompatible configuration. |
| Any supplied `.cursor(...)`, including an empty string | Reject explicitly before conversion. Current structural conversion omits this field; ignoring it would misrepresent the request. |
| Stale binding or changed accepted authority | Reject through the existing adapter contract before returning cached diagnostics. |

The terminal has no continuation or read-set proof arguments. It describes the
logical request before live/exhaustive-page machinery adds total ordering,
lookahead, page limits or a continuation boundary. It does not describe the
specialised exact-count or direct-key terminal. Test parity against the same
logical query, not an execution-shaped page that has been rewritten internally.

Execution-only public admission is not imposed on diagnostics. This does not
waive semantic validation, request work limits, or diagnostic construction bounds.
Do not grow an admission-report DTO or a policy-selection option in this slice.
Document the distinction next to the terminal, not only in implementation notes.

## No row execution and disclosure

Explain must not traverse result rows, invoke typed row decoders, advance a
cursor, publish mutations, or create a new execution scope to reset budgets.
Use current session/request ownership. Planning may inspect accepted catalog,
store/index readiness and maintained cardinality metadata, and populate existing
in-memory plan caches. This is not a promise of zero stable-memory access or zero
lifecycle work at the existing session boundary.
Never scan result rows to manufacture missing cardinality evidence; retain the
planner's existing metadata-unavailable behavior.

Returned plans are informational snapshots, not authority retained for later
execution. Predicates, values, field names and index metadata can appear in their
structured fields or renderings. Do not describe them as redacted or safe for
arbitrary public exposure. Application authorization and response transport stay
application-owned; no redaction mode or generated endpoint is introduced.

## Diagnostic bounds: mandatory preflight

### Renderer contract selected for this design

User-approved output hard cut (2026-09-11): canonical logical reports describe
planner decisions and already-admitted clause labels, not raw operand collections
or predicate/HAVING ASTs. Access reports keep counts, index/bound fields and
inclusivity; grouping keeps strategy, fields, aggregate labels and limits, with
predicate/HAVING presence flags. Text and JSON share access/grouping/decision
writers. The access writer has one contract, also used by execution JSON; no
simple/detailed mode, extra DTO family, render cache or new budget is introduced.
This replaces earlier byte-preservation requirements for canonical reports only.
The plan metadata and ordinary query/cursor identity are preserved.
The demonstrated need is plan inspection; preserving arbitrary Rust Debug dumps
would require a broader formatter framework without a demonstrated consumer need.
Canonical output now avoids Value/Expr formatting entirely. Existing labels may
still contain literals, so this is not a redaction or public-exposure guarantee.

Hard-cut canonical text and JSON rendering to fallible results. Enforce output
limits incrementally in the existing writers, including escaping and metadata
formatting, without a second predictive renderer or rendering to measure size.
Apply the guarantee to every call to these maintained canonical renderers, not
only plans returned by typed explain. Projection must separately bound its copies
and strings before or during construction; retained bytes alone are insufficient.

Construction implementation now requires the existing request's
`PreparationWork` at the prepared logical-explain boundary. Filter labels, HAVING
expression copies, grouped key/path storage, aggregate metadata/labels and ordering labels
use shared charged copy/writer owners; successful canonical models are unchanged.
Predicate DTO copies use required construction authority for nodes, containers,
values and coercion parameters. Execution descriptors share that DTO projector.
Logical explain retains only diagnostic fields, not an identity hash or source
models used solely for hashing. Its fields remain private. This removes diagnostic
hash construction entirely; ordinary identity work remains under preparation.
Access DTO copies also require that authority in logical and execution explain.
The shared visitor borrows index-field iterators and projects children on demand,
so DTO backing is admitted before descent and failures stop sibling construction.
Hashing preserves postorder without collecting child outputs; summary visitors
skip child results they do not consume. No parallel access walker is introduced.
Logical decision projection also charges candidate/alternative/rejection lists,
retained names/labels, identity comparisons and composite constraint visits.
Selected identity matching shares the candidate copy pass; streaming label owners
avoid temporary strings without changing output or first-match semantics.
Grouped family/streaming classification now reads borrowed aggregate identity
facts instead of constructing an owned identity to inspect row-count/DISTINCT
properties. Owned normalization and borrowed row-count inspection share one rule;
no extra cache artifact is introduced. Canonical grouped ordering now uses a
shallow field/constant-offset proof; heap detection and Top-K admission both
short-circuit through the shared expression visitor instead of constructing
recursive summaries. Successful cursor validation no longer builds unused error labels.
Strategy-local aggregate, heap/Top-K/HAVING visits and field/index-key comparisons
now consume the current diagnostic request allowance before work. The shared
Expr walk stops on false or error, without visiting later siblings. String/path
comparison admission uses a conservative byte bound from the stored group label,
including path separators; it constructs no new label or operand copy.
The strategy boundary uses one borrowed semantic evaluator with a required
fallible visit observer. Diagnostic callers supply current request charging;
ordinary identity callers observe infallibly, without depending on a diagnostic
DTO or limit. This is not an optional construction budget or a retry after
exhaustion: diagnostic observation must fail immediately. The demonstrated need
is repeated uncharged strategy walks; the simpler alternative of retaining an
extra cached strategy would add state and still leave cold derivation unbounded.
The canonical owners remain strategy selection and expression traversal. No new
query mode, cache artifact, numerical limit or persisted state is introduced.
Finalized residual inspection now lends the predicate already retained in the
static contract. The demonstrated unnecessary construction was a clone before
presence checks or charged DTO projection. A standard borrowed/owned view at the
existing accessor is smaller than exposing phase-specific getters to each
consumer: frozen predicates are borrowed, unfinished derivations remain owned.
This changes ownership, not the existing planning-phase semantics or state space.
No unmetered copy is substituted for a rejected diagnostic DTO copy. Initial
guard/bound derivation remains a separate unqualified construction owner.
The required argument is not a complete-bounds claim. The
[prepared-path audit](0.257-explain-remaining.md#frozen-terminal-prerequisite-scope--2026-09-10)
shows runtime logical projection borrows finalized shared plans; grouped residual
checks read frozen facts there. Initial residual construction and candidate
enumeration remain planner work, and execution-descriptor construction is outside
the typed logical terminal. Session-facing projection now requires
`SharedPreparedExecutionPlan`; raw model projection stays query-local. Cold/warm
scalar/grouped residual-plan tests qualify that handoff, cumulative rejection,
identity isolation and detached rendering. The final
[projection/rendering qualification](0.257-explain-remaining.md#projectionrendering-qualification--2026-09-11)
records owner-local construction bounds and early/intermediate/exact admission
tests without adding runtime machinery. Direct big-integer scalar labels now use
the shared decimal-chunk converter with one conservative admission before scratch
allocation and arithmetic. Its inner loops have no budget callbacks; output
remains fallible. Ordinary label spelling and numeric/key bytes are preserved;
borrowed schema limb iterators replace owned limb-helper results (low-level Rust
API hard cut). Nested scalar labels share the admitted converter. Detached
canonical reports use plan summaries and no longer reach arbitrary Value Debug
conversion. The existing diagnostic access visitor now admits at most 128
root-to-leaf levels, rejecting with `QueryExplainDepthExceeded` before child
allocation/descent beyond the limit. This bounds canonical access recursion for
projected plans without another walk or any ordinary planning/identity change.
Diagnostic construction/rendering functional qualification is complete at this
prepared boundary. Matched IC/Wasm evidence remains with terminal qualification;
ordinary preparation gaps are not closed by this result. No additional planning
route is introduced.
Ordinary fingerprints and cursors do not acquire this diagnostic requirement. Verbose
execution reads its small scalar fact set directly without building the DTO.

The returned DTO remains owned and detached: no session borrow, budget handle,
stored render cache or new budget lifecycle. Repeated `.explain()` invocations
charge the existing request; later formatting allocates at the caller and has a
per-call output limit, not cumulative session accounting. Repeated formatting can
allocate repeatedly. Emit the current canonical summary; return a typed error
on exhaustion, never truncated output. Do not retain infallible wrappers.

Implemented output policy: each logical text/JSON call admits at most 1,048,576
UTF-8 bytes, including escaping, at the destination before growth. Public
renderers return `Result<String, QueryError>`; output exhaustion carries
`RuntimeBoundaryCode::QueryExplainOutputExceeded` with numeric limit/actual facts
and no report payload. Formatter failure also rejects. The shared JSON writer
streams nested access objects without child Strings and propagates failures to
SQL. Execution-descriptor JSON shares emission but retains its existing output
policy; this does not add a new execution-descriptor limit. Unescaped JSON control
characters are corrected to valid escapes. Projection and recursive formatter
work/internal allocations remain separate proof obligations, as do IC cost gates.

### Construction and resource obligations

Current `AccessPlannedQuery::explain()` is infallible and allocates expression
models, projected collections and diagnostic strings. Its canonical renderers
allocate further strings. The SQL endpoint's 3-MiB Candid reply check runs after
encoding and does not bound these allocations; do not reuse it as a construction
proof or introduce Candid merely to measure this Rust result.

The existing [retained accounting](../../../crates/icydb-core/src/retained.rs)
has checked byte accounting and a depth ceiling, with owners for expressions,
predicates and values. Reuse applicable accounting rather than inventing another
generic object walker. It measures retained capacity, not formatter expansion,
allocation peaks or all traversal work; it is not sufficient by itself.

Before production edits, record numerical limits and enforcement owners for:

- Input expression/value depth, visited nodes and bytes, checked before recursive
  conversion/cloning. Caller construction has already happened; no decoding or
  caller-allocation guarantee is claimed.
- Accepted-schema/index candidate expansion and planner-produced structures,
  bounded conservatively before construction or charged during construction,
  not only checked after planning finishes.
- Diagnostic model copies, candidate lists, and string expansion, bounded before
  allocation or incrementally as existing projection/render owners build them.
- Canonical text/JSON output under the incremental writer contract above, including
  escaping, large literal values and Debug formatting. Checking an already-created
  string is not a peak-memory bound.
- Cumulative work for repeated explains sharing one request, including cache hits.

Prefer one fixed policy and existing typed budget resources. Record any genuinely
missing diagnostic code at its current owner; do not match error strings or add
a broadly consumed mode enum. Return a typed failure, never silent truncation.
Depth rejection must also consider error cleanup/drop behavior: do not claim
arbitrary nesting is stack-safe solely because a validation walk is bounded.

Any bounded logical projection needed by both SQL and typed explain must converge
at the existing explain owner; do not maintain two projection implementations.
Inventory non-frontend callers, including fingerprint-related model access,
before changing existing infallible helpers or public renderer signatures.
The implementation technique and exact numbers remain unproven. If bounding this
path requires a general planner/rendering redesign, report and rescope before
implementation rather than quietly expanding this feature.

## Complexity decision

Demonstrated need: fixed application queries currently require SQL solely for
logical introspection. Simplest alternative: retain that opt-in SQL dependency.
Chosen direction: one consuming terminal over existing authorities. State-space
delta: one public terminal, no runtime mode, config, persisted state, cursor
format, endpoint or compatibility path. Diagnostic bounds may require a narrow
fallible handoff at the existing owner; they do not justify a second planner.
