# Borrowed aggregate lowering

Date: 2026-09-08. Active release: 0.257.1, preparation slice 10.
Baseline: the preceding [literal-copy candidate](0.257-literal-copy-perf.md),
not published 0.257.0.

## Ownership and qualification

Aggregate lowering borrows SqlAggregateCall instead of cloning a complete
subtree before lowering it. Input and FILTER expressions use existing borrowed
expression lowering and its charged value copier. Retained direct-field names
use the shared charged text copier; aggregate input/filter boxes charge requested
backing before allocation. The grouped caller uses the same owner: its former
direct-field name move becomes one charged copy. No ownership mode or parallel
lowering implementation is added. Analysis, folding and canonicalization remain
at their existing owners and are not newly fully bounded by this change.

125 focused native test passes cover SQL lowering (38), session preparation and
authority (42), and fingerprint-related tests (45; selections overlap).
New coverage checks exact/short backing for COUNT star, field, literal and FILTER,
preserved syntax after failure and successful repeat lowering. Core all-feature
lint, formatting, admission/branch/authority/panic invariants and whitespace
checks pass. Full suites remain user-owned.

## Matched actor measurements

The native aggregate probe uses the unchanged SQL-perf actor, canonical
WasmRelease/LocalTest build with SQL and Candid enabled. It executes COUNT(*)
with a FILTER comparing name against 16-, 256- and 4096-byte text literals.
Each size starts from six fixture rows; three different literals each compile
then immediately repeat for a hit. Result equality is checked across repetitions
and hits. The probe does not independently assert the aggregate's numeric value.
Local instructions exclude endpoint Candid decoding/encoding; cycles measure the
whole update. Deterministic settling ticks occur outside measurement.

Both frozen artifacts were run twice on isolated PocketIC servers. All four runs
pass and reproduce all 18 records exactly. Both servers were stopped afterward.

These are independent medians of three samples, not median paired differences.
Two individual hit samples cross the existing positive >250,000 and >3%
instruction-review threshold: 16-byte repeat 2 adds 483,750 (+14.218%);
256-byte repeat 2 adds 480,059 (+13.372%). Their cause is **unresolved**.
Exact replay rules out dismissing them as random run noise. The much smaller
cycle changes do not explain away instruction regressions, and cache hits do
not establish the cost of aggregate lowering itself. No blanket performance
improvement or completed line-level cost gate is claimed. Prior CASE flags also
remain open. Grouped direct-field costs and SQL-disabled actor cost are unmeasured.

## Complexity and remaining work

Ten files change in this step: five Rust and five documentation, approximately
+10 production and +100 test/probe lines. Ownership is simpler: one borrowed
lowering flow, no intermediate complete aggregate clone, shared copy/accounting
helpers. Remaining normalization/folding/alias and construction gaps keep slice
10 open; slice 11 and typed `.explain()` have not started. Investigate the
reproducible instruction/cycle discrepancy before claiming performance closeout.
