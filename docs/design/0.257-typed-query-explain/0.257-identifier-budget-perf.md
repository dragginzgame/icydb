# Charged identifier normalization without qualifier temporaries

Date: 2026-09-08. Active release: 0.257.1, preparation slice 10.
Baseline: the preceding [alias-budget candidate](0.257-alias-budget-perf.md),
not published 0.257.0.

## Ownership and bounds

The identifier normalizer now propagates the current `PreparationWork` through
projections, predicates, aggregate input/FILTER, grouping, ordering, assignment
targets and RETURNING fields. Expression visits and introduced field-path
backing charge before work/allocation; rejected child processing stops before
later siblings. Clause vectors and unchanged field strings retain ownership.
The NULL-test special preparation still performs its existing extra qualifier
reduction, but moves the field instead of copying it and replacing its box.

Nested field-path normalization no longer joins every candidate qualifier or
builds a second root-plus-segments vector. Full identifier equality implies
equal tails; therefore the established full-or-tail matching rule is equivalent
to matching the final component of each prefix. Prefixes are still considered
longest first, including dotted components, empty components and ASCII-only
case matching. Retained strings/vector backing move without copying, with
handle compaction charged before mutation.

Dotted-field construction is shared with the alias operand copier. Plain
projection fields bypass the parser constructor's redundant string copy.
The public pure `normalize_identifier_to_scope` utility and its candidate-order
semantics remain unchanged. Its SQL caller charges conservative byte-work
allowances for direct/full/tail matching, splitting and compaction, using O(1)
string lengths and charged candidate visits. These are work allowances, not
claims to count exact character comparisons or allocations performed by the
public utility outside query preparation. No alternate matching policy is added.

This closes the owned identifier-rewrite operation's traversal/construction
gap. It does not account for the initial statement clone, the preceding
local-canonical classification walk, route lookup or remaining projection
copies. Mutation-job publication rejection qualification remains part of the
broader preparation completion gate; this landing does not close slice 10.

## Qualification

New focused tests cover exact dotted-field backing, cumulative matching-work
rejection, first-child termination, longest-prefix/tail semantics and owned path
normalization with zero new temporary-byte allowance. Existing current-authority,
bound-query, cache and UPDATE-policy tests protect the surrounding flow.

The frozen probe and unchanged audit actor use canonical WasmRelease/LocalTest
settings and PocketIC 16. Entity-qualified queries exercise path reduction;
projection-alias workloads cover ORDER BY and grouped HAVING; literal-only
arithmetic controls establish fast-path/cache behavior. Every query returns six
rows with compile/hit parity. Settling ticks stay outside whole-update cycle
intervals, and local instruction windows retain their separate interpretation.

Incremental complexity: eight files, approximately +50 production/+160 test
Rust lines, plus documentation. Matching/allocation flow is simpler; required
fallible propagation and checks add plumbing. No new modes, query routes,
request roots, public utility changes or compatibility paths are introduced.
Earlier dirty changes, applications and Cargo versions are preserved. No
commits or pushes are performed.

bindings (45), UPDATE policy (26), identifier matching (5), and input admission
