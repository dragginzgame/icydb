## Accepted diagnostic trade-off — 2026-09-11

After reviewing the full cost comparison, the user explicitly accepted stopping
explain-specific optimization rather than adding caching or redesigning binding
authority to meet SQL's cost. This closes the diagnostic cost decision for R9
and the associated slice-5 projection/rendering qualification, not preparation
slices 10/11 or the whole 0.257 line.

Acceptance applies to the measured published 0.257.5 implementation below:
typed explain saves 25.74% raw Wasm versus SQL explain, while complete diagnostic
calls including rendering cost 13.03–14.84% more instructions cold and
84.68–100.91% more warm. Warm means repeated calls within one request, not
guaranteed reuse across endpoint invocations. Ordinary reads pass their original
regression gate with 4.03% fewer instructions against the frozen control.

The seven original +5% comparison failures remain recorded. The opt-in comparison
harness is unchanged and will still report those misses; that result is an
accepted exception for these artifacts, not a passing assertion or a new numeric
ceiling. Use the retained typed results as comparison evidence for future work;
this acceptance does not preapprove additional regressions or larger workloads.
Wasm, ordinary-read, authority/lifecycle, no-row-execution, input/projection and
rendering limits remain in force. No cache, runtime mode, validation bypass or
additional accounting is authorized. No production change or new measurement
is made by recording this decision.

thread-local state. The early read precedes that selection. Same-actor repeated
calls observe the same allocation, but that is not a sufficient cross-domain
correctness contract. Recovery admission itself does not replay or mutate durable
state; the relevant change here is selection of the ambient allocation.

shared binding matcher within the synchronous validation operation. Preserve
current accepted root, field identity, live constraint-job and index visibility

its exact per-binding domain rejection. Tests should switch active commit domains
between retained sessions, reject foreign/stale bindings, and preserve existing
rename, revision, startup and atomic-batch behavior. Do not reuse an issuance-time
identity across a builder's lifetime or cache it across requests.

This targets one approximately 91,000-instruction read per validation in this
workload; net savings and Wasm impact must be measured after implementation, not
assumed from a phase subtraction. Root/bundle checks are another substantial

## Remaining binding-cost audit — 2026-09-11

Read-only runtime audit after current matched requalification. The user asked
to continue; this review keeps the failed ceilings and current-authority checks,
and proposes one bounded follow-up rather than introducing a binding cache.

The next concrete construction candidate is the existing commit-control decoder:

  the framed control payload, then calls `inspect_commit_control_slot`.
- `parse_current_control` constructs the entire owned allocation registry even
  when the caller only needs the incarnation, cursor key, sequence, marker
  presence, encoded length or header. Each registry entry builds a temporary
  four-role vector and owned stable-key strings. Registry validation also
  constructs a memory-ID vector solely for each entry's ordering comparison.
- `ic-memory 0.13.2`'s `StableKey::parse` makes another owned string for successful
  validation. Its grammar remains upstream authority: do not copy that grammar
  into IcyDB to claim allocation-free validation.
- Within the inspected control-store consumers, the persisted-allocation getter
  and persisted-control observation need owned registry output. Test control
  rewrites also use it. Identity/key/marker/header readers discard it.

registry names from its already bounded payload, and materialize the existing
owned registry only for consumers that need ownership. Keep one parser and one
registry-validation authority for decoding and encoding; eliminate disposable
ordering vectors using borrowed role comparisons. Do not introduce a header-only
decoder, optional validation mode, cached incarnation, upstream dependency change
or new persisted representation. Existing current version-1 bytes stay exact.
Borrowed views must not outlive the payload or be retained across publication.
