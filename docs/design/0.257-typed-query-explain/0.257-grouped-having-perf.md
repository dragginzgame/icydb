# 0.257.1 — Owned grouped HAVING conversion

The grouped-key literal converter now updates the owned lowering intermediate
in place. Unchanged scalars and list/set backing storage are retained. Children
that do not convert stay in their slots, preserving the grouped converter's
partial-conversion semantics without fallback clones. Ordinary filter conversion
still requires all children to convert; the two contracts are not conflated.

Each grouped visit charges the current request's nested-value work counter.
The existing scalar converter remains the sole scalar normalization authority,
including its own work and introduced-storage charges. A failure propagates
through SQL lowering, which discards its private intermediate. Neither immutable
retained syntax nor a previously bound value is mutated. HAVING parameter
placement is not expanded; the binding regression uses supported WHERE
parameters with a fixed HAVING clause.

The filter materialization helper no longer has a production caller outside its
module, so its re-export is removed and it becomes private. There is no new copy
helper, policy mode, runtime route, cursor format or schema authority.

## Matched IC measurement

The existing `sql_perf` actor and update endpoint are unchanged. Only an ignored
native integration probe is added, so there is no measurement-only Wasm growth.
The baseline is published 0.257.0 at
`6e60aaf85ee51d3e414f05248e2b0384d6eac6b8`; both modules keep Cargo versions at
0.257.0, the same lockfile, Rust 1.97.1, Binaryen 132, canonical `wasm-release`,
SQL/Candid enabled and local-test actor profile. PocketIC is 16.0.0 on an
application subnet.

Each cell installs a fresh actor, loads the same six users, and executes:

```sql
SELECT name, COUNT(*) FROM PerfAuditUser GROUP BY name HAVING name != '<literal>'
```

Literal widths are 16, 256 and 4,096 ASCII bytes. Three distinct literals per
width each produce one concrete-command compilation, immediately followed by
an identical-query cache hit. The first compilation is also the first query
after fixture setup; the table reports medians across all three repeats, not a
claim of fixed-history steady state. Every result contains the same six groups
and no continuation. There is no additional source-row workload at wider widths.

Before every update, settle 64 deterministic rounds without time advancement
or auto-progress. Local instructions cover session acquisition and SQL query
work, including facade result conversion but excluding endpoint Candid decoding
and reply serialization. Whole-update cycles
include those and platform overhead. Cache hits still perform ordinary ingress
and parsing work but avoid semantic compilation, including this conversion.

All nine compilation calls consume fewer whole-update cycles, but local
instructions are mixed. The largest individual increase is 232,501 instructions
(5.462%) on the second 4-KiB compilation; no sample crosses both existing review
thresholds of 250,000 instructions and 3%. That does not erase the increases or
establish a blanket speedup. The different measurement windows and call-history
effects are not phase-attributed here; cache-hit changes are not evidence that
hits now execute this converter. Both frozen-module replays reproduce all 18
instruction/cycle records exactly.

This measures scalar text HAVING, not collection conversion or generic typed
query throughput. Storage-identity and zero-copy-budget tests establish the
collection improvement separately. Broader preparation and diagnostic cost
gates, including the earlier typed-construction review flag, remain open.

## Borrowed field-resolution follow-up

The next 0.257.1 cleanup removes temporary field/key/type construction at grouped
HAVING normalization. GroupField retains ownership of nested scalar/comparable/
stable-group eligibility. A borrowed component iterator preserves dotted spelling
without constructing strings; schema lookup returns the current retained kind.
Direct fields keep their broader existing resolution contract. Actual execution
keys still retain the metadata they need. No new conversion authority, cache
mode, public API or actor instrumentation is introduced.

This comparison starts from the preceding candidate above, **not** from published
0.257.0. The actor, native probe, configured build and 18-request matrix are
unchanged. It measures direct text-field HAVING only; native tests cover nested
resolution and conversion, but no nested-path performance claim follows from
this measurement. Counter scopes and first-compilation/median caveats above
continue to apply.
