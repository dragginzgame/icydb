# 0.257 — Non-Reentrant Boolean Ordering Measurement

Date: 2026-09-08. Tracker slice 6; see [status](0.257-status.md).

## Outcome and scope

The canonical comparator now renders its already-normalized operands directly
with the existing scalar renderer. It no longer clones and normalizes them again
through the general filter-label helper. Label ordering and the structural Debug
tie-break remain unchanged; no second renderer, sort key cache or semantic owner
is introduced. The general filter-label helper keeps its existing contract for
other callers.

Repeated matched native measurements reduce six-level nested-CASE preparation
from about 270 ms to 1.2 ms (99.6% less time). CASE condition duplication and
expanded node counts are unchanged. This removes repeated work, not the need for
diagnostic limits or a total CASE-expansion bound. It is not an IC-cycle,
end-to-end query, allocation-count or Wasm-size measurement.

## Matched protocol

- Baseline: pending slice-4 worktree plus the approved diagnostics preflight and
  new parity/timing tests, on commit `bd40327d5657bd5700933d0d7e2dca162b4a4539`.
  It already includes balanced lowering, shared associative normalization and
  compact membership. Candidate changes only the comparator's renderer calls,
  imports and invariant comment in production.
- Rust 1.97.1, x86_64 Linux, AMD Ryzen Threadripper 7970X. Native test profile
  opt-level 1, debug assertions disabled in both binaries; SQL/migration/metrics
  disabled. No dependency, Cargo-version or production-profile change.
- The same nested one-arm boolean CASE fixture as the
  [construction preflight](0.257-diagnostics-preflight.md), using distinct boolean
  fields in THEN/ELSE and nesting in WHEN. Levels 0, 2, 4 and 6 are measured.
- Input construction/cloning is outside the timer. Scalar-WHERE canonicalization,
  its temporary allocations and output disposal are timed, with `black_box` on
  input/output. Each process warms each case once, then takes the median of three
  batches of three calls. The new maintained ignored test is
  `nested_case_normalization_native_timing`.
- Frozen binaries run baseline/candidate/baseline/candidate sequentially after
  compilation, with no agent-launched concurrent build. Each process has a
  20-second external guard; all four runs pass. No CPU pinning, statistical
  confidence interval or representative production workload is claimed.
- The timing test is available only with debug assertions disabled. A constant
  runtime assertion in the frozen harness was subsequently replaced with that
  compile-time test gate to satisfy lint. The measured production code and
  timing loop are unchanged.

## Complexity and remaining work

Eight files in this slice: one production file, its tests, root/detailed release
notes, design/status, this receipt and a historical preflight cross-reference.
Production executable line count is unchanged, with two added intent-comment
lines; tests/timing grow by 126 net lines. The implementation is simpler: render
normalized operands directly instead of re-entering a preparation stage.

No new API, limit, authority, mode or compatibility path. No additional hard cut
is introduced by this repair; the earlier compact-membership migration remains.
Full suites are user-owned. Production-profile timing, IC cycles, raw Wasm and
defined-function measurements were not run. Bounded diagnostics is the next
pending slice, not included in this handoff.
