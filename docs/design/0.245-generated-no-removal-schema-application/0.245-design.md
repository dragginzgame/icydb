## Outcome

Determine whether minimum generated canisters can avoid retaining explicit
schema-removal lowering that their sealed generated proposals cannot request.
The generated path must still decode and canonicalize the current schema
fragment, obtain opaque runtime identities, prove the accepted head through
the existing core application authority, and publish through the existing
atomic commit owner.

This is a hard-gated build/no-build line. It adds no public schema behavior,
SQL behavior, cache, persisted state, stable format, generated model authority,
feature, compatibility path or runtime mode. If every required minimum actor
does not save at least 32 KiB final raw Wasm, or startup work regresses, all
runtime and focused-fixture changes are reverted and 0.245 closes as a measured
no-build.

## Frozen Contract

Generated proposal composition currently passes `Vec::new()` for removals.
0.245 may represent that existing fact as one private compiler-visible
contract so code reachable only from explicit removal proposals can be omitted
from minimum generated actors.

The generated contract must:

1. be constructed only after the ordinary generated fragment decoder and
   `SchemaProposal::try_compose` canonicalizer succeed;
2. reject a non-empty removal set with the existing typed internal failure;
3. enter the same core recovery, idempotency, database-identity, accepted-head,
   preflight, capacity, receipt and publication owners as `apply_schema`;
4. use the same initial proposal lowering on fresh installation;
5. use the same existing entity, type, index, relation and constraint lowering
   for generated additions or replacements;
6. differ only by making explicit removal resolution and removal mutation
   unreachable; and
7. retain all explicit public `SchemaProposal` removal behavior unchanged.

The compiler specialization is not a runtime choice. No request, snapshot,
schema value or persisted record selects between routes. The authored caller
determines at compile time whether it is the sealed generated no-removal
boundary or the ordinary public proposal boundary.

## Singular Authority

```text
sealed generated fragment bytes
  -> existing public decoder and canonical proposal composition
  -> private no-removal proof
  -> singular core schema-application admission
  -> no-removal existing-head lowering specialization
  -> singular candidate validation and atomic publication
```

Only core schema application may decide whether a target database, accepted
head, submission identity and candidate are current and publishable. The
generated proof cannot issue identities, establish freshness, select an
accepted bundle, publish a candidate or reconstruct authority from generated
models.

The general explicit proposal entry remains semantically unchanged. A
minimum generated actor should not retain it unless application code actually
calls that public Rust capability.

## Least-Complex Structure

The application owner may gain one private compiler-only specialization or one
private proof type, but not both a new policy hierarchy and a new state object.
Admission and publication remain one implementation. Existing-head lowering
may separate removal preparation from shared entity/candidate completion only
to let dead-code elimination remove the former.

Permitted structural changes:

- one hidden generated-session delegate from the public facade to core;
- one core generated application entry sharing the ordinary application body;
- one no-removal existing-head lowering entry;
- one private immutable helper/type if it reduces duplication; and
- direct focused tests for fail-closed admission and general removal equality.

Forbidden changes:

- a second schema-application authority or publication function;
- bypassing fragment decoding, proposal composition or target/head proof;
- a runtime enum, flag, mode or adaptive route;
- duplicated receipt, capacity, activation or publication logic;
- generated-model fallback reconstruction;
- removal aliases or compatibility behavior;
- a cache, mutable owner, persisted marker or invalidation edge; and
- specializing fresh install while leaving upgrade behavior incomplete.

for parallel semantic flows fails the complexity gate.

The 32 KiB gate applies independently to all four actors. A large SQL saving
cannot compensate for a miss in the empty or typed minimum. Gzip is recorded
but cannot rescue a raw-Wasm miss.

## Required Proof

- empty generated proposal and one-entity initial publication;
- exact generated replay before and after same-Wasm upgrade;
- existing-head generated field/index/constraint evolution;
- fail-closed non-empty removal input at the generated core boundary;
- general field, index, relation, constraint, type and entity removals;
- pending activation, receipt replay and publication failure behavior;
- journal recovery and accepted-root reopening;
- no-default, SQL and maintained feature compilation;
- final raw/gzip Wasm, function count, Candid digest and exports for the four
  required actors; and
- production/test line delta with new owner/state inventory.

## Rejected Alternatives

- **Skip generated decoding or proposal canonicalization:** rejects the single
  canonical proposal contract and could admit malformed generated input.
- **Generated-only publication:** creates a second accepted-schema authority.
- **Merge all removal representations:** introduces an enum/dispatch coupling
  for only 13,833 diagnostic sort bytes.
- **Source-only facade DRY cleanup:** unused generic methods are dead-stripped;
  no final-Wasm saving is demonstrated.
- **Inlining directives:** one retained caller provides no credible removable
  duplication ceiling.
