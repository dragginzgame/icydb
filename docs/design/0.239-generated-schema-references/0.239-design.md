# IcyDB 0.239 Generated Schema References

Status: IMPLEMENTED — READY FOR USER REVIEW

Last updated: 2026-08-24

Evidence source: Toko Miner `ICYDB-012`

## Outcome

Generate schema-authored source references on runtime-enabled entity and
record types so application queries and structural writes do not maintain a
second hand-written vocabulary of entity, field, and record-member names.

This is one bounded authoring-surface slice. It does not change accepted
schema authority, query admission, execution, persistence, Candid, exports,
or public database behavior.

## Demonstrated need

Toko Miner currently maintains a temporary bridge containing 124 entity field
references, eight record-member references, and thirteen entity source names.
Without that bridge, a schema rename can leave otherwise typed query or
structural-write code compiling until accepted-schema binding rejects the old
string at runtime.

IcyDB generated `Entity::FIELD` string constants before 0.5.7 and generated
`FieldRef` constants from 0.5.7 through 0.62.9. The 0.62.10 per-entity surface
cleanup deliberately removed those query-facing constants together with
unrelated generated API clutter while consolidating runtime model metadata.
The later 0.213 package hard cut preserved that absence; it did not cause it.
Maintained query examples consequently used `FieldRef::new("...")`, while
structural writes continued to accept source-name strings.

Toko Miner's temporary bridge reproduced the former entity field constants and
also added record-member references and inherent `Entity::ENTITY` source names.
Those latter two conveniences were not part of the old upstream field-constant
generator.

The smallest correction is to restore the vocabulary at its existing schema
declaration owner. A new query type, structural-write route, runtime cache, or
schema authority is unnecessary.

## Frozen contract

1. Every field declared by a runtime-enabled `#[entity]` emits one public
   associated `FieldRef` constant using the field's upper-snake Rust name.
2. Managed timestamp fields are included because they are part of the emitted
   entity schema.
3. Every member declared by a runtime-enabled `#[record]` emits the same form
   of public associated `FieldRef` constant.
4. Every runtime-enabled entity implements `EntitySource` with its exact
   authored entity source name. The canonical collision-safe access is
   `<Entity as icydb::traits::EntitySource>::ENTITY`; `Entity::ENTITY` is only
   shorthand when no inherent field constant has that name.
5. `FieldRef::as_str()` remains the conversion into existing structural patch,
   embedded-map, schema-inspection, and ordering surfaces. No second field
   reference type or structural-write overload is added.
6. A schema-only consumer with no direct `icydb` runtime dependency continues
   to emit model declarations without runtime-owned references.
7. Renamed direct dependencies resolve through the existing generated-path
   rewriting contract.
8. Generated references are application-model convenience only. They cannot
   select, validate, publish, refresh, or reconstruct accepted schema.
9. Runtime queries and writes continue to resolve source names exclusively
   through the current accepted-schema binding.
10. No legacy alias, compatibility wrapper, fallback generator, or dual
    vocabulary is retained.

## Public examples

```rust
let page = db!()?
    .query::<User>()?
    .filter(User::ACTIVE.eq(true))
    .order_by(asc(User::ID))
    .limit(25)
    .execute_live_page(None)?;

let patch = StructuralPatch::new().field(
    User::ACTIVE.as_str(),
    WriteCell::Value(InputValue::Bool(true)),
);

db!()?.execute_trusted_structural_insert_batch(
    <User as icydb::traits::EntitySource>::ENTITY,
    vec![patch],
)?;
```

The field and entity constants carry source spelling, not proof that the
source is accepted or current. Admission still occurs when the request binds
to the immutable accepted runtime snapshot.

An authored field named `entity` remains valid and generates the inherent
`Entity::ENTITY: FieldRef`. The source remains available without ambiguity
through the fully qualified `EntitySource` constant; no schema name is reserved
for generated convenience.

## State-space and complexity budget

| Dimension | Delta |
| --- | --- |
| Runtime behavior axes | 0 |
| Accepted-schema authorities | 0 |
| Persisted or cursor formats | 0 |
| Mutable owners or caches | 0 |
| Public generated constants | one per runtime-enabled field/member plus one entity source constant |
| Production owners | existing entity/record macro emission only |
| Measured Wasm effect | +3,248 final raw bytes; -1,617 compiler-emitted bytes; -417 deterministic gzip bytes |

The change is rejected if it requires a new runtime semantic path, generated
model fallback, schema-only dependency on `icydb`, or a second source-name
representation.

## Proof boundary

- macro-token tests prove entity, managed timestamp, record-member, and entity
  source constants;
- the renamed-runtime fixture proves real expansion through query predicates,
  ordering, structural patches, embedded maps, and insert-batch entity
  selection;
- the schema-only fixture proves the model/runtime package boundary remains
  intact;
- maintained query and structural-write examples use generated references;
- focused warning-denied checks cover the macro, model, runtime facade, and
  both boundary fixtures;
- raw Wasm, Candid, exports, and stable-format impact are reported, with no
  expected semantic delta.

## Non-goals

- generated projection types or field-type-level query checking;
- runtime freshness or schema-admission proof in a constant;
- changing structural mutation signatures;
- generating SQL identifiers or rewriting SQL text;
- generated relation/index constants;
- compatibility aliases for the deleted pre-0.213 macro package;
- downstream Toko Miner adoption in this repository.
