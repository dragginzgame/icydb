One material gap remains. Equal structural and residual prefix-family

## Frozen Scope

0.236 is limited to exact-cardinality tie-breaking for existing non-grouped
`IndexPrefix`, `IndexMultiLookup`, and `IndexBranchSet` routes.

It:

- extends the final lexicographic tie only;
- reads exact evidence through `StoreHandle` and 0.230 authority;
- uses one opaque nonpersisted lifecycle stamp only for cached unavailable
  fallbacks, derived from existing 0.230 lifecycle/source authority without a
  mutation revision;
- keeps one shared plan/template cache and one planner;
- pins a cardinality-ranked route by accepted `IndexId`, access family, and
  consumed prefix arity inside the current authenticated scalar cursor;
- extends the existing explain snapshot; and
- falls back to the exact predecessor decision whenever complete bounded
  evidence is unavailable.

It adds no persisted statistics, range/group cost model, generated-model
fallback, caller hint/budget, optimizer mode, second cache/planner/executor, or
new Candid endpoint.

The cursor change is a pre-1.0 hard cut. The sole current version-1 codec is
replaced in place, predecessor bytes fail closed, and no predecessor constant,
decoder, dual form, or fallback remains. A version-2 cursor is intentionally
not used because repository policy requires every current pre-1.0 internal
format discriminator to remain exactly version 1.

## Fixed Advisory Policy

| Resource | Maximum |
| --- | ---: |
| Tied candidates | 64 |
| Exact prefix probes | 256 |
| Cumulative lowered probe bytes | 4 MiB |
| Prefixes prepared together | 16 |
| Transient lowered bytes prepared together | 1 MiB |

An exceeded advisory policy preserves query admission and uses structural
lexicographic fallback. Maximum-shape IC measurements are required before
closeout and may lower these caps if necessary; implementation may not make
them caller-selectable or silently exceed them.

## Review Feedback Resolution

The design review's three gates are resolved as follows:

1. `(IndexId, family)` is not assumed to be permanently unique. The route pin
   also stores consumed prefix arity, and continuation planning must find
   exactly one ordinary eligible match. Singleton branch canonicalization,
   differing prefix depths, zero matches, and multiple matches remain explicit
   closeout proof cases; Patch 2 covers current-pin round-trip, foreign-entity
   rejection, and successful exact-route resume.
2. An unavailable proof returns a cheap comparable lifecycle stamp for Absent,
   Building, malformed, or unreadable evidence. Only a cached unavailable
   fallback checks it; an unavailable-to-Ready change therefore retries the
   bounded proof without probing counts on every unchanged fallback hit or
   revalidating exact-selected plans after ordinary writes.
3. The requested version-2 cursor would violate the repository's explicit
   pre-1.0 version-1-only policy. The accepted resolution is a genuine hard cut
   of the sole current version-1 layout with no legacy reader or fallback.
4. The subsequent complexity review removes mutation-driven cache freshness.
   Exact counts are consulted at cold compilation or new parameter binding and
   retained as `exact_at_selection`. Only unavailable fallbacks compare the
   0.230 lifecycle stamp so Ready publication cannot remain hidden.

The review also confirmed that fewer exact matching prefix entries is the only
claimed fact. Implementation terminology may use `cardinality_tiebreak`, not
cost/estimate/cheapest or general optimizer scoring.

## Complexity And Size Budget

Local source complexity will increase moderately: one selection-proof DTO, one
final tie comparison, one unavailable-fallback lifecycle stamp,
candidate-neutral template retention, and one authenticated route discriminator
are required.
Architectural complexity remains bounded because these replace or extend the
current StoreHandle/planner/cache/token owners and add no persisted state,
cache, executor, mode, job, configuration, or public hint.

Patch 2 must stop for review if it needs a second candidate model/planning flow
or independent state axis. It must record production files and approximate
line delta and charge candidate-neutral templates by their actual bounded
retained authority.

Performance and artifact gates are frozen:

- non-tied queries perform no new cardinality reads or probes;
- warm exact-selected cache hits perform no lifecycle reads or probes, even
  after ordinary writes;
- only warm unavailable fallbacks perform one lifecycle-stamp check and no
  probes while unchanged;
- resumed pinned cursors perform no cardinality reads or probes;
- unavailable-stamp and cursor overhead each stay within the greater of 5% or
  2 million instructions on matched predecessor fixtures;
- the production-shaped selective fixture must reduce both entries visited
  and total instructions after including cold planning work; and
- raw non-gzipped Wasm growth against the exact same `v0.235.1` artifact stops
  for attribution/reduction above the smaller of 96 KiB or 3%. Gzip cannot
  waive the gate; Candid and exports remain unchanged.

## Patch 3 Evidence

Patch 3 found and corrected one real lifecycle defect. The SQL compiled-command
resident plan slot could retain an `Unavailable` fallback and bypass the shared
cache's lifecycle-stamp comparison forever. Scalar SELECT and global aggregate
commands now decline to retain only that state in their command-local slot.
They continue through the canonical shared cache until Ready is observed, then
retain the exact-selected plan normally. Exact-selected and policy-fallback
warm paths remain unchanged and perform no lifecycle read.

The focused native matrix passes with five cardinality tie-break/cache/cursor
tests and six current scalar-token tests. It directly records zero evidence
calls for non-tied, warm exact-selected, and pinned-continuation paths; one
lifecycle read and zero probes for an unchanged unavailable fallback; and one
bounded proof when Ready changes the stamp. A new regression specifically
warms the SQL compiled-command path while unavailable and proves that the same
compiled command re-enters the shared cache after Ready. Focused all-feature
`icydb-core`, audit-canister, and recovery-test Clippy runs are warning-clean.
