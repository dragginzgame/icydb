# IcyDB 0.250 Native I256 Status

Status: RESERVED — DESIGN ONLY; IMPLEMENTATION NOT AUTHORIZED

Last updated: 2026-08-29

## Reservation

The 0.250 minor is reserved for an independent native fixed-width `I256`
investigation after 0.249 closes. This reservation does not activate the line,
open a changelog release, or authorize production code.

## Patch Ledger

| Patch | Bounded outcome | Status |
| ---: | --- | --- |
| 1 | Real signed workload plus `IntBig`, adapter-only and native representation/carrier measurement | Not authorized |
| 2 | Native `I256` storage and query support through maintained authorities, conditional on Patch 1 | Not authorized |
| 3 | Checked scalar arithmetic; exact wider-accumulator `SUM` only after separate proof | Not authorized |
| 4 | Cumulative qualification and closeout | Not authorized |

## Frozen Review Points

- `I256` is independent from the released `U256` decision.
- A real downstream signed schema is required before implementation.
- Allocation-free ordinary runtime kernels and hot-enum inflation are central
  admission evidence.
- Signed ordered keys use fixed big-endian two's-complement bytes with the sign
  bit toggled.
- `SUM(I256)` cannot use stepwise same-width accumulation; it remains deferred
  unless exact final-range semantics are proven with a wider accumulator.
- `AVG(I256)`, implicit coercion, bitwise SQL operators and compatibility paths
  remain out of scope.

## Next Action

Finish and accept 0.249. Then an explicit user instruction to start 0.250 may
authorize Patch 1 measurement only.
