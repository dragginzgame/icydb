The new 0.297 boot identity is a fresh-installation contract. Earlier database formats
refuse before recovery or payload decoding. Do not convert, clear or delete

landing slices group this authorized implementation; they are not a second
feedback queue. Dispositions for obsolete old-format repair requests must be

The registry contract replaces irreversible retirement with bounded dormancy.
It preserves all four allocation identities and bytes, reactivates only an exact
empty-tail quartet, never remaps or clears roots, and still refuses topology
changes with a pending marker or generated application. Active and dormant
entries share the existing sixteen-quartet bound. A failed schema reconciliation
can be corrected by restoring the original declaration; this is restoration of
current retained authority, not a reader for retired database formats.

Migration retries use `migration_attempt` on the canister declaration (zero by
default). A deliberate increment changes only generated proposal identity.
After abort and source-data correction, redeploy the same successor/plan with a
new attempt and explicitly advance. Exact attempts retain terminal replay;
active/irreversible migrations cannot be superseded. Rejection retains its first
bounded findings batch; repeated explicit repair/abort/new-attempt cycles can
reveal later bad rows without a fictitious acknowledgement protocol.

Progress retirement is an explicitly authorized Rust session administration API.
Applications own any remote wrapper and its authorization. It uses raw shared
record keys and complete-record digests, includes corrupt payloads, refuses stale
evidence, protects the header and requires completed recovery. Retirement removes
receipts/progress, never committed data or external application effects; normal
owner acknowledgement remains the ordinary retention contract.

Generated readiness identity also binds each entity's declared store path and
heap/journaled allocation key. Stable database identity must not let an unchanged
fragment receipt authorize a changed store assignment or storage mode. Unused
store membership remains outside this source-submission binding, so unrelated
store changes do not invalidate an already-migrated declaration's readiness.
