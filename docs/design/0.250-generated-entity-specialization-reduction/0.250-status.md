## Decision

The user explicitly started 0.250 after the 0.249 closeout verdict. The line
targets measured generated-entity specialization in a real downstream actor,
not schema declaration cost in an actor where unused adapters are dead-stripped.

Supplied intake evidence attributes 49.7–54 KiB of direct database/entity
monomorphization and 112–128 KiB of all entity-specialized supporting code to
11 reachable generator entities. A disposable common-execution experiment
reduced the optimized code section by approximately 49–51 KiB, but its dynamic
page callback added approximately 95 functions through vtable shims. The code
saving qualifies the owner; the callback shape does not.

Landing Slice 1 now freezes the downstream identities and preserved artifacts,
records the missing experiment-source limitation, and adds a reproducible
maintained one-to-ten reachable-entity pair. See the exact
[Landing Slice 1 receipt](0.250-landing-slice-1-receipt.md).

Landing Slice 2 evaluated the specified concrete driver on a reproducible
final Toko A/B. It saved 27,201 code-section bytes and 31,578 raw bytes, removed
13 defined functions and kept `call_indirect` flat. The 32 KiB code gate was
missed by 5,567 bytes, so the candidate was removed exactly as the frozen stop
rule required. See the
[Landing Slice 2 receipt](0.250-landing-slice-2-receipt.md).

0.250 continues with the remaining static-descriptor, exact-key and typed-write
owners while recording the concrete page owner as unretained. It adds no
planner, executor, storage path, persisted state, runtime registry or
compatibility layer.
