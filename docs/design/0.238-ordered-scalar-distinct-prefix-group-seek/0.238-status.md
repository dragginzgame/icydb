## Assignment

The user explicitly accepted 0.238 on 2026-08-23 as exactly one bounded
ordered scalar DISTINCT prefix-group-seek slice. The review corrections are
frozen into the authoritative design:

1. physical index-entry work has an exact store-level definition;
2. one immutable prepared-plan contract owns all admission;
3. the contract owns one private validated window and constructs the adjacent
   accumulator from it, with no second offset/limit input;
4. exactly one authored `ORDER BY` on the projected direct field is required;
5. one full or compatible projected-field-bounded lowered range is admitted,
   with no new predicate classifier;
6. `LIMIT + OFFSET` is capped at exactly three before execution;
7. NULL rejection, scalar normalization, scalar ordering and ASC/DESC
   boundaries require explicit proofs; and
8. 5,000,000 instructions is a hard release gate that cannot be weakened.

A measured, uncommitted implementation candidate is present for review. It
adds no cache, mutable owner, persisted state, invalidation edge, public API,
Candid or export change. On 2026-08-23 the maintainer accepted the
performance-first audit: raw Wasm remains report-only evidence, while the
instruction, physical-work, correctness, authority and public-surface gates
remain hard. The candidate also corrects `index_store_entry_reads` at the raw
heap-range visitor and proves heap/journal counter parity without adding an
executor-local counter.

## Raw Wasm Attribution

The growth is code, not public or embedded state. The final opaque-contract
artifact is 276 raw bytes larger than the measured +6,094-byte positional
prototype. Final deployable data bytes, Candid and the 70-method export set are
unchanged. The symbol-level table below records the prototype attribution that
identified the additive fast-path owners; the small contract delta does not
change that causal conclusion.

`twiggy diff` shows the following normalized signals. They are not an exact
additive partition because link-time optimization moves and inlines code across
function boundaries, but the 6,312-byte non-name attribution growth closely
corroborates the 6,094-byte deployable result.

| Retained code signal | Approximate bytes | Interpretation |
| --- | ---: | --- |
| New group coordinator and facade integration | +1,308 | Necessary control flow plus representative-to-retained-slot handoff |
| New single-value covering decoder specialization | +1,233 | A new generic monomorph created by the identity `Value` mapper; the clearest avoidable-looking duplication |
| Additional direct `components_chunk_structural` retention | +762 | The group route adds a second call shape and changes whether the existing scanner is retained out of line |
| Covering-plan accessors retained through the new call path | +956 | `EntityAuthority` and shared-plan getters become larger/reachable through an additional handoff |
| Existing covering wrapper/inlining relocation | +911 net | +13,433 bytes moved into one wrapper while 12,522 bytes disappear from its former pure helper; this is optimizer placement, not 13 KiB of new logic |
| New and shifted boundary encoders | +74 | Prefix-bound construction is demonstrably not the main source of growth |
| Renumbered facade closure | +22 net | Optimizer replacement rather than material new behavior |
| Remaining code and call-shape effects | about +1,017 | Error paths, tuple/result handling, allocations and smaller optimizer movements |

The binary is bigger because the optimization is an additive fast path. The
complete predecessor route must remain for every ineligible query, while the
eligible route adds admission, repeated group-boundary scans and a handoff back
to canonical DISTINCT finalization. Rust monomorphization and Wasm LTO then
retain specialized copies of generic covering helpers and rearrange existing
inlining. The runtime work removed from the four measured queries therefore
does not remove the fallback implementation from the binary.

The raw heap-entry counter correction introduces no named function in the
positive attribution list and is not a material hotspot.

A bounded simplification experiment then removed the named decoder monomorph
by performing the identical row-presence check and single-component decode
directly in the group coordinator. It also shared one covering-plan accessor
call between the predecessor and group paths. The experiment compiled, but its
exact deployable raw Wasm was 4,456,420 bytes: +6,280 bytes over the predecessor
and 186 bytes larger than the positional prototype. Compiler-emitted Wasm was
5,100,173 bytes, final gzip was 1,731,154 bytes, and Candid, data bytes and
exports remained unchanged. The experiment was rejected and completely
removed. The final opaque contract is intentionally larger than that prototype
because it closes an accepted structural-safety requirement.

This result disproves the decoder symbol and accessor source call as
independently removable byte buckets. Their semantic work was inlined into the
coordinator and new closure/control flow offset the apparent symbol saving.
Meeting the fixed gate now requires a genuinely more converged execution
shape, not local inlining or source-level deduplication. Such a redesign is not
authorized by Patch 1's bounded simplification allowance.

## Required Hostile Evidence

The initial hard Wasm gate stopped the slice before the complete release proof
matrix. The accepted performance-first amendment authorized completing that
proof without broadening the cohort. The final evidence covers:

- duplicate-heavy low/high edges in ASC and DESC;
- `OFFSET 1 LIMIT 2`, inclusive/exclusive projected-field bounds and exact
  range exhaustion in both directions;
- empty, one-group, exactly-three-group and 2,048-row mostly-unique shapes;
- absent-order rejection plus nullable-expression, derived-order,
  multi-term-order, direct-nullable, oversized-window and
  other-field-predicate fallbacks;
- missing representatives, invalid witnesses and malformed raw keys in ASC
  and DESC;
- cursor fallback, journal-overlay execution, same-Wasm recovery/fold and
  reinstall;
- explicit SQLite result/order equality on an admitted descending offset
  window;
- true-warm reuse and exact expected result/order plus physical-work
  assertions; and
- all six shipped 0.237 optimization-family gates unchanged.
