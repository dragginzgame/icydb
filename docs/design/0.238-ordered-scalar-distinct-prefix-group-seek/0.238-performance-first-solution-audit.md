# IcyDB 0.238 Performance-First Solution Audit

Status: AUDIT COMPLETE — RECOMMEND THE NARROW COVERING GROUP-SEEK ROUTE

Last updated: 2026-08-24

Design authority: [0.238 design](./0.238-design.md)

Measured status: [0.238 status](./0.238-status.md)

## Scope

This audit answers one question: if query performance is the primary decision
criterion and raw Wasm growth is a secondary reported cost, what is the best
implementation shape for the measured ordered scalar `DISTINCT ... LIMIT`
hotspot?

This document authorized no implementation on its own. The maintainer
subsequently accepted its bounded recommendation, and Patch 1 completed the
contract and proof work without adding a second 0.238 patch or broader
`DISTINCT` cohort.

## Decision

The best solution is the narrow planner-admitted covering group-seek route.
Its two pre-release qualifications are now complete:

1. replace the positional tuple-shaped internal payload with one named, opaque
   immutable group-seek contract/window so the accepted admission and window
   ownership rules are enforced structurally; and
2. complete the hostile correctness, lifecycle and SQLite-equivalence proof
   matrix that was stopped by the Wasm gate.

Do not move group seeking into the generic scalar key-stream hierarchy. That
rewrite has little remaining instruction headroom, would make index component
payloads and reposition control cross generic stream wrappers, and would
increase rather than reduce the proof surface. Do not add persisted distinct
state, statistics, adaptive execution or a generalized skip-scan mode.

Raw Wasm remains measured and reviewed but is not a hard rejection gate for
this slice. The final opaque-contract implementation adds 6,292 raw bytes,
0.141% of the 4,450,140-byte predecessor, and saves
88,895,465–91,095,389 instructions per frozen query.

| `age ASC LIMIT 1` | 92,605,670 | 1,510,281 | 91,095,389 | 2 entries, 2 refills, 0 row gets |
| `age ASC LIMIT 3` | 93,144,415 | 2,083,119 | 91,061,296 | 4 entries, 4 refills, 0 row gets |
| `age DESC LIMIT 3` | 92,261,973 | 1,692,549 | 90,569,424 | 4 entries, 4 refills, 0 row gets |
| `name ASC LIMIT 3` | 90,861,504 | 1,966,039 | 88,895,465 | 4 entries, 4 refills, 0 row gets |

The closest measured non-DISTINCT covering peer, `age ASC LIMIT 3`, costs
1,366,834 instructions. The candidate is 716,285 instructions above that peer
and captures 99.220% of the measured predecessor-to-peer removable gap. A
larger execution convergence can therefore recover less than 0.8M realistic
instructions on this probe while risking a much larger state-space increase.

The candidate also preserves the important scaling property: physical work is
bounded by the requested distinct-group window, not by rows or duplicate
population. This is the actual database optimization commonly described as a
loose index scan or group-boundary seek. Sequential adjacent stopping is not
equivalent: the frozen fixture requires 385 ascending candidates and 1,793
descending candidates before the same logical output.

## Current Ownership And Execution Flow

```text
accepted EntityAuthority + logical plan + selected accepted index
  -> CoveringReadExecutionPlan admission
  -> one lowered immutable range
  -> one-entry structural component scan
  -> canonical component-prefix low/high boundary
  -> next group representative
  -> retained-slot page
  -> existing OrderedAdjacent DISTINCT finalizer
```

This flow is architecturally sound for the bounded cohort:

- accepted schema authority remains singular;
- the planner is the only eligibility authority;
- the executor does not consult generated models or reselect an index;
- the request uses the already lowered accepted-index range;
- prefix framing and envelope checks remain in the canonical index codec;
- row presence remains fail-closed through the existing covering decoder;
- skipped duplicates are never loaded or decoded as rows;
- canonical projected equality, offset, limit, lookahead and final output stay
  with the existing adjacent DISTINCT materializer; and
- the route adds no cache, persisted state, invalidation edge or public
  behavior surface.

The route is additive in code but convergent in semantics. Ineligible queries
retain the predecessor path; eligible queries rejoin the canonical projection
finalizer before result construction. This is a justified execution route, not
a parallel schema authority or a second SQL semantics implementation.

## Current Candidate Findings

### Strengths

The measured implementation has the right physical algorithm. It makes one
bounded range visit per representative, constructs the next raw group boundary
from canonical component bytes, and stops after the output window plus one
lookahead. The four original probes all remain below 2.2M instructions and
perform no data-row gets.

The current component row and returned raw anchor originate from the same
`IndexScan::components_chunk_structural` visitor. The component payload is
extracted from the decoded raw key before the row and anchor are returned.
Consequently, a second independent source cannot disagree about which physical
component owns the synthetic boundary. The later raw-anchor decode explicitly
checks component-zero equality before constructing the next bound; it is a
fail-closed consistency proof, not an authority split.

The final +6,292 raw Wasm bytes are entirely code. Data bytes, imports, exports
and Candid are unchanged. The earlier positional prototype was +6,094 bytes;
the opaque contract and explicit anchor/component check add 198 bytes. A
source-level attempt to remove the visible decoder monomorph and duplicate
accessor call made the prototype binary 186 bytes larger, proving that local
inlining changes are not a reliable path to a smaller or cleaner solution.

### Contract resolution

The prepared covering plan now owns one private
`OrderedDistinctGroupSeekContract` with named direction, projected slot,
offset and limit fields. Its sole constructor validates `OFFSET + LIMIT <= 3`,
and its representative budget is derived from those private window fields
rather than stored as a second fact. The executor receives no independent
pagination values, and finalization reads the window only through the same
covering-plan owner. The only remaining two-element handoff pairs the
representative vector with that owning plan; it does not expose positional
window scalars.

Conceptually, the retained structure is:

```rust
struct OrderedDistinctGroupSeekContract {
    direction: Direction,
    projected_slot: u16,
    output_offset: u8,
    output_limit: u8,
}

// All fields are private; representative_budget is derived.
```

Construction remains private to prepared covering-plan admission. Execution
obtains only derived accessors, and projection finalization does not reread
pagination from the logical plan. This replaced the prototype payload without
adding a planner or runtime behavior axis.

### Proof resolution

The focused evidence now covers:

- empty, one-group, exactly-three-group and mostly-unique distributions;
- inclusive outer bounds and descending non-zero offset;
- direct nullable fields, multi-term order and cursor rejection;
- corrupt raw key, corrupt witness and missing representative in both
  directions;
- heap and journal-overlay query equality, journal fold and reinstall;
- explicit SQLite result and order equality; and
- unchanged physical work for every incompatible fallback.

The six shipped 0.237 performance families also pass unchanged. The remaining
full repository validation is release-workflow-owned, not a missing Patch 1
design proof.

### Why canonical stream convergence is not the best solution

The existing `OrderedKeyStream` contract deliberately emits
`DecodedDataStoreKey`. Its wrappers reason about key order, held heads, budgets
and merge/intersection behavior. Group seeking needs different information:
the accepted index component bytes, the raw physical anchor, the index key kind
and arity, and permission to reposition the physical range to a synthesized
component boundary.

The existing `SeekableIndexRangeKeyStream` is not this capability. It positions
prefix-family leaves by primary-key target and is admitted only for that merge
shape. Generalizing it to component-group targets would either expose a method
that most stream variants cannot implement or require skip semantics to flow
through every wrapper. It would also not solve covering projection: the scalar
terminal would still need component payloads to avoid data-row gets.

The current covering lane already owns exactly those payloads. Moving them into
the generic scalar stream would relocate a narrow, proven primitive into a
broader abstraction without a measurable performance need. That is not useful
convergence.

## Recommended Performance-First Acceptance Contract

The maintainer accepted this audit and revised the existing 0.238 design in
place without creating Patch 2. The resulting decision contract is:

1. Keep the current cohort, maximum output window of three and at most four
   representatives.
2. Keep the planner-owned admission and direct covering group coordinator.
3. Replace positional tuples with one private opaque contract/window.
4. Keep canonical covering decode, fail-closed row presence, prefix-bound codec
   and adjacent DISTINCT finalization.
5. Complete every missing hostile, corruption, lifecycle, fallback and SQLite
   proof before release readiness.
6. Keep the 5M instruction, 75M absolute-saving and exact physical-work gates.
7. Keep Candid, exports, stable format, persisted state and public API equality
   as hard gates.
8. Report raw and gzip Wasm exactly, but treat raw growth as review evidence
   rather than an automatic failure for this slice.
9. Keep the current no-cache/no-state/no-new-module boundary. Do not use the
   relaxed Wasm decision to broaden query eligibility.
10. Run all six shipped 0.237 query-family regression proofs unchanged.

The tuple prototype was not accepted as it stood. The contract and proof gaps
were closed, and the resulting 6,292-byte raw growth remains proportionate to
the measured performance gain.

## Final Verdict

**BEST SOLUTION CONFIRMED: KEEP THE NARROW COVERING GROUP-SEEK IMPLEMENTATION;
DO NOT REWRITE THE GENERIC SCALAR STREAM.**

This verdict is performance-led but not performance-only. It preserves one
schema authority, one admission authority, canonical index encoding,
fail-closed corruption behavior and canonical DISTINCT semantics. It captures
nearly all measured removable work with bounded physical access. Contract
hardening and focused proof are complete; full release validation remains
user-owned.
