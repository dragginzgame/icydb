# IcyDB 0.237 Secondary Indexed Scalar MAX Convergence

Status: COMPLETE — PATCH 8

Design cut: 2026-08-23

Evidence authority: [0.237 status](./0.237-status.md)

Published predecessor: `v0.237.0`, commit
`86cd43227a0b7d7bcee1646f6af3384aa21ecd3c`.

## Outcome

Route one unfiltered, non-nullable direct-field scalar `MAX` through the
existing aggregate route planner and descending accepted-index edge even when
the maximum field value is not unique. The aggregate returns only the maximum
field value; it does not expose which tied row supplied that value. Therefore
the primary-key suffix chooses a deterministic physical row without changing
the scalar result.

This patch extends the bounded extrema owner introduced by Patch 5. It adds no
new executor route, index reader, cache, authority, or lifecycle state.

## Evidence And Removable Ceiling

The frozen clean Patch 3 scale profile measured `MAX(age)` at 99,224,647
instructions and 2,048 row reads. Patch 5 deliberately retained that query as
a full-reduction control because its accepted `age,id` index permits duplicate
age values.

A fresh focused `v0.237.0` predecessor measurement in the same local canister
configuration used for the Patch 8 candidate cost 114,777,435 instructions,
including 2,048 row reads and no index-entry reads. The existing descending
secondary endpoint already proved that one accepted index edge can be read in
about 1.2M instructions, so more than 98M instructions were theoretically
removable without changing physical authority.

## Canonical Owner And Flow

Accepted schema remains the only owner of field identity, nullability, primary
key identity, and accepted index order. SQL binding may project descending
execution intent only when the complete unfiltered `target, primary-key...`
order exists in accepted schema. The canonical planner still selects the
physical access path, and the aggregate route still proves reverse traversal,
target/index alignment, window safety, and bounded fetch.

```text
one unfiltered direct-field MAX terminal
  -> accepted schema proves non-null target and complete target/PK index order
  -> canonical planner selects the accepted index
  -> aggregate route proves descending reverse traversal and one-row fetch
  -> existing scalar reducer consumes one retained row
  -> MAX returns only the target value; tied row identity remains unobservable
```

The old tie-free helper duplicated a stricter row-identity rule after the
route had already proved target/index compatibility. Patch 8 removes that
second gate and its now-unused plan parameter. It does not weaken accepted
schema selection or route capability proof.

## Semantic Boundary

The bounded candidate requires exactly one direct-field `MAX` terminal with
no aggregate-local filter, no `DISTINCT`, no input window, and a non-nullable,
orderable target. A matching accepted primary or field-path index and physical
reverse traversal are mandatory.

Duplicate maximum values are safe because every tied row carries the same
projected target value. The primary-key suffix supplies deterministic physical
ordering only; it cannot change the aggregate value.

Secondary `MAX` with a query predicate is not admitted by this patch. An
exploratory upper-range candidate for `MAX(age) WHERE age < 43` returned the
correct value and read one row, but visited 13 index entries at 16 rows and 193
at 256 rows, costing 23,309,917 instructions at 256 rows. It did not begin at
the accepted upper range edge and exceeded the existing 10M bounded-extrema
ceiling. The query therefore retains complete reduction. Fixing descending
range-edge admission belongs to the separate Patch 9 intake.

Computed extrema, aggregate-local `FILTER`, multiple terminals, nullable or
unindexed fields, incompatible predicates, and unsupported reverse traversal
also retain complete reduction. Corrupt accepted-index rows remain fail-closed.

## State And Complexity Budget

Patch 8 may change only existing extrema lowering and route gates. It may
delete the redundant tie-free helper. It may not add a type, module, cache,
mutable owner, persisted state, invalidation edge, format, endpoint, public
behavior mode, or generated-model fallback.

The budget is at most six production files, 100 net runtime lines, and 4 KiB
raw Wasm growth. Any new state axis, result drift, corruption weakening, or
failure to save at least 75,000,000 instructions at 2,048 rows closes the
patch as a no-build.

## Required Proof

- exact results at 0, 16, 256, and 2,048 rows;
- duplicate maximum values still consume one deterministic descending edge;
- one data row and at most one index entry are read for admitted queries;
- true-warm execution retains the compiled-command cache contract;
- upper-range secondary `MAX`, computed extrema, aggregate `FILTER`, multiple
  extrema, nullable targets, and unindexed targets remain complete reductions;
- a missing row at the accessed descending edge fails closed;
- same-Wasm recovery preserves the result and existing authority lifecycle;
- no-default, SQL-only, and all-feature builds remain warning-clean; and
- generated code, Candid, exports, stable formats, package versions, and public
  APIs remain unchanged.

## Measured Outcome

The focused candidate passes the complete ladder:

| Rows | Candidate instructions | Row gets | Index entries |
| ---: | ---: | ---: | ---: |
| 16 | 1,293,930 | 1 | 1 |
| 256 | 1,369,826 | 1 | 1 |
| 2,048 | 1,414,045 | 1 | 1 |

Against the same focused `v0.237.0` predecessor measurement, the 2,048-row
saving is 113,363,390 instructions. True-warm execution costs 982,067
instructions with one compiled-command hit, one row read, and one index-entry
read.

The patch changes five production files by approximately 53 fewer net runtime
lines plus focused native, PocketIC, and recovery proofs. It adds no new state
or behavior axis. Release-shaped raw Wasm shrinks by 1,049 bytes from
4,583,069 to 4,582,020 bytes; a like-for-like gzip-9 comparison shrinks by 385
bytes from 1,776,699 to 1,776,314. Generated code, Candid, exports, stable
formats, package versions, and public APIs are unchanged.

Patch 8 is complete. It does not authorize or begin the separately planned
descending secondary range-edge Patch 9.
