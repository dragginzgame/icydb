# IcyDB 0.237 Indexed Scalar Extrema Convergence

Status: COMPLETE — PATCH 5

Design cut: 2026-08-22

Evidence authority: [0.237 status](./0.237-status.md)

## Outcome

Route one direct-field global SQL `MIN` or `MAX` through the executor's
existing aggregate route planner and bounded index-edge probe contract. The
change is deliberately narrower than general aggregate optimization:

- exactly one prepared aggregate terminal must remain after semantic
  de-duplication;
- the terminal must be a direct accepted field target;
- aggregate-local `FILTER` and expression inputs remain on the existing full
  reducer path;
- the accepted field must be orderable and have a route-compatible primary or
  field-path index; and
- `MAX` retains the existing tie-free rule; this first bounded slice projects
  an implicit descending order only for a scalar primary-key target.

The current 2,048-row costs are 102,814,331 instructions for `MIN(id)`,
105,158,825 for `MAX(id)`, 102,538,164 for `MIN(age)`, and 134,776,857 for
`MIN(age) WHERE age >= 31`. Each reads all 2,048 rows. Existing primary
first/last controls cost 846,218 and 853,302 instructions, establishing
absolute best-case removable ceilings of 101,864,622 and 104,195,066
instructions for the primary extrema.

## Canonical Owner And Flow

Accepted schema remains the only authority for field identity, type,
nullability, primary-key identity, and accepted index key order. SQL binding
may project an internal target-plus-primary-key order only when the accepted
schema contains that complete unfiltered field-path index order. It does not
name or execute an index. The canonical query planner still selects the access
path, and the canonical aggregate route planner still decides whether the
selected path admits an extrema seek:

```text
one prepared direct-field extrema terminal
  -> accepted schema admits a target/index order contract
  -> canonical query planner selects the access plan
  -> authority derives AggregateRouteShape
  -> canonical aggregate route planner proves direction, predicate and tie safety
  -> existing scalar kernel consumes the route-owned one-row fetch hint
  -> existing reducer returns the aggregate value
```

The prepared plan's existing aggregate execution-preparation resident owns
predicate capability evidence. The execution itself retains the existing
runtime predicate preparation and retained-slot reducer. No SQL-local index
scan, direct stable-store read, duplicate reducer, or generated-model fallback
is allowed.

## Semantic Boundary

The bounded candidate requires one direct field terminal with no
aggregate-local filter. Multiple aggregates, `MIN(expr)`, `MAX(expr)`, and
aggregate `FILTER` remain buffered. Query-level `WHERE` is allowed only when
the existing aggregate planner proves its selected access/predicate route
safe; uncertainty forces materialized execution and removes the bounded fetch.

Null semantics do not move. Nullable values are not indexable in the existing
accepted index encoding, so Patch 5 deliberately excludes every nullable
target from the bounded route. Mixed and all-null nullable inputs therefore
stay on complete reduction, where the existing reducer ignores nulls. An empty
non-nullable edge stream still finalizes to SQL null.

For `MIN`, any planner-selected compatible ascending index edge may establish
the minimum target value; ties do not alter that value. For `MAX`, this patch
does not weaken the route owner's conservative tie rule or synthesize a
secondary order. The measured non-unique composite `age,id` index therefore
does not authorize a bounded `MAX(age)` probe. It remains a required scan
control even if a broader terminal-specific proof might be technically
possible.

An internal order hint is permitted only when there is no semantic input
window and the accepted schema proves the exact direct-field
`target, primary-key...` order through an unfiltered field-path index. It is
execution intent for an order-insensitive single extrema reduction, not a new
SQL behavior. Queries with `LIMIT` or `OFFSET` retain their existing input
window semantics and receive no synthetic order.

## State And Complexity Budget

This patch adds no public behavior axis, mutable owner, cache, persisted
state, format, endpoint, Candid surface, export, stable-memory use, or new
route family. It activates the existing aggregate route plan for the scalar
SQL terminal sink and allows a route plan to replace the ordinary load plan
for that one execution.

The implementation budget is at most eight production files, 300 net runtime
lines, no new module, and no more than 8 KiB raw Wasm growth. It may add one
small immutable classification helper and consume the already-present
aggregate preparation resident. It may not add an extrema cache, alternate
index resolver, independent invalidation edge, or terminal-owned authority.
Exceeding this budget closes Patch 5 as a no-build.

## Required Proof

- exact primary `MIN` and `MAX` results at 0, 16, 256, and 2,048 rows;
- exact secondary `MIN` results at the same ladder, including a supported
  range predicate;
- repeated warm execution preserves the compiled-plan cache contract;
- multiple extrema, computed extrema, aggregate `FILTER`, non-orderable or
  unindexed fields, input windows, and non-tie-free secondary `MAX` remain
  conservative;
- empty non-nullable targets preserve SQL null rules, while nullable mixed and
  all-null targets are explicitly rejected to complete reduction;
- ascending and descending primary edges preserve signed-value ordering;
- publication and same-Wasm recovery rebuild or reuse only the existing
  accepted authority and prepared-plan lifecycle;
- route rejection falls back to complete reduction without result drift;
- result, stable extent, Candid, exports, public API, and package versions are
  unchanged; and
- no-default, SQL-only, and all-feature focused builds remain valid.

## Acceptance Gate

At 2,048 rows, retained primary `MIN(id)` and `MAX(id)` must each save at least
75,000,000 instructions and inspect at most one data row. Retained secondary
`MIN(age)` and its supported range form must each save at least 75,000,000
instructions, inspect at most one index entry and at most one data row, and
return the exact predecessor result. Warm execution must not regress. Raw Wasm
growth must remain within 8 KiB.

Any result drift, predicate underfill, null-semantic drift, acceptance of
non-tie-free `MAX(age)`, new authority/state, or failure of an absolute gate
closes the patch as a no-build. Gates are not weakened after measurement.

## Measured Outcome

The retained 2,048-row cases all clear the frozen 75,000,000-instruction
saving gate while reading at most one row. Secondary cases additionally read
exactly one index entry:

| Query | Predecessor | Candidate | Saving | Row gets | Index entries |
| --- | ---: | ---: | ---: | ---: | ---: |
| `MIN(id)` | 102,814,331 | 899,317 | 101,915,014 | 1 | 0 |
| `MAX(id)` | 105,158,825 | 910,110 | 104,248,715 | 1 | 0 |
| `MIN(age)` | 102,538,164 | 1,711,855 | 100,826,309 | 1 | 1 |
| `MIN(age) WHERE age >= 31` | 134,776,857 | 1,727,704 | 133,049,153 | 1 | 1 |

The same proof passes at 0, 16 and 256 rows. True-warm `MIN(id)` costs
579,445 instructions with one compiled-command hit. Non-tie-free `MAX(age)`,
computed `MIN`, aggregate `FILTER`, multiple extrema and unindexed `MIN`
remain complete reductions. Explicit global-aggregate order/limit semantics
retain the exact result while the canonical planner may still use its safe
bounded edge. Nullable targets are rejected before route construction and
therefore retain the predecessor reducer semantics; focused mixed and all-null
indexed fixtures confirm complete row reduction and exact SQL null handling.

Primary extrema results remain equal across same-Wasm recovery, and the
existing accepted-root publication-atomicity and signed numeric index-order
proofs pass. No schema, generated, Candid, export, stable-format, package
version or public API changes are introduced.

Patch 5 changes eight production files by approximately 180 net runtime lines
plus focused tests. It adds no module, mutable owner, cache, invalidation edge,
persisted state or authority. The existing aggregate preparation resident and
route planner gain one additional consumer, so maintained code complexity
rises modestly while lifecycle state-space remains unchanged. Raw Wasm is
4,579,290 bytes (`063bf521abe561d3ce61a1b6e30440afce13e1c885610238c4e64250c9b5fa4f`),
2,208 bytes above Patch 4 and within the 8 KiB gate.

Patch 5 is complete. It does not authorize or begin the separately planned
secondary ordered-limit work in Patch 6.
