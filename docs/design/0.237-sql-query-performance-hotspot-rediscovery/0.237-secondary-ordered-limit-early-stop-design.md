# IcyDB 0.237 Secondary Ordered `LIMIT` Early Stop

Status: COMPLETE — PATCH 6 GATES PASS

Date: 2026-08-22

Parent: [0.237 SQL performance design](./0.237-design.md)

## Outcome

Patch 6 evaluates one existing SQL load-route inefficiency: a cursorless,
non-`DISTINCT`, pure-covering projection whose selected secondary index already
satisfies the complete deterministic `ORDER BY` still materializes and checks
the complete index range before applying a finite `LIMIT`.

The implementation may make the existing index-component stream demand-driven
through the requested output window. It may not add a planner route, cache,
mutable owner, persisted state, cursor behavior, schema authority or public
surface.

## Accepted Evidence

The clean 0.237 calibration measured these 2,048-row queries:

| Query shape | Total | Store | Executor | Index entries | Result |
| --- | ---: | ---: | ---: | ---: | ---: |
| `ORDER BY age ASC, id ASC LIMIT 1` | 55,557,996 | 41,224,391 | 13,283,534 | 2,048 | `31` |
| `ORDER BY age DESC, id DESC LIMIT 1` | 55,361,305 | 41,027,857 | 13,283,534 | 2,048 | `43` |

The same families grow by approximately 54 million instructions from 16 to
2,048 rows while returning one covering value. Phase attribution and physical
work agree: the selected index route is correct, but the pure-covering terminal
requests an unbounded component vector because row presence is not
planner-proven, then checks all 2,048 candidates before applying the page.

## Frozen Scope

The candidate is admitted only when all of these facts already exist in the
prepared plan:

- scalar load, not grouped or aggregate execution;
- cursorless first-page execution through the existing pure-covering lane;
- no `DISTINCT` and no residual predicate or expression;
- exactly one lowered secondary index-range contract and no prefix-family
  contract;
- the planner-owned order contract is `IndexOrder` in either direction;
- a finite page `LIMIT` exists;
- every projected field is already covered by an index component, primary key
  component or constant.

`OFFSET` is counted over authoritative present rows. The stream may stop only
after it has checked and admitted `OFFSET + LIMIT` present rows or exhausted
the selected range.

The following remain on their existing routes: live cursor pages, continuation
requests, prefix sets, branch merges, materialized reorder, hybrid or row-backed
projection, residual predicates, `DISTINCT`, unbounded reads, aggregates and
unsupported order shapes.

## Ownership And Semantics

The existing planner remains the only owner of access selection and the order
contract. The accepted entity authority remains the only schema authority. The
existing lowered range remains the only physical index contract. Patch 6 adds
no fallback selection or reconstruction.

The executor-owned covering stream may pull bounded chunks from that range.
Every pulled entry retains current index decoding, budget charging and
corruption handling. When the covering plan requires a row-presence check, the
row store remains authoritative:

- a missing candidate under `Error` fails immediately with the existing typed
  missing-row error;
- a missing candidate under `Ignore` is not counted toward `OFFSET` or
  `LIMIT`, and the stream continues until the requested present-row window is
  full or the range is exhausted;
- malformed index keys, values or components retain their existing typed
  failures;
- entries beyond a satisfied SQL window are not accessed, matching bounded
  execution rather than treating `LIMIT` as a whole-index integrity scan.

No existence witness, cardinality, fingerprint or cache may replace the
authoritative row-presence check for a pulled candidate.

## Required Proofs

Correctness and route controls:

- empty, ascending and descending finite-limit results;
- `LIMIT 1`, a wider limit and `OFFSET` over duplicate secondary values;
- covered secondary, primary-key and multi-field projection assembly;
- a stale candidate before the requested window fails under the selected-index
  `Error` policy;
- order mismatch, residual predicate, no limit, `DISTINCT`, hybrid projection,
  prefix-family and live-page controls retain their prior routes;
- result rows, deterministic order and physical work remain equal to the
  predecessor for supported non-corrupt states;
- publication and same-Wasm recovery do not add lifecycle state.

Build and surface controls:

- focused core SQL tests;
- focused integration scale cases at 16, 256 and 2,048 rows;
- no-default, SQL-only and all-feature checks where supported;
- raw Wasm comparison, with gzip secondary;
- stable extent, Candid, exports, generated files and package versions
  unchanged.

## Measured Outcome

The exact PocketIC ladder passes at 0, 16, 256 and 2,048 rows. Each non-empty
endpoint reads exactly one index entry, performs no row fetch and returns the
predecessor result:

| Query | 16 rows | 256 rows | 2,048 rows | Predecessor at 2,048 | Saving |
| --- | ---: | ---: | ---: | ---: | ---: |
| ascending first age | 1,312,997 | 1,471,836 | 1,510,582 | 55,557,996 | 54,047,414 |
| descending last age | 1,090,399 | 1,168,590 | 1,211,211 | 55,361,305 | 54,150,094 |

Both savings clear the frozen 40,000,000-instruction gate. True-warm ascending
execution costs 1,079,099 instructions with one compiled-command cache hit,
one index entry and no row fetch.

The unbounded control still reads all 2,048 index entries. The uncovered-field
hybrid control still reads all 2,048 index entries and rows, proving that Patch
6 does not broaden into hybrid materialization. Focused native tests prove
ascending, descending, duplicate tie order, `OFFSET`, exact physical-work
limits and typed corruption when an accessed accepted-index candidate has no
authoritative row.

Same-Wasm recovery preserves both ordered endpoint results and stable-memory
extent. The existing atomic accepted-root publication proof passes. No-default,
SQL-only and all-feature core checks, formatting and the diff check pass.

Release validation exposed 42,741 added instructions on an unaffected
16-branch materialized covering page because the first implementation routed
existing materialized component vectors through the new fallible source
adapter. The final implementation restores the predecessor's direct loop for
all existing routes and keeps the fallible demand-driven source exclusive to
the new bounded single-range lane. The unaffected page measures 5,285,262
instructions against its unchanged 5,300,000 ceiling, versus 5,284,966 at the
Patch 5 parent, with the same 65 index entries and result.

Patch 6 changes two production runtime files by approximately 180 net lines
plus focused tests. It adds no module, mutable owner, cache, invalidation edge,
persisted state, schema authority, endpoint or public behavior mode. Raw Wasm
is 4,581,200 bytes in the isolated corrected Patch 6 snapshot, 1,910 bytes
above Patch 5 and within the 8 KiB gate. Generated code, Candid, exports,
stable formats and package versions remain unchanged.
