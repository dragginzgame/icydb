# IcyDB 0.237 Exact Entity Count SQL Convergence

Status: COMPLETE — PATCH 4

Design cut: 2026-08-22

Evidence authority: [0.237 status](./0.237-status.md)

## Outcome

Route one schema-proven row-equivalent global SQL `COUNT` through the existing
accepted-authority exact entity-cardinality terminal. This patch covers:

- `COUNT(*)`;
- non-distinct `COUNT` of a non-null literal;
- non-distinct `COUNT` of an accepted non-null field; and
- the same shapes with no predicate or a canonical constant-true predicate.

The current 2,048-row costs are 96,891,236 instructions for `COUNT(*)`,
97,310,566 for `COUNT(id)`, 96,928,342 for `COUNT(1)`, and 126,777,804 for
`COUNT(*) WHERE true`. All read 2,048 rows. The existing exact-prefix control
costs 1,218,508 instructions with no row traversal. The demonstrated removable
ceiling is therefore large enough to justify this bounded existing-owner
change.

## Canonical Owner And Flow

Accepted schema binding remains the sole owner of whether a field is non-null.
Query intent remains the sole owner of whether the complete load window and
predicate are eligible. The existing compiled global-count entry carries one
of the executor's already-maintained exact-cardinality target shapes:

```text
accepted schema binding proves row-equivalent COUNT
  -> query intent proves entity or exact-prefix eligibility
  -> compiled global-count entry binds the accepted schema fingerprint
  -> existing exact-cardinality executor reads Entity or UserIndexPrefixes
  -> unavailable metadata falls back to the existing aggregate scan
```

No generated model is consulted. A cache hit cannot establish authority: the
current accepted catalog supplies the entity authority and the cached entry is
usable only under its accepted-schema fingerprint. Publication replaces that
fingerprint and forces normal re-resolution.

## Semantic Boundary

Eligibility requires exactly one scalar `COUNT`, no aggregate `FILTER`, no
`DISTINCT`, no `HAVING`, no grouping, and an unbounded aggregate output window.
The input must be rows, a non-null literal, or a field that the accepted schema
proves non-null. Nullable fields, nullable expressions, false or nontrivial
predicates, limits/offsets that change visible output, and all non-count
aggregates retain the existing scan path.

Constant-true handling removes only a predicate whose canonical meaning is
unconditionally true. It does not widen SQL predicate admission or add a
second expression simplifier.

## State And Complexity Budget

This patch adds no public behavior axis, mutable owner, cache, persisted state,
format, route, mode, endpoint, Candid surface, export, or stable-memory use. It
extends the payload of the existing fingerprint-bound global-count cache entry
from prefix-only to the executor's existing entity-or-prefix distinction.

The implementation budget remains the audited maximum of six production
files, 250 net runtime lines, no new module, no more than 8 KiB raw Wasm growth,
and no gzip acceptance substitution. Exceeding the budget or requiring another
authority returns the patch to no-build review.

## Required Proof

- exact results at 0, 16, 256, and 2,048 rows;
- `COUNT(*)`, `COUNT(1)`, and accepted non-null `COUNT(field)` converge;
- nullable `COUNT(field)`, `COUNT(DISTINCT ...)`, aggregate `FILTER`, false and
  nontrivial predicates, and output-window edge cases do not use entity count;
- heap and journaled stores preserve insert/update/delete, overlay/fold, and
  recovery behavior through the existing entity-cardinality authority;
- compiled cold/warm reuse remains fingerprint-bound and publication-safe;
- unavailable metadata falls back without result drift;
- direct execution reports zero row and index traversal;
- result, physical work, stable extent, Candid, exports and public API remain
  unchanged; and
- no-default, SQL-only and all-feature focused builds remain valid.

## Acceptance Gate

At 2,048 rows, each retained row-equivalent count must save at least 75,000,000
instructions, perform zero row and index traversal, and preserve its exact
result. Warm behavior must not regress. Raw Wasm growth must remain within the
8 KiB budget. Failure of any gate closes Patch 4 as a no-build and leaves the
other hotspot designs independent.

## Measured Outcome

The accepted design passed. At each retained scale point, every row-equivalent
form returns the exact entity count with zero data-row gets and zero index-entry
reads:

| Form | 16 rows | 256 rows | 2,048 rows | Predecessor at 2,048 | Absolute saving |
| --- | ---: | ---: | ---: | ---: | ---: |
| `COUNT(*)` | 803,077 | 801,636 | 815,629 | 96,891,236 | 96,075,607 |
| `COUNT(id)` | 841,583 | 840,360 | 854,348 | 97,310,566 | 96,456,218 |
| `COUNT(1)` | 832,834 | 831,611 | 845,599 | 96,928,342 | 96,082,743 |
| `COUNT(*) WHERE true` | 816,440 | 813,662 | 827,751 | 126,777,804 | 125,950,053 |

The absolute savings exceed the 75,000,000-instruction gate by
21,075,607–50,950,053 instructions. Percentage reductions are 99.12%–99.35%
and are secondary to those absolute results. A true-warm `COUNT(*)` after the
existing update-owned cache fill costs 731,475 instructions and records the
expected compiled-command cache hit.

An isolated zero-row heap fixture returns zero without a row read. An accepted
nullable field containing one value and one null returns one from
`COUNT(nullable_field)` while reading both rows, proving that schema
nullability remains semantic authority. `DISTINCT` and aggregate `FILTER`
controls likewise retain 2,048-row buffered execution.

The pre-existing exact-cardinality owner continues to prove heap replacement,
insert/delete, journal overlay, fold, malformed-key fail-closed behavior and
durable-base/live-delta convergence. The focused recovery closeout also passes
ordinary readiness gating and exact counts before and after same-Wasm upgrade.

The implementation uses six production files and approximately 90 net runtime
lines. It adds one private entity-or-prefix payload distinction to the existing
fingerprint-bound compiled count entry, but no mutable owner, cache,
invalidation edge, authority, endpoint, public API or persisted state. This is
a small local complexity increase with lifecycle state-space unchanged. Raw
release Wasm grows by 453 bytes, from 4,576,629 to 4,577,082 bytes, within the
8 KiB gate. No generated, Candid, export, stable-format or package-version file
changes.
