# IcyDB 0.237 Compound One-Sided Range Edge Convergence

Status: COMPLETE — PATCH 9

Design cut: 2026-08-23

Evidence authority: [0.237 status](./0.237-status.md)

Published predecessor: `v0.237.1`, commit
`105da497de3d9868a70810003a32ac65a28a8d60`.

## Outcome

Let the canonical access planner lower a single ordered comparison on the
leading component of a compound accepted index into its existing one-sided
index-range contract. The existing aggregate route can then consume that
selected range for compatible `MIN` and `MAX` edge probes without any new SQL
or executor admission rule.

This is the ordinary B-tree leading-component rule applied to the range family
IcyDB already owns. It adds no aggregate-specific index reader, route family,
cache, authority or lifecycle state. Scalar reads and compatible `MIN` probes
benefit from the same planner correction.

## Evidence And Removable Ceiling

The `v0.237.1` runtime accepts two-sided ranges on the compound accepted
`age,id` index, but explicitly rejects a single one-sided compare when index
arity is greater than one. Consequently simple ordered `LIMIT 1` queries scan
all 2,048 index entries, while `MAX(age) WHERE age < 43` falls back to 2,048
row reads.

| Query | `v0.237.1` instructions | Physical work |
| --- | ---: | --- |
| `MAX(age) WHERE age < 43` | 121,581,549 | 2,048 row reads |
| `MIN(age) WHERE age > 31` | 15,757,520 | 129 index entries, one row |
| `age < 43 ORDER BY age DESC, id DESC LIMIT 1` | 246,977,320 | 2,048 index entries |
| `age > 31 ORDER BY age ASC, id ASC LIMIT 1` | 274,751,259 | 2,048 index entries |

Equivalent two-sided controls already cost approximately 1.47M instructions
and read one index entry. A temporary three-gate prototype, removed before the
Patch 8 handoff, measured the one-sided candidates at 1.15M–1.44M instructions
with exact results and one index entry. The removable phase is therefore
observed and substantially larger than the proposed change.

## Canonical Owner And Flow

Accepted schema remains the only authority for index identity, key order,
field type, nullability and primary-key suffix. SQL aggregate binding may
project order intent but cannot select or execute an index. The canonical
planner remains the sole access selector, and existing semantic-to-raw range
lowering remains the sole bound encoder.

```text
single leading-field <, <=, > or >= compare
  -> accepted visible-index authority supplies candidate contracts
  -> canonical access-choice evaluator admits the compound leading range
  -> canonical compare planner emits SemanticIndexRangeSpec
  -> existing raw-key lowering fills trailing components with low/high sentinels
  -> existing forward/reverse range stream begins at the requested edge
```

For the aggregate target, the planner-chosen range supplies the accepted index
contract. The existing aggregate route continues to prove direct-field target
compatibility, nullability, direction, reverse traversal and the one-row fetch.
SQL binding does not gain another predicate classifier or index decision.

No SQL-local fallback may reconstruct an index, encode a bound, or bypass the
accepted planner. A failed candidate keeps the existing complete-reduction
route.

## Semantic Boundary

The planner correction applies to one ordered `Compare` predicate over the
leading key item. Remaining compound key components are unconstrained and are
covered by the existing raw-bound low/high sentinels. Strict versus inclusive
bounds keep their existing group semantics: an excluded component excludes
every trailing-key row in that component group, while an included component
includes the complete group.

Conjunction extraction, equality prefixes, two-sided ranges, text-prefix
ranges, filtered-index implication, residual filters and candidate ranking do
not change. Primary-key ranges are unchanged.

Filtered secondary extrema retain the existing aggregate capability rules:
one direct non-null field terminal, no aggregate-local filter, a compatible
selected accepted index and supported physical direction. Both lower and upper
one-sided ranges may therefore use the existing edge probe once the planner
selects their bounded compound path. Existing two-sided ranges are unchanged.

Predicates on another field, expressions, tautologies, unsupported coercions,
nullable or unindexed targets, multiple terminals and aggregate `FILTER`
remain conservative. The patch does not optimize `WHERE true`; that is a
separate normalization question.

Empty and duplicate-value ranges retain SQL semantics. An empty aggregate
returns SQL null. Duplicate edge values may choose any deterministic
primary-key-suffixed row because every retained row supplies the same scalar
extremum. Any accessed stale or missing row remains a typed corruption failure.

## State And Complexity Budget

Patch 9 may modify only the existing access-choice evaluator, compare planner
and rejection taxonomy. It may remove the obsolete single-field-only
rejection. It may not add a SQL classifier, type, module, executor route,
mutable owner, cache, invalidation edge, persisted state, format, endpoint,
generated-model fallback or public behavior mode.

The budget is at most four production files, 40 net runtime lines and 2 KiB raw
Wasm growth. Runtime state-space must remain unchanged. Exceeding any bound
closes the patch as a measured no-build.

## Required Proof

- exact `<`, `<=`, `>` and `>=` leading-component semantics over duplicate
  values and a compound secondary index;
- exact empty-range behavior;
- `MAX(age) WHERE age < 43`, `MIN(age) WHERE age > 31`, and ascending/descending
  covering `LIMIT 1` results at 0, 16, 256 and 2,048 rows;
- ascending and descending covering `LIMIT 3` stop after three entries;
- exactly one physical range and at most one index-entry and row read for
  populated accepted candidates;
- excluded bounds skip the complete duplicate component group;
- compatible target-field lower bounds retain exact bounded `MAX` results;
- other-field predicates, `WHERE true`, expressions, aggregate `FILTER` and
  multiple extrema remain conservative for secondary `MAX`;
- true-warm execution retains compiled-command cache reuse;
- an accessed missing range-edge row fails closed;
- same-Wasm recovery preserves result and existing authority lifecycle;
- no-default, SQL-only and all-feature focused builds remain warning-clean;
  and
- generated code, Candid, exports, stable formats, package versions and public
  APIs remain unchanged.

## Acceptance Gate

At 2,048 rows, `MAX(age) WHERE age < 43` must save at least 100,000,000
instructions from its frozen 121,581,549 predecessor and remain below
10,000,000 instructions. Each retained ordered `LIMIT 1` case must save at
least 200,000,000 instructions, and `MIN(age) WHERE age > 31` must save at least
10,000,000. Every admitted populated case must read at most one index entry and
one data row.

Any result drift, bound-group error, corruption weakening, new state or
authority, raw Wasm growth above 2 KiB, or failure of an absolute instruction
gate closes Patch 9 as a no-build. Gates are not weakened after measurement.

## Measured Outcome

The focused 0/16/256/2,048 PocketIC ladder passes with exact results. At 2,048
rows:

| Query | Predecessor | Candidate | Saving | Row gets | Index entries |
| --- | ---: | ---: | ---: | ---: | ---: |
| `MAX(age) WHERE age < 43` | 121,581,549 | 1,213,725 | 120,367,824 | 1 | 1 |
| `MIN(age) WHERE age > 31` | 15,757,520 | 1,444,681 | 14,312,839 | 1 | 1 |
| descending upper-range `LIMIT 1` | 246,977,320 | 1,153,168 | 245,824,152 | 0 | 1 |
| ascending lower-range `LIMIT 1` | 274,751,259 | 1,343,875 | 273,407,384 | 0 | 1 |

Inclusive, exclusive, empty and duplicate-component-group semantics pass in
both directions. At 2,048 rows, the corresponding descending/ascending
covering `LIMIT 3` reads cost 1,427,077/1,619,273 instructions, read exactly
three index entries and fetch no rows. True-warm upper-range `MAX` costs
824,989 instructions with one compiled-command hit and the same bounded
physical work. Accessed-corruption and same-Wasm recovery proofs pass.
No-default, SQL-only and all-feature focused checks are warning-clean.

The implementation deletes ten net runtime lines across the existing access
evaluator, rejection taxonomy and compare planner. It adds no runtime type,
state or behavior axis. Against an isolated exact `v0.237.1` archive built by
the same current pipeline, raw final-deployable Wasm shrinks by 108 bytes from
4,450,084 to 4,449,976 and deterministic gzip shrinks by four bytes from
1,728,371 to 1,728,367. Candid is byte-identical. Patch 9 is complete.
