# IcyDB 0.237 Checked-Hybrid Finite-Window Route Narrowing

Status: COMPLETE — PATCH 10 GATES PASS

Design cut: 2026-08-23

Evidence authority: [0.237 status](./0.237-status.md)

Candidate predecessor: commit
`14955cc29f39e212b976e4edfe48c14d085fbc05` (`0.237.2`, not published).

## Outcome

Stop the specialized checked-hybrid projection route from preempting the
existing canonical bounded scalar path for one cursorless, non-`DISTINCT`,
residual-free, finite window whose single selected secondary index range
already satisfies complete deterministic order.

This is a subtractive route-admission correction. It does not add a hybrid
stream, route, cache, authority, mode or state. Pure covering reads and
planner-proven hybrid reads remain unchanged. `DISTINCT` remains outside this
patch.

## Current Evidence

At 2,048 rows the selected `age,id` index and requested order are already
correct, but a direct row-backed projection enters the checked-hybrid terminal.
That terminal materializes all selected index candidates and reads their row
fields before applying the finite page window:

| Query shape | `LIMIT 1` | `LIMIT 3` | Row gets / index entries |
| --- | ---: | ---: | ---: |
| `SELECT name`, `age < 43` | 71,574,774 | 71,581,154 | 512 / 512 |
| `SELECT name`, unbounded age order | 291,267,361 | 291,273,583 | 2,048 / 2,048 |

The cost is effectively independent of the requested window. The bounded
range shape grows from 1,770,352 instructions and four candidates at 16 rows,
through 9,985,327 and 64 candidates at 256 rows, to 71,581,154 and 512
candidates at 2,048 rows. The unbounded shape grows from 3,248,231/16 through
37,201,177/256 to 291,273,583/2,048.

Equivalent or broader projections already prove that the canonical scalar path
owns the required demand-driven behavior:

| Control at 2,048 rows | Instructions | Row gets | Index entries |
| --- | ---: | ---: | ---: |
| covering `SELECT age ... LIMIT 3` | 1,427,077 | 0 | 3 |
| schema-equivalent `COALESCE(name, '') ... LIMIT 3` | 1,862,889 | 3 | 4 |
| `LOWER(name) ... LIMIT 3` | 1,835,380 | 3 | 4 |
| `SELECT * ... LIMIT 3` | 1,927,796 | 3 | 4 |

The smaller alternative is therefore to decline the specialized hybrid plan,
not to build a second demand-driven projection implementation. The realistic
bounded-range saving ceiling is approximately 69.7 million instructions; the
unbounded ceiling is approximately 289 million.

## Canonical Owner And Boundary

Accepted `SchemaInfo` remains the authority for projection fields, index
components and row-backed fields. The access planner remains the authority for
the selected index range and deterministic order. Hybrid projection-plan
admission is the only owner changed by this patch.

The hybrid execution plan is not produced only when all of these are true:

- scalar load with no `DISTINCT`;
- no residual filter expression or predicate;
- one selected `IndexRange` access path;
- the accepted index range supplies complete `IndexOrder`;
- a finite authored `LIMIT` exists; and
- hybrid projection would still require authoritative row reads.

Absence of that optional optimization plan makes the existing projection
facade fall through to its canonical scalar retained-row path. No execution
policy is reconstructed downstream. `EXPLAIN` observes the same absent hybrid
plan and therefore remains aligned with runtime.

Index-prefix, multi-lookup, branch-set, primary-store, unbounded-result,
`DISTINCT`, cursor and continuation shapes retain their existing decisions.
Pure covering remains preferred before hybrid admission.

## Semantics And Corruption

The canonical scalar path retains exact projection values, deterministic
order, `OFFSET`, limit and missing-row policy. It reads only candidates needed
to fill the requested present-row window plus existing lookahead. A missing or
corrupt row that is accessed remains a typed failure. Entries beyond a
satisfied finite window are not an implicit integrity scan, matching the
bounded semantics already accepted for Patch 6.

No error taxonomy, public result, stable representation, cursor encoding,
generated code, Candid or export changes.

## Required Proof

- direct `name` and `id,name` projections for bounded and unbounded secondary
  age order at 0, 16, 256 and 2,048 rows;
- ascending and descending `LIMIT 1`, `LIMIT 3` and non-zero `OFFSET`;
- exact result and SQLite-reference equality;
- at most `OFFSET + LIMIT + 1` index entries and at most `OFFSET + LIMIT` row
  reads for populated supported shapes;
- the hybrid-path diagnostic is absent and the canonical scalar path is used;
- accessed missing rows fail closed while an unaccessed row beyond the
  satisfied window does not change the result;
- no-limit, `DISTINCT`, prefix-family, cursor, residual and incompatible-order
  controls retain their existing route;
- true-warm compiled-command reuse;
- same-Wasm recovery preserves results;
- no-default, SQL-only and all-feature focused builds;
- stable extent, Candid, exports, generated files, package versions and public
  APIs remain unchanged.

## Frozen Gates

At 2,048 rows, bounded `SELECT name ... LIMIT 3` must save at least 60,000,000
instructions and unbounded-age-order `SELECT name ... LIMIT 3` must save at
least 250,000,000. Both candidates must cost less than 10,000,000 instructions
and remain bounded to at most four index entries and three row reads.

The implementation budget is at most two production files and 30 net runtime
lines. It must add no type, enum variant, module, route, mutable owner, cache,
invalidation edge, persisted state, behavior mode or authority. Any result,
order, corruption, route, feature, artifact or absolute-gate failure closes the
patch as a no-build. Gates are not weakened after measurement.

## Measured Outcome

The candidate declines the optional hybrid plan during covering-plan admission
and therefore converges on the pre-existing scalar executor. The exact
PocketIC ladder passed:

| Shape and rows | Predecessor | Candidate | Saving | Row gets | Index entries |
| --- | ---: | ---: | ---: | ---: | ---: |
| bounded, 16 | 1,770,352 | 1,721,572 | 48,780 | 3 | 4 |
| bounded, 256 | 9,985,327 | 1,732,279 | 8,253,048 | 3 | 4 |
| bounded, 2,048 | 71,581,154 | 1,770,593 | 69,810,561 | 3 | 4 |
| unbounded, 16 | 3,248,231 | 1,653,866 | 1,594,365 | 3 | 4 |
| unbounded, 256 | 37,201,177 | 1,805,482 | 35,395,695 | 3 | 4 |
| unbounded, 2,048 | 291,273,583 | 1,859,072 | 289,414,511 | 3 | 4 |

Both maximum-shape savings clear their frozen 60,000,000 and 250,000,000
gates, and both candidates remain below 1.9 million instructions. True-warm
bounded execution costs 1,204,324 instructions with one compiled-command hit
and the same bounded physical work.

Exact `name` and `id,name` projections, ascending and descending order,
non-zero `OFFSET`, empty fixtures, `EXPLAIN`, and same-Wasm recovery pass. The
existing no-limit and token-prefix controls retain hybrid attribution. The
existing focused missing-row test continues to prove that an accessed absent
row fails closed; the candidate reuses that scalar behavior rather than adding
another corruption policy. `DISTINCT`, residual and incompatible shapes remain
outside admission.

The implementation changes one production file by 23 net runtime lines and
adds no type, enum variant, module, route, mutable owner, cache, invalidation
edge, persisted state, behavior mode or authority. Against the Patch 9
candidate, final raw Wasm grows by 164 bytes from 4,449,976 to 4,450,140 and
deterministic gzip grows by 37 bytes from 1,728,367 to 1,728,404. Candid is
byte-identical. All frozen gates pass.
