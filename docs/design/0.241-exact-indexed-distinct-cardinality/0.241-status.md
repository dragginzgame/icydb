## Outcome

Patch 1 implements the one approved 0.241 slice. A bare global
`COUNT(DISTINCT direct_non_nullable_int32_field)` may now count synchronized
non-empty leading-component metadata from one planner-selected complete
accepted user index. Every other shape retains the prepared executor.

The implementation is a hard cut onto the renamed singular `exact_count`
owner. It adds one target variant to the existing fingerprint-bound
exact-or-prepared compiled slot. It adds no cache, result memo, mutable owner,
persisted field, invalidation edge, mode, compatibility path, public method or
accepted-schema authority.

## Correctness And Authority Result

- SQL lowering owns one immutable exact-distinct shape fact. Authored
  `ORDER BY`, even when semantically inert for a single aggregate row, is
  retained long enough to reject admission.
- The accepted query planner owns deterministic complete-index selection. It
  reuses the established shortest-arity, then stable-name rule; session and
  executor code cannot search for another index.
- The compiled command retains one exact-or-prepared `OnceLock` entry. The new
  payload is only an accepted `IndexId`; it cannot select schema or prove
  freshness.
- The executor verifies that the target belongs to the pinned accepted entity
  root and reads metadata only through `StoreHandle`.
- `IndexPrefixCardinality` now formally owns exact synchronized leading-key
  multiplicity. Decoding failure, generation mismatch, unmaterialized
  metadata or non-Ready store state produces unavailability, never zero.
- Mutation remains conservative: supported raw index changes invalidate the
  metadata generation before they can affect a result. Existing mutation,
  rollback, replay and fold publication continues to stamp synchronization
  only after the row/index/metadata transition completes.
- Stop-after is the minimum remaining capacity across the active execution
  and request scopes. Exact success commits all DISTINCT-state and result
  charges through the canonical budget owner as one atomic bundle.
- The canonical scalar-DISTINCT reducer now owns the conservative retained
  value/hash/collision layout calculation. The exact route consumes that fact
  instead of reconstructing reducer layout in the executor.
- Impossible zero multiplicity and checked metadata-count or budget-layout
  overflow are typed invariant failures. They cannot be reclassified as
  optional metadata unavailability and hidden by prepared fallback.
- Unavailable or over-budget evidence enters the one existing prepared
  fallback before output begins. It retains no speculative semantic charge.

## Complexity Delta

The implementation is materially faster and state-space neutral, but its
proof footprint is larger than the design's initial six-file/~300-line
forecast. The runtime delta is approximately +510 net lines across 13
substantive production Rust files plus narrow module wiring; the hard-cut
owner rename is included in that count.

Those files span required authority seams rather than independent behavior:
SQL authored-shape capture and binding, accepted planner selection, the one
compiled slot, exact-count session orchestration, canonical budget ownership,
the exact executor, and the existing index-metadata owner. There are zero new
production types, modules after the rename, cache slots, mutable owners,
persisted states or invalidation edges. Current governance treats file/domain
counts as review signals, not execution limits; the zero-state/type/cache gate
remains hard.

Implementation shape became more complex in maintained logic because exact
result authority and atomic budget semantics are now explicit. The complexity
is localized and proportional to a 120.2M-instruction demonstrated saving; no
generic aggregate or cache framework was introduced.

Closeout removed two avoidable ownership duplications: lowering now carries
the admitted target slot instead of retaining a boolean and re-deriving the
field in session code, and the request budget exposes one checked atomic commit
operation rather than a public preflight plus unchecked commit pair. The large
0.241 integration test was split into evidence-specific helpers and no longer
needs a Clippy line-count suppression.
