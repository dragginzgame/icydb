# 0.224 Coherent SQL Introspection Surfaces

Status: proposed slice authority; implementation not started

Design cut: 2026-08-08

Predecessor: the published 0.223 closeout; the exact release, commit, tree,

## Planning Status

This document assigns one substantive SQL-introspection landing slice to the
0.224 line. It is not yet a complete 0.224 minor-line tracker. Implementation
must not start until:

1. 0.223 has a reported ready/complete closeout;
2. the user explicitly directs implementation of 0.224; and
3. a 0.224 status tracker groups the complete line into roughly six to eight
   meaningful landing patches.

Parser, typed-result, execution, renderer, Candid, tests, help, and release-note
fallout from this decision belong to this one slice. They must not be split
into artificial micro-patches merely to fill the minor-line plan.

This work must not be folded back into 0.222 streaming execution or combined
with 0.223 durable mutation jobs.

## Decision Summary

`DESCRIBE <entity>` becomes a compact, conventional one-table column summary.
The current multi-section entity dossier moves to the explicit
`DESCRIBE <entity> VERBOSE` form.

The command family becomes:

| Command | Human-facing result |
| --- | --- |
| `DESCRIBE Card` | One compact columns table |
| `DESCRIBE Card VERBOSE` | The complete current entity dossier |
| `SHOW ENTITY Card [VERBOSE]` | Entity/catalog summary |
| `SHOW COLUMNS Card` | The same compact column rows as `DESCRIBE Card` |
| `SHOW COLUMNS Card VERBOSE` | Detailed field and layout metadata only |
| `SHOW INDEXES FROM Card` | Indexes only |
| `SHOW CONSTRAINTS FROM Card` | Constraints only |
| `SHOW RELATIONS FROM Card` | Relations only |

`VERBOSE` is the sole detail modifier. IcyDB already uses that vocabulary for
`SHOW ENTITY`, `SHOW ENTITIES`, `SHOW STORES`, and `EXPLAIN`. This design does
not add `FULL`, `EXTENDED`, `DESC`, or section selectors such as
`DESCRIBE Card INDEXES`.

## User Outcome

The common command is immediately scannable:

```text
icydb> DESCRIBE Card;
+--------+----------+----------+-----+---------+----------+
| name   | type     | nullable | key | default | extra    |
+--------+----------+----------+-----+---------+----------+
| id     | Ulid     | no       | PRI | auto    | identity |
| rarity | Text(32) | no       | MUL | common  | -        |
+--------+----------+----------+-----+---------+----------+
```

Operators who need the complete accepted-schema report request it explicitly:

```text
DESCRIBE Card VERBOSE;
```

The verbose form retains the current entity path, row-layout window, identity
state, fields, indexes, relations, and constraint-validation sections.

## Current Problem

The current `DESCRIBE` response always constructs and renders an
`EntitySchemaDescription`. Its shell output contains:

- entity path and row-layout metadata;
- identity generator range and high-water state;
- a fifteen-column field table containing migration-era details;
- indexes;
- relations; and
- constraints plus validation progress.

That information is valuable, but the default command behaves like an
operational schema dossier rather than the familiar SQL column summary. It is
harder to scan, transfers more typed data than the common case needs, and
duplicates the narrower `SHOW COLUMNS`, `SHOW INDEXES`, and
`SHOW CONSTRAINTS` surfaces.

Relations are the exception: they currently appear in the full dossier but do
not have a narrow SQL command.

## Syntax Contract

The accepted grammar is exactly:

```text
DESCRIBE <entity> [VERBOSE]
SHOW COLUMNS <entity> [VERBOSE]
SHOW RELATIONS (FROM | IN) <entity>
```

Keywords remain case-insensitive. Schema-qualified entity identifiers retain
their current behavior. A trailing token other than the admitted modifier
returns a typed parser diagnostic. `DESCRIBE VERBOSE Card`, repeated
`VERBOSE`, `FULL`, `EXTENDED`, and section-selector spellings are rejected.

The parser carries mode explicitly:

```text
DescribeMode {
    Compact,
    Verbose,
}
```

The compiled metadata command must also retain that mode. Execution must not
infer output shape from the renderer or reconstruct the parsed SQL text.

## Compact Column Contract

The compact row is a dedicated typed projection, not a truncated verbose DTO.
Exact Rust names remain implementation-owned, but the semantic payload is:

```text
ColumnSummary {
    name,
    type,
    nullable,
    key,
    default,
    extra,
}
```

The shell columns are fixed and ordered as shown. Their authority is:

- `name`: the accepted query-visible field name or nested field path;
- `type`: the accepted field-kind rendering;
- `nullable`: the accepted explicit-null contract;
- `key`: a compact index-membership hint;
- `default`: the accepted insert-omission/default summary; and
- `extra`: bounded typed flags such as identity, generated, or relation.

`key` uses this precedence:

1. `PRI` for the accepted primary key;
2. `UNI` for membership in an accepted unique secondary index;
3. `MUL` for membership in an accepted non-unique secondary index; and
4. `-` when none apply.

For a compound index, `UNI` or `MUL` communicates membership, not independent
single-field uniqueness. `SHOW INDEXES FROM <entity>` remains authoritative
for ordered key composition, uniqueness, and index identity.

The default summary is derived only from accepted insert semantics. It may
render `auto`, `NULL`, a bounded canonical accepted default, or `-` for a
required field without a default. It must not inspect generated models or
invent a value from the Rust field type.

The typed payload uses enums or otherwise bounded typed values for key/default
and extra classifications. Free-form renderer strings are not runtime
authority.

## Verbose Contract

`DESCRIBE <entity> VERBOSE` owns the current full
`EntitySchemaDescription` behavior. Its sections remain:

1. entity identity and path;
2. row-layout current and history-floor versions;
3. identity-generator state, when present;
4. detailed fields;
5. indexes;
6. relations; and
7. constraints and validation progress.

`SHOW COLUMNS <entity> VERBOSE` returns only the detailed field table. It does
not become a second spelling for the complete dossier.

`SHOW RELATIONS FROM <entity>` returns the maintained typed relation
descriptions. Its compact shell table contains `field`, `target`, and
`cardinality`; the typed response retains accepted target identity required by
non-shell consumers.

## Authority And Execution

Accepted schema snapshots remain runtime authority. Compact and verbose
projections must resolve one accepted catalog context and derive every row from
that same context.

Compact execution must not construct the full verbose report and discard most
of it afterward. In particular, ordinary `DESCRIBE` and `SHOW COLUMNS` must not
load identity high-water state, constraint-validation jobs, or full relation
and constraint sections merely to render columns.

The compact projection may read accepted fields, indexes, and relation facts
needed for the six fixed columns. The verbose path retains the existing full
metadata collection. `SHOW RELATIONS` projects relation facts directly from
the accepted catalog.

Generated `EntityModel` and `IndexModel` remain proposal and convenience
surfaces. No introspection command may reconstruct runtime output from them
when accepted authority is missing.

A named entity absent from accepted schema authority retains the typed
not-found diagnostic established before this line:

```text
E_RUNTIME_NOT_FOUND: SQL query target entity was not found in the accepted schema
```

Compact and verbose modes must produce the same not-found classification.

## Typed Result And Hard Cut

Mode must remain visible through core statement results and the public SQL
query result. The maintained shape should use one discriminated describe
output, conceptually:

```text
DescribeOutput {
    Compact { entity, columns },
    Verbose { description },
}
```

The implementation must not use an object containing two optional payloads,
must not infer the mode from which fields happen to be populated, and must not
keep the old default full-response variant as a fallback.

This is a pre-1.0 public SQL/Candid hard cut. Clients that decode or match the
current `DESCRIBE` result must move to the discriminated current form and send
`VERBOSE` when they require the dossier. There is no persisted-data migration,
cursor migration, compatibility alias, or dual dispatch path.

`SHOW COLUMNS` must share the canonical compact projection with compact
`DESCRIBE`, while retaining its own statement identity in parsing and surface
diagnostics. Shared projection does not mean one command is reparsed or
rewritten into the other.

## Non-Negotiable Invariants

1. Default `DESCRIBE` renders exactly one table and no metadata preamble or
   additional section.
2. Compact and verbose output are derived from one accepted catalog context per
   command.
3. Compact execution does not construct identity or constraint-validation
   state that its result cannot expose.
4. `DESCRIBE` and `SHOW COLUMNS` compact rows are semantically identical for
   the same accepted entity snapshot.
5. Index hints never claim that one member of a compound unique index is
   independently unique.
6. Verbose `DESCRIBE` retains all currently maintained dossier sections.
7. Relation output follows accepted relation authority and never generated
   model fallback.
8. Missing entities return typed not-found diagnostics in every mode.
9. Parser, core result, public result, Candid, and shell renderer preserve the
   selected mode explicitly.
10. Production introspection paths remain bounded, fallible, and non-panicking.

## Scope

This slice adds or changes:

- compact and verbose `DESCRIBE` grammar;
- a dedicated typed compact column summary;
- mode-preserving compiled commands and result envelopes;
- compact and verbose `SHOW COLUMNS` behavior;
- typed `SHOW RELATIONS FROM|IN` introspection;
- deterministic one-table compact rendering;
- shell help and active SQL documentation;
- Candid/result contract fixtures; and
- focused instruction, raw Wasm, and complexity evidence.

This slice does not add:

- `DESC`, `FULL`, `EXTENDED`, or compatibility spellings;
- arbitrary `DESCRIBE` section selectors;
- `SHOW CREATE ENTITY` or DDL reconstruction;
- JSON/text output modes beyond the maintained typed response and shell table;
- schema diffing, historical schema browsing, or cross-canister discovery;
- public access-policy changes to controller-gated introspection;
- generated-model runtime fallback; or
- changes to storage, accepted schema persistence, query cursors, or mutation
  jobs.

## Landing Boundary

This is one reviewable landing patch once the 0.224 line is authorized. It is
complete only when grammar, accepted projection, execution, public DTOs,
Candid, rendering, diagnostics, fixtures, documentation, and the `Unreleased`
note agree on the hard-cut surface.

If implementation reveals an independently useful outcome beyond this
contract, it must be proposed as another planned 0.224 slice rather than folded
into this patch. Direct exhaustive-match, fixture, and generated-surface fallout
remains part of this patch.

## Validation And Evidence

Focused validation must cover:

- parser acceptance and rejection for every admitted modifier position;
- schema-qualified and case-insensitive entity resolution;
- compact rows for primary, unique, compound, and non-unique index membership;
- required, nullable, identity, generated, and bounded-default fields;
- nested query-visible field paths;
- compact `DESCRIBE`/`SHOW COLUMNS` semantic equality;
- verbose preservation of identity, layouts, indexes, relations, constraints,
  and validation progress;
- `SHOW RELATIONS FROM` and `IN` equivalence;
- missing-entity not-found classification in every mode;
- public Candid/Serde round trips and generated interface snapshots; and
- deterministic shell output vectors.

Before implementation, freeze representative instruction counts for compact
columns, current full `DESCRIBE`, and the narrow `SHOW` commands. Closeout must
report:

- compact versus verbose instruction and response-byte deltas;
- raw non-gzipped Wasm deltas, with gzip as secondary context;
- files touched and approximate line delta; and
- whether the maintained implementation shape became simpler, stayed neutral,
  or became more complex.

Compact mode is accepted only if it performs no verbose-only identity or
constraint-validation collection and is measurably no more expensive than the
frozen current full description on the same entity. Exact regression thresholds
must be recorded with the implementation baseline rather than invented in this
design.

## Acceptance Criteria

The slice is complete when:

1. `DESCRIBE Card` returns one compact typed table;
2. `DESCRIBE Card VERBOSE` returns the maintained full dossier;
3. `SHOW COLUMNS Card` and compact `DESCRIBE Card` share the same column
   semantics;
4. `SHOW COLUMNS Card VERBOSE` exposes detailed field/layout facts only;
5. `SHOW RELATIONS FROM Card` exposes accepted relation facts directly;
6. compact execution does not load verbose-only state;
7. the old default full-result contract is absent rather than preserved behind
   compatibility code;
8. missing entities return the accepted-schema-specific not-found diagnostic;
9. focused native, facade, CLI, and Candid contract validation passes; and
10. instruction, response-size, raw Wasm, and complexity evidence is recorded.
