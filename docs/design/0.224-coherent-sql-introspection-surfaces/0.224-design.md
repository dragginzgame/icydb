## Decision Summary

`DESCRIBE <entity>` becomes a compact, conventional one-table column summary.
The current multi-section entity dossier moves to the explicit
`DESCRIBE <entity> VERBOSE` form.

The command family becomes:

| Command | Human-facing result |
| --- | --- |
| `DESCRIBE Card` | One compact columns table |
| `DESCRIBE Card VERBOSE` | The complete current entity dossier |
| `SHOW ENTITY Card [VERBOSE]` | Entity/catalog summary |
| `SHOW COLUMNS Card` | The same compact column rows as `DESCRIBE Card` |
| `SHOW COLUMNS Card VERBOSE` | Detailed field and layout metadata only |
| `SHOW INDEXES FROM Card` | Indexes only |
| `SHOW CONSTRAINTS FROM Card` | Constraints only |
| `SHOW RELATIONS FROM Card` | Relations only |

`VERBOSE` is the sole detail modifier. IcyDB already uses that vocabulary for
`SHOW ENTITY`, `SHOW ENTITIES`, `SHOW STORES`, and `EXPLAIN`. This design does
not add `FULL`, `EXTENDED`, `DESC`, or section selectors such as
`DESCRIBE Card INDEXES`.

## User Outcome

The common command is immediately scannable:

```text
icydb> DESCRIBE Card;
+--------+----------+----------+-----+---------+----------+
| name   | type     | nullable | key | default | extra    |
+--------+----------+----------+-----+---------+----------+
| id     | Ulid     | no       | PRI | auto    | identity |
| rarity | Text(32) | no       | MUL | common  | -        |
+--------+----------+----------+-----+---------+----------+
```

Operators who need the complete accepted-schema report request it explicitly:

```text
DESCRIBE Card VERBOSE;
```

The verbose form retains the current entity path, row-layout window, identity
state, fields, indexes, relations, and constraint-validation sections.

## Current Problem

The current `DESCRIBE` response always constructs and renders an
`EntitySchemaDescription`. Its shell output contains:

- entity path and row-layout metadata;
- identity generator range and high-water state;
- a fifteen-column field table containing migration-era details;
- indexes;
- relations; and
- constraints plus validation progress.

That information is valuable, but the default command behaves like an
operational schema dossier rather than the familiar SQL column summary. It is
harder to scan, transfers more typed data than the common case needs, and
duplicates the narrower `SHOW COLUMNS`, `SHOW INDEXES`, and
`SHOW CONSTRAINTS` surfaces.

Relations are the exception: they currently appear in the full dossier but do
not have a narrow SQL command.

## Syntax Contract

The accepted grammar is exactly:

```text
DESCRIBE <entity> [VERBOSE]
SHOW COLUMNS <entity> [VERBOSE]
SHOW RELATIONS (FROM | IN) <entity>
```

Keywords remain case-insensitive. Schema-qualified entity identifiers retain
their current behavior. A trailing token other than the admitted modifier
returns a typed parser diagnostic. `DESCRIBE VERBOSE Card`, repeated
`VERBOSE`, `FULL`, `EXTENDED`, and section-selector spellings are rejected.

The parser carries mode explicitly:

```text
DescribeMode {
    Compact,
    Verbose,
}
```

The compiled metadata command must also retain that mode. Execution must not
infer output shape from the renderer or reconstruct the parsed SQL text.

## Compact Column Contract

The compact row is a dedicated typed projection, not a truncated verbose DTO.
Internal Rust names remain implementation-owned; the public labels are frozen
later in this document, and the semantic payload is:

```text
ColumnSummary {
    name,
    field_type,
    nullable,
    key,
    default,
    extra,
}
```

The shell columns are fixed and ordered as shown. Their authority is:

- `name`: the accepted query-visible field name or nested field path;
- `field_type`: the accepted field-kind rendering (shell header `type`);
- `nullable`: the accepted explicit-null contract;
- `key`: a compact index-membership hint;
- `default`: the accepted insert-omission/default summary; and
- `extra`: the closed ordered `Identity`, `Generated`, and `Relation` flags.

`key` uses this precedence:

1. `PRI` for the accepted primary key;
2. `UNI` only when the exact field path is the sole key item in an accepted
   unique secondary index;
3. `MUL` when the exact field path is a member of any compound index or any
   accepted non-unique secondary index; and
4. `-` when none apply.

Every member of a compound unique index therefore renders `MUL`, never `UNI`.
If one field path also owns a single-field unique index, the precedence above
still renders `UNI`. `SHOW INDEXES FROM <entity>` remains authoritative for
ordered key composition, compound uniqueness, and index identity.

The default summary is derived only from accepted insert semantics. It may
render `auto`, `NULL`, a bounded canonical accepted default, or `-` for a
required field without a default. It must not inspect generated models or
invent a value from the Rust field type.

The typed payload uses the closed key, default, and extra enums frozen below.
Free-form renderer strings are not runtime authority.

### Closed compact values

The public compact values are exactly:

```text
SqlColumnKey = Primary | Unique | Multiple | None

SqlColumnDefault =
    Auto
  | Null
  | Literal { text }
  | Required
  | NotApplicable

SqlColumnExtra = Identity | Generated | Relation
```

Their shell renderings are fixed:

| Typed value | Shell value |
| --- | --- |
| `Primary` | `PRI` |
| `Unique` | `UNI` |
| `Multiple` | `MUL` |
| `None` | `-` |
| `Auto` | `auto` |
| `Null` | `NULL` |
| `Literal { text }` | the bounded `text` |
| `Required` | `-` |
| `NotApplicable` | `-` |
| empty extras | `-` |

Top-level default classification follows only the accepted insert contract:

- accepted database-owned generation is `Auto`;
- accepted null-if-missing is `Null`;
- an accepted insert-default payload is decoded and returned as `Literal`;
- a required field without an accepted insert default is `Required`; and
- a nested path is `NotApplicable` because it owns no independent persisted
  insert slot or omission policy.

Application constructors, Rust/Serde defaults, generated-model proposal
defaults, and historical row-layout fill never affect this value. Generated
insert values use `Auto`, not a fabricated literal. Historical fill remains a
verbose field/layout fact.

Literal text reuses the current accepted-value canonical renderer. Text is
single-quoted and each character uses the maintained `escape_default`
escaping; other admitted values use the maintained `OutputValue` rendering.
The UTF-8 result is at most 128 bytes. A longer rendering becomes exactly
`<kind>(bytes=<encoded-bytes>, sha256=<first-8-digest-bytes-as-16-lower-hex>)`.
The bounded fallback itself must fit the same 128-byte limit.

`extra` is a vector solely so one field may carry more than one accepted fact.
Its complete admitted vocabulary and order are `Identity`, `Generated`, then
`Relation`; no other value may be emitted. `Identity` means the accepted
identity inspection names this exact top-level field. `Generated` means the
accepted write policy synthesizes the field on insert, not merely that the
field originated in a generated schema proposal. `Relation` means this exact
top-level field participates in an accepted relation edge. Nested paths inherit
`Generated` from their owning top-level persisted value but never inherit
`Identity` or `Relation` unless accepted authority directly identifies that
exact path in a future current-format contract.

### Nested query-visible paths

Compact nested names are canonical dotted query paths: the accepted top-level
field name followed by the accepted relative nested path, joined with `.`, for
example `profile.address.city`. Tree glyphs and indentation are verbose shell
presentation only and never enter the compact typed name.

For one nested path:

- `type` is the accepted kind of that exact path;
- `nullable` is true when the owning top-level field, any accepted intermediate
  path, or the leaf itself permits explicit `NULL`;
- `default` is `NotApplicable`, with the owning top-level row remaining the
  sole report of effective insert omission/default behavior;
- the index hint is computed only from an accepted index key item matching the
  exact dotted path; and
- relation and primary-key hints are attached only where accepted relation or
  primary-key authority names the exact path.

The projector must not infer nested semantics from the verbose tree rendering
or from generated composite models.

### Deterministic ordering

Compact columns are ordered by accepted top-level field ID. Each top-level row
is followed immediately by its accepted nested paths in lexicographic order of
the complete relative path using UTF-8 byte ordering. Compact `DESCRIBE` and
compact `SHOW COLUMNS` return the exact same `Vec<SqlColumnSummary>` sequence;
equality is positional and byte-for-byte, not set equivalence.

Verbose fields retain the same accepted-field and nested-path ordering frozen
by the pre-0.224 golden fixture. Relations are ordered by accepted stable
relation ID. Multiple extra flags use the fixed order above. Existing verbose
index and constraint ordering remains part of the named golden fixture rather
than being re-sorted by the renderer.

## Verbose Contract

`DESCRIBE <entity> VERBOSE` owns the current full
`EntitySchemaDescription` behavior. Its sections remain:

1. entity identity and path;
2. row-layout current and history-floor versions;
3. identity-generator state, when present;
4. detailed fields;
5. indexes;
6. relations; and
7. constraints and validation progress.

`SHOW COLUMNS <entity> VERBOSE` returns only the detailed field table. It does
not become a second spelling for the complete dossier.

`SHOW RELATIONS FROM <entity>` returns the maintained typed relation
descriptions. Its compact shell table contains `field`, `target`, and
`cardinality`; the typed response retains accepted target identity required by
non-shell consumers.

For the shell table, `field` is the maintained accepted source-field rendering
(including the existing ordered comma-separated form for compound local
fields), and `target` is the exact accepted qualified entity `target_path`.
It never substitutes the display-only entity name and never appends or invents
a target field; the target primary-key contract is implicit in accepted
relation authority. Cardinality is the existing closed public enum `Single`,
`List`, or `Set`, rendered with those exact labels. Relations use the accepted
stable relation-ID order and the public projection reuses the verbose dossier's
existing `EntityRelationDescription` rows byte-for-byte.

`SHOW ENTITY`, `SHOW ENTITIES`, `SHOW STORES`, `SHOW MEMORY`, `SHOW INDEXES`,
and `SHOW CONSTRAINTS`, including every already-admitted `VERBOSE` form, are
unchanged by this line. The new modifier does not become a generic parser rule
for other commands.

## Authority And Execution

Accepted schema snapshots remain runtime authority. Compact and verbose
projections must resolve one accepted catalog context exactly once at the
metadata-command execution boundary and pass that resolved context by
reference to every projector. A projector may derive accepted fields, indexes,
relations, identity, or constraint facts from that context, but may not repeat
entity-name catalog lookup or reopen another catalog snapshot during the same
command.

Compact execution must not construct the full verbose report and discard most
of it afterward. In particular, ordinary `DESCRIBE` and `SHOW COLUMNS` must not
load identity high-water state, constraint-validation jobs, or full relation
and constraint sections merely to render columns.

The compact projection may read accepted fields, indexes, and relation facts
needed for the six fixed columns. The verbose path retains the existing full
metadata collection. `SHOW RELATIONS` projects relation facts directly from
the accepted catalog.

Generated `EntityModel` and `IndexModel` remain proposal and convenience
surfaces. No introspection command may reconstruct runtime output from them
when accepted authority is missing.

A named entity absent from accepted schema authority retains the typed
not-found diagnostic established before this line:

```text
E_RUNTIME_NOT_FOUND: SQL query target entity was not found in the accepted schema
```

Compact and verbose modes must produce the same not-found classification.

## Bounded Projection Contract

The projection is bounded by current accepted-schema limits, not caller input:

| Collection/value | Maximum |
| --- | ---: |
| accepted top-level fields | 256 |
| accepted nested rows per top-level field | 256 |
| compact column rows | 65,792 |
| accepted relation rows | 64 |
| extra flags per column | 3 |
| rendered literal-default UTF-8 bytes | 128 |

The compact-row maximum is
`MAX_FRAGMENT_FIELDS * (1 + MAX_FRAGMENT_FIELDS)`. Implementations must use
checked/saturating arithmetic before allocation and return typed internal
corruption or boundary errors for impossible over-limit accepted state; they
must not truncate, partially render, panic, or allocate from an unchecked
decoded count.

Focused tests must exercise the current accepted maximums and max-plus-one
rejection for columns, relations, flags, and rendered defaults. Maximum-size
tests must also prove deterministic order and bounded Candid encoding. This
line does not add paging, caller-tunable limits, or a second response mode to
accommodate oversized introspection.

## Typed Result And Hard Cut

Mode must remain visible through core statement results and the public SQL
query result. The following Candid labels and nesting are design authority:

```text
type SqlColumnKey = variant { Primary; Unique; Multiple; None };
type SqlColumnDefault = variant {
  Auto;
  Null;
  Literal : record { text : text };
  Required;
  NotApplicable;
};
type SqlColumnExtra = variant { Identity; Generated; Relation };
type SqlColumnSummary = record {
  name : text;
  field_type : text;
  nullable : bool;
  key : SqlColumnKey;
  default : SqlColumnDefault;
  extra : vec SqlColumnExtra;
};

type SqlDescribeOutput = variant {
  Compact : record { entity : text; columns : vec SqlColumnSummary };
  Verbose : record { description : EntitySchemaDescription };
};

type SqlShowColumnsOutput = variant {
  Compact : record { entity : text; columns : vec SqlColumnSummary };
  Verbose : record {
    entity : text;
    columns : vec EntityFieldDescription;
  };
};

type SqlShowRelationsOutput = record {
  entity : text;
  relations : vec EntityRelationDescription;
};
```

The maintained `SqlQueryResult` variant payloads become exactly:

```text
Describe : SqlDescribeOutput;
ShowColumns : SqlShowColumnsOutput;
ShowRelations : SqlShowRelationsOutput;
```

Internal Rust type names remain implementation-owned, but public Candid
variant labels, field labels, and nesting above do not. The implementation
must not use an object containing optional compact/verbose payloads, infer mode
from populated fields, or keep the old default full-response variant as a
fallback.

This is a pre-1.0 public SQL/Candid hard cut. Clients that decode or match the
current `DESCRIBE` result must move to the discriminated current form and send
`VERBOSE` when they require the dossier. There is no persisted-data migration,
cursor migration, compatibility alias, or dual dispatch path.

`SHOW COLUMNS` must share the canonical compact projection with compact
`DESCRIBE`, while retaining its own statement identity in parsing and surface
diagnostics. Shared projection does not mean one command is reparsed or
rewritten into the other.

`SHOW RELATIONS` reuses the existing public `EntityRelationDescription` DTO
unchanged. Its Candid fields remain `field`, `target_path`,
`target_entity_name`, `target_store_path`, and `cardinality`.

## Non-Negotiable Invariants

1. Default `DESCRIBE` renders exactly one table and no metadata preamble or
   additional section.
2. Compact and verbose output are derived from one accepted catalog context per
   command.
3. Compact execution does not construct identity or constraint-validation
   state that its result cannot expose.
4. `DESCRIBE` and `SHOW COLUMNS` compact rows are positionally and
   byte-for-byte identical for the same accepted entity snapshot.
5. `UNI` is emitted only for a single-field unique secondary index; every
   compound-index member is `MUL` unless a higher-precedence independent key
   contract also applies.
6. Verbose `DESCRIBE` retains all currently maintained dossier sections.
7. Relation output follows accepted relation authority and never generated
   model fallback.
8. Missing entities return typed not-found diagnostics in every mode.
9. Parser, core result, public result, Candid, and shell renderer preserve the
   selected mode explicitly.
10. Production introspection paths remain bounded, fallible, and non-panicking.
11. Public Candid labels and nesting match the frozen envelopes exactly.
12. Column, relation, and extra ordering is deterministic from accepted stable
    identity/path order, never map iteration or renderer sorting.

## Scope

This slice adds or changes:

- compact and verbose `DESCRIBE` grammar;
- a dedicated typed compact column summary;
- mode-preserving compiled commands and result envelopes;
- compact and verbose `SHOW COLUMNS` behavior;
- typed `SHOW RELATIONS FROM|IN` introspection;
- deterministic one-table compact rendering;
- shell help and active SQL documentation;
- Candid/result contract fixtures; and
- focused instruction, raw Wasm, and complexity evidence.

This slice does not add:

- `DESC`, `FULL`, `EXTENDED`, or compatibility spellings;
- arbitrary `DESCRIBE` section selectors;
- `SHOW CREATE ENTITY` or DDL reconstruction;
- JSON/text output modes beyond the maintained typed response and shell table;
- schema diffing, historical schema browsing, or cross-canister discovery;
- public access-policy changes to controller-gated introspection;
- generated-model runtime fallback; or
- changes to storage, accepted schema persistence, query cursors, or mutation
  jobs.

## Validation And Evidence

Focused validation must cover:

- parser acceptance and rejection for every admitted modifier position;
- schema-qualified and case-insensitive entity resolution;
- compact rows for primary, unique, compound, and non-unique index membership;
- required, nullable, identity, generated, and bounded-default fields;
- nested query-visible field paths;
- compact `DESCRIBE`/`SHOW COLUMNS` semantic equality;
- verbose preservation of identity, layouts, indexes, relations, constraints,
  and validation progress;
- `SHOW RELATIONS FROM` and `IN` equivalence;
- missing-entity not-found classification in every mode;
- public Candid/Serde round trips and generated interface snapshots; and
- deterministic shell output vectors.

The named `pre_0_224_verbose_dossier_golden` fixture freezes the complete
pre-change verbose payload and shell output. It must include entity/path and
fingerprint facts, identity state, current/history-floor layouts, top-level and
nested fields, generated and DDL indexes, single/list/set relations, validated
constraints, and an in-progress constraint-validation entry. Patch 1 must
capture its exact typed value, Candid bytes/hash, and rendered lines before the
default `DESCRIBE` behavior changes. `DESCRIBE <entity> VERBOSE` must match that
golden except for values the fixture deliberately advances.

Before implementation, freeze representative instruction counts for compact
columns, current full `DESCRIBE`, and the narrow `SHOW` commands. Because
compact syntax does not exist at baseline, its ceiling is derived from the
measured current full dossier and recorded in the status tracker before parser
or DTO implementation. The tracker must also freeze exact Candid response
bytes and hashes for current `DESCRIBE`, `SHOW COLUMNS`, `SHOW INDEXES`, and
`SHOW CONSTRAINTS`; a prose statement that compact is merely "measurably no
more expensive" is not an acceptance gate. Closeout must report:

- compact versus verbose instruction and response-byte deltas;
- raw non-gzipped Wasm deltas, with gzip as secondary context;
- files touched and approximate line delta; and
- whether the maintained implementation shape became simpler, stayed neutral,
  or became more complex.

Compact mode is accepted only if it performs no verbose-only identity or
constraint-validation collection and remains at or below the frozen compact
instruction and response-byte ceilings for the same entity. Exact baseline
values and thresholds belong to the status tracker and must be populated from
the published predecessor before the first implementation patch.

## Acceptance Criteria

The slice is complete when:

1. `DESCRIBE Card` returns one compact typed table;
2. `DESCRIBE Card VERBOSE` returns the maintained full dossier;
3. `SHOW COLUMNS Card` and compact `DESCRIBE Card` share the same column
   semantics;
4. `SHOW COLUMNS Card VERBOSE` exposes detailed field/layout facts only;
5. `SHOW RELATIONS FROM Card` exposes accepted relation facts directly;
6. compact execution does not load verbose-only state;
7. the old default full-result contract is absent rather than preserved behind
   compatibility code;
8. missing entities return the accepted-schema-specific not-found diagnostic;
9. public Candid labels, closed enums, deterministic ordering, nested-path
   semantics, and accepted-maximum bounds match the frozen contract;
10. the named pre-0.224 verbose golden remains exact under `VERBOSE`;
11. focused native, facade, CLI, and Candid contract validation passes; and
12. instruction, response-size, raw Wasm, and complexity evidence is recorded.
