## Minor-Line Plan

The line has two meaningful landings:

1. **Public contract and committed-baseline freeze.** Record the exact wire
   envelopes and bounds in authority, add the named pre-change verbose golden,
   and freeze instruction, Candid-response, raw Wasm, gzip, and complexity
   evidence without changing runtime behavior.
2. **Coherent SQL introspection hard cut.** Land compact/verbose `DESCRIBE`,
   compact/verbose `SHOW COLUMNS`, and `SHOW RELATIONS FROM|IN` end to end,
   including parser, accepted projection, compiled mode, public DTO/Candid,
   renderer, diagnostics, fixtures, active docs, and closeout evidence.

The usual six-to-eight-patch planning range is a target rather than a quota.
Splitting parser, result, execution, Candid, renderer, tests, or docs into
separate landings would create partial public states explicitly forbidden by
the design. No additional introspection feature has demonstrated need in this
minor, so the tracker does not invent one.

## Patch 2 — Coherent SQL Introspection Hard Cut

Status: Accepted on focused implementation evidence; landing complete

The implementation hard-cuts the old default-full public result rather than
retaining an alias or decoder. `DESCRIBE` and `SHOW COLUMNS` now carry explicit
`Compact` or `Verbose` envelopes through parser, compiler, executor, public
facade, Candid, and shell rendering. `SHOW RELATIONS FROM|IN` projects the
maintained relation DTO directly from the same accepted catalog context.

One accepted-schema compact projector owns both compact commands. It orders
top-level fields by stable field ID, nested paths lexicographically, classifies
compound unique members as `Multiple`, includes nullable ancestors, derives
defaults only from accepted insert semantics, and emits the closed ordered
`Identity`, `Generated`, `Relation` extras. Compact execution does not load
identity high-water state or constraint-validation jobs and does not construct
the verbose dossier.

The public hard cut is reflected in the normative generated-endpoint ABI
golden. The former `Describe(EntitySchemaDescription)` and
`ShowColumns(Vec<EntityFieldDescription>)` payloads have no maintained alias,
fallback, or compatibility decoder.

### Patch 2 Invariant Disposition

| Design invariant | Disposition |
| --- | --- |
| compact and verbose public envelopes are explicit | satisfied end to end and mirrored by exact Candid tests |
| one accepted catalog context per command | satisfied; metadata execution receives the resolved context by reference |
| compact commands share one positional projection | satisfied; both call `describe_compact_columns_with_persisted_schema` |
| compact work excludes verbose-only metadata | satisfied by execution shape and representative instruction deltas |
| `PRI`/`UNI`/`MUL` follows exact accepted index membership | satisfied, including compound-unique and precedence regressions |
| nested names, nullability, defaults, indexes, and extras are canonical | satisfied by focused projector tests and live SQL coverage |
| literal/default, column, relation, and extra bounds are enforced | satisfied at current maximum and max-plus-one; maximum Candid is deterministic |
| `SHOW RELATIONS` reuses maintained accepted relation DTOs | satisfied in stable relation-ID order with qualified `target_path` rendering |
| compact and verbose not-found behavior agrees | satisfied by live PocketIC SQL coverage |
| existing verbose behavior is preserved | satisfied by the named complete pre-0.224 typed/Candid/shell golden |
| other maintained metadata commands remain unchanged | satisfied by focused controls and exhaustive command propagation |
| no generated-model fallback, paging, tunable bound, or second executor exists | satisfied by implementation audit |

The accepted maximum is 65,792 compact column rows. Its canonical Candid
encoding is deterministic at 9,737,847 bytes. Max-plus-one field, nested-row,
relation, extra-flag, and rendered-default inputs fail through typed invariant
errors rather than truncating or allocating from unchecked arithmetic.
