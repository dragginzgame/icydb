## Minor-Line Plan

The line has two meaningful landings:

1. **Public contract and committed-baseline freeze.** Record the exact wire
   envelopes and bounds in authority, add the named pre-change verbose golden,
   and freeze instruction, Candid-response, raw Wasm, gzip, and complexity
   evidence without changing runtime behavior.
2. **Coherent SQL introspection hard cut.** Land compact/verbose `DESCRIBE`,
   compact/verbose `SHOW COLUMNS`, and `SHOW RELATIONS FROM|IN` end to end,
   including parser, accepted projection, compiled mode, public DTO/Candid,
   renderer, diagnostics, fixtures, active docs, and closeout evidence.

The usual six-to-eight-patch planning range is a target rather than a quota.
Splitting parser, result, execution, Candid, renderer, tests, or docs into
separate landings would create partial public states explicitly forbidden by
the design. No additional introspection feature has demonstrated need in this
minor, so the tracker does not invent one.

## Patch 2 — Coherent SQL Introspection Hard Cut

Status: Implementation landing complete; closeout corrections below supersede
the original focused evidence where noted

The implementation hard-cuts the old default-full public result rather than
retaining an alias or decoder. `DESCRIBE` and `SHOW COLUMNS` now carry explicit
`Compact` or `Verbose` envelopes through parser, compiler, executor, public
facade, Candid, and shell rendering. `SHOW RELATIONS FROM|IN` projects the
maintained relation DTO directly from the same accepted catalog context.

One accepted-schema compact projector owns both compact commands. It orders
top-level fields by stable field ID, nested paths lexicographically, classifies
compound unique members as `Multiple`, includes nullable ancestors, derives
defaults only from accepted insert semantics, and emits the closed ordered
`Identity`, `Generated`, `Relation` extras. Compact execution does not load
identity high-water state or constraint-validation jobs and does not construct
the verbose dossier.

The public hard cut is reflected in the normative generated-endpoint ABI
golden. The former `Describe(EntitySchemaDescription)` and
`ShowColumns(Vec<EntityFieldDescription>)` payloads have no maintained alias,
fallback, or compatibility decoder.

rendered-default inputs fail through typed invariant errors rather than
truncating or allocating from unchecked arithmetic.

### Closeout Audit Corrections

The implementation-first audit found that the synthetic 65,792-row ceiling
had been described as an accepted maximum without reconciling persisted-schema
reachability or the public reply boundary. A real persisted snapshot now
round-trips through maintained accepted decoding at 310,861 bytes and projects
24,416 compact rows. Its canonical compact output is 3,693,110 Candid bytes,
proving that a valid schema under the 524,288-byte persisted payload limit can
exceed the deployed 3-MiB query-reply limit.

Generated `icydb_query` handlers now exact-encode the complete successful
`Result<SqlQueryPerfResult, Error>` envelope before returning it. An envelope
above 3 MiB becomes typed diagnostic
`RUNTIME_BOUNDARY_SQL_QUERY_REPLY_BYTES_EXCEEDED` (raw code 279, response
origin); no row, schema maximum, or public result shape is truncated or
weakened. Focused PocketIC coverage returns that typed error through the real
generated endpoint for a three-row oversized result, then proves a subsequent
query still observes all three stored rows. Unit coverage proves the borrowed
preflight bytes are byte-for-byte identical to the owned endpoint envelope and
that the typed error itself is deliverable.

The audit also found that the live default-fallback proof did not actually
publish an accepted default and that the relation comparison encoded a wrapper
and the wrong cardinality. The corrected PocketIC default fixture publishes a
long text default, derives its byte count and hash from the accepted verbose
payload, and observes that exact bounded fallback through both compact
commands. The relation performance fixture now contains exactly three accepted
relations and the gate encodes their direct maintained DTO sequence.
