## Patch 1 — Schema-Authoring Correctness

Patch 1 changes the generated enum-literal trait qualification from the invalid
`icydb_model::node::Path` path to the maintained public `icydb_model::Path`
path. A downstream-style model fixture contains one entity check over two unit
enums and must compile as part of the existing durable-rule UI suite.

The maintained identity contract is corrected to require `_id` on singular and
optional relation fields and `_ids` on collection relation fields, matching the
existing compiler validation and regression authority. The validator itself is
unchanged.

Patch 1 adds no runtime branch, public API, Candid shape, persisted field,
stable allocation, endpoint, executor, query plan, or compatibility alias.

## Patch 2 — Atomic Generated Typed Batch

The public session now accepts a non-empty `Vec<TypedWrite>` and passes its
opaque bindings and source-bound mutations directly to one core typed batch
adapter. The core requires exact binding equality across every item, checks the
first binding against current accepted authority, lowers every mutation with
its batch position, and delegates the complete vector to the existing accepted
structural save-batch owner.

The adapter introduces no new limit or transaction route. It inherits the
4,096-operation cap, exact 16 MiB writer-owned staged-byte accounting, 1 MiB
result bound, one operation timestamp, batch-final constraint/relation overlay,
input-order results, commit marker, and recovery behavior. Empty batches use
the existing empty-batch diagnostic; stale, mixed, or cross-bound patches fail
closed through the existing typed stale-binding contract.

### Evidence

- A direct core regression covers the empty and 4,097-item boundaries, rejects
  a late duplicate without committing its earlier staged row, accepts two
  exact-binding inserts in input order, and rejects one mismatched binding.
- A mixed insert/update/replace regression preserves three input-ordered result
  rows and reports all three logical changes.
- A journaled two-row typed batch interrupted after row publication remains
  inaccessible behind startup recovery and becomes visible as one complete
  transition after the existing recovery driver quiesces.
- The public no-SQL compile contract reaches the new method with `Vec<TypedWrite>`.
- The renamed-dependency generated-adapter fixture passes with enum, record,
  list, set, map, tuple, and recursive-record inputs. Invalid generated enum
  variants remain unrepresentable in Rust, and value-shape encoding still runs
  before a `TypedWrite` can enter the batch; Patch 2 adds no unchecked encoder.
- The three focused runtime regressions, public compile contract,
  warning-denied core/facade Clippy, formatting, and repository invariant checks
  pass. Full repository validation remains user-owned.
- The Rust facade adds no Candid method, generated endpoint, persisted field,
  stable allocation, cursor, or compatibility path. The maintained one-entity
  typed-query canister is byte-identical before and after Patch 2: 2,417,825
  compiler Wasm bytes, 2,117,446 final raw Wasm bytes, 811,510 deterministic
  gzip bytes, 64 Candid bytes, and six exports. Final line-wide attribution
  remains part of Patch 4 closeout.
- No instruction delta is claimed because no maintained canister endpoint
  reaches the additive terminal; admitted work still executes the already
  measured canonical structural batch.
- Patch 2 changes three source/test files at `+414/-74` lines. Runtime state-space is
  neutral: one lowering adapter reuses the sole structural mutation executor;
  code complexity increases slightly for the new public batch surface.
