## Patch 2 — Atomic Generated Typed Batch

The public session now accepts a non-empty `Vec<TypedWrite>` and passes its
opaque bindings and source-bound mutations directly to one core typed batch
adapter. The core requires exact binding equality across every item, checks the
first binding against current accepted authority, lowers every mutation with
its batch position, and delegates the complete vector to the existing accepted
structural save-batch owner.

The adapter introduces no new limit or transaction route. It inherits the
4,096-operation cap, exact 16 MiB writer-owned staged-byte accounting, 1 MiB
result bound, one operation timestamp, batch-final constraint/relation overlay,
input-order results, commit marker, and recovery behavior. Empty batches use
the existing empty-batch diagnostic; stale, mixed, or cross-bound patches fail
closed through the existing typed stale-binding contract.

### Evidence

- A direct core regression covers the empty and 4,097-item boundaries, rejects
  a late duplicate without committing its earlier staged row, accepts two
  exact-binding inserts in input order, and rejects one mismatched binding.
- A mixed insert/update/replace regression preserves three input-ordered result
  rows and reports all three logical changes.
- A journaled two-row typed batch interrupted after row publication remains
  inaccessible behind startup recovery and becomes visible as one complete
  transition after the existing recovery driver quiesces.
- The public no-SQL compile contract reaches the new method with `Vec<TypedWrite>`.
- The renamed-dependency generated-adapter fixture passes with enum, record,
  list, set, map, tuple, and recursive-record inputs. Invalid generated enum
  variants remain unrepresentable in Rust, and value-shape encoding still runs
  before a `TypedWrite` can enter the batch; Patch 2 adds no unchecked encoder.
- The three focused runtime regressions, public compile contract,
  warning-denied core/facade Clippy, formatting, and repository invariant checks
  pass. Full repository validation remains user-owned.
- The Rust facade adds no Candid method, generated endpoint, persisted field,
  stable allocation, cursor, or compatibility path. The maintained one-entity

## Patch 3 — Fail-Closed Exact Scalar Count

The dynamic session and accepted-binding typed query facades now return exact
visible `u64` cardinality without constructing row output. The shared planner
adapter admits only whole-entity metadata or one strict equality/`IN` proof
over the leading field of an accepted unfiltered field-path user index. The
index may contain trailing fields, so a composite index's one-component leading
prefix is eligible. Public `IN` input is capped before lowering at the existing
16-prefix planner bound. Projection, ordering, limits, grouping, cursors,
residual predicates, nonindexed fields, empty membership, and unavailable
metadata all fail closed through the existing query-unsupported class.

The exact entity/prefix executor and accepted-index visibility boundary are no
longer SQL-only. SQL still owns its optional aggregate fallback, but both SQL
and public facades now consume the same prefix proof and metadata executor.
The public terminal never enters row execution and adds no cursor or separate
count-maintenance authority.

### Evidence

- Five focused session regressions cover exact entity, equality, deduplicated
  bounded `IN`, a leading composite-index prefix, zero-match and larger-
  population counts; SQL shared-executor parity; unsupported scalar
  decorations, residual and nonindexed predicates, 17-member input,
  unavailable generation metadata, and stale typed bindings.
- Physical counters remain unchanged across exact counts before and after the
  matching population grows from two to 66 rows: zero row-store fetches and
  zero index-entry traversal. Executor budget work is charged only for one
  entity metadata target or the at-most-16 admitted prefixes.
- The shared direct-count mixed-index-generation guard passes with every
  feature enabled. Core and public-facade all-feature Clippy plus
  no-default-feature and repository invariant checks pass; full repository
  validation remains user-owned.
- Existing PocketIC exact-cardinality scale evidence exercises the same moved
  executor and remains the instruction authority; Patch 3 adds facade-specific
  zero-physical-read proof rather than another measurement endpoint.
- The patch adds two Rust methods and one shared query adapter without a Candid
  endpoint, export, persisted format, stable allocation, continuation, new
  budget, or generated runtime authority. The maintained one-entity typed-query
  control measures 2,418,133 compiler Wasm bytes, 2,117,584 final raw Wasm

## Closeout Correction — Composite Index Prefixes

The exact-count contract now states the implementation's existing admission
rule precisely: the predicate may target the leading field of an accepted
unfiltered field-path user index, including the one-component leading prefix
of a composite index. A focused regression exercises equality and bounded

index-entry traversal occur. This correction changes test construction and

## Release-Gate Harness Correction

The user-owned release gate exposed one nondeterministic PocketIC harness
failure before a SQL performance scenario reached its query assertions. The
shared single-watchdog delivery helper advanced the one-second cadence once but
allowed only two completion ticks, while ordinary fixture setup already used
four. The helper now owns one four-tick completion constant shared by both
paths. Zero-time completion ticks cannot admit another one-second watchdog
wake-up, so the frozen 42-delivery residual bound is unchanged.

If the watchdog still exceeds that bound, the failure reports its bounded
scheduler and work counters. The exact previously failing scenario passes
against the current candidate with its query results, physical-work limits,
and instruction comparisons intact. This correction changes test harness and
evidence only; production code, state, Candid, exports, instructions, and Wasm
are unchanged. It touches five 0.234 files at approximately `+50/-8` lines;
runtime and persisted state-space remain neutral, and the shared completion
constant makes the harness slightly simpler.

## Deferred Same-Store Multi-Entity Assessment

Toko Miner `ICYDB-009` was assessed against the current writer. Multi-entity
atomicity is not a small typed-facade extension: the maintained precommit flow
owns one accepted catalog, row layout, final-row overlay, identity range,
entity-path commit, and result projection. Broadening it would require a new
bounded cross-entity precommit contract plus relation, uniqueness, marker, and
recovery proof. That independently reviewable state-space addition remains
outside 0.234's explicit non-goal; downstream enrollment should retain its
idempotent repair contract unless a future minor is explicitly authorized to
design the engine capability.

The final candidate touches 34 files at approximately `+1,020/-304` lines.
Runtime state-space remains neutral; the correction adds one direct regression
and clarifies maintained documentation without another execution route.
