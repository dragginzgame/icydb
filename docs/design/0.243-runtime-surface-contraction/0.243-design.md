# IcyDB 0.243 Runtime Surface Contraction

Status: COMPLETE — THREE PATCHES CLOSED

Last updated: 2026-08-26

Exact pushed predecessor:
`0.242.0` at `32750aeb570c8a6e7599ff5eb175f33d10242ed9`.

## Outcome

Reduce runtime and Wasm complexity only where current ownership evidence proves
that a broader representation is unused. Follow that cleanup with a bounded
measurement audit of whether the existing exact leading-component metadata can
serve both indexed `SUM` and `AVG` without introducing aggregate-specific
parallel flows.

This line does not authorize a generic cache, statistics framework, persisted
metadata change, public SQL change, compatibility path or second schema/index
authority. Each patch is an independent landing boundary. A failed raw-Wasm or
ownership gate closes that patch as a measured no-build instead of carrying a
source-only cleanup forward.

## Patch 1 Contract

SQL index DDL stages exactly one entity-owned accepted-after index domain and
publishes exactly one entity snapshot revision. The current producer is
singular, but the commit boundary accepts a vector, revalidates duplicate
entity identity through a set, allocates a second vector of references, sorts
it, and loops over it.

Patch 1 may:

- carry one `StagedUserIndexDomainReplacement` in the existing prepared-domain
  enum;
- validate that single replacement directly against the accepted-before and
  candidate-after authority;
- append its delete chunks followed by its put chunks directly after the
  accepted-schema publication record; and
- apply the replacement through the existing index-state and cardinality
  generation boundary.

It may not preserve a plural wrapper, add an iterator abstraction, move domain
authority out of schema publication, change journal record encoding/order, or
generalize schema publication for hypothetical multi-entity SQL DDL.

### Patch 1 Frozen Gates

- exactly one staged replacement from the SQL DDL caller through validation,
  journaling and live apply;
- no temporary replacement collection, entity-order sort or duplicate-entity
  set;
- schema publication remains the first journal record, followed by bounded
  deletion chunks and then bounded insertion chunks;
- live and journaled stores publish the same accepted candidate and physical
  index domain as the predecessor;
- index readiness and synchronized cardinality generation retain their current
  fail-closed transitions;
- negative net production Rust and no new type, module, cache, state, owner,
  invalidation edge, public API or persisted format;
- final raw `one_entity_sql_query` Wasm must not grow; Candid and exports remain
  equal;
- focused SQL index create/drop, recovery and core publication evidence pass.

## Patch 2 Contract

Relation ordering is an accepted-snapshot invariant only if every constructor,
decoder, migration replacement and activation transition establishes it before
publication. Patch 2 must first prove or install that singular invariant. Only
then may relation description iterate the accepted slice directly.

Deleting the description sort without an authority proof is forbidden. The
patch must retain duplicate-ID corruption detection, deterministic relation
output, migration/recovery behavior and target resolution. It must reduce
production Rust and cannot grow final raw Wasm.

## Patch 3 Audit Contract

Patch 3 is measurement and design only. It must compare current cold and true
warm `SUM`/`AVG` over the same non-nullable leading indexed `Int32` field at
16, 256 and 2,048 rows, plus unindexed, nullable, filtered, distinct and
multi-terminal controls.

The audit must separate row reads, index reads, metadata entries, reducer work,
planning and result projection. Before recommending another design it must
calculate the absolute removable ceiling and determine whether one checked
metadata fold can return a shared `(count, sum)` fact from which both SQL
terminals project canonical results. Aggregate-specific cache entries,
persisted sums and duplicated planner/executor classifiers are rejected.

The only allowed verdicts are:

- `DO NOT BUILD — CURRENT COST OR COMPLEXITY DOES NOT JUSTIFY IT`;
- `EVIDENCE INSUFFICIENT — MEASURE A SEPARATE BASELINE`; or
- `SEPARATE DESIGN JUSTIFIED — NO 0.243 RUNTIME BUILD`.

## Patch 3 Closeout

### Method and comparability

**Observed.** The maintained scale fixture gives `PerfAuditUser.age` one
complete accepted leading `Int32` index. The field is non-nullable and has five
values (`31`, `32`, `33`, `34`, and `43`) at every scale. `rank` is the
unindexed numeric control, `active = true` selects one quarter of the rows, and
`NULLIF(age, 43)` supplies a nullable expression without changing the stored
schema.

**Measured.** The audit used the current Patch 2 production runtime, the
current production-profile SQL performance Wasm, Rust 1.97.1 and pinned
PocketIC 15.0.0. Controller state was restored before every cold observation
and again before one unmeasured warm-up followed by the true-warm observation.
Every cold/warm pair returned the same result signature.

**Measured.** The preceding 0.237 scale evidence remains comparable. Fresh
2,048-row `SUM(age)` is 184,897 instructions below the retained 98,266,855
observation, and fresh `AVG(age)` is 185,746 below 98,252,917. Those differences
are under 0.2% and do not alter the physical route: both current queries still
fetch and reduce all 2,048 rows.

**Measured.** At 2,048 rows, directly attributed base-row plus reducer work is

**Inferred.** The five-entry exact DISTINCT query is the closest existing

a best-case whole-query ceiling of 97,490,094 cold / 97,348,021 warm for

with checked decimal semantics, and project one or two results, so the
reference is not itself a candidate measurement.

**Proposed.** A separate design should use hard gates of at most 2,000,000 cold
and 1,000,000 true-warm instructions at 2,048 rows for the five-value fixture.
Even at those conservative ceilings, the absolute required savings are
96,081,958 cold / 96,717,969 warm for `SUM` and 96,067,171 / 96,703,437 for

| 1 | 96,067,171 instructions |

**Inferred.** There is no recovery saving to claim. Accepted-root recovery,
query compilation and metadata availability retain their current lifecycle.
The proposed work changes only aggregate execution after a request has pinned
a current authority and selected a usable exact target. It transfers no cost
to first access of another entity and creates no materialization job or cache.

**Inferred.** A metadata fold is `O(D)` in distinct leading values instead of
the current `O(N)` row loads, where `D <= N`. One duplicate group is the best
case. All-unique input is the hostile case and must be measured rather than
assumed cheap; it still has no reason to hydrate rows, but it examines 2,048
metadata entries.

### Current authority and the only acceptable structure

**Observed.** The accepted request catalogue supplies the immutable entity
authority and schema fingerprint. `SqlGlobalAggregatePlanCacheEntry` is the
single fingerprint-bound exact-or-prepared command slot. The planner selects
an accepted physical index once. `StoreHandle` resolves that selected store,
and `IndexStore` owns generation-matched `first_component_counts`. The map is
already exact correctness authority for indexed DISTINCT and range cardinality
while synchronized with the row generation.

**Observed.** Each retained metadata key contains one canonical non-empty
leading component and its exact row multiplicity. The current owner already
checks generation, readiness, zero multiplicity, bounded traversal, atomic
budget charging and unavailable fallback. No persisted sum or aggregate cache
exists.

**Proposed.** A viable later design may extend only that ownership chain:

1. Lowering records one immutable shape fact for an unfiltered global
   aggregate whose unique terminals are `SUM`, `AVG`, or both over the same
   direct non-nullable accepted `Int32` field. DISTINCT, expressions, HAVING,
   authored ordering, grouping, predicates and other terminals are rejected.
2. The existing planner authority selects one complete accepted index whose
   leading field is that exact slot. The executor never reselects another
   compatible index.
3. The existing singular compiled-command slot retains either that exact
   accepted target or the existing prepared plan. No nested slot, side cache,
   fallback cache or second fingerprint owner is added.
4. The index metadata owner performs one bounded checked fold and returns one
   exact `(count, sum)` fact. It exposes no map, iterator, canonical component
   bytes or mutable metadata reference above `IndexStore`.
5. Canonical aggregate finalization projects `SUM` from `sum` and `AVG` from
   the same `sum` and `count`, including the existing empty-input `NULL`,
   checked-decimal overflow and average-rounding behavior. Existing projection
   ownership preserves aliases, column order, fixed scales and duplicate
   output references.
6. Missing, stale, undecodable or unmaterialized optional metadata enters the
   existing prepared executor. An accepted target with an impossible type,
   index identity or component encoding mismatch fails with the existing typed
   invariant/corruption behavior instead of silently falling back.

**Proposed.** Canonical ordered-`Int64` decoding must be owned below or beside
the index metadata fold. Reaching upward into covering execution, duplicating
its private decoder, or returning raw component bytes to session code is not
acceptable. A later design must either move the existing canonical decoder to
the index-key owner for reuse or prove an equally singular lower-layer decode
contract.

### Alternatives and complexity boundary

| Alternative | Decision | Reason |
| --- | --- | --- |
| Optimize the current reducer loop | Reject as primary fix | fold work is only 2.18M–2.20M; base-row work is about 95M |
| Add persisted sums | Reject | creates new correctness state, write amplification, recovery and format obligations when exact multiplicities already suffice |
| Add an aggregate result cache | Reject | adds keying, invalidation and snapshot-consistency state; the measured target is physical row hydration |
| Admit nullable, filtered or DISTINCT inputs | Reject for first slice | existing multiplicities do not prove those result semantics without another classifier or state source |
| Admit arbitrary numeric kinds | Reject for first slice | canonical decoding, coercion, scale and overflow axes expand materially beyond the measured `Int32` target |
| One shared exact `(count, sum)` fold for direct indexed `Int32` `SUM`/`AVG` | Carry into separate design | one existing authority can answer both terminals without new persisted or cache state |

**Proposed.** The later design should close as no-build if it cannot stay
within one cached-plan variant, one index-metadata operation, one shared
numeric fact, no new cache/module/persisted field/mutable owner/invalidation
edge, at most 250 net production Rust lines, and at most 8 KiB final raw Wasm
growth from the exact released predecessor. Final raw Wasm is primary; gzip is
secondary. These are design ceilings, not permission to implement here.

### Required proof for a later design

**Proposed.** Acceptance would require focused equality and physical-work
proof for:

- `SUM`, `AVG`, both terminal orders, aliases and repeated projection
  references over the same target;
- empty initialized metadata, deletion of the final value, one duplicate
  group, five duplicate groups, all-unique values, negative/zero/positive
  values and `Int32` extrema;
- checked component decode, multiplicity multiplication, decimal addition,
  AVG division and every overflow/failure boundary against the prepared
  reducer;
- selected metadata unavailable while another compatible index exists,
  becoming available later, generation mismatch, stale metadata and an
  unmaterialized journaled store;
- insert, update, delete, rollback, journal replay/fold, projection reset,
  publication, same-Wasm upgrade and reinstall;
- old request context retained across publication and a new context using only
  the new accepted target;
- unavailable and over-budget probes leaving no semantic budget charge before
  prepared fallback, with exact success charging its complete bundle
  atomically;
- unindexed, nullable, expression, filtered, DISTINCT, HAVING, grouped,
  ordered, mixed-target and other-terminal shapes remaining on the prepared
  route with equal result/error and physical work;
- zero row and physical index-entry reads on exact success, metadata entries
  bounded by distinct values, deterministic results, stable extent, Candid,
  exports and persisted formats unchanged; and
- no-default, SQL-only and all-feature builds, raw/gzip Wasm, cold/warm scales
  and an all-unique hostile distribution.

### Verdict

`SEPARATE DESIGN JUSTIFIED — NO 0.243 RUNTIME BUILD`

**Measured.** Current supported indexed `SUM` and `AVG` each spend more than
97.1M directly attributed instructions in row loading and reduction at 2,048
rows, while the existing five-entry exact authority completes below 0.6M cold
and 0.4M warm with no row or index-entry reads.

**Inferred.** A reducer-only cleanup cannot recover the dominant cost. One
authority-owned `(count, sum)` fold is technically sufficient and can reuse
the existing exact-or-prepared lifecycle without persisted sums or another
cache. Its benefit is large enough to justify a separately reviewed design,
but decoder ownership, exact projection semantics, hostile cardinality,
fallback budgets, code size and raw Wasm must be frozen before implementation.
