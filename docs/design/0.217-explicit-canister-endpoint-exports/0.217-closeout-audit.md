# IcyDB 0.217 Final Closeout Audit

Date: 2026-08-02

## Verdict

**Complete after bounded corrections.**

Patches 1 through 8 are present and demonstrably implement the accepted 0.217
design after the corrections in this closeout worktree. Source declarations
are the sole maintained public-endpoint authority: Cargo features compile
private capabilities, `icydb::endpoints!` emits one fixed public wrapper per
active declaration, and neither `icydb::start!()`, build generation, local
configuration, target inference, nor CLI inspection creates or suppresses an
endpoint.

The most serious defect found was a live CLI exception to that rule:
`icydb fixtures load` converted a deployed method-not-found response into
success based on local interpretation. That exception is deleted. The next
most serious finding was an unreachable 1,272-line declaration parser and
wrapper emitter left in the model crate after the public macro became the
authority. It had no caller and created no artifact, but represented a second
maintained endpoint vocabulary; it is deleted rather than retained as hidden
compatibility machinery.

No accepted schema, database execution, cursor, row/key/index/relation,
marker, journal, Identity, integrity-progress, or persisted byte format changes
were found. The closeout corrections await the user-owned release and push
workflow.

## Endpoint Authority Hard Cut

The committed diff deletes the root and all six maintained canister
`icydb.toml` files, the entire `icydb-config` crate, its workspace/dependency
edges, configuration discovery/parsing/resolution/reporting/model code, the
CLI `config` command tree, config help/tests, target inference, and child
process propagation. No live config file remains outside ignored build output.

Responsibility-based searches found no active source, script, CI, template,
README, installation guide, or contract that asks a user to create
`icydb.toml`, run `icydb config`, set `ICYDB_CONFIG_PATH`, or select endpoint
policy through `ICYDB_BUILD_TARGET`. Historical investigation reports and the
accepted migration history still name the retired system as history. The
integration crate still has a test-only `CanisterBuildOptions`; that type
selects explicit Cargo profiles/features for artifact construction and is not
the retired public `icydb::build::BuildOptions` endpoint model.

`build_configured_canister!`, public endpoint-selection `BuildOptions`,
`BuildSqlUpdatePolicy`, and public `generate_with_options` have no live owner,
alias, tombstone, or decoder. `build_canister!` accepts one type and derives the
path with `stringify!` from that same typed argument.

SQL, metrics, snapshot, schema, and fixture CLI operations now call the fixed
deployed name against the selected environment. The closeout removed the only
exception: fixture load no longer treats `CanisterMethodNotFound` or a
similarly worded replica failure as a successful skip. The shell also no
longer annotates an intentional missing `icydb_query` as probable stale Wasm.

## Macro And Binding Contract

`start!()` creates one root marker, one private `__icydb_generated` module, and
one include of `OUT_DIR/actor.rs`. It carries no IC query/update attribute.
`endpoints!()` creates a distinct root marker, statically requires
`__ICYDB_START_BINDING`, and recursively accepts only the frozen declaration
grammar. The root-binding references make nested placement fail. Fixed marker
and declaration symbols make duplicate active starts, endpoint blocks, and
same-kind declarations collide. An endpoint block without `start!()` fails
while resolving `crate::__icydb_generated`; that diagnostic is clear but is a
normal Rust resolution diagnostic rather than a custom `compile_error!`.

Declaration order is proved in both directions: maintained actors call
`start!()` before `endpoints!()`, while the package-shaped consumer declares
endpoints before `start!()`. Empty/default actors prove that no endpoint block
is required. The compile UI proves duplicate declarations and blocks, nested
placement, unknown names, invalid options, unsupported attributes, capability
failures, and an inactive conditional declaration. A new UI case proves an
ordinary handwritten query with the same Candid name fails because
`canister_query.icydb_metrics` is already defined.

The fixture load arm coerces the named path to the exact synchronous
`fn() -> Result<(), icydb::Error>` type before passing it to the private
handler. This is direct compiler enforcement; there is no general callable,
async, or alternate-error adapter.

## Frozen Endpoint ABI And Authorization

The 13 declaration forms in the frozen table map exactly to 11 deployed
methods. The two query-introspection forms share `icydb_query`; the two update
admission forms share `icydb_update`; and public/controller report forms share
their corresponding report method. They are mutually exclusive forms, not
grouped presets.

| Declaration family | Deployed name/mode | Capability | Authorization/handler result |
| --- | --- | --- | --- |
| `icydb_sql_query(introspection = false|true)` | `icydb_query`, query | `sql`; `true` also `sql-explain` | SQL controller, then `sql_query::<BOOL>` returning `SqlQueryPerfResult`. |
| `icydb_ddl` | `icydb_ddl`, update | `sql` | SQL controller, then `sql_ddl`. |
| `icydb_update(admission = ...)` | `icydb_update`, update | `sql` | SQL controller, then exactly the primary-key or bounded handler. |
| `icydb_integrity` | `icydb_integrity`, update | `sql` | SQL controller mapped into `SqlIntegrityError::Sql`, then `sql_integrity`. |
| fixture reset/load | fixed update names | `sql` plus canister `test-admin-api` | SQL controller, then reset or reset-and-handler. |
| compact/extended metrics | fixed query names | base / `metrics-extended` | Explicit public or operational-controller token, then the matching report handler. |
| metrics reset | `icydb_metrics_reset`, update | base | Operational controller, then reset. |
| snapshot | `icydb_snapshot`, query | base | Operational controller, then snapshot. |
| schema | `icydb_schema`, query | base | Explicit public or schema-controller token, then schema. |

No declaration emits a composite query or lets the caller choose a mode or
public name. Runtime tests establish the exact
`SqlSurfaceControllerRequired`, `SchemaSurfaceControllerRequired`, and
`OperationalSurfaceControllerRequired` classifications with
`ErrorOrigin::Interface`, including the integrity error wrapper. Authorization
runs before parsing/execution and returns a typed value rather than a trap or
ingress rejection.

`icydb_sql_query` deliberately remains the source spelling while the deployed
method remains `icydb_query`. With introspection disabled, `EXPLAIN`,
`DESCRIBE`, `SHOW CONSTRAINTS`, `SHOW INDEXES`, `SHOW COLUMNS`, `SHOW ENTITIES`,
`SHOW STORES`, and `SHOW MEMORY` all classify as requiring introspection and
return `SqlIntrospectionDisabled`; ordinary `SELECT` does not. The true form
has a targeted `sql-explain` compile failure.

`SqlQueryPerfResult` has exactly the frozen `result` plus eight `nat64`
attribution fields. `SqlQueryResult::Explain` is compiled whenever `sql` is
compiled, including a build without `sql-explain`. The checked-in 837-line
transitive Candid golden is rendered from maintained public Rust types. The
built-artifact gate independently compares each extracted Candid method name
and mode with each raw-Wasm IC export; wrapper type tracing and the golden own
the nested argument/result proof.

## Private Capability Ownership

Generated actor output contains only inherited-visibility dispatch functions,
handlers, and a `pub(crate)` reexport module. Searches for query/update,
`export_name`, `no_mangle`, `canister_query`, and `canister_update` in the
generator find only the explicit forbidden-token test literals. Raw-Wasm
inspection is the final proof that no equivalent route survived code
generation or linking.

The final public macro is the sole wrapper emitter. Closeout removed the
unreachable internal endpoint specification/parser/emitter from
`crates/icydb-model/src/build/actor/endpoint.rs`; only authorization-helper
generation remains. This is a hard deletion with no hidden or deprecated
macro replacement.

The asymmetry is demonstrated in both directions. SQL-enabled
`one_entity_sql_query` has no IcyDB endpoint declarations and exports no IcyDB
method. `default_empty` and both typed-query actors likewise gain no implicit
exports. Active declarations without SQL, SQL-explain, extended metrics, or
the consuming-canister fixture feature fail. The inactive conditional DDL
fixture compiles without SQL. Raw production artifacts omit local-only method
names and exclusive handler symbols.

## Fixture Safety And Failure Semantics

All maintained fixture methods require the source declaration, the non-default
canister `test-admin-api` feature, and controller authorization. Production
profiles omit the feature. Enabling the capability without a declaration is
covered by the SQL-capable/no-export actors and the `sql_perf` production
fixture omission.

The generated load handler calls the reset handler exactly once and then the
coerced function pointer. Reset statements are emitted in deterministic schema
entity order and execute the ordinary trusted SQL delete path; user fixture
writes use normal committed structural mutation paths. There is no publish of
one transaction spanning reset and load. A later reset error can therefore
leave an earlier entity reset, and a handler error can leave a fully reset or
partially reloaded database. Token/order and implementation-path tests prove
that contract; a live actor does not yet inject failures at both boundaries.
That is a residual evidence limitation, not evidence of rollback or a
different implementation.

## Maintained Migration And Artifact Matrix

`MAINTAINED_CANISTER_POLICIES` contains exactly the seven former config-owned
actors plus `default_empty` and `default_empty_metrics`. Every nested build
uses `--no-default-features --locked`, selects exactly the frozen feature row,
and writes to distinct `target/icydb/canister-production` or
`target/icydb/canister-local` directories. Make, app-build, and fixture helpers
select that code-owned profile; no endpoint-policy environment is passed to
IcyDB.

The complete 18-build gate confirms:

- `default_empty`, SQL-only query audit, and typed-query actors have no
  generated IcyDB methods;
- `default_empty_metrics` explicitly has compact metrics and reset;
- production SQL and bounded SQL omit `icydb_query`, both fixture methods, and
  `sql-explain` while retaining their explicitly declared production methods;
- production RPG additionally omits extended metrics and
  `metrics-extended`;
- `sql_perf` explicitly declares compact metrics/reset, exposes generated
  fixtures only locally, performs one generated reset per load, and retains
  its separate handwritten performance API; and
- Candid method names/modes and raw-Wasm IC function exports are identical for
  every artifact and equal the frozen policy.

The gate inspects the raw module export section, not source spelling or gzip
size. Direct raw scans also find local-only public names and private handler
symbols in local actors and not in their production counterparts.

## Query-Only Grouped Follow-Up

Patches 7 and 8 remain distinct from endpoint authority. `DynamicQuery` and
generated `Query<E>::execute_grouped()` lower to the existing
`StructuralQuery`, accepted-schema binding/cache, grouped planner/executor, and
public-value finalizer. There is no SQL response DTO, SQL compiler, second
planner, second executor, physical decoder, or cursor format in that path.

Ordered group fields and aggregates survive the facade boundary. Nonzero group
and group-byte limits are required. Public and trusted admission retain their
existing distinction; scalar selection on grouped output is rejected.
Accepted-binding staleness, page/budget/full-scan policy, and opaque cursor
validation retain their canonical structured diagnostics. Terminal-shape and
scalar-selection mistakes are query-intent failures; absent/zero grouped
limits are read-admission failures rather than planner invariants.

The query-only dependency tree contains `icydb/query` and no SQL feature. A
generated one-entity query-only canister executes its real typed grouped
terminal at runtime. Successful SQL envelopes, the grouped cursor wire vector,
accepted schema, and persisted data remain unchanged. `GroupedQueryOutput` is
the intentional new 0.217.1 public grouped facade shape.

## Findings And Corrections

### High — CLI fixture absence overrode deployed authority (corrected)

`crates/icydb-cli/src/icp/commands/fixtures.rs` classified method-not-found
stderr and returned success. That contradicted the frozen rule that the replica
is authoritative. The classifier and skip branch are removed; a direct
regression asserts `CanisterMethodNotFound` remains an error. The shell's stale
Wasm hint for a missing SQL endpoint was removed for the same reason.

### Medium — unreachable second declaration/emitter vocabulary (corrected)

`crates/icydb-model/src/build/actor/endpoint.rs` retained a complete private
endpoint grammar and wrapper emitter with no production caller. It did not
affect generated output, but keeping it would invite a second authority. The
file now owns only private authorization helper emission, reducing it by about
1,200 lines.

### Medium — closeout proof omitted several rejection boundaries (corrected)

The original UI set did not directly cover duplicate blocks, handwritten IC
symbol collisions, invalid options, unsupported attributes, inactive
declarations, or three feature conjunctions. Focused fixtures now cover those
boundaries and pass in no-feature, SQL-only, and full endpoint-capability
profiles.

### Low — active documentation retained retired policy language (corrected)

The SQL surface map, SQL subset contract, and durability guide still described
TOML/build-target endpoint policy. They now point to source declarations and
Cargo capabilities. Historical reports remain historical.

### Low — Patch 6 cost table was not the final tagged line (corrected label)

The nine-actor table was measured before Patches 7 and 8, although later text
could be read as the final 0.217.2 matrix. The status now labels it as Patch 6
evidence and records exact final-tag representative artifacts below.

### Residual evidence limits

- Missing `start!()` fails clearly through unresolved
  `crate::__icydb_generated`, but not through a bespoke diagnostic.
- Duplicate-start rejection follows mechanically from fixed root item names;
  no standalone trybuild actor fixture currently generates `actor.rs` solely
  to snapshot that collision.
- Fixture partial-reset and partial-reload behavior is proved from exact call
  ordering and normal commit paths rather than a live fault-injection test.
- The full 18-artifact export matrix was rerun at the final implementation
  boundary, but the raw `wasm-release` byte-size build for every actor was not
  repeated after Patches 7 and 8. Final tagged representative size and
  instruction measurements were reproduced.

None of these limitations exposes a second authority, implicit method, format
change, or observed runtime failure.

## Public, Persisted, Execution, And Compatibility Impact

The intentional 0.217 public changes are:

- public generated endpoints are absent unless source-declared;
- TOML/config/target endpoint selection and CLI config support are removed;
- `SqlQueryPerfResult` has a stable public Rust owner without changing its
  deployed Candid record;
- `GroupedQueryOutput` and grouped dynamic/typed terminals are added under
  `query` in 0.217.1; and
- the never-produced Rust `TypedQueryError::Binding` variant is removed in
  0.217.2.

The closeout corrections change CLI failure handling, compiler diagnostics,
tests, host build exactness, and documentation. They add no endpoint, Candid
type, accepted schema, cursor, database algorithm, or persisted byte. There is
no alias, compatibility reader, disabled stub, dual dispatch, runtime endpoint
registry, target-derived policy, or retained parser tombstone.

Execution complexity is neutral: wrappers authorize and call the same private
handlers, and grouped facades use the existing engine. Build/maintenance
complexity is materially lower after deleting the config system and the dead
emitter. The audit-owned correction is approximately net `-1.1k` lines despite
expanded UI/runtime/docs evidence.

## Remaining Risk

There is no known 0.217 release blocker after the bounded corrections. The
remaining risk is evidence granularity rather than contradictory behavior:
the live fixture failure matrix and a final post-Patch-8 all-actor release-size
matrix could strengthen the record, and a custom missing-start diagnostic
could improve ergonomics. None warrants reopening the endpoint authority,
authorization, migration, grouped-query, or persisted-format design.
