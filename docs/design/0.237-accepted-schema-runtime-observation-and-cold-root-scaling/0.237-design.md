## Audit Outcome

The accepted runtime root is the right authority. It gives every query, write,
integrity operation, and recovery consumer one immutable database-wide accepted
root and one complete set of compiled entity contracts. 0.237 does not weaken,
split, or replace it.

The released predecessor construction and observation flow nevertheless
repeated work:

1. every lookup captures and sorts every registered store root before checking
   whether the database-wide runtime root is already cached;
2. a cold root loads the complete accepted runtime-entity inventory;
3. each entity then re-enters its store's current accepted bundle selection,
   including current-root selection and accepted identity-closure validation;
4. each entity runtime is compiled and retained; and
5. only after every entity succeeds is the root published.

`SchemaStore` already has the missing reuse authority. Its existing
`accepted_bundle_cache` is keyed by the selected accepted root, retains the
verified immutable bundle/value catalog, caches entity selections, and is
cleared by accepted-root writes, journal projection reset, and retained-entry
replacement. `current_accepted_schema_authority_matches` already relies on
that fact to avoid a stable root read when the cached selection is available.
0.237 reuses this owner rather than adding another cache or generation.

The measured need is material:

- 0.227's fully ready populated post-upgrade lifecycle observation used
  10,593,191 instructions against a 10,750,000 gate, leaving 1.46% headroom;
- 0.228 found that co-locating an unrelated 64-index entity raised a
  2,048-row/three-index recovery probe from 21,617,488,641 to
  45,190,180,079 instructions; and
- 0.236 widened a shared accepted audit schema without changing two query
  routes, moving the maximum prefix fixture to about 5.288 million
  instructions and the sparse intersection to about 2.264 million while their
  physical work remained 65 index entries/no row fetches and 41 entries/one
  row fetch respectively.

These measurements do not prove that all unrelated-schema cost is removable.
The current root deliberately validates every accepted store and compiles every
entity before publication. They do prove that repeated store/bundle observation
must be isolated before any further instruction ceiling is raised.

## Semantic Boundary: Global Validity Versus Repeated Materialization

0.237 preserves the current global failure boundary.

Work required to establish one accepted runtime root includes:

- recovery/readiness admission;
- registered-store topology and canonical ordering;
- both checksummed accepted-root slots for every store;
- immutable bundle hash, current-format decode, store binding, constraint-job
  closure, identity-state closure, and accepted value catalogs;
- database-wide unique entity tag, path, and canonical-name checks;
- complete accepted inspection plans, row contracts, constraints, indexes,
  relations, identity declarations, `SchemaInfo`, and `EntityAuthority`; and
- unchanged-root/incarnation confirmation before publication.

That work remains fail-closed and complete. A corrupt unrelated accepted entity
continues to prevent publication of the database-wide root. Cold root work may
therefore scale once with the complete bounded accepted schema.

What is not semantic authority is repeating the same selected-root, verified
bundle, or global closure work for every entity in that bundle. 0.237 removes
that repetition. It does not defer entity compilation until first use, return a
partially compiled root, or change when corruption becomes observable.

This distinction is normative. If the measured improvement requires lazy
entity validity, independently invalidated fragments, or target-only corruption
semantics, this design no longer authorizes implementation and must return to
review.

## No-Build Gate

The no-build choice preserves correct behavior but retains a demonstrated IC
scaling tax. Raising lifecycle, recovery, and query fixture ceilings again
would hide the dependency without changing the underlying work.

The smallest justified correction is:

1. on a cold root, select and validate each store's current accepted authority
   once;
2. derive every entity selection for that store from the same verified bundle
   borrow rather than re-entering store/root selection per entity;
3. compile every entity runtime exactly once and publish the same complete root;
4. on a warm root, prove store-root continuity through the existing cached
   accepted-bundle selection before performing stable root capture; and
5. fall back to the sole cold authority whenever that cheap witness is absent
   or mismatched.

Simpler alternatives were considered:

- **Raise instruction ceilings:** rejected; it preserves the bad scaling
  dependency.
- **Trust the root cache without a current witness:** rejected; schema
  publication or recovery could leave stale accepted authority visible.
- **Add a publication epoch or generation:** rejected; the current accepted
  root and bundle-cache invalidation already provide the needed witness.
- **Add per-entity caches beside the root:** rejected; entity runtime state
  remains owned by the one root.
- **Compile entities lazily:** rejected for this line because it changes the
  global corruption boundary and query-message cache persistence.
- **Persist compiled schema derivatives:** rejected; accepted snapshots remain
  runtime authority and heap products are rebuilt after upgrade.
- **Reconstruct from generated models:** forbidden; generated models remain
  proposal/reconciliation/test inputs only.

## Decision Summary

### Cold root construction

One cold construction performs these phases:

1. admit current recovered state;
2. capture the ordered accepted root for every registered store;
3. for each store, borrow one verified current accepted bundle and derive its
   complete ordered entity-selection batch from that same authority;
4. validate database-wide entity uniqueness across those batches;
5. compile each accepted entity runtime exactly once from its already-selected
   accepted snapshot and value catalog;
6. verify the database incarnation and accepted store roots remain unchanged;
   and
7. publish one complete immutable `AcceptedSchemaRuntimeRoot`.

There is no partially usable root. Any failure discards the candidate root and
returns the existing typed internal/corruption error. The accepted store bundle
cache may retain only products it already retains today; 0.237 adds no second
candidate publication or repair flow.

### Warm root observation

The common warm path checks the database's existing cached runtime root first.
For every store identity retained by that root, it asks `SchemaStore` whether
its existing validated bundle-cache selection still names the same accepted
root. A complete match reuses the runtime root without stable root-slot reads,
bundle decode, entity enumeration, or allocation of a replacement store-root
vector.

If any store witness is absent, invalidated, mismatched, or the registered
store topology is inconsistent, the lookup performs the sole current full
store-root capture. Matching roots may still reuse the existing runtime root;
changed roots rebuild through the cold flow. A borrow conflict or corruption
remains an error, not a cache miss.

A retained store whose accepted root is absent cannot be distinguished from an
unloaded bundle cache without adding state. It therefore never qualifies for
the fast witness and uses the authoritative capture. This is bounded by the
existing store limit and avoids an absent-root cache state or publication epoch.

The fast witness does not become authority by itself. It is a projection of
the existing verified `SchemaStore` bundle cache, whose selection is invalidated
before accepted root-key mutation. No new epoch, revision, callback registry,
or cross-layer publication notification is introduced.

### Publication and invalidation

Accepted root-key mutation inside `SchemaStore` remains the canonical volatile
cache-invalidation owner. Normal marker-bound publication, live journal replay,
canonical fold, overlay reset/retirement, reinstall, and upgrade must all make
the warm witness unavailable or different before stale authority can be reused.

The seven SQL DDL call-site invalidations are duplicated policy once this
owner-side proof is complete. Patch 2 may delete them and the session-local
invalidation entrypoint only after direct tests prove every maintained root
publication/recovery path invalidates the existing bundle witness. It may not
replace them with commit-to-session callbacks or a new generation counter.

An unrelated-schema publication intentionally invalidates the database-wide
root. The next access may be cold once; 0.237 does not add granular entity
invalidation. The rebuild must still avoid repeated per-entity re-entry into
the same store authority.

## Canonical Ownership

| Concern | Canonical owner after 0.237 |
| --- | --- |
| Persisted accepted bundle/root bytes and root-key invalidation | existing `SchemaStore` |
| Verified current bundle/value catalog/entity selections | existing `SchemaStore` accepted-bundle cache |
| Database-wide store/entity ordering and duplicate detection | existing runtime entity/root construction boundary |
| Complete compiled accepted runtime authority | existing `AcceptedSchemaRuntimeRoot` |
| Query/write/integrity entity projection | existing `AcceptedSchemaCatalogContext` / `EntityAuthority` |
| Marker, journal, replay, fold, and recovery | existing commit/recovery owners, unchanged |

The maintained flow remains:

```text
accepted SchemaStore root
        -> one verified store-bundle projection
        -> one complete database runtime-root compilation
        -> immutable entity contexts
        -> existing query/write/integrity consumers
```

There is one root cache, one accepted bundle cache per existing `SchemaStore`,
one runtime root builder, and one failure path.

## Bounds And Cost Model

0.237 changes no accepted schema, store, entity, field, index, relation, or
constraint limit. It inherits the current bounded codecs and catalog maxima,
including at most 38 persisted store allocations, 4,096 schema assignments,
1,024 entities per fragment, and 64 indexes per entity.

The intended complexity is:

- cold root slot selection: once per registered store before and after
  compilation, as required by the unchanged atomicity proof;
- verified effective bundle/closure selection: once per store, not once per
  entity;
- accepted entity runtime compilation: once per accepted entity;
- warm root validation: one cheap existing-bundle witness per registered store,
  with zero stable root-slot reads when every witness is present; and
- changed/uncertain authority: one fallback to the existing full capture and,
  only when roots differ, one cold rebuild.

No caller selects these costs or supplies a cache policy. There is no retry
loop: a failed or corrupt observation returns its existing typed failure.

## Performance Acceptance

Patch 1 retains the historical measurements above but does not pretend they are
a current `v0.236.1` phase breakdown. Patch 2 must first record exact owner-local
counters for root-slot reads, verified bundle selections, complete closure
validations, entity-selection derivations, entity compilations, root
publications, and warm-root reuse. These counters remain test-only; no new
public metric or Candid field is authorized.

The maintained fixture matrix holds the target entity and query constant while
varying unrelated accepted authority:

| Target | Unrelated authority | State |
| --- | --- | --- |
| small three-index entity | small entity | cold and warm |
| same target | one 64-index entity in the same store | cold and warm |
| same target | one 64-index entity in another store | cold and warm |
| same target | maximum practical bounded multi-entity audit shape | cold and warm |

It runs after fresh install, same-Wasm post-upgrade, target-schema publication,
and unrelated-schema publication. Query results, errors, accepted root identity,
and physical query work must remain identical.

Acceptance requires:

- one verified bundle/closure selection per store and one compilation per
  entity on a cold root, with no count proportional to entities multiplied by
  total bundle size;
- zero stable accepted-root reads, bundle decodes, closure validations, entity
  compilations, or runtime-root publications on a fully witnessed warm hit;
- warm target observation with the 64-index unrelated entity to remain within
  the greater of 3% or 250,000 instructions of the small-unrelated control;
- the target entity's own cold compilation phase to remain within that same
  3%/250,000 gate when unrelated schema grows;
- the complete large-unrelated cold path to improve materially against exact
  `v0.236.1`, with a provisional minimum 25% reduction subject to Patch 2
  recording the fresh baseline before changing production logic; and
- no new stable-memory read, row/index read, query-plan branch, or response work
  on ordinary warm queries.

Cold total work is not required to become independent of all unrelated schema:
global validation and one compilation per entity remain deliberate. It must
become single-pass rather than repeated. If the fresh baseline does not show
the repeated work or the candidate cannot meet the structural proof, the line
stops at no-build instead of adding laziness.

## Wasm And Complexity Gates

Raw non-gzipped Wasm is authoritative. The exact released `v0.236.1` baselines
are:

| Surface | Compiler Wasm | Final raw Wasm | Gzip | Candid | Exports |
| --- | ---: | ---: | ---: | ---: | ---: |
| Typed query | 2,419,238 | 2,118,718 | 812,164 | 64 | 6 |
| SQL query | 3,726,899 | 3,284,298 | 1,298,460 | 57 | 6 |

The implementation goal is non-positive production source and raw-Wasm growth:
delete repeated lookup/invalidation logic and reuse existing owners. A
candidate stops for review if either representative raw Wasm grows by more than
the smaller of 32 KiB or 1%, or if maintained runtime code grows by roughly
200 net lines or requires a new production module. Those are review signals,
not permission to trade correctness for line count.

Candid bytes, exports, stable-memory length, stable memory IDs, persisted
formats, generated surfaces, and public Rust APIs must remain unchanged.

The complexity readout must report:

- independent behavior axes: none;
- persisted/public states: none;
- duplicated authority removed: per-entity store/bundle re-entry and, if fully
  proven, SQL DDL call-site cache invalidation;
- retained duplication: the second cold root capture, because it proves the
  root did not change during complete compilation; and
- final production/test/documentation file and line deltas.

## Correctness Invariants

1. Accepted schema snapshots and their current store roots remain runtime
   authority; generated models never reconstruct runtime state.
2. Exactly one complete immutable database-wide runtime root is visible to
   consumers.
3. A cold root validates every accepted store/entity and compiles every entity
   before publication.
4. An unrelated corrupt entity still fails complete root construction.
5. Each store's current accepted bundle and global closure are selected at most
   once during one cold construction.
6. Each accepted entity runtime is compiled exactly once during one cold
   construction.
7. A warm hit is accepted only when every existing `SchemaStore` bundle-cache
   witness names the exact store root retained by the runtime root.
8. An absent or mismatched warm witness falls back; it never proves freshness.
9. Schema root publication invalidates the existing bundle witness before a
   new accepted root can be observed.
10. Target and unrelated schema publication both prevent reuse of the old
    database-wide root.
11. Recovery replay/fold, reinstall, and upgrade cannot reuse a root compiled
    from predecessor authority.
12. Cold/warm status affects cost only, never results, errors, authorization,
    root identity, query planning, mutation semantics, or corruption policy.
13. No post-commit fallible runtime-root construction is added to schema
    publication.
14. No persisted derivative, new cache, epoch, mode, setting, timer, job,
    endpoint, or compatibility reader is added.

## Recovery And Hard Cut

0.237 is an internal pre-1.0 hard cut of the heap-only root observation and
construction flow. Patch 2 replaces the old per-entity re-entry loop and warm
capture-before-cache order in place. It must not retain a compatibility builder,
feature flag, dual lookup path, fallback to generated models, or predecessor
test fixture.

No version discriminator changes because no persisted, cursor, wire, generated,
or public representation changes. Upgrade naturally clears the heap-only
runtime root and rebuilds the sole current form from current version-1 accepted
authority. Existing `SchemaStore` caches also reopen empty and therefore force
the complete cold path before any warm witness is trusted.

Marker publication, journal append, replay, canonical fold, live overlays,
root-slot codecs, bundle codecs, accepted fingerprints, and database
incarnation identity are unchanged. 0.237 adds no migration or adoption step.

## Rejected Scope

0.237 does not add:

- lazy or partial entity validity;
- per-entity root caches, independently invalidated root fragments, or granular
  schema-publication invalidation;
- a new volatile/persisted epoch, revision, generation, or publication
  notification registry;
- persisted compiled `SchemaInfo`, inspection plans, row contracts, or entity
  authority;
- generated-model reconstruction, repair, fallback, or dual authority;
- planner, executor, cardinality, query-cache, SQL grammar, cursor, or mutation
  changes;
- background warming, timer work, startup pages, or caller-triggered cache
  control;
- caller-selected budgets, cache policy, or performance mode;
- changes to recovery admission, marker atomicity, journal convergence, or
  accepted-schema corruption taxonomy; or
- another instruction-ceiling increase as a substitute for removing work.

Bound public SQL invocation and authenticated SQL continuation remain the
preferred later product capability. Million-row updates continue through the
existing durable mutation-job executor; they are not part of this line.

## Acceptance Evidence

Closeout requires all of the following:

- exact `v0.236.1` and candidate phase counts for small and large unrelated
  schemas;
- one store bundle/closure selection per store and one entity compilation per
  entity on cold construction;
- zero stable root reads and zero compilation on a fully witnessed warm hit;
- complete fail-closed corruption for root slots, bundle hash/decode, store
  binding, identity/constraint closure, duplicate tag/path/name, row layout,
  index, relation, and identity-plan failures;
- old contexts remain bound to their immutable old root while all new contexts
  observe the complete new root after target or unrelated publication;
- missing or mismatched witnesses take the authoritative fallback and never
  return stale state, while borrow conflicts and corruption fail closed;
- replay, fold, overlay reset, reinstall, and same-Wasm upgrade cannot preserve
  a stale warm witness;
- cold and warm instruction gates above, including the 64-index unrelated
  fixture and current lifecycle/recovery controls;
- identical query results and physical row/index work across every comparison;
- unchanged stable bytes apart from ordinary fixture state, unchanged Candid
  and exports, and no new memory ID or format field;
- final typed and SQL raw-Wasm comparison against exact `v0.236.1`; and
- a complexity report demonstrating one root/cache flow and no new behavior
  axis.

Repository-wide validation and release remain user-owned.
