## Predecessor-Surface Findings

The released predecessor runtime root was already one immutable database-wide
authority and remains so. Its repeated work was inside the observation/build
flow:

- warm lookup captures and sorts every store root before consulting the
  runtime-root cache;
- cold construction enumerates accepted entities from verified store bundles;
- each entity then re-enters current accepted catalog selection, causing
  selected-root/bundle/identity-closure work to repeat; and
- every entity runtime is compiled before the root is published.

`SchemaStore::accepted_bundle_cache` already retains the selected verified
bundle, value catalog, and entity selections and is invalidated by accepted
root-key mutation and recovery projection reset. The maintained
`current_accepted_schema_authority_matches` path already treats a cached
selection as the current in-memory witness. This is sufficient authority for a
cheap warm check and a single-pass cold store projection; a second cache or
generation is unnecessary.

## Frozen Decisions

1. Cold root validity remains global. Every accepted entity still compiles
   before root publication, and unrelated corruption still fails the root.
2. Each store's current accepted bundle/closure is selected once per cold root,
   and every entity selection is derived from that same verified authority.
3. Each accepted entity runtime compiles exactly once per cold root.
4. Warm lookup first uses the existing `SchemaStore` bundle-cache selection as
   a witness. A fully witnessed match performs no stable root read or rebuild.
5. Missing, mismatched, or absent-root witnesses take the sole authoritative
   full capture; they never prove freshness. Borrow conflicts and corruption
   fail closed. No absent-root cache state is added.
6. Target and unrelated schema publication both invalidate the database-wide
   root. Granular invalidation is not added.
7. SQL DDL call-site invalidation may be deleted only after the existing
   `SchemaStore` root-key invalidation is proven complete across publication,
   replay, fold, reset, and retirement.
8. No lazy entity validity, extra cache, epoch, persisted derivative, generated
   fallback, public surface, mode, job, timer, or compatibility path is allowed.

## Patch 2 Implementation Evidence

The implementation replaces the old per-entity re-entry and
capture-before-cache order in place:

- cold construction retains the selected physical root with each existing
  `StoreHandle`, admits the selected bundle once, and derives every runtime
  entity plus catalog selection from that same verified borrow;
- `AcceptedSchemaEntityRuntime` consumes that preselected catalog authority and
  still compiles every inspection plan, row contract, `SchemaInfo`, and
  `EntityAuthority` before one complete root is published;
- a cached runtime root first compares every non-empty retained store root with
  the existing verified bundle-cache selection, without a stable read;
- a missing, mismatched, empty-root, or topology witness falls back to the sole
  full store-root capture, while borrow/corruption errors remain typed failures;
  and
- root-key mutation remains the sole cache-invalidation owner. Seven SQL DDL
  call-site invalidations and the session invalidation method were deleted; no
  callback, epoch, new cache, or second publication route replaced them.

Test-only phase evidence records:

The warm assertion is repeated across 1,000 new request sessions. A registered
store with no accepted root deliberately performs one root selection on a warm
reuse attempt, then reuses the matching database root without recompilation.
Target and unrelated publication both replace the root while old contexts keep
their immutable old identity. The maintained PocketIC DDL journey confirms
that publication still updates `DESCRIBE`, `EXPLAIN`, and indexed reads after
removing caller-side invalidation. The focused journaled replay/fold test also
proves that projection reset clears a populated bundle witness before reopening
the folded accepted root.

Focused no-default, SQL-only, and all-feature core checks pass. All-feature
core Clippy is warning-clean. Patch 2 does not claim the production-shaped
large-unrelated IC instruction matrix owned by Patch 3.

met the structural gate: one verified bundle/closure selection per store, one
compilation per entity, and zero stable root/bundle/compile work on a fully
witnessed warm hit.

The large-unrelated fixture must hold target query/result/physical work fixed.
Warm and target-owned cold phases remain within the greater of 3% or 250,000
instructions of the small-unrelated control. Complete large-unrelated cold work

review.

growth. The explicit captured-root proof costs approximately 170 net maintained

behavior axis remains forbidden. Candid, exports, stable state, and public APIs
