# IcyDB 0.241 Global-Aggregate Attribution Convergence

Status: CLOSED — MEASURED NO-BUILD — CANDIDATE NOT RELEASED

Last updated: 2026-08-25

Exact released predecessor:
`v0.240.1` at `1cf73c9346595b4d6a6a7845cb2297df1dba44d5`.

## Outcome

Collapse the ordinary and diagnostics SQL global-aggregate planning and
execution branch trees onto one semantic flow. Diagnostics may observe that
flow, but may not select a target, resolve a fallback, interpret a cache entry,
or execute a different branch tree.

This is a hard-cut internal convergence. It adds no SQL capability, public
surface, execution route, cache, accepted-schema authority, persisted state,
configuration, compatibility path, or diagnostic fact. Its primary outcome is
less maintained production code. Smaller final raw Wasm is desired, and raw
Wasm growth is prohibited, but line deletion is not presented as proof of a
binary saving.

## Measured Closeout

The candidate correctly converged the six paired branch families onto one
exact-or-prepared planning and execution flow. It introduced no cache, mutable
owner, state, mode, invalidation edge, public surface or persisted
representation. The final bounded shape removed 118 net production lines
across the six touched runtime files, exceeding the 80-line deletion gate.

Focused exact-count and ordinary aggregate evidence remained correct and
within the frozen instruction gates. Exact entity and indexed-distinct routes
retained zero row fetches and zero index-entry reads. The ordinary aggregate
controls measured 114,400,148 instructions cold and 114,062,836 warm, which
are respectively 0.299% and 0.119% above the frozen predecessor observations
and below the 1% closeout limit. Exact indexed distinct measured 467,387 cold,
299,035 true-warm and 940,500 for 2,048 all-unique values. Its prepared
all-unique control remained 136,635,465 instructions, and same-Wasm recovery
retained the exact result and zero row/index traversal.

Source convergence did not translate into production binary convergence. The
exact released SQL-only final subject was 3,299,581 raw bytes and 1,308,763
deterministic-gzip bytes. Three progressively narrower candidate shapes
measured:

| Candidate shape | Final raw Wasm | Raw delta | Gzip bytes | Gzip delta |
| --- | ---: | ---: | ---: | ---: |
| Shared optional recorder throughout | 3,301,324 | +1,743 | 1,309,562 | +799 |
| Recorder compiled out of production | 3,300,360 | +779 | 1,309,052 | +289 |
| Merged prepared resolver/execution owner | 3,299,967 | +386 | 1,308,847 | +84 |

The first shared candidate also reduced the diagnostics SQL-audit subject from
the exact released 4,465,729 raw bytes to 4,464,611 (-1,118), meeting the
diagnostics target. That does not override the production no-growth gate. The
candidate Candid digest remained
`a22d2bfdf48ab6473734010e1e1a79c8dd3fc23d277e204e611a0c884963c474`
with six final exports.

The production growth is attributed to post-inlining/code-layout effects from
converging differently shaped ordinary and attributed control envelopes, not
to new state or behavior. The frozen rule explicitly rejects treating source
deletion as proof of a binary saving. All runtime changes from this candidate
were therefore reverted to exact `v0.240.1` behavior. No convergence
implementation or measurement fixture is retained. The later independently
authorized 0.241 visibility cleanup changes only module reachability and does
not reopen or release this candidate.

## Demonstrated Need

The released global-aggregate flow retains six measured/ordinary function
pairs across three files:

| Owner | Ordinary branch | Diagnostics branch |
| --- | --- | --- |
| Prepared-plan resolution | `resolve_global_aggregate_prepared_plan_for_authority` | `resolve_global_aggregate_prepared_plan_for_authority_with_phase_attribution` |
| Compiled prepared-plan resolution | `resolve_compiled_global_aggregate_prepared_plan` | `resolve_compiled_global_aggregate_prepared_plan_with_phase_attribution` |
| Exact target resolution | `resolve_compiled_exact_count_target` | `resolve_compiled_exact_count_target_with_phase_attribution` |
| Exact target execution | `execute_exact_count_target` | `execute_measured_exact_count_target` |
| Exact-or-prepared orchestration | `execute_global_aggregate_after_exact_count_target` | `execute_measured_global_aggregate_after_exact_count_target` |
| Compiled aggregate entry | `execute_global_aggregate_compiled_statement_ref_with_catalog` | `execute_global_aggregate_compiled_statement_ref_with_phase_attribution` |

`aggregate_plan.rs`, `exact_count.rs`, and `global_aggregate.rs` contain 1,015
lines in the released tree. That total is a discovery signal, not a deletion
target. The actionable duplication is the repeated exact/prepared target
matching, fallback-authority propagation, shared-plan extraction, cache
installation, and result/error handling in the six pairs above.

The duplication is current rather than hypothetical. The exact-distinct work
shipped in `v0.240.1` extended both sides of the branch tree. A future exact
target or fallback rule must now be propagated through ordinary execution,
diagnostics execution, ordinary plan resolution, and diagnostics plan
resolution.

The repository already has the smaller pattern required to remove this
duplication:

- `QueryPlanCompilePhaseRecorder::none()` and `::new(...)` let one query-plan
  cache flow either record or omit phase attribution;
- `GroupedSqlDiagnosticsCollector` keeps grouped result finalization on one
  semantic path; and
- `SqlExecutePhaseAttribution` already owns outward aggregation of planner,
  store, executor, terminal, and response counters.

The selected slice reuses those ownership principles locally. It does not add
a general observer framework.

## Wasm Evidence And Ceiling

The released SQL-only final subject is 3,299,581 raw bytes. The locally retained
diagnostics-heavy SQL audit subject built from the same released revision is
4,465,729 raw bytes. Their SHA-256 values are respectively
`f950e70cf9665768fb245c315867b570618d0fb0d3083a4c923026d9d1d8f988`
and `4f851f1b0d27fa7592087fd8158add76614fd5791e4c43861be05043fdf20a7f`.

An isolated symbol-bearing build from the exact tag produced a 6,562,844-byte
named, shrunk attribution artifact. In that non-deployable artifact,
`execute_trusted_sql_query_with_attribution` alone retained 14,642 shallow
bytes. This proves the diagnostics flow is linked into the audit subject; it
does not prove how many bytes this cleanup can remove after inlining, LTO and
final Binaryen shrinking.

Implementation must rebuild the exact tag and candidate through the same
toolchain, features, profile, Candid metadata policy and post-link pipeline.
The retained artifacts above are orientation and reproducibility checks, not a
substitute for the clean comparison.

## Selected Structure

```text
ordinary entry ───────┐
                      ├─> one fingerprint-checked exact-or-prepared resolver
diagnostics entry ────┘          │
                                 ├─> one exact target execution/fallback flow
                                 ├─> one prepared aggregate execution flow
                                 └─> one result/error projection
                                           │
                                           └─> optional attribution projection
```

The semantic flow owns all decisions. Optional diagnostics state may only
measure already selected phases and construct the outward attribution value.

For planning, the implementation should reuse the existing optional
`QueryPlanCompilePhaseRecorder` pattern. Visibility may be narrowed or widened
only as far as the SQL/query-plan sibling boundary requires. The recorder must
not become public API or a general executor callback.

For execution, the implementation may retain one small owner-local conditional
measurement boundary around the selected exact or prepared operation. The
result of that operation must then enter one common outcome matcher. It must
not retain complete measured and unmeasured match trees behind different names.

The two outward entrypoints may remain because they return different envelopes.
They must be thin adapters into the shared internal flow. Normal execution
must not read performance counters, install physical-access attribution, or
allocate diagnostics state merely because the crate was compiled with the
`diagnostics` feature.

## Canonical Ownership

| Decision or fact | Canonical owner after the slice | Diagnostics capability |
| --- | --- | --- |
| Accepted catalogue and entity authority | request-pinned accepted runtime snapshot | observe identity only |
| Exact-count eligibility | lowered command facts and planner-selected accepted index | none |
| Exact-or-prepared compiled entry | existing fingerprint-bound global-aggregate slot | observe hit/miss only |
| Prepared fallback | existing registry-scoped shared query-plan cache | observe plan phases only |
| Exact metadata availability | exact-cardinality executor and synchronized store metadata | observe physical work only |
| Exact/prepared result and error | singular global-aggregate execution flow | project counters beside it |
| Phase totals | `SqlExecutePhaseAttribution` | sole outward diagnostic projection |

Diagnostics are not an authority. Absence, disabling, reset, or loss of
diagnostic state cannot alter result, error, cache state, physical work, or
accepted behavior.

## Frozen Invariants

1. Every request remains bound to one immutable accepted catalogue and entity
   authority for its complete execution.
2. The existing fingerprint-bound compiled slot remains singular.
3. Cache hits cannot authorize, select, refresh, or replace accepted schema.
4. Exact entity, exact prefix, and exact leading-component-distinct targets
   retain their current planner and metadata owners.
5. Metadata unavailability enters the existing shared prepared-plan fallback.
6. The shared query-plan cache remains the only fallback-plan cache owner.
7. Diagnostics cannot reclassify a query, select another index, or alter
   fallback eligibility.
8. Ordinary and diagnostics execution return identical values and typed errors
   and perform identical row/index/store work.
9. Cache attribution and detailed phase totals retain their current meanings.
10. Ordinary execution performs no diagnostics-only counter reads or retained
    allocation.
11. Publication and defensive fingerprint mismatch retain the current
    immutable-slot and outer-command replacement lifecycle.
12. Corruption, unavailable metadata, budget rejection, journal recovery and
    reinstall behavior remain unchanged.
13. No public, Candid, export, generated, stable-memory or persisted-format
    change is permitted.
14. No dynamic dispatch, boxed callback, generic recorder framework or new
    execution mode may be introduced to share the flow.
15. No compatibility alias or duplicate predecessor entrypoint remains after
    the hard cut.

## Scope

Included:

- global-aggregate prepared-plan resolution;
- exact-count target resolution and execution;
- exact-versus-prepared fallback orchestration;
- optional planner/executor/store attribution over that same flow;
- direct owner-local and focused integration proofs;
- production-line, raw-Wasm and instruction comparisons.

Excluded:

- parser, lowering or aggregate semantic changes;
- new exact-count targets or wider `COUNT(DISTINCT)` admission;
- changes to cardinality metadata or maintenance;
- select, grouped, write, DDL or mutation-job diagnostics convergence;
- a SQL-wide recorder abstraction;
- cache key, eviction, invalidation or publication changes;
- public metrics, endpoints, Candid or CLI changes;
- unrelated cleanup in large schema, executor or session modules.

## Rejected Alternatives

### Keep both trees

Safe but needlessly preserves a current propagation burden. The existing
optional-recorder pattern demonstrates that phase observation does not require
a second semantic resolver.

### Generalize all SQL diagnostics in 0.241

Rejected as too broad. Select, grouped, metadata, write and aggregate paths
have different physical and response attribution. A generic framework would
add vocabulary and monomorphization risk before a second concrete convergence
slice is evidenced.

### Merge initial and existing schema proposal lowering

Rejected. Symbol attribution identifies those functions as large Wasm
contributors, but they own materially different identity-allocation,
source-binding, removal, migration and publication contracts. A mode-bearing
shared lowerer would increase semantic state and risk accepted-schema
authority merely to reduce apparent duplication.

### Replace facade wrappers with generic closures

Rejected. The repeated facade methods are small frontend adapters with distinct
authorization contracts. Generic closure plumbing has little deletion ceiling
and can increase monomorphized Wasm.

### Always collect attribution and discard it for ordinary calls

Rejected. That would make diagnostics affect normal query cost and could add
allocations or performance-counter reads to production execution.

## Complexity And Wasm Gates

| Dimension | Acceptance gate |
| --- | --- |
| Semantic exact/prepared resolver trees | two to one |
| Semantic exact/prepared execution/fallback trees | two to one |
| Paired internal measured/ordinary functions | remove the six listed pairs; only thin outward-envelope adapters may remain |
| Production runtime lines | net decrease of at least 80 lines across the selected owner |
| Production types | no net increase |
| New caches, mutable owners, states, modes or invalidation edges | zero |
| SQL-only final raw Wasm | no growth from the clean `v0.240.1` reproduction |
| Diagnostics SQL-audit final raw Wasm | no growth; a reduction of at least 1,024 bytes is the target, not a weakened correctness gate |
| Gzip | report as secondary context only |
| Exact-count and ordinary aggregate instructions | existing absolute gates pass and no focused predecessor case regresses by more than 1% |
| Results, errors, cache facts and physical work | exact equality between ordinary/diagnostics and predecessor/candidate cases |
| Candid, exports and stable extent | exact equality |

If convergence needs a new framework, retains parallel policy matching, adds
runtime diagnostics work to ordinary calls, misses the 80-line deletion gate,
or grows either final raw Wasm subject, close this design as a measured
no-build and revert the candidate. Do not weaken the gate because the code
appears cleaner.

## Required Proof

- exact entity `COUNT(*)`, `COUNT(id)` and `COUNT(1)`;
- exact bounded equality and `IN` prefix counts;
- exact indexed `COUNT(DISTINCT Int32)` with duplicate-heavy, all-unique and
  empty inputs;
- cold compiled-command miss and true-warm command hit;
- exact metadata available, unavailable and becoming available later;
- prepared fallback cache miss and hit;
- non-count scalar aggregate and aggregate-filter fallback;
- ordinary and attributed calls returning identical result/error, cache facts,
  row fetches, index-entry reads and store calls;
- attributed planner phase totals for exact hit, exact miss, prepared hit and
  prepared miss;
- budget rejection before and after an exact metadata probe;
- accepted-root publication, retained old request and new request;
- journal replay/fold, same-Wasm recovery and reinstall;
- missing or corrupt metadata retaining the current fail-closed outcome;
- no-default, SQL-only, SQL+diagnostics and all-feature focused builds;
- final SQL-only and diagnostics raw Wasm comparison;
- stable extent, Candid and exports unchanged.

Existing 0.240.0 and 0.240.1 cache, lifecycle, corruption, performance and
recovery tests provide most semantic evidence. New proof is limited to parity
between the converged ordinary/attributed adapters and owner-local recorder
behavior.

## Landing Plan

The complete convergence design contains one substantive landing patch:

| Patch | Canonical owner and bounded outcome | Delivery domains | Acceptance evidence |
| --- | --- | --- | --- |
| 1 | SQL global-aggregate execution owner: collapse measured/ordinary exact-or-prepared planning, fallback and execution onto one semantic flow | Lowering / Session, Integration Tests | Measured no-build; candidate reverted after production raw-Wasm growth |

No Patch 2 is planned for this design. If implementation exposes an
independently reviewable select, grouped, schema, metrics or cache outcome,
stop rather than folding it into this design.

## Design Verdict

`CLOSED — MEASURED NO-BUILD — CANDIDATE NOT RELEASED`

The candidate met its semantic, complexity, correctness, instruction,
diagnostics-Wasm and public-surface goals, but every bounded implementation
shape grew the production raw Wasm. The hard no-growth gate failed and the
runtime candidate was reverted.
